# REQ-0063 · 365일 상시가동: 워치독 + ESP 하드웨어 리셋선 (와이어 포맷 불변)

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

사용자 요구: "esp8266 이 365일 상시가동되도록 개선하라".
내가 client.ino 를 감사한 결과, **이미 잘 되어 있는 것**과 **빠진 것**은 이렇다.

이미 되어 있음(건드리지 마라):
  - String/malloc 없음 — 고정 char[] + snprintf (client.ino:20). 힙 단편화 없음
  - millis() 비교가 전부 `now - x < y` 뺄셈형 → 롤오버 안전 (616,1095,1152,1211 확인)
  - 링크 복구 사다리: CIPCLOSE ×3 → AT+RST (1103~1117)
  - 전송 3연속 실패 → goOffline (608)

**빠진 것 — 이번 작업 범위:**

① **워치독이 아예 없다.** `wdt_`/`avr/wdt` 검색 0건.
   무인 상시가동에서 1순위다. 어디서든 행에 걸리면 영구 정지고, 사람이 가서 리셋해야 한다.
   ⚠ 켜기 전에 **이 보드의 부트로더와 WDT 상호작용을 반드시 확인하라.** 구형 optiboot 가
   아닌 부트로더에서는 WDT 리셋 후 부트로더가 WDT 를 끄지 않아 **부팅 직후 재리셋이 반복되는
   벽돌 루프**가 된다. 확인 못 하면 켜지 마라 — 벤치 세션을 통째로 날린다.
   ⚠ 주기는 넉넉하게. SoftwareSerial 이 비트뱅잉 중 인터럽트를 막으므로 짧은 주기는 오탐한다.
   최소 2초, 가능하면 4초 이상을 권한다. 근거를 코드 주석에 남겨라.

② **ESP 를 하드웨어로 리셋할 수단이 없다.** 지금 복구 최상단이 `AT+RST`(1112) 인데
   이건 **소프트웨어 리셋이라 AT 펌웨어가 먹통이면 도달하지 못한다.** 실제로 ESP-01 은
   장시간 돌리면 AT 계층이 wedge 되는 사례가 흔하다. 그러면 사다리 최상층이 무력해진다.
   → 남는 GPIO 하나로 ESP 의 RST(또는 CH_PD)를 당기는 경로를 넣어라.
   핀 배정은 client.ino:85~100 주석의 금지 목록(D0,D1,D7,D8,D13,A4,A5)과
   10칸 센서 배정을 반드시 지켜라. 남는 핀이 없으면 **없다고 보고하고 대안을 제시하라**
   (예: 어느 칸을 옮길지). 임의로 센서 핀을 뺏지 마라.
   ⚠ 배선이 따라오는 변경이므로, 무엇을 어디에 연결해야 하는지 **사용자에게 줄 배선 지시**를
   결과 노트에 명확히 적어라.

**범위 밖 — 하지 마라:**
  - seq/uptime 랩 문제는 **REQ-0062 로 socket-engineer 가 판정 규칙을 정하는 중**이다.
    client.ino:684,689 의 `millis()/1000UL` 과 361 의 seqNo 를 지금 임의로 고치지 마라.
    규칙이 정해지면 socket-engineer 가 너에게 직접 요청을 보낼 것이다.
  - 와이어 포맷(§2 프레임)은 이번 REQ 에서 건드리지 않는다.

**플래시는 네가 하지 마라 ⚠**
사용자가 Arduino IDE 로 직접 굽고 시리얼을 보고 있다. 포트를 잡으면 충돌한다.
지난번 실제로 사고가 났다. 너는 **코드 변경과 컴파일 검증까지만** 하고, 굽는 것은 사용자에게 맡겨라.
컴파일 확인이 필요하면 이전처럼 /tmp 사본으로 하라(폴더명≠스케치명 때문에 원본 경로로는 거부된다).

## 왜 필요한가

ESP-01 의 AT 계층 wedge 와 스케치 행(hang)은 둘 다 "며칠~몇 주에 한 번" 나오는 고장이라
짧은 테스트로는 안 잡히고, 잡히면 이미 현장이다. 워치독과 하드웨어 리셋선이 없으면
복구 수단이 사람의 손밖에 없어서 "365일 상시가동"이 원리적으로 불가능하다.

## 완료 기준

① 워치독: **기다리지 말고 유도해서 증명하라.** 임시 무한루프를 넣어 행을 만들고,
   워치독이 실제로 리셋하는 것을 시리얼로 보여라. 그리고 부팅 직후 재리셋 루프가
   없다는 것도 같이 보여라(위 ⚠ 부트로더 항목). 검증 로그를 결과 노트에 붙여라.
② 하드웨어 리셋선: 사다리에서 AT+RST 가 N회 실패하면 하드웨어 리셋으로 올라가는
   경로가 코드에 있고, 핀 배정이 금지 목록·센서 10칸과 충돌하지 않음을 보여라.
③ 컴파일 통과(flash/RAM 사용률 보고). **업로드는 하지 마라.**
④ 사용자가 따라 할 수 있는 **배선 지시 한 문단**을 결과 노트에 남겨라.
⑤ ①의 임시 무한루프는 반드시 제거하고 최종 컴파일을 다시 통과시켜라.
