# REQ-0077 · 서버 재기동 + 새 망 기준선 — 맥 IP 가 192.168.50.146 에서 192.168.35.21 로 바뀌었다

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

지금 srv_parking 프로세스가 아예 없다(ps 확인). 내려놓고 다시 안 띄웠다.

## 왜 재기동인가 (1순위 이유)
맥이 다른 공유기로 옮겨 IP 가 **192.168.50.146 → 192.168.35.21** 로 바뀌었다. 지금 서버는 옛 망에서 뜬 프로세스라 자기 주소를 옛 대역으로 알고 있고, 브라우저에 내려보내는 접속 주소와 소크 통계가 전부 어긋난다. 리슨은 와일드카드라 accept 자체는 되지만, **관측자가 거짓말하는 상태**라 이대로 디버깅하면 안 된다.
부차적 이유: 방화벽 허용 항목이 옛 바이너리 신원(srv_parking_new)에 묶여 무효화됐다. 사용자가 방화벽을 껐으니 재기동하면 새 판정이 붙는다.

## 할 일
1. 새 빌드로 기동, 9991·9900·5500 리슨 확인, 새 pid 보고
2. 소크 기준선을 새로 잡아라 — 현재 카운터는 두 망이 섞여 미복구 8000초를 물고 있다
3. swap_server.sh 에 방화벽 재등록(--remove/--add/--unblockapp) 추가. sudo 필요하면 스크립트가 안내만 하고 사용자가 실행하게 하라
4. 아두이노 접속·S 프레임 적재·웹 화면(192.168.35.21:9900) 응답까지 확인

## 규약
- **한 턴 돌고 멈추지 마라.** 프레임이 실제로 쌓일 때까지 자율 진행한다
- arduino-engineer 와 직접 요청을 주고받아라(루트 경유 불필요). 단 **반드시 req.sh 로 발행**해서 원장에 남겨라 — 사용자가 상태창으로 모니터링한다
- 진행 상황을 req.sh 로 갱신하라. 말로만 하면 사용자가 못 본다

## 왜 필요한가

서버가 죽어 있어 아무것도 진행되지 않는다. 그리고 망이 바뀐 위에서 옛 프로세스를 계속 쓰면 통계와 안내 주소가 어긋나 오진을 부른다.
