# REQ-0078 · client.ino 플래싱까지 자율 수행 — ESP_RST_WIRED 0 복귀 · aptest 판정 버그 · 프레임 적재 확인

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

**권한 변경**: 사용자가 명시적으로 허가했다. 플래싱과 시리얼 포트 사용을 허가한다. 포트는 **/dev/cu.usbmodem21201**(101 은 사라졌다). 사용자에게 권한을 묻지 말고 자율 진행하라.

## 상황
오늘 장애의 원인은 장치가 아니라 공유기였다. 다른 AP 로 옮기니 같은 하드웨어·같은 코드가 5초 만에 결합했다. 배제된 것: 전원(재부팅 0회·3.199V 안정) · 코드 로직(141행 aptest 도 동일 실패) · 채널 · 보율.
새 환경: AP=SK_WiFiGIGA50DC_2.4G · ESP=192.168.35.79 · 서버(맥)=192.168.35.21:9991.
사용자가 client.ino 의 SSID·비번·서버IP 를 이미 고쳐 플래싱했다.

## 할 일
1. **ESP_RST_WIRED 를 1 → 0** 으로 되돌려라. A2 선이 물리적으로 분리돼 있는데 1 이면 코드가 없는 배선을 전제한다
2. **aptest 판정 블록 버그 수정** — B 를 미시행했는데 'MAC 을 바꿔도 못 붙었다'는 결론을 낸다. 실행되지 않은 시행으로 결론 내지 않게 하라
3. client.ino 컴파일 → **직접 플래싱** → 시리얼 확인 → 서버에 S 프레임이 쌓이는지 확인
4. 안 되면 스스로 진단하고 될 때까지 반복하라

## 규약
- **한 턴 돌고 멈추지 마라.** 자율 완료가 지시다
- socket-engineer 와 직접 주고받되 **반드시 req.sh 로 발행**하라 — 사용자가 상태창으로 모니터링한다. tmux 로 말만 주고받으면 원장에 안 남아 사용자가 진행을 볼 수 없다
- 진행 상황도 req.sh 로 갱신하라

## 처리 결과

_(진행 중 · arduino-engineer)_

### ★ DNS Fail 의 원인을 찾았다 — **서버가 아니다. 서버IP 문자열의 앞 공백이다**

`client.ino` 의 사용자 수정본이 **디스크 어디에도 없어서**(저장소 파일은 옛 AP·옛 서버IP 그대로),
`avrdude` 로 **보드 플래시를 덤프해 실제로 구워진 문자열을 읽었다**:

```
AT+CIPSTART="TCP"," 192.168.35.21",9991      ← ★ IP 앞에 공백 하나
AT+CWJAP="SK_WiFiGIGA50DC_2.4G","2011050796"
```

`SERVER_IP` 매크로가 AT 명령에 그대로 이어붙는데 앞 공백이 들어가 **ESP 가 IP 리터럴로 파싱하지
못하고 호스트명으로 해석 → `DNS Fail`** 이다.

> **socket-engineer 에게**: 서버를 되살려도 이 펌웨어로는 그대로 실패한다.
> REQ-0077 의 서버 재기동은 필요하지만 **이 증상의 원인은 아니다.** 서버를 계속 의심하지 마라.

### 한 일

1. **`ESP_RST_WIRED` 1 → 0** (`client.ino:649`). A2 선이 물리적으로 분리됐으므로 되돌렸다.
   1 로 두면 4단이 "하드웨어 리셋했다"는 **거짓 로그**를 남긴다.
2. **네트워크 3줄을 새 환경으로 확정**(플래시 덤프에서 복원한 실측값 기준):
   `SK_WiFiGIGA50DC_2.4G` / `2011050796` / `192.168.35.21` — **공백 없이**.
   재발 방지 주석을 붙였다(공백 하나가 곧 고장이라는 것과, 실물 덤프 문자열을 근거로 남김).

### 남은 것
- aptest 판정 블록 버그(미시행 B 로 결론내는 것) 수정
- 컴파일 → `/dev/cu.usbmodem21201` 플래싱 → 시리얼로 `[TX] S,...` 확인 → 서버 `+ARD` 적재 확인
