# REQ-0070 · 폴백 device{online,last_frame_ts} 준비 완료 — 샘플 레코드 첨부

**요청자** `socket-engineer` → **담당** `web-engineer`

## 요청 내용

REQ-0068 처리 완료. 명세(§9.1·§9.4 개정 9·v1.8)와 server.cpp 구현이 끝났고 전이 기록까지 실측 확인했다. 네가 요청한 샘플 레코드를 붙인다 — 실제로 서버가 쓴 파일에서 그대로 떠온 것이다(가짜 장치로 재현).

오프라인 전이 레코드(배열 0번, 최신):

{"ts":1786730741404,"device_id":"P1","uptime":14,"seq":14,
 "device":{"online":false,"last_frame_ts":1786730740581},
 "occupied":"0011011101","reserved":"0000000000",
 "test_mode":{"armed":false,"override_count":0},
 "slots":[{"id":"A1","occupied":0,"reserved":0,"overridden":0}, ... 10칸]}

읽을 때 알아 둘 것:
- device.last_frame_ts 는 ts 보다 **앞선다**(위 예: 741404 vs 740581 = 823ms 전). 마지막 S 수신 시각이고 파일 쓴 시각이 아니다. 나이 계산은 now - last_frame_ts 로 해라.
- online:false 레코드도 occupied/reserved/slots 는 **마지막으로 알던 값 그대로**다(0011011101 보존). 요청대로 0 으로 밀지 않았다. 화면에서 "마지막으로 알던 값"으로 표시하면 된다.
- 장치를 한 번도 못 본 상태면 last_frame_ts = 0 이다. 그 경우 나이를 계산하지 마라.
- 기존 필드는 하나도 안 바뀌었고 최상위는 여전히 배열이다. snapshotFromLog() 의 device:{online:null} 자리에 그대로 옮겨 담으면 된다.

주의 하나 — **아직 실서버(PID 41260)에는 안 올라갔다.** 소크 동결 지시 때문이다. 지금 9900 에서 받는 data_log.json 에는 device 필드가 아직 없다. 그러니 화면 코드는 **device 필드가 없을 때 기존처럼 null(모름)로 떨어지게** 유지해 달라 — 교체 전후 둘 다 견뎌야 한다. 교체 시점은 오케스트레이터가 정한다.

## 왜 필요한가

web 이 폴백 화면에 센서 끊김을 표시하려면 필드 모양과 실제 값이 필요하다. 요청자가 샘플을 붙여 달라고 명시했다.

## 대상 파일

- `조별과제샘플/index.html`
## 완료 기준

폴백 경로에서 device.online=false 일 때 센서 끊김이 표시되고, last_frame_ts 로 경과 시간이 나온다. device 필드가 없는 옛 파일에서도 기존처럼 모름으로 동작한다.

## 처리 결과

처리 완료 (web-engineer). 대상 `조별과제샘플/index.html` 한 파일.

### 무엇이 없었나

정규화 계층은 이미 `last_frame_ts` 를 받아 두고 있었다(REQ-0068 응답 때 미리 자리를 만들어 둠).
**빠진 것은 화면이었다** — 값을 들고만 있고 어디에도 그리지 않아, 폴백에서 "센서 끊김"이라고
말하면서 *언제부터인지는 말하지 못하는* 상태였다. 끊긴 지 2초인지 두 시간인지에 따라
사용자가 할 일이 다르다(기다린다 vs 장치를 보러 간다). 이번 변경은 그 한 줄을 채운 것이다.

### 변경점

1. **`<dt>마지막 프레임</dt><dd id="dev-frame">` 추가** (장치 상태 dl, `센서` 바로 아래).
   `센서` 줄의 근거를 그 옆에 붙였다. 이 dd 는 **aria-live 가 아니다** — 그래서 매초 갱신해도
   스크린리더가 다시 읽지 않는다(배너는 live 라 흐르는 숫자를 못 넣는다).

2. **`renderFrameAge()` 신설.** 표시 기준은 요청대로 `now - last_frame_ts`.
   뒤에 `ts - last_frame_ts` 를 한 마디 덧붙였다 — **이 값만은 둘 다 서버 시계라 시계
   어긋남과 무관한 정확한 수**다(첨부 샘플의 823ms 가 그것). 예:
   `⚠ 12초 전 수신 — 그 뒤로 장치 프레임 없음 · 기록 시점에 이미 1초 침묵`

3. **매초 타이머에 연결** (`renderAge()` 옆). ⚠ 여기에 판단이 하나 들어갔다:
   이 숫자를 `renderConnection()`(끊김 배너)에 얹으면 **안 된다.** 그쪽은
   `state.link === 'reconnecting'` 일 때만 매초 도는데, 실제 폴백은 `file://` 로 열린
   `'nows'` 상태에서도 돈다(`pollOnce()` 는 `link === 'ws'` 일 때만 건너뛴다).
   즉 배너에 넣었으면 **데모 버튼에서는 잘 흐르고 실제 file:// 폴백에서는 얼어붙는**,
   자체 확인으로는 안 잡히는 모양이 됐다. 배너에는 흐르지 않는 안내문만 두고
   ("…「장치 상태 · 마지막 프레임」에 있습니다") 숫자는 매초 도는 쪽에 뒀다.

4. **`never_seen` 필드 추가** (normalizeSnapshot). `last_frame_ts = 0` 을 null 로 접되
   **접었다는 사실을 잃지 않게** 했다. "키가 없다"(모름)와 "0"(서버가 이 장치를 한 번도 못 봤다)은
   나이를 못 재는 것만 같지 사용자에게는 다른 사실이다 — 후자는 *서버는 떴는데 아두이노가
   한 번도 붙지 않았다*는 적극적인 정보다. 검증 중에 이 둘이 한 문장으로 합쳐져
   0 인 기록에 "개정 9 이전 형식입니다"라는 **틀린 말**이 뜨는 것을 발견해서 갈랐다.

5. **`ts < last_frame_ts` 방어.** `fmtAge` 가 음수를 0 으로 깎기 때문에, 뒤집힌 기록이 들어오면
   "0초 침묵"이라는 없는 사실이 떴다. 뒤집혔으면 그 절을 아예 빼도록 했다.
   브라우저 시계가 서버보다 뒤선 경우도 "0초 전 수신"이라고 우기지 않고 `계산 불가` 로 적는다.

6. **데모 버튼 `§9.1 개정 9 폴백 + 센서 끊김(last_frame_ts)` 추가** (`makeOfflineFileLog()`).
   첨부해 준 실제 서버 레코드를 그대로 옮기되 **타임스탬프만 클릭 시각 기준으로 다시 만든다**
   — 1786730741404 를 그대로 박으면 화면이 영원히 "N시간 전"이라 아무것도 증명하지 못한다.
   `ts`↔`last_frame_ts` 간격 823ms 와 `occupied:"0011011101"` 보존은 실제 값 그대로다.
   기존 `§9.1 파일 폴백 경로` 버튼은 **device 키가 없는 옛 형식**으로 이름을 명확히 해서
   두 버튼을 번갈아 누르면 '끊김+경과' ↔ '모름' 이 갈리는 것을 볼 수 있게 했다.

7. **개정 9 이후 거짓이 된 기존 문구 3곳 정정.** 새 필드를 그리는 것보다 이쪽이 더 급했다 —
   화면이 *"파일 폴백에는 센서 연결 여부가 없습니다(§9.1)"* 라고 단정하고 있었는데,
   개정 9 로 **그 말이 틀린 말이 됐다.** 없는 것은 경로가 아니라 그 기록이다.
   경로 탓으로 적힌 문구는 서버를 교체한 뒤에도 옛말을 계속하게 된다.
   - `renderFreshness()` 의 unknown 배너 → "이 기록에는 … (§9.1 개정 9 이전 형식)",
     경과 시간 안내도 `마지막 갱신` → **`마지막 프레임`** 으로 고쳤다(이번에 만든 그 줄이다).
   - `renderDevice()` 의 `센서` = `알 수 없음 (파일에는 이 정보가 없음)` → 기록 기준으로 정정,
     파일/WS 를 갈라 적는다.
   - `normalizeSnapshot()` 머리주석 — 코드 바로 위에서 코드와 반대되는 계약을 설명하고 있었다.

### 검증 방법과, 검증하지 **않은** 것

`index.html` 의 인라인 스크립트에서 순수 함수(`makeOfflineFileLog`/`snapshotFromLog`/
`normalizeSnapshot`/`fmtAge`/`renderFrameAge`)를 그대로 잘라 내 node 로 돌렸다.
렌더 대상만 스텁(`el.devFrame`)으로 바꿨으므로 **문자열이 만들어지는 경로는 실제 코드 그대로**다.
하네스는 일회성이라 확인 후 지웠다(저장소에 남기지 않음).

| # | 입력 | `#dev-frame` 결과 |
|---|---|---|
| 1 | 개정 9 폴백 `online:false` + `last_frame_ts` | `⚠ 1초 전 수신 — 그 뒤로 장치 프레임 없음 · 기록 시점에 이미 1초 침묵` |
| 2 | 옛 형식 (device 키 없음) | `알 수 없음 (이 기록에 last_frame_ts 가 없습니다 — 개정 9 이전 형식)` |
| 3 | `last_frame_ts: 0` | `한 번도 받지 못했습니다 (last_frame_ts = 0 · 장치가 서버에 붙은 적이 없습니다)` |
| 4 | WS 스냅샷(§5.3, 키 없음) | `알 수 없음 (이 경로에는 이 정보가 없습니다)` |
| 5 | 74초 경과 | `⚠ 1분 전 수신 …` (분 단위로 넘어감 = 매초 자란다) |
| 6 | 브라우저 시계 역전 | `계산 불가 (브라우저 시계가 서버 시계보다 뒤섭니다)` |

2번에서 `occupied` 보존(`0011011101`)과 `online=false` 정규화도 함께 확인했다.
인라인 스크립트 전체(1791줄)를 잘라 `node --check` 로 구문 검사도 통과했다 —
2000줄 인라인 스크립트는 오타 하나로 페이지가 통째로 비는데 코드만 읽어서는 안 잡힌다.

**브라우저에서 실제로 열어 보지는 않았다.** 이 세션에 `claude-in-chrome` 이 없다.
위 표는 "값 → 문자열" 경로의 실측이고, 실제 픽셀 배치·대비·스크린리더 낭독은 **코드 판단**이다.
새 데모 버튼(`fileFallbackOffline()`) 도 **눌러 본 것이 아니라** 기존 `fileFallback()` 을
줄 단위로 그대로 따른 것을 읽고 판단한 것이다. 위 표 1번이 그 버튼이 통과시키는 데이터와
같은 입력(`makeOfflineFileLog()`)을 쓰므로 값 경로는 실측됐고, **클릭 배선만 미확인**이다.
누군가 `?demo=1` 로 열어 눌러 주면 그 부분까지 닫힌다.

6번 케이스의 이름은 과했다 — `last_frame_ts` 만 밀어서 `ts < last_frame_ts` 를 만든 것이므로
실제로는 **깨진 기록** 시험이다. 진짜 시계 어긋남은 `ts >= last_frame_ts` 가 유지되므로
`계산 불가 … · 기록 시점에 이미 N 침묵` 이 되어 **시계 무관한 절이 살아남는다** — 의도한 동작이다.

### 교체 전후 양쪽을 견디는가

견딘다 — 위 표 1번(새 형식)과 2번(옛 형식)이 같은 코드에서 갈린 결과다.
지금 9900 이 주는 `device` 없는 파일은 2번 경로로 떨어져 **기존과 똑같이** 동작하고,
교체되면 1번으로 올라선다. 화면 쪽은 교체 시점을 몰라도 되고, 별도 조치도 필요 없다.
