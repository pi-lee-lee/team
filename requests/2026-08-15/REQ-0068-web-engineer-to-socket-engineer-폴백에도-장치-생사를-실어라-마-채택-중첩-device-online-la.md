# REQ-0068 · 폴백에도 장치 생사를 실어라 — (마) 채택, 중첩 device{online,last_frame_ts}

**요청자** `web-engineer` → **담당** `socket-engineer`

## 요청 내용

읽는 쪽(web)이 정하라고 해서 정한다. **(마) 채택**: 최상위 배열(§9.1) 유지, 레코드에 필드만 추가.

**필드 모양 — 중첩으로 간다.** 네 추천대로다.

```json
{"ts":…, "device_id":"P1", "uptime":…, "seq":…,
 "device":{"online":false,"last_frame_ts":1755193200000},
 "occupied":"…", "reserved":"…", "test_mode":{…}, "slots":[…]}
```

- `device.online` : bool
- `device.last_frame_ts` : **ms epoch, 서버 시계** (`ts` 와 같은 단위·같은 시계). 서버가 장치로부터
  **마지막 S 프레임을 받은 시각**이라고 명세에 못박아 달라. "파일을 쓴 시각"이 아니다 — 둘이 갈린다.
- `online:false` 인 레코드에서도 `last_frame_ts` 는 유효해야 한다(그때가 제일 필요한 값이다).

**왜 중첩인가**: `snapshotFromLog()` 가 이미 `device:{online:null,…}` 을 만들고 있고, 그 `null` 이
"파일에는 이 정보가 없다"는 뜻으로 비워 둔 자리다. 중첩이면 **그 자리에 그대로 옮겨 담기만 하면 되고**
WS 경로(§5.3)와 파일 경로의 모양이 같아져 정규화 함수가 갈라지지 않는다. 평평하게 두면 파일 경로에만
있는 별도 규칙이 하나 생긴다.

**같이 부탁하는 것 둘**

1. **중복쓰기 방지 키에 `online` 을 포함**시켜라(네 제안 그대로). 그래야 오프라인/복귀 **전이**가
   진짜 상태 변화로 파일에 한 번 기록된다. 주기적 쓰기는 필요 없다.
2. `online:false` 로 전이한 레코드의 `occupied`/`reserved`/`slots` 는 **마지막으로 알던 값 그대로** 둬라.
   0 으로 밀거나 지어내지 마라. 화면은 그것을 "마지막으로 알던 값"이라고 표시한다.

**네 정정 1 에 대한 보정 한 줄** — "서버가 죽으면 fetch 자체가 실패한다"는 **조건부로만 참**이다.

- 페이지를 srv_parking 이 아닌 다른 정적 서버가 서빙하면 서버가 죽어도 fetch 는 계속 성공한다.
  (방금 내가 폴백 검증을 정확히 그 구성으로 했다 — `python3 -m http.server`.)
- 서버가 **행**에 걸리면(02:19 의 블로킹 send) fetch 는 성공도 실패도 하지 않고 매달린다.
  내 `pollOnce()` 에 타임아웃이 없어 실패 보고조차 안 온다. **이건 내 쪽 결함이고 내가 후속으로 고친다.**

결론은 바뀌지 않는다 — (마) 로 간다. 다만 "fetch 실패가 서버 사망을 대신 알려 준다"를 설계 근거로
남기지는 말아 달라. 그 전제가 항상 서지는 않는다.

**내 쪽 진행 상황**: REQ-0067 로 `조별과제샘플/index.html` 은 이미 바뀌었다(done). 브라우저가
`receivedAt` 으로 직접 신선도를 재고, 폴백에서는 **내용이 같으면 이전 시각을 들고 간다**(재열람을
재확인으로 세지 않는다). 네가 읽은 `snapshotFromLog()` 구조는 그대로이고 네 분석은 유효하다.
지문이 `ts`+occupied+reserved 라서, 오프라인 전이로 파일이 새로 써지면 `ts` 가 바뀌어 새 관측으로 잡힌다.

**화면 쪽 후속은 내가 한다** — `device.online`/`last_frame_ts` 읽기, "이 경로에는 센서 연결 여부가
없습니다(§9.1)" 문구 교체, 폴백에서도 센서 끊김 표시. 명세 개정과 서버 구현이 끝나면 **나에게 REQ 하나**
보내 달라(샘플 `data_log.json` 한 줄 붙여 주면 바로 붙인다).

## 왜 필요한가

폴백은 WS 가 끊겼을 때의 마지막 방어선인데, 지금은 장치 생사 정보가 도달할 경로가 아예 없다. 그래서 "서버는 살아 있고 장치가 죽은" 상황에서 낡은 occupied 비트가 실측처럼 그려진다. 개정 4 에서 test_mode 를 파일에 넣어 고친 것과 똑같은 종류의 구멍이다.

### ① 명세 — `docs/net/parking-protocol.md` **개정 9 · v1.8**

- **§9.1** — 레코드에 `device{online,last_frame_ts}` 추가. 예제·필드표·주의사항 명시:
  `last_frame_ts` 는 **ms epoch(서버 시계, `ts` 와 동일)**, **"파일을 쓴 시각"이 아니다**,
  `online:false` 에서도 유효, 장치를 한 번도 못 봤으면 `0`,
  그리고 **`occupied`/`reserved`/`slots` 는 마지막으로 알던 값 그대로 둔다**(0으로 밀지 않는다).
- **§9.4** — 중복쓰기 판정 키를 명시하고 **`online` 포함**. `last_frame_ts` 는 **키에서 제외**한다
  (넣으면 매 프레임이 변화가 되어 초당 한 번 쓴다).
- **§9.4 노트** — 깜빡임 교환(전이 두 건이 두 칸을 채워 직전 점유 이력이 밀려날 수 있다)을 남겼다.
- **§13** — 개정 9 이력. 최상위 형식 무변경이라 §12 절차는 밟지 않았다.

### ② 서버 — `조별과제샘플/server.cpp`

- 레코드에 `device{online,last_frame_ts}` 출력. 중복키에 `online` 포함.
- **`ard_last_epoch_ms` 를 따로 들었다.** 기존 `ard_last_ms` 는 `now_ms()` 기반(윈도우에서는
  부팅 후 경과)이라 **바깥으로 나가는 필드에 쓰면 수십 년짜리 값이 된다** — 이 파일 28행이
  경고하는 함정 그대로다. epoch 시각은 프레임 수신 때 `epoch_ms()` 로 따로 찍는다.

### ③ 🔴 하마터면 필드가 거짓말할 뻔했다 — 호출 지점 문제

`write_log_if_changed()` 의 기존 호출 지점 **두 곳이 모두 `on_ard_line` 안**이었다.
즉 **장치가 조용하면 아예 실행되지 않는다.** 필드를 추가하고 키에 `online` 을 넣어도
**오프라인 전이는 영영 파일에 안 써진다** — 필드가 **가장 필요한 순간에** `true` 로 남는다.
→ 온/오프라인 엣지 처리부에서 `write_log_if_changed()` 를 부르도록 했다.
("추가했으니 되겠지"로 넘어갔으면 그대로 죽은 필드가 됐다. `docs/dead-detector-pattern.md` 규칙 1.)

### ④ 검증 — 실측했다 (포트 옮긴 사본, cwd `/tmp`, 가짜 장치)

`g++ -O2 -Wall` 무경고 · `--selftest` 회귀 없음. 장치를 **붙였다 → 끊었다 → 붙였다 → 끊었다**:

```
[온라인]        ts=…691356  online=true   last_frame_ts=…691356  occupied=0000000000
[끊음 3.5초 뒤] ts=…704786  online=false  last_frame_ts=…704485  occupied=0000000000
[복귀]          ts=…726450  online=true                          occupied=0011011101
[다시 끊음]     ts=…741404  online=false  last_frame_ts=…740581  occupied=0011011101  ← 점유 보존됨
```

완료 기준 대조: **오프라인 전이 1건 ✅ / 복귀 전이 1건 ✅** 각각 정확히 한 번만 기록된다.
`last_frame_ts` 가 **쓴 시각(`ts`)보다 앞선다** — 요청대로 "마지막 수신 시각"이지 "쓴 시각"이 아니다.
**점유값이 있는 상태에서 끊었을 때 `occupied=0011011101` 이 그대로 보존**됐다(0으로 밀지 않음 ✅).

### ⑤ ⚠ 실서버 반영은 아직 — 소크 동결

오케스트레이터가 **"서버는 소크 끝날 때까지 동결"**, arduino-engineer 가 **"소크 시작 뒤에는
재기동 금지"** 로 지시했다. 그래서 **소스·명세만 반영하고 실행 중인 `srv_parking`(PID 41260)은
건드리지 않았다.** 빌드는 끝나 있으므로 창이 열리면 교체는 수 초다.
**교체 시점은 오케스트레이터가 정한다.**

### ⑥ 요청자 보정 수용 — "fetch 실패가 서버 사망을 알려 준다"는 설계 근거로 쓰지 않았다

지적이 맞다. ⑴ 페이지를 다른 정적 서버가 서빙하면 서버가 죽어도 fetch 는 성공하고,
⑵ 서버가 **행**에 걸리면 성공도 실패도 하지 않는다. 조건부로만 참인 명제다.
**그래서 §9.1 개정문 어디에도 그 전제를 쓰지 않았다.** 근거는 "상태가 스스로 말하게 한다"로만 적었다.
