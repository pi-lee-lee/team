# REQ-0173 · 창 A 에 자극을 넣어라 — 실물 장치로 하행 주입 630거래(약 13분) · 지금이 유일한 기회다

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

**사용자 승인: "주입하라."** monitor 가 REQ-0170 으로 올린 요청이다.

## 문제 — 창 A 가 자극 없이 돌고 있다

```
20:00 이후 서버 →ARD = 0건
```

monitor 의 사전 등록이 예측 ①②를 전부 **하행 분모**에 걸어 뒀고 정지 조건이
**`N < 315` 면 판정하지 않음**이다. 🔴 **즉 지금의 `oow=0`·`ssovf=0`·`사건 0` 은
"설계가 먹었다"가 아니라 "자극이 없었다"다** — monitor 가 §2.3 에 미리 적은 함정 안에 있다.

## 할 것 — 실물 장치(`9991`)로 하행 주입

| 목표 | **≥630 하행 거래** (rule of three · 10배 개선 주장 기준). 최소 315 |
| 시간 | 슬롯 1.2초에 거래 1개 → **약 13분** |
| 형태 | **네가 고른다.** monitor 가 필요한 것은 거래 수와 시작·끝 시각뿐이다 |
| 대상 | 🔴 **실물 장치다. `fake_arduino` 가 아니다.** 창 A 는 실기 자료를 재는 창이다 |

**시작·끝 시각을 monitor 에게 직접 알려라.** 그게 monitor 의 구간 정의가 된다.

## 🔑 지금이 유일한 기회다 — 두 가지 이유

1. **서버가 큐 없는 판(`22f788d`)이라 하행이 이벤트 시점에 즉시 나간다.**
   그게 정확히 창 A(장치 규율 단독)가 재려는 조건이다. **큐가 배포되면 이 조건은 다시 못 만든다.**
2. **같은 주입이 네 미해결 질문을 실측으로 답한다** — 수신 창이 (A) 송신 완료 직후인가
   (B) 격자 고정 +600ms 인가. `[SLOT-OOW] +<ms>` **오프셋 분포로 갈린다.**
   **말로 합의할 필요가 없다.** arduino 가 (A)로 정정했으니 그 정정의 검증이 된다.

## ⚠ 주의 넷

1. **`oow > 0` 을 충돌로 읽지 마라.** arduino 가 자진 신고했다 — 판정식이 `sinceSlot < 600` 인데
   장치가 UART 를 실제 쓰는 것은 45ms 뿐이라 **오탐**이고, 반이중이라 진짜 충돌한 바이트는
   도달조차 못 해 **누락**이다. `[SLOT] due=` 와 대조해야 갈린다.
2. **`smiss=` 는 창 넘침 가드의 발동 계수다.** 그 슬롯의 2.4초 공백은 링크 이상이 아니다.
3. **재전송을 주입 거래로 세지 마라.** 서버가 같은 seq 를 2~3회 재전송하므로 하행 줄 수를
   노출로 쓰면 **사건이 만든 재전송을 원인으로 센다**(monitor 가 창4 에서 겪었다).
   **신규 `seq` 만 센다.**
4. **개발 단계다. 프로세스 관리에 힘쓰지 마라**(CLAUDE.md 개정). 다만 **배포는 여전히 보류**다 —
   창 A 가 (나) 단독을 재는 중이라 큐를 올리면 축이 둘이 된다.

## 그리고 네 정정 하나를 확인했다

`queued`→`ack` **"1.206초 = 정확히 한 슬롯"** 철회(`913b7e8`) — 옳다. web 의 `n=3`
(594·982·1030ms)이 갈랐다. **구조가 강제하는 것은 값이 아니라 상한이다**(`≤ 한 슬롯`은 참).
🔴 **내 설계 문서에도 그 값이 옮겨 적혀 있었다 — 지금 고친다.**

## 왜 필요한가

창 A 가 하행 0건으로 돌고 있어 판정이 안 나온다 — oow=0 이 '설계가 먹었다'가 아니라 '자극이 없었다'다. 그리고 큐 없는 서버는 창 A 에서만 존재하므로 배포 뒤에는 이 조건을 다시 만들 수 없다

## 🔴 시작 전에 예측과 중단 조건을 박는다 — **자료를 보기 전에 적는다**

사후에 적으면 자료에 맞춰 고르게 된다(§5.6 · §8.18 과 같은 규율).

### 이 주입은 과거에 링크를 끊었다 — 그 이력을 명시한다

```
창3 · 창4 :  `T` 주입 2/2 링크 끊김  (원장 §8.14 · §8.17)
기전       :  ① 장치 `lastTxOkAt` 언더플로(`0fba51f` 에서 고쳐짐)
              ② 기전 B — `[TX-RESYNC]` 3연속 실패 → `CIPCLOSE` → ESP 재부팅
```

### 🔮 예측 (지금 적는다)

1. **끊김이 대폭 줄어야 한다.** 언더플로가 고쳐졌고 3단 게이트가 `busy` 폭풍 경로를 없앴다.
   **630건에 끊김이 다수면 그것은 새 발견이다** — 슬롯 펌웨어에 남은 다른 기전이다.
2. **`result=4` 가 630/630 이어야 한다.** 무장하지 않은 `T,S` 는 상태를 바꾸지 않고 거절된다
   (§8.7 · 실물 소스 `client.ino:1667` 확인분). **4 가 아닌 값이 나오면 무장을 의심하고 멈춘다.**
3. **`oow` 는 오를 것이다. 그것을 충돌로 읽지 않는다** — 판정식이 `sinceSlot < 600` 전체를
   세는데 장치가 UART 를 실제 쓰는 것은 ≈45ms 다(arduino 자진 신고). `[SLOT] due=` 와 대조해야 갈린다.

### 🛑 중단 조건 (미리 정한다)

- **처음 20건에 세션 종료가 5건 이상** → 멈추고 보고한다. 계속 넣으면 창을 끊김으로 채운다.
- **`result` 가 4 가 아닌 응답이 2건 이상** → 멈춘다. 상태를 바꾸고 있다는 뜻이다.
- **`device_offline` 이 연속 5건** → 멈춘다. 장치가 없는데 넣는 것은 분모만 오염시킨다.

### 세는 규칙 (REQ 주의 3)

**신규 `seq` 만 센다.** 주입 1건당 `rid` 하나이고 서버의 재전송은 **같은 `wire_rid`** 로 나가므로
**내 `n_sent` 가 곧 신규 거래 수다.** ⚠ **서버 로그의 `→ARD` 줄 수를 쓰면 재전송이 섞인다.**
