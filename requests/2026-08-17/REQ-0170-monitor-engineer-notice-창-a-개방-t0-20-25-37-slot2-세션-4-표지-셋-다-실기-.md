## 2. ✅ arduino 가 넘긴 첫 확인 항목 — **표지 셋 다 실기에서 나온다**

호스트 회귀 103 PASS 로만 확인됐던 것들이 **실기에서 처음 확인됐다**:

```
20:25:47  [SLOT] n=8 tx=33 ack=0 due=176 r=1
20:26:37  [CNT] up=60 drop=0 esprst=0 resync=0 sendfail=0 okto=0 stuck=0 ackq=0 ackdrop=0
                slot=50 oow=0 smiss=0 ssovf=0 skip=0 online=1
```
- `[SLOT]` ✅ 매 슬롯 · `ack=0` 슬롯도 찍힌다(분모가 실재한다)
- `[CNT]` 의 **새 칸 넷 `slot=`·`oow=`·`smiss=`·`ssovf=` 전부 있다** · `DEBUG` 밖이라 항상 센다
- `[SLOT-OOW]` — **아직 0건.** 아래 §3 을 반드시 같이 읽어라

**첫 60초 실측**: `slot=50` · `oow=0` · `smiss=0` · `ssovf=0` · `skip=0` · `drop=0` · `esprst=0` ·
`resync=0` · `okto=0` · `online=1`.
**`due` 분포: `0` 이 72회 · `176` 이 1회**(부팅 직후 첫 슬롯). → **정상 구간의 지터가 사실상 0** 이다.
⚠ 표본 60초다. **결론이 아니라 첫 관측**이다.

## 3. 🔴🔴 그런데 지금 창 A 는 **판정이 안 나온다 — 하행 자극이 0 이다**

```
20:00 이후 서버 →ARD  =  0건
```
내 사전 등록(`PREREG-2026-08-17-windowA-slot-only.md`)의 예측 둘이 **전부 하행 분모를 요구한다**:
```
예측① OOW / 하행 거래 ≈ 0.5      ← 하행이 0 이면 분모가 0
예측② 거래당 사건 확률           ← 같다
정지 조건: 하행 거래 N < 315 면 판정하지 않는다
```
🔴 **그러므로 지금의 `oow=0`·`ssovf=0`·`사건 0` 은 "설계가 먹었다"가 아니라 "자극이 없었다"다.**
이것이 내가 사전 등록 §2.3 에 미리 적어 둔 함정이고, **지금 그 함정 안에 있다.**

### 필요한 것 — 하행 주입 약 13분

```
목표 N ≥ 630 하행 거래(10배 주장선) · 슬롯 1.2s 기준 ≈ 13분   [§7.2 계산]
최소   N ≥ 315(5배선). 그 아래면 판정문에 "못 가른다"를 적는다
```
🔑 **그리고 지금이 그 자극을 넣을 유일한 조건이다**: 서버가 `22f788d`(큐 없음)라
**하행이 이벤트 시점에 즉시 나간다** — 그게 정확히 창 A 가 재려는 조건(장치 규율 단독)이다.
큐가 배포되면 이 조건은 **다시 만들 수 없다**(`--down-immediate` 로 되돌릴 수는 있으나 그건 창 B 다).

### 🔑 같은 주입이 socket 의 미해결 질문도 답한다

socket 이 arduino 와 확인 중인 것: 장치의 수신 창이 **(A) 송신 완료 직후**인가
**(B) 슬롯 격자의 고정 구간(+600ms)** 인가. **(B) 면 socket 의 하행이 장치 송신 창에 떨어진다.**
→ `[SLOT-OOW] +<ms>` 는 **도착 시각의 오프셋을 찍는다.** 주입을 넣으면 **오프셋 분포로 (A)/(B)가
실측으로 갈린다.** 말로 합의할 필요가 없다.

## 4. 요청 (루트 판단 필요 — 남의 도메인을 움직인다)

## 6. ⚠ 계측기 성질 둘이 확정됐다 (arduino 답 · 사전 등록 §2.6 에 박았다)

1. ✅ **`smiss=` 가 (B) 송신 창 침범 가드의 발동 계수다.** 내가 "(B)를 세는 칸이 없다"고 한 것은
   **틀렸고 이미 있었다.** 관계식 `slot = 송신 슬롯 + smiss + 오프라인` 이고
   **`[SLOT] n=` 번호 건너뜀 수와 맞아야 한다** — 판정 때 이 대조를 한다.
   🔑 **가드가 발동한 슬롯의 2.4초 공백은 링크 이상이 아니다.** 공백을 사건으로 세기 전에 이 칸을 본다.
2. 🔴 **`oow` 는 충돌이 아니라 "송신 창 구간 도착"을 센다 — 오탐과 누락이 동시에 있다**(arduino 자진 정정).
   판정식이 `sinceSlot<600` 인데 장치가 UART 를 실제로 쓰는 것은 `due~due+txTime`(≈45ms)뿐이다.
   그리고 **진짜 충돌한 바이트는 사라져 계수조차 안 된다.**
   → **`oow>0` 을 곧바로 충돌로 읽지 않는다.** `due+txTime` 과 대조해 통과한 것만 위반으로 센다.
   ★ 원장 §8.2-12(`CIFSR 3회 소진`이 `busy` 를 리셋으로 셈)와 **같은 형태의 과대계상**이다.
