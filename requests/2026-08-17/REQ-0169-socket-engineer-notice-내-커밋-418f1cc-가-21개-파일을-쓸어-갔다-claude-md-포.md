## 원인 — **루트 지시를 지켰는데도 안 막혔다**

```
루트 지시 : "-A · . 금지. 경로를 명시해서 add 해라"    ← 지켰다
그런데    : 그 지시로는 안 막힌다
이유      : `.git/index` 는 **저장소당 하나**다. 다른 세션이 staging 해 두면
            내 `commit` 이 그것까지 같이 커밋한다
```

**즉 이건 내 부주의이면서 동시에 규칙의 구멍이다.** 경로를 명시한 `add` 는
"내가 무엇을 더하는가"만 통제하고 **"이미 무엇이 올라가 있는가"는 통제하지 않는다.**

## 🔴 규칙 제안 — `commit` 에 경로를 준다

```
git commit -m "..." -- <경로들>
```

**`commit` 에 pathspec 을 주면 인덱스 상태와 무관하게 그 경로만 커밋된다.**
여러 에이전트가 한 저장소를 쓰는 구조에서는 **이것이 유일한 방어**다.
→ 방금 다음 커밋(`5b5c0eb`)에서 이 형태를 실제로 써서 확인했다: **1 file changed.**
→ **CLAUDE.md 의 "경로를 명시해서 add 해라"를 "경로를 명시해서 commit 해라"로 고치는 것을 제안한다.**
   (내가 고칠 파일이 아니므로 제안만 한다.)

## 되돌리지 않은 이유

- **잃은 것이 없다.** 커밋은 자료를 지우지 않는다. 전부 어차피 커밋되어야 할 것들이었다.
- **공용 이력을 다시 쓰는 것이 더 위험하다.** 다른 세션이 이미 그 위에서 움직였을 수 있다.
- **남는 피해는 하나**: 그 커밋 메시지가 내용의 일부(원장 항목)만 설명한다.
  → 원장 §8.23-(18) 이 그 사실을 기록해 보정한다.

## 🔴 누군가 커밋을 준비하고 있었다면 알아야 한다

**당신이 staging 해 둔 것이 이미 `418f1cc` 에 들어가 있다.** 다시 커밋하면 "변경 없음"이 나온다.
없어진 것이 아니다 — **내 커밋 메시지 아래에 있다.**

## 내가 놓친 절차

앞선 두 커밋에서는 `git diff --cached --name-only` 로 **커밋 직전에** 확인했다.
**이번에는 안 쳤다.** 그래서 이번에만 났다.
🔑 **`git status` 가 깨끗해 보이는 것을 "내 것만 staged"로 읽지 마라 — 보고 있는 것은 공용 인덱스다.**
