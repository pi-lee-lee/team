# REQ-0164 · 상행 배치 + 슬롯 표지 둘 + 운영 복귀 — 굽기 한 번에 묶는다 (사용자 지시: 모두 완료하고 플래싱)

REQ-0157 접수했다. 네 칸 다 답이 왔고 `rxmax`=창당 540B 를 설계 문서에 확정으로 올렸다.

## 🔴 사용자 지시가 순서를 정했다 — **한 굽기로 묶는다**

사용자 원문: *"충분히 기다리겠다. … 모두 완료하고 플래싱하라."*

그래서 네가 물은 2번의 답은 **묶는다** 다. 다만 네가 걱정한 "변수가 둘"은 **이 경우 성립하지 않는다** —
확인해 보면 변수는 하나다:

```
운영 복귀 굽기 = client.ino 를 굽는 것
상행 배치      = client.ino 안 sendLine() 을 고치는 것
                 ↑ 별개의 두 바이너리가 아니다. 하나다.
```

**"먼저 원본 client.ino 를 굽고 나중에 배치를 굽는다"는 굽기를 하나 늘리기만 하고 대조군을 안 만든다** —
대조군은 이미 있다. **창4**(`07:53:49~14:48:10` · 6.9h · 사건 11건)가 슬롯 없는 client.ino 계열이다.

🔴 **그래서 네가 해야 할 기록이 하나 있다**: **창4 바이너리와 새 바이너리의 커밋 차이.**
그게 없으면 "슬롯 때문인가 그 사이 다른 수정 때문인가"를 못 가른다. **굽기 전에 적어라** —
창4 구간에 올라가 있던 것이 어느 커밋인지, 그 뒤 `client.ino` 에 무엇이 더 들어갔는지.
슬롯 외 변경이 섞여 있으면 **그 목록 자체가 판정문에 들어가야 한다.**

## 굽기 한 번에 들어갈 것 — 셋

### ① 상행 배치 (`sendLine()` 단일 통로 · 전제 확인 완료)

- 슬롯마다 **반드시** 보낸다. 보낼 게 없어도 상태 프레임이 나간다 —
  그 한 프레임이 **반송파 · 생존 신호 · 슬롯 시작 통보**를 겸한다.
- 밀린 ACK 는 **전부 그 한 번에** 실어 보낸다(`S,...\n@,3\n@,4`).
- **한 줄 상한은 그대로.** 줄을 LF 로 이어 붙여 한 거래에 여러 줄을 담을 뿐이다.
- **큐에는 바이트가 아니라 의도를 담는다**(네 판단이었다) — 미뤄 둔 텔레메트리는 재생이 아니라
  **재생성**이다. 옛 값을 나중에 보내면 틀린 값이다.

### ② 슬롯 로그 표지 둘 — monitor 가 요구했고 내가 승인한다

`monitor/METRICS-slot-boundary-2026-08-17.md` §4 다. **형식은 네가 정한다.**
monitor 가 요구하는 것은 **셀 수 있는 단위**뿐이다 — `0` 을 낼 때 분모가 같이 나오면 된다.

| # | 필요한 줄(예시) | 왜 |
|---|---|---|
| ① | `[SLOT] n=<번호> tx=<바이트> ack=<건> due=<ms>` | 슬롯이 실제로 상수인지 · 묶음이 몇 건인지를 **분모로** 쓴다 |
| ② | 수신 창 **밖** 도착 시 `[SLOT-OOW] +<ms>` | **이 줄이 없으면 설계 위반이 조용하다** |

🔴 **②가 왜 중요한지는 monitor 의 창4 판정이 말한다.** 기전 사슬이 로그 원문으로 확인됐다
(`JUDGMENT-2026-08-17-win4.md`):

```
하행 도착 → 다음 상행의 SEND OK 소실 → 3초 뒤 ESP 부트 배너 → CIFSR "0.0.0.0"
```

**순서까지 줄 단위로 확인된 것 4건** — `13:19:54` · `13:20:28` · `13:43:44` · `14:45:49`.
미확인 3건은 **반증이 아니다**(배너 없는 리셋 · UART 손상 시 `0.0.0.0` 유실).

> ⚠ **이 REQ 초판은 `n=6` 으로 적었다. 정정이다.** "6" 은 집계 도구 둘의 **표지 공존**에서 나온
> 수이고 **그 도구들은 순서를 안 본다**(monitor 원장 7.42 · `chain_verify.py` 로 사건마다 재확인).
> 🔴 **arduino 원장 §8.2-4 의 `6/6` 과 이름이 같고 정의가 다르다 — 출처로 걸 때 섞지 마라.**

**반이중 충돌은 줄 손상이 아니라 ESP 모듈 리셋까지 간다.** 슬롯은 "상행 송신 중 하행 도착"이라는
조합을 없애서 이걸 막는 설계다. **그런데 그 성공은 "지표가 0"으로 나타난다.**
`0` 은 두 가지다 — 설계가 먹은 것과 못 센 것. **②가 그 둘을 가르는 유일한 줄이다.**

### 🔴 ②를 넣어야 하는 **더 강한 이유** — 우리는 이 기전을 재현할 수 없다

**우리 주입 사건(07:54:40)은 사슬 확인에서 빠진다.** 즉 **"주입으로 같은 기전을 재현했다"는
성립하지 않는다.** 이 기전의 유일한 증거원은 **사용자가 화면을 두들긴 13:18~14:48 세 시간**이다.

→ **②가 없으면 슬롯이 먹었는지 다시 확인할 방법이 "사용자에게 또 부하를 걸어 달라고 부탁하는 것"뿐이다.**
장치가 위반을 직접 찍으면 자연 부하를 기다리지 않아도 된다.

### ③ 운영 복귀 — 굽고 나서 붙는 것을 확인해라

서버 주소는 지금 맞다(확인했다): `SERVER_IP "192.168.35.81"` = 맥 현재 IP · 포트 `9991`.
**사용자가 IP 문제를 의심했던 것이라 이 확인이 그 답이다.** 00:12 의 `.21`→`.81` 재발이 아니다.

⚠ 굽고 나서 **실제로 서버에 붙는 것까지 보고**해라. 운영 인스턴스는 `pid 46224`(`build=22f788d`)이고
**루트가 재빌드·교체를 금지해 뒀다** — 그 바이너리가 `22f788d` 배포의 유일한 현물 참조다.
안 붙으면 원인을 밝히기 전에 서버를 갈아 끼우지 마라.

### ① 창4 바이너리와의 커밋 차이 — 🔴 **굽기 전에 기록했고, 결과가 REQ 의 전제와 다르다**

기록 위치: `arduino/INTERVENTIONS.md`(굽기 전 절).

**창4 = `0fba51f`**(07:49 굽기, hex 대조 IDENTICAL). 그 뒤 `client.ino` 에 들어간 커밋은
**`443a352` 하나**(+173/−13)뿐인데, **그 안에 슬롯과 무관한 변경이 다섯 있다:**

| # | 변경 | 판정 지표에 주는 영향 |
|---|---|---|
| 1 | ACK 보류 큐 (`ackq*`) | 하행 응답률 |
| 2 | **3단 게이트**(`SEND_OK_GIVEUP_MS=8000`·`stuck`) | 🔴 **`busy` 폭풍 경로를 없앴다 → 링크 끊김률** |
| 3 | `sendOkT1Passed` 걸쇠 | 🔴 **`okto` 의 단위가 증상→사건으로 바뀐다** |
| 4 | `cifsrRefused` | 🔴 **`esprst` 의 정의가 바뀐다**(오탐 제거, 원장 §8.2-12) |
| 5 | `[CNT]` 칸 3개 추가 | 옛 로그엔 없는 칸 |

> ### 🔴 **그러므로 "창4 대비 변수는 슬롯 하나"가 아니다 — 여섯이다.**
> REQ 의 *"변수는 하나다"* 는 **운영복귀 대 배치**를 두고 한 말이고 **그건 맞다**(같은 파일·같은 굽기).
> **그러나 그것이 창4 를 깨끗한 대조군으로 만들지는 않는다.**
> 특히 **2·3·4 는 판정 지표 자체를 건드린다** — `esprst`·`okto` 는 창4 와 **이름이 같고 세는 것이 다르다.**
>
> ✅ 그나마 안전한 비교: **`drop`**(정의 불변). ⚠ 그것도 2번이 경로를 바꾸므로 "슬롯 단독 효과"는 아니다.
> **→ 판정문에 이 표를 그대로 넣어야 한다.** (다섯 변경은 **한 번도 구워진 적이 없다** — 이번이 처음이다)

### ② 구현 — 배치 + 표지 둘

**상행 배치**
- `sendLine()` 의 몸통을 **`sendPayload(buf, len)`** 로 뺐다. `sendLine()` 은 한 줄 래퍼로 남아
  **기존 규약(§2.1 한 줄 64B)을 그대로 유지**한다. 호출부는 안 바꿨다.
- **`sendSlotBatch()`** 신설 — `S` 프레임 + 밀린 ACK 를 **한 `CIPSEND`** 로:
  `S,912,...,3F\nA,7,A1,1,2C\nA,8,B3,1,5D`
- **ACK 는 캐시에서 재생성한다**(재생 아님). 큐에는 `rid` 만 있다.
- 🔑 **성공했을 때만 큐에서 소비한다.** 만들 때는 peek 만 하고, `sendPayload` 가 참을 준 뒤 뺀다.
  → **실패해도 ACK 를 잃지 않는다.** (옛 `ackqDrain` 의 "먼저 빼고 실패 시 되넣기"는 배치에서
  순서가 뒤집힐 수 있어 못 쓴다.)
- ⚠ **길이를 먼저 확정하고 그만큼 정확히 쓴다.** `waitForPrompt()` 안에서 `pumpSerialRaw()` 가
  돌아 캐시가 바뀔 수 있으므로 **나중에 다시 계산하면 안 된다** — 그러면 `AT+CIPSEND=N` 과
  실제 바이트가 어긋나 원장 §1.4 의 (a)/(b) 갈래를 우리 손으로 만든다.
- `ackqDrain()` 제거(배치에 흡수) · `loop()` 에서 호출 삭제.
- **이벤트가 전송을 만들지 않는다**: `debounced` 를 송신 조건에서 뺐다. 변화는 다음 슬롯 화물에 실린다.

**표지 둘**
```
[SLOT] n=<번호> tx=<바이트> ack=<건> due=<ms> r=<0|1>     ← 매 슬롯. ack=0 인 슬롯도 찍는다
[SLOT-OOW] +<ms>                                          ← 수신 창 밖 하행 도착
```
- **`ack=0` 인 슬롯도 찍는 이유**: 그래야 `0` 이 "묶을 것이 없었다"이지 "못 셌다"가 아니게 된다(§5.1).
  monitor 가 잃게 될 `[TX] A,` 의 **대체 분모**가 이 칸이다.
- **누적은 `[CNT]` 에 `slot=`·`oow=`·`smiss=` 로 `DEBUG` 밖**에 뒀다(원장 §8.4-2 경계:
  정수 계수는 밖, 장문 진단은 안). → `DEBUG=0` 시연 빌드에서도 슬롯 준수를 셀 수 있다.
- ⚠ **`[SLOT-OOW]` 는 `millis()` 를 새로 뜬다.** `loop()` 의 `now` 는 낡았고 `slotStart` 는
  `statusTick()`(더 뒤)에서 전진한다 — 낡은 값으로 판정하면 경계에서 틀린다(원장 §8.7-7 형태).
- ⚠ **문구에 다른 표지 문자열을 넣지 않았다**(`SEND OK`·`busy`·`+IPD`·`[TX]`).
  monitor 파서가 우리 산문 속 `SEND OK` 를 세어 `0/7` 을 낸 사고가 오늘 있었다.

**호스트 회귀: 103 PASS / 0 FAIL**
- `[12d]` 는 **지우지 않고 개정**했다(원장 §8.2-15-2) — `ackqDrain()` → `sendSlotBatch()`.
  **목적("보류 ACK 가 실제로 나간다")은 그대로**이고 부르는 함수만 바뀌었음을 그 자리에 적었다.
- 신설: `[12h]` 배치가 한 거래에 담기는가(거래 수·LF 이어붙임·**선언 길이 == 실제 바이트**) ·
  `[12i]` **실패 시 ACK 잔존** · `[15]` 슬롯당 1거래 · `[16]` 수신 창 무송신 ·
  `[17]` 위상 드리프트 없음(`+=` 확인) · `[18]` 다중 슬롯 건너뜀 후 위상 유지 ·
  **`[19]` `oow` 가 실제로 오르는 것**(§8.2-15-1: "안 오른다"만 시험하면 영원히 0 인 계수기도 통과한다).

### 🔴 새로 확정된 사실 둘 — 다른 도메인이 알아야 한다

**1. 프레임 주기가 1.113s → 1.200s 로 바뀌었다** (실측: `S,32`~`S,51` = 19프레임/23초)
```
옛 칩: 2초 간격이 약 9프레임마다   (1/(1.113−1) = 8.9)
새 칩: 2초 간격이 약 5프레임마다   (1/(1.2−1)   = 5)
```
> **"2초 공백이 늘었다"를 고장으로 읽으면 틀린다. 설계대로 늘어난 것이다.**
> **굽기 전후의 간격 분포를 같은 표에 넣지 마라.**

**2. 접속 직후 첫 두 프레임은 간격이 0.6초까지 좁아질 수 있다** (설계상 정상)
한 슬롯의 송신 창 **끝자락**에 보내고 다음 슬롯 창 **시작**에 보내면 0.6초가 된다.
둘 다 자기 송신 창 안이라 수신 창을 침범하지 않는다. **socket 은 하한 0.6초를 염두에 둬야 한다.**
