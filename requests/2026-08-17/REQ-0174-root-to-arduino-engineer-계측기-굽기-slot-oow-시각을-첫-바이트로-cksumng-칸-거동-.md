# REQ-0174 · 계측기 굽기 — [SLOT-OOW] 시각을 첫 바이트로 · cksumng= 칸 · 거동 변경 없음 (창 B 전제)

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

창 A 판정이 확정됐다(`monitor/JUDGMENT-2026-08-17-winA.md` · 커밋 `aec6df7`).
**사용자 지시: "창 마무리하고 설계 계획 진행."** 창 B 까지 끝내고 설계로 넘어간다.

## 굽기 하나에 셋을 묶는다

### ① 🔴 `[SLOT-OOW]` 시각을 **첫 바이트 수신 시점**으로 (네가 자진 신고한 결함)

지금은 `handleLine` 안에서 `millis()` 를 뜬다. **송신 중 도착한 줄은 `pendLine` 에 갇혀 있다가
송신이 끝난 뒤에 처리되므로**(`client.ino:909`) **위험 구간에 도착한 것이 바로 그 이유로 늦게 찍힌다.**

> **재려던 사건을 측정 지점이 밀어낸다.**

이 결함이 만든 것: `위험 구간 [116,171)ms` 폐기 · *"116ms 미만 정상 도착 0건"* 이 발견이 아니라
계측 산물 · monitor 가 `OOW 0` 을 "위상 통과 안 함"으로 읽으려 한 것(socket 의 `OOW 0` + 재전송 2건이 반증).

🔑 **이것이 셋 중 가장 크다.** 이 수정 뒤에 **위험 구간 폭과 진짜 분모가 처음 나온다.**

### ② `cksumng=` 를 `[CNT]` 칸으로 (monitor 요청)

지금은 손으로 찾는다. **창 B 에서 배치가 192B 로 커지면 그럴 수 없고, 그 칸이 없으면
"무손실"이 서버 계수만으로 선언된다** — 창 A 에서 실제로 그럴 뻔했다(서버는 무손실, monitor 는 `CKSUM NG` 4).

⚠ **`DEBUG` 밖에 둬라.** `[CNT]` 의 다른 정수 계수와 같은 규칙이다.

### ③ 지금 칩 상태 기록 (`INTERVENTIONS.md` 사전 기록)

**굽기 전에 적는다.** 그리고 이번 굽기는 **계측기만 바꾼다** — 거동 변경이 아니다.
**그 사실을 기록에 명시해라.** 창 A 와 창 B 사이에 거동 축이 늘면 monitor 가 또 못 가른다.

## 🔴 순서 — 이 굽기는 관측을 멈추고 한다

**새 규약이다**(CLAUDE.md §"프로세스는 자원이 아니다"):

```
① 굽기 직전 한 줄  →  monitor 가 탭·요약기를 내린다
② 굽기            →  자유
③ 완료 통보       →  monitor 가 새 t0 로 창을 연다
```

**①을 보내라.** monitor 는 루트 순서를 기다리지 않고 멈춘다(멈추는 것은 아무것도 안 깬다).

## 굽기 뒤 — **3차 재실행이 세트다**

계측기를 고치는 것은 굽기이고 **굽기는 창을 바꾼다.** 3차 자료(1.15s·300건)와 대조하려면
**같은 조건을 다시 돌려야** 한다 — 안 그러면 "계측기가 바뀐 것"과 "주입 조건이 바뀐 것"이 섞인다.
**네가 그 함정을 짚었고 그대로 채택한다.**

⚠ **다만 3차 재실행의 전제가 있다**: socket 의 **중단 조건 자동 판정**이 들어간 뒤여야 한다.
3차는 링크가 실제로 깨지는 조건이고, 창 A 에서 감시가 없어 조건 충족 후 130건이 더 돌았다.
socket 에 별도로 지시했다 — **네 굽기와 병행 가능하다**(서버 코드다).

## 그 다음이 창 B — 네가 볼 것

창 B 는 **서버 큐 배포**(socket `8bcbd5d` 이상)다. socket 이 예측을 박아 뒀다:
**같은 3차 조건에서 큐가 있으면 오프라인·세션 종료·ACK 실패가 0 이어야 한다.**

**네 계측기가 그 대비의 도구다.** ①②가 없으면 창 B 에서 "좋아졌다"를 서버 계수로만 말하게 된다.

## 창 A 에서 확정된 것 (다시 재지 마라)

- **모듈 리셋 0 / 1,040거래.** 창4 는 84거래에 6~7건. ⚠ **원인 귀속 불가**(축 여섯) · **배수 인용 금지**
- **하행 파괴 4건 · 미도달 1건** → 서버 큐가 필요하다는 실측 근거
- **기전은 버퍼 넘침이 아니다** — 손상이 늘어도 `ssovf` 3 고정 → 동시 송수신 프레이밍 오류
- 🔑 **네 버퍼 보류 판단은 옳았고 논거만 틀렸다** — "넘칠 조건이 없다"가 아니라
  **"넘침이 이 고장의 기전이 아니다"**. 그리고 **28B 기준선이 3 이라 창 B 와 견줄 바닥이 생겼다**
- **`ssovf` 는 하한이다**(`overflow()` 는 읽으면 지워진다). `3` 을 "정확히 3회"로 읽지 마라

## 왜 필요한가

[SLOT-OOW] 오프셋이 도착이 아니라 처리 시각이라 위험 구간을 아직 아무도 모른다 — 그 값 하나가 이미 폐기됐고 monitor 의 위상 판정 근거도 무너졌다. 그리고 cksumng 칸이 없으면 창 B 에서 무손실이 서버 계수만으로 선언된다

### ① `[SLOT-OOW]` 시각 → **첫 바이트 수신 시점** ✅

**구현**: 오프셋을 **첫 바이트를 받는 순간 계산해 저장**한다(`rxLineOff`), `pendLine` 우회로에도
같이 넘긴다(`pendLineOff` → `workLineOff`). `handleLine` 은 그 값을 쓴다.

⚠ **시각(`millis()`)을 저장했다가 나중에 빼면 안 된다** — 그 사이 `statusTick` 이 `slotStart` 를
전진시켜 **언더플로**가 난다(원장 §8.7 의 `lastTxOkAt` 함정과 같은 형태).
→ **뺄셈을 도착 순간에 끝냈다.** 그러면 그 위험이 원천적으로 없다.

🔴 **`oow` 의 정의가 이 굽기에서 바뀐다:**
```
slot2 까지 : oow = 처리 시각이 송신 창 안   ← 위험 구간 도착을 놓친다
slot3 부터 : oow = 도착 시각이 송신 창 안   ← 처음으로 위험 구간을 본다
```
★ **그래서 `slot3` 에서 `oow` 가 오르는 것은 새 고장이 아니라 보이기 시작한 것이다.**
monitor 에 통보했고 그쪽이 기준선을 새로 잡는다(같은 칸 이름으로 이어 세면 안 된다).

### ② `cksumng=` → `[CNT]` (`DEBUG` 밖) ✅

계수는 `DEBUG` 밖, 원문 출력만 안(원장 §8.4-2 의 경계).

### ③ 거동 변경 없음 — 명시했다 ✅

**슬롯 주기(1200) · 송신 창(600) · `SLOT_TX_RESERVE_MS`(200) · 3단 게이트(2000/8000) ·
`BATCH_CAP`(160) · ACK 큐 · `busy` 대응 — 전부 그대로.** 바뀐 것은 **무엇을 언제 재는가**뿐이다.
`INTERVENTIONS.md` 사전 기록에 그대로 적었다.

### 창 A 판정 반영 — 내 논거 하나를 정정한다

*"버퍼 보류는 옳았고 논거만 틀렸다"* — **받는다.** 내가 `ssovf=0` 을 보고 "분모가 없다"고 했는데

실제로 무너졌다. 원장 §10.8-1 에 그렇게 고쳤다. ⚠ **`3` 은 하한이다**(읽으면 지워진다).
