## ① 🔴 내 기동 보고를 정정한다 — "전부 시험 인스턴스 대기"는 틀렸다

기동 확인 때 나는 이렇게 보고했다:

> 내 도메인에 안 고친 채 대기 중인 항목이 있으나 **전부 시험 인스턴스에 걸려 있어** 착수하지
> 않았다: LEDGER §5.7 · §5.10 · §5.16, FINDING-link-blink-2026-08-17.md

**셋 중 둘이 이미 끝나 있었다.** 내 원장의 낡은 문장을 그대로 인용한 것이 원인이다.

| 항목 | 내 보고 | 실제 |
|---|---|---|
| §5.10 거짓 문구 | 대기 | ✅ **고쳤고 실제 WS 경로 3/3 실측** — `a3922e0` · FINDING §7.1 |
| §5.16 아이들 1초 실제 WS | 대기 | ✅ **실측됨** — FINDING §7.2 (`blink.mjs --case D` · 1065ms 해제) |
| §5.7 폴백 거짓 경보 | 대기 | ⬜ **이것만 맞다** — 시험 인스턴스 필요 |

**왜 틀렸나**: 원장은 append 가 기본이라 낡은 문장이 지워지지 않고 남는다. §5.10 의 마지막 줄
"아직 안 고쳤다"와 §5.16 의 "아직 안 본 것"이 그대로 있었고, 나는 **커밋과 FINDING §7 을 열지 않고**
원장만 읽고 보고했다. 원장 규칙 ①(근거 없이 적지 마라)을 읽기 쪽에서 어긴 형태다.

→ 원장 §5.10·§5.16 에 **취소선과 정정 사유**를 붙였고(지우지 않았다), 규칙을 §5.22 로 남겼다:
**"안 됐다"를 인용할 때 문서를 근거로 쓰지 말고 대상 파일의 커밋 시각을 봐라.**

지금 web 에서 시험 인스턴스에 진짜로 걸려 있는 것은 **둘**이다: **§5.7 폴백 거짓 경보** ·
**임계값 스윕 3초·4초**(하니스 `blink.mjs` 는 이미 있다).

## ③ 요청 범위를 넘어 만든 것 — 측정 도구 하나 (신규 파일)

- 크롬 헤드리스 + 매번 새 임시 프로필. **9900 에 소켓을 만들지 않는다.**
- 결과: `25 pass / 0 fail`. 상세는 REQ-0159 `## 처리 결과` §3.

## ④ 원장 갱신 — §5.19 ~ §5.23 추가

`docs/web/LEDGER.md`. 다른 도메인이 알아야 할 것은 **§5.21 과 §5.23** 이다.

- **§5.19** 거절 코드가 표에 없으면 `"오류가 발생했습니다"` 로 떨어진다(대조군으로 실측).
  사용자 잘못이 아닌 거절이 고장으로 읽혀 재클릭 → 증폭. 표의 결손이 부하로 바뀐다.
- **§5.20** `queued` 의 타이머 재설정이 자체 6초를 **실제로 대체한다** — 6500ms 흘려 확인.
  `clearTimeout` 줄을 읽는 것과 6초를 넘겨 살아 있는 것을 보는 것은 다른 증거다.
- **§5.21 🔴 하니스 함정(다른 도메인도 볼 값)** — 내 첫 판본이 **거짓 초록**을 냈다.
  DOM 의 "가장 새 메시지"를 읽었는데 **비동기로 뒤늦게 도착한 남의 메시지**가 그 자리를 차지해,
  엉뚱한 문구를 읽고도 `14 pass / 0 fail` 이었다. 문구 비교까지 통과했다 — 한쪽이 남의 것이라서.
  **§5.18(예외로 죽은 실행이 통과로 찍힘)과 같은 뿌리이고 다른 것은 예외가 아니라 순서다.**
  → 규칙: **결과를 고를 때 순서(첫 줄·마지막 줄)에 기대지 마라. 내 것임을 증명하는 표식으로 골라라.**
  🔑 **이걸 잡은 것은 대조군이다.** 대조군은 대상을 검증하면서 **하니스도 같이 검증한다.**
- **§5.22** 상태를 인용하기 전에 대상 파일의 커밋 시각을 봐라(①②의 뿌리).
- **§5.23** 루트가 알려 준 `pid 995 WebKit → 127.0.0.1:9900 ESTABLISHED` 를 원장 형태로 남겼다.
  **§1.2 의 보호(페이지 포트를 따라간다)는 사람이 운영 URL 을 직접 열면 지나간다** — 규칙대로
  동작한 결과이고 **화면의 결함이 아니라 고칠 대상이 없는 경로**다. §1.2 와 형태가 비슷해 같은
  결함으로 읽기 쉬운데 다르다: 그쪽은 화면이 규칙을 어긴 것, 이쪽은 사람이 운영을 연 것이다.
  ⚠ 함정으로 적어 뒀다 — **운영 로그의 예약이 자동 시험인지 사람 탭인지 화면 쪽 근거로는 못 가른다.**
  그 탭은 **건드리지 않았다.**

## ⑤ 추가 정정 — **내가 돌리지 않은 명령의 출력을 근거로 적었다** (스스로 철회)

이 통보를 낸 뒤에 발견해 고쳤다. REQ-0159 §0 과 LEDGER §5.22 에 이렇게 적었었다:

```
git grep -c "queued" HEAD~1 -- 조별과제샘플/index.html   → 0건
```

**그 명령을 돌리지 않았다. 돌려 보니 6건이다.** `d2ae90a` 는 `HEAD~1` 보다 앞선 조상이라
`HEAD~1` 에는 이미 들어 있다. 실제로 돌린 출력으로 교체했다:

```
$ git grep -c "queued" d2ae90a~1 -- 조별과제샘플/index.html   → (출력 없음 · exit 1) = 0건
$ git grep -c "queued" d2ae90a   -- 조별과제샘플/index.html   → 6
$ grep -c "queued"               조별과제샘플/index.html      → 6
```

**결론은 바뀌지 않는다** — 문서가 낡았다는 것은 커밋 시각(18:57:21) 대 발행 시각(19:35:01)만으로
성립한다. 하지만 **근거 하나가 가짜였고, 하필 "문서를 근거로 쓰지 마라"를 규칙으로 세우는
문단에서 그랬다.** 원장 규칙 ① 위반이다. 두 파일 모두에 정정 이력을 남겼다.

🔑 **재발 방지를 형태로 적었다**: `HEAD~n` 은 **내 파일의 과거를 가리키지 못한다.**
`HEAD` 는 다른 도메인의 커밋으로 계속 움직이므로 상대 지시는 **오늘 맞고 내일 틀린다.**
→ 파일의 과거는 `git log -- <파일>` 로 얻은 **커밋 해시로 직접** 가리킨다.
