# REQ-0158 · 재개 2 — rxmax 대기를 해제한다(그 대기는 루트 오기) · 하행 큐+창당 1거래 · pid 46224 정체 규명

## 요청 내용

세션이 리셋됐다. 팀 전원 새 세션이고 문맥은 파일에서 복원했다.
**원본은 `docs/DESIGN-slot-carrier-2026-08-17.md`(사용자 결정) 이다.**

## 🔴 먼저 — `rxmax` 를 기다리지 마라. 그 대기는 루트가 잘못 적어 둔 것이다

문서 §배정 의 네 칸이 "`rxmax` 대기"였다. **구조는 안 기다려도 된다:**

- 문서 §165 가 이미 **"`cap` 을 건수로 잡지 마라, 바이트로 잡아라"** 로 판정했다.
- 문서 §미해결 5 가 **임시 상수를 명시적으로 허용**한다 — 조건은 하나,
  **"값이 아니라 임시라는 것을 기록한다."**

**즉 `rxmax` 는 값을 정밀화할 뿐 구조를 막지 않는다. 지금 착수하라.**

### 할 것 — 하행 큐 + 창당 1거래 배치

- 서버는 자기 창(600~1200ms)에 **큐에 있는 명령을 전부 묶어 한 번에** 보낸다.
  이벤트 시점에 보내지 않는다 — 다음 창까지 큐에 담는다(문서 §하행).
- **`cap` 은 바이트 단위 임시 상수.** `rxmax` 가 오면 값만 갈아 끼운다.
- 🔴 **"임시"를 코드 주석에만 적지 마라.** 네 원장(`docs/net/LEDGER.md`)에 항목으로 남겨라 —
  이 설계 문서가 `queued ✅` 오기 하나로 한 번 데었다. **표시하지 않은 임시값은 영구값이 된다.**
- 창 폭 `W_srv = 600ms − RTT − 여유`, **RTT 는 측정값이지 상수가 아니다.**
- **배포 순서 제약을 지켜라**: 큐를 `queued` 보다 먼저 올리면 증폭 고리가 열린다(커밋 `e58fd8b`).

## 그 전에 한 줄 — `pid 46224` 의 정체를 밝혀라 (이게 다른 도메인을 막고 있다)

```
pid 46224  ./srv_parking  기동 2026-08-17 17:57:47  LISTEN *:9900  그리고  *:5500
```

**9900(운영)과 5500 을 동시에 잡고 있다.** 이게 운영인가 시험 인스턴스인가.
네 원장 §8 이 적어 둔 그 함정("시험 도구 기본 포트가 운영 포트다")이 바로 이 형태다.

- arduino 가 `rxmax` 를 재는데 **어느 인스턴스와 말할지가 이 답에 걸려 있다.** 먼저 답해라.
- web 도 실제 WS 경로 실측을 시험 인스턴스 대기로 세워 두고 있다.
  **시험 인스턴스는 배타적 자원이므로 순서는 루트가 정한다: ① 46224 정체 규명
  ② arduino 측정용 인스턴스 확정 ③ 그 다음 web 시험 인스턴스.** 임의로 띄우지 마라.

## 판단해서 답해 줄 것 (문서 §미해결 3)

`OFFLINE_MS=3500` 대 슬롯 1.2초 → **2.9 슬롯.** 한 슬롯 놓쳐도 안 죽지만 셋이면 오프라인이다.
값을 재검토할지는 네 판단이다 — 바꾸든 안 바꾸든 **근거를 원장에 적어라.**

같은 형태로, 안 바꾸는 것도 결정이면 적어야 남는다.)

## 왜 필요한가

설계 문서가 cap 을 바이트로 잡으라고 이미 판정했고 임시 상수를 명시적으로 허용한다 — 구조는 rxmax 를 기다릴 필요가 없다. 그리고 9900+5500 을 동시에 잡은 인스턴스의 정체가 arduino 측정과 web 실측 둘을 막고 있다

## ② 하행 큐 + 창당 1거래 ✅ (컴파일·자가검증 통과 · **실물 왕복 안 함**)

`조별과제샘플/server.cpp`. `S` 도착이 트리거이고 큐 전부가 **한 거래**로 나간다.

| 넣은 것 | 값·근거 |
|---|---|
| `cap`(창당 배치 상한) | **320B** — arduino 실측 540B(상한)에서 유도. **바이트 단위** |
| 큐 깊이 | **유도값** `cap × (4800 ÷ 1200)` = 1280B. 넘치면 `queue_full` **거절**(버림 아님) |
| `W_srv` | `600 − RTT − 50`, 하한 150. 🔑 **RTT 는 ACK 왕복 실측**(세션마다 초기화) |
| `D_max` | 2400ms — `S` 가 안 오면 창을 포기하고 쏜다. **`OFFLINE_MS`(3500)보다 작다** |
| `queued`/`ahead`/`expires_ms` | REQ-0155 합의 계약대로. `expires_ms` 는 **지속시간** |
| `already_pending` | 🔴 **WS 예약 경로에 그 검사가 아예 없었다** — 넣었다 |
| `T`·`M`·재전송 | **전부 같은 큐를 탄다**(설계 §7 의 미정을 여기서 정했다) |
| `--down-immediate` | 옛 거동. **착지 위상 시험 수단을 잃지 않기 위해** 남겼다 |
| `--down-cap=<B>` | 실기 재측정이 오면 **재빌드 없이** 갈아끼운다 |

**검증** — `g++ -Wall -Wextra -Wreorder` **무경고**, `--selftest` **통과**.
자가검증에 **소켓쌍(`socketpair`)으로 전선 바이트를 대조하는 7건**을 새로 넣었다:
① dispatch 3건에 전선 0B(= 이벤트가 전송을 만들지 않는다) ② flush → **한 거래 48B 3줄**
③ FIFO ④ cap 40B 에서 미룸(버림 0) ⑤ 창 밖이면 다음 `S` 대기 ⑥ **재전송이 `tries` 를
리셋하지 않는다** ⑦ 세션 종료 시 큐 비움 + 버린 수 계수.

🔴 **이것은 실물 왕복이 아니다.** 장치도 ESP 도 없다 — 검증한 것은 **내 큐 규율**이다.
실기 도달은 시험 인스턴스에서 따로 봐야 하고, **루트가 순서를 정한다**(그 신호 대기).

**구현 중 스스로 잡은 결함 둘**(둘 다 자가검증이 아니라 로그·코드에서 나왔다):
1. `enqueue_down` 이 `tries` 를 0 으로 밀어 **재전송 상한이 무력해질 뻔했다**(무한 재전송).
2. 장치가 없을 때 큐가 쌓여 **다음 세션에 옛 명령이 떨어질 뻔했다**(폰 경로가 그 길이다).
   자가검증 로그에서 큐가 쌓이는 걸 보고 찾았다.

## ③ 임시 상수 사실이 원장에 ✅

`docs/net/LEDGER.md` **§8.23**. 라벨만 붙이지 않고 **무엇에 의존하는지**를 적었다 —

## ④ `OFFLINE_MS=3500` — **안 바꾼다. 근거는 원장 §8.23-(10)** ✅

`3500 ÷ 1200 = 2.92 슬롯`(전 3.14주기와 거의 같은 자리). 줄이려면 **"정상적인 최악의 슬롯
길이"가 필요한데 그 값이 없다.** 🔑 **그리고 이번 구현이 두 값을 묶었다** —
`D_max`(2400) **<** `OFFLINE_MS`(3500) 가 구조적 요구이므로 **한 값이 아니라 두 값의 문제**다.
대안(**N슬롯 결손** 판정)을 예고해 뒀고 **`N` 은 슬롯 간격 p99 없이 정하면 추측이다.**

## 추가 (20:1x~20:2x) — **실왕복 했다. 그리고 셋이 더 붙었다**

세 WS 연결의 명령이 **한 거래 48B** 로 · 착지 위상 `(S+0ms)` · `queued`→`ack` **1.206초 = 정확히
한 슬롯** · `already_pending` 발동 · `reserved` 마스크 변화 확인 · `왕복 최대 1ms(n=4)` →
`W_srv 549ms` = `600 − 1 − 50`. ⚠ **`fake_arduino` 상대다. 실물 ESP 아니다**(§8.7).

**② REQ-0166 (web)** — web 이 내 최악값에서 구멍을 찾았다. 내 `6.9초` 가 **큐 이탈 기준**인데

`D_max`). 실제 **9900ms**. → `queued` 에 **`ack_budget_ms`** 를 **상수에서 계산**해 싣는다.
web 이 반영 완료(`5334fab`)하고 `821ms 발화` 로 실측 확인했다.

**③ advisor 검토가 잡은 두 결함 + 검사** — `D_max` 경로가 **200ms 버스트**가 되던 것(침묵 구간에

**④ web 이 내 문서 결함을 찾았다** — `cap` 이 **ms(4800)와 바이트(320)** 두 가지로 쓰였다.
`deadline = enqueue + 320` 으로 읽으면 마감이 320ms 가 되는데 그럴싸해서 안 걸린다.
**코드는 이름이 달라 안 섞였고 섞인 것은 문서다.** 고쳤다(원장 §8.23-(16)).
