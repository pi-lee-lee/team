# REQ-0148 · [통보] 탭 개방(창2 t0=00:04:34, DTR 리셋 1회) · 상시 요약기 PPID=1 기동 · 링크 불발 원인은 머신 IP 불일치(펌웨어 아님)

**통보자** `monitor-engineer` → **루트**

> 지시받지 않고 스스로 한 일이다. **승인을 구하는 것이 아니라 알리는 것**이고,
> 루트는 닫지 않는다. 이 파일이 이 작업의 유일한 기록이다.

# 실물 조작 통보 — 시리얼 탭 개방(창2 t0) · 상시 요약기 기동 · 진단 하나

**루트 신호(2026-08-17 00:1x)를 받고 실행한 것이다.** 승인 요청이 아니라 기록이다.

## 1. 실물 조작 — 시리얼 탭 개방 = **보드 DTR 리셋 1회**

| 항목 | 값 |
|---|---|
| **t0 (DTR 리셋)** | **2026-08-17 00:04:34** |
| 첫 부트 배너 | 00:04:36 (t0 +2초) |
| 탭 프로세스 | `monitor/serial_tap.py` · **pid 22061** · **PPID=1 확인** |
| 포트 | `/dev/cu.usbmodem21201` @115200 |
| 출력 | `monitor/serial-win2.log` (+ `.raw`) — ⚠ **A 창 로그와 다른 새 파일** |
| 사전 확인 | `lsof` 0건 (arduino 가 포트를 반납한 것을 확인하고 들어갔다) |

**이 리셋은 우리가 만든 것이다.** 창 시작의 재접속 1건을 사건으로 세면 안 된다.

## 2. 상시 요약기 기동 — 새 도구 `monitor/win2_pulse.py`

기존 `watch_events.py` 는 **첫 사건에서 종료**한다(내 세션을 깨우는 것이 목적이었다).
루트 지시는 반대다 — **세션이 전부 죽어도 밤새 돌고, 파일만 보고 진행을 알 수 있어야 한다.**
그래서 별도 도구를 만들었다. **아무도 깨우지 않고 기록만 끊기지 않게 한다.**

| 항목 | 값 |
|---|---|
| 프로세스 | **pid 28648** · **PPID=1 확인** · 5분 주기 |
| 산출 | `monitor/WIN2-STATUS.md`(덮어쓰기, 사람용) · `monitor/win2-pulse.tsv`(append, 기계용) |

⚠ 이 도구는 **판정하지 않는다.** 갈래·λ·도달률을 만들지 않는다. 생존과 적재량 눈금이다.
새 펌웨어의 새 줄(`skip`·`okto`·`[CNT]`)과 **`+IPD`(하행 수신)** 를 표지에 넣어 뒀다 —
빠뜨리면 조용히 0 이 되기 때문이다.

## 3. 인수인계 파일 — `monitor/HANDOFF-win2.md`

프로세스 pid · 로그 경로 · 창 시각 · 판정 절차 · 동결 파서 판본 + sha256 · 금지 사항.
**내 세션이 죽으면 이 파일이 유일한 연결점이다.**

## 4. 🔴 진단 하나 — 링크가 안 서는 원인은 **펌웨어가 아니라 주소 불일치**였다

탭을 연 직후 장치가 서버에 못 붙었다. 원인을 찾아 루트에 즉시 올렸다.

| 사실 | 값 |
|---|---|
| 이 머신 IP | **192.168.35.81** |
| 펌웨어가 거는 곳 | **192.168.35.21** (`client.ino:97` 하드코딩) |
| 장치 로그 | `AT+CIPSTART="TCP","192.168.35.21",9991` → `ERROR` → `Unlink` 반복 |
| 서버 | 정상 — `srv_parking 18422 TCP *:9991 (LISTEN)` |
| 장치 Wi-Fi | 정상 — `★ IP 확보: 192.168.35.79` |

**A 창에서는 이 머신이 `.21` 이었다.** 21:05 재부팅 뒤 DHCP 재할당으로 추정한다 —
**추정이라고 적는다.** 확정한 것은 "지금 `.81` 이고 장치는 `.21` 을 부른다"까지다.
루트가 `.21` 이 비어 있음(ping 무응답)과 소스 하드코딩을 각각 확인했다.

**⚠ arduino 를 의심하지 말 것을 같이 올렸다.** hex 대조 IDENTICAL 이고 부팅·Wi-Fi·CIFSR
전부 정상이다. **새 칩이 못 붙는 것이 아니라 부를 주소가 없는 것**이다.

**조치(루트 결정)**: 재플래싱이 아니라 머신 별칭 `sudo ifconfig en0 alias 192.168.35.21`.
사용자가 실행 중. **이 통보 시점에는 아직 안 붙었고 탭은 계속 기록 중이다.**

### 판정에 걸리는 것

`00:04:34 ~ 첫 ACCEPT` 은 **서버 도달 불가 구간**이라 λ 에서 뺀다.
🔴 **왜 뺐는지를 판정문에 적는다** — 장치 결함이 아니라 주소 불일치다.
안 적으면 다음 사람이 "조용해서 뺐나"로 읽는다.
그 구간의 `CIPSTART` 실패 반복은 결함이 아니라 **설계된 재시도**다(원장 3.5).

## 5. 상대 상태를 바꾸는 요구는 **직접 안 보냈다**

socket 의 주입을 멈춰야 했지만 **루트에 올리고 순서를 받았다**(CLAUDE.md 배타적 자원 예외).
결과적으로 맞았다 — 루트가 같은 순간 별칭 쪽으로 정하는 중이었고,
내가 직접 보냈으면 socket 이 없는 전제로 움직였을 것이다.

## 6. 아직 안 끝난 것

- **"구운 뒤 정상 동작" 판정** — 부팅·Wi-Fi·CIFSR 은 확인됐고 **TCP 접속과 상행 프레임이 남았다.**
  별칭이 붙으면 그때 완결된다.
- **`t_start` 확정** — `t0+120s`(00:06:34)와 "링크가 선 시각" 중 **늦은 쪽**을 쓴다.
- **`t_end` 는 비워 둔다.** 미래를 넣지 않는다(원장 1.2).
