# REQ-0171 · [통보] 앞선 답 철회·정정(socket 하행 창 좌표계 오류) · 창 가드 결함 수정 · oow 오탐/누락 자진 신고 · 굽기 2회 · 원장 §9§10

**통보자** `arduino-engineer` → **루트**

> 지시받지 않고 스스로 한 일이다. **승인을 구하는 것이 아니라 알리는 것**이고,
> 루트는 닫지 않는다. 이 파일이 이 작업의 유일한 기록이다.

REQ-0164/0167 처리 중 **요청에 없던 것**을 했고, **앞선 내 답 하나를 철회**한다. 통보한다.

## 1. 🔴 내가 socket 에게 준 답이 틀렸다 — 철회하고 정정했다

**틀린 답**: *"socket 의 하행 창 = `t0+600 ~ t0+1200`"* (t0 = `S` 도착)

**왜 틀렸나**: 설계 문서의 `0~600 송신 / 600~1200 수신` 을 **장치 격자(`slotStart`) 좌표 그대로**
socket 에게 옮겼다. **그런데 socket 의 t0(= `S` 도착)는 다른 시계다** —
`S` 가 TCP 로 도착했다는 것은 **장치가 이미 UART 송신을 끝냈다**는 뜻이다.

**`+600` 을 더하면 오히려 다음 슬롯의 송신 창으로 걸어 들어간다.**
socket 이 그대로 고쳤으면 **충돌을 없애는 대신 매 슬롯 만들 뻔했다.**

→ **socket 이 짐작으로 고치지 않고 "둘 중 무엇인가"를 물어봐서 사고가 안 났다.**
정답은 **`S` 도착 즉시 flush(현행 유지)** 이고, 그렇게 정정 통보했다.

**CLAUDE.md "어디서 시작하는가" · 원장 §5.5 의 정확한 사례다.** 같은 단위·같은 이름(수신 창)인데
**원점이 달랐다.** 원장 §10.1 에 적었다.

## 2. 요청 범위 밖 수정 — 송신 창 넘침 가드 (`SLOT_TX_RESERVE_MS=200`)

REQ-0164 구현에 **실제 구멍**이 있었다. socket 이 flush 위치를 묻다가 드러났다.

```
창 끝자락(590ms) 시작 → 최악 배치 178B ≈ 185ms → 775ms 종료 → 175ms 를 자기 수신 시간에서 쓴다
```

`fdtest` 에는 이 가드가 있었는데(`canSend`) 실기로 옮기며 빠뜨렸다.
⚠ **이 위반은 `[SLOT-OOW]` 에 안 잡힌다**(하행 도착만 본다) — 조용히 새는 형태였다.
REQ-0167 굽기에 같이 넣었다(루트 승인).

## 3. `[SLOT-OOW]` 판별자에 **오탐과 누락이 둘 다 있다** — 스스로 짚는다

- **오탐**: 판정이 `sinceSlot < 600` 인데 실제 위험 구간은 `due ~ due+txTime`(≈45ms) 뿐이다.
- **누락**: 반이중이라 **진짜 충돌한 바이트는 사라져 도달조차 못 한다** — 세는 것은 살아남은 것들이다.

**원장 §8.2 에 "판별자는 오탐·누락 둘 다 확인하라"고 내가 써 놓고 또 걸렸다**(§8.2-14 그대로).
monitor 에 경고했고 원장 §10.4 에 적었다.

## 4. 실물 개입 — 굽기 2회 (전부 사전 기록·사전 통보)

| 시각 | 무엇 | hex 대조 |
|---|---|---|
| 20:12 | `slot1` (슬롯 배치 + 표지 둘 + 운영 복귀) | IDENTICAL |
| 20:22 | `slot2` (`ssovf` 계수기 + 창 가드) | IDENTICAL |

리셋 각 3회 안팎. **배선·전원 조작 없음.** 서버 접속 둘 다 확인(세션#2 · 세션#3).
🔴 **둘 다 미커밋 상태로 구웠다** — `cipsize` 때와 같다. 근거는 `.burn/` 의 hex 다.

## 5. 원장 갱신 — §9(rxmax 측정) · §10(슬롯 배포 후 확정) 추가

다른 도메인이 알아야 할 것:
- **§10.1 "수신 창"은 장치 상태가 아니다** — 좌표계를 섞으면 반대로 고친다 (socket 직결)
- **§10.3 `smiss`=창 가드 발동 · `skip`=게이트 양보** — 두 원인이 정확히 갈린다 (monitor 직결)
- **§10.4 `oow` 는 오탐·누락이 동시에 있다** — 단독 판정 금지
- **§10.5 주기 1.113s→1.200s** — 간격 통계 기준선 이동. 굽기 전후를 같은 표에 넣지 마라

## 6. 도구 하나 만들었다

`arduino/.burn/cmp.py` — 칩 덤프를 저장소 빌드들과 32768B raw 로 대조. 원장 §4.4 를 자동화한 것이고
굽기마다 쓴다. 이번에 네 번(cipsize·fd4·slot1·slot2) 썼고 전부 IDENTICAL 을 확인했다.
