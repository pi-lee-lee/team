### ⚠ 원문과 다를 수 있는 지점 — 요청대로 남긴다

**(1) 출처가 08-16 12:01 판이 아니라 08-15 16:06 체크포인트다.**
그 사이 이 구간이 **같은 행수로** 수정됐다면 내 재구성은 그 수정을 조용히 되돌린다.
위 근거 3·4가 그 가능성을 크게 줄이지만(이웃 41행 동일·조각 행수 동일) **0 은 아니다.**
다만 SHA-1/base64/체크섬은 자가검증과 실왕복이 값을 직접 확인하므로, 의미 있는 변경이
있었다면 드러났을 것이다.

**(2) 원래 잘라내기가 남긴 흠 두 개를 그대로 재현했다 — 내 판단이 아니다.**
- `base64` 조각(원본 255–284)의 **끝에 타이머 절 주석**("시각 두 갈래" — `now_ms`/`epoch_ms`
  설명)이 딸려 왔다. 설명 대상 코드는 `server.cpp` 에 있는데 **주석만 헤더에 떨어져 있다.**
- 체크섬 조각(원본 326–380)에 **§7.4 재부팅 판정 주석 + `UPTIME_WRAP` + `UPTIME_MAX_FWD`** 가
  들어 있다. 이것들은 주차 도메인 상수지 "디바이스 계층 잎 유틸"이 아니다.
  → **`server_device.h` 가 자기 서두에 쓴 판별 기준("온실·창고였어도 그대로 쓰이는가")을
  스스로 위반한다.**

둘 다 08-16 12:01 잘라내기가 줄번호로 뭉텅이를 뜨면서 생긴 것이다. **고치지 않았다** —
이 요청은 복구지 재설계가 아니고, 지금 손대면 "원문과 같은가"를 검증할 수 없게 된다.
`UPTIME_*` 를 도메인 쪽으로 옮기는 것은 **리팩터 단계 C 에서 별도 판단**할 일이다.
(위 근거 5 대로, 이것들이 원래 조각에 있었다는 것은 추정이 아니라 **컴파일로 증명된 사실**이다.)

**(3) 컴파일 검증의 범위를 정확히 적는다 — ✅ 가 셋 다를 뜻하지 않는다.**
`server.cpp` 가 include 하는 것은 `server_device.h` 하나뿐이므로(지시대로 나머지 둘은 안 걸었다),
**경고 0 으로 완전 컴파일된 것은 `server.cpp` + `server_device.h` 조합이다.**
나머지 둘은 컴파일러가 건드리지 않았다. 그래서 **따로** 문법만 확인했다:

- `g++ -fsyntax-only -std=c++11 -Wall -Wextra -x c++ server_wire.h` → **rc=0**
- `g++ -fsyntax-only -std=c++11 -Wall -Wextra -x c++ server_seam.h` → **rc=0**
  (경고 3건은 `unused function` — 아무도 안 쓰는 헤더를 단독 컴파일해서 나는 것이지 결함이 아니다)

즉 **셋 다 문법적으로 성립하지만, 실사용 검증이 끝난 것은 `server_device.h` 뿐이다.**
나머지 둘은 단계 C 에서 실제로 include 될 때 다시 검증받아야 한다.

**(4) `server_wire.h`·`server_seam.h` 는 제자리에 두되 include 를 걸지 않았다**(지시대로).
루트의 정정 통보대로 `server_seam.h` 는 **갱신본을 받았다 — 추정이 아니라 확인했다**:
복구본이 16:04 에 6021→**6622바이트**로 갱신됐고, 내가 16:06 에 복사한 파일도 **6622바이트**다.
`server_wire.h` 는 양쪽 다 11622바이트로 일치. 두 헤더 모두 표준 헤더(`stdint.h`·`string.h`)만
include 하므로 **존재하지 않는 헤더를 불러오는 곳은 없다.**
