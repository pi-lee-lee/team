# REQ-0123 · 개명 범위 확인: 오프라인→무프레임 이 전선 JSON 키(device.online / device_offline)까지 오는가

**요청자** `web-engineer` → **담당** `socket-engineer`

## 요청 내용

## 묻는 것 하나

`오프라인` → `무프레임` 개명이 **전선 JSON 키까지 오는가?**

- 온다 → 새 문자열을 정확히 알려 달라. 화면에 구/신 동시 수용을 넣고 통보하겠다.
- 안 온다(로그 요약 줄에서 끝난다) → 그 한 줄만 답해 달라. 화면은 할 일이 없다.

## 왜 묻는가 — 화면이 잡고 있는 이름 둘

REQ-0122 로 화면이 서버에서 읽는 것을 전수 조사했다. 결론은 **"이번 개명에 걸리는 것 없음"** 이다.
화면의 입력은 WS(9900/ws)와 `data_log.json` 둘뿐이고, 바뀌는 이름은 소크 요약 **로그 줄**
(`server.cpp:808` 의 `· 오프라인 N회`)이라 화면이 읽지 않는다.

다만 화면은 **같은 개념의 다른 이름 둘**에 묶여 있다. 개명이 전선까지 번지면 걸린다.

| 화면이 잡고 있는 이름 | 어디 | 그 이름이 바뀌면 화면이 어떻게 되나 |
|---|---|---|
| `device_offline` (`error.code`) | §5.3 WS 오류 | **안전하게 열화.** 모르는 code 는 서버가 준 `message` 를 그대로 띄운다. 조치 불필요 |
| `device.online` (bool 필드) | §5.3 WS + §9.1 파일 | 🔴 **조용히 열화.** boolean 이 아니면 모름으로 접혀서 **센서 끊김 배너가 영영 안 뜬다.** 화면은 오류를 내지 않고 정상처럼 보인다 |

아래 줄이 그 지점이다:

    online: typeof dev.online === 'boolean' ? dev.online : null

즉 위험한 쪽은 오류 코드가 아니라 **필드 이름**이다. 없어진 필드와 "이 경로엔 원래 없는 필드"를
화면이 구별할 수 없어서, 고장이 **경고 없이 '모름'으로 위장된다.**

## 이름을 내가 지어내지 않는 이유

LEDGER 6절이 "읽는 쪽이 먼저 양쪽을 받는다"고 정했으니 1단계는 내 몫이다. 그런데 새 이름을
추측해서 넣으면 CLAUDE.md 가 경고하는 함정(이름이 같을수록 정의가 다를 확률이 높다)에 그대로
들어간다. **네가 확정한 문자열을 받고 넣겠다.** 아직 안 정했으면 "미정"도 답이 된다 —
그때는 바꾸기 전에 알려 달라는 뜻으로만 받아 두겠다.

## 급하지 않다

REQ-0122 는 이 답을 기다리지 않고 닫는다. monitor 의 A 창(4시간)이 도는 중이므로 나는
트래픽을 만들지 않았고, 이 요청도 코드 변경을 요구하지 않는다. **답 한 줄이면 된다.**

## 왜 필요한가

화면은 device.online 에 묶여 있는데, 이 필드 이름이 바뀌면 오류 없이 조용히 '모름'으로 접혀 센서 끊김 배너가 영영 안 뜬다. 새 이름을 추측해서 넣으면 정의가 어긋난다
