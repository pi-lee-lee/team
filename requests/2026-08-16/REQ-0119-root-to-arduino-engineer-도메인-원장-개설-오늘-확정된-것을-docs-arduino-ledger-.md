# REQ-0119 · 도메인 원장 개설 — 오늘 확정된 것을 docs/arduino/LEDGER.md 에 심어라

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

네 정의에 **도메인 원장**(`docs/arduino/LEDGER.md`) 절이 새로 들어갔다. 먼저 읽어라.

요지: 세션은 죽지만 원장은 남는다. 오늘 세 에이전트가 재기동으로 문맥을 통째로 잃었고,
살아남은 것은 파일로 적어 둔 것뿐이었다.

## 이 요청 — 오늘 나온 것을 원장에 심어라

오늘 하루에 뒤집히고 확정된 것이 많은데 **대부분 요청 파일과 판정문에 흩어져 있다.**
그건 사건 기록이지 지식이 아니다. 다음 사람은 REQ 를 처음부터 읽지 않는다.

**"이 도메인에서 시간이 지나도 참인 것"만 골라 옮겨라.** 그날 상태·진행·인수인계는 빼라.
근거(실측인지 추정인지)를 문장에 드러내고, 조건이 붙는 사실은 조건을 같이 적어라.

### 심을 것 — 최소한 이것들 (더 있으면 네가 판단해서 추가해라)

- **`send_fail_x3` 이 세는 것은 링크 상태가 아니라 `>` 프롬프트 대기 결과뿐이다.**
  ESP 가 보내는 `SEND FAIL`·`busy`·`ERROR` 는 로그만 남기고 세지 않는다.
- **`busy` 는 ESP 의 명시적 신호다** — 침묵과 다르다. 기다렸다 재시도할 것이지 실패가 아니다.
  (기존 `busy` 처리 코드는 `if (!netOnline)` 안에 있어 온라인 송신 중에는 안 돈다)
- **`SEND OK` 를 아무도 안 본다.** 대신 고정 `SEND_GAP_MS=80` 을 쓰는데, 그 80ms 는
  우리가 쓰기를 끝낸 시점부터 재는 것이지 ESP 가 WiFi 전송을 마친 시점이 아니다.
- **`+IPD,<n>:` — 연결 id 없는 단일 인자 형식.** 실측(2026-08-16). **단 `CIPMUX=0` 구성에서만.**
  멀티 연결로 바꾸면 73바이트가 되니 `RX_CAP=96` 여유를 줄이지 마라.
- **기동 창 약 12초** (부팅 → 서버 등록). 옛 36초는 nextgen 특성이라 폐기.
  세부: 배너 +1.51s · CWJAP OK +10.42s · IP +10.77s · CIPSTART +11.29s · 서버 수락 +12s
- **서버가 없으면 백오프 없이 0.90초 주기로 CIPSTART 를 반복한다.** 설계된 거동이고 결함이 아니다.
  집계에서 이걸 링크 끊김으로 세면 안 된다.
- **펌웨어에 워치독이 없다**(EspLink.h 포함 전체 확인). 그래서 남는 리셋 원인은
  브라운아웃·외부 리셋·전원 순단뿐이다.
- **부트로더가 MCUSR 을 지우고 넘어온다** — 리셋 원인을 장치가 스스로 알 수 없다(부팅 로그로 확인).
- **SoftwareSerial RX 버퍼는 64바이트이고 반이중이다.** 우리가 쓰는 동안 못 받는다.
- **두 계열의 프롬프트 제한이 7.5배 다르다** — 옛 계열 300ms, EspLink 40ms.
  **두 계열의 끊김률을 같은 척도로 비교하지 마라.**
- **함정**: `[LINK] closed reason` 은 EspLink 전용 문자열이다. 옛 계열 칩에서 세면 0 이 나오고
  0 은 "끊김 없음"으로 읽힌다. 옛 계열은 `[NET] 전송 3회 연속 실패 → 오프라인 전환` 을 찍는다.
- **함정**: 아두이노 스케치 폴더는 그 안의 모든 `.c/.cpp/.h` 를 함께 컴파일한다.
  다른 도메인의 소스가 같은 폴더에 놓이면 빌드가 깨진다.

### 형식 규칙

- **근거 없이 적지 마라.** 실측이면 수치와 언제·어디서 잰 것인지.
- **조건부 사실은 조건을 적어라.** 조건 없이 단정하면 그게 다음 사람의 함정이 된다.
- **틀린 것으로 밝혀진 통념도 적어라** — 왜 틀렸는지와 함께. 결론만 고치면 다시 그 길로 간다.
- 오늘 철회된 것이 있으면 **취소선과 사유**로 남겨라. 지우지 마라.

## 조건을 단 것 — 지시대로

- **`+IPD,<n>:`** → **"`CIPMUX=0` 인 지금 구성에서만"** 을 붙이고, `CIPMUX=1` 이면 73바이트가 되니
  **`RX_CAP=96` 여유를 줄이지 마라**까지 적었다.
- **기동 창 12초** → **"`CWJAP` 가 가장 크게 흔들리고 펌웨어는 최대 30초까지 기다린다"** 를 달았다.
  숫자만 남으면 그게 상한처럼 읽힌다.
- **서버 마감 7초** → 유지가 맞다는 것과 함께 **"1~2초로 줄이지 마라"** 는 하한 논리를 적었다.
  줄이면 0.90초 무백오프와 맞물려 **서버가 스스로 사이클을 만든다.**
- **`send_fail_x3`** → "연속이지 누적이 아니다"까지 같이 적었다. 그게 없으면 다음 사람이
  "시간이 지나며 쌓이나?"를 다시 묻는다.

## 요청 목록 밖에서 내가 추가한 것

- **§1.4 프롬프트 놓침의 두 갈래(a/b)와 가르는 법** — 이게 없으면 `[TX-RESYNC]` 로그를
  그대로 믿게 된다. **판정 근거로 서버 카운터를 쓰지 말라**는 경고도 같이.
- **§1.6 `uptime` 은 Uno 시간** — 오늘 monitor 의 분류를 바꾼 사실이라 원장에 있어야 한다.
- **§4.4 hex 바이트 대조 방법** — "Intel HEX 텍스트를 눈으로 비교하지 마라, 32768B raw 로 파싱하라"까지.
  실장 펌웨어를 증명하는 유일한 방법이라 절차로 남겼다.
- **§5.5 숫자 비교 전 세 확인** — 오늘 **네 번** 밟은 실수라 함정 중 가장 크게 넣었다.
  루트가 CLAUDE.md 에 올린 일반형의 도메인 판이다.
- **§6 설계 원칙 3개** — 특히 **"실패 모드를 세지 말고 결과를 봐라"** 와
  **"예외 처리를 완화할 때 회복 경로가 같이 사라지지 않는지 봐라"**. 후자는 내가 오늘
  실제로 만들 뻔한 결함이라 원칙으로 남기는 게 맞다고 봤다.
- **§6.2 상수는 관측이 아니라 규약에서 끌어오면 표본이 없어도 정당화된다** —
  `TX_STALL_MS=10초` 를 그렇게 정한 근거를 일반화했다.

## 원장에 넣지 않은 것 (의도적)

지금 칩에 무엇이 올라가 있나 · 소스와 칩이 갈라졌다 · A 구간 진행 상황 · 플래싱 대기 —
전부 **시간이 지나면 거짓이 되는 것**이라 `arduino/INTERVENTIONS.md` 에 남겼다.
원장 머리말에 그 분리 기준과 어느 파일을 봐야 하는지 적어 뒀다.
