# REQ-0118 · 서버 구조 작업 재개 — 잃은 계획서 복구 · (A) 재부팅 오보 결함 · 리팩터링 단계 C

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

**서버 구조 작업을 재개한다.** 보드도 시리얼 포트도 안 건드리니 관측을 기다릴 이유가 없다.
그리고 **서버 교체는 이제 싸다** — 로그 계약 v1.0 의 인스턴스 경계로 갈리고, 재기동이 보드를
리셋하지 않는다는 것도 오늘 실측으로 확인됐다.

## 0. 먼저 — 사고로 잃은 계획서를 되살려라

`server_seam.h` 주석이 `docs/net/plan-windows-and-mapping.md` §5.7 을 가리키는데
**그 파일이 없다.** 사고 때 사라졌고 아무도 복구하지 않았다. 지금 그 주석은 **없는 문서를
가리키는 포인터**다.

트랜스크립트에 남아 있다. 위치를 준다:

```
~/.claude/projects/-Users-idong-u-learn/363b40c4-6681-4c11-b2e9-762ec7a60627.jsonl
  2721행  Write  9141B  docs/net/plan-windows-and-mapping.md   ← 원문
  2730행  Bash   이후 수정 (python heredoc)
  2765행  Bash   "## 0. 전제가 바뀌었다" 절 교체
  2777행  Bash   `/utf-8` 관련 문장 수정
```

⚠ **Write 만 꺼내면 안 된다.** 그 뒤 Bash 로 세 번 더 고쳤다 — 오늘 `server_seam.h` 에서
똑같이 당할 뻔했다(Edit 이 0건이라 완전해 보였지만 Bash 수정이 있었다). **순서대로 적용해라.**

같은 방법으로 **REQ-0096(리팩터링) 상태**도 되살려라. 단계 A·B 완료와 **단계 C 규모 실측
(이음매 넘는 호출 5곳)** 이 그 세션에 기록돼 있는데 요청 파일이 사라졌다.
복구한 내용은 `docs/net/` 에 두고, 필요하면 `req.sh notice` 로 알려라.

## 1. 우선순위 — (A) 부터

**(A) 세션을 가로지르는 Uno 재부팅 관측 결함.** 이게 먼저인 이유는 **지금 이 순간에도
틀린 자료를 만들고 있기 때문**이다. 오늘 17:21:36 에 서버가 "재부팅 감지"라고 찍었는데
장치는 재부팅하지 않았다(uptime 1286 → 1295). monitor 는 로그 사후 분석으로 갈라냈지만
**서버는 실시간으로 못 가른다.**

- 통계가 `uptime추론 0` 이라 하는데 실제로는 19회 있었다
- 재연결 시 uptime 기준선을 버리는 것이 원인이다
- **monitor 와 맞춰라** — "마감 56건이 재부팅인지 링크 재접속인지" 대조가 같은 지점이다.
  따로 만들면 두 번 만든다.

⚠ 그리고 **지표 이름이 현실을 잘못 부르고 있다.** 서버가 "오프라인"으로 세는 것 상당수가
장치 고장이 아니라 링크 계층 재접속이다(기준선 36건 중 35건). 이름도 같이 손봐라 —
숫자가 맞아도 이름이 틀리면 읽는 사람이 틀린다.

## 2. 그다음 — 리팩터링 단계 C

단계 A·B 는 살아 있다(`server_device.h`·`server_seam.h`, `server.cpp` 2244행).
C 는 이음매를 넘는 호출 5곳을 정리하는 것으로 실측돼 있었다. 복구한 기록을 보고 이어가라.

**조건**: 한 번에 하나씩, 각 단계마다 **빌드 경고 0 + 자가검증 + 실왕복**. 오늘 배운 대로
**여러 변경을 한 교체에 묶지 마라** — 깨지면 어느 것 때문인지 못 가른다.

## 3. 서버 교체 절차 (이제 정착됐다)

1. 교체 전 **루트에 알린다**(사전 통보, 승인 대기 아님)
2. 구 인스턴스는 **SIGTERM 으로 정상 종료** — `INSTANCE-END reason=signal` 이 남아야 한다
3. 새 인스턴스는 경계 줄로 열린다(`logfmt`·pid·build·ports)
4. **세 포트 리슨 + 실왕복 1회** 확인 후 보고
5. monitor 에 교체 시각 통보 — 집계가 인스턴스로 갈린다

## 하지 말 것

- **PAL(REQ-0086) 윈도우 이전은 지금 하지 마라.** 시연 일정이 없다고 사용자가 확인했다.
  급하지 않고, 지금 손대면 리팩터링과 변수가 겹친다. 계획서 복구까지만 해 둬라.
- 보드·시리얼 포트 접촉 금지. arduino 와 monitor 의 영역이고 관측 창이 돌고 있다.

## 왜 필요한가

서버 작업은 보드·포트를 안 건드리니 관측을 기다릴 이유가 없다. 그리고 (A) 결함은 지금 이 순간에도 재부팅 오보를 만들고 있다 — 오늘 17:21:36 이 실물 사례다.
