# REQ-0132 · WS 스냅샷에 last_frame_ts 를 넣어 달라 · GET /?쿼리 가 404 (둘 다 크롬 실측)

## (1) 🔴 WS 스냅샷에 `last_frame_ts` 가 없다 — 신선도 표시가 **주 경로에서만** 안 돈다

### 실측

브라우저가 받은 스냅샷 프레임 원문(`web/artifacts/ws-snapshot.json`)의 `device` 객체:

```json
"device": { "online": true, "device_id": "P1", "uptime": 326, "seq": 326 }
```

같은 순간 파일 폴백(`data_log.json`)의 `device` 객체:

```json
"device": { "online": true, "last_frame_ts": 1786875051474 }
```

그 결과 화면의 "마지막 프레임" 칸에 이렇게 뜬다 — CDP 로 읽은 실제 DOM 문자열이다:

```
"알 수 없음 (이 경로에는 이 정보가 없습니다)"
```

### 왜 문제인가

**폴백에는 있고 주 경로에는 없다.** 즉 신선도 표시는 WebSocket 이 끊겨 파일로 내려갔을 때만
동작하고, **정상 운영 중에는 영영 "알 수 없음"** 이다. 기능이 있는데 평소에 안 도는 것이라
있는 줄 알고 지나치기 쉽다. REQ-0067 이 화면에 신선도를 넣은 이유가
"죽은 데이터를 살아있는 것처럼 보여주지 않는다"였는데, **주 경로에서 그 목적이 미달**이다.

REQ-0122 때 나는 이걸 **코드를 읽어서** 추정만 해 뒀다(`server.cpp:1174-1178`).
오늘 실물로 확인해서 요청으로 올린다.

### 요구

WS 스냅샷의 `device` 에 `last_frame_ts` 를 넣어 달라.

- **키 이름과 단위를 파일 경로와 똑같이** 해 달라 — `last_frame_ts`, epoch **밀리초**.
  이름이 같은데 단위가 다르면 화면은 조용히 틀린 나이를 그린다. 그게 더 나쁘다.
- 값의 정의도 파일 쪽과 같아야 한다("마지막 S 프레임을 받은 서버 시각"으로 이해하고 있다 —
  다르면 알려 달라. **내가 화면에 "N초 전"으로 그리는 값이라 정의가 곧 표시다.**)
- 장치가 한 번도 프레임을 안 준 상태면 `null` 을 달라. 키 자체를 빼면 지금과 같아진다.

화면은 **이미 이 키를 읽고 있다.** 오면 그날로 동작한다. 없으면 지금처럼 "알 수 없음"으로
안전하게 접히므로, 네 쪽 배포 순서가 내 쪽보다 앞서도 깨지지 않는다.

## (2) `GET /?쿼리` 가 404 — `GET /index.html?쿼리` 는 200

### 실측 (같은 서버, 같은 순간)

```
GET /                    → 200
GET /index.html?demo=1   → 200
GET /?demo=1             → 404      ← 이것
```

브라우저에서는 이렇게 보인다: `chrome-error://chromewebdata/` · "127.0.0.1 페이지를 찾을 수 없음".

### 원인 (내 판독 — `serve_file()`)

```cpp
if (path == "/") path = "/index.html";      // ① 쿼리가 붙어 있으면 여기 안 걸린다
...
std::string fn = path.substr(1);
size_t q = fn.find('?');
if (q != std::string::npos) fn = fn.substr(0, q);   // ② 쿼리 제거는 여기
```

`/?demo=1` 은 ① 에서 `"/"` 와 다르므로 index.html 로 안 바뀌고, ② 에서 `?` 앞을 자르면
`fn` 이 **빈 문자열**이 된다 → `ifstream("")` 실패 → 404. **①과 ②의 순서 문제**다.

### 왜 지금 중요한가

시연에서 주소창에 `호스트:9900/?demo=1` 을 치면 **빈 페이지가 뜬다.** 데모 모드는
서버 없이 화면을 보여주는 경로라 시연 대비로 쓸 가능성이 높은데, 그때 `/index.html` 을
빼먹으면 그대로 404 다. 오늘 나도 정확히 여기서 걸려서 시험이 한 번 죽었다.

### 요구

쿼리 제거를 `"/"` 판정 **앞으로** 옮겨 달라(또는 `path` 에서 `?` 이후를 먼저 잘라내고 시작).
그러면 `/?x` · `/index.html?x` · `/data_log.json?t=…` 가 한 규칙으로 처리된다.

### 완료 확인 방법

내 하니스가 이미 이 세 줄을 **매번 검사**한다(`web/tools/e2e.mjs` [9]단계).
지금은 마지막 줄이 빨간색이고, 고쳐지면 **저절로 초록이 된다** — 따로 알려 주지 않아도 된다.

## 참고 — 오늘 확인된 것 (네 쪽 회귀 감시에 써도 된다)

브라우저 구간은 **실제로 동작한다.** 진짜 크롬으로 확인했다:

| 확인한 것 | 결과 |
|---|---|
| 예약 왕복 | 타일 클릭 → `<dialog>` 확인 → `{"type":"reserve","slot":"A1",…}` 송신 → `→ARD R,7,A1,…` → `←ARD A,7,A1,0,36` → ack 수신 → **화면에 "내 예약" 205ms** |
| 취소 왕복 | 같은 칸 재클릭 → "예약을 취소하시겠습니까?" → `→ARD C` → 화면 "빈 자리" 복귀 |
| 폴백 폴링 | WS 를 죽은 포트로 돌리면 `data_log.json` 폴링이 10칸을 채운다 |
| 콘솔 | 예외·오류 0건 |

시험 인스턴스는 계속 쓰고 있다. 끝나면 알리겠다 — **내가 내리지 않는다.**

## 왜 필요한가
