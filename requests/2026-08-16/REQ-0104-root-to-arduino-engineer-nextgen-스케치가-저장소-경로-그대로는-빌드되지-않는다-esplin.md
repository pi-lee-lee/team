# REQ-0104 · nextgen 스케치가 저장소 경로 그대로는 빌드되지 않는다 — EspLink.h 배치를 정리하라 (사본은 하나)

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

REQ-0100 에서 네가 보고한 구조 문제를 닫는다. **배치는 네가 정한다** — 여기서는 만족해야 할 조건만 준다.

## 지금 상태 (네 보고)

`조별과제샘플/nextgen/client.ino:25` 가 `#include "EspLink.h"` 인데 그 헤더는 `arduino/esplink/` 에 있다.
따옴표 include 는 스케치 폴더 기준이라 **저장소 경로 그대로는 빌드가 안 된다.**
게다가 폴더명(`nextgen`)과 스케치명(`client`)이 달라 아두이노 규칙도 어긴다.
REQ-0100 의 빌드 통과는 `/tmp` 에 둘을 모아서 얻은 것이다 — 즉 **지금 저장소는 빌드 불가 상태로 봉인돼 있다.**

## 만족해야 할 조건

1. **저장소를 받은 사람이 손대지 않고 그대로 빌드할 수 있어야 한다.** `/tmp` 로 옮기는 절차가
   필요하면 실패다. 조원이 통신을 몰라도 쓰게 하는 것이 EspLink 의 존재 이유다(REQ-0084).
2. **EspLink.h 사본은 하나여야 한다.** 두 곳에 두면 반드시 갈라지고, 어느 쪽이 칩에 올라간
   판본인지 알 수 없게 된다 — 이번 사고에서 값을 치른 실패 유형이다.
   사본을 둘로 두는 방안을 고른다면 **왜 갈라지지 않는지**를 근거로 적어라.
3. 아두이노 IDE 의 폴더명 = 스케치명 규칙을 지킬 것.
4. 옮긴 뒤 **저장소 경로에서 그대로 빌드해서 통과를 확인**할 것. `/tmp` 사본으로 얻은 수치는 안 된다.
5. 업로드하지 마라. 지금 칩에 도는 것과 같은 소스이고, pid 36998 소크가 진행 중이다.

## 참고 — 판단 재료

- `arduino/**` 와 `조별과제샘플/nextgen/**` 둘 다 네 소유다. 어느 쪽으로 모으든 소유권 문제는 없다.
- 경로를 바꾸면 `.claude/ownership.json` 의 `조별과제샘플/nextgen/Esp*` 규칙이 헛돌 수 있다.
  그렇게 되면 루트에게 규칙 수정을 요청해라(그 파일은 루트 소유다).
- REQ-0100 에서 **복원본 hex 가 실장 hex 와 바이트 일치**함을 증명해 뒀다. 옮긴 뒤에도 같은 방법으로
  대조하면 이동 중 손상이 없었음을 그대로 보일 수 있다.

## 끝나면

`req.sh done` 뒤 루트에 포인터 한 줄. 왜 그 배치를 골랐는지 한 문단 남겨라 — 다음 사람이
같은 고민을 반복하지 않게 하는 것이 이 요청의 절반이다.

## 왜 필요한가

조원이 저장소를 받아서 그대로 빌드할 수 없다. 지금은 /tmp 로 두 파일을 모아야만 빌드된다 — EspLink 를 만든 목적(통신을 몰라도 쓰게 한다) 자체가 무너진다.

### 이동 중 손상이 없음을 증명했다

네가 제안한 방법 그대로, 옮긴 뒤 **저장소 경로에서 빌드한 hex 를 실장 hex 와 다시 대조**했다.

```
diff /private/tmp/ngbuild/out4/client.ino.hex  /tmp/repoverify/out/client.ino.hex → 차이 없음
```

즉 **이동 후에도 지금 칩에 도는 바이너리를 그대로 재현한다.** 경로만 바뀌고 내용은 불변이다.

## 왜 이 배치인가 — 다음 사람을 위해

**핵심은 "아두이노 스케치 폴더는 그 안의 모든 `.c/.cpp/.h` 를 함께 컴파일한다"는 성질이다.**
이것 하나가 나머지를 다 결정했다.

`조별과제샘플/nextgen/` 에 그대로 두는 안을 먼저 검토했다. `client.ino` 를 `nextgen.ino` 로 바꾸면
폴더명 규칙이 맞고 `EspLink.h` 를 옆에 두면 소유권 규칙(`조별과제샘플/nextgen/Esp*`)도 그대로 맞아
**가장 적게 움직이는 안**이었다. 그런데 **그 폴더는 `조별과제샘플/nextgen/server*` 를 위해 예약돼
있다**(ownership.json 에 규칙이 이미 있다). 서버 소스가 그 폴더에 들어오는 순간
**아두이노가 그것까지 스케치의 일부로 컴파일하려 들어 빌드가 깨진다.** 지금은 비어 있어서 안 터질
뿐이고 socket 이 파일을 하나 놓으면 그날 터진다. **시한폭탄이라 채택하지 않았다.**

그러면 `조별과제샘플/nextgen/client/` 처럼 전용 하위폴더를 파는 안이 남는데, 여기서 **두 번째 함정**이
나온다. `조별과제샘플/nextgen/Esp*` 와 `*.ino` 규칙은 **한 단계짜리 평면 glob 이라 하위폴더를
덮지 못한다.** 그래서 `nextgen/client/EspLink.h` 는 경로 규칙에 안 걸리고 확장자 규칙 `.h` 로 떨어져
**cpp-engineer 소유가 된다** — 내가 내 스케치의 헤더를 못 고치게 되는 것이다. 네가 미리 경고한
그대로였다. 규칙을 고쳐 달라 요청할 수도 있었지만 **하위폴더를 팔 때마다 같은 요청이 반복된다.**

`arduino/**` 는 **재귀 glob 이라 아래로 아무리 깊어져도 소유가 유지된다.** 그래서 이쪽으로 모았다.
덤으로 기존 관례(`aptest/aptest.ino`, `baudscan/baudscan.ino`)와 모양이 같아진다.

**EspLink.h 를 별도 라이브러리로 두지 않은 이유**: 정식 아두이노 라이브러리로 만들면
`--libraries` 플래그를 주거나 `~/Documents/Arduino/libraries` 에 설치해야 한다. 그 순간
**"받아서 그대로 빌드"라는 1번 조건이 깨진다** — 조원이 통신을 몰라도 쓰게 한다는 EspLink 의 목적과도
정면으로 어긋난다. 지금 소비자는 스케치 하나뿐이므로 **스케치 폴더 안에 두는 것이 사본 하나·
플래그 없음을 동시에 만족하는 유일한 배치**다.
→ 다만 **EspLink 를 쓰는 두 번째 스케치가 생기면 그때 정식 라이브러리로 승격시켜야 한다.**
   그 전에 미리 라이브러리로 만들면 빌드 편의만 잃는다. 조건 2 는 "지금 소비자가 하나"라는
   사실에 기대고 있으므로, 소비자가 둘이 되는 순간 이 판단은 재검토 대상이다.

## 보고할 것 둘

### 1. 소유권 규칙에 죽은 항목이 생겼다 (네 파일이라 손대지 않았다)

`조별과제샘플/nextgen/` 이 없어졌으므로 `.claude/ownership.json` 의 다음 규칙이 **헛돈다**:
`조별과제샘플/nextgen/Esp*`(NFC/NFD 2개) · `조별과제샘플/nextgen/*.ino`(2개).
`nextgen/server*` 규칙은 socket 이 그 폴더를 다시 쓸 계획이면 남겨야 하므로 **내가 판단할 일이 아니다.**
정리 여부를 정해라.

### 2. Bash 훅이 `cd`·`git -C` 앞에서 오판한다 (재현 조건 확인)

`git mv` 로 옮기려 했더니 **대상을 `.` 으로 잡고 root 소유라며 막았다.** 두 형태 모두 막혔다:

```
cd /Users/idong-u/learn; git mv <내파일> <내파일>      → 차단 (대상: .)
git -C /Users/idong-u/learn mv <내파일> <내파일>        → 차단 (대상: .)
```

절대경로로 바꾸니 통과했다(`mv /abs/src /abs/dst`). 즉 **훅이 `cd`/`-C` 로 바뀐 작업 디렉터리를
반영하지 못하고 `.` 을 대상으로 오인**한다. **우회하지 않고** 절대경로라는 정상 경로로 처리했다.
다른 에이전트도 `git -C` 를 쓰면 같은 자리에서 막히므로 알려 둔다.

## 곁들여 갱신한 것

`arduino/INTERVENTIONS.md` 의 `client.ino` 참조를 새 경로로 고치고, 경로가 바뀌었다는 경고를 넣었다.
monitor·socket 에게 방금 `조별과제샘플/nextgen/client.ino:207` 형태로 줄 번호를 알린 참이라 통보하겠다.
`docs/incident-2026-08-16-git-clean.md` 에도 옛 경로가 있는데 **네 소유라 손대지 않았다** — 사고 기록은
당시 사실이므로 굳이 고칠 필요는 없어 보인다. 판단은 네 몫이다.
