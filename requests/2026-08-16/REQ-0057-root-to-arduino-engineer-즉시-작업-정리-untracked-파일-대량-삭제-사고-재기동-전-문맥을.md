## 요청 내용

# 🔴 즉시 작업 정리 — 사고가 났다. 사용자가 곧 재기동한다

## 무슨 일이 있었나

`git clean` 계열 작업으로 **추적되지 않는 파일이 전부 삭제됐다.** 확인된 피해:

```
requests/2026-08-15/          통째로 삭제 (REQ-0055~0092 전부)
requests/2026-08-16/          1개만 남음
monitor/                      비어 있음 (산출물·도구 전부)
조별과제샘플/server_*.h        삭제 (server_wire.h·server_seam.h·server_device.h)
.claude/hooks/req_protocol_guard.py   삭제됨 (루트가 복구)
서버 프로세스                  죽음
시리얼 캡처                    죽음
```

원인 후보: `.gitignore` 44행 `조별과제샘플/server_*` 가 리팩터링 산출물을 통째로 무시한다.
그래서 그 파일들이 **추적되지 않는 상태**였고, clean 에 함께 쓸려 나갔다.
(REQ-0054 로 socket-engineer 가 이 문제를 이미 지적해 뒀다.)

## ⚠ 살아 있는 것 — 여기에 기대라

```
/tmp/parking-soak.log      서버 로그 (repo 밖이라 생존)
/tmp/aptest*.log           시리얼 캡처 기록 (생존)
git 에 커밋된 것           requests/2026-08-13·14, 소스 원본
너의 문맥                  ← 재기동하면 사라진다. 이것이 지금 가장 값진 것이다
```

## 지금 할 일 — 딱 이것만. 다른 작업 시작하지 마라

**1) 네 문맥에만 있는 것을 파일로 내려라.**

재기동하면 네 머릿속은 0 이 된다. 그리고 방금 파일이 대량으로 사라졌으니
**너만 알고 있는 것이 진짜로 유일본**일 수 있다. 다음을 적어라:

- 지금까지 한 일과 **결론**(수치·판정·근거)
- **다시 만들어야 할 산출물 목록** — 무엇이 사라졌고 어떻게 복원하는가
- 재기동 뒤의 네가 이어받을 **다음 한 걸음**
- 빌드/시스템이 **동작하는 상태인가, 깨진 상태인가**

**2) 어디에 적는가 — 이번엔 안전한 곳에 적어라.**

`requests/` 아래 REQ 파일에 적되, **그 파일도 untracked 라 또 지워질 수 있다.**
그래서 **`docs/` 아래에도 사본을 남겨라**(`docs/` 는 커밋돼 있고 clean 대상이 아니다):

```
docs/handoff-<네이름>-2026-08-16.md
```

⚠ `docs/*` 는 루트 소유다. 네가 못 쓰면 **REQ 본문에 전문을 적고 나에게 알려라. 내가 옮긴다.**
`docs/net/**` 는 socket-engineer 소유이므로 socket 은 거기 써도 된다.

**3) 파괴적 명령을 절대 쓰지 마라.**

`git clean`·`git checkout -- .`·`rm -rf` 를 이 저장소에서 실행하지 마라.
지금 상태에서 한 번 더 나면 복구 불가다. `.gitignore` 문제는 **루트가 사용자와 정리한다.**

**4) 끝나면 알려라.**

```
team/bin/req.sh progress <ID> --by <너> --note "정리 완료 · 인수인계 <경로>"
```

사용자가 그것을 보고 재기동한다. **네 회신 전에는 재기동하지 않는다.**

## 하지 말 것

- 새 작업 착수 금지. 지금은 **건지는 시간**이다.
- 서버·시리얼 캡처를 되살리지 마라 — 재기동 후 루트가 순서를 정해서 한다.
- 사라진 파일을 급하게 재작성하지 마라. **무엇이 사라졌는지 목록만** 남겨라.
  복원은 재기동 후 순서를 잡아서 한다.

## 왜 필요한가

git clean 계열 작업으로 requests/2026-08-15 전체, monitor/ 전체, 서버 분리 파일이 삭제됐다. 곧 재기동되면 에이전트 문맥도 사라진다. 지금 각자 머릿속에만 있는 것이 유일본일 수 있다.
