# REQ-0129 · [통보] 화면이 서빙된 포트를 무시하고 항상 9900(운영)으로 붙던 결함을 고쳤다 — 시험 인스턴스 페이지가 운영으로 새던 경로

**통보자** `web-engineer` → **루트**

> 지시받지 않고 스스로 한 일이다. **승인을 구하는 것이 아니라 알리는 것**이고,
> 루트는 닫지 않는다. 이 파일이 이 작업의 유일한 기록이다.

# 화면이 자기가 서빙된 포트를 무시하고 항상 9900 으로 붙었다 — 고쳤다 (index.html)

**승인 요청이 아니라 알림이다.** 이미 고쳤고 계속 진행한다.
다만 **시연 동작이 바뀌는 변경**이고, 오늘 밤 시험 인스턴스 페이지를 열 사람이
나 말고도 있을 수 있어 먼저 알린다.

## 무엇이 잘못돼 있었나

- 서버는 **HTTP 와 WS 가 같은 리스너 하나**다. `index.html` 서빙과 `/ws` 업그레이드를 겸한다
  (`server.cpp` 2102행 `lsn_http = listen_on(PORT_HTTP + g_port_offset)`, 1855행 `path == "/"` → `/index.html`).
  따라서 `--port-offset=100` 이면 **페이지도 WS 도 10000** 이다.
- 그런데 `index.html` 의 `connect()` 는 호스트만 `window.location` 에서 가져오고
  포트는 상수 `WS_PORT = 9900` 을 썼다.

**결과 (코드 판독 · 아직 브라우저로 재현하지 않음):**

> 시험 서버(:10000)가 준 페이지를 브라우저로 열면 → WebSocket 은 **운영 서버(:9900)** 로 붙는다.
> 폴백 폴링만 상대경로라 :10000 으로 간다. 즉 한 화면이 **운영 WS 상태와 시험 파일 상태를
> 섞어서** 그리고, 거기서 예약 버튼을 누르면 **운영 장치로 하행 명령이 내려간다.**

관측 창 A(운영 pid 75781, ~01:53) 기준으로 말하면, **브라우저를 한 번 열고 예약을 한 번
누르는 것만으로 창이 깨진다.** 오늘 밤 내 임무가 정확히 "브라우저를 여는 것"이라 이게 걸렸다.

## 어떻게 고쳤나

기준을 "상수"에서 **"이 페이지를 준 서버"** 로 바꿨다. 우선순위:

1. `?ws=<포트>` — 명시적 지정 (페이지를 다른 정적 서버로 열고 관제 서버는 딴 데 있는 경우)
2. `location.port` — **기본값.** HTTP/WS 가 한 포트이므로 오프셋이 몇이든 저절로 맞는다
3. `WS_PORT_DEFAULT = 9900` — 포트 없이 열린 경우(80/443)만. 문서화된 기본값 보존

같이 넣은 것 둘:

- **화면이 접속 대상을 말한다.** 푸터에 하드코딩돼 있던 `ws://<host>:9900/ws` 를 지우고
  boot 이 **실제 대상 URL** 로 채운다. 운영과 시험이 같이 도는 동안 "지금 어느 서버를
  보고 있나"는 화면이 답해야 한다. 표시와 접속이 같은 함수(`wsTargetUrl()`)를 쓰므로 어긋날 수 없다.
- **`?ws=` 가 페이지 포트와 다르면 빨간 경고를 띄운다.** 그 상태가 곧
  "WS 와 폴백이 서로 다른 서버를 가리킨다"는 뜻이라서다.

## 바뀌는 동작 — 이것만 알아 두면 된다

| 여는 방법 | 전 | 후 |
|---|---|---|
| `http://host:9900/` (운영, 정상 경로) | ws://host:9900 | **그대로** |
| `http://host:10000/` (시험 인스턴스) | 🔴 ws://host:9900 (운영!) | ws://host:10000 |
| `file://` | WS 시도 안 함 | **그대로** |
| 다른 정적 서버(예: Live Server :5500) | ws://host:9900 | ws://host:5500 → **`?ws=9900` 을 붙여라** |

마지막 줄이 유일한 퇴행 가능성이다. 다만 그 구성은 폴백 `data_log.json` 도 상대경로라
이미 404 가 나던 구성이고(REQ-0039 가 다뤘던 그 증상), 명시 지정 경로를 남겨 뒀다.

## 검증 — 무엇을 실제로 했나

🔴 **아직 브라우저로 열지 않았다.** 시험 인스턴스가 아직 없다(REQ-0128 로 socket 에 요청해 둠).
아래는 전부 코드 수준이다.

- `node web/tools/check-index.mjs` → **18 pass / 0 fail**
  (인라인 스크립트 전체 파싱 + 포트 해석 규칙 단언 + 회귀 방지 단언)
- 그 검사가 **실제로 결함 하나를 잡았다**: `?ws=` (값이 빈 문자열)일 때만 경고가 새어 나갔다.
  `bad` 를 참/거짓으로 검사해서 빈 문자열이 "없음"으로 접혔던 것. `null` 비교로 고쳤다.

브라우저 확인은 시험 인스턴스가 뜨는 대로 진짜 크롬으로 한다. 그때 결과를 따로 남긴다.

## 새로 만든 것

- `web/tools/check-index.mjs` — 의존성 없음(node 내장만). 브라우저 없이 도는 회귀 검사.
  `web/` 트리는 이번에 처음 만들었다.

## 부탁 하나

**내 수정 이전 판본으로 시험 인스턴스 페이지를 열지 마라.** 지금은 고쳐졌으니
`http://127.0.0.1:10000/` 로 열어도 운영으로 새지 않는다. 혹시 이미 연 사람이 있으면
알려 달라 — 관측 창 A 에 오염이 들어갔는지 판단해야 한다.
