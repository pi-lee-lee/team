## 2. 🔴 잡은 것 셋 — 읽고 썼으면 셋 다 놓쳤다

### (1) `INSTANCE-END reason=signal` 은 **존재하지 않는 값**이다 — 루트 파일 둘이 틀렸다

- `docs/RESUME-2026-08-16.md` §7-3 → *"SIGTERM"* 절차의 근거로 쓰임
- `requests/.../REQ-0118.md` §3-2 → **"`INSTANCE-END reason=signal` 이 남아야 한다"**

**소스에 그 문자열이 없다.** `server.cpp` 가 내는 값은 둘뿐이다:
`reason=normal`(L2556) · `reason=port_bind_fail`(L2151).
SIGTERM·SIGINT 는 둘 다 `g_stop=1` 로 **정상 루프 종료**를 타므로 `normal` 이 맞는 결과다.

**실측**: `pkill -TERM` → `=== INSTANCE-END logfmt=3 pid=59954 stop=2026-08-16T23:35:31+0900
reason=normal frames=0 sessions=0 ===`

⚠ **그대로 따랐으면**: 배포 중 구 인스턴스를 SIGTERM 한 뒤 `signal` 을 찾다가 못 찾고
**멀쩡한 정상 종료를 실패로 판정**했을 것이다. 새벽에 그 오판이 나면 되돌리기까지 갔을 수 있다.

🔴 **두 파일 다 내 소유가 아니다**(`docs/*` · `requests/**` 의 REQ 본문).
**루트가 고쳐야 한다.** 내 절차서 §4.1 에는 정정과 근거를 적어 뒀다.

### (2) `net/ws_probe.py` 의 `--port` 기본값이 **9900 — 운영 포트**다

`fake_arduino.py` 도 기본값이 **9991**(운영 아두이노 포트)이다.
즉 **시험 절차 안에 운영 접촉 경로가 숨어 있다.** `--port` 를 빼먹은 사람은
"시험한다"고 생각하면서 운영에 붙는다.

- 지금은 절차서 §3.1 · §8 에 **명시 경고**로 막아 뒀다(내 도구이므로 기본값 자체를
  바꿀 수도 있지만, **오늘 밤 배포 직전에 도구를 건드리지 않는다** — 변수를 늘리는 짓이다).
- **A 창을 깬 web REQ-0129 와 같은 형태의 함정이다**(포트 상수가 운영을 가리키던 건).
  거기서는 `index.html` 이 `9900` 을 박아 뒀고, 여기서는 파이썬 기본값이 그렇다.
  **포트 분리·`flock`·`chmod` 잠금을 전부 통과하는 경로**라는 점까지 같다.

### (3) 운영에서 **화면이 안 뜬다** — `GET /` 는 cwd 에 걸려 있다 (결정 필요)

`serve_file()` 은 **현재 작업 디렉터리 기준 상대경로**로 파일을 연다.
`data_log.json` 쓰기도 마찬가지다. `--webroot` 옵션은 **없다.**

| cwd | `data_log.json` | `GET /` |
|---|---|---|
| `~/parking-bin` (**직전 운영과 동일**) | `~/parking-bin/data_log.json` | **404** |
| `조별과제샘플/` | 레포 안에 씀 | 200 |

→ REQ-0132 의 `/?demo=1` 404 를 고쳤어도 **운영에서는 여전히 화면이 안 뜬다.**
RESUME §2 가 "시연 경로 결함 둘"이라 부른 것 중 **둘째가 이번 배포로 안 고쳐진다.**

**내 기본 선택: 직전과 동일하게 `~/parking-bin` 에서 띄운다.**
cwd 를 바꾸면 `data_log.json` 경로가 이동해 **폴백 경로와 관측 기준선이 같이 움직인다** —
배포 하나에 변경 둘을 묶는 짓이다(LEDGER §6). **화면 서빙은 `--webroot` 로 별건 처리한다.**
**다르게 하려면 지시해라.** 지시가 없으면 위 기본으로 간다.

## 3. 배포 준비 상태 — **커밋까지 끝났다. 신호만 기다린다**

```
build=22f788d   (조별과제샘플/ 워킹트리 깨끗 — `-dirty` 아님)
빌드            c++ -std=c++11 -O2 -Wall -Wextra  → 경고 0
자가검증        통과 (WS 벡터 · 체크섬 22종 · §7.4-A 8종 · §7.4-B 4종)
시험 왕복       세 포트 · 예약 왕복(ack result=0 + reserved 마스크 A1:01) · HTTP 4종 200
```

⚠ **소스는 이미 커밋돼 있었다** — `server.cpp` 최종 커밋은 `4d31341` 이고 그 뒤 변경이 없다.
따라서 "배포 전 커밋" 단계에서 **내가 새로 만든 커밋은 없다.** `22f788d` 는 현재 HEAD 다.

**이번 배포에 들어가는 것 넷**: 이음매 1 상행 4/6 이관 · `DEV_ACK`(격리 검증 완료) ·
(A) 재부팅 판정 `up < G` · REQ-0132 둘.

**신호를 받으면** §4.1(b) → §4.2 → §4.3 → §4.4 → 통보 순으로 친다.
**§4.1 은 (b) 갈래다** — 선행 인스턴스가 없다(75781 은 21:05 재부팅으로 사망).
그 죽음은 **`INSTANCE-END` 가 아니라 pid·포트로** 확인한다. SIGKILL 류 죽음은 END 줄을
남길 기회를 안 주기 때문이다(LEDGER §1.2).

🔴 **배포 통보에 "A 창과 합산 금지"를 적는다** — 이음매 1 이 아두이노 상행 경로를 건드렸고
**그 경로가 바로 재고 있는 대상**이다.
