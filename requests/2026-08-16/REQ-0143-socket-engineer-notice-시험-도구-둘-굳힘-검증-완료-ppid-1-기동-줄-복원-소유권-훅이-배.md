# REQ-0143 · [통보] 시험 도구 둘 굳힘(검증 완료) · PPID=1 기동 줄 복원 · 소유권 훅이 배포 기동을 막는다(루트 결정 필요)

# 시험 도구 두 개를 굳혔다(검증 완료) · PPID=1 기동 줄 복원 · 🔴 배포를 막는 것 하나

창 개방 전 작업 ①②③ 완료. **남은 것은 ④ 하행 주입 계획**(monitor 와 정의 맞추는 중).

---

## 1. `ws_probe.py` · `fake_arduino.py` — 기본값 제거 + 운영 포트 거부

**둘 다 `--port` 를 필수로 바꿨다.** 기본값이 각각 9900·9991(운영)이었다.

### 막는 방식이 둘로 갈린다 — 일부러 그렇게 했다

| 도구 | 운영 포트 정책 | 이유 |
|---|---|---|
| `fake_arduino.py` | **전면 차단. 탈출구 없음** | 가짜 장치를 운영에 붙일 정당한 이유가 **존재하지 않는다.** 가짜 S 프레임이 운영 로그에 들어가면 **사후에 진짜와 구별되지 않는다** — 되돌릴 수 없는 오염이다 |
| `ws_probe.py` | **상태 변경은 전면 차단**(플래그로도 안 열림) · **관측은 `--allow-production` 명시 시 허용** | A 창을 깰 뻔한 것은 관측이 아니라 **예약 한 번**이었다. 그래서 막을 것은 "운영 접속"이 아니라 **"운영에 상태 변경을 쏘는 것"** 이다 |

⚠ **`ws_probe` 의 관측까지 전면 금지하지 않은 이유**: 새벽에 운영을 들여다볼 정당한 이유가
실제로 생기는데, 그때 도구가 무조건 거부하면 **사람이 압박 속에서 그 파일을 고치게 된다.**
그게 더 나쁘다. 탈출구를 **좁게, 시끄럽게** 두는 편이 낫다고 판단했다.

### 검증 — 네가 조건으로 단 것 (전부 실행)

**둘 다 시험 인스턴스에서 정상 동작한다:**

- `fake_arduino --port 10091 --start-empty` → 1Hz 프레임 정상
- `ws_probe --port 10000 --reserve B3` → ack `result=0` → **`B3:01` 마스크 변화 확인**

**막는 것도 실제로 막는다(종료 코드까지 확인):**

| 시도 | 결과 |
|---|---|
| `ws_probe` (포트 없음) | argparse 거부 · **exit 2** |
| `ws_probe --port 9900` | 거부 · **exit 2** |
| `ws_probe --port 9900 --reserve A1 --allow-production` | **거부** — 플래그로도 안 열린다 · exit 2 |
| `ws_probe --port 9900 --allow-production` (관측만) | **통과** — 경고 찍고 접속 시도(9900 비어 있어 ConnectionRefused) |
| `fake_arduino` (포트 없음) | argparse 거부 · **exit 2** |
| `fake_arduino --port 9991` | 거부 · **exit 2** |

🔑 **덤으로 결함 하나를 고쳤다**: 두 도구 다 `main()` 의 반환값을 버리고 있어서
**거부해 놓고도 종료 코드가 0** 이었다. 감싼 스크립트에는 성공으로 보인다.
`sys.exit(main() or 0)` 로 고쳤다 — **거부는 코드로도 말해야 한다.**
(원장 §5.2 "0 이 무엇인지 안 갈리는 자리"의 또 다른 형태다)

## 2. PPID=1 분리 기동 — 복원했고 **실제로 검증했다**

절차서 §4.3.1 에 넣었다. 추측이 아니라 오프셋 +300 으로 띄워 본 결과다.

```bash
cd ~/parking-bin
nohup ./srv_parking >/dev/null 2>/Users/idong-u/parking-bin/stderr.log &
```

검증: `PID 94308 · PPID 1` · fd1 → `/dev/null` · fd2 → `stderr.log`(**0바이트**) ·
fd3/4 → 서버 자기 로그 · 세 포트 리슨. **직전 운영 인스턴스와 같은 모양이다** —
`~/parking-bin/stderr.log` 가 0바이트인 것이 이 구조의 증거였고, 재현으로 확인됐다.

`--port-offset` 없이 그냥 `./srv_parking` 을 치면 **세션에 매달린다.** 7~8시간 무인 창에서
tmux 종료·에이전트 재기동이 일어나면 서버가 같이 죽고, **monitor 에게는 원인 불명의 정지로 보인다.**
그래서 §4.4 확인 항목을 셋 → **넷**으로 늘렸다(`PPID=1` 추가).

## 3. 🔴 배포를 막는 것 — 소유권 훅이 그 기동 줄을 거부한다

**내가 위 명령을 치면 훅이 막는다. 실제로 막혔다:**

```
[소유권 차단] 너의 역할=socket-engineer · 이 파일의 소유자=root
  대상: ~/parking-logs/detach-test.stderr.log
  근거: 규칙 없음 → 기본 소유자
  탐지: 출력 리다이렉션으로 남의 영역 파일에 쓴다
```

`~/parking-bin/**` 과 `~/parking-logs/**` 는 **소유 규칙이 없어 기본 소유자 `root`** 다.
서버 프로세스가 자기 `fopen` 으로 쓰는 것은 훅이 안 보지만, **셸 리다이렉션은 막는다.**

**선택지 둘 — 네가 정해라. 나는 우회하지 않는다:**

1. **네가 기동 명령을 직접 친다.** 가장 단순하고 규칙을 안 건드린다.
   대신 **배포 시각을 네가 잡게 된다** — monitor 의 t0 도 거기서 나온다.
2. `.claude/ownership.json` 에 `~/parking-bin/**` · `~/parking-logs/**` 를
   `socket-engineer` 소유로 추가한다. **그 파일은 너만 고칠 수 있다.**

⚠ 2번이 맞다고 보지만 **내가 정할 일이 아니다.** 그리고 지금 규칙을 고치는 것은
창 개방 직전의 변경이라 1번이 더 안전할 수 있다 — 판단은 네 것이다.

⚠ **훅 동작 하나 더 알아 둬라**: 훅은 **상대경로를 프로젝트 루트 기준으로 해석한다.**
`cd` 한 디렉터리 기준이 아니다. `조별과제샘플/` 에서 `2>server_test.stderr.log` 를 썼더니
`learn/server_test.stderr.log` 로 판정해 막았다. **오판은 아니지만 놀랄 자리다.**
