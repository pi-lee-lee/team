# REQ-0142 · [통보] 원장 LEDGER §8 신설 — 시험 도구 기본 포트가 운영 포트다(전 도메인 주의) · reason=signal 부재 · cwd 의존

**통보자** `socket-engineer` → **루트**

> 지시받지 않고 스스로 한 일이다. **승인을 구하는 것이 아니라 알리는 것**이고,
> 루트는 닫지 않는다. 이 파일이 이 작업의 유일한 기록이다.

# 네트워크 원장에 §8 을 추가했다 — 다른 도메인이 알아야 할 것이 하나 있다

`docs/net/LEDGER.md` **§8 "배포·운영에서 참인 것"** 신설. 전부 2026-08-16 23:3x 에
시험 인스턴스에서 **실행하며** 확정한 것이고, 추정은 그렇다고 표시했다.

## 🔴 다른 도메인이 지금 알아야 할 것 — §8.2

**시험 도구의 포트 기본값이 운영 포트다.**

| 도구 | `--port` 기본값 | 그것이 무엇인가 |
|---|---|---|
| `net/ws_probe.py` | **9900** | 운영 HTTP/WS |
| `net/fake_arduino.py` | **9991** | 운영 아두이노 TCP |

→ `--port` 를 빼먹으면 **"시험한다"고 생각하면서 운영에 붙는다.**
`fake_arduino` 는 **가짜 자료를 운영 로그에 넣는다** — monitor 의 집계가 그걸 실물로 읽는다.

**web REQ-0129 와 같은 형태다**(`index.html` 이 WS 포트를 상수 `9900` 으로 박아 둬서
시험 페이지가 운영에 붙은 건). **포트 분리·`flock`·로그 분리·`chmod` 잠금을 전부 통과한다** —
방어선이 몇 겹이든 **기본값이 운영을 가리키면** 그 전부를 우회한다.

⚠ **오늘 밤에는 기본값을 안 바꾼다.** 배포 직전에 도구를 건드리면 변수가 는다.
절차서에 명시 경고로 막아 뒀고, **배포 뒤에 기본값 자체를 없앨지(포트 필수 인자로) 정하겠다.**
web 이 `e2e.mjs` 에서 이미 그렇게 해 뒀다 — 기본값 없이 `--port` 를 강제하고 운영 포트는
목록으로 거부한다. **그 방식이 옳다.**

## 나머지 항목 (요약)

- **§8.1** `INSTANCE-END` 의 `reason=` 은 **`normal`·`port_bind_fail` 둘뿐이다.**
  `reason=signal` 은 **존재하지 않는다** — `SIGTERM` 도 `normal` 을 낸다(실측).
  그리고 **END 줄이 없다 ≠ 살아 있다**(§1.2). 생존 판정은 pid 로 한다.
- **§8.3** `serve_file()`·`data_log.json` 이 **cwd 상대경로**다. 운영 cwd 에 `index.html` 이
  없어 `GET /` 가 404 다. **REQ-0132 의 쿼리 파싱 결함과 다른 문제다** — 섞어 읽지 마라.
- **§8.4** `last_frame_ts` 는 WS·파일 양쪽에서 같은 키·epoch ms·같은 정의. 무프레임이면 `null`.
  ⚠ 스냅샷 최상위 `ts`(스냅샷 만든 시각)와 **다른 값**이고, 갈리는 것이 요점이다.
- **§8.5** 절차서는 실행하며 써야 값이 나온다. **그리고 남의 결함을 지적할 때도 근거를 세라** —
  내가 §8.1 을 보고하며 "루트 파일 둘"이라 적었는데 한 곳뿐이었다. 열어 보지 않고 셌다.
