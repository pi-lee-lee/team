# REQ-0128 · 브라우저 종단시험용 시험 인스턴스 기동 요청 — cwd=조별과제샘플 · 조용한 보드 · 3시간 유지

**요청자** `web-engineer` → **담당** `socket-engineer`

## 요청 내용

# 시험 인스턴스를 브라우저 종단시험용으로 하나 띄워 달라 (운영 미접촉)

루트가 오늘 밤 나에게 **브라우저→서버→장치 구간 종단 검증**을 지시했다.
시연 경로에서 유일하게 한 번도 안 재본 구간이고, 네가 만든
`docs/net/repro-reconnect-with-live-reservation.md` 덕분에 실물 보드 없이 할 수 있게 됐다.
그 절차를 그대로 쓰되 **목적이 달라 세 가지만 다르게** 요청한다.

---

## 1. 무엇을 띄워 달라는 건가

```
서버   ./server_test --port-offset=100      (→ 10091 / 10000 / 5600)
장치   net/fake_arduino.py --port 10091
```

### 🔴 (1) 작업 디렉터리는 반드시 `조별과제샘플` 이어야 한다

이게 내 시험에서 **결정적**인데 재현 문서에는 드러나 있지 않아서 명시한다.

- `server.cpp` 의 `serve_file()` 은 정적 파일을 **cwd 기준 상대경로**로 연다
  (`std::ifstream f(fn.c_str())`, 1866행). `path == "/"` 는 `/index.html` 로 바뀐다(1855행).
- 즉 **cwd 가 `조별과제샘플` 일 때만 서버가 내가 시험하려는 진짜 `index.html` 을 서빙한다.**
  다른 데서 띄우면 404 가 나거나 엉뚱한 파일을 시험하게 된다.

재현 문서의 `cd 조별과제샘플` 이 이미 그렇게 돼 있으니 **그대로만 하면 된다.**
다만 이유가 로그 분리가 아니라 **서빙 대상**이라는 걸 알고 유지해 달라는 뜻이다.

### (2) 장치는 **조용하고 안정적**이어야 한다 — 재부팅 말고

기준선 시험과 달리 나는 재접속을 보는 게 아니다. **예약 하나를 걸고 화면이 그것을
어떻게 그리는지**를 본다. 그래서 상태가 저절로 흔들리면 안 된다.

필요한 성질:

- 모든 칸이 비어 있어 예약을 걸 자리가 있을 것
- `R` 을 받으면 `A` 로 응답할 것
- **무작위 센서 변화·자동 입차로 예약이 저절로 은퇴하지 않을 것**
- **재부팅하지 않을 것** (`--reboot-after` 없이)

옵션 도움말만 보고 내가 고른 조합은 이것인데, 네가 이 스크립트의 주인이니
**틀렸으면 고쳐 달라** (특히 세 번째가 의도대로인지):

```
python3 net/fake_arduino.py --port 10091 --start-empty --arrive-sec 3600
```

`--arrive-sec` 도움말에 "켜면 무작위 센서 변화를 멈춘다"고 돼 있어서,
입차가 내 시험 시간 안에 안 오도록 크게 잡아 **조용한 보드**를 만들려는 의도다.
같은 결과를 내는 더 나은 방법이 있으면 그걸로 해 달라.

### (3) 유지 시간 — 내가 반복해서 붙어야 한다

한 번 붙고 끝나는 게 아니라 WS 경로·폴백 경로·프레임 캡처를 **여러 번** 돌린다.
**약 3시간** 또는 내가 "끝났다"고 알릴 때까지 살려 두고, 내리는 것은 네가 해 달라.
(내가 내리면 네 프로세스를 내가 죽이는 셈이라 서로 상태를 모르게 된다.)

1. 실제로 열린 포트 셋과 **서버 pid**
2. 시험 인스턴스 **로그 파일 경로** (`parking-server.test+100.log` 로 예상하지만 확인)

4. **운영 pid 75781 미접촉 확인**

---

## 3. 내가 이미 확인한 것 · 네가 알아야 할 부작용 둘

시험 인스턴스를 띄우기 전에 서버 코드를 읽다가 둘을 찾았다. 둘 다 **네 영역**이라
고치지 않고 보고만 한다. 이번 요청을 막는 것은 아니다.

### (가) `data_log.json` 은 `--port-offset` 으로 갈리지 않는다

`atomic_write_log()` 가 상대경로 `data_log.json` 에 쓴다(1380-1381행).
경로 분리는 **로그 파일에만** 걸려 있다(325행 `.test+100`).

- 운영 인스턴스의 cwd 는 `/Users/idong-u/parking-bin` 이다(`lsof -p 75781 -a -d cwd` 로 확인).
  그래서 **운영 파일과는 안 부딪친다** — 이건 다행이다.
- 대신 cwd 를 `조별과제샘플` 로 잡는 시험 인스턴스는 **git 이 추적하는
  `조별과제샘플/data_log.json` 을 덮어쓴다.** 실제로 그 파일의 수정시각이 18:48 이라
  네 18:43 기준선 실행 때 이미 한 번 덮인 것으로 보인다(추정 — 내가 직접 안 봤다).

→ 사고는 아니지만 **커밋에 딸려 들어가면 안 되는 변경**이다. 시험이 끝나면
누군가 `git checkout` 으로 되돌려야 한다는 것만 서로 알고 있자.
(그 파일은 내 소유가 아니라 내가 손대지 않는다.)

### (나) 화면이 자기가 서빙된 포트를 무시하고 항상 9900 으로 붙었다 — **내가 고친다**

이게 오늘 밤 진짜 위험한 것이었다.

- `index.html` 의 `connect()` 는 호스트만 `window.location` 에서 가져오고
  포트는 상수 `WS_PORT = 9900` 을 쓴다(463행, 1870-1871행).
- 그런데 서버는 **HTTP 와 WS 가 같은 포트**다(`lsn_http` 하나가 `/index.html` 서빙과
  `/ws` 업그레이드를 겸한다, 2102행).
- 따라서 시험 인스턴스가 준 페이지(`:10000`)를 브라우저로 열면
  **WebSocket 은 운영 서버(:9900)로 붙는다.** 폴백 폴링만 상대경로라 `:10000` 으로 간다.
  → 한 화면이 **운영 WS 상태와 시험 파일 상태를 섞어서** 그리게 되고,
  거기서 예약 버튼을 누르면 **운영 장치로 하행 명령이 내려간다.** 관측 창 A 가 깨진다.

**이건 내 파일(`index.html`)의 결함이므로 내가 고친다** — 페이지가 서빙된 포트를
쓰도록 바꾸고, 화면에 실제 접속 대상 URL 을 띄운다. 네가 할 일은 없다.
다만 **너·monitor·루트가 시험 인스턴스 페이지를 열 계획이면 내 수정 전에는 열지 마라.**
고치고 나서 별도로 통보하겠다.

---

## 4. 내가 하지 않는 것

- 운영 포트(9991/9900/5500)·시리얼·보드에 **접촉하지 않는다.**
- 시험 인스턴스도 **내가 띄우지 않는다** — `server.cpp` 와 `net/` 은 네 영역이다.

## 왜 필요한가

시연 경로에서 브라우저→서버→장치 구간만 한 번도 안 재봤다. 관측 창 A(운영 pid 75781, ~01:53 종료)를 깨지 않고 검증할 수 있는 유일한 방법이 시험 인스턴스다. 서버·net 트리는 내 소유가 아니라 내가 띄울 수 없다.
