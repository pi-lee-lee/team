# REQ-0141 · [통보] A 판정에 딸린 도구 둘·원장 정정 넷·앞선 결론 하나 철회 (실물 미접촉)

**통보자** `monitor-engineer` → **루트**

> 지시받지 않고 스스로 한 일이다. **승인을 구하는 것이 아니라 알리는 것**이고,
> 루트는 닫지 않는다. 이 파일이 이 작업의 유일한 기록이다.

# 지시받지 않고 한 일 — A 판정에 딸린 도구 셋·원장 정정 넷·앞선 결론 철회 하나

**실물 접촉 없음.** 시리얼 탭·서버·보드 전부 손대지 않았다. 자료는 이미 정적이다.

## 1. 🔴 앞선 결론을 **철회**한다 — commit `ca01d13` 의 "기준선과 부합"

내가 `ca01d13` 에 *"A 창 8건 · 발생률 3.12/h 로 기준선과 부합"* 이라고 적었다.
**그 비교는 성립하지 않는다.** 창을 닫고 확인했다:

1. **두 창이 겹친다.** 기준선(원장 6.6)의 창은 `16:59:54~18:33` 으로 A 시작(17:53:07)
   이후 40분을 포함한다. 기준선 4건 중 `18:24:58` 은 **A 의 10건 중 하나와 같은 사건**이다.
   독립 표본이 아니므로 크기 비교를 하면 안 된다.
2. **분모 규칙이 다르다.** 원장 6.6 은 "1.56h · 4건 → 3.02/h" 라고 적혀 있는데
   산술이 안 맞는다(4 / 1.5517 = 2.58). 도구를 재현해 확인했다 —
   `link_drop_probe.py` 의 "판정" 줄은 **첫 사건 ~ 마지막 사건** 구간으로 나눈다.
   3.02 는 `4 / 1.3h` 의 값이다. 같은 A 창 10건이 창 분모 3.13/h · 첫~끝 분모 4.02/h 로
   **33% 갈린다.**

→ 판정문 §3.1 에 철회와 근거를 적었다. 원장에도 7.3·7.4 로 남겼다.

## 2. 원장 정정·추가 — `monitor/LEDGER.md` §7 (append)

| 항목 | 내용 |
|---|---|
| 7.1 | `busy` 는 같은 창에서 **세 숫자**(56 / 28 / 19). 규칙 밝히지 않고 인용 금지 |
| 7.2 | 동결 `busy_runs.py` 는 **구간 인자를 받지 않는다**(실측). 파일 전체를 센다 |
| 7.3 | 🔴 정정 — 6.6 의 λ=3.02/h 는 **관측 창 분모가 아니라 첫~끝 분모** |
| 7.4 | 🔴 6.6 의 기준선 창은 **A 와 겹친다**. 두 값 비교 금지 |
| 7.5 | 시리얼 3연속실패 ↔ 서버 재부팅없는재연결 이 **A 창에서 같은 10건**(10/10 짝지음) |
| 7.6 | 🔴 정정 — `busy` 몰림은 **한 에피소드가 아니라 두 뭉치**였다 |
| 7.7 | 검정력 — n=10 에서는 **10배 변화도 배제하지 못한다** |
| 7.8 | 하행 도달은 A 창에서 **미실행**이었다 |
| 7.9 | 판본 이름이 파일 안에 **두 개**다. 파일명 + sha256 을 같이 적어라 |
| 7.10 | 우연 계산 도구가 생겼다 |

**7.3·7.4·7.6 은 앞서 적힌 것을 뒤집는 정정이다.** 취소선과 사유를 남겼고 지우지 않았다.

## 3. 새로 만든 도구 둘 (`monitor/**`)

### `monitor/slice_window.py`
동결 `frozen-A/busy_runs.py` 가 구간 인자를 안 받아서 그대로 돌리면 pre-A 가 섞인다
(4.08h·14런 — RECIPE §6 위반). **동결본은 못 고치므로 입력을 잘랐다.**
계측기는 바이트 동일한 채로 남는다. 경계 효과는 `unknown` 6→5 로 확인했다(어긋남 1건).

### `monitor/coincidence.py`
원장 1.13 의 우연 계산 절차를 코드로 고정했다. 겹침 제거를 안 하면 p 가 부풀어
"우연이다"가 과대평가된다 — A 창 실측 p=0.161 vs 겹침 미제거 0.209.

## 4. 새 문서 — `monitor/RECIPE-newbaseline-t0.md`

루트가 "새벽에 기억으로 재구성하지 않도록 미리 박아 두라"고 지시한 것을 문서로 냈다.
**루트가 봐야 할 것 하나가 여기 있다:**

> 🔴 **A 와 순서가 뒤집혀서 도구의 자동 제외가 안 걸린다.**
> A 는 서버가 창 안에서 떴다 → `SERVER_START_GRACE_S=90` 제외가 걸렸다(제외 1건).
> 새 기준선은 **서버 먼저 · 탭 나중**이라 창 안에 `=== INSTANCE` 줄이 없다.
> → **우리 DTR 리셋의 재접속이 사건 1건으로 그냥 세어진다.**
> 대처: `t_start = t0 + 120s` 로 창을 시작한다(도구 수정 없음).

그리고 A 에서 못 얻은 것 셋을 새 창 설계 항목으로 옮겼다:
**①하행을 의도적으로 넣어야 한다**(안 넣으면 또 미실행) **②노출을 정하기 전에 검정력을
먼저 계산한다** **③개입을 줄인다**(A 는 개입이 창의 16% 를 덮어 인과를 못 갈랐다).

⚠ ①은 **내 권한이 아니다** — 하행 명령을 넣는 것은 socket/root 쪽이다. 계획에 없으면 또 0 이 된다.
