# REQ-0120 · 도메인 원장 개설 — 오늘 확정된 것을 docs/net/LEDGER.md 에 심어라

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

네 정의에 **도메인 원장**(`docs/net/LEDGER.md`) 절이 새로 들어갔다. 먼저 읽어라.

요지: 세션은 죽지만 원장은 남는다. 오늘 세 에이전트가 재기동으로 문맥을 통째로 잃었고,
살아남은 것은 파일로 적어 둔 것뿐이었다.

## 이 요청 — 오늘 나온 것을 원장에 심어라

오늘 하루에 뒤집히고 확정된 것이 많은데 **대부분 요청 파일과 판정문에 흩어져 있다.**
그건 사건 기록이지 지식이 아니다. 다음 사람은 REQ 를 처음부터 읽지 않는다.

**"이 도메인에서 시간이 지나도 참인 것"만 골라 옮겨라.** 그날 상태·진행·인수인계는 빼라.
근거(실측인지 추정인지)를 문장에 드러내고, 조건이 붙는 사실은 조건을 같이 적어라.

### 심을 것 — 최소한 이것들 (더 있으면 네가 판단해서 추가해라)

- **로그의 모든 줄에 날짜가 있어야 한다.** 없으면 시:분:초를 오늘로 읽어 **반드시 오독한다** —
  2026-08-16 에 두 사람이 각각 당했다(하루 전 줄을 당일로 읽고 "두 프로세스 동시 기록"이라 판단).
- **인스턴스 경계 줄**(`=== INSTANCE` / `INSTANCE-END`)이 없으면 누적 카운터가 섞인다.
  `logfmt`·pid·기동시각·바이너리·빌드·포트·offset 을 남긴다.
- **한 로그 파일에 두 인스턴스가 쓰지 못하게 `flock` 으로 막는다.** 규칙이 아니라 기계다.
- **`UNKNOWN_TIMEOUT_MS = 7초`는 옳은 값이다.** 그 마감이 재는 구간은 `accept → 첫 프레임`
  (실측 최대 1.0초)이지 부팅 창이 아니다. 장치가 WiFi·IP 를 끝낸 뒤 TCP 를 열기 때문에
  **부팅 지연은 마감 시계에 안 들어온다.**
  🔴 **줄이지 마라** — 1~2초로 낮추면 정상 세션을 끊고, 장치가 0.90초 무백오프로 재접속해
  **서버가 44초 사이클을 스스로 만들어 낸다.** 7초는 실측 최악의 7배이고 그 여유가 함정과의 거리다.
- **`W` 프레임과 `server_wire.h` 디코더는 EspLink 계열 산물이다.** 옛 계열 칩은
  `R·C·T·M` 만 받고 `W` 는 버린다. 칩이 아는 말로 걸어야 경로를 재는 것이지,
  모르는 말로 걸면 파서를 재는 것이다.
- **하행 형식**: `R,<rid>,<slot>,<user_id>,<cksum>` / `C,<rid>,<slot>,<cksum>` (server.cpp:1301)
- **"오프라인"으로 세는 것 상당수가 장치 고장이 아니라 링크 계층 재접속이다** —
  기준선 13.92h 의 새 연결 36건 중 35건. 첫 프레임 uptime 이 계속 커진다(126 → 34,541).
- **승격 전 소켓의 줄은 어느 카운터도 올리지 않고 버려진다**(server.cpp:2156-2176).
  그래서 **서버측 `버린줄 0` 은 "안 왔다"의 증명이 못 된다.** 이제 `승격전버림` 으로 갈린다.
- **함정**: 재연결 시 uptime 기준선을 버려서 재부팅과 링크 재접속을 실시간으로 못 갈랐다.
  통계가 `uptime추론 0` 이라 해도 실제로는 있었다(사후 분석 19회).

### 형식 규칙

- **근거 없이 적지 마라.** 실측이면 수치와 언제·어디서 잰 것인지.
- **조건부 사실은 조건을 적어라.** 조건 없이 단정하면 그게 다음 사람의 함정이 된다.
- **틀린 것으로 밝혀진 통념도 적어라** — 왜 틀렸는지와 함께. 결론만 고치면 다시 그 길로 간다.
- 오늘 철회된 것이 있으면 **취소선과 사유**로 남겨라. 지우지 마라.

## 판단해서 더 넣은 것

**§5 "반복된 실패형"** — 지시 목록에 없었지만 이게 가장 값진 절이라고 봤다. 개별 사실은
코드를 읽으면 다시 찾을 수 있지만, **"우리가 어떤 식으로 틀리는가"는 겪어야만 알 수 있다.**
오늘 같은 형태의 오류가 네 번 났고 그게 우연이 아니다:

1. 서로 다른 것을 재는 두 지표를 **총계로 비교**하기 (하루에 4회)
2. `0` 이 건강인지 미실행인지 **못 셈**인지 구별 안 하기
3. 관측 구간에 **무슨 일이 있었는지 모르고** 집계하기
4. 사고 직후 피해 목록을 **검증 없이 인용**하기
5. 복구된 기록을 **지도로** 쓰기

**§6.1 "배포 전 커밋"** — 방금 루트가 확정한 규칙이라 바로 심었다. `build=…-dirty` 면
도는 것이 어느 소스인지 특정 불가라는 것, 그리고 **소스가 앞선 구간의 조용한 위험**까지 적었다.
