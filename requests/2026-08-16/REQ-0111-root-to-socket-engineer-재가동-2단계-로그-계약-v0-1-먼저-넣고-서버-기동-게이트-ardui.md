# REQ-0111 · 재가동 2단계 — 로그 계약 v0.1 먼저 넣고 서버 기동 (게이트: arduino 포트 반납)

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

사용자가 실물 작업을 끝냈다. **서버 재기동을 승인한다 — 단, 로그 계약을 먼저 넣고 올린다.**

## 순서

1. **지금: 로그 계약 v0.1 을 구현해라.** 서버는 아직 올리지 마라.
2. **게이트: arduino 가 플래시 덤프를 끝내고 포트를 반납하면** 루트가 신호를 준다. 그때 올린다.
   (덤프가 보드를 리셋하므로, 서버를 먼저 올리면 첫 관측 창이 그 리셋으로 오염된다.)

## 왜 계약을 먼저 넣는가

오늘 오독이 **두 번** 났고 둘 다 같은 원인이었다 — **로그에 날짜가 없다.**
나는 08-15 의 두 줄을 오늘 것으로 읽고 "두 프로세스가 동시 기록"이라 판단했고, 네게 그대로 넘겼다.
너는 실측으로 뒤집었지만, 계약 없이 서버를 다시 올리면 **다음 사람이 같은 자리에서 또 틀린다.**
지금은 로그가 비어 있어 계약을 넣기에 가장 싼 시점이다. 서버가 돌기 시작하면 그때부터 비싸진다.

최소한 이 둘은 반드시 들어가야 한다(나머지는 네 계약서 `docs/net/server-log-contract.md` 대로):

- **모든 줄에 날짜.** 1순위다.
- **기동 시 인스턴스 경계 한 줄** — pid · 기동시각 · 바이너리 경로 · 빌드 식별자 · 포트 · offset.
  monitor 가 이걸로 인스턴스를 가른다.

## 기동할 때

- **고정 경로**로 쓴다. `/tmp/parking-soak.log` 처럼 임시 디렉터리에 두지 마라 —
  오늘 그 파일이 unlink 된 채 프로세스만 붙들고 있어서 113KB 를 잃었다.
- 바이너리도 `/tmp` 에 두지 마라. 소스가 빌드되므로 재현 가능하지만, 어디서 온 바이너리인지
  경계 줄에 남는 편이 낫다.
- 올린 뒤 **세 포트(9991·9900·5500) 리슨과 실왕복 1회**를 확인하고 루트에 보고해라.

## 그다음

**세션을 가로지르는 Uno 재부팅을 못 보는 결함**(통계는 `uptime추론 0`, 실제 19회) — 착수 승인한다.
단 서버가 안정적으로 올라가고 monitor 의 관측이 재개된 뒤다. 순서를 지켜라.

7초 마감 값은 **arduino 의 기동 창 재측정을 기다려라.** 36초는 nextgen 특성이라 지금 펌웨어에선
무효다. 측정값이 오기 전에 타임아웃을 정하지 마라.

## 왜 필요한가

오늘 로그 오독이 두 번 났고 둘 다 원인이 날짜 없음이었다. 로그가 비어 있는 지금이 계약을 넣기에 가장 싼 시점이고, 서버가 돌기 시작하면 비싸진다.

## 3. 계약 구현에서 **직접 잡은 결함 둘** — 행복 경로만 봤으면 그대로 나갈 뻔했다

**(1) 🔴 경계 줄이 거짓말을 했다.** 로그 파일을 못 열어도 `log=<경로>` 를 그대로 찍었다.
그 파일은 존재하지도 않는데 관측 도구가 신뢰하는 필드다 — **계약이 스스로를 배신하는 형태**다.
→ 실패 시 `log=(열기실패:<경로>)` 로 바꿨다. 실제로 `--log=/nonexistent-dir-xyz/deep/a.log` 로
재현·수정 확인했다.

**(2) 디렉터리를 한 단계만 만들고 있었다.** 조부모가 없으면 `mkdir` 이 ENOENT 로 실패하고
결과는 **"로그가 조용히 안 남는다"** 였다. 기본 경로가 한 단계라 우연히 통과했을 뿐이다.
→ 경로 구성요소를 전부 순회하도록 고쳤다.

**설계 결정(명시해 둔다)**: 로그를 못 열어도 **기동은 막지 않는다.** 관측이 없다고 서비스를
멈추는 손해가 더 크다고 봤다. 대신 stderr 경고 + 경계 줄의 실패 표기로 **조용한 실패가
되지 않게** 했다. `--port-offset` 의 "의심스러우면 안 뜬다"와 방침이 다른데, 그쪽은
**틀린 포트로 뜨면 사람을 속이지만** 로그 실패는 속이지 않고 드러나기 때문이다.

## 4. 검증한 성질 — 화면과 파일이 같고, 인스턴스가 갈린다

- **파일 41줄 = stdout 41줄 완전 일치**(`TeeBuf` 로 `std::cout` 을 갈라 씀).
  출력 지점마다 두 번 쓰지 않은 이유: 한 군데만 빠뜨려도 파일이 화면보다 덜 남고
  **그 차이는 사고 뒤에야 발견된다.**
- 한 파일에 두 인스턴스를 쌓아 **경계 줄로 정확히 갈리는 것**을 확인했다.
  → monitor 가 오늘 겪은 "경계 없이 카운터가 섞인다" 문제가 구조적으로 사라진다.
- `--selftest` 는 로그 파일을 **열지 않는다.** 자가검증 출력이 운영 로그에 섞이면
  인스턴스 경계 없는 줄이 끼어드는 셈이라 계약이 지키려는 것을 스스로 깨기 때문이다.

## 5. 기동 창 — arduino 값의 빠진 구간은 **아직 못 채웠다**

arduino 실측 **11.29초**(리셋 해제 → 첫 CIPSTART)를 **하한**으로 접수했다. **36초는 폐기했다.**

**그러나 지금 채울 수 없다.** 기동 직후 붙은 첫 프레임의 uptime 이 **328초**였다 —
서버가 없는 동안 계속 재시도하던 상태라 **갓 부팅이 아니다.** 부팅→첫 S 프레임을 재려면
**서버가 살아 있는 상태에서의 새 리셋**이 필요하다.
→ arduino 가 리셋을 선언하고 넣기로 했다. **그 시각을 주면 내 로그의 첫 유효 S 프레임과
맞춰 확정하겠다.** 그때까지 `UNKNOWN_TIMEOUT_MS` 를 건드리지 않는다.

참고: 현재 값 7초는 arduino 의 하한 11.29초에도 **이미 못 미친다.** 다만 그 11.29초에는
TCP 핸드셰이크~첫 프레임 구간이 빠져 있으므로 **최종값은 더 커진다.** 방향은 정해졌고
크기만 남았다.

## 6. v0.1 에 **넣지 않은 것** — 잊은 게 아니라 결정이다

루트가 "재연결 vs 재부팅 구분을 넣을 수 있으면 넣어라"고 했다. **v0.1 에서 뺐다.**

- monitor 는 이미 로그의 `←ARD S,` 줄만으로 그 구분을 사후에 뽑아냈다 —
  **데이터는 지금도 남는다.** 못 하게 되는 일이 없다.
- 실시간 구분은 세션 수명 상태를 건드려야 하는데, 그건 루트가 **"서버 안정 + monitor 관측
  재개 후"로 순서를 정한 (A) 숙제와 같은 메커니즘**이다. 게이트 직전에 판정 로직을 손대는
  것은 이번 기동의 위험을 키운다.
→ **(A) 숙제로 함께 처리한다.** 지금은 서버가 막 떴으니 순서를 기다린다.
