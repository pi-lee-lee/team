# REQ-0240 · 🔴 :9900 이 내주는 index.html 이 a3922e0(08-17) 판이다 — 배포 단계 누락인가 유물인가

**요청자** `root` → **담당** `web-engineer`

## 요청 내용

## 실측 — 서버가 내주는 화면이 **08-17 판**이다

루트가 `b0d58d9` 배포를 확인하다가 곁가지로 찾았다. **전부 실측이다:**

```
서빙 실체 : /Users/idong-u/parking-bin/index.html   127,344B   2026-08-17 12:56
저장소 최신: 조별과제샘플/index.html                196,739B   2026-08-19 06:22
일치 커밋  : a3922e0 (2026-08-17 08:34) — 서빙본과 바이트 동일
```

**서빙본에서 새 화면의 표지가 하나도 안 잡힌다:**
```
             서빙본   저장소본
zones          0        13
open_gate      0         4
completion     0         1
module         0         (있음)
```

**기전**(socket 소스 · `조별과제샘플/server.cpp`):
```
3576  if (path.empty() || path == "/") path = "/index.html";
3583  std::string fn = path.substr(1);
3585  std::ifstream f(fn.c_str(), ...);   ← 🔴 **cwd 상대경로. 폴백 없음**
3587  if (!f) → 404
```
**서버 프로세스의 cwd 는 `/Users/idong-u/parking-bin`** 이다(`lsof -p 62347 -d cwd` 로 확인).
즉 **`parking-bin/index.html` 이 실기 화면이고, 그 파일은 08-17 이후 갱신된 적이 없다.**

## 🔴 그래서 묻는 것 — **의도인가, 배포 단계가 빠진 것인가**

두 갈래이고 내가 정할 수 없다. **`.html` 은 네 소유다.**

**ⓐ 배포 단계 누락** — 서버 바이너리는 socket 이 `parking-bin` 으로 갱신하는데
   **화면은 아무도 안 옮긴다.** 그러면 `IMPL-PLAN 4`(격자·모듈 행·버튼 분리·차단봉)가
   **실기 화면에 하나도 안 올라가 있다.**

**ⓑ :9900 화면은 이미 쓰지 않는 것** — 실제 화면은 다른 경로로 연다(네 개발 서버 등).
   그러면 `parking-bin/index.html` 은 유물이고 **문서가 그렇게 안 적혀 있는 것**이 문제다.

## ⚠ 왜 이제야 나왔나 — 이게 이 결함의 성질이다

**네 하니스(`live-map.mjs`)는 WS 로 직접 붙는다.** 그래서 `state.zones[...].actions` 를 정확히
읽었고 **37 pass 도 진짜다.** 🔴 **그런데 하니스는 `index.html` 을 한 번도 안 가져온다.**

> ### **계측 경로(WS)와 실기 경로(브라우저가 받는 HTML)가 다르다.**
> ### **그래서 통과 수가 멀쩡한 채로 화면이 이틀 전 판일 수 있다.**

CLAUDE.md §"시험 경로 ≠ 실기 경로"의 **③번 얼굴**(가장 조용한 것)에 가깝다 —
시험이 실패하지 않고 **실기만 빈다.** 아무 신호도 없다.

## 완료 기준

1. **ⓐ/ⓑ 중 어느 것인지 답한다.**
2. **ⓐ면**: 화면이 어떻게 실기에 올라가는지 **절차를 정하고 문서에 적는다**(누가·언제·어디로).
   🔴 **절차만 적지 말고 그것을 볼 자리를 만들어라** — CLAUDE.md §"조건을 적었으면"의 셋째다.
3. 🔴 **판본을 값으로 확인할 수단을 페이지에 넣어라.**
   서버는 `srv_id` 를 준다. **화면에는 그런 것이 없어서 이 결함을 아무도 못 봤다.**
   빌드 해시든 커밋 짧은해시든, **`curl` 한 번으로 판정되는 표지**여야 한다.
   그러면 다음부터 "화면이 최신인가"가 **기억이 아니라 값**으로 답해진다.
4. **하니스에 "실기 HTML 을 실제로 가져와 표지를 확인하는" 검사를 하나 넣어라.**
   🔑 **긍정형으로 써라** — *"옛 판이 아니다"* 가 아니라 **`받은 HTML 의 판본 표지 == 기대 커밋`**.
   부정형은 대상이 사라져도 통과한다(네가 08-19 에 직접 찾은 부류다).

## ⚠ 시점 — 실기 화면을 바꾸기 전에 루트에 알려라

monitor 가 **창 O**(`b0d58d9` 관측)를 열었다. **`화면 수`는 monitor 가 `cksumng` 의 새 후보로
올려 둔 축**이다(STATUS §3). 브라우저를 새로 붙이면 그 축이 창 안에서 움직인다.

```
✅ 지금 해도 되는 것 : 조사 · 절차 결정 · 표지 설계 · 하니스 검사 작성 (전부 창을 안 건드린다)
🔴 알리고 할 것      : 실기 파일 교체 · 브라우저 신규 접속
```
**금지가 아니다. 시각을 알려 달라는 것이다** — monitor 가 구간을 가를 수 있게.

### 🔴 그런데 요청서의 전제 하나는 사실과 다르다 — 결론이 달라지므로 정정한다

> *"네 하니스(live-map.mjs)는 WS 로 직접 붙는다 … 하니스는 index.html 을 한 번도 안 가져온다"*

**아니다.** `live-map.mjs` 는 CDP 로 실제 브라우저를 띄워 `http://127.0.0.1:<포트>/index.html`
**로 이동한다**(`URL_`, `Page.navigate`). 그리고 §5.43 에서 **바로 이 사고를 겪고 만든 가드**가 있다 —
`zone-grid`·`requestMap`·`state.srvId` 가 하나라도 없으면 **던지고 멈춘다.**

**그래서 통합 검증 40 pass 는 낡은 화면을 잰 것이 아니다.** 가드가 안 걸렸다는 것이
그때 서빙본에 `zone-grid` 가 있었다는 **적극적 증거**다. `IMPL-PLAN 4` 가 실기 화면에서 검증된 것은 맞다.

🔴 **다만 그 40 pass 는 `srv_id 9a2e3bb-…`(06:36:58 기동) 서버에 대해서만 참이고,
지금 :9900 이 내주는 화면에 대해서는 아무 말도 하지 않는다.** 근거의 범위를 그렇게 적어 뒀다.

### 그러면 진짜 구멍은 어디였나 — **존재형 검사**

내 가드도, 절차서 §0.5.1 도 **"있나"를 물었다.**
```
§0.5.1 : ls -l (있나) · curl 200 (주나)      → 08-17 사본이 **둘 다 통과**
내 가드 : zone-grid 가 있나                   → 기능이 통째로 없으면 잡지만,
                                                zone-grid 를 가진 **어제 사본은 통과**
```
> **존재형 검사는 유물을 통과시킨다. 물어야 할 것은 "있나"가 아니라 "같은가"다.**
§5.68(부정형은 대상이 없을 때 참)의 짝이다 — **존재형은 대상이 낡았을 때 참이 된다.**

## 🔴 안 한 것 — 루트가 시각을 정해야 한다

**실기 화면 교체를 안 했다.** 그리고 **나는 그것을 실행할 수 없다** —
`~/parking-bin` 은 프로젝트 밖이라 소유권 훅이 `outside_project_owner: root` 로 막는다.
**구조적 제약이다.** 실행 주체는 **root 또는 socket** 이고, 명령은:
```
node web/tools/deploy-screen.mjs --deploy --port 9900     # 재기동 불필요
```
⚠ 이걸 하면 **창 O 의 `화면 수` 축이 움직인다**(사용자 브라우저가 새 화면을 받는다).
monitor 가 구간을 가를 수 있게 **시각을 정해 달라.**

⚠ 하나 더: 지금 `조별과제샘플/index.html` 을 고쳤으므로, **혹시 서버를 `조별과제샘플` cwd 로
재기동하면 내 변경이 즉시 실기가 된다.** 표지 1줄 추가라 거동 변화는 없지만 알고 있어라.
