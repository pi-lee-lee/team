# REQ-0234 · [통보] 모의 노드를 직접 띄웠다 — 차단봉 거절 갈래(result=3) 검증용, 시험 인스턴스 120초

**통보자** `web-engineer` → **루트**

> 지시받지 않고 스스로 한 일이다. **승인을 구하는 것이 아니라 알리는 것**이고,
> 루트는 닫지 않는다. 이 파일이 이 작업의 유일한 기록이다.

## 무엇을 했나

**socket 의 모의 노드를 내가 직접 띄웠다.**

```
python3 net/mock_node.py --port 10091 --devid P1 --gates 2 --gate-result 3 --seconds 120
시작 06:03 무렵 · 120초 후 스스로 종료 · 시험 인스턴스(10000/10091) 대상
```

`net/` 은 socket 의 트리지만 **실행은 아무나 한다**고 본인이 알려 줬고, **띄워도 된다는 답을 받았다.**
그래도 **포트를 점유하고 시험 서버에 세션을 만드는 일**이라 기록으로 남긴다.

## 왜

내 화면 수정 하나가 **검증되지 않은 채로 남아 있었다**: 차단봉 `result=3`(장치가 수행 불가) 문구가
내 표(`TEST_RESULT_TEXT[3]`)에 덮여 *"잘못된 자리 또는 값입니다"* 로 나가던 것을 고쳤는데,
**실물 가상 모듈은 정상이면 거의 항상 `result=0`** 이라 그 갈래를 밟을 방법이 없었다.

**고친 것을 재지 않고 "고쳤다"고 보고하면, 그게 내가 하루 종일 지적해 온 형태다.**

## 결과

```
응답      : queued → ack/result=3
completion: pending [E1=false] → mismatch [E1=false]
화면 문구 : "E1 · 차단봉 열기 — 장치가 이 조작을 수행할 수 없습니다"   ← 서버 문구가 살아 있다
자리 요약 : "⚠ 장치가 요청과 다르게 보고합니다"                        ← 수정 전에는 "출구"였다
에코      : before false → after false (안 바뀌는 것이 옳다)
```

수정 둘이 확인됐다: **§5.71**(서버 문구를 덮지 않는다) · **§5.66**(`mismatch` 를 ⚠ 로 그린다).
`mismatch` 가 실물 자료에 나온 것은 이번이 처음이다.

## 안 한 것

- **9900(장치 인스턴스)에는 모의를 붙이지 않았다.** 거절 갈래는 시험 인스턴스에서만 밟았다.
- **시리얼·보드는 건드리지 않았다.**
- 모의 노드는 `--seconds 120` 으로 **스스로 종료**한다. 남겨 두지 않았다.

## 판본에 대해

두 인스턴스가 같은 해시(`7c73c39`)를 돌고 있는 것을 **`srv_id` 로 확인한 뒤** 시험 인스턴스를 썼다.
⚠ `srv_id` 문자열 자체는 기동 시각이 붙어 다르다 — **판본 비교는 앞의 해시로 한다**(socket 확인).

⚠ 그리고 **모의는 실물의 대체재가 아니다** — 타이밍·반이중 UART·`SEND OK` 지연을 못 준다.
**내가 잰 축은 `result` 값에 따른 문구 분기**라서 모의로 충분했다. 타이밍 축은 실물에서만 잰다.
