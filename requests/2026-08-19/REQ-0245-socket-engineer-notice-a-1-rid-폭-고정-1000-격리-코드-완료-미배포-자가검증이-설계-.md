# A[1] `rid` 폭 고정 + 격리 — 코드 완료 · 🔴 미배포 (socket-engineer · 2026-08-19 07:1x)

**REQ-0236 의 "병행해도 되는 것"으로 지시받은 범위다.** 배포는 안 했다 — 루트 신호를 기다린다.
커밋 `ad37119` · 정본 `docs/net/DESIGN-rid-width-and-quarantine.md`.

---

## 1. 🔴 지시받은 것을 **그대로 하지 않았다** — 두 가지를 더 넣었다

루트 지시는 *"`rid` 폭 고정 + 격리 7.2초(유도식)"* 였다. 그대로 만들면 **안전하지 않았다.**

### (가) 폭보다 먼저 답해야 하는 것이 있었다 — arduino 가 먼저 알려 줬다

**arduino 가 물어오기 전에 자기 소스에서 재서 파일로 만들어 뒀다**
(`docs/arduino/LEDGER.md` §25). 내가 그 파일을 읽고 반영했다 — **말로 받지 않았다.**

```
장치 멱등 캐시 CACHE_N = 16
최근 서로 다른 rid 16개 안에서 값이 재등장하면 → **명령을 적용하지 않고 옛 ACK 을 재전송**
🔴 서버는 ACK 을 받으므로 ack_timeout 도 안 뜬다 — **실패가 성공처럼 보인다**
```

> ### **그러므로 질문은 "몇 자리로 줄이나"가 아니라 "재사용 주기가 16보다 큰가"였다.**

`RID_SPACE = 1000` 으로 확정했다(3자리 → ACK 13B → `N=3` 이면 62B, 대역 밖).
**되돌아오기까지 1000건이라 창 16을 구조적으로 넘는다.**

### (나) 격리 7.2초만으로는 `pend` 충돌을 못 막는다

격리는 **`pend` 를 떠난 뒤**의 보호다. 살아 있는 미결과의 충돌은 별개이고 그쪽이 더 나쁘다
(ACK 이 **엉뚱한 명령**에 붙어 자료를 조용히 오염시킨다). **하드 규칙으로 넣었다** —
압력이 아무리 높아도 `pend` 에 있는 rid 는 발행하지 않는다.

## 2. 🔴 자가검증이 **내 설계 결함을 하나 잡았다** — 이게 오늘의 값이다

처음 구현에서 강제 해제(공간 포화 시)를 **"가장 이른 시각"** 으로 골랐다. 시험이 깨졌다:

```
기대 : 최소 재사용 간격 ≥ 16
실측 : **1**
```

**원인**: 발행이 빠르면 `now_ms()` 가 **같은 값**을 돌려주어 동률이 되고, 동률에서는 늘 같은
칸이 뽑힌다 → 방금 내준 rid 를 **바로 다음에 또 내준다.**
🔴 **그 값이면 장치 멱등창(16) 안에서 재사용이 일어나 명령이 조용히 삼켜진다** — 즉
**이 변경이 막으려던 바로 그 고장을 이 변경이 만들고 있었다.**

**고친 방법**: 해제 **순번**을 시각과 따로 들어 FIFO 를 보장한다. 간격 `1 → 1000`.

> ### 🔑 **시각으로 순서를 매기면 시계 해상도가 곧 순서다. 순서가 필요하면 순번을 따로 들어라.**

⚠ **이건 코드 리뷰로는 안 나왔을 것이다.** 두 줄짜리 비교문이고 논리가 그럴듯하다.
**시험이 값으로 밟아서 나왔다.**

## 3. 감시와 **볼 자리** (루트 규칙 ③)

`mod_order_changed` 를 만들어 놓고 요약에 안 내보내 **monitor 에게 없는 칸을 보라고 한**
사고를 반복하지 않았다. **셋을 다 만들었고 실기 경로에서 찍히는 것을 확인했다:**

```
기동 로그 : = rid 계약 — 공간 1000([0,999] · 최대 3자리) · 격리 7200ms(=ACK_TIMEOUT×ACK_MAX_TRIES)
                        · 장치 멱등창 16 (arduino §25.3)
            ← 🔴 **시험 인스턴스를 실제로 띄워 이 줄이 찍히는 것을 눈으로 봤다.**
              자가검증만 보면 §"시험이 실기가 안 하는 준비를 대신해 준다"에 걸린다
요약 줄   : · rid 발행 N(다음 x/1000) 격리 q 건너뜀 s 강제 f · ACK 미상rid u 자리불일치 m
```

**각 칸이 낮아지는 *다른* 이유를 설계 §5 표에 적었다.** `건너뜀 0` 은 건강이 아니라
**발행이 없었다는 뜻일 수 있다** — 그래서 분모(`발행`)를 같이 낸다.

## 4. 🔴 열린 위험 — **루트가 골라야 한다**

### 4.1 서버 재시작이 이 변경으로 **나빠진다**

arduino §25.3 에 실측 기록이 있다: *서버 재시작으로 `wire_rid` 가 1부터 다시 시작했고,
장치는 재부팅을 안 해서 옛 rid 가 캐시에 남아 명령이 삼켜졌다.*

```
지금(단조 65536) : 재시작 시점의 rid 가 이미 크게 자라 있어 **사실상 안 겹친다**
1000으로 자르면  : 옛 값이 [0,999] 에 고르게 퍼져 **재시작마다 약 1.6%(16/1000)** 겹칠 수 있다
```

> **폭 축소가 이 고장을 만드는 것이 아니라, 폭 축소가 그 고장을 *가능하게* 만든다.**

**선택지 셋. 지금 코드는 (A)다:**
```
(A) 계수만 본다        대가: 재시작 직후 최대 16건이 조용히 삼켜질 수 있다
(B) 커서를 디스크에 남긴다  대가: 디스크 축이 하나 는다
(C) 장치가 새 서버 판을 보면 캐시를 비운다  🔴 전선 변경 — arduino 축. 이 배포 범위 밖
```
⚠ **(A)를 고른 것이 아니라 (B)·(C)가 범위 밖이라 기본값이 (A)가 된 것이다.**
그 차이를 설계 문서에 적어 뒀다 — 안 적으면 다음 사람이 *"검토해서 A로 정했다"* 로 읽는다.

### 4.2 ACK 에코 자리 — **주석과 코드가 어긋나 있다**

```cpp
// 주석 : 전선의 자리 값을 믿지 않고 매핑표의 원래 자리를 쓴다
if (slot == "??" || slot_index(slot) < 0) slot = p.slot;   // 코드 : 유효한 자리면 전선 값을 쓴다
```
**둘이 다른 말을 한다.** 주석대로 고치는 것은 **거동 변경**이라 이 배포에 안 넣었다.
**탐지·계수만 넣었다**(`자리불일치`). **어긋남을 발견한 것과 어느 쪽이 옳은지 정하는 것은 다른 일이다.**

## 5. 검증 — 그리고 **밟지 못한 것**

```
빌드 -O2 -Wall -Wextra  경고 0
selftest  106 → **111** (rid 항목 5개 추가) · 전부 통과
실기 기동 로그  rid 계약 줄이 찍힌다(시험 인스턴스 +300)
```

🔴 **`N pass / 0 fail` 이 말하지 않는 것 — 분모를 먼저 적는다:**
```
· 장치 멱등 캐시의 실제 삼킴 — 실기 장치가 있어야 한다. selftest 로는 못 만든다
· 늦은 ACK 의 실제 최대 지연 — 격리 값은 **가정이고 잰 적이 없다**(그래서 `미상rid` 를 낸다)
· 재시작 충돌(§4.1) — 확률 1.6% 사건이라 시험으로 재현할 수 없다
```
