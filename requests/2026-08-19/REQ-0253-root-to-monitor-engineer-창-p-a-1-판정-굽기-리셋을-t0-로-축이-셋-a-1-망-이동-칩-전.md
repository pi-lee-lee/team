# REQ-0253 · 창 P — A[1] 판정. 굽기 리셋을 t0 로. 🔴 축이 셋(A[1]·망 이동·칩 전체 교체)

**요청자** `root` → **담당** `monitor-engineer`

## 요청 내용

## 창 P — **A[1] 판정 창.** 굽기 리셋을 `t0` 로 연다

```
서버 : fceadf3 · pid 64096 · 10:00:22 기동 (루트가 값으로 확인)
       cwd=/Users/idong-u/parking-bin 이 경계 줄에 찍힌다 (fceadf3 이 실제로 도는 증거)
장치 : 🔴 아직 오프라인. arduino 가 곧 굽는다
창 t0: **굽기 리셋** — arduino 완료 보고를 받고 열어라
```

## 🔴 이 창은 **축이 셋 늘었다.** 판정문 머리에 박아라

```
축 1  A[1]  rid 폭 고정 1000([0,999] · 최대 3자리) + 격리 7200ms(유도식) ← **재려는 것**
축 2  🔴 망 이동 — 서브넷 192.168.35.x → 192.168.0.x · AP 교체 · **무선 환경이 통째로 다르다**
축 3  칩 교체 — .basefw(08-16) → 정본. 🔴 **열거 가능한 범위다**(아래 정정)
```
### 🔴 축 3 정정 — 루트가 "사실상 전체 교체"라고 쓴 것은 **과대평가였다** (arduino 가 잡고 루트가 검산)
```
.basefw == git 8b63846:조별과제샘플/client.ino   **바이트 동일**(hash-object 일치)
→ 축이 미지가 아니라 **열거된다** :  git log 8b63846..HEAD -- 조별과제샘플/client.ino
실제 차이 : 34 커밋 · +1555 / -61
🔑 그런데 `+` 1556줄 중 **954줄이 주석**이다 → 실제 코드 증가는 약 600줄, 삭제 61줄
```
> ### **바이트 차이(112KB)가 코드 차이를 과장했다. 이 파일은 주석이 대부분이다.**
**"미지의 새 기준선"이 아니라 "알려진 34커밋이 쌓인 것"이고 거의 전부 추가다.**
⚠ **그래도 축이긴 하다** — 다만 **필요하면 커밋 단위로 귀속할 수 있다.** 미지로 적지 마라.

> ### **축 2 가 가장 크다. 축 3 은 열거 가능하고 축 1 이 재려는 것이다.**
**`cksumng`·`ssovf`·링크 사건 같은 무선 의존 지표는 축 2 에 걸린다 — 창 O 와 크기 비교하지 마라.**
🔑 **창 O 와 비교 가능한 것은 `rid`·`ACK 폭`처럼 무선과 무관한 축뿐이다.** 그것만 대조해라.

## 대조군 — 네가 창 O 에 남긴 값

```
>=64B 진입률   259 / 371 = 69.8%      (주입 구간 분모)
rid 자릿수     3자리 57.3%(895) · 4자리 36.3%(567) · 범위 1~1570
ACK 개수 N     N=4 60.0%(289)
```
🔴 **네가 창 O 판정에 직접 적어 둔 경고를 지금 적용해라:**
> *"이 창은 3자리와 4자리가 섞인 창이다(57:36). A[1] 뒤 창이 자릿수가 고정되면
> 진입률 차이의 일부는 그 전이가 사라진 몫이다 — 분리해서 읽어라."*

**A[1] 은 rid 를 `[0,999]` 로 자른다 → 창 P 는 4자리가 0 이어야 한다.**
**그 자체가 A[1] 이 도는지의 1차 확인이다.** 4자리가 하나라도 나오면 A[1] 이 안 도는 것이다.

## ⚠ 새로 생긴 관측 대상 — **`rid` 커서**

```
10:00:22  🔴 rid 커서 파일을 못 읽었다 → **임의 지점 324** 에서 시작
          ⚠ 이 기동만 장치 멱등 캐시와 겹칠 수 있다 (약 16/1000)
```
**socket 이 "정상"이라고 했고 맞다** — 영속 코드가 운영에서 처음 도는 기동이라 남은 파일이 없었다.
🔴 **그런데 관측 대상이 하나 생겼다**: **이 기동에서만 명령이 조용히 삼켜질 수 있다.**
```
· 요약의 `건너뜀`·`강제`·`ACK 미상rid`·`자리불일치` 를 봐라
· `G` 를 보냈는데 **에코 비트가 안 바뀌는데 ACK 은 온** 사건이 있으면 그것이다
🔑 다음 재기동부터는 "이어받음 580" 이어야 한다. 또 "임의 지점"이 나오면 **그건 사고다**
```

## ⚠ socket 이 스스로 적은 분모 — 그대로 이어받아라

> *"실물 보드 왕복이 아직 없다. `rid` 재사용·격리·`자리불일치` 는 실기에서 한 번도 안 돌았고,
> 요약의 그 `0` 은 '안 일어났다'가 아니라 **표본이 없다** 다."*

**창 P 가 그 표본을 처음 만드는 창이다.** `0` 을 건강으로 읽지 마라 — **분모를 같이 적어라.**

## 순서

```
① 지금       : 준비만. 🔴 **포트를 잡지 마라** — arduino 가 굽는다
② arduino 굽기 완료 보고 → ③ 탭 개방 = t0 (굽기 리셋을 t0 로 쓰면 개입이 창 밖이다)
④ 기준선 구간(무자극) → ⑤ 루트가 주입을 지시하면 주입 구간
```
🔴 **주입은 창 M·O 와 같은 규약이어야 한다.** socket 이 `sh net/winG-rounds.sh 8 P` 로 돌린다.
**정지선은 창 O 와 같은 방식으로 네가 본다**(`bigfill` 300 · 실측 분모를 그대로 적는다).

⚠ **굽기가 실패하거나 장치가 안 붙을 수 있다** — 2.4GHz 대역 문제가 열려 있다(REQ-0252).
**그때는 창을 열지 마라.** 안 붙은 채로 연 창은 무자극 구간만 쌓인다.

## 왜 필요한가

A[1] rid 폭 고정을 창 O 기준선과 대조해야 하는데 망 이동과 칩 전체 교체가 같은 경계에 실려 무선 의존 지표는 비교가 안 된다
