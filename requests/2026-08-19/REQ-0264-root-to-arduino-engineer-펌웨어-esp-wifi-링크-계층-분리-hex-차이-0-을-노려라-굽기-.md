# REQ-0264 · 🔴 펌웨어 ESP/WiFi 링크 계층 분리 — hex 차이 0 을 노려라. 굽기 입력 불변식이 깨진다 (사용자 지시)

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

# 펌웨어의 **ESP/WiFi 링크 계층을 분리**한다 (사용자 지시)

> 사용자 원문: *"**펌웨어도 포함**이다. 현재는 `esplink.h` 같이 **와이파이 모듈을 사용하지 않고 있다.**
> **분리해서 영향이 없도록** 해달라."*
> 앞 지시: *"1개의 단일 슬롯(노드)에 대한 네트워크 안정화는 **확인된 사항**이다 … **슬롯에 대한
> 수정이 아닌 수정사항에 의해 수정되지 않도록 설정**하라."*

## 0. 🔴 이 작업은 서버 쪽과 제약이 다르다 — **먼저 읽어라**

```
서버 : 텍스트가 바뀌어도 산출물이 같으면 통과 (별도 .o 해시로 잠근다)
🔴 펌웨어 : **분리 자체가 굽기 축이다.** 산출물이 바뀌면 구워야 하고, 구우면 창이 하나 생긴다
```
**그래서 목표가 하나 더 있다: 🔑 `hex` 차이 0 을 *노려라*.**
차이가 나면 굽기가 필요하고 그 창의 축이 하나 늘어난다.

### ⚠ 그리고 **네가 방금 세운 불변식이 깨진다**

원장 §23 에 *"굽기 입력 = 그 굽기 커밋의 `조별과제샘플/client.ino`"* 라고 적었다.
**파일을 나누면 그 문장이 거짓이 된다.**
🔴 **분리와 같은 커밋에서 그 불변식을 고쳐라.** 안 고치면 **다음 사람이 낡은 불변식으로
굽기 입력을 재구성하고 틀린 것을 얻는다** — 그리고 **틀렸다는 표시가 없다.**
**`BURN-CHECKLIST` 의 `cmp` 블록도 같이 봐라**(파일이 여럿이면 대조 대상도 여럿이다).

## 1. 선례가 둘 있다 — **둘 다 읽고 시작해라**

```
✅ 성공 : espRead · espWrite · espReset  →  이름만 바꿈 → **hex 차이 0**
🔴 실패 : espInit                        →  **둘을 합침** → hex **15줄 상이**
          원인은 인라인이 아니라 **합치는 것 자체**였다 —
          wifi.begin(9600) 과 netStepAt = millis() 사이 29줄이 사라져 **millis() 시점이 앞당겨졌다**
⚠ 잔재  : arduino/client/EspLink.h  — REQ-0091 의 추출판. 08-17 에 멈췄고 **칩에 올라간 적 없다**
          🔴 **참고만 해라. 그것으로 굽지 마라.** `arduino-cli compile arduino/client` 는
             성공하고 **전혀 다른 펌웨어를 낸다**(네 §27.5)
```
> ### **"이미 한 함수였던 것을 옮기는 것"은 hex 가 같고, "흩어진 것을 모으는 것"은 다르다.**
**분리 계획을 세울 때 각 함수가 어느 쪽인지 먼저 분류해라.**

## 2. 무엇을 분리하나 — **네가 목록을 정한다**

**후보**(확정은 네 몫):
```
· AT 명령 송수신 · CIPSEND · SEND OK 대기(바이트 흐름 매칭) · 링버퍼 비우기(16B마다)
· CWJAP·CIFSR·CIPSTART · 링크 재수립 사다리(netStep·netStepAt·netStepWait)
· T2 게이트 · esprst · drop/stuck/okto 계수
```
🔴 **기준은 "창 P 에서 확인된 것"이다** — `T2 0/451` · `SEND OK` 축 · 링크 사건 0.
⚠ **전부 넣지 마라.** *"슬롯 무관한 변경이 건드릴 수 있는데 건드리면 안 되는 것"* 이 기준이다.

⚠ **`espInit` 은 이미 물린 자리다.** 부팅 1회성 시점 이동이 그 안에 있으므로
**경계에 넣을지 뺄지를 근거와 함께 적어라.**

## 3. 판정 — **hex 가 답한다. 코드 판독으로 갈음하지 마라**

```
① 분리 전후 빌드 → cmp.py 로 대조
   ✅ 차이 0      → 굽기 불필요. **가장 좋은 결과다**
   🔴 차이 있음   → **왜 다른지를 적어라**(인라인 경계·순서·초기화 시점·선후 교체)
                    그리고 **굽기가 필요해진다** — 루트에 알리고 시각을 받아라
② 🔴 **선후가 바뀐 곳을 따로 세라** — 네 §26 이다.
   **앞당김은 눈에 띄고 선후 교체는 안 띈다.** `hex` 대조도 그것을 "몇 줄 이동"으로만 보여 준다
③ 회귀 시험 전부 통과
```
⚠ **`cmp.py` 가 답하지 않는 것도 네가 적어 뒀다**(§27.6) — *"칩 == 내가 빌드한 것"* 에는 답하고
*"내가 빌드한 것 == 옳은 소스"* 에는 답하지 않는다. **분리로 파일이 늘면 그 구멍이 커진다.**

## 4. 잠그는 기계 — 루트가 만든다

```
너   : 파일 분리 · 경계 문서화 · 굽기 입력 불변식 갱신 · 경로를 루트에 알린다
루트 : 그 파일이 **슬롯/링크 REQ 없이 바뀌면 잡는 검사**
```
🔑 **펌웨어는 서버와 잠금 방식이 다르다** — 산출물을 영역별로 못 쪼개므로 **파일 기준**으로 잠근다.
**대신 펌웨어는 원래 굽기마다 hex 대조를 하므로 그 짝이 이미 있다.**

## 5. 🔴 지금 굽지 마라

**분리 코드를 쓰고 `hex` 대조까지 하되 굽기는 루트가 시각을 준다.**
서버 쪽 `0262`(다중 노드 상행 경로)가 진행 중이고 **둘을 같은 창에 넣을지는 루트가 정한다.**

## 6. 완료 기준
```
① 지키는 목록이 이름으로 적혀 있다
② 파일 분리 · 경계 문서화
③ 🔴 hex 대조 결과 — 차이 0 이거나, 다르면 **왜**(선후 교체 포함)
④ 굽기 입력 불변식(§23)과 BURN-CHECKLIST 갱신
⑤ 회귀 통과 · 파일 경로를 루트에 알림
```

### ★ 방법 — **모으지 않았다. 그게 hex 0 의 이유다**

```
🔴 한 파일로 모으기 → 링크가 9곳에 흩어져 있다 → 순서가 바뀐다 → hex 가 달라진다
✅ 연속 구역을 원문 그대로 빼고 **원래 그 자리에서 `#include`** → 전처리 텍스트 동일 → **hex 동일**
```
**§19(`espInit`)의 정확한 반대 사례다** — 그때는 합쳐서 `millis()` 시점이 밀렸고,
이번엔 **아무것도 안 합쳐서 밀릴 것이 없었다.**

### 실측 — 네 번 쟀다 (코드 판독으로 갈음하지 않았다)

```
시범 1구역(TX)                     → cmp exit=0
🔴 사다리 구역 단독(espInit 포함)   → cmp exit=0    ← 물린 자리라 루트 요청대로 따로
3구역                               → cmp exit=0
🔴 최종 4구역(실제 파일에서 빌드)    → **cmp exit=0** = `move0819` = **지금 칩**
846줄 이동(3822 → 2980) · 26032B · RAM 1196B · 회귀 237 PASS / 0 FAIL
```
> **소스 파일이 바뀌었는데 칩과 안 갈렸다. 그래서 이 분리로는 구울 필요가 없다.**

### 선후 교체 — **0. 그리고 `hex` 가 증명한다**

> **순서가 바뀌면 주소가 바뀌고, 주소가 바뀌면 `hex` 가 바뀐다.**
> **`hex` 차이 0 은 "선후 교체 0"의 증명이다 — 눈으로 세는 것보다 강하다.**
§26 의 함정은 **"모으는 변경"에서만** 생긴다. 순서 보존 분리에서는 구조적으로 없다.

### 같이 고친 것 — 불변식이 깨지는 자리 둘

```
원장 §23   "굽기 입력 = 그 굽기 커밋의 client.ino"  → 취소선 + 갱신(EspLink_*.h 포함)
           ⚠ 지우지 않았다 — 08-19 이전 굽기는 옛 문장이 맞다. **판본마다 참인 문장이 다르다**
체크리스트  cp/cmp/git 블록이 client.ino 하나만 봤다 → EspLink_*.h 를 같이 본다
           ⚠ `cp` 는 옛 파일을 안 지운다 — 헤더 이름이 바뀌면 스테이징에 유령 파일이 섞인다
```
