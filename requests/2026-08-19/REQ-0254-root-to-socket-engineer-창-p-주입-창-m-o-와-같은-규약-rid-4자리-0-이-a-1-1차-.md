# REQ-0254 · 창 P 주입 — 창 M·O 와 같은 규약. rid 4자리=0 이 A[1] 1차 판별자

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

## 창 P 주입 — **A[1] 을 실제로 밟는 유일한 길이다**

```
창 P t0    : 탭 10:15:11 (monitor) · 굽기 리셋 10:09:55 (arduino) — 🔴 리셋이 둘이다
서버       : fceadf3 · pid 64096 · rid 공간 1000([0,999]) · 격리 7200ms
장치       : 192.168.0.214 · 등록 n=12 · hex · 가상 O* E1·X1
```
### 🔴 정정 (socket 이 소스로 잡았다) — 위 문장은 **틀렸다**
```
❌ 루트가 쓴 것 : "rid 는 G 명령이 나가야 발행된다"
✅ 사실         : 주입기의 `T` 도 **같은 alloc_rid() 를 탄다**
                  dispatch_test(...) { uint16_t rid = alloc_rid(); … }
→ 창 O 도 이미 rid 를 발행했다(시도 1679건) · 창 P 도 **주입만으로 A[1] 이 밟힌다**
```
🔑 **`G` 가 필요한 것은 `rid` 축이 아니라 `자리불일치` 축이다** — 에코 비트를 대조하려면
실제 자리 조작이 있어야 한다. **둘을 갈라 적어야 판정문이 안 흐려진다.**
지금 요약이 `rid 발행 0(다음 324/1000)` 인 것은 **"안 일어났다"가 아니라 "표본이 없다"** 다.

## 🔴 규약 — **창 M·O 와 같아야 한다**

```
sh net/winG-rounds.sh 8 P
```
**창 O 와 같은 스크립트·같은 인자.** 다르면 대조군이 아니라 그냥 다른 자료다.
**무엇을 썼는지 값으로 보고해라** — 스크립트 경로·인자·회차 구성·`N`. monitor 가 분모 정의에 옮긴다.
✅ **날짜 상수는 주입 시작 전에 네가 이미 고쳤다** — 이번엔 `net/inject-winP-2026-08-19.log` 로 남을 것이다.

## 착수 시점 — **monitor 의 무자극 기준선이 선 뒤**

**루트가 착수를 승인한다. 다만 시작 신호는 monitor 의 기준선 확인 뒤에 내라:**
```
① monitor 가 "무자극 기준선 떴다" 를 알린다   ← 창 O 는 13분 01초였다. 비슷하게 두면 대조가 쉽다
② 네가 시작한다. 🔴 **첫 주입 시각을 값으로 monitor 에 준다** (창 O 때처럼 로그에서 읽어라)
③ 정지선은 monitor 가 본다 — `bigfill` 300. 도달하면 `.team/STOP-P` 를 만든다
④ 네 상한은 네가 볼 수 있는 것으로 — **라운드 수와 40분**
```
⚠ **정지 신호가 오면 진행 중인 라운드를 끊지 마라.** 다음 라운드를 안 여는 것으로 충분하다 —
창 O 때 그렇게 해서 분모 성격이 안 바뀌었다(지연 63초, 미리 알린 한 라운드 상한 안).

## 🔴 A[1] 판정에 필요한 것 — **네 쪽에서만 나오는 값**

```
· rid 자릿수 분포        → **4자리가 0 이어야 한다.** 하나라도 나오면 A[1] 이 안 도는 것
· 격리 발동 수 · 건너뜀 · 강제
· ACK 미상rid · 자리불일치
· 🔴 rid 재사용이 실제로 일어났는가
  ⚠ **정정(socket)**: 문턱은 `1570` 이 아니라 **발행 1000건째**다. 커서가 발행마다 1 나아가고
    공간이 1000 이라, **324 에서 시작했으니 커서 1324 에서 첫 재사용**이다.
    분모는 `rid 발행` 이고 **미주입(서버 거절)도 발행에 든다**(`alloc_rid()` 뒤에 `enqueue_down`
    이 실패하면 해제하고, 그 해제가 곧 격리 투입이다).
    창 O 규모(시도 1679)면 324→약 2000 이라 **1324 를 넘는다 → 밟힐 것으로 본다.**
    ⚠ **예측이다.** 밟혔는지는 `건너뜀`·`강제`·`발행` 으로 **사후에** 판정한다
```
⚠ **재사용이 안 일어나면 격리 로직은 이 창에서도 안 밟힌다.** 그러면 그 `0` 도 **표본 없음**이다.
**밟혔는지 안 밟혔는지를 판정문에 갈라 적어라** — 통과 수가 아니라 분모다.

## ⚠ 그리고 이 기동만의 위험

```
10:00:22  🔴 rid 커서 파일을 못 읽어 **임의 지점 324** 에서 시작했다
          → 이 기동만 장치 멱등 캐시(최근 16)와 겹칠 수 있다 (약 16/1000)
```
**겹치면 명령이 조용히 삼켜지고 ACK 은 온다.** `건너뜀`·`강제`·`ACK 미상rid`·`자리불일치` 를 봐라.
🔑 **`G` 를 보냈는데 에코 비트가 안 바뀌는데 ACK 은 온 사건**이 그것이다.
⚠ **다음 재기동부터는 "이어받음"이어야 한다. 또 "임의 지점"이 나오면 그건 사고다.**

## 비교 대상 (창 O 판정문에 고정돼 있다)

```
>=64B 진입률  259/371 = 69.8%
rid 자릿수    3자리 57.3% · 4자리 36.3%     ← 🔴 창 P 는 4자리가 0 이어야 한다
ACK 개수 N    N=4 60.0%
>=64B T2      2/341 = 0.59%  (창 M 은 0/886)
```
🔴 **monitor 가 창 O 판정에 박아 둔 경고를 잊지 마라**: 창 O 는 **3자리와 4자리가 섞인 창**이다.
**진입률 차이의 일부는 그 전이가 사라진 몫이다 — 분리해서 읽어야 한다.**
⚠ **그리고 망 이동 축이 있다.** `cksumng`·`ssovf`·링크 사건은 **창 O 와 크기 비교하지 마라.**

## 왜 필요한가

rid 는 G 명령이 나가야 발행되므로 주입 없이는 A[1] 이 한 번도 안 밟히고 판정할 것이 없다
