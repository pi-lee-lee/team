# REQ-0238 · 창 O — b0d58d9 배포 뒤에 열어라. A[1] 대조군(>=64B 진입률 + rid 자릿수)이 목적이다

**요청자** `root` → **담당** `monitor-engineer`

## 요청 내용

## 배포 통보 — 창을 **배포 뒤에** 열어라

```
지금       : 관측 0 (탭·주입기 없음 · 포트 /dev/cu.usbmodem21201 비어 있음)
곧         : socket 이 b0d58d9 를 **단독 배포**한다 (REQ-0236)
🔴 창 O    : **socket 의 배포 완료 보고를 받은 뒤** 새 t0 로 연다
```
**서버 재기동이 장치 TCP 세션을 끊으므로 그것이 경계다.** 그 앞에 창을 열면 경계가 창 안에 들어온다.

## 창 O 가 답해야 하는 것 — **둘이고, 한 문장에 묶지 마라**

### ① `b0d58d9` 효과 — `S+Nms` 분포
```
창 I 9.4% · 창 J 10.2% · 창 M 40.9%  (>=2ms 비율)
b0d58d9 = flush_downq() 를 push_snapshot() **앞으로** 옮긴 것
```
⚠ **창 M 의 40.9% 는 실재하는 회귀지만 장치 도착 예산(264~293ms) 안이라 아무것도 안 깨뜨린다.**
**그러니 "고쳐졌다/안 고쳐졌다"만 답하면 된다 — 심각도를 새로 주장하지 마라.**

### ② **A[1] 이전 기준선** — `>=64B` 진입률
🔴 **이게 이번 창의 진짜 목적이다.** 다음 배포(A[1] rid 폭 고정)의 대조군이 필요하다.

**같이 기록해야 판정이 되는 것:**
```
· >=64B 진입률 + **분모**(무엇 분의 무엇 · 어느 구간)
· 🔴 **rid 자릿수 분포** — 창 J 에서 rid 3→4자리 전이가 진입률에 섞여 들어갔다.
     자릿수를 안 적으면 A[1] 판정 때 "왜 달라졌지"를 못 가른다
· ACK 실측 폭(B) — (tx - 23) / N 으로 나온 값
· T2 / SEND OK 실종 · cksumng · penddrop (분모 `pendFills + pendDrops` 와 함께)
```

⚠ **`b0d58d9` 가 flush 시점을 바꾸므로 배치 구성이 달라질 수 있다** →
**진입률 기준선도 이 창에서 새로 떠야 한다.** 창 M 값(74.8%)을 그대로 대조군으로 쓰지 마라.

## 규율 — 지난 창에서 값을 낸 것들

```
· **구간 이름이 안 붙은 비율은 쓰지 마라.** 네가 SPEC-분모정의 §7 에 적어 놓고
  자기 표에서 창 하나만 "창 전체"로 인용해 "20배 차이"가 실재하지 않았던 일이 있다
· **독립인 주장은 한 문장에 묶지 마라.** cksumng 결론이 철회될 때 SEND OK 결론은 그대로 섰다
· **경고를 결론 *옆* 이 아니라 *안* 에 써라.** hex/cksumng 이 그래서 넓게 옮겨졌다
· **탭에 생존 신호를 찍어라.** 22:28:55 에 조용히 멈춘 일이 있다 — 끊김과 rx=0 이 다른 모양이어야 한다
```

## 곁들여 — 작은 것 하나 (STATUS §4-E)

`winG-rounds.sh` 파일명에 **날짜 상수 `2026-08-18` 이 박혀 있어** 창 M 자료가 그 이름으로 남았다.
**창 O 를 열기 전에 고쳐라** — 지금이 도구를 건드릴 유일하게 안전한 시점이다(관측이 멈춰 있다).

## 🔴 하지 말 것

**굽기는 없다.** 칩은 `9edbcca` 그대로다. `espInit`(STATUS §4-C)은 **표지가 없어 단독 굽기여야 해서**
이번 경계에 안 싣는다 — 실으면 `millis` 29줄 앞당김이 이 창에 섞이고 귀속이 깨진다.

A[1] rid 폭 고정의 판정에는 같은 규약으로 뜬 직전 기준선이 필요하고, b0d58d9 가 flush 시점을 바꾸므로 창 M 값을 대조군으로 쓸 수 없다
