# REQ-0276 · 🔴 572a4cb 가 map/state 에 zones 대신 lot.zones() 키를 낸다 — 실기에서 개정 격자가 통째로 안 뜬다

**요청자** `web-engineer` → **담당** `socket-engineer`

## 요청 내용

## 실측 — 지금 실기에서 개정 격자가 **안 뜬다**

`build 572a4cb` 의 `map`·`state` 봉투가 **`zones` 대신 `lot.zones()` 라는 키**를 낸다.
전선 프레임 원문(CDP 로 직접 뜬 것):

```
map 프레임 키   : "type", "srv_id", "epoch", "grid", "lot.zones()"
state 프레임 키 : "type", "srv_id", "epoch", "ts_ms", "lot.zones()"
'zones' in map  : false
srv_id          : 572a4cb-1787130990660
```

**화면 쪽 결과:**
```
mapUsable()                  → false
#zone-grid 의 hidden         → true      ← 🔴 개정 격자가 통째로 안 보인다
```

**즉 사용자가 지금 보는 것은 옛 `slots[]` 타일 격자다.** 오늘 넣은 것 — 7영역·노드 박스·
모듈 인덱스(`주차확인센서 #0 (A1)`)·표시 이름(`영역1`)·상태등 — **하나도 안 보인다.**

⚠ **화면은 잘못이 없다.** `map` 에 `zones` 배열이 없으면 격자를 켜지 않는 것이 설계다
(원장 §5.43 계열: 낡거나 모양이 다른 `map` 으로는 안 그린다). **옛 경로가 받아 준 덕에
화면이 죽지는 않았다** — 그 안전장치가 정확히 이 일을 위해 있었다.

## 원인 추정 — **네 코드다. 나는 못 고친다**

키 이름이 `lot.zones()` 인 것으로 보아 JSON 을 만드는 자리에서 **C++ 표현식이 키 문자열 안으로
들어간 것**으로 보인다. 조립 API(`ParkingLot`) 도입 리팩터링 중에 생긴 것 같다.

```
"zones":[...]      ← 있어야 할 것
"lot.zones()":[...]  ← 지금 나가는 것
```

🔴 **추정이다.** 나는 서버 소스를 고칠 수 없고, 어디서 그렇게 됐는지는 네가 값으로 확인해라.

## 요청

`map`·`state` 봉투의 배열 키를 **`zones`** 로 되돌려 달라. **계약 이름은 안 바뀐 것으로 안다** —
바뀐 것이면 그건 별개 논의이고 나에게 먼저 알려 달라(내 파서·하니스가 전부 `zones` 를 본다).

## 🔑 이걸 어떻게 잡았나 — 네 리팩터링을 재는 계측기가 이것이다

루트가 *"서버·펌웨어가 대규모 리팩터링 중이니 계측기부터 고쳐라"* 고 했고, 그 직후
`zone-nodes.mjs --live 9900` 이 **`서버가 map 을 보냈다 → 받은 것: null`** 로 멈췄다.

⚠ **그리고 나는 이것을 바로 네 탓으로 적지 않았다.** 오늘만 두 번 *"서버가 안 보낸다"* 로
갈 뻔했다가 둘 다 **내 계측기 문제**로 드러났기 때문이다(`sm.name` · `srv_id`).
그래서 **전선 프레임 원문을 직접 떠서** 키 이름을 눈으로 확인한 뒤에 이 요청을 쓴다.

🔑 **자가검증이 이걸 못 잡는다** — 서버가 자기 JSON 을 자기가 파싱하지 않기 때문이다.
**받는 쪽만 볼 수 있다**(CLAUDE.md §"보낸다와 기록된다 사이에 파서가 끼어 있다").
**배포 뒤에 브라우저를 한 번 붙이는 것이 이 부류를 잡는 유일한 값싼 방법**이다.

## 완료 기준

- `map`·`state` 프레임에 `"zones"` 키가 있다(전선 원문 기준)
- 내 `node web/tools/zone-nodes.mjs --live 9900` 이 다시 통과한다 — 배포되면 내가 돌려서 확인하고 알려 주겠다

## 왜 필요한가

map 에 zones 배열이 없어 mapUsable() 이 false 가 되고 zone-grid 가 hidden 이다. 사용자가 지금 옛 타일 격자를 보고 있고 오늘 넣은 7영역·노드박스·인덱스·라벨이 하나도 안 보인다

## 대상 파일

## 완료 기준

### 🔴 왜 자가검증이 못 잡았나 — web 의 진단보다 한 겹 나빴다
web: *"서버는 자기 JSON 을 자기가 파싱하지 않는다. 그래서 원리적으로 못 잡는다."*
**절반만 맞다. 검사가 있었다.** `selftest.h` ㉗ 이 `map` 에 `"zones":[]` 가 있는지 보고 있었는데
**같은 정규식이 그 기대값도 바꿨다.**
```
코드와 시험이 같은 방향으로 틀림 → 대조가 성립 → 114개 전부 초록
키를 고치자 그 시험이 빨강 → 그 빨강은 회귀가 아니라 "기대값이 낡았다"는 신호였다
```
> **"시험 경로 ≠ 실기 경로" 의 넷째 얼굴 — 시험이 실기와 *같은 방향으로* 오염된다.**
> ①못 밟는다 ②다르게 밟는다 ③시험이 준비를 대신해 준다 — 셋은 어딘가 티가 난다.
> ④ 는 **둘 다 자기 안에서 일관돼서 일관성 검사로 못 잡는다.**

⚠ web 이 같은 부류를 오늘 아침에 다른 경로로 밟았다(원장 §5.88 · 기대 표를 피검체에서 읽어 `[]==[]` 공허 통과).
**web: "너는 도구가 같아서, 나는 출처가 같아서. 둘 다 *기대값이 피검체와 독립인가* 를 안 물었다."**

1. `selftest.h` ㉟ 신설 — 계약 키를 **손으로 박은 리터럴**로 단언.
   + **서명 검사**: 키에 `.` 나 `(` 가 하나라도 있으면 실패(이번 사고의 서명).
2. `docs/net/DEPLOY-CHECKLIST.md` §4.4 — 확인 항목 **넷 → 다섯**.
   *"배포 뒤 봉투를 떠서 키 목록을 눈으로 본다."*
   §0.5.1-정정("존재형은 유물을 통과시킨다")의 한 겹 안쪽 —
   거기서는 *파일이 있다* 가, 여기서는 **프레임이 나간다** 가 통과시켰다.
3. `docs/net/LEDGER.md` (96) 에 기전을 남겼다.

### ⚠ 남는 한계 — 다음 사람이 알아야 한다
