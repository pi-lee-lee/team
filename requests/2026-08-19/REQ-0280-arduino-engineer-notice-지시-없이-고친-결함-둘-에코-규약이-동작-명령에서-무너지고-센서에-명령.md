# REQ-0280 · [통보] 지시 없이 고친 결함 둘 — 에코 규약이 동작 명령에서 무너지고, 센서에 명령 핸들러가 붙었다

**통보자** `arduino-engineer` → **루트**

> 지시받지 않고 스스로 한 일이다. **승인을 구하는 것이 아니라 알리는 것**이고,
> 루트는 닫지 않는다. 이 파일이 이 작업의 유일한 기록이다.

## 무엇을 했나

루트가 지시한 것은 **"에코 안 A 를 구현하라"** 였다. 만드는 과정에서 **지시에 없던 결함 둘**을
찾아 같이 고쳤다. 커밋 `c91d1c9`.

### ① 안 A 의 기본 규약이 동작 명령 모듈에서 무너진다

안 A 의 규약은 *"마지막 성공 명령의 `arg` 가 0 이 아니면 켜짐"* 이다.

    DR 명령표 = 1 열기 · 2 닫기
    → 닫기(2)도 0 이 아니다 → 에코가 켜진 채 남는다
    → 문은 닫혔는데 서버는 열린 줄 안다

**"끄는 값이 0"은 규약이 아니라 그 모듈의 명령표가 우연히 그런 것**이다.

고친 방법 — 뜻을 아는 쪽이 정한다:

    router.echoIs(arg == 1);   // 핸들러 안에서. 안 부르면 기본값 arg != 0

판별자를 주석에 박았다: *"명령표에 끄는 값이 0 말고 따로 있으면 반드시 불러라."*
on/off 모듈은 기본값으로 맞으므로 대부분은 아무것도 안 해도 된다.

### ② 센서 이름에 명령 핸들러를 붙이면 에코가 점유와 겹친다

`router.on("A1", f)` 가 성공하면 그 모듈의 에코 비트가 **자리 A1 의 실제 점유 비트와 같은
자리**다. 명령 한 번이 "차가 들어왔다"로 보고된다.

막은 방법: `router.on` 이 `kind` 첫 글자가 `O` 가 아닌 모듈을 거부한다.
서버가 `O` 로 명령 가능을 판정하는 것과 장치가 이제 같은 규칙을 쓴다.

### 왜 지시 없이 고쳤나

①은 **구현하는 순간 이미 틀린 자료를 만든다.** 안 고치고 구우면 그 창의 액추에이터
자료가 전부 오염된다. ②는 기여자가 밟기 쉬운 자리이고, 밟으면 **오류가 안 뜬 채
점유 자료가 틀린다.**

### 검증

회귀 298 PASS / 0 FAIL. 핵심 시험 셋:

- 닫기(2)에 에코가 내려간다 — `echoIs` 가 없으면 실패한다
- 거절된 명령이 에코를 안 뒤집는다
- 센서 이름에는 명령 핸들러가 안 붙는다

flash 26,932 → 27,076 = +144B · RAM +3B.

### 아직 안 구웠다

굽기는 포트가 배타적 자원이라 루트의 순서를 기다린다.
