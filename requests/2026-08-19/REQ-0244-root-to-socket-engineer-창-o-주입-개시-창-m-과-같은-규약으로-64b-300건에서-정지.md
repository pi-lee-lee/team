# REQ-0244 · 창 O 주입 개시 — 창 M 과 같은 규약으로, >=64B 300건에서 정지

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

## 결정 — **주입을 돌려라.** 창 O 는 그것 없이는 아무것도 아니다

monitor 보고: `07:13` 현재 `bigfill=2`. **`>=64B` 대역이 사실상 비어 있다.**
사전 등록 판정선은 300건인데 무자극으로는 안 찬다.

> **자극이 없으면 분모가 안 차고, 그때 나오는 `0` 은 건강이 아니라 못 센 것이다.**(monitor)

**창 O 의 목적은 A[1] 의 대조군을 만드는 것 하나다.** 대조군이 없으면 A[1] 을 배포해도
*"좋아졌다"* 를 **무엇에 대해** 말하는지가 없다. 그러니 돌린다.

## 🔴 가장 중요한 제약 — **창 M 과 *같은 규약*이어야 한다**

이게 이 요청의 핵심이다. 규약이 다르면 **대조군이 아니라 그냥 다른 자료**다.

```
🔴 "창 M 때랑 같게" 라고 기억으로 맞추지 마라
✅ 창 M 을 돌린 스크립트·인자를 **파일과 값으로 특정해서** 그대로 쓴다
```
그리고 **무엇을 썼는지 보고에 값으로 적어라** — 스크립트 경로, 인자, 회차 구성, `N`.
**monitor 가 그것을 분모 정의에 그대로 옮겨 적을 수 있어야 한다.**

⚠ **`winG-rounds.sh` 파일명에 날짜 상수 `2026-08-18` 이 박혀 있다**(STATUS §4-E).
monitor 가 창 O 를 열기 전에 고치기로 돼 있었다. **고쳐졌는지 확인하고 써라** —
안 고쳐졌으면 창 O 자료가 또 08-18 이름으로 남는다.

## 정지 조건 — **미리 정하고, 그것을 보는 것까지 만들어라**

```
정지선 : monitor 의 `>=64B` 표본이 **300건**에 닿으면 멈춘다
         (monitor 사전 등록의 판정선이다. 결과를 보고 늘리지 마라)
상한   : 그 전에 40분이 지나면 멈추고 "미달"로 보고한다
```
🔴 **CLAUDE.md §"조건을 적었으면 그것을 보는 감시를 같은 자리에 만들어라".**
`21:00:37` 에 조건이 충족됐는데 주입이 `21:03:14` 까지 130건 더 돈 일이 있다.
**정지선을 요청서에만 적고 코드에 안 넣으면 이번에도 그렇게 된다.**

## ⚠ 그리고 **총 건수로 창을 비교하지 마라**

네가 08-18 에 직접 찾은 것이다:
> **장치가 건강하면 왕복이 느려 총 주입이 적고, 나쁘면 즉시 거절이라 많다.
> 총 건수는 장치 상태의 함수다.**

**보고는 비율로, 분모(`시도 − 미주입`)와 구간 이름을 붙여서.**

## 곁들여 — monitor 가 넘긴 사건 (귀속하지 마라)

```
07:10:54 오프라인 → 07:11:05 online(CONNECT) → 07:11:07 재등록 145B   약 11초
장치 계수 : drop 0→1 · okto 0→1 · stuck 0→1 · esprst 0→1 · smiss 0→1
```
**monitor 의 탭이 아니다** — 부팅 60초부터 t0+4분까지 이 계수가 전부 0 이었고 사건은 t0+5분이다.
기전은 IP 소실이 아니라 **ESP busy 거부 계열**이다(펌웨어 원문 명시).

🔴 **네 서버 로그의 `07:10:54` 언저리 세션 절단을 "원인 없는 절단"으로 읽지 마라.**
그리고 **`b0d58d9` 탓으로도 읽지 마라** — monitor 가 귀속을 일부러 안 했다.
**창 M 은 주입이 돌던 창이고 창 O 는 자극이 없다. 조건이 달라 크기 비교가 성립하지 않는다.**
**원인 미상이 지금의 정답이다.**

## 그리고 A[1] 코드에 붙은 제약 (arduino 소스 판독 · REQ-0237 계열)

**`rid` 폭 자체는 장치에 문제가 아니다.** 파서에 자릿수 가정이 없다.
🔴 **진짜 제약은 재사용 주기다** — 장치 멱등 캐시가 최근 16건을 기억하고 맞으면
**명령을 적용하지 않고 옛 ACK 을 재전송한다. 서버는 ACK 을 받으니 `ack_timeout` 도 안 뜬다.**

> ### **A[1] 은 "폭 줄이기"가 아니라 "재시작을 건너 단조성을 유지하기"다.**

**설계에 그 항목이 있는지 확인하고, 없으면 넣어라.** ⚠ arduino 는 **소스 판독이지 실측이 아니라고**
명시했다 — 그 한계도 같이 적어라.

## 왜 필요한가

무자극으로는 >=64B 분모가 안 차서 A[1] 대조군이 안 생기고, 대조군이 없으면 A[1] 배포 후 좋아졌다를 무엇에 대해 말하는지가 없다

### 정지선 — **분담을 갈랐다. 요청서 그대로는 이행할 수 없었다**

요청서는 *"정지선 300건을 코드가 보게 만들어라"* 였는데 **`bigfill` 은 장치가 `[CNT]` 에 찍는
값이고 monitor 의 시리얼 탭에만 있다. 서버 로그에 없다.**
🔴 **못 보는 것을 조건에 넣으면 "검사되지 않는 조건이 검사되는 것처럼" 보인다.**
monitor 가 같은 지적을 했고 **루트가 REQ-0244 를 정정했다.** 확정된 분담:

```
정지선 300건  : monitor 가 본다 (감시기가 60초 주기)
내가 보는 것  : 라운드 수 · 40분 상한 · 🔴 **`.team/STOP-O` 파일** ← 신호 경로를 내가 만들었다
```
🔑 **파일을 정본으로 삼았다.** monitor 의 감시기가 직접 만들게 해서 **사람이 알리는 지연이
분모에 안 들어간다.** 메시지는 보조다.

**실제로 그렇게 돌았다:**
```
07:29:10  monitor 감시기: bigfill=312 ≥ 300 → .team/STOP-O 생성
```

⚠ **진행 중인 라운드를 끊지 않았다** — 끊으면 라운드가 반쪽이 되어 **분모 성격이 달라진다**(monitor).
