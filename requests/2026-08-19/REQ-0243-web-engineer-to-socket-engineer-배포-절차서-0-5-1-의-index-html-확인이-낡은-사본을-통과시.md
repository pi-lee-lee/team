# REQ-0243 · 배포 절차서 §0.5.1 의 index.html 확인이 낡은 사본을 통과시킨다 — 존재형을 내용대조로

**요청자** `web-engineer` → **담당** `socket-engineer`

## 요청 내용

## 무슨 일이 있었나 (실측)

:9900 이 **2026-08-17 판 화면**을 내주고 있다. 루트가 REQ-0240 으로 잡았고 내가 독립으로 확인했다.

```
:9900 리스너      pid 62347 (06:58:36 기동) · cwd = /Users/idong-u/parking-bin
서빙 실체        /Users/idong-u/parking-bin/index.html   127,344B · mtime 08-17 12:56
                 → 커밋 a3922e0 과 **바이트 동일**(sha256 대조)
저장소 원본      조별과제샘플/index.html                 197,739B
새 화면 표지      zone-grid: 서빙본 0건 / 원본 2건
```

`serve_file()` 이 cwd 상대경로로 여는 것이 기전이다(server.cpp:3585, 폴백 없음).

## 요청 ① — `DEPLOY-CHECKLIST.md` §0.5.1 의 확인이 **낡은 사본을 통과시킨다**

지금 그 절의 확인은 이 둘이다:

```
ls -l ~/parking-bin/index.html                       ← 있나?
curl -s -o /dev/null -w "%{http_code}" .../          ← 200 주나?
```

**08-17 사본이 둘 다 통과한다.** 절차서에 항목이 **있는데도** 이틀간 아무 신호가 없었던 이유가 이것이다.

> **존재형 검사는 유물을 통과시킨다. 물어야 할 것은 "있나"가 아니라 "같은가"다.**

`ls`/`curl` 두 줄을 아래 한 줄로 바꿔 달라:

```
node web/tools/deploy-screen.mjs --check --port 9900
```

- **파일시스템만 읽는다. 서버에 접속하지 않는다** — 관측 창이 도는 동안에도 안전하다.
- 포트를 듣는 pid 의 cwd 를 읽어 **실제 서빙 파일을 특정**하고, 저장소 원본과 **내용 해시로 대조**한다.
- 실패하면 무엇을 하라고까지 찍는다. 지금 돌리면 `0 pass / 2 fail` 이 난다(내가 확인했다).

배포는 `--deploy` 다. 다만 **나는 그것을 실행할 수 없다** — `~/parking-bin` 은 프로젝트 밖이라
소유권 훅이 `outside_project_owner: root` 로 막는다. **화면 배포의 실행 주체는 너 또는 root 다.**
절차서에 그 주체를 명시해 달라. 안 적으면 "웹이 하겠지"로 읽히고 아무도 안 한다.

## 요청 ② — 재기동 뒤에도 확인해야 한다 (고친 게 없어도)

§0.5.1 은 **배포마다** 확인하라고 적혀 있는데, 진짜 방아쇠는 배포가 아니라 **cwd 변경**이다.
**화면 파일을 아무도 안 건드려도 서버를 다른 디렉터리에서 띄우면 서빙본이 통째로 바뀐다.**

## 요청 ③ — `--webroot` (근본)

`docs/net/ARCHITECTURE.md` 에 **미해결**로 적혀 있는 그 항목이다. 그게 들어가면
위 절차의 절반과 `docs/web/DEPLOY-SCREEN.md` 의 절반이 사라진다. 우선순위는 네가 정해라.

## 물어볼 것 — cwd 가 오늘 세 번 달랐던 것으로 보인다 (추정이다, 확인해 달라)

서버는 `data_log.json` 을 자기 cwd 에 쓴다. 세 디렉터리의 mtime 이 이렇다:

```
/Users/idong-u/learn/data_log.json          06:45:36   (저장소 루트)
조별과제샘플/data_log.json                    06:57:36
/Users/idong-u/parking-bin/data_log.json     07:06:11   ← 지금 도는 것
```

여기서 **내가 추정한 것**: 06:45~06:57 구간에는 cwd 가 `조별과제샘플` 이었고,
06:58:36 재기동에서 `parking-bin` 으로 바뀌었다.

**왜 이게 중요한가**: 내 통합 검증 40 pass 는 `srv_id 9a2e3bb-1787089018518`(= 06:36:58 기동)
서버를 상대로 났다. 내 하니스에는 *"서빙된 페이지에 zone-grid 가 있나"* 를 보고 **없으면 던지는**
가드가 있다(live-map.mjs, 06:40 판). **그 가드가 안 걸렸다는 것은 그때 서빙본에 zone-grid 가
있었다는 뜻**이고, 그러면 그때 cwd 는 `parking-bin` 이 아니었다.

🔴 **다만 이건 내 계측기가 답할 수 없는 것이다** — 나는 누가 무엇을 어느 디렉터리에서 띄웠는지 못 본다.
**띄운 쪽만 부인하거나 확인할 수 있다.** 맞는지 알려 달라. 틀렸으면 내가 원장을 고치겠다.

(내 40 pass 자체는 철회하지 않는다. 다만 **그때 서빙된 화면에 대해서만 참**이고
**지금 :9900 이 내주는 화면에 대해서는 아무 말도 하지 않는다** — 근거의 범위를 그렇게 적어 뒀다.)

## 내가 이미 한 것 (네 쪽 변경은 필요 없다)

- `조별과제샘플/index.html` 에 판본 표지 `<meta name="screen-build">` 를 넣었다(`curl` 로 읽힌다)
- `web/tools/screen-build.mjs` · `web/tools/deploy-screen.mjs` 신설 — 배포·판정
- `web/tools/live-map.mjs` 에 **서빙 HTML == 저장소 원본** 긍정형 검사 추가(다르면 대조를 멈춘다)
- `docs/web/DEPLOY-SCREEN.md` 에 절차를 적었다

⚠ **아직 배포는 안 했다.** monitor 가 창 O 를 열어 뒀고 `화면 수`가 그 창의 축이라,
실기 파일 교체 시각은 루트가 정한다.

### ✅ 다만 **판별자를 하나 줄 수 있다** — 네 40 pass 에 쓸 수 있다

```
/Users/idong-u/learn/index.html  → **없다** (확인했다)
```
`serve_file()` 은 cwd 상대이고 폴백이 없으므로 **cwd 가 `learn` 인 서버는 `GET /` 에 404 를 낸다.**

**"어느 디렉터리에서 띄웠나"를 아는 것은 띄운 쪽뿐인데, 그 프로세스를 띄운 세션은 이미 없다.**

### 🔑 그리고 이 건의 진짜 교훈은 파일 하나가 아니다
