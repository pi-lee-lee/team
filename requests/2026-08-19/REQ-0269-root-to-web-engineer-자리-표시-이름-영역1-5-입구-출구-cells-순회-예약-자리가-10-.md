# REQ-0269 · 자리 표시 이름(영역1~5·입구·출구) · cells 순회 · 🔴 예약 자리가 10→5 로 준다 (사용자 확정)

## 요청 내용

# 자리 표시 이름 · `cells` 순회 · 🔴 **자리가 5개가 된다** (사용자 확정)

⚠ **루트가 이 사양을 메시지로만 보냈다. web 이 "REQ 로 내 달라"고 요구했고 맞다** —
세션이 죽으면 사양이 사라지고 처리 결과를 적을 자리도 없다. **이 파일이 정본이다.**

## 1. 🔴 사용자 확정 — **주차 자리는 5개다. 센서가 이중화된 것이다**

루트가 대가를 눈에 보이게 적어 물었고 그대로 고르셨다:
```
영역1 (= 자리 하나)  ● 예약하기
  ├─ 주차확인센서 #0 (A1)
  └─ 주차확인센서 #5 (B1)
…
영역5 (= 자리 하나)  ○ 예약하기
  ├─ 센서 #4 (A5)
  └─ 센서 #9 (B5)

🔴 예약 가능 자리 **10 → 5**
🔴 **B* 예약 버튼이 사라진다** — 사용자가 11:32:59 에 실제로 누른 그것이다
```
⚠ **살아 있는 B* 예약은 0건**(socket 확인). **전환에 잃을 것은 없다.**
🔴 **그래도 사용자 눈에는 버튼이 반으로 준다.** 배포 뒤 *"버튼이 없어졌다"* 를 물어올 수 있는 자리다.

## 2. 표시 이름 — **네가 정한 방향 그대로 승인한다**

```
Zone.id      A1 A2 A3 A4 A5 E1 X1      ← 🔴 안 바뀐다. 전선 예약 id 다
표시         영역1 … 영역5 · 입구 · 출구
```
✅ **`ZONE_LABEL` 표를 한 곳에만** — 2단계(id 자체를 `영역1~5` 로)에서 **그 표 하나만 지운다.**
✅ **`id` 를 감추지 않는다** — 표시 이름 + 작은 `id`. **예약 전선에 나가는 값이고 로그와 맞춰야 한다.**
✅ **`cells` 는 길이 가정 없이 순회.** socket 이 강제를 푼다. 실제 길이는 지형 정의가 정하고 명세에 적힌다.

⚠ **2단계는 별건이다** — arduino 굽기와 같은 경계에서 `id` 를 바꾼다. **지금은 라벨만.**

## 3. 🔴 서버가 곧 보낼 것과 맞춰라 (socket 이 명세에 박는다)

```
· zones 가 12 → **7** 개로 온다
· 자리 하나에 modules 가 **둘**
· 🔴 자리 `occupied` 를 **서버가 계산해 값으로 준다** — 두 센서를 화면이 조합하지 마라
  (§"파생 값은 원본을 가진 쪽이 계산한다" · `ack_budget_ms` 판례)
· 🔴 **B\* 예약 요청의 거절 사유 코드**가 새로 생긴다 — socket 이 정한다
  **네 REASON_TEXT 에 넣어라.** 모르는 코드는 지금처럼 조용히 무시하되,
  **그 코드가 오면 사람이 읽을 수 있어야 한다**
```
⚠ **필드 이름을 지어내지 마라.** socket 이 정하면 루트가 넘긴다.

## 4. 검사

✅ **`--live` 로 지형 하드코딩(Z1/Z2/Z3)을 걷어내고 map 순회로 일반화한 것** — 그래서 **7영역이 와도 그대로 돈다.** 그 판단이 이 변경을 미리 받아 낸 것이다.

**추가로 볼 것:**
```
· 표시 이름 집합 == ZONE_LABEL 이 정의한 집합 (긍정형·집합 대조)
· 🔴 id 가 화면 어딘가에 **반드시 보인다** — 감추면 로그와 못 맞춘다
· cells 길이가 1 이 아닌 지형에서도 그려지는가
⚠ 음성 대조를 붙여라 — 라벨 표를 비우면 실제로 빨강이 되는가
```

## 5. 순서

**socket 의 0260 배포보다 먼저 준비해 두는 것이 낫다** — 지형이 7로 바뀌는 순간 라벨이 없으면
화면에 `A1`·`A2` 가 그대로 뜬다. **다만 배포 시각은 루트가 준다.**

사용자가 주차 자리를 5개(센서 이중화)로 확정했고 지형이 7영역으로 바뀌는데 라벨이 없으면 화면에 A1·A2 가 그대로 뜬다

### 2. 표시 이름 — `ZONE_LABEL` 한 곳

```
A1→영역1 … A5→영역5 · E1→입구 · X1→출구
```
- ✅ **표가 한 곳이다.** 2단계에서 `id` 자체가 바뀌면 **그 표만 지우면 된다.**
- 🔴 **표에 없는 id 는 지어내지 않고 id 를 그대로 쓴다.** `B*` 가 지금 그렇다 —
  자리가 5개가 되면 `B*` 는 영역이 아니라 **같은 자리의 둘째 센서**라서 이름이 없는 것이 맞다.
  ⚠ 없는 이름을 붙였으면 사용자가 **`영역6`** 을 보게 된다.
- 🔴 **`id` 를 감추지 않았다**: 표시 이름 옆 작은 글씨로 날 id + 툴팁에 *"예약·명령에 쓰이는 자리 id"*.
  🔑 **`.zone__id` 칸의 내용은 여전히 날 id 로 뒀다** — `live-map` 이 그 칸으로 두 경로를 대조하기
  때문에 거기에 표시 이름을 넣었으면 **그 대조가 조용히 깨진다.** 표시는 새 칸(`.zone__name`)에 담았다.

### 3. `cells` — 순회는 이미 하고 있었다. 🔴 **그런데 중복 렌더 결함이 있었다**

```
옛 코드 : 칸마다 byCell 에서 자리를 꺼내 renderZone 을 부른다
        → cells 가 둘이면 **같은 자리에 예약 버튼이 두 개** · 노드 박스도 두 벌
```
⚠ **지금 지형(모든 `cells` 길이 1)에서는 안 보인다.** socket 이 강제를 푸는 순간 드러난다.
🔑 *"순회하니까 N:1 이 와도 이 코드가 안 바뀐다"* 는 주석이 **이미 있었는데**, 순회가 만든 **중복**은
안 봤다 — **입력을 일반화한 것과 출력이 옳은 것은 다른 진술이다.**
→ **한 번만 그리고**, 같은 행에서 연속이면 `span`, 아니면 나머지는 **"이어짐"** 칸으로 둔다
(빈 칸과 달라야 한다: 빈 칸은 *자리가 아니고*, 이어짐은 *자리인데 왼쪽에서 그렸다*).
**주입으로 `cells:[[1,0],[1,1]]` 자리를 넣어 실제로 밟았다 — 한 번만 그려지고 예약 버튼 1개다.**

### 1. 자리 5개 전환 — **화면은 이미 준비돼 있다**

서버가 `zones` 를 7개로 보내면 **그대로 그려진다.** `B*` 가 사라지면 예약 버튼도 같이 사라진다 —
**화면이 자리 수를 세지 않고 서버가 준 `zones`·`actions` 를 그리기 때문**이다.
🔴 **`occupied` 를 화면이 조합하지 않는다** — 두 센서를 합치는 것은 서버 몫이라고 §3 에 못 박혔고,
내 코드는 지금도 `state` 의 자리 `occupied` 를 그대로 쓴다. **바꿀 것이 없다.**
⏳ `B*` 예약 거절 사유 코드는 **socket 이 정하면 `REASON_TEXT` 에 넣는다.** 지금은 모르는 코드가
오면 조용히 무시하고 `fault` 계열 기본값으로 그린다(§5.65) — **화면이 안 깨진다.**

#### 🔴 음성 대조에서 **내 예상이 틀렸다** — 이게 오늘 제일 중요한 발견이다

`--drop-labels` 로 라벨 표를 비웠더니:
```
❌ 화면에 ZONE_LABEL 표가 있다                          ← 이것만 잡았다
✅ 표시 이름 집합 == ZONE_LABEL 집합   [] == []          ← 🔴 **공허하게 통과**
✅ 표시 이름의 글자가 표와 같다                          ← 🔴 대상 0개라 통과
```
> **기대값을 피검체에서 읽으면, 피검체가 비었을 때 기대도 같이 비어 양쪽이 만난다.**
> **`A == B` 는 둘 다 사라져도 참이다.**

**기대 표를 하니스에 복사하지 않은 것 자체는 옳다**(판정자 하나). **비었을 때를 따로 단언하면 된다** —
`Object.keys(LABELS).length > 0` 한 줄이 막는다. 원장 §5.88.
🔑 **긍정형·집합 대조인데도 통과했다.** §5.68(부정형)·§5.85(존재형)를 아는 사람도 이건 안 걸러낸다.
⚠ **돌리기 전 내 예상은 "표를 비우면 빨강"이었고 틀렸다** — **검사가 실패하는 것을 눈으로 보기 전까지
그 검사가 무엇을 잡는지 모른다.**
