# 🔴 정정 — 05:37:03 굽기의 장치 축은 **하나가 아니라 둘**이었다

**앞선 보고를 철회한다.** 굽기 전 보고와 `arduino/INTERVENTIONS.md` 는
*"축은 A(가상 O* 모듈) 하나다 · espInit 은 뺐다"* 라고 적었다. **안 빠졌다.**

## 무엇이 사실인가

```
칩 판본  커밋 9edbcca · 2026-08-19 05:37:03 · hex IDENTICAL (이 세션에서 재빌드로 독립 재확인)
실제 축  A = 가상 O* 모듈 (6498b52)     ← 기록됨
         B = espInit    (b2d6574)      ← 🔴 "뺐다"로 잘못 기록됨. 같이 구워졌다
축 아님  ba744b3 = 주석만  ·  e6091b5 = hex 차이 0 실측
```

## 근거 — 세 각도 (전부 실측)

```
① git merge-base --is-ancestor b2d6574 9edbcca  → 0 (조상이다)
   git show 9edbcca:.../client.ino → espInit() 정의 3393행 · setup() 호출 3696행
   옛 wifi.begin / netStep 3줄은 사라져 있다
② 굽기 입력 arduino/.burn/client/client.ino (05:36) → 저장소 스케치와 cmp 차이 0
   git diff 9edbcca -- 스케치 → 비어 있음
🔴 ③ 그 소스를 재빌드 → vmodburn/client.ino.hex 와 바이트 동일
   cmp.py chip-vmod.hex → verify-espinit 응용 다른바이트 0 · IDENTICAL
```
①②는 소스 판독이라 같은 각도다. ③이 컴파일러 산출물과 칩 덤프라 각도가 다르다.

## 영향 범위 — 좁게 적는다

**축 B 는 어느 계측기에도 표지가 없다.** 소스 판독으로는 `setup()` 에서
`netStepAt = millis()` 가 29줄 앞당겨지는 **부팅 1회성 시점 이동**이다(`netStepWait = 500`,
이후 사다리가 시각을 다시 잡는다). **실측이 아니라 소스 판독이다.**

```
정상상태(사다리가 도는 중) 현상  → 이 축과 무관하다고 읽어도 된다
부팅 국면 현상                   → 🔴 이 축에서 배제할 근거가 없다
```
**경계는 05:37:03 하나다.** 창 J 칩(def8093)에는 이 축이 없었다(검사 exit=1).
그 앞 창들은 영향 없다.

## 루트가 판단할 것

```
1. 창 L/M 판정의 축 재귀속 — 나는 장치 축만 안다. monitor 와 맞춰야 한다
2. espInit 단독 굽기 계획은 폐기다 — 이미 섞였으므로 실행할 수 없다.
   따로 지시가 없으면 나는 이 항목을 다음 굽기 목록에서 지운 상태로 둔다
```

## 왜 안 잡혔나 — CLAUDE.md 가 이미 적어 둔 부류다

앞 세션은 **"이번 굽기에서 espInit 을 뺀다"를 결정했고 그 결정을 정확히 기억했다.**
그 커밋이 이미 굽는 트리의 조상이라는 것을 아무도 재지 않았다.

> "안 했다"는 자기 행동의 기록이지 시스템 상태의 기록이 아니다.
> 빼려면 되돌리거나 갈라내야 한다. "안 넣기로 정하는 것"으로는 안 빠진다.

socket 의 08-18 "미배포 커밋 목록에 미배포가 하나도 없었다" 와 같은 형태다.
그쪽은 "배포", 이쪽은 "굽기"라 다른 일로 보여서 그 사고를 읽고도 밟았다.
⚠ INTERVENTIONS 에 "❌ 뺐다"라고 명시적으로 적혀 있어서 더 안 보였다 —
**적어 놓은 것이 확인의 자리를 차지했다.**

## 재발 방지 — 원장 §23.7 에 규칙으로 박았다

```
git log --oneline <직전 칩 커밋>..<굽는 커밋> -- 조별과제샘플/client.ino
git merge-base --is-ancestor <빼려는 커밋> <굽는 커밋>     # 0 이면 이미 들어 있다
```
굽기 축 목록을 이 두 명령으로 만든다. 손으로 적은 PLAN-axes 는 초안으로만 쓴다.
"뺀다"고 적을 때는 is-ancestor 를 실제로 친다.
