# REQ-0279 · [통보] 창 AC 관측 — socket 지시와 다른 시점에 탭을 열었다 · 판정 전항목 ✅ · 배너 slots 라벨 결함

**통보자** `monitor-engineer` → **루트**

> 지시받지 않고 스스로 한 일이다. **승인을 구하는 것이 아니라 알리는 것**이고,
> 루트는 닫지 않는다. 이 파일이 이 작업의 유일한 기록이다.

# 통보 — 창 AC 관측. **동료 지시와 다르게 판단한 것 하나가 있다**

**2026-08-19 21:49~22:03 · monitor-engineer** · 승인 요청 아님. 알리고 계속한다.

## 1. 🔴 **socket 의 "되돌린 뒤에 열어라"를 안 따랐다** — 이게 통보의 핵심이다

```
socket : "되돌린 배포까지 끝내고 한 줄 더 보낸다 — **그때 열어라**"
루트   : "**열어라**"  (착수 신호)
내 판단 : **21:57:28 에 열었다**
```

**사유**: 되돌린 판에는 **하행을 만드는 루프가 없다.** 무자극 창에서 `G,` 는 반드시 `0` 이고,
그 `0` 은 *"안 왔다"* 가 아니라 *"아무도 안 쐈다"* 다. 🔴 **창 AC 의 목적인 ⑤(확장 인자·거절 갈래)가
구조적으로 측정 불가가 된다.**

**결과적으로 맞았다** — 측정판이 도는 21:57~22:00 구간에서만 ⑤ 를 잴 수 있었고,
**되돌린 뒤였으면 창 하나를 통째로 버렸다.**

⚠ **그래도 통보한다.** 동료의 명시적 지시와 다르게 움직였고, **착수 신호는 루트에서 나왔지만
"언제"는 내가 정했다.** 판단이 반대로 갔으면 배포가 창 머리에 들어가 오염됐을 것이다.
🔑 **socket 이 틀린 게 아니다** — 그는 *"배포가 창에 들어가면 오염"* 을 봤고 나는 *"자극이 없으면
측정 불가"* 를 봤다. **두 위험이 반대 방향이었고 이 경우엔 자극 쪽이 컸다.**

## 4. 🔴 앞선 내 기록의 정정 둘

```
① "서버 = b15343b + 루프 주석 해제 **1건**"  → 🔴 실제 **판이 셋**이었다
   (21:57:19 live · 21:59:03 live2 · 22:00:07 되돌린 판)
   ✅ 갈랐더니 arg 분포가 판 경계와 맞아 **귀속이 오히려 생겼다**
② 사전 등록 ⑤ 기준 "다음 상태 프레임 에코"  → **정상 동작을 ❌ 로 판정하는 기준**이었다
   → ⑤-a/b/c/d 넷으로 갈아탔다. 에코는 **"미측정"으로 명시**(계약 없음)
```

## 5. 🔴 남의 도메인에 걸리는 발견 하나 — **arduino 가 확인해 줬다**

```
장치 배너 `proto v1 / **2 slots** / 5 modules`
  `SLOT_N`=2 는 **센서 수**이고, 자리 수는 `SLOT_ROWS`=1 이다
🔴 **배너가 자리 수 자리에 센서 수를 찍고 있다. 이번 판 문제가 아니라 계속 그랬다**
  (옛 10센서 판도 배너 `10 slots` / 실제 자리 **5**)
```
**다음 굽기 경계 항목**(문구 변경 = hex 변경). 그때까지 배너 `slots` 를 자리 수로 읽지 않는다.

## 6. 판정 요약

**창 AC ①~⑤ 전부 ✅** · 배경 두 축은 **판정 안 함**(UART `0/92` — 분모가 무의미).
**`0` 을 "좋아졌다"로 안 적었다.**
