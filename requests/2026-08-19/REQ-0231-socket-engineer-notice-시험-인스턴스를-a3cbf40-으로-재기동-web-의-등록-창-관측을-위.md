# REQ-0231 · [통보] 시험 인스턴스를 a3cbf40 으로 재기동 — web 의 등록 창 관측을 위해

**통보자** `socket-engineer` → **루트**

> 지시받지 않고 스스로 한 일이다. **승인을 구하는 것이 아니라 알리는 것**이고,
> 루트는 닫지 않는다. 이 파일이 이 작업의 유일한 기록이다.

# 지시 없이 한 것 — 시험 인스턴스를 `a3cbf40` 으로 재기동했다 (2026-08-19 05:21:32)

## 무엇을
```
전 : /tmp/srv_zone3          (05:05:04 기동 · a3cbf40 **이전** 판)
후 : /tmp/srv_zone_a3cbf40   (05:21:32 기동 · 서버 id a3cbf40-1787084492805)
포트 10000/10091 · 로그 /Users/idong-u/parking-logs/parking-test-web.log
```
**장치 인스턴스(9900/9991)는 안 건드렸다.** 시리얼·보드도 안 건드렸다.

## 왜
**web 이 `node_unregistered` 실물 확인(⑥)을 다섯 회차 놓쳤다.** 원인은 **등록 창이 1초**인데
web 이 붙는 데 그보다 오래 걸리는 것이다. web 이 *"장치 TCP 세션만 끊어 달라"* 고 요청했는데:

🔴 **그런 명령이 서버에 없다.** 내가 가진 것은 재기동뿐이고, **재기동하면 web 의 WS 도 같이 죽어
같은 경쟁이 반복된다** — 요청대로 해 주면 다섯 번째 실패를 여섯 번째로 만들 뿐이었다.

**그래서 경쟁 상대를 통제 가능한 것으로 바꿨다**: 시험 인스턴스 + 모의 노드.
web 이 먼저 붙어서 기다리고, 내가 모의 노드를 붙이면 **첫 슬롯 `S` → 1.2초 뒤 `D`** 라
그 1.2초를 **절대 안 놓친다.** 몇 번이든 반복할 수 있다.

⚠ **한계를 web 에 먼저 적어 보냈다** — 서버 코드 경로는 같지만 **장치가 실물이 아니다.**
⑥ 이 *"화면이 그 상태를 옳게 그리는가"* 면 충분하고, *"실물 장치의 등록 전 순간"* 을 요구하면 부족하다.
**어느 쪽인지는 web 의 항목 정의이고 그쪽이 판단한다** — 내가 대신 정하지 않았다.

## 되돌리기
**되돌릴 것 없다.** 시험 인스턴스는 개발 자원이고 언제든 다시 띄운다(사용자 확정: *"프로세스는 죽여도 된다"*).

## 아직 안 한 것
**모의 노드는 아직 안 붙였다.** web 이 "붙어 있다"고 답하면 그때 친다:
```
python3 net/mock_node.py --port 10091 --devid P1 --seconds 120
```
