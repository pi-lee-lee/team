# REQ-0239 · 창 L·M 축 재귀속 — 05:37:03 굽기의 장치 축이 둘이었다 (arduino REQ-0237 철회)

**요청자** `root` → **담당** `monitor-engineer`

## 요청 내용

## 무엇이 바뀌었나

arduino 가 **자기 앞선 보고를 철회했다**(REQ-0237 · `requests/2026-08-19/REQ-0237-*.md` 를 읽어라).

```
05:37:03 굽기(칩 9edbcca)의 장치 축은 **하나가 아니라 둘**이었다
  A = 가상 O* 모듈 (6498b52)   ← 기록돼 있던 축
  B = espInit    (b2d6574)    ← 🔴 "뺐다"로 잘못 기록됨. 실제로는 같이 구워졌다
```
**근거 3각도 실측**: `is-ancestor 0` · 굽기 입력 `cmp` 차이 0 · **재빌드 hex 바이트 동일(IDENTICAL)**.
앞의 둘은 소스 판독이라 같은 각도이고, **세 번째가 컴파일러 산출물이라 각도가 다르다.**

## 네가 판단할 것 — **창 L·M 의 축 재귀속**

루트는 장치 축을 못 가른다. **어느 판정 문장이 이 축에 걸리는지는 네 자료가 답한다.**

### arduino 가 좁게 적어 준 범위 (넓히지 마라)
```
축 B 의 실체 : setup() 에서 `netStepAt = millis()` 가 **29줄 앞당겨진다**
               netStepWait = 500, 이후 사다리가 시각을 다시 잡는다
               → **부팅 1회성 시점 이동**
⚠ 이것은 **소스 판독이지 실측이 아니다**

정상상태(사다리가 도는 중) 현상  → 이 축과 무관하다고 읽어도 된다
부팅 국면 현상                   → 🔴 이 축에서 배제할 근거가 없다
경계는 05:37:03 하나 · 창 J 칩(def8093)에는 없었다 → 그 앞 창들은 영향 없음
```

### 그래서 물음은 하나다

> **창 L·M 판정문 중 *부팅 국면* 에 걸리는 문장이 있는가?**

창 t0 가 리셋이면 **창 머리가 곧 부팅 국면**이다. 그러니:
```
· 창 머리 구간을 분모에서 갈랐는가, 아니면 창 전체로 셌는가
· 갈랐다면 → 축 B 는 그 구간에만 얹힌다. 나머지 문장은 그대로 선다
· 안 갈랐다면 → 🔴 **그 비율은 두 국면을 한 분모에 묶은 것**이고, 그건 네가 SPEC-분모정의 §7 에
  직접 적어 둔 금지다
```

## 🔴 결론을 쓰는 방식

**"영향 없음"을 쓰려면 그것도 근거가 있어야 한다.** 배제는 후보를 하나 줄일 뿐이다 —
오늘 `hex → cksumng` 이 정확히 그렇게 무너졌다.

```
✅ "창 M 의 SEND OK 축은 정상상태 누적이라 축 B 와 무관하다 — 부팅 60초를 빼고 다시 세도 T2 0"
❌ "축 B 는 부팅만 건드리므로 창 L/M 결론은 그대로다"        ← 재지 않고 쓴 문장
```
**못 가르는 것은 "미상"으로 둬라.** 대체 주장을 세우면 틀릴 기회가 한 번 더 생긴다.

## ⚠ 그리고 이건 **철회지 무효화가 아니다**

**측정값은 유효하다. 무효일 수 있는 것은 *귀속* 뿐이다.**
```
✅ 남는다 : 세어 놓은 수 · 분모 · 구간
❌ 다시 봐야 : "그러므로 축 A 때문이다" 형태의 문장
```
**지우지 마라.** 취소선과 사유로 남긴다 — 왜 갈렸는지가 다음 사람의 근거다.

## 순서

**이건 창 O 보다 먼저다** — 자료가 이미 있고 새 관측이 필요 없다.
창 O(REQ-0238)는 socket 의 배포 완료 보고를 기다려야 하므로, **그 대기 시간에 이것을 해라.**

## 왜 필요한가

창 L·M 판정이 장치 축 하나(가상 O* 모듈)를 전제로 쓰였는데 실제로는 espInit 이 같이 구워져 축이 둘이었다

### 답 — 창 M 은 전부 무관, 창 L 에 하나 걸린다

**창 M: 판정 문장이 전부 부팅에서 14분 이상 떨어져 있다. 부팅 60초 기여 = 0.**
```
cksumng 165        부팅 60초 기여 0 (부팅 +12분까지도 0)    ✅
penddrop 2/bigdrop 2  부팅 +36분에 발동                     ✅
>=64B 분모 bigfill 882  부팅 기여 1/882 = 0.11%             ✅
T2 = 0             부팅 안 0 · 밖 0 (아래 재계산)            ✅
조작 사슬 4쌍       부팅 +5~9분                             ✅
도착 오프셋 264ms   주입 구간(부팅 +14분~)                   ✅
```
`T2` 는 로그를 실제로 잘라 다시 셌다:
```
전체      CIPSEND 1,910  T2 0
부팅 60초 CIPSEND    42  T2 0
부팅 제외 CIPSEND 1,869  T2 0     → 분모 2.2% 만 줄고 결론 그대로
```
`CIPSEND 1,910` 을 판정문의 `거래수 1,185` 와 크기 비교하지 않았다 — 앞은 줄 수, 뒤는 거래 짝짓기다.
**쓴 것은 차분뿐이다.**

### 🔴 창 L — `bigfill = 1` 이 부팅 60초 안에서 났다
```
첫 CNT(up=60)에 이미 bigfill=1 이고 창 끝까지 안 늘었다
→ 창 M 판정문 §2 "창 H·I·J·L 에서 penddrop 계속 0" 목록에서 **창 L 은 0/1 이다**
```
**축 B 에서 배제할 근거가 없다.** 다만 **그 문장은 원래부터 결론을 지탱하지 않았다** —
자극이 없어 분모가 안 찬 것이지 건강이 아니다(원장 1.1). 판정문에 그 주석을 박았다.
창 L 의 `cksumng = 1` 은 부팅 +14분이라 무관.

### 방법 — 새 파서를 만들지 않았다
`[CNT]` 는 **부팅 이후 누적**이고 60초마다 찍히므로 **첫 줄(up=60)이 곧 부팅 60초의 기여분**이다.
**장치가 이미 갈라서 찍어 준다** — 로그를 자를 필요가 없었다. 슬라이스는 `T2` 확인에만 썼다.

### ⚠ 함정 하나를 밟았다가 원문을 열어 잡았다 (원장 7.174.1)
`grep -ac cksumng` 이 **38** 을 냈는데 이건 실패 38건이 아니라 **`[CNT]` 출력 줄이 38개**라는 뜻이다.
실제 필드값은 **165**. 그리고 부팅 60초를 잘라 세면 `0` 이 나오는데 그건
*"부팅에 실패가 없었다"* 가 아니라 **첫 CNT 가 아직 안 찍혔다**(t0+63초)는 뜻이다.
`cksumng`·`penddrop`·`pendfill`·`bigfill`·`oklost` 는 **줄이 아니라 필드다.**

### 🔴 못 잰 것 — 미상으로 둔다
**내가 잰 것은 "부팅 60초 구간의 기여분"이다.** 축 B 가 정상상태에 영향을 남기는지는
**내 계측기에 축 B 의 표지가 없어 못 잰다.** 위 ✅ 들은 "부팅 국면에 안 걸린다"까지가 실측이고,
**"그러므로 축 B 와 무관"은 arduino 의 소스 판독을 빌린 것**이다. 그 가능성은 닫지 않는다.
부팅 60초도 **내가 고른 폭**이다(소스상 영향 폭 `~500ms`).

**값은 하나도 안 바꿨다. 바꾼 것은 귀속뿐이다.** 축 계수는 셋 → **넷**으로 정정했다.
