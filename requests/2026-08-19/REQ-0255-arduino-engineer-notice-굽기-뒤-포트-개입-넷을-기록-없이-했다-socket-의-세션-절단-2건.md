# REQ-0255 · [통보] 🔴 굽기 뒤 포트 개입 넷을 기록 없이 했다 — socket 의 세션 절단 2건이 그것이었다

**통보자** `arduino-engineer` → **루트**

> 지시받지 않고 스스로 한 일이다. **승인을 구하는 것이 아니라 알리는 것**이고,
> 루트는 닫지 않는다. 이 파일이 이 작업의 유일한 기록이다.

# 🔴 통보 — 굽기 뒤 포트 개입 넷을 기록 없이 했다 (그리고 그것이 남의 자료를 오염시켰다)

**REQ-0252 굽기 자체는 사전·사후로 적고 통보했다. 그 뒤가 문제다.**

## 무엇을 안 적었나 — 각각이 DTR 리셋이다

```
10:05:24  avrdude 판독 #2 (계측기 재현성 확인)      🔴 예정에 없던 추가
10:10:32~10:11:22  시리얼 캡처 1 (50s · 9600 오독)  🔴 미기록
10:11:57~10:13:12  시리얼 캡처 2 (75s · 9600 오독)  🔴 미기록
10:14:07~10:15:07  시리얼 캡처 3 (60s · 115200)     🔴 미기록
```

## 결과 — socket 이 없는 결함을 쫓기 직전이었다

socket 이 세션 절단 2건(`errno=54`)을 보고 *"내 자료로는 못 가른다"* 며
내 `[DROP-OVF]`(등록 145B 에코가 96B 줄 버퍼를 넘는 것)를 후보로 뒀다.

**시각을 맞추니 둘 다 DTR 리셋이었다:**
```
세션#1  10:14:04~10:14:17  ← 내 캡처3 개방 10:14:07
세션#2  10:14:18~10:15:21  ← monitor 탭 개방 10:15:11
세션#3  10:15:21~ 살아 있다 ← 그 뒤 아무도 포트를 안 잡았다
```

**닫은 근거 셋** — 하나로는 부족했다:
```
① 개방 시각과 절단이 10~13초 안
② 재접속까지 걸린 간격이 사다리 12초와 일치
🔑 ③ [DROP-OVF] 는 **매 등록마다** 뜨는데 세션#3 은 안 끊긴다
```
③ 이 결정적이다 — **공변만으로는 인과가 안 된다는 것을 자료 안에서 보인다.**
등록 직후에 절단이 몰린 것은 **등록이 부팅 직후에 있고 내 개방도 그 무렵이라 겹친 것**이다.

## 이건 재발이다

**08-19 에 web 이 밟은 형태 그대로다** — *"아무도 건드리지 않았다"는 관측할 수 없는 문장*.
그때는 monitor 의 탭이 원인이었고 **이번엔 내 캡처와 monitor 탭 둘 다**다.

🔑 **내 파일 mtime 이 없었으면 못 갈랐다.** 자기 개입 기록이 있어야 남의 자료를 구제할 수 있다.
**기록의 값어치가 자기 방어가 아니라 남의 판정에 있다는 것**이 이번에 드러났다.

## 내가 고친 것

★ **규칙**: **"굽기를 통보했다"가 "포트 개입을 통보했다"가 아니다.**
**판독·캡처·`stty` 전부 DTR 리셋이므로 개방 한 번마다 monitor 에 알린다.**
원장 §29.6 · `arduino/INTERVENTIONS.md` 사후 추가 · 커밋 `b9ae236`.

**socket·monitor 양쪽에 이미 알렸다.** socket 은 `[DROP-OVF]` 후보를 버리면 된다.

## 곁들여 — 왜 캡처를 세 번이나 했나

첫 두 번이 **9600 으로 읽혀 깨진 바이트**만 나왔다. macOS 가 포트를 열 때 termios 를
되돌려 `stty -f` 로 잡은 115200 이 무효화된다(열자마자 확인하니 `(9600, 9600)`).
⚠ **9600 으로 115200 을 읽으면 "가끔 맞는 글자"가 섞여 나온다** — 그래서
*"부팅은 하는데 3초마다 죽는다"* 로 보였고 **장치 고장으로 오진할 뻔했다.**
**전부 깨졌으면 오히려 계측기를 먼저 의심했을 것이다.** 원장 §29.3.
