# REQ-0263 · 🔴 노드 통신 경로를 별도 클래스로 추출하고 잠근다 — 빈번한 수정이 안정화된 영역을 건드린다 (사용자 지시)

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

# 노드 통신 경로를 **별도 클래스로 추출하고 잠근다** (사용자 지시)

> 사용자 원문: *"1개의 단일 슬롯(노드)에 대한 **네트워크 안정화는 확인된 사항**이다.
> **현재 코드수정이 빈번히 발생하고 있어 해당 영역에 영향이 있을 수 있다.**
> 슬롯에 대한 리팩토링을 진행하여 **별도의 클래스로 추출**하고 해당 영역에 대하여
> **슬롯에 대한 수정이 아닌 수정사항에 의해 수정되지 않도록 설정**하라."*

## 0. 루트가 읽은 범위 — **틀렸으면 즉시 말해라**

```
대상 : 조별과제샘플/server.cpp 의 **노드 하나와의 통신·링크 경로**
근거 : "빈번한 코드 수정"이 지금 일어나는 곳이 여기다 — REQ-0260(7영역) · REQ-0262(mod_bits 를
       Node 로) · 3b(map<devid,Node>) 가 전부 이 파일의 구조를 흔든다
❌ 펌웨어는 이번 범위 밖 : arduino 는 오늘 값 셋 말고 변경이 없고,
   **펌웨어 리팩터링은 곧 굽기라 축이 하나 더 생긴다**(espInit 이 그 판례다)
```

## 1. 무엇이 "확인된" 것인가 — **먼저 목록을 만들어라**

**지키려는 것을 이름으로 못 적으면 잠글 수가 없다.** 창 P 실적이 근거다:
```
T2 0/451 · ACK 100.0% · 주입 중 절단 0 · 미주입 0 · 재전송 94
```
**후보**(네가 확정해라):
```
· 연결 수락 · devid 승격 · first-S-wins · 유예 교체
· 수신 조립(줄 경계·과길이·체크섬) · 승격 전 버퍼
· 오프라인 판정(§3.4 엣지) · keepalive · 회수
· 하행 큐 · 배치(cap 192B/4건) · ACK 대기·타임아웃·재전송 · rid 발행/격리
```
⚠ **전부 넣지 마라.** *"이번 리팩터링들이 건드릴 수 있는데 건드리면 안 되는 것"* 이 기준이다.

## 2. 🔴 추출은 **거동 변화 0** 이어야 한다 — 이게 이 작업에서 제일 어렵다

> ### **§"흩어진 것을 모으면 그것이 곧 거동 변경이다"**
> **`espInit` 이 그것으로 물렸다** — 이름만 바꾼 줄 알았는데 **`millis()` 호출 시점이 29줄 앞당겨졌고
> hex 가 15줄 달랐다.** *"이미 한 함수였던 것을 옮기는 것"* 과 *"흩어진 것을 모으는 것"* 은 다른 작업이다.

**그러니 판정을 산출물로 해라:**
```
① 추출 전후로 **-O2 빌드 산출물을 대조**해라. 같으면 그것이 "거동 변화 0"의 증거다
   ⚠ 다르면 **왜 다른지를 적어라** — 인라인 경계·순서·초기화 시점 중 무엇인가
   🔑 **다른 것 자체가 실패는 아니다. 설명 없이 다른 것이 실패다**
② 🔴 **선후가 바뀐 곳을 따로 세라** — "무엇이 앞당겨졌나"만 보면 부족하다
   (arduino §26: **앞당김은 눈에 띄고 선후 교체는 안 띈다**)
③ selftest 전부 통과 + 무경고
```

## 3. 잠그는 기계 — **루트가 만든다. 너는 경계만 정해라**

**"설정하라"는 규율이 아니라 기계여야 한다.** 우리 규칙 그대로다 —
§*"조건을 적었으면 그것을 보는 감시를 같은 자리에 만들어라."*

```
socket 이 하는 것 : ① 파일 분리(예: net_node.h / net_node.cpp — 이름은 네가 정한다)
                    ② 그 경계에 무엇이 들어가고 무엇이 안 들어가는지 문서화
루트가 하는 것    : ③ 그 파일이 **슬롯 REQ 없이 바뀌면 잡는 검사**를 team/bin 에 만든다
```
🔴 **파일을 분리하지 않으면 잠글 수가 없다** — `server.cpp` 한 덩어리로는 *"이 변경이 그 영역을
건드렸나"* 를 기계가 못 본다. **분리가 잠금의 전제다.**

⚠ **그리고 분리 자체가 축이다.** 이 작업을 **REQ-0260·0262 와 같은 배포에 넣지 마라** —
셋이 섞이면 무엇이 무엇을 깼는지 못 가른다. **순서는 루트가 준다.**

## 4. 순서 제안 (루트가 확정한다)

```
🔴 지금 진행 중인 것과 충돌한다 — REQ-0260·0262 가 바로 그 코드를 만진다
① 이 추출을 **먼저** 한다 → 잠근다 → 그 다음 0260·0262 를 그 위에서 한다
   장점: 0260·0262 가 잠긴 영역을 건드리면 **그 자리에서 잡힌다**
   단점: 추출이 늦어지면 나머지가 대기한다
② 0260·0262 를 끝내고 추출한다
   단점: 🔴 **지키려던 그 기간에 안 지켜진다.** 사용자가 걱정한 것이 정확히 이 구간이다
```
**루트 판단은 ①이다.** 사용자가 *"현재 코드 수정이 빈번히 발생하고 있어"* 라고 **현재형**으로 말했다.
**다르게 보면 근거와 함께 말해라 — 네가 코드를 안다.**

## 5. 완료 기준

```
① 지키는 목록이 이름으로 적혀 있다 (무엇이 "확인된" 것인가)
② 별도 파일로 분리됐고 경계가 문서에 있다
③ 🔴 추출 전후 산출물 대조 결과 — 같거나, 다르면 **왜**
④ selftest 통과 · 무경고
⑤ 루트가 잠금 검사를 만들 수 있게 **파일 경로를 확정해서 알린다**
```

## 왜 필요한가

3b·7영역·mod_bits 이동이 창 P 에서 확인된 통신 안정성 영역을 그대로 흔드는데 지금은 그것을 기계로 막을 수단이 없다
