# REQ-0275 · 펌웨어도 class 은닉으로 — 서버와 같은 2단계. 잠금·RAM·판별자 제약 셋

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

사용자 지시: **"아두이노도 리팩토링 해야겠는데? 서버랑 동일한 리팩토링을 했다."**

## 무엇이 다른가 — 서버가 걸어간 길

```
1단계 分離 : struct 를 파일로 뺐다  → 산출물 0 차이로 증명. **그런데 책임은 안 옮겨졌다**
             server.cpp 6,321 → 6,154 (167줄). 사용자가 "이건 은닉이 아니다" 로 정정했다
2단계 隱蔽 : class 로 책임을 옮겼다 → 사용 코드가 흐름으로 읽힌다. **지금 실기에서 돌고 있다**
```
**arduino 는 지금 1단계에 있다.** `client.ino` 2,980 → 1,786 줄에 헤더 8개 —
**전부 `static` 전역 + 자유 함수**다. 자료와 함수가 파일만 나뉘었지 **캡슐이 아니다.**

## 목표 — 사용 코드가 흐름으로 읽혀야 한다

서버의 실물이 기준이다:
```cpp
ParkingLot lot;
lot.spot("A1").sensor("A1").sensor("B1");
ParkingServer srv(lot);
if (!srv.openPorts()) return 1;
while (srv.serveOneTick()) { }
```
**아두이노에서 이에 대응하는 것이 `setup()`/`loop()` 여야 한다.** 지금은 그 안이 전부 절차다.

## 🔴 제약 셋 — 서버와 다르다. 반드시 지켜라

### ① 잠금 영역을 함부로 클래스화하지 마라
```
.claude/protected.json · firmware-esp-link (5파일)
잠금 사유(083d608) : **이 코드가 하드웨어 리셋을 불필요하게 만든 물건이다**(사용자 확정)
```
→ **링크 계층은 이번 범위에서 뺀다.** 겉을 감싸는 것(파사드)까지는 되지만
   **내부 절차·타이밍·상태 기계는 손대지 마라.** 만지려면 먼저 알려라.

### ② 자원 예산이 실재한다 — 서버에는 없던 제약
```
지금 : 플래시 26,320B (81%) · RAM 1,199B (58%)
여유 : 플래시 약 6KB · RAM 약 849B
```
→ **가상 함수·상속·동적 할당 금지.** 클래스는 **상태를 묶고 메서드를 다는 것**까지다.
   🔑 pimpl 도 쓰지 마라 — AVR 에서는 포인터 간접이 RAM 과 사이클을 먹는다.
→ **각 단계에서 플래시·RAM 증분을 값으로 보고해라.** 늘면 그것도 결과다.

### ③ 판별자가 서버와 다르다
```
`.o` 대조 : 안 된다(AVR 은 hex 가 재현되지만 클래스화는 산출물을 바꾼다)
✅ 쓸 것  : ① 회귀 시험 통과 수와 **분모** ② 플래시·RAM 증분 ③ **굽고 나서 부팅 로그·계수**
⚠ **"hex 차이 0" 을 목표로 삼지 마라** — 그건 1단계의 판별자였고, 은닉은 정의상 산출물을 바꾼다
```

## 요구

```
1. 지금 `client.ino` 1,786줄과 헤더 8개를 **무엇을 무엇으로** 묶을지 분해안 (덩어리별 줄 수)
2. 목표 `setup()`/`loop()` 를 **코드 모양으로** 제시 — 말이 아니라 시그니처로
3. 단계 순서. 한 단계에 하나씩. **각 단계의 판별자를 미리 적어라**
4. 🔴 **안 하겠다고 정한 것**을 같이 적어라 (REQ-0273 에서 네가 한 그대로)
5. 링크 계층에 닿는 지점이 있으면 **그 자리를 명시**하고 내 신호를 기다려라
```

⚠ **착수 전에 분해안부터 보내라.** 서버에서 방향이 한 번 틀렸고, 그때 되돌리는 비용이 컸다.
🔑 **그리고 굽기는 18시 이동 뒤다** — 이동하면 SSID·서버 IP 때문에 어차피 굽는다. **같은 경계에 실어라.**

## 왜 필요한가

지금은 파일 분리(1단계)까지다. 자료와 함수가 파일만 나뉘었고 책임은 안 옮겨졌다 — 서버가 같은 자리에서 사용자에게 정정받았다

- `조별과제샘플/ardu/client.ino`

setup()/loop() 이 흐름으로 읽히고, 회귀 통과 + 플래시·RAM 증분이 값으로 보고되며, 링크 잠금 영역 내부가 안 바뀐다

## 🔴 사용자 정정 (2026-08-19) — **`setup()`/`loop()` 는 유지한다**

> 사용자 원문: *"아니 ino 기본 구조는 `setup()` `loop()` 이다. **이 구조를 유지**하고
> 나머지는 클래스로 작성하여 **해당 구조 내에서 클래스 생성과 멤버 함수 호출 방식**으로
> 흐름이 보이는 구조로 작성하는 것이다."*

### 그러므로 이렇게 읽어라

```
❌ setup()/loop() 를 없애거나 감싸는 안        → **안 된다.** .ino 의 기본 구조다
✅ setup()/loop() 는 그대로 두고, **그 안이 조립 코드**가 된다
```

**목표 모양(예시 — 이름·경계는 네가 정한다):**
```cpp
Slots   slots;
EspLink link;
Node    node;

void setup() {
    slots.begin();              // 핀 배치·초기 점유
    link.begin(9600);           // ESP 링크 — 🔴 잠금 영역의 파사드
    node.begin(slots, link);    // 배치: 무엇이 무엇을 쓰는지 보인다
}

void loop() {
    link.pump();                // 수신 조립·해독
    node.tick();                // 슬롯 한 박자
    node.flushAck();            // ACK 배출
}
```

### 🔑 `loop()` 가 서버의 `serveOneTick()` 자리다

```
서버 : while (srv.serveOneTick()) { }   ← 한 박자가 호출부에 보인다
장치 : void loop() { … }                ← **한 박자가 여기 보여야 한다**
```

### 판별자는 이미 세워 둔 것을 그대로 쓴다 (`94f277e`)

```
호출자가 **순서를 바꿀 수 있다**  → 🔓 `loop()` 에 남겨라 (그게 흐름이다)
호출자가 **바꿀 수 없다**        → 🔒 멤버 함수 안에 넣어라 (드러내 봐야 지킬 의무만 생긴다)
```
⚠ **`loop()` 안의 호출이 열 줄이 되면 그건 흐름이 아니라 절차다.** 바꿀 수 없는 순서는 안으로 넣어라.
⚠ **반대로 세 줄로 줄이려고 바꿀 수 있는 선택까지 감추지 마라** — 그러면 흐름이 사라진다.

### ⚠ 전역 인스턴스에 주의

AVR 에서 전역 객체는 **생성자가 `main()` 전에 돈다.** 지금 `setup()` 안에서 하던 초기화가
생성자로 올라가면 **순서가 바뀐다** — 원장 §19(`espInit`: 흩어진 것을 모으면 그것이 거동 변경)의 재현이다.
🔑 **생성자는 비워 두고 `begin()` 에서 초기화해라.** 그게 아두이노 관용이기도 하다.
