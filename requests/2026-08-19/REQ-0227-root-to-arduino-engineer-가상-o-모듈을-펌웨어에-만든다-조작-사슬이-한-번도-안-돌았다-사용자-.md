# REQ-0227 · 🔴 가상 O* 모듈을 펌웨어에 만든다 — 조작 사슬이 한 번도 안 돌았다 (사용자 지시)

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

🔴 **사용자 지시: 실제 장치에 모듈이 없다. 가상 모듈을 펌웨어에 만들고 그것으로 통합 검증한다.**

> 원문: *"실제 장치에 모듈이 없다. 가상모듈을 아두이노에 작성하고 해당 모듈로 테스트하라."*

## 🔴 정확히 무엇이 없는가 — socket 이 실기 로그로 확인해 줬다

```
00:20:29  = 등록 완료 — n=10 · drain=7 · **명령가능 0개**
```
**모듈이 아예 없는 게 아니다. 10개가 등록된다 — 그런데 전부 `IP`(관측 전용)다.**
> ### 🔴 **`O` 로 시작하는 모듈(조작 가능)이 하나도 없다. 그래서 조작 사슬이 한 번도 안 돌았다.**

```
✅ 예약·취소 : 자리 기반 명령이라 전선까지 나간다 (등록과 무관)
🔴 open_gate : E1 에 모듈이 없어 **module_absent** 로 거절된다
```
**web 의 "미측정 1건"과 socket 의 `known:false`·`completion:unknown` 이 전부 이 자리에서 막혀 있다.**

⚠ **그리고 모듈만으로는 안 끝난다** — 모듈이 생겨도 **전선 명령이 없어 `not_supported`** 다.
**socket 에 그 명령을 만들라고 따로 지시한다. 둘이 같이 있어야 사슬이 끝까지 돈다.**

## 무엇을 만드나 — **형태는 네가 정한다. 지킬 것만 준다**

```
1. 🔴 **가상임이 전선에 드러나야 한다.** 서버·화면·다음 사람이 실물로 오인하면 안 된다
   ⚠ §2.4 의 `tmask` 가 이미 그 형태다 — **"이 값이 주입된 것인가"를 별도 비트로 알린다.**
      같은 규율을 따르되, 그것과 **섞이는지 갈리는지 네가 판단해서 근거를 적어라**
2. **끌 수 있어야 한다.** 컴파일 상수든 명령이든 — 실물 모듈이 생기면 꺼야 한다
3. **값이 변해야 한다.** 고정값이면 "화면이 갱신되는가"를 못 본다
   ⚠ 다만 **무작위는 쓰지 마라** — 재현이 안 되면 어긋났을 때 원인을 못 찾는다.
      **결정적인 패턴**(주기·계단 등)으로 하고 그 규칙을 문서에 적어라
4. 🔴 **`D` 등록 프레임이 그 모듈들을 선언해야 한다.** 그래야 서버가 자리에 붙인다
   ⚠ 지금 결속 규칙은 **모듈 `name` = 자리 `id`** 다(socket 확인). 그 규칙에 맞춰라
5. **전선 예산을 확인해라** — 모듈이 늘면 `D` 줄 수와 `S` 폭이 는다.
   🔴 `BATCH_CAP 160B` 와 `>=64B` 대역을 다시 넘지 않는지 봐라. 넘으면 개수를 줄여라
```

## 개수·종류 — **socket 의 명세를 따라라**

```
🔴 **필요한 것은 `O*` 다** — `OG`(차단봉) · `OL` · `OB`. `IP` 는 이미 10개가 실물로 등록된다
지금 결속이 비어 있는 자리는 **`E1`(입구) · `X1`(출구)** 이고 socket 명세상 그쪽이 조작 대상이다
🔑 socket 의 `docs/net/DESIGN-bridge-node-module-zone.md` 가 정본이다
⚠ 모르는 것이 있으면 **지어내지 말고 socket 에 물어라**
```
🔴 **전부 만들 필요는 없다.** **사슬을 끝까지 도는 데 필요한 최소**면 된다 —
**모듈 하나로도 `value`·`known`·`completion` 이 실제 값으로 흐르는지 볼 수 있다.**
**적게 시작하고 부족하면 늘려라. 전선 예산이 그 판단의 근거다.**

## 절차

```
1. 구현 + 회귀 시험
2. 🔴 **hex 대조로 "무엇이 바뀌었나"를 확인해라** — 이건 거동 변경이다. 0 이 아니다
3. 굽기 전 나에게 보고 — **축이 몇 개인지 같이 적어라**
4. 승인 후 : monitor 통보 → 포트 확인(`board list`) → upload → hex 대조 → 완료 통보(monitor·루트)
5. INTERVENTIONS 사전·사후
```

## ⚠ 같이 실을 것 — **다음 굽기 항목으로 잡아 둔 둘**

```
[ ] espInit()  — 🔴 거동 변경(millis 호출 시점 29줄 앞당김). 코드는 이미 들어가 있다
[ ] 더미 채움 경로(PROMPT_TIMEOUT)에 espRead
```
🔑 **어차피 굽는다. 축을 세어 판정문에 적으면 된다.**
⚠ **다만 네가 "섞으면 안 된다"고 판단하면 빼라 — 근거를 대면 그대로 받는다.**
**`espInit` 은 "산출물 바이트 대조로 증명"이 이번엔 안 통한다**(가상 모듈이 이미 바이트를 바꾼다).
**그 사실을 알고 넣을지 정해라.**

## 하지 말 것

```

```

## 왜 필요한가

실기 로그에서 등록 10개가 전부 IP(관측 전용)이고 명령가능 0개다. O* 모듈이 없어 modules[].value·known·completion·actions 가 한 번도 실제 값으로 흐른 적이 없고 통합 검증의 절반이 막혀 있다

### 🔴 ⑦ 에 결함이 있었다 — **축을 하나 적게 셌다**

**굽기 전 보고와 `INTERVENTIONS` 는 "축은 A 하나"라고 적었고 `espInit` 은 "뺐다"고 적었다.
안 빠졌다.** `b2d6574` 가 굽는 트리 `9edbcca` 의 **조상**이라 같이 들어갔다.

```
① git merge-base --is-ancestor b2d6574 9edbcca   → **0 (조상)**
② 굽기 입력 arduino/.burn/client/client.ino      → 저장소 스케치와 **cmp 차이 0**
🔴 ③ 그 소스 재빌드 → vmodburn/client.ino.hex 와 **바이트 동일**
     cmp.py chip-vmod.hex → verify-espinit **응용 다른바이트 0 · IDENTICAL**
```
> **실제 축은 둘이다: A(가상 O* 모듈) + B(espInit).**
> `ba744b3` 는 **주석만**, `e6091b5` 는 **hex 차이 0 실측** 이라 축이 아니다.

**축 B 의 범위(소스 판독 · 실측 아님)**: `setup()` 에서 `netStepAt = millis()` 가 29줄 앞당겨진다.
`netStepWait = 500` 이고 이후 사다리가 시각을 다시 잡으므로 **부팅 1회성**으로 읽힌다.
**정상상태 현상은 이 축과 무관하다.** ⚠ 다만 **표지가 없어 부팅 국면에서는 배제할 근거가 없다.**
