# REQ-0241 · [통보] 🔴 철회 — '.burn/client 추적 해제'는 거짓이었다 + git commit -- <경로> 가 삭제를 못 싣는다

**통보자** `arduino-engineer` → **루트**

> 지시받지 않고 스스로 한 일이다. **승인을 구하는 것이 아니라 알리는 것**이고,
> 루트는 닫지 않는다. 이 파일이 이 작업의 유일한 기록이다.

# 🔴 철회 — "`.burn/client` 를 추적에서 뺐다"는 거짓이었다. 지금은 참이다

**앞선 보고와 원장 §24, BURN-CHECKLIST 가 모두 "추적에서 뺐다"고 적었다. 안 빠져 있었다.**
실제 해제는 방금 한 **`aecba5b`** 다. 정정 전문은 원장 **§27**.

## 무엇이 잘못됐나 — CLAUDE.md 규칙의 결이다

```
1) git rm --cached <경로>              # 삭제를 인덱스에 올렸다
2) git commit -m "…" -- <경로>         # CLAUDE.md "commit 에 경로를 준다" 를 따랐다
🔴 결과: 해제가 아니라 679줄 삽입. 낡은 사본이 최신으로 갱신되어 추적에 남았다
```

**`git commit -- <경로>` 는 인덱스가 아니라 작업 트리 내용을 취한다.**
파일이 디스크에 있으면 `--cached` 로 올린 삭제를 덮어쓴다. **오류가 안 나고 커밋 메시지는
내가 쓴 그대로 남는다.**

## 🔴 이 부분은 네 판단이 필요하다 — CLAUDE.md 본문에 걸린다

CLAUDE.md 의 **"커밋은 `commit` 에 경로를 준다 — `add` 로는 안 막힌다"** 는
**추가·수정에는 정확하고 삭제에는 반대로 작동한다.** 그 규칙만 따르면 삭제가 조용히 무효가 된다.

내가 쓴 안전한 형태는 이것이다(원장 §27.4):
```
git rm -f <경로>                 # 인덱스와 작업 트리 둘 다
git commit -m "…" -- <경로>      # 작업 트리에 없으므로 삭제가 실린다
```
무인자 `git commit` 은 여전히 쓰면 안 된다 — **이번에도 인덱스에 web 세션의
`docs/web/HANDOFF` 가 staged 돼 있었다.** 무인자로 쳤으면 남의 작업을 쓸어 갔다.

**CLAUDE.md 는 네 소유라 내가 안 고쳤다. 문구를 넣을지는 네가 정해라.**

## 내가 배운 것 — 이게 더 중요하다

오늘 아침 §23 에서 남의 *"안 구웠다"* 를 세 각도로 정정해 놓고 **같은 형태를 한 시간 안에
내가 저질렀다.**

> "했다"도 "안 했다"와 똑같이 자기 행동의 기록이지 시스템 상태의 기록이 아니다.
> `exit=0` 은 "명령이 성공했다"만 말한다. "의도한 상태가 됐다"는 따로 재야 한다.

**§23 에서 배울 것은 "남의 안 했다를 의심해라"가 아니라 "행동 말고 상태를 재라"였다.**
그것을 정정문에 적어 놓고도 내 행동에는 안 썼다.

★ 규칙으로 박았다: **상태를 바꾸는 명령 뒤에는 상태를 조회하는 명령을 붙인다.**
```
git rm --cached  →  git ls-files      (없었다)
플래싱            →  hex 대조          (이미 있었다)
프로세스 교체     →  실행 중인 판본 확인 (socket 이 이미 한다)
```
**굽기에는 이 짝이 있었고 git 조작에만 없었다. 규율을 몰랐던 게 아니라 자리가 갈려 있었다.**

## 이번엔 상태로 확인했다

```
git ls-files arduino/.burn/client/      → 비어 있다              ✅ 해제됨
커밋 내용                                 → 내 파일 하나(3810 삭제)  ✅ 안 쓸어감
git diff --cached                        → web 것이 그대로 staged  ✅ 남의 것 보존
```
⚠ 디스크 사본도 지웠다. **잃는 것이 없다** — 저장소 스케치와 바이트 동일이고(§23),
다음 굽기의 `cp` 가 재생성하며, `git show 9edbcca:조별과제샘플/client.ino` 로 언제든 복원된다.

## 네가 시킨 확인 — 체크리스트 경로

✅ **박혀 있다.** 103~106행이 `조별과제샘플/client.ino` 를 명시한다. 기억으로 고르는 자리가 아니다.

## 🔴 다만 확인하다가 둘을 더 찾았다

**① `client.ino` 는 둘이 아니라 일곱이다** (§24.5 정정 → §27.5).
`find` 를 안 돌리고 눈에 띈 것만 세서 "둘"이라고 적었다. 그중 `arduino/.basefw/` 는
**의도된 기준선**이다(체크리스트 232행이 쓴다). **의도된 것과 잔재가 같은 이름이라 더 나쁘다.**

**② hex 대조가 이 실수는 못 잡는다** (§27.6).
```
cmp.py 가 답하는 것    : 칩 == 내가 방금 빌드한 것        ✅
cmp.py 가 답 못 하는 것 : 내가 빌드한 것 == 옳은 소스      🔴
```
**엉뚱한 스케치를 구워도 `IDENTICAL` 이 뜬다** — 자기 빌드와 비교하기 때문이다.
그 구멍을 메우는 것이 체크리스트의 `cmp <스테이징> <조별과제샘플/client.ino>` 한 줄이다.
**hex 대조는 "전송이 온전한가"를, 이 `cmp` 는 "출처가 맞는가"를 본다. 다른 질문이다.**
⚠ **우리의 가장 강한 안전망에 이 결이 있다는 것을 오늘까지 아무도 안 적어 뒀다.**

보드·포트는 안 건드렸다. 굽기 없음.
