# REQ-0252 · 이동 굽기 — SSID 3F_302 · 새 IP 192.168.0.29 · 지금 칩은 .basefw 다

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

## 0. 🔴 먼저 — **지금 칩은 네가 구운 것이 아니다**

사용자 통보: *"내가 테스트를 목적으로 `arduino/.basefw/client.ino` 파일 이용하여 플래싱하였다."*

```
🔴 지금 칩 = arduino/.basefw/client.ino  (2026-08-16 18:52 · 139,300B)
❌ STATUS 의 "칩 9edbcca" 는 낡았다. 정본 조별과제샘플/client.ino 는 251,589B — 112KB 차이
```
**⚠ 이것도 전언이다. 굽기 전에 hex 로 확인해라** — 우리 규칙이고 대조 한 번이면 된다.
**확인 결과가 다르면 그 사실이 더 중요하다. 굽기 전에 알려라.**

## 1. 새 환경값 — 셋을 **한 번에** 고친다

```
조별과제샘플/client.ino:91  WIFI_SSID   "SK_WiFiGIGA50DC_2.4G"  →  "3F_302"
조별과제샘플/client.ino:92  WIFI_PASS   "2011050796"            →  "0424719222!!"
조별과제샘플/client.ino:97  SERVER_IP   "192.168.35.21"         →  "192.168.0.29"
```
**새 IP 는 루트가 값으로 쟀다**: `ipconfig getifaddr en0` → `192.168.0.29` · 게이트웨이 `192.168.0.1`.
**서브넷이 `192.168.35.x` → `192.168.0.x` 로 통째로 바뀌었다.**

### 🔴🔴 비밀번호에 `!!` 가 있다 — **셸에서 그대로 치지 마라**
앞 판 주석이 *"이번 값엔 `!` 가 없다(히스토리 확장 걱정 없음)"* 라고 적어 뒀다. **전제가 뒤집혔다.**
```
❌ 대화형 bash 의 큰따옴표 · req.sh --body
✅ 작은따옴표 · 인용된 heredoc(<<'EOF') · 편집기로 직접
```
🔑 **소스에 박힌 뒤 값으로 확인해라.** 확장이 일어나면 **조용히 다른 문자열이 들어간다.**

### 🔴 SSID 는 대소문자가 두 번 다르게 왔다
```
1차 3f_302 (소문자) · 2차 3F_302 (대문자) ← 나중 값을 쓴다
```
**WiFi SSID 는 대소문자를 구분한다.** 나중 값으로 굽되, **안 붙으면 이것이 후보 하나다.**

### 🔴 그리고 **2.4GHz 문제** — 안 붙으면 **첫 번째로 의심할 것**

```
이 Mac 은 지금 **5GHz 채널 153 · 802.11ax** 에 붙어 있다 (system_profiler 실측)
🔴 ESP8266 은 **2.4GHz 전용**이다
옛 SSID 는 `..._2.4G` 로 **대역이 이름에 박혀 있었다** — 그 공유기는 대역을 갈랐다
새 SSID `3F_302` 에는 대역 표시가 없다
```
**둘 중 하나다:**
- **한 이름으로 두 대역을 다 쏜다**(요즘 흔함) → 그대로 붙는다. **문제 없음**
- **대역별로 이름이 다르다** → 2.4GHz 쪽 이름이 따로 있다. **그 이름을 받아야 한다**

⚠ **루트는 이것을 못 쟀다** — 최신 macOS 에서 `airport` 스캔 유틸이 제거됐고 OS 가 SSID 를 가린다.
🔑 **그러니 "안 붙는다 = 펌웨어 결함"으로 읽지 마라.** 안 붙으면 **순서대로** 의심해라:
```
① 2.4GHz 대역 이름이 따로 있는가   ← 가장 유력
② SSID 대소문자
③ PASS 에 !! 가 확장돼 들어갔는가
④ 그 다음에야 펌웨어
```
**①②③ 은 사용자에게 물어야 닫힌다. 혼자 쫓지 말고 루트에 올려라.**

## 2. 굽는 대상 — 🔴 **`조별과제샘플/client.ino` 다**

**저장소에 `client.ino` 가 일곱 개다**(네 §27.5). `.basefw` 도 `arduino/client/` 도 아니다.
⚠ **`.basefw` 를 지우거나 고치지 마라** — 잔재가 아니라 **의도된 기준선**이다.
⚠ `client.ino:93~95` 의 **앞뒤 공백 금지** 경고 — 실제로 `" 192.168.35.21"` 로 구워진 적이 있다.

## 3. 순서 — **서버 배포가 먼저다**

socket 이 A[1] 다섯을 배포하고 서버를 재기동한다(REQ 별건). **그 완료 보고를 받고 구워라** —
장치가 부팅해서 만나는 서버가 최종본이어야 창이 깨끗하다.

```
① 지금       : 소스 셋 수정 + hex 로 현재 칩 확인 (보드 안 건드림)
② socket 배포 완료 보고 대기
③ 🔴 굽기 직전 monitor 에 한 줄  (관측은 지금 멈춰 있지만 규약대로 알려라)
④ 굽는다 → 등록 `D` 프레임이 서버 로그에 뜨는지로 확인
⑤ 루트에 결과 보고 — 굽기 축 목록을 `is-ancestor` 로 만들어라(손으로 적지 마라)
```

## 4. 이 굽기의 **축**을 적어라

```
축 A : .basefw(08-16) → 정본(08-19) — **112KB 차이. 사실상 전체 교체다**
축 B : WiFi SSID/PASS 변경
축 C : SERVER_IP 변경 (서브넷 이동)
```
🔑 **축 A 가 압도적이라 나머지가 묻힌다.** 다음 창은 **"9edbcca 대비"가 아니라
"`.basefw` 대비"도 아니고 — 사실상 새 기준선**이다. 그 사실을 판정문에 적어라.

## 왜 필요한가

위치가 이동해 WiFi·서버 IP 가 모두 바뀌었고, 사용자가 테스트로 .basefw 를 구워 정본이 칩에 없다

## 대상 파일

- `조별과제샘플/client.ino`
## 완료 기준

굽기 전 hex 로 현재 칩 확인 · 셋을 한 번에 수정 · socket 배포 뒤 굽기 · 등록 D 프레임으로 확인 · 축 목록을 is-ancestor 로
