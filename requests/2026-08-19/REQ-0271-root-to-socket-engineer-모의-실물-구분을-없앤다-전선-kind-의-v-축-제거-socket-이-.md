# REQ-0271 · 🔴 모의/실물 구분을 없앤다 — 전선 kind 의 V 축 제거. socket 이 정본을 박는다 (사용자 확정)

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

# 🔴 **모의/실물 구분을 없앤다** — 경계는 아두이노다 (사용자 확정)

> 사용자 원문: *"**모의값에 의미는 없다. 모두 실물로 처리하자.** 실물도 센서 데이터가 그대로
> 들어오지 않는다. **아두이노 코드로 정제되어서 값만 서버로 전송된다. 해당 구조는 실물센서와 동일하다.**
> **모의를 구분하지 않는 구조로 진행하자.**"*

## 0. 🔑 이 지시의 논거를 먼저 이해해라 — 편의가 아니라 **경계 정의**다

```
실물 센서  핀 읽기 → 아두이노가 정제 → **값** 이 전선으로
모의       내부 상태 → 아두이노가 정제 → **값** 이 전선으로
```
> ### **전선 밖에서 보면 둘이 구별 불가능하고, 구별할 이유도 없다.**
> ### **무엇이 값을 만드는가는 아두이노 안쪽 사정이다.**

**그러니 이건 "가상을 숨기자"가 아니라 "경계를 제대로 긋자"다.**
🔑 **서버와 화면이 아두이노 내부 구현을 알고 있던 것이 층 위반이었다.**

## 0-A. 🔴 사용자 추가 확정 — **모의 전용 패킷을 만들지 마라**

> *"또한 **모의용 데이터 패킷을 작성하고 이후 실물 패킷으로 동작하면 또 다른 문제가 생길 것 같다.**"*

**이 경고가 이 REQ 의 설계 제약이다. 그리고 우리 원장이 그 사고를 이미 여러 번 적어 뒀다.**

```
❌ 금지 : 모의용 패킷 형식 + 나중에 실물 패킷 형식으로 교체
   → 두 경로가 생기고, **실물로 바꾸는 그 순간까지 실물 경로는 한 번도 안 돈다**
   → §"시험 경로 ≠ 실기 경로" 의 ③번 얼굴: **시험이 통과하고 실기만 빈다. 신호가 없다**
✅ 확정 : **패킷은 하나다.** 값의 출처가 핀이든 내부 상태든 **같은 형식·같은 경로**로 나간다
```
🔑 **아두이노 안에서 값이 어떻게 만들어지는가만 다르고, 그 바깥은 완전히 동일해야 한다.**
**그것이 곧 "경계는 아두이노다"의 실행이다.**

⚠ **이 제약을 어기는 형태를 미리 세어 둬라:**
```
· 모의일 때만 붙는 필드·접미·플래그      ← 🔴 `OBV` 의 `V` 가 정확히 그것이다
· 모의 전용 프레임 타입
· "실물이면 이 경로, 모의면 저 경로" 분기
· 모의일 때만 도는 초기화              ← §"시험이 실기가 안 하는 준비를 대신 해 준다"
```
**하나라도 남으면 이 작업이 목적을 달성 못 한다.** 🔑 **"구분을 안 보여 준다"가 아니라 "구분이 없다"여야 한다.**

## 1. 지금 구분이 박힌 곳 (루트가 값으로 훑었다)

```
펌웨어  client.ino:233  SLOT_SRC_DEFAULT / :235 srcReal / :248 :294 :314 :324
전선    D,E1,**OBV**  ·  D,X1,**OBV**      ← 🔴 `V` 접미가 "가상"을 뜻한다
서버    server.cpp:2537 "차단봉(OBV)은 자리 점유를 말하지 않는다"
        :5852~5860 자가검증이 OBV 를 쓴다
화면    index.html:2457 baseKind() / :2460 isVirtualKind() / :2867 "(가상)" 라벨
```

## 2. 🔴 해석에 **빈 자리가 하나 있다 — 지어내지 말고 확인해라**

**`OBV` 의 `V` 를 떼면 `OB` 가 된다.** 그런데 **`OB` 와 `OBV` 가 지금 무엇을 가르는지**를 봐야 한다:
```
· `V` 가 **오직 "가상"만** 뜻하면 → 떼면 된다. `OB` 하나로 합친다
· `V` 가 **다른 것도 뜻하면**(예: 차단봉 종류 구분) → 떼면 정보가 사라진다
```
🔴 **명세(`docs/net/DESIGN-bridge-node-module-zone.md` §5)와 네 코드를 보고 답해라.**
**"아마 가상일 것"으로 진행하지 마라.**

## 3. 범위 — 세 도메인이 같이 움직인다. **순서가 있다**

```
① socket  전선 계약에서 `V` 축을 없앤다 — 명세에 **정본**을 박는다
          🔴 kind 집합이 무엇이 되는가 · 옛 `OBV` 를 받으면 어떻게 하는가(하위호환)
          그리고 server.cpp 의 OBV 취급·자가검증
② arduino 펌웨어가 `OB` 를 보낸다 · `srcReal`/`SLOT_SRC` 구분을 없앤다
          🔴 **전선이 바뀌므로 굽기다.** socket 명세 확정 뒤에 움직여라
③ web     `isVirtualKind`·`baseKind`·`(가상)` 라벨 제거
          ⚠ **socket 이 이름을 박은 뒤에 착수.** 지어내지 마라
```
🔑 **socket 이 먼저다** — 전선 계약이 정본이고 나머지가 그것을 따른다.
**셋이 동시에 착수하면 같은 개념에 다른 이름이 붙는다**(§"병렬로 도는 설계 작업").

## 4. ⚠ 잃는 것을 세라 — **지우기 전에 적어라**

web 이 `(가상)` 라벨에 근거를 달아 뒀다:
> *"`(가상)` 은 **그 장치가 물리적으로 없다** 는 뜻이다. 이걸 안 갈라 쓰면
> **시험용 가상 모듈의 값을 실제 개방으로 읽는다.**"*

🔴 **사용자 지시가 그 우려를 덮는다** — *"모두 실물로 처리하자"* 이므로 **화면이 그 구분을 말하지 않는 것이 확정**이다.
⚠ **다만 그 우려가 틀렸다는 뜻은 아니다. 원장에 "왜 없앴는지"를 적어라** —
**나중에 실물 차단봉이 생기면 그때 이 결정을 다시 볼 사람이 근거를 읽어야 한다.**

## 5. 🔴 그리고 이것이 **`센서갈림` 문제를 대체한다**

앞서 낸 **REQ-0270(시뮬을 지형에 맞춘다)은 이 결정에 흡수된다.**
```
· 모의/실물 구분이 없어지면 `srcReal` 마스크가 사라진다
· 그래도 **A_i 와 B_i 가 같은 자리라는 지형은 그대로**다
🔴 → 값의 출처가 무엇이든 **두 모듈이 같은 자리를 보면 같은 값이어야** 한다
   그 정합은 여전히 필요하다. **REQ-0270 의 §2 를 이 작업에 합쳐라**
```

## 6. 굽기 — 대기 목록에 합친다

```
① ESP_RST_WIRED 0 → 1
② 배너 "10 slots" → 12
③ 시뮬 지형 정합 (REQ-0270)

```
**넷을 한 굽기로 묶는다**(§"개입은 한 번으로"). ⚠ **판정문에 축 넷을 명시해라.**
🔴 **창 R 판정 뒤 루트가 시각을 준다. 지금은 코드·명세만.**

## 왜 필요한가

사용자가 아두이노가 정제한 값만 전선으로 나가므로 모의와 실물이 구별 불가능하고 구별할 이유도 없다고 확정했다
