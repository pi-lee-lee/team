# REQ-0273 · 펌웨어 리팩터링 검토 — hex 0 으로 되는 것과 굽기가 필요한 것을 갈라 목록을 내라 (사용자 지시)

**요청자** `root` → **담당** `arduino-engineer`


## 🔴🔴 **최우선 요구 — 사용 코드가 간단해야 한다** (사용자 강조)

> 사용자 원문: *"그리고 **사용 코드 구조가 간단하게 나와야 함을 꼭! 명시**해달라."*

> ### **이것이 이 작업의 *합격 기준* 이다. 파일이 몇 개인지·줄이 몇 줄인지는 부차적이다.**
> ### **바깥(쓰는 쪽)이 단순해지지 않으면 이 리팩터링은 실패다 — 안이 아무리 깔끔해도.**

**🔑 검증 방법 — 말로 하지 말고 *쓰는 코드를 실제로 써 보여라*:**
```
① 명세에 **사용 예시**를 넣어라. 그 예시가 곧 합격 판정이다
② 지금 코드로 같은 일을 하려면 몇 줄인지 **나란히** 적어라 (전/후)
③ 🔴 **호출자가 몰라도 되는 것을 세라** — 순서·의존·초기화·널 검사.
   그것이 여전히 호출자 몫이면 **자동화가 안 된 것**이다
```

**설계 제약:**
```
✅ 기본값으로 동작한다        — 아무것도 안 정해도 지금 것이 나온다
✅ 어려운 것은 함수가 대신 한다 — 호출자가 순서·의존을 몰라도 되게
✅ 이름만 보고 무엇인지 안다   — 주석을 읽어야 쓸 수 있으면 안 단순한 것이다
🔴 잘못 쓰면 **컴파일이나 기동에서 막힌다** — 못 쓰게 만드는 것이 못 쓰는 것보다 낫다
```
⚠ **"안이 복잡해도 바깥이 단순하면 성공"이다.** 복잡도를 없애는 것이 아니라 **옮기는 것**이고,
**옮길 곳은 함수 안**이다. 사용자가 *"난이도 높은 설정은 최대한 자동화(함수 내에서 수행되도록)"* 라고
말한 것이 정확히 그것이다.

🔑 **그리고 이건 §"계약에 빈 자리가 있으면 받는 쪽이 메운다" 의 API 판본이다** —
**기본값이 없으면 호출자가 지어낸다.** 기본값을 주거나, 안 주면 강제해라.

### 🔴🔴 그리고 **은닉화가 그 수단이다** (사용자 재강조)

> *"**복잡한 구조는 기본적으로 은닉화**하여 개발자(사용자)에게는 **간단한 구조로 이용 가능**해야 한다.
> **매우 중요하다.**"*

> ### **드러난 표면이 곧 계약이다. 표면을 줄이는 것이 이 작업의 본체다.**

```
🔴 밖으로 내보내지 마라 : 내부 상태 · 호출 순서 · 초기화 의존 · 자료구조 · 널 검사
✅ 밖에 두는 것         : **하고 싶은 일을 그대로 적은 이름** 하나

판정 : 헤더(또는 공개 API)만 읽고 쓸 수 있는가?
       🔴 `.cpp`/구현을 열어야 쓸 수 있으면 **은닉이 안 된 것**이다
```

**구체적으로:**
```
· 공개 표면을 **세라.** 지금 몇 개이고 뒤에 몇 개인가 — 수가 줄어야 한다
· 내부 전용은 익명 namespace / static / private 로 내려라
· 🔴 "이 함수를 부르기 전에 저것을 먼저 불러야 한다" 가 **하나도 없어야** 한다
     남아 있으면 그 순서를 **함수 안으로 넣어라** — 그게 사용자가 말한 자동화다
· 실패는 **밖으로 새지 않게** 하되, 조용히 삼키지도 마라 — 우리가 계속 잡아 온 그 자리다
```
⚠ **은닉화가 "감춘다"가 아니다.** 값이 왜 그런지는 여전히 로그·계수로 볼 수 있어야 한다.
🔑 **감출 것은 *복잡함* 이고, 드러낼 것은 *상태* 다. 둘을 바꾸지 마라.**

### 🔴🔴 **왜 그래야 하는가 — 사용자가 근거를 줬다. 이게 판정을 날카롭게 만든다**

> *"이 방식을 선호하는 이유는 **간단한 구조로 코딩 시 코드 작성 시점에 해당 코드의 흐름이 보인다.**
> 복잡한 구조의 경우 **프로세스 흐름이 잘 보이지 않는다.**"*

> ### **목적은 "짧게"가 아니라 🔴 "읽으면 *흐름* 이 보이게" 다.**

**그래서 판정이 이렇게 바뀐다:**
```
❌ 나쁜 판정 : 줄 수가 줄었나
✅ 좋은 판정 : **사용 코드를 위에서 아래로 읽으면 무슨 일이 어떤 순서로 일어나는지 보이는가**
```

🔴 **그리고 이것이 어떤 "단순함"을 *탈락* 시킨다 — 짧아 보여도 흐름을 숨기면 실패다:**
```
❌ 자동 등록·매직 배선 — 한 줄인데 **언제 무엇이 붙는지 안 보인다**
❌ 콜백·이벤트로만 이어진 것 — 호출부에 순서가 없다
❌ 설정 파일이 흐름을 정하는 것 — 코드를 읽어도 흐름을 모른다
❌ 이름이 무슨 일을 하는지 안 말하는 것 — `setup()` · `init()` · `process()`
✅ **하는 일이 순서대로 적혀 있고, 각 줄의 이름이 그 일을 말한다**
```

⚠ **은닉화와 충돌하지 않는다. 갈라 읽어라:**
```
숨긴다  : 그 일을 **어떻게** 하는가 (순서·의존·초기화·자료구조·널 검사)
드러낸다 : 🔴 **무엇을 어떤 순서로** 하는가  ·  지금 상태가 어떤가(로그·계수)
```
🔑 **`함수 안으로 넣어라` 가 `흐름을 감춰라` 가 아니다.**
**한 단계의 *내부* 를 감추고, 단계들의 *나열* 은 호출부에 남긴다.**

**🔑 검증**: 이 코드를 처음 보는 사람에게 사용 예시만 보여 주고
*"이걸 실행하면 무슨 일이 순서대로 일어나나"* 를 물었을 때 **답할 수 있어야 한다.**

# 펌웨어 리팩터링 — **검토부터 하고 계획을 내라** (사용자 지시)

> 사용자: *"코드 리팩토링 작업하자. **펌웨어쪽도 리팩토링할 작업이 있는지 검토해라.**"*

🔴 **이건 "해라"가 아니라 "검토하고 계획을 내라"다.** 굽기가 걸리므로 착수 전에 루트가 순서를 준다.

## 0. 현황 (루트가 값으로 쟀다)

```
client.ino        **2,979줄 · 193KB**   ← ESP 링크 846줄을 뺀 뒤
EspLink_state.h    285줄 · 22KB
EspLink_tx.h       295줄 · 22KB
EspLink_ladder.h   217줄 · 13KB
EspLink_gate.h     133줄 · 11KB

긴 함수
  🔴 handleLine       **424줄**   ← 가장 큰 덩어리
     statusTick        133
     processCommand    112
     feedRxChar        100
     cntTick            95
     sendSlotBatch      95
     handleFrameLine    86
     applyRung          82
```

## 1. 🔑 네가 오늘 증명한 방법이 그대로 쓰인다

```
① 연속 구역을 **원래 자리에 include** → 전처리 결과 동일 → **hex 차이 0**
   → 굽기가 **필요 없다.** 이게 가능한 만큼이 이번 범위다
🔴 ② 흩어진 것을 모으거나 함수를 쪼개면 → hex 가 바뀐다 → **굽기 축이 하나 는다**
```
> ### **①로 되는 것과 ②가 필요한 것을 갈라서 목록을 내라. 그게 이 검토의 결과물이다.**

⚠ **`handleLine` 424줄을 쪼개는 것은 ②다.** 인라인 경계가 바뀌므로 `hex` 가 거의 확실히 달라진다.
**그래도 할 가치가 있는지, 있다면 언제 할지를 네가 판단해서 적어라.**

## 2. 검토할 축 — **네가 아는 것을 쓰라는 것이다**

```
· 🔴 잠금 대상과의 관계 — EspLink_* 넷은 `protected.json` 에 있다.
     그것을 건드리는 리팩터링은 **잠금 검사가 노랑을 낸다.** 그게 정상 동작이다
· `handleLine` 이 무엇을 겸하고 있나 — 프레임 종류가 늘 때마다 여기가 자라는 구조인가
· 슬롯 규율(`sendSlotBatch`·`statusTick`)과 링크(`EspLink_*`)의 경계가 맞나
· 계수(`cntTick`) — 오늘 socket 이 "파생 상태를 사건처럼 세지 마라"를 겪었다. 네 계수에도 그 형태가 있나
· 🔴 **`SLOT_SRC`/`simOcc` 구분** — REQ-0271 로 없애기로 확정됐다. 그 작업과 겹치는 자리
· 낡은 문구 — 배너 `10 slots`(실제 12) 같은 것. **문자열은 hex 를 바꾼다**
```

## 3. 🔴 굽기 대기 목록에 이미 넷이 있다 — 같이 세라

```
① ESP_RST_WIRED 0 → 1        (사용자가 A2↔ESP RST 를 물렸다)
② 배너 "10 slots" → 12
③ 시뮬 지형 정합 (REQ-0270)
④ 모의/실물 구분 제거 (REQ-0271 · socket 명세 뒤)
⑤ ← 여기서 나올 리팩터링 중 hex 가 바뀌는 것
```
**다섯을 한 굽기로 묶는다.** 🔑 §"개입은 한 번으로 묶어라" — **다만 판정문에 축을 다 적는다.**

## 4. ⚠ 지금 하지 말 것

```
🔴 굽기 금지 — 창 S 가 돈다(13:21~14:21). monitor 가 포트를 잡고 있다
🔴 포트 접근 금지 — 빌드·hex 대조는 포트를 안 쓰므로 해도 된다
```

## 5. 내라는 것

```
① ①로 되는 것 / ②가 필요한 것 **목록**
② 각각의 **값어치와 위험** — 특히 handleLine
③ 순서 제안 — 굽기 대기 넷과 어떻게 묶을지
④ 🔴 **네가 안 하겠다고 정한 것과 그 이유** — 다 하겠다고 하지 마라
```
⚠ **①에 해당하는 것은 검토와 함께 *해도 된다*.** `hex` 0 이면 굽기가 아니니 위험이 없다.
**하되 대조를 붙이고, 하나라도 0 이 아니면 멈추고 보고해라.**

### 🔑 `handleLine` 424줄 판단 — **쪼갤 게 아니라 옮길 것이었다**

속을 보니 **거의 전부가 링크 계층**이다(사다리 응답 176줄 · `ALREADY CONNECT`/`CONNECT`/`CLOSED` ·

⚠ **함수 자체는 여전히 424줄이다. 줄 수는 안 줄었고 경계만 생겼다** — 숨기지 않는다.

### 🔴 ② 굽기 필요 — **하나만 올린다**

**`commitAck()`** — `cachePut` → `sendAck` 순서를 **호출부 5곳이 지키고 있었다.**
소스 주석이 그 위험을 이미 적고 있었다: *"호출부가 `cachePut` 을 먼저 부르므로…"*
> ### **사용자가 없애라고 한 "이걸 부르기 전에 저걸 먼저"가 코드에 실재한 유일한 자리다.**
**빠뜨리면 캐시 없는 재전송이 *다른 답*을 받는다**(§4.2 멱등 파손) — **조용히 틀린다.**
**측정: 26032 → 26038B (+6) · hex 다름.** 굽기 대기 목록의 **다섯째**로 세라.

### 🔴 안 하겠다고 정한 것 (이유는 계획서에)

```
❌ handleLine 함수 쪼개기        — ①로 격리가 됐다. 쪼개면 축만 는다
❌ statusTick·feedRxChar·sendSlotBatch — 슬롯 규율의 심장. **검증된 것을 미관으로 안 건드린다**
❌ 작은 구역(체크섬·부팅원인) 추가 분리 — 파일만 늘고 잠금이 넓어져 정상 작업을 막는다
❌ 전역 상태 구조체화             — RAM 58% 쓰는 중. **측정 없이 깔끔함에 자원을 안 쓴다**
```

### 은닉화 판정 (사용자가 두 번 강조한 것)

| 자리 | 판정 |
|---|---|
| 모듈 추가 (`MODULE_TABLE` 한 곳) · 센서 배선 (`SLOT_PIN[]`) · 링크 계층 | ✅ 이미 은닉 |
| **ACK 발행 순서** | 🔴 **유일한 하자 → 2-A** |
| `T,A` 무장 선행 | ✅ **전선 규약**이지 내부 API 가 아니다 — 대상 아님 |

> ⚠ **감출 것은 *복잡함* 이고 드러낼 것은 *상태* 다.** 계수기·`[LADDER]`·`[TX]` 로그는 **하나도 안 감쌌다** —
> 오늘 하루가 그 관측 가능성 덕에 **세 번** 구제됐다.

### ⚠ 이 작업에서 실제로 터진 것

`commitAck` 실험에서 **정의를 먼저 넣고 치환을 나중에** 했더니 새 함수 본문이 치환 패턴에 걸려
**자기 자신을 부르게 됐다**(`commitAck(){ commitAck(); }`). **컴파일은 통과한다.**
★ **텍스트 치환 리팩터링은 치환 먼저·삽입 나중. 그리고 생성물을 눈으로 봐라.**

### 곁들여 고친 것 — **같은 불변식이 하루에 세 번 깨졌다**

굽기 입력 목록이 헤더가 늘 때마다 낡았다(4개→8개). **파일을 나열하는 형태가 원인**이라
**`조별과제샘플/ardu/` 폴더 전체로** 바꿨다(체크리스트·RECOVERY·원장 §23). **이제 헤더가 더 늘어도 안 깨진다.**

**굽지 않았고 포트도 안 잡았다.**
