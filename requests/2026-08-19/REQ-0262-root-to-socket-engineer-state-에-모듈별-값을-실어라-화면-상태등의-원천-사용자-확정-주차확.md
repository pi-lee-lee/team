# REQ-0262 · state 에 모듈별 값을 실어라 — 화면 상태등의 원천 (사용자 확정: 주차확인센서와 같은 구조)

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

# 🔴🔴 **제목이 틀렸다. 이 REQ 의 진짜 내용은 §0-A 다** — web 이 잡았다

~~`state` 에 모듈별 값을 실어라~~ → ✅ **여러 노드의 모듈에도 값이 채워지게 하라**

## 0-A. 🔴 루트의 전제가 거짓이었다 — 잘린 창에서 "없다"를 결론 냈다

```
❌ 루트가 쓴 것 : "state_json 의 자리 본문은 id·occupied·reserved·actions 뿐이다 → 모듈별 값이 없다"
✅ 사실         : **있다.** server.cpp:2502~2519
```
```cpp
o << "{\"devid\":" << … << ",\"name\":" << … << ",\"idx\":" << mi
  << ",\"value\":" << (known ? (mod_bits[mi] ? "true" : "false") : "null")
  << ",\"known\":" << (known ? "true" : "false") << "}";
```
**주석까지 있다**: *"🔴 **이제 값이 있다** — `S` 의 비트열에서 뽑는다(비트 `idx`).
⚠ **모르면 여전히 `known:false` 다** … **모름과 거짓은 다르다.**"*

🔑 **루트가 요구한 세 번째 표시(⚪ 모름)가 계약에 이미 있다 — `known:false`.**
**web 의 화면도 이미 그것을 읽고 있다**(`renderModuleRow`: `known!==true → ⏱`).

### ⚠ 어쩌다 틀렸나 — **잘린 창**
```
state_json() 은 2442 행에서 시작한다
루트가 본 것 : sed -n '2442,+55p'  →  **2497 행까지**
modules 직렬화 시작 : **2502 행**   →  🔴 5줄 차이로 못 봤다
```
> ### **오늘 같은 형태가 셋째다** — socket 의 `head` 가 `+ARD` 를 먹었고,
> ### socket 의 `awk` 가 날짜를 빼먹었고, 이번엔 루트의 `sed +N`.
> ### **셋 다 "없다"가 그럴듯해서 통과했다.**

## 0-B. ✅ 그러면 **진짜 고칠 것**은 이것이다 (web 이 찾았다)

```cpp
int mi = -1;
if (z.modules[m].first == park.devid)          // 🔴 **주 노드일 때만** idx 를 찾는다
    for (…) if (park.mods[k].first == …) { mi = (int)k; break; }
const bool known = (mi >= 0 && mi < mod_bits_n);
```
> ### **둘째 노드의 모듈은 `mi = -1` 이라 *항상* `known:false` 다. 영원히 ⚪ 모름으로 그려진다.**

🔴 **REQ-0260 의 7영역 지형에서 이것이 곧바로 터진다** — `영역1 ← A1·B1` 인데 둘이 다른 노드에
있으면 **그 영역이 통째로 미상**이 된다. **가상 아두이노를 붙이는 순간 그 노드의 모듈은 전부 회색이다.**

### 할 일
```
① 모듈의 `idx` 를 **그 모듈을 등록한 노드**에서 찾아라 — `park` 고정을 걷어낸다
   🔑 `map_json()` 은 이미 그렇게 한다(`all_nodes()` 를 훑어 `devid` 로 고른다).
      **같은 파일 안에서 두 곳이 다른 규칙을 쓰고 있다** — §"같은 문서 안에서도" 의 코드 판본
② `mod_bits` 도 노드마다 있어야 한다 — 지금은 주 노드 한 벌로 보인다. 확인하고 적어라
③ 🔴 **`known:false` 의 사유를 갈라라** — "등록 전" · "폭 못 읽음" · **"이 노드는 값 경로가 없다"**
   지금은 셋이 같은 값으로 나온다. **원인이 다른데 표시가 같으면 아무도 못 고친다**
```

## 0-C. 그대로 유효한 것

아래 본문의 **§"REQ-0260 과 만난다"** 는 그대로다 — 영역에 모듈이 둘이 되면 **자리 `occupied` 와
모듈 값이 둘 다 있게 되고 둘의 관계를 명세가 답해야 한다.** 설계 §3.5 를 써라.

# ~~`state` 에 모듈별 값을 실어라~~ (아래는 틀린 전제 위에 쓴 원문 · 지우지 않고 남긴다)

> 사용자 지시(REQ-0261): *"노드는 각각 개별 박스이고 내부에 보유한 모듈이 리스트 형식으로 표시되고
> **동작상태가 녹색/적색등**으로 표시되어야 한다."* / *"지금 **주차확인센서와 같은 구조**이다."*

## 지금 없는 것 (루트가 코드로 확인)

```
state_json()  자리 본문 : id · occupied · reserved · actions      ← **자리 단위뿐**
map_json()    모듈      : devid · name · kind · idx              ← **값이 없다**
```
> ### **모듈별 값이 화면까지 오지 않는다. 화면이 그리면 지어내는 것이다.**

⚠ **네 TODO 가 이 항목을 이렇게 적어 뒀다**:
> *"`state` 의 모듈 `value` 가 `known:false` … **비트열을 모듈 `idx` 에 연결하면 채워진다.**
> ⚠ **지금 채우면 지어내는 것이다.**"*

🔑 **그 유보가 이제 풀렸다.** 사용자가 *"주차확인센서와 같은 구조"* 라고 확정했다 —
**`occupied` 비트열의 `idx` 번째 비트가 그 모듈의 값**이다. **짐작이 아니라 지시다.**

## 할 일

```
① state 의 각 자리에 modules[] 를 싣고, 모듈마다 값을 준다
② 값의 원천은 `S` 의 자리 비트열 — 모듈 `idx` 로 색인한다
   ⚠ 비트 >= 실물 자리 수는 **자리 점유가 아니라 차단봉 상태**다(명세 §7.2). 뜻을 갈라 적어라
③ 🔴 **"모름"을 반드시 별도 상태로 준다** — 노드 오프라인·미등록·결속 끊김·비트 범위 밖
```

## 🔴 이름을 **네가 박아라** — web 이 기다린다

web 에 *"필드 이름을 지어내지 마라"* 라고 못 박아 뒀다. **네가 정하면 루트가 넘긴다.**
정할 것:
```
· 키 이름 (state.zones[].modules ? 다른 이름 ?)
· 값의 모양 — bool ? {known, value} ? 상태 코드 ?
· 🔴 **"모름"의 표현** — 키 부재인가 known:false 인가
  ⚠ §6.5 존재/부재 규칙을 따라라. **일시 상태를 키 부재로 답하면 화면이 영영 안 그린다**
    (`occupied` 사유를 키 부재로 안 한 것이 그 판례다)
· **전달 시점** — 매 state 마다인가. 안 적으면 받는 쪽이 가장 편한 시점을 고른다
```

## ⚠ 이것이 **REQ-0260(7영역 · 1:N 결속)과 만난다**

영역 하나에 모듈이 둘이 되면 **자리 수준 `occupied` 와 모듈 수준 값이 둘 다 있게 된다.**
```
· 둘의 관계를 명세에 적어라 — 자리 `occupied` 는 모듈들에서 **어떻게 유도되는가**
· 🔴 **파생 값은 원본을 가진 쪽이 계산한다.** 화면이 조합하게 두지 마라
  (§"요구를 넘길 때 계산 주체를 적어라" — `ack_budget_ms` 가 그 판례다)
· 설계 §3.5 가 *"자리가 여러 모듈에 걸칠 때"* 를 다루고 `ok/total`·`missing[]` 을 준다.
  **그 절을 쓰고, 비어 있으면 채워라. 새로 짓지 마라**
```
