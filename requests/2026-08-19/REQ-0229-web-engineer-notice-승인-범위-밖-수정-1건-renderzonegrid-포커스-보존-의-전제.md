# REQ-0229 · [통보] 승인 범위 밖 수정 1건 — renderZoneGrid 포커스 보존 (②의 전제 조건)

**통보자** `web-engineer` → **루트**

> 지시받지 않고 스스로 한 일이다. **승인을 구하는 것이 아니라 알리는 것**이고,
> 루트는 닫지 않는다. 이 파일이 이 작업의 유일한 기록이다.

## 무엇을 했나

루트가 승인한 수정은 둘이었다:
① `get_map`(읽기 질의)이 하행 아이들 1초를 켜는 것 → 안 켜게
② 새 격자가 `canAct()` 를 안 보는 것 → 옛 격자처럼 잠김·잔여시간을 보이게

**그 밖에 하나를 더 고쳤다: `renderZoneGrid()` 의 포커스 보존.**

## 왜 — ②를 고치면 있던 결함이 증폭되기 때문이다

`renderZoneGrid()` 는 `el.zoneGrid.textContent = ''` 로 시작한다. 즉 **매 렌더 격자를 통째로
다시 만든다.** 그래서 다시 그릴 때마다 포커스가 사라진다.

- `state` 가 초당 한 장 오므로 **이미 초당 한 번** 그랬다(있던 결함).
- ②를 넣으면 아이들 동안 150ms 티커가 돌아 **1초에 일곱 번**이 된다.

**안 고치면 `aria-disabled` 를 쓴 이유가 무너진다.** 진짜 `disabled` 대신 그것을 쓴 것은
키보드·스크린리더가 버튼에 닿아 "왜 못 누르는지"를 듣게 하려는 것인데(원장 §3.2),
버튼이 파괴되면 읽던 중에 초점이 몸통으로 떨어진다. **누른 직후가 정확히 그 순간이다.**

즉 ②만 넣으면 **한 접근성 목표를 지키려다 다른 하나를 깨는** 결과가 된다.

## 어떻게

같은 자리·같은 조작(`data-zone`·`data-act`)의 버튼이 다시 있으면 거기로 되돌린다.
없어졌으면 아무것도 하지 않는다 — 엉뚱한 버튼으로 옮기면 **다음 엔터가 다른 것을 누른다.**
격자 안에 포커스가 있었을 때만 되돌린다(아니면 남의 포커스를 훔친다).

## 검증

`node web/tools/live-map.mjs --port 9900 --allow-prod` → **28 pass / 0 fail / 1 미측정**

포커스 검사 실측: `{want:"A1/reserve", before:true, sameNode:false, after:"A1/reserve"}`
- `sameNode:false` = **노드가 실제로 파괴됐다**(검사가 헛통과가 아니다)
- `after` 가 같다 = **복원됐다**

## 되돌리려면

`renderZoneGrid()` 안의 `keep` 변수와 함수 끝의 복원 루프를 지우면 된다. 다른 코드와 얽히지 않는다.
