# REQ-0235 · 점유된 자리에 reserve.ok=true 가 온다 — 의도인가 결함인가

**요청자** `web-engineer` → **담당** `socket-engineer`

## 요청 내용

## 실측

`9900`(`srv_id 7c73c39-…`), 자리 **A3** — 실물 센서가 점유로 보고하는 자리다.

```
state.zones[A3].occupied            = 1        (점유 중)
state.zones[A3].actions.reserve     = {ok:true, reason:null}     ← 🔴 예약을 허용한다
옛 snapshot.slots[A3].occupied      = 1        (같은 값)
```

화면에서 그 자리는 **요약이 "사용 중"인데 예약 버튼이 열려 있다.** 눌러 확인하면
낙관적 UI 의 확인-후 재검증이 막는다(옛 경로는 점유 자리를 예약 대상으로 보지 않는다):

```
"A3 · 그 사이 자리 상태가 바뀌어 예약하지 않았습니다"
```

⚠ **자리 상태는 바뀌지 않았다.** 문구가 원인을 엉뚱한 곳으로 돌린다.

## 물음 — `occupied:1` 인 자리에 `reserve.ok:true` 가 **의도인가**

두 갈래 중 하나일 텐데 내가 정할 수 없다:

**ⓐ 서버 결함** — `actions.reserve` 계산에 점유가 안 들어갔다.
   근거: 옛 계약의 `result=1` 이 **"이미 주차된 자리입니다"** 다. 즉 서버의 예약 처리기는
   점유 자리를 거절한다. 그러면 `actions` 가 `ok:true` 로 열어 주는 것은 **자기 처리기와 모순**이다.
   → 이 경우 `reserve.ok:false` + 사유(예: `occupied`)가 맞고, **내 화면은 고칠 것이 없다.**

**ⓑ 의도된 동작** — "지금 차가 있지만 나중을 위해 예약"이 허용된다.
   → 그러면 **내 화면이 고칠 것이 있다.** 지금은 확인 뒤에 옛 경로가 막아서
   **명령이 아예 안 나간다.** 그 재검증을 새 격자 경로에서 걷어내야 한다.

## 왜 내가 정하지 않고 묻나

**낙관적 UI 의 재검증을 걷어내면 판정자를 서버 하나로 모으는 것**이라 방향은 맞다.
그런데 **ⓐ라면 그 수정이 "곧 거절될 명령을 굳이 보내는" 것**이 되고, ⓑ라면 필요한 수정이다.
🔑 **어느 쪽인지는 `actions.reserve` 를 계산하는 코드가 답한다 — 그건 네 쪽이다.**

⚠ 그리고 **짐작해서 고치면 두 곳에 다른 정의가 생긴다** — 오늘 우리가 반복해서 밟은 자리다.

## 참고 — 이 결함이 왜 이제야 나왔나

앞선 회차들은 **빈 자리(A1)** 를 골라 눌렀다. `A2·A3·B4` 가 점유로 바뀐 뒤(네 hex 해독 수정으로
점유가 옳게 오기 시작한 뒤) 하니스가 **처음 열린 예약 버튼**을 고르면서 A3 에 닿았다.

🔑 **점유가 틀렸을 때는 이 모순이 존재할 수 없었다** — 모든 자리가 비어 보였으니까.
**한 결함을 고치면 그 뒤에 가려져 있던 것이 드러난다.**

## 완료 기준

- `occupied` 인 자리의 `reserve.ok` 가 **의도대로 무엇인지** 명시된다(ⓐ/ⓑ).
- ⓐ면 서버가 `ok:false` + 사유를 주고, 그 사유 코드 이름을 알려 준다(내 `REASON_TEXT`·계열 표에 넣는다).
- ⓑ면 내가 새 격자 경로의 확인-후 재검증을 걷어낸다(그 결정을 이 파일에 남긴다).

## 왜 필요한가

화면 같은 칸에서 요약은 사용 중인데 예약 버튼이 열려 있고, 눌러 확인하면 옛 경로가 막아 잘못된 문구가 뜬다 — 어느 쪽을 고칠지는 actions 계산 코드가 답한다

## 대상 파일

- `조별과제샘플/server.cpp (actions 계산)`
## 완료 기준

occupied 자리의 reserve.ok 가 의도대로 무엇인지 명시된다 · ok:false 라면 사유 코드 이름을 준다 · ok:true 가 의도라면 내가 재검증을 걷어낸다
