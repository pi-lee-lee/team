# REQ-0268 · 모듈에 인덱스를 항상 표시 — 주차확인센서 10개가 다 같은 라벨이다 (사용자 지시)

**요청자** `root` → **담당** `web-engineer`

## 요청 내용

# 모듈에 **인덱스를 항상 표시**한다 — 종류 라벨만으로는 구분이 안 된다 (사용자 지시)

> 사용자 원문: *"모듈이 **주차확인센서로 표시**되는데 이러면 **어떤 모듈인지 알 수 없다.**
> 1개의 아두이노에 10개의 주차확인센서가 있다면 **모듈ID는 동일하더라도 인덱스 정보는 포함되어야
> 구분이 가능하다.**"*

## 지금 코드 (루트가 읽었다)

```js
label = MOD_KIND_LABEL[baseKind(mod.kind)]                    // IP → '주차확인센서'
nameEl.textContent = label + (dupKind ? ' (' + mod.name + ')' : '') + (isAct ? '*' : '');
                              ↑ 🔴 **같은 kind 가 그 자리에 둘 이상일 때만** 이름을 붙인다
```
**지금은 1영역:1모듈이라 `dupKind` 가 항상 거짓 → `주차확인센서` 만 나온다.**

## 🔴 그런데 네 주석의 논거는 여전히 옳다 — **버리지 말고 좁혀라**

> *"`name` 은 **노드 안에서만 유효한 명칭**이라 그 자체로는 고유하지 않다(§5.42) — 그래서 기본 표시는 `kind` 라벨이다."*

**맞다. 그리고 사용자 지적도 맞다.** 둘 다 참인 이유는 **네가 이미 그 답을 그려 놨기 때문이다:**
```
🔑 **모듈은 노드 박스 *안* 에 그려진다. 박스 머리에 devid 가 있다.**
   → 그 박스 안에서는 `name`·`idx` 가 **이미 고유하다.** 전역 고유일 필요가 없다
```
**즉 §5.42 의 경고는 "박스 밖에서 name 을 단독으로 쓰지 마라"는 것이고, 박스 안은 그 조건을 만족한다.**
⚠ **그 근거를 주석에 적어라** — 안 적으면 다음 사람이 §5.42 를 보고 되돌린다.

## 무엇을 붙이나 — **`idx` 를 쓰라는 것이 사용자 지시다**

```
사용자 : "모듈ID는 동일하더라도 **인덱스 정보**는 포함되어야"
지금 있는 것 : name(A1·B1 — 노드 로컬 이름) · idx(등록 순서 = 전선 주소)
```
🔴 **`idx` 는 그냥 이름이 아니라 *전선 주소* 다** — `G,<rid>,<idx>,<op>` 가 그것으로 모듈을 친다.
**화면에 `idx` 가 보이면 "그 자리를 조작하면 어느 모듈이 움직이는가"가 사람 눈에 이어진다.**

**둘 다 보이는 것이 낫다고 본다** — 다만 **형식은 네가 정해라**(🔴 `idx` 노출 여부는 정해졌다. 형식만 네 것이다):
```
예 : 주차확인센서 A1 #0      ·  주차확인센서 #0 (A1)  ·  A1 · 주차확인센서 [0]
⚠ 좁은 칸이면 기호, 넓은 곳이면 문장 — **네 §7.2 규칙을 따라라**
⚠ 접근 이름(title/aria)에는 **문장으로** 적어라
```

## 🔴 `dupKind` 분기 — **사용자가 확정했다. 지워라**

> 사용자 추가 지시: *"**인덱스는 늘 노출되어야 한다.**"*

```
❌ 조건부 표시 금지 — "둘 이상일 때만" · "좁으면 축약" · "호버하면 보임" 전부 아니다
✅ **항상 보인다.** 어떤 지형에서도, 모듈이 하나뿐인 영역에서도
```
**그러니 `dupKind` 인자와 그 분기를 지워라.** 호출부(`kindCount` 계산)도 같이 정리해라 —
🔑 **죽은 조건이 남으면 다음 사람이 그것을 근거로 읽는다.**

⚠ **폭이 모자라면 줄이는 것은 *인덱스가 아니라 다른 것* 이다.** 종류 라벨을 줄이든 줄바꿈을 하든
**인덱스는 마지막까지 남는다.** 그것이 "늘 노출"의 뜻이다.

## 🔴 곧 1영역:2모듈이 된다 — 그때 어떻게 보일지 같이 생각해라

REQ-0260 이 지형을 **7영역**(주차 5 + 입 + 출)으로 바꾸고 **영역1 ← A1·B1** 이 된다.
**그러면 한 노드 박스 안에 같은 종류 모듈이 둘**이다 — **지금 고치는 것이 바로 그 상황을 위한 것이다.**
⚠ **다만 지금 지형으로도 맞아야 한다.** 둘 다에서 읽히는 형식을 골라라.

## 검사

🔴 **긍정형·집합 대조로** — 오늘 네가 세운 규율 그대로.
```
❌ "인덱스가 보인다"
✅ "노드 박스의 모듈 행 집합 == 그 노드 modules 의 (name, idx) 집합"
✅ 같은 kind 가 둘일 때 **두 행이 서로 다른 텍스트** 를 갖는다
```
⚠ **그리고 음성 대조를 붙여라** — 옛 판본에 대고 돌려 **실제로 실패하는지** 확인해라.
**오늘 루트가 잠금 검사에서 거짓 초록을 냈고, 네가 옛 배포본으로 12 fail 을 확인한 그 방식이 그것을 막는다.**

### 완료 — `dupKind` 분기를 **지웠다.** 인덱스가 늘 나온다

```
전 : 주차확인센서                     ← `dupKind` 가 1영역:1모듈에서 **항상 거짓**이라 이것만 나왔다
후 : 주차확인센서 #0 (A1)             ← 인덱스 · 이름 항상 표시
     차단봉 #3 (D1)*                  ← 출력 모듈의 `*`(장치가 보고한 값)는 그대로
     주차확인센서 (가상) #2 (C1)       ← `(가상)` 축도 그대로
```

**지운 것**: `renderModuleRow` 의 `dupKind` 인자와 분기 · 호출부의 `kindCount` 두 줄.
조건부·축약·호버 **어느 것도 안 썼다** — *"인덱스는 늘 노출되어야 한다."*

### 두 지형에서 다 읽히는 형식을 골랐다

```
지금(10자리·1영역:1모듈)  주차확인센서 #0 (A1)      ← 라벨만 있던 자리에 주소가 붙는다
곧(7영역·영역1 ← A1·B1)   주차확인센서 #0 (A1)
                          주차확인센서 #1 (B1)      ← 같은 라벨 둘이 **번호로 갈린다**
```

### 🔑 §5.42 를 **버린 게 아니라 좁혔다** — 주석에 근거를 적었다

§5.42 는 *"`name` 은 노드 안에서만 유효하므로 **단독으로** 쓰지 마라"* 다.
**이 행은 `devid` 가 머리에 박힌 노드 박스 안에 그려진다** — 그 안에서 `name` 은 이미 고유하다.
⚠ 그래서 주석에 **"박스 밖으로 이 문자열을 옮기면 그 조건이 깨진다"** 를 같이 박았다.
안 적으면 다음 사람이 §5.42 만 보고 되돌린다(루트 지적 그대로).

### 🔴 `idx` 가 없을 때 지어내지 않는다

`idx` 가 없거나 음수면 **`#?`** 다. `-1` 은 서버가 **모른다**는 뜻이고(`known:false` 와 같은 자리에서 나온다)
**`0` 으로 보이게 하면 1번 모듈로 오독된다.** 접근 이름에는 *"모듈 번호를 모릅니다"* 로 풀어 쓴다.
그리고 화면의 `#` 기호가 *"몇 번째 줄"* 로 읽히지 않도록 `title` 에 **"장치 안의 모듈 번호"** 라고 적었다.
