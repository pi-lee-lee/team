# REQ-0046 · 시뮬 트리거 구현: server.cpp 의 M 중계 + fake_arduino.py 자율 전진 제거

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

## 명세 승인 — v1.4 를 얼린다. 판단 2건 모두 승인

**루트 검산**: 문서에서 전선 라인 27개를 뽑아 체크섬을 재계산했다. **26개 일치.**
유일한 불일치 `A,42,??,3,1B` 는 "이게 틀렸었다"고 설명하는 **서술문**(334·1361행)이고,
살아 있는 예제(211·313행)는 `74` 로 맞다. `M,60,4B`·`M,65535,7D` 둘 다 확인했다.

### ① 새 타입 `M` — 승인. 근거가 특히 좋다

`T` 에 얹지 않은 이유가 **"8바이트로 짧다"가 아니라 "구현자가 무장 검사를 붙일 위험"** 이라는 것이
핵심이다. §12A.2 가 `T,S`/`T,X` 에 "무장 안 하면 result=4"를 못 박아 뒀으니, 같은 타입에 두면
다음 사람이 그 검사를 그대로 복사한다. 그러면 **"테스트 모드와 별개"라는 요구 자체가 깨진다.**
타입을 나눠서 그 실수가 일어날 자리를 없앤 것이 맞다.

### ② `result=5`(바꿀 시뮬 칸 없음) — 승인

대안(`result=0` + `slot="??"`)을 기각한 이유가 정확하다 — **성공과 무동작이 구분되지 않는다.**
버튼을 눌렀는데 아무 일도 안 났는데 화면이 "성공"으로 표시하는 것은
이 프로젝트에서 반복해서 잡아온 바로 그 모양이다(rid 충돌·폴백 404·주입값 위장).

### ③ "예약된 빈칸 우선"의 근거도 승인

**"도달 가능하지만 평균 열 번 눌러야 보이는 상태는 도달 불가와 실질적으로 같다"** — 이 문장을
명세에 남긴 것이 좋다. REQ-0018 완료기준 6 때 내가 판정을 뒤집었던 근거와 같은 성질이다.

### ④ §13 에 "자유 실행이 왜 없어졌는지" 남긴 것

이게 없으면 누군가 "주차장처럼 보이게" 다시 넣는다는 판단이 맞다. 실제로 그 연출은 내가 REQ-0018 에
넣으라고 지시했던 것이고, 그때는 이유가 있었다. **이유가 바뀐 것이지 그때가 틀렸던 게 아니다** —
그 점도 읽히게 돼 있으면 좋겠다(이미 그렇다면 됐다).

## 구현할 것

1. **`조별과제샘플/server.cpp`** — 브라우저 WS 트리거 → `M` 하달 → ACK 상관 → 결과를 화면으로.
   `result=5` 를 브라우저가 구분할 수 있게 전달해라.
2. **`net/fake_arduino.py`** — **자율 전진 코드를 제거하고 `M` 을 구현해라.**
   네가 지적한 대로 지금 명세와 어긋나 있다. 가짜 아두이노가 명세보다 낡으면
   **통합 시험이 실물을 대변하지 못한다** — REQ-0032 때 우회를 안 넣은 것과 같은 이유다.
   "예약된 빈칸 우선" 규칙도 여기 들어가야 CDP 하네스로 (1,1) 을 실증할 수 있다.

## 검증

macOS 에서 실제로 돌리고 로그를 붙여라:
- 트리거 → 한 칸만 바뀐다 (여러 칸이 아니다)
- **예약된 빈 칸이 있으면 그 칸이 먼저 채워진다** → `occupied=1,reserved=1` 관측
- 바꿀 시뮬 칸이 없을 때 `result=5` 가 오고 화면이 성공으로 표시하지 않는다
- **무장 여부와 무관하게** 트리거가 동작한다 (무장 중에도 먹는다)
- 실물 소스로 지정된 칸은 트리거의 영향을 받지 않는다
- 트리거 없이는 값이 스스로 안 바뀐다 (자율 전진 제거 확인)
- 기존 검증 회귀 없음

**명령을 엮지 마라(a && b).** 하나씩 실행한다.

## 왜 필요한가

명세가 얼렸으므로 서버와 가짜 아두이노가 없으면 웹·아두이노가 붙을 상대가 없다. 특히 fake_arduino 의 자율 전진은 지금 명세와 어긋나 있어, 그대로 두면 통합 시험이 실물과 다른 것을 검증하게 된다.

### 검증 7항

**① 트리거 → 한 칸만 바뀐다** (5회 연속, 매번 정확히 한 칸)

```
1회: 바뀐 칸 ['B2'] · ack slot=B2 result=0 · 0000001000
2회: 바뀐 칸 ['A4'] · ack slot=A4 result=0 · 0001001000
3회: 바뀐 칸 ['A2'] · ack slot=A2 result=0 · 0101001000
4회: 바뀐 칸 ['B4'] · ack slot=B4 result=0 · 0101001010
5회: 바뀐 칸 ['A3'] · ack slot=A3 result=0 · 0111001010
```

**ACK 의 `slot` 이 실제로 바뀐 칸과 매번 일치한다** — 화면이 "A3 이 바뀌었습니다"를 띄울 수 있다.

**② ★ 예약된 빈칸 우선 → `occupied=1 ∧ reserved=1` 관측** (이 개정의 요점)

```
예약 후:   A5 occ=0 res=1
→ sim_step
트리거 후: A5 occ=1 res=1 · ack slot=A5
=> 예약된 빈칸이 우선 채워짐: True
=> occupied=1 ∧ reserved=1 (성공 상태) 관측: True
```

**한 번 눌러서 나왔다.** 무작위였다면 평균 열 번쯤 눌러야 했다.
아두이노 로그도 의도를 그대로 말한다:

```
15:28:13  * 한 걸음: A5 예약된 빈칸에 입차 (occupied=1, reserved=1)
15:28:32  * 한 걸음: B4 occupied=0            ← 예약 대기가 없으면 무작위 뒤집기
```

**③ 바꿀 시뮬 칸이 없을 때** (10칸 전부 `--real-slots` 로 실물 지정)

```json
{"type":"ack","rid":"n1","slot":null,"result":5,"message":"바꿀 시뮬 자리가 없습니다"}
```

```
=> result 가 0(성공)이 아니다: True
=> result=5 로 구분됨: True
=> 문구가 성공이 아님: True
```

**④ 무장 중에도 트리거가 먹는다** (테스트 모드와 별개)

```
armed = True
무장 중 트리거 → ack slot=B4 result=0
overridden 비트: 0000000000
=> 무장 중에도 동작: True
=> 시뮬 값이 tmask 에 안 들어감: True
```

**⑤ 실물 칸은 영향 없음** — `--real-slots A1,B5` 로 지정하고 5회 눌렀다.

```
=> 실물 칸(A1,B5)이 바뀐 적 있는가: False
```

**⑥ 트리거 없이는 안 바뀐다** (자율 전진 제거 확인) — 12초 관찰

```
서로 다른 점유 패턴: 1 ['0000000000']
=> 자율 전진 없음: True
```

**개정 전이었다면 여기서 서너 개 패턴이 나왔다.** 그게 시험을 불가능하게 만들던 것이다.

**⑦ 회귀**

```
한글 번호판 예약 → res=1 user_id=980가4568
테스트 주입 → armed=True override_count=1
해제 후 예약 생존: True          (§7.5-3)
/ → 200 · data_log 2건
빌드 -Wall -Wextra 0경고 · --selftest 22/22
```

전선 로그(서버 → 아두이노): `→ARD M,4,79` `M,5,78` `M,7,7A` `M,9,74` `M,12,4E` — **8~11바이트**다.

### 구현에서 신경 쓴 것

- **`M` 을 무장 여부로 막지 않는다.** 코드에 그 이유를 주석으로 남겼다 — 다음 사람이
  `T` 쪽 무장 검사를 보고 여기에도 붙일 자리라서다. 타입을 나눈 이유가 그것이었다.
- **`M` 도 rid 멱등·재전송·타임아웃을 그대로 탄다.** 재전송이 두 걸음이 되면
  한 번 눌렀는데 두 칸이 바뀐다 — §12B.2 가 막으려던 것이 그대로 깨진다.
- `result=5` 는 메시지도 성공 문구와 분리했다. 화면이 문구만 보고 성공으로 표시하지 않게.
- `fake_arduino.py` 의 `--arrive-sec` 는 **명세 밖의 시험 보조 장치**임을 주석에 명시하고
  기본 꺼짐으로 뒀다. 예약 은퇴 경로를 시간으로 재현할 때만 쓴다 — 시뮬레이터가 아니다.
- `--real-slots` 를 추가했다. 이 스크립트에 진짜 센서는 없지만
  **"실물 칸은 안 건드린다"를 시험하려면 지정할 수 있어야 한다.**

### 명세에 한 줄 더

루트가 ④에서 짚은 것을 §13 에 넣었다 — **"그때가 틀렸던 것이 아니라 이유가 바뀐 것이다."**
자율 전진은 센서도 화면도 없던 시절 "빈 화면이 아니라 주차장이 도는 것처럼" 보이려고 넣은 것이고
그 목적에는 맞았다. 실물과 시연이 생기면서 **관찰 가능성**이 더 중요해졌을 뿐이다.
폐기 기록을 "지난 결정이 나빴다"로 읽지 말라고 적어 뒀다.

### 미검증

- **Windows 빌드 여전히 불가.**
- **실제 브라우저에 "시뮬레이션" 버튼이 아직 없다** — WS `sim_step` 메시지 수준까지만 확인했다.
  버튼과 화면 표시(특히 `result=5` 를 성공으로 표시하지 않는 것)는 web-engineer 쪽이다.
- **실기 아두이노(`client.ino`)의 자율 전진 제거 여부는 확인할 수 없다** — 그쪽 요청이 따로 나갔다.
  실기 조합은 그게 끝나야 이 명세대로 돈다.
- 대역폭 53.12ms/왕복은 계산값이고 실측이 아니다.
