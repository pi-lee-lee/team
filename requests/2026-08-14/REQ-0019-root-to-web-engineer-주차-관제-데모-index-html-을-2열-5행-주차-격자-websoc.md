# REQ-0019 · 주차 관제 데모: index.html 을 2열 5행 주차 격자 + WebSocket 예약 화면으로 다시 쓴다

## 요청 내용

## 먼저 읽어라 — 이 요청의 근거 문서

**`docs/net/parking-protocol.md` v1 (얼림).** socket-engineer 가 쓰고 루트가 검산했다.
WebSocket JSON 스키마·예약 시퀀스·오류 코드가 전부 §5, §8 에 있다. **이 요청은 그 문서를 대체하지 않는다.**
문서와 이 요청이 어긋나 보이면 문서가 이긴다. 문서를 바꿔야겠다면 루트에게 요청을 발행해라(12절).

현행 코드: `조별과제샘플/index.html` (293줄). 이 파일을 개선한다 — 새 트리로 옮기지 않는다.
**단일 파일을 유지해라.** 조별과제 데모라 파일 하나로 배포·제출되는 것이 이점이다. 빌드 도구·외부 CDN 금지.

## 만드는 것

2열 5행 = 10칸 주차 격자. 빈자리를 누르면 예약 확인 → 예약 → 서버 → 아두이노까지 흐른다.

### 화면

```
        열 A      열 B
행 1  [  A1  ]  [  B1  ]
행 2  [  A2  ]  [  B2  ]
 …               …
행 5  [  A5  ]  [  B5  ]
```

**`occupied` 와 `reserved` 는 직교한다(§1.1). 4가지 조합을 전부 구분해서 보여라:**

| occupied | reserved | 의미 | 화면 |
|---|---|---|---|
| 0 | 0 | 빈 자리 | 선택 가능 — 클릭하면 예약 |
| 0 | 1 | 예약됨, 차는 아직 | 예약자 표시. 내 예약이면 취소 가능 |
| 1 | 0 | 예약 없이 주차됨 | 사용 중 |
| 1 | 1 | 예약한 자리에 차가 들어옴 | 사용 중(예약자) — **정상 완료 상태다** |

마지막 조합을 "그냥 사용 중"으로 뭉개지 마라. 이 시스템이 성공했을 때의 모습이다.

### 데이터 경로 — WebSocket 이 주, data_log.json 이 예비

- **주 경로**: `ws://<현재호스트>:9900/ws` 로 접속. 스냅샷을 push 로 받는다(폴링 아님).
- **예비 경로**: WS 가 끊기면 `data_log.json` 을 폴링해서 화면을 계속 갱신한다.
  사용자가 이 파일을 명시적으로 요구했고 서버가 최신 2건을 원자적으로 유지한다(§9).
  **두 경로가 같은 렌더 함수를 타게 만들어라** — 따로 만들면 예비 경로가 실제로는 안 도는 죽은 코드가 된다.
  (data_log.json 은 §9.1 형태의 **JSON 배열**이다. 현행 코드처럼 줄 단위로 파싱하면 안 된다.)
- WS 끊김은 지수 백오프로 재접속. 화면 어딘가에 연결 상태를 항상 보여라.
- `device.online == false` 면 **"센서 끊김"** 을 명확히 표시한다. 이때 격자는 마지막으로 알던 값이다 —
  실시간인 척하면 안 된다.

### 예약 흐름 (§8)

1. 빈자리 클릭 → **"예약하시겠습니까?"** 확인
2. 예약 누르면 `{"type":"reserve","slot":"B3","user_id":<사용자값>,"rid":<불투명 문자열>}` 송신
3. **낙관적 UI**: 즉시 "요청됨"으로 표시 (확정이 아님을 시각적으로 구분해라)
4. `ack` 수신 → `result` 에 따라:
   - `0` 확정 / `1` "이미 주차된 자리입니다" / `2` "이미 예약된 자리입니다" / `3` "잘못된 요청"
   - `0` 이 아니면 **낙관적 UI 를 되돌린다**
5. `error` 수신(`device_offline`, `ack_timeout`, `bad_request`, `rate_limited`) → 사람이 읽을 메시지로 표시하고 롤백
6. **ACK 가 안 와도 영원히 "요청됨"으로 두지 마라.** 자체 타임아웃(서버 최종 실패가 4.5초 뒤이므로
   그보다 넉넉하게, 예: 6초)을 걸고 롤백한다.
7. 내 예약은 취소도 가능해야 한다 — `{"type":"cancel","slot":"B3","rid":...}`

`rid` 는 **그 브라우저 안에서만 유일한 불투명 문자열**이다(최대 32자). 서버가 전선용 uint16 으로
번역하므로(§4.1) 다른 브라우저와 겹쳐도 된다.

### 사용자 고유값 — 지금은 없다. 자리만 만들어 둔다 ⚠

인증 체계가 아직 없다. **하지만 나중에 값만 채우면 되도록 데이터 형식을 지금 마련해 둔다:**
- `user_id` 를 한 곳에서 만들고 `localStorage` 에 보존해 새로고침해도 유지되게 해라
  (예: 최초 방문 시 무작위 생성). 그래야 "내 예약"과 "남의 예약"을 화면에서 구분할 수 있다 —
  이게 없으면 취소 버튼을 누구에게 보여줄지 정할 수 없다.
- 사용자 정보를 담는 객체를 **한 군데로 모아라**(`user_id`, `display_name`, 향후 확장 자리).
  인증이 붙을 때 고쳐야 할 지점이 한 곳이 되도록.
- 서버 스냅샷의 각 자리에는 `user_id` / `reserved_at` 키가 **`null` 이어도 항상 존재한다**(§5.3).
  키가 없을까 봐 방어할 필요는 없지만, 값이 `null` 인 경우는 처리해야 한다.

## 현행 코드에서 버릴 것

- 10초 `setInterval` 폴링 — WS push 로 대체(예비 경로에만 폴링을 남긴다)
- 줄 단위 JSON 파싱(`rawText.split(\n)`) — 이제 유효한 JSON 배열이다
- 온습도/조도/가스 카드와 로그 표 — 주차 도메인이 아니다. 격자와 예약 UI 로 대체한다
  (장치 상태 표시는 `device.online`/`uptime`/`seq` 정도로 충분하다)

## 검증

socket-engineer 가 서버를, arduino-engineer 가 스케치를 병렬로 만든다. 셋이 붙기 전에는
**명세 §5.3 의 스냅샷 예제 JSON 을 코드에 하드코딩해 넣어 렌더링을 먼저 확인해라.**
그 예제는 `A5` 가 `occupied=1,reserved=1` 인 케이스를 포함하므로 4조합 중 3개가 바로 보인다.
서버가 준비되면 실제 연결로 다시 확인한다.

**명령을 엮지 마라(`a && b`).** 하나씩 실행한다.

## 왜 필요한가

현행 화면은 센서 카드와 로그 표뿐이라 주차 격자도 예약 UI 도 없고, 서버로 보내는 경로가 아예 없어 예약이 성립하지 않는다. 10초 폴링은 실시간이 아니다. user_id 를 지금 한 곳에 모아 두지 않으면 인증이 붙을 때 화면 전체에 흩어진 예약 소유 판정을 다 고쳐야 한다.

9) §5.3 예제 스냅샷을 넣어 렌더링을 실제로 확인한 결과를 적어라 (브라우저에서 열어 본 것인지, 코드 검토만인지 구분해서)
확인하지 않은 것을 "동작한다"고 적지 마라.

### 무엇을 만들었나

- **격자**: `<ul role="list">` 안에 자리마다 `<button>` 하나. DOM 순서는 §1 전선 인덱스 그대로
  `A1 A2 A3 A4 A5 B1 B2 B3 B4 B5` 이고, 배치만 CSS 로 열 우선(`grid-auto-flow: column` +
  `grid-template-rows: repeat(5,…)`)으로 돌렸다. 기본 행 우선 흐름이면 `A1|A2 / A3|A4 …` 로
  어긋나므로 여기서 갈린다.
- **전송 계층 3종이 렌더 함수 하나로 합류한다**: WS 스냅샷 / `data_log.json` 배열 / 데모 예제가
  모두 `normalizeSnapshot()` → `applySnapshot()` → `render()` 를 탄다. 화면을 바꾸는 입구는
  `applySnapshot()` 하나뿐이라 예비 경로가 죽은 코드가 될 수 없다.
- **낙관적 UI 는 스냅샷을 변조하지 않는다**: `state.pending` 이라는 별도 레이어에 쌓고 렌더 시
  합성한다 → 롤백이 `delete` 한 줄이고, 서버 상태와 요청 상태가 섞이지 않는다.
- 버린 것: 10초 `setInterval` 폴링(주 경로에서 제거, 예비 경로에만 남음), 줄 단위 JSON 파싱
  (`split('\n')` → `res.json()`), 온습도/조도/가스 카드와 로그 표, 모든 `innerHTML` 템플릿.

### 3) 4조합의 시각적 구분 — 색만으로 구분하지 않는다

| occupied·reserved | 테두리/배경 | 문구(1행) | 부가 문구(2행) | 동작 |
|---|---|---|---|---|
| 0·0 | 초록 테두리 + 흰 배경 | **빈 자리** | 눌러서 예약 | 활성 |
| 0·1 | 주황 테두리 + 미색 배경 | **예약됨 (입차 전)** | `예약자 u17` / `소유자 정보 없음` | 비활성 |
| 1·0 | 회색 테두리 + 회색 배경 | **사용 중** | 예약 없이 주차됨 | 비활성 |
| 1·1 | **파란** 테두리 + 파란 배경 | **사용 중 (입차 완료)** | `예약자 u17` | 비활성 |

"내 예약"은 위 4종과 **직교하는 축**이라 색이 아니라 **보라색 안쪽 링**(`box-shadow: inset`)으로
겹쳐 표시한다. 그래서 `1·1 + 내 것`(내 예약에 내가 입차 = 성공 상태)과 `1·1 + 남의 것`이
같은 파란 타일이면서도 링 유무로 갈린다. 내 예약이면 2행이 `내 예약`으로 바뀌고,
`0·1 + 내 것`일 때만 문구가 **`내 예약 / 눌러서 예약 취소`** 로 바뀌며 활성이 된다.
진행 중 요청은 **점선 테두리 + 깜빡임 + `요청됨…` / `아직 확정이 아닙니다`** 로,
확정 상태와 눈으로 구분된다(`prefers-reduced-motion` 이면 애니메이션은 끈다).

### 브라우저에서 실제로 확인한 것 (Google Chrome 151.0.7922.109 headless, 스크린샷 판독)

`claude-in-chrome` 스킬이 이 세션에 없어 Chrome 을 직접 headless 로 띄우고 렌더 결과를
이미지로 받아 눈으로 확인했다. 검증용 자동 클릭 하네스는 `/tmp` 사본에만 넣었고 배포 파일에는 없다.

1. **§5.3 예제 스냅샷 렌더** — A1/A4/B1/B2/B3 빈자리(초록), A2/A3/B4/B5 사용 중(회색),
   **A5 가 파란 "사용 중 (입차 완료) · 예약자 u17"**. 열 A 에 A1..A5, 열 B 에 B1..B5. 장치 패널에
   `P1 / 1시간 0분 0초 / seq 1234`.
2. **예약 전 구간** — 빈자리 클릭 → `<dialog>` 확인 → 점선 "요청됨…" → ack(result 0) → 주황
   "내 예약 · 눌러서 예약 취소"(보라 링) → 2.5초 뒤 데모 장치가 입차 → 파란 "사용 중 (입차 완료) ·
   **내 예약**". 같은 화면의 A5(남의 1·1)와 링 유무로 대비된다.
3. **ack 실패 롤백** — result=2 응답 → 타일이 빈 자리로 되돌아가고 빨간 알림
   "A1 · 이미 예약된 자리입니다".
4. **자체 타임아웃 롤백** — ACK 를 아예 보내지 않는 경우, 6초 뒤 롤백 + "응답이 없어 요청을
   되돌렸습니다 (자체 타임아웃 6초)". `요청됨` 이 영구히 남지 않는 것을 확인.
5. **취소** — 내 예약 클릭 → 확인 → ack → "예약이 취소되었습니다" 후 빈 자리 복귀.
6. **§9.1 파일 폴백** — `data_log.json` 형태 배열을 같은 렌더 경로로 통과. 장치 패널이
   "data_log.json 폴링 (폴백)", 센서가 "알 수 없음 (파일에는 이 정보가 없음)",
   A5 가 "소유자 정보 없음", 빈자리는 "예약 불가 (파일 폴백)".
7. **`device.online=false`** — 상단 빨간 배너 "⚠ 센서 끊김 — 아래 격자는 실시간이 아니라
   마지막으로 알던 값입니다" + 장치 패널 "끊김" + 빈자리 타일 "센서 끊김 — 예약 불가".
8. **서버 없이 `file://` 로 연 경우** — 스크립트 오류 없이 "상태 미상"으로 정직하게 degrade.
9. **키보드 접근성** — 10개 전부 `<button>`, `disabled` 속성 보유 **0개**. 비활성 타일은
   `aria-disabled="true"` 라 탭 순서에 남고, A5 에 `focus()` 가 실제로 걸리는 것을 확인했다
   (`disabled` 를 썼다면 4조합 중 3개에 키보드로 도달할 수 없다). 비활성 타일을 눌러도 무반응이
   아니라 이유를 알림에 띄운다.
10. **라이트/다크 테마** — `prefers-color-scheme` 양쪽 모두 렌더 확인.
11. **폴백 → WS 복귀 회귀** — 파일 폴백 중에는 "예약 불가 (파일 폴백)", WS 가 다시 붙은 직후
    (아직 새 스냅샷이 없는 상태)에는 같은 격자가 다시 "눌러서 예약"으로 돌아오는 것을 확인.
    이 두 장이 아래 `canAct()` 버그의 회귀 증거다.

### 확인하지 **못한** 것 (추정으로도 적지 않는다)

- **실제 서버와의 WebSocket 연결 전체**(핸드셰이크·프레이밍·16비트 확장 길이·실 ack/스냅샷).
  `server.cpp` 가 아직 없어 시도 자체가 불가능했다. WS 관련 코드는 **코드 검토만** 거쳤다.
- **HTTP 로 서빙되는 실제 `data_log.json` 폴링**(fetch·캐시·404 처리). `.json` 은 내 소유가
  아니라 테스트 픽스처를 만들 수 없어, 명세 §9.1 형태를 코드에 넣어 **같은 정규화·렌더 경로로**
  통과시키는 것으로 대신했다. `fetch()` 호출부와 실패 처리는 코드 검토만이다.
- 지수 백오프 재연결의 실제 반복 동작(서버 부재로 1회차까지만 확인).

### 판단이 필요했던 지점 — 명세가 말하지 않아 좁게 잡은 것

- **`user_id` 를 8자로 제한했다.** §2.3 `userid ::= 0*8(ALPHA/DIGIT/"_"/"-")` 이 전선 상한인데,
  §4.1 은 `rid` 에 대해서만 서버 번역을 규정하고 `user_id` 는 언급하지 않는다. 그대로 흘러간다고
  보고 `u` + 7자 = 8자, `[A-Za-z0-9_-]` 로만 생성한다. UUID 를 썼다면 전선에서 잘렸을 것이다.
  **서버가 user_id 를 따로 번역·해시한다면 이 제한은 불필요하다** — 그렇다면 알려 달라.
- **파일 폴백 중에는 예약·취소를 막았다.** §5.4 의 `reserve`/`cancel` 은 WebSocket 경로에만 있고
  HTTP 대체 경로가 없다. 눌러도 보낼 곳이 없으므로 타일을 비활성으로 두고 이유를 표시한다.
  단 **판단 근거는 연결 상태(link)이지 스냅샷 출처(source)가 아니다** — 검토 중 잡은 버그다.
  출처로 판단했더니, WS 가 다시 붙어도 서버가 다음 스냅샷을 push 할 때까지 출처가 `file` 로 남아
  **연결된 채로 전 타일이 영구히 "예약 불가"로 굳었다.** §5.3 은 "변화가 있을 때" push 라고만 하고
  접속 시 초기 스냅샷을 보장하지 않으므로, 조용한 주차장에서는 이 상태가 무한정 간다.
  격자가 조금 낡은 채로 요청을 보내는 것은 §7.2("최종 판정은 ACK")가 이미 상정한 모델이다.
  브라우저에서 폴백 → WS 복귀 두 방향을 각각 렌더해 확인했다.
- **`device.online=false` 면 클릭 전에 막는다.** §7.1 대로라면 서버가 `device_offline` 오류를
  돌려주겠지만, 왕복을 돌기 전에 화면에서 먼저 알려 주는 편이 낫다고 봤다. 오류가 실제로 와도
  처리한다(양쪽 다 구현).
- **폴백에서 `device.online` 을 지어내지 않았다.** §9.1 에 그 필드가 없다. `null`(모름)로 두고,
  기록 `ts` 가 10초보다 오래되면 "센서 끊김(**추정**)"이라고 따로 적었다. `ts` 는 서버 시계라
  브라우저 시계와 어긋날 수 있어 이 표시는 참고값이다 — WS 경로의 `online=false` 와 문구를 구분했다.

### 명세 변경 요청 없음 — REQ-0020 판정도 확인했다

§5.3/§5.4/§9.1 만으로 화면을 다 만들 수 있었다. 위 네 가지는 명세 위반이 아니라 명세가 열어 둔
자리를 좁게 채운 것이라 §12 절차(루트 경유 변경)를 밟지 않았다. 서버 구현이 다르게 가정하고
있다면 그때 요청을 발행하겠다.

작업 중 arduino-engineer 가 올린 **REQ-0020(프로토콜 v1 공백 3건)** 을 읽었다. 루트 판정은
**"web-engineer → 없음. WS 스키마를 얼린 채로 둔다"** 였고, 웹에 닿는 두 항목을 내 코드에 대조했다:

- **① 예약 은퇴(채택: 서버가 `occupied` 1→0 을 보고 `C` 로 소진)** — 웹에는 그 결과가 스냅샷의
  `reserved=0` 으로만 도착한다. 별도 처리 없이 현재 렌더가 그대로 반영한다. 변경 불필요.
- **② `result=3` 의 ACK `slot` = `"??"` 고정 표식** — 이건 전선(§2.3) BNF 확장이고 §5.3 WS 스키마는
  그대로다. 다만 서버가 그 값을 그대로 브라우저 ack 에 실어 보내더라도 내 핸들러는 안전하다:
  **대기 중인 요청이 있으면 자리 이름을 `rid` 로 찾은 내 쪽 기록(`p.slot`)에서 가져오고**,
  `msg.slot` 은 대응되는 요청이 없을 때의 알림 문구에만 쓴다. 지어낸 자리를 화면에 표시하지 않는다.
- **③ 은 아두이노 완료 판정 문제라 웹 무관.**

노쇼 예약 만료(`expires_at`)는 루트가 v1 범위 밖으로 명시적으로 미뤘다. 지금 화면은 만료 개념을
갖지 않으며, 사용자는 취소로 스스로 회복한다 — 이 화면의 취소 버튼이 그 회복 경로다.
