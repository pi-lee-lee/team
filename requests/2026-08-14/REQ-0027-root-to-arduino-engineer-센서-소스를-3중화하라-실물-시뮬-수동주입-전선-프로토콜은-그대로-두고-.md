# REQ-0027 · 센서 소스를 3중화하라: 실물 / 시뮬 / 수동주입 — 전선 프로토콜은 그대로 두고 USB 시리얼에 테스트 콘솔 추가

**요청자** `root` → **담당** `arduino-engineer`

## ⚠ 정정 (루트, 착수 전 발행) — **USB 시리얼 콘솔은 만들지 마라**

아래 원문 중 **"테스트 콘솔은 USB 시리얼에 붙인다" 절 전체를 취소한다.**
사용자가 원한 테스트 인터페이스는 시리얼이 아니라 **브라우저 화면**이었다.
원문의 그 부분은 루트가 "테스트 인터페이스"를 벤치 시험으로 잘못 해석한 것이다.

**같은 오버라이드 상태를 건드리는 제어 경로가 둘이면 서로 어긋난다.** 그래서 하나만 남긴다.

### 이 요청에서 지금 할 것 (이것만)

1. **`readSlotSensor(i)` 안의 층 구조** — 칸별 오버라이드 > 활성 소스(REAL/SIM). 원문대로.
2. **`SLOT_PIN[]` 배열 정의** + D0/D1/D7/D8 회피 근거 주석. 원문대로.
3. **센서 도착 시 절차 주석.** 원문대로.

### 하지 말 것

- USB 시리얼 명령 파서 (`Serial.available()` 읽기), `TEST_CONSOLE` 스위치 — **전부 취소**.
- 오버라이드를 **설정하는 경로는 이 요청에 없다.** 오버라이드를 *담을 그릇*만 만든다.

### 왜 지금 그릇만 만드는가

제어는 **전선(TCP)을 타고 브라우저에서 내려온다.** 그건 프로토콜 개정이라
socket-engineer 가 `docs/net/parking-protocol.md` 를 먼저 고친다(REQ-0028).
그 명세가 얼면 너에게 수신·반영 요청이 따로 내려간다.

명세를 기다리는 동안 **그릇(오버라이드 층 + 핀 배열)은 확정된 부분**이라 지금 만들어도 버려지지 않는다.
완료 기준 3·6·7 중 시리얼 관련 항목은 무시하고, 나머지와 아래를 만족하면 닫아라:

- 칸별 오버라이드를 설정/해제하는 **내부 함수**가 있다(외부 진입점은 아직 없다)
- 그 함수를 호출하면 다음 `S` 프레임의 해당 비트가 바뀐다는 것을 어떻게든 확인한다
  (임시 호출을 넣어 컴파일·확인 후 빼도 된다 — 확인 방법을 적어라)
- 플래시·RAM 사용량 변화

## 요청 내용

## 사용자 요구

> 아두이노에 현재 연결된 센서가 없다. 센서는 뒤에 연결할 것이다.
> 현재 인터페이스를 유지하고 테스트 인터페이스를 추가할 수 있는가?

답은 예다. 다만 지금 구조에는 빈 곳이 있다.

## 지금 구조의 문제

`readSlotSensor(i)`(109행)가 유일한 교체 지점인 것은 좋은 설계다. 그런데 그 안이
시뮬레이터에 **직결**되어 있다:

```cpp
uint8_t readSlotSensor(uint8_t i) {
  simAdvance(i);
  return (uint8_t)((simOcc >> i) & 1);
}
```

주석대로 "실물 센서가 오면 본문만 바꾼다" 를 하면 **차 없이 시험할 방법을 그 순간 잃는다.**
그리고 실제 설치는 한 번에 10칸이 다 되지 않는다 — 3칸만 배선하고 나머지 7칸은 아직 없는
중간 상태가 반드시 생긴다. 지금 구조는 그 상태를 표현할 수 없다.

## 만들 것 — 소스 3중화 + 칸별 오버라이드

`readSlotSensor(i)` **시그니처는 그대로 두고** 그 안을 층으로 나눈다:

```
readSlotSensor(i)
  ├─ 이 칸에 수동 오버라이드가 걸려 있으면 → 그 값을 돌려준다   (테스트)
  └─ 아니면 활성 소스에서 읽는다
       · REAL : digitalRead(SLOT_PIN[i])   ← 배선된 칸
       · SIM  : 지금의 simAdvance()        ← 배선 안 된 칸의 기본값
```

**오버라이드는 칸별이어야 한다.** 전역 스위치로 만들면 "3칸은 실물, 7칸은 시뮬" 이라는
실제 설치 중간 상태를 못 만든다. 그게 이 요구의 핵심이다.

## 테스트 콘솔은 USB 시리얼에 붙인다 ⚠

**전선 프로토콜(TCP 9991)에 테스트용 메시지를 추가하지 마라.** 그건 `docs/net/parking-protocol.md`
개정이고 서버·웹까지 흔든다. 테스트는 서버가 알 필요가 없는 일이다.

`Serial`(115200)은 지금 **출력에만 쓰이고 입력은 한 번도 읽지 않는다**(`Serial.available()` 없음).
비어 있는 채널이 이미 있다 — 아두이노 IDE 시리얼 모니터에서 바로 칠 수 있다.

명령 문법은 네가 정하되 다음이 되어야 한다:

| 하고 싶은 것 | 예 |
|---|---|
| 특정 칸을 강제 점유/해제 | `A3` 를 1 로, 0 으로 |
| 오버라이드 해제(원 소스로 복귀) | 한 칸씩, 그리고 전체 |
| 칸별 소스 지정 | `A3` 는 실물, 나머지는 시뮬 |
| 현재 상태 덤프 | 10칸의 소스·오버라이드·현재값 |

전선 문법(`S,A,R,C`)과 **첫 글자가 겹치지 않게** 해라. 사람이 로그를 볼 때 헷갈린다.

## 실물 센서 배선 준비도 지금 해 둔다

`SLOT_PIN[SLOT_N]` 핀 배열을 지금 정의해라. 나중에 배선할 때 표 한 줄만 고치면 되도록.
**D7/D8 은 SoftwareSerial 이 쓰고 D0/D1 은 USB 시리얼이다** — 그 넷을 피해서 배정하고
근거를 주석에 남겨라. 아날로그 핀을 디지털로 쓸지 여부도 네 판단이다.

## 지킬 것

1. **전선 프로토콜 무변경.** 서버·웹은 아무 차이를 못 느껴야 한다. 명세 개정 요청이 필요하다고
   판단되면 만들지 말고 먼저 루트에게 물어라.
2. **논블로킹.** `loop()` 가 상태 기계다. 시리얼 읽기가 막으면 예약 수신을 놓친다.
3. **컴파일 타임에 뺄 수 있게.** `#define TEST_CONSOLE 1` 같은 스위치로 감싸고, 껐을 때
   플래시·RAM 사용량이 실제로 줄어드는지 숫자로 확인해라.
4. **RAM 을 보라.** 지금 전역 744/2048바이트(36%)다. 시리얼 입력 버퍼가 늘어난다.
   켰을 때/껐을 때 사용량을 둘 다 적어라.
5. `readSlotSensor(i)` 를 호출하는 쪽(499행 등)은 고치지 마라. 인터페이스 유지가 요구사항이다.

## 실물 센서가 왔을 때의 절차를 주석으로 남겨라

이 요청의 진짜 산출물은 코드가 아니라 **"센서가 도착했을 때 무엇을 하면 되는가"** 다.
파일 상단이나 해당 함수 근처에 절차를 3~5줄로 적어라. 6개월 뒤에 읽을 사람이 대상이다.

**명령을 엮지 마라(a && b).** 하나씩 실행한다.

## 왜 필요한가

센서가 아직 없고 나중에 붙는다. 지금 readSlotSensor() 본문을 실물로 바꾸면 차 없이 시험할 수단이 사라지고, 10칸이 한꺼번에 배선되지 않으므로 "일부만 실물"인 중간 상태가 반드시 생기는데 현재 구조는 그것을 표현할 수 없다. 테스트 경로를 전선 프로토콜이 아니라 USB 시리얼에 두면 서버·웹을 전혀 건드리지 않고 해결된다.

### 1. `readSlotSensor()` — 층 구조

> ⚠ **이 절은 REQ-0030 에서 갱신됐다.** 아래 판본에는 **무장 조건이 빠져 있다.**
> §12A.2("무장 중일 때만 칸별 주입이 적용된다")에 맞춰 `testArmed &&` 가 추가됐다.
> 현재 코드와 그 근거는 **REQ-0030 의 처리 결과**를 봐라. 아래는 당시 기록으로 남긴다.

```c
uint8_t readSlotSensor(uint8_t i) {
  if (ovrActive & ((uint16_t)1 << i)) return (uint8_t)((ovrValue >> i) & 1);   // 수동 주입 최우선
  if (srcReal   & ((uint16_t)1 << i)) return readRealSensor(i);                // 배선된 칸
  simAdvance(i);                                                                // 배선 안 된 칸
  return (uint8_t)((simOcc >> i) & 1);
}
```

시그니처도 호출부도 그대로다. `srcReal`·`ovrActive`·`ovrValue` 전부 **칸별 비트마스크**라
"3칸만 실물, 7칸은 시뮬" 이라는 설치 중간 상태가 그대로 표현된다.

**그릇(내부 함수) — 지금 부르는 곳은 아무 데도 없다. 그게 의도다.**

```c
void slotOverrideSet(uint8_t i, uint8_t value);   // 그 칸 값을 강제
void slotOverrideClear(uint8_t i);                // 한 칸 해제
void slotOverrideClearAll(void);                  // 전 칸 해제
void slotSourceSet(uint8_t i, uint8_t useReal);   // 소스 전환(REAL 로 갈 때 pinMode 까지)
```

`static` 이 아니라 전역으로 뒀다 — `static` 이면 호출자가 없어 `-Wunused-function` 경고가 뜬다.
REQ-0028 로 명세가 얼면 수신 처리부가 이 넷을 부르면 된다.

### 2. `SLOT_PIN[]` 과 회피 근거

| 자리 | A1 | A2 | A3 | A4 | A5 | B1 | B2 | B3 | B4 | B5 |
|---|---|---|---|---|---|---|---|---|---|---|
| 핀 | D2 | D3 | D4 | D5 | D6 | D9 | D10 | D11 | D12 | **A0** |

- **D0/D1** USB 시리얼 — 물리면 업로드·디버그 출력이 깨진다
- **D7/D8** SoftwareSerial 로 ESP-01 과 통신 중
- **D13** 요청에 없던 항목인데 뺐다. 온보드 LED 가 저항+LED 로 GND 쪽으로 당겨
  `INPUT_PULLUP`(20~50kΩ)과 분압이 된다 → HIGH 가 확실히 안 읽힌다.
  **"가끔 점유로 읽히는" 형태의 고장**이라 배선 뒤에 찾기가 가장 어렵다. 처음부터 뺐다.
- **A4/A5** Uno 의 I2C(SDA/SCL). 지금 I2C 를 안 쓰더라도 채우면 나중에 디스플레이 하나 못 단다.

남는 디지털 핀이 **아홉 개뿐**이라 10번째(B5)만 아날로그 `A0` 을 디지털로 쓴다.
그래서 난수 시드를 `analogRead(A0)` → **`analogRead(A1)`** 로 옮겼다(시드는 안 물린 핀이라야 노이즈가 나온다).
⚠ 주석에 못 박아 뒀지만 여기도 적어 둔다: **핀 `A0`** 과 **자리 `A1`~`A5`** 는 아무 상관이 없다.
글자가 겹칠 뿐이고 자리 `A0` 은 존재하지 않는다. D10~D12 가 SPI 라는 것도 주석에 남겼다.

### 3. 플래시·RAM — 그리고 지금은 그릇이 **이미지에 안 들어간다**

| 빌드 | 플래시 | 전역 RAM |
|---|---|---|
| REQ-0024 직후 (이 요청 전) | 9298 B (28%) | 744 B (36%) |
| **지금 (그릇만, 호출자 없음)** | **9316 B (28%)** | **744 B (36%)** |
| 참고: 임시 호출 1개를 넣었을 때 | 9388 B (29%) | 748 B (36%) |

RAM 이 안 늘어난 게 이상해서 파고들었다. **호출자가 없으니 옵티마이저가 오버라이드 층을 통째로 접는다** —
`ovrActive`/`ovrValue` 가 어디서도 쓰이지 않으므로 0 으로 상수 접힘되고, 함수 넷은 `--gc-sections` 가
최종 이미지에서 뺀다. 확인 방법은 루트가 허용한 그대로다: `setup()` 에 `slotOverrideSet(2,1);` 한 줄을
임시로 넣고 컴파일 → **플래시 +72 B, RAM +4 B** 로 실체화되는 것을 보고 다시 지웠다.

즉 **그릇의 실제 비용은 호출자가 생기는 순간 +72 B 플래시 / +4 B RAM**(+`slotSourceSet` 이 쓰이면 `srcReal` 2 B)이다.
지금 올린 18 B 는 `SLOT_PIN[]` 접근 코드와 `readRealSensor()` 몫이다(`SLOT_PIN` 자체는 PROGMEM 이라 RAM 0).

### 4. 실제 시험 — 보드는 없지만 **로직은 실행했다** (기준 8)

⚠ **실장 검증은 여전히 미실시다.** 보드가 없다. 그래서 대신 **client.ino 를 호스트(PC)에서 그대로
컴파일해 돌리는 회귀 테스트**를 만들었다. 내 소유 트리에 뒀다:

```
arduino/test/Arduino.h          Arduino 코어 스텁(가상 시계·가상 핀·Serial)
arduino/test/SoftwareSerial.h   SoftwareSerial 스텁 + 가짜 ESP-01(AT 응답)
arduino/test/avr/pgmspace.h     PROGMEM 스텁
arduino/test/host_test.cpp      시나리오 (client.ino 를 #include 한다)
arduino/test/run.sh             빌드 + 실행  →  `bash arduino/test/run.sh`
```

실행 비트는 세우지 않았다(`chmod` 이 bash 변조 가드 패턴에 있어 무인 세션에서 멈출 수 있다).
`bash` 로 부르면 된다. 빌드 산출물 `arduino/test/host_test.bin` 은 실행 후 지웠는데,
`.gitignore` 가 루트 소유라 무시 규칙은 내가 못 넣는다 — 필요하면 루트가 한 줄 추가해 달라.

가짜 ESP 는 `AT+CIPSTART` 에 `CONNECT` 를, `AT+CIPSEND=<n>` 에 `>` 를 돌려주고 그 뒤 n 바이트를
전선 라인으로 수집한다. `>` 를 안 주면 모든 전송이 실패하는데 그걸 "정상"으로 착각하기 딱 좋아서
일부러 구현했다. `+IPD,<n>:` 포장도 해서 수신 경로를 끝까지 태운다.

**기준 8 이 요구한 것([2])이 실제 실행으로 확인됐다** — 내부 함수를 부르면 다음 `S` 프레임의

스케치의 체크섬 함수가 틀려도 통과하지 않는다.

**처음 판본은 이 두 항목이 사실 아무것도 증명하지 못했다 — 고쳤다.** 가상 시계가 빨리 흘러
시뮬이 거의 모든 칸을 채워 두는 바람에, `slotOverrideSet(i,1)` 이 **완전한 no-op 이어도**
그 비트는 시뮬 때문에 1 로 읽혔다. 지금은 강제하기 전에 그 칸의 시뮬 값을 0 으로 못 박고
(`pinSimLow()` — `simOcc` 비트를 내리고 `simNextAt` 마감을 멀리 민다) **"밑바닥이 0 임"을 먼저
단언**한 뒤 1 을 강제한다. 그래서 1 이 나오면 출처가 오버라이드밖에 없다.
[3]에는 오버라이드를 걸지 않은 옆칸(B4)이 0 으로 남는지도 같이 본다 — 그게 "칸별"의 실제 증거다.

덤으로 [6]은 그동안 한 번도 실행해 보지 못했던 **수신 파서 전 구간**(LF 분할 → `+IPD` → 타입 문자
→ 체크섬 → 필드 분해 → 예약 반영 → ACK 생성)을 처음 끝까지 태운 것이다. 지금까지의 검증은
"내가 만든 라인의 체크섬이 맞다"였지 "받은 라인을 제대로 푼다"가 아니었다.

**이 테스트가 검증하지 않는 것 (중요)**
- **타이밍.** 가상 시계는 `millis()` 호출마다 1ms 씩 흐른다(스핀 루프를 끝내려면 필요하다).
  "1Hz 하트비트가 정확히 1000ms 인가"는 여기서 확인되지 않는다. 확인되는 것은 순서와 바이트다.
- **실기.** SoftwareSerial 송신 중 수신 유실(§6.3), ESP-01 의 실제 AT 응답 문구·지연, 전기적 문제.
- **AVR 최적화 결과.** 호스트 테스트는 오버라이드 층을 호출하므로 그 코드가 살아 있지만,
  현재 AVR 이미지에서는 호출자가 없어 접혀 나간 상태다(위 3절). 기능이 사라진 게 아니라
  호출자가 생기면 돌아온다 — 임시 호출 측정으로 확인했다.
