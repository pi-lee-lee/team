# REQ-0047 · 시뮬 자율 전진 제거 + M 프레임 수신 — 명세 v1.4 §12B

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

## 명세가 얼렸다 — `docs/net/parking-protocol.md` v1.4, §12B 신설

루트가 예제 체크섬 27개 중 26개를 검산해 확인했다(나머지 1개는 "이게 틀렸었다"는 서술문이다).
`M,60,4B` · `M,65535,7D` 둘 다 맞다.

## 할 것 — 네 묶음이 한 번에 간다

### ① 시뮬레이터 자율 전진 제거

`simAdvance()` 의 타이머 기반 자율 전진을 없앤다. **트리거를 받을 때만 한 걸음.**
네가 예상한 대로 `simNextAt[10]`(40바이트)와 `SIM_*_MS` 상수 상당수가 필요 없어진다.
RAM 이 얼마나 줄었는지 숫자로 적어라.

### ② REQ-0043 잔재 제거 ⚠

**반려된 요청의 코드가 파일에 살아 있다.** 네가 붙인 경고 블록 그대로다:

```
client.ino:273   if (!testArmed) simAdvance(i);      ← 이 무장 검사는 반드시 빠져야 한다
client.ino:118   simResume()
client.ino:641   simResume()
```

**무장 중에도 트리거는 먹어야 한다** — "테스트 모드와 별개"가 이 요구의 핵심이다.
그 검사가 남아 있으면 무장 중에 버튼이 안 먹어서 요구를 정면으로 어긴다.

### ③ `M` 프레임 수신 + ACK

§6.2 의 기존 4단계 파서를 그대로 타야 한다. **rid 멱등 캐시(§4.2)가 `M` 에도 적용되어야 한다** —
서버가 재전송하면 한 번 누른 것이 두 걸음이 된다.
ACK 는 **바뀐 칸**을 실어 준다. 바꿀 시뮬 칸이 없으면 `result=5`.

### ④ "예약된 빈 칸 우선" — 네가 제안한 규칙이다

`reserved=1, occupied=0` 인 칸이 있으면 **그 칸을 먼저 채운다.** 없으면 무작위로 한 칸.
`ARRIVE_MIN_MS`/`ARRIVE_MAX_MS` 는 이 규칙이 대체하므로 제거한다.

명세에 네 근거가 그대로 들어갔다 — **"도달 가능하지만 평균 열 번 눌러야 보이는 상태는
도달 불가와 실질적으로 같다."** REQ-0018 완료기준 6 때 내가 판정을 뒤집었던 것과 같은 성질이다.

## 지킬 것

- **실물 소스(`srcReal`) 칸은 트리거의 영향을 받지 않는다.** 그건 진실이고 사람이 흔들 것이 아니다
- 한 번 누르면 **한 칸만** 바뀐다. 여러 칸이면 지금 문제가 그대로 재현된다
- `readSlotSensor(i)` 시그니처와 호출부는 그대로
- 논블로킹

## 검증

하네스로 최소한:
- 트리거 없이는 값이 스스로 안 바뀐다
- 트리거 한 번에 한 칸만 바뀐다
- 예약된 빈 칸이 있으면 그 칸이 먼저 채워진다 → `occupied=1,reserved=1` 도달
- **무장 중에도 트리거가 먹는다** ← ②의 회귀 방지 핵심
- 실물 칸은 안 바뀐다
- 같은 rid 재수신 시 두 걸음 가지 않는다 (멱등)
- 바꿀 칸 없으면 `result=5`

컴파일 결과와 플래시·RAM 변화도 적어라. 실기 검증은 사용자 몫이다.

**명령을 엮지 마라(a && b).** 하나씩 실행한다.

## 왜 필요한가

사용자가 실물에서 시뮬 데이터가 계속 바뀌어 시험이 불가능하다고 보고했다. 자율 전진을 없애고 버튼 트리거로 바꾼다. 그리고 반려된 REQ-0043 의 무장 검사가 파일에 남아 있어, 그대로 두면 무장 중에 버튼이 안 먹는다.

## 대상 파일

- `조별과제샘플/client.ino`
## 완료 기준

1) 자율 전진 제거 — 트리거 없이 값이 안 바뀐다
2) REQ-0043 의 `if (!testArmed)` 검사와 simResume 잔재 제거 — 무장 중에도 트리거가 먹는다
3) M 수신이 §6.2 파서를 타고 rid 멱등이 적용된다
4) ACK 가 바뀐 칸을 싣고, 바꿀 칸 없으면 result=5
5) 예약된 빈 칸 우선 규칙 + ARRIVE_MIN_MS/MAX_MS 제거
6) 실물 칸은 영향 없음 / 한 번에 한 칸
7) 하네스 케이스 + PASS/FAIL, 컴파일 + 플래시·RAM 변화
8) REQ-0043 요청 md 의 경고 블록을 해소 처리로 갱신

### ① 자율 전진 제거 — RAM 이 정확히 44바이트 줄었다

사라진 것: `simNextAt[10]`(40 B), `simLastChangeAt`(4 B), `SIM_MIN_GAP_MS`,
`SIM_OCC/EMPTY_MIN/MAX_MS`, `ARRIVE_MIN/MAX_MS`, `simAdvance()`, `simResume()`.

| 빌드 | 플래시 | 전역 RAM |
|---|---|---|
| REQ-0049 직후 | 11860 B (36%) | 832 B (40%) |
| **지금** | **11654 B (36%)** | **788 B (38%)** |
| 차이 | −206 B | **−44 B** |

**−44 B 는 `simNextAt` 40 + `simLastChangeAt` 4 와 정확히 일치한다** — 예상과 맞았다.

`readSlotSensor()` 는 이제 세 줄이다: 오버라이드(무장 중) → 실물 → 시뮬 값 그대로 읽기.
시그니처와 호출부는 그대로다.

### ② REQ-0043 잔재 — **함수째 사라져서** 없어졌다

`if (!testArmed) simAdvance(i);` 는 `simAdvance()` 가 통째로 사라지면서 같이 없어졌다.
`simResume()` 호출 두 곳도 제거했고, `T,D`(해제) 처리에는 **무장/해제가 시뮬에 아무 영향이 없다**는
주석을 남겼다(§12B.3).

**회귀 방지**: [24]-(g) 가 *무장 중에 M 을 보내면 `simOcc` 가 바뀐다*를 단언한다.
무장 검사가 되살아나면 그 시험이 실패한다.

### ③ `M` 수신 — 새 파서를 만들지 않았다

`handleLine()` 의 타입 문자 검사에 `M` 을 더하고 `processCommand()` 의 필드 수만 3으로 분기했다
(`R`=5, `C`=4, `T`=6, **`M`=3**). `+IPD` 추출·체크섬·**멱등 캐시**·ACK 생성이 전부 기존 경로다.
멱등은 위쪽 `cacheFind()` 가 이미 처리하므로 `M` 을 위해 따로 쓴 코드가 없다 —
**재전송이 두 걸음이 되는 사고(§12B.4)가 구조적으로 막힌다.**

착수 전에 명세 §2.5 의 예제 4줄을 손으로 검산했고 전부 맞았다:
`M,60,4B` · `M,65535,7D` · `A,60,A3,0,05` · `A,60,??,5,72`. 하네스 [24]-(b) 가 같은 대조를 자동으로 한다.

### ④ 예약된 빈칸 우선 — **판단이 하나 들어갔다. 명세 보완이 필요하다** ⚠

1순위 `reserved=1 ∧ occupied=0` 인 시뮬 칸 채우기, 없으면 2순위 무작위 뒤집기. 명세 그대로다.

**다만 "시뮬 칸"의 정의에 내가 조건을 하나 더 넣었다.** 후보에서 빼는 칸이 둘이다:

| 뺀 것 | 근거 |
|---|---|
| (a) 실물 센서 칸(`srcReal`) | **명세가 명시**(§12B.3) — 진실이고 사람이 흔들 것이 아니다 |
| (b) **지금 오버라이드가 먹는 칸**(`testArmed && ovrActive`) | **명세에 없다 — 내 판단이다** |

(b)를 뺀 이유: 그 칸을 고르면 `simOcc` 는 바뀌는데 **보고되는 `occupied` 는 오버라이드에 가려
안 바뀐다.** ACK 는 "그 칸이 바뀌었다"고 말하는데 화면은 그대로 → **§12B.2 가 지키려는
"눌렀다 → 저 칸이 바뀌었다" 1:1 대응이 깨진다.**

부수 효과 하나가 더 있다: 후보에서 빼면 **후보의 `simOcc` 가 곧 보고되는 `occupied`** 이므로
1순위 판정(`occupied=0`)에 "어느 occupied 냐"는 모호함이 없어진다.

전 시뮬 칸이 오버라이드 중이면 **관측 가능한 변화가 없으므로 `result=5`** 로 본다.
명세에 한 줄 넣을지 루트가 정해 달라 — 지금은 위 근거로 구현했다.

`ARRIVE_MIN_MS`/`ARRIVE_MAX_MS` 는 제거했고, 예약 성공 자리(`R` 처리)에 **그 일을 이제
§12B.2 규칙이 대신한다**는 주석을 남겼다.

### 하네스 (기준 7) — **120 PASS / 0 FAIL**

```
[24]-(a) 트리거 없이 가상시각 2분 → simOcc 0000 → 0000  (0비트 변화)
     (b) 명세 §2.5 의 M/ACK 예제 4줄 체크섬 일치
     (c) M,60,4B → 정확히 한 칸(A5)만 바뀜, ACK "A,60,A5,0,03" 이 그 칸을 가리킴
     (d) 같은 rid 재전송 → simOcc 불변 (두 걸음 안 됨)
     (e) B3 예약 후 M → B3 이 먼저 채워지고 occupied/reserved 둘 다 1 로 전선에 나감
     (f) 시뮬 변화는 tmask 와 무관 (해제 상태라 필드 자체가 없음)
     (g) ★ 무장 중 M → simOcc 0080 → 0280 으로 바뀜. tmask 는 0000000000 유지
     (h) 전 칸 실물 → ACK "A,63,??,5,71" (result=5)
```

**(e) 가 이번 요청의 핵심 성과다** — `occupied=1, reserved=1`(§1.1 마지막 행)이 **실제로
전선에 나가는 것을 단언**한다. 내가 REQ-0043 중단 때 "이 경로가 사라진다"고 경고했던 그 조합이고,
이제 하네스가 그 도달을 지킨다.

**하네스에서 하나 손봐야 했다(스케치 결함 아님).** `simAdvance()` 가 사라지면서 **가상 시계의
속도가 바뀌었다** — 가상 시계는 `millis()` 호출 수에 비례해 흐르는데, `sensorTick()` 이 칸마다
`millis()` 를 부르던 것이 없어져 루프당 시간 진행이 크게 줄었다. 그래서 `spin(400)` 이 예전엔
하트비트(1000ms)를 넘겼는데 이제 못 넘긴다. [25] 의 "복귀 후 다시 S 를 보낸다"가 그것 때문에
실패했고, **루프 횟수가 아니라 가상 시간으로 기다리도록**(`spinMs(2500)`) 고쳤다.
[17] 의 즉시 전송 시험은 176ms 로 여전히 유효하다(디바운스 100ms 통과, 하트비트 1000ms 미만).

### 검증하지 않은 것

- ⚠ **실기 검증은 사용자 몫이다.** 보드에서 버튼을 눌러 한 칸씩 움직이는지는 올려 봐야 안다.
- **연타(§12B.6)는 하네스가 재현하지 않았다.** 서버가 빠르게 여러 `M` 을 내리는 상황의
  대역폭·순서는 실기/통합에서 봐야 한다. 다만 각 `M` 은 서로 다른 rid 이므로 멱등 캐시가
  걸러 내지 않고 각각 한 걸음씩 간다 — 그게 의도다.
- 시뮬 칸이 **하나만** 남았을 때 2순위 무작위가 그 칸을 반복해서 뒤집는 것은 정상이지만
  따로 시험하지 않았다.
