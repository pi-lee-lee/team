# REQ-0050 · 명세 §12B.2 에 한 줄: 오버라이드 중인 칸은 시뮬 후보에서 제외한다

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

## 승인 — arduino-engineer 의 판단을 명세에 반영한다

구현 중에 명세에 없는 조건을 하나 넣었고, **근거가 맞다.** 문장으로 남겨야 한다.

> **지금 오버라이드가 먹고 있는 칸(`testArmed && ovrActive`)은 시뮬 후보에서 제외한다.**

### 근거 (그대로 적어라)

그 칸을 고르면 `simOcc` 는 바뀌는데 **보고되는 `occupied` 는 오버라이드에 가려 안 바뀐다.**
그러면 ACK 는 "그 칸이 바뀌었다"고 말하는데 화면은 그대로다 — **§12B.2 가 지키려는
"눌렀다 → 저 칸이 바뀌었다" 1:1 대응이 정확히 깨진다.**

부수 효과도 적어라: 후보에서 빼면 **후보의 `simOcc` 가 곧 보고되는 `occupied`** 이므로
1순위 판정("예약된 빈 칸")에서 "어느 occupied 를 보느냐"는 모호함이 사라진다.

**전 시뮬 칸이 오버라이드 중이면 관측 가능한 변화가 없으므로 `result=5`** 다.
이건 네가 `result=5` 를 만든 취지(성공과 무동작을 구분한다)와 정확히 같은 성질이다.

### 왜 이게 명세에 있어야 하는가

서버·웹이 기댈 수 있는 성질이 된다 — **ACK 의 `slot` 은 항상 화면에서 보이는 변화에 대응한다.**
안 적으면 다음 구현자가 후보에서 빼지 않고, 그러면 "버튼을 눌렀는데 ACK 는 성공인데 화면은 그대로"가
된다. 이 프로젝트에서 반복해서 잡아온 모양이다.

§13 개정 이력에도 넣어라 — 구현 중에 발견된 보완이라는 사실이 남을 값어치가 있다.

`server.cpp`·`fake_arduino.py` 에 변경이 필요한지도 확인해라. 후보 선택은 아두이노가 하지만
`fake_arduino.py` 도 같은 규칙을 따라야 통합 시험이 실물을 대변한다.

**명령을 엮지 마라(a && b).** 하나씩 실행한다.

## 왜 필요한가

구현이 명세보다 앞서 있다. 적지 않으면 다음 구현자가 오버라이드 칸을 후보에 넣어 "ACK 는 성공인데 화면은 그대로"가 된다. 그리고 fake_arduino 가 같은 규칙을 안 따르면 통합 시험이 실물과 다른 것을 검증한다.

1) §12B.2 에 규칙과 근거(1:1 대응이 깨진다)가 들어간다
2) 전 시뮬 칸이 오버라이드 중일 때 result=5 라는 점이 명시된다
3) §13 개정 이력에 기록
4) fake_arduino.py 가 같은 규칙을 따르는지 확인하고, 안 따르면 맞춘다 (맞췄으면 로그로 보여라)

### 완료 기준

| # | 항목 | 결과 |

`server.cpp` 는 **변경 불필요**하다 — 후보 선택은 전적으로 장치가 하고,
서버는 ACK 의 `slot`/`result` 를 중계할 뿐이다. `result=5` 경로는 이미 구현·검증돼 있다.

### 결함이 실재했음을 먼저 보였다 (옛 규칙 재현)

`A3` 만 시뮬 칸으로 두고 `A3` 에 주입을 건 상태에서, **개정 6 이전 후보 조건**을 그대로 돌렸다:

```
옛 후보: ['A3']
A3 시뮬값 뒤집음 → 내부 occupied[A3]=1
그런데 보고되는 occupied: 0010000000 → 0010000000
ACK 는 (A3, result=0) 을 돌려줬을 것이다

*** 옛 규칙의 결과: ACK 성공 · 화면 변화 없음 → True
```

**ACK 는 성공, 화면은 그대로.** 지적한 그대로다.

### 고친 뒤 — 3가지 경우 실증

```
1) 오버라이드 칸만 남았을 때
   sim_step → slot=?? result=5
   보고되는 occupied 변화: False
   => 무동작을 성공으로 보고하지 않는다: True

2) 오버라이드 안 걸린 시뮬 칸이 있을 때 (A3 주입, A4 는 자유)
   sim_step → slot=A4 result=0
   => A3(주입됨)를 안 고른다: True
   => 보고 값이 실제로 바뀐다: True

3) 무장 해제 상태
   sim_step → slot=A3 result=0        (평소대로 동작)
```

### ⚠ 검증 방식을 바꿔야 했다 — 공용 포트가 오염돼 있었다

처음엔 평소처럼 서버 + 가짜 아두이노 + WS 로 재현하려 했는데 **결과가 이상했다.**
후보가 `A3` 뿐인데 ACK 가 `A1` 을 돌려주고, 내가 보낸 적 없는 예약
`R,17,A1,u9kf94qe` 가 아두이노 로그에 찍혔다.

원인을 확인했다 — **다른 에이전트의 검증 하네스가 같은 포트에서 돌고 있었다:**

```
90368  python3 net/fake_arduino.py --start-empty --seed 11     ← 내 것이 아니다
90402  Google Chrome (CDP 하네스)
90155  ./server                                                 ← 내 인스턴스를 그쪽이 쓰고 있었다
```

가짜 아두이노 둘이 9991 을 두고 다투면서 서로의 연결을 끊고 있었다
(서버는 새 아두이노가 붙으면 옛 연결을 닫는다 — §7.4 설계대로다).

**그래서 오염된 실행 결과로 결론을 내지 않았다.** 대신 이 규칙이 **전적으로 후보 선택
로직 안에 있다**는 점을 이용해 `handle_simstep()` 을 **직접 호출하는 인프로세스 검증**으로 바꿨다.
포트를 전혀 쓰지 않으므로 오염되지 않고, 난수 시드를 고정해 **결정적**이다.

**내 가짜 아두이노는 즉시 내렸다** — 남의 진행 중인 CDP 검증을 방해하고 있었기 때문이다.
서버(90155)는 그쪽이 쓰고 있어서 **일부러 살려 뒀다.**

> 이건 이 작업의 결함이 아니라 **운영 조건**이다. 세 도메인이 동시에 같은 고정 포트
> (9991·9900·5500)에서 검증하면 서로의 결과를 오염시킨다. 루트가 알아야 할 사항이라 보고한다.
> 지금은 인프로세스 검증으로 피했지만, 통합 검증처럼 **포트를 꼭 써야 하는 시험**은
> 동시에 돌면 결과를 믿을 수 없다.

### 미검증

- **소켓을 통한 왕복으로는 이번 규칙을 확인하지 않았다.** 위 이유로 인프로세스 검증만 했다.
  후보 선택은 장치 내부 로직이라 이 방식으로 충분하다고 판단했지만, **전선을 탄 확인은 아니다.**
- 빌드·`--selftest` 는 `server.cpp` 변경이 없어 다시 돌리지 않았다(직전 REQ-0046 에서 22/22 통과).
- **실기 `client.ino` 쪽 반영은 arduino-engineer 몫**이고 내가 확인할 수 없다.
- Windows 빌드 여전히 불가.
