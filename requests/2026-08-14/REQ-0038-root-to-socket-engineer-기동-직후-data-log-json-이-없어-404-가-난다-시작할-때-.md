# REQ-0038 · 기동 직후 data_log.json 이 없어 404 가 난다 — 시작할 때 빈 배열로 만들어라

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

## 재현 (루트가 실측)

`data_log.json` 이 없는 디렉터리에서 서버를 띄우고 브라우저로 접속했다:

```
GET /               → 200
GET /data_log.json  → 404
```

화면에 빨간 오류가 뜬다: **"예비 경로(data_log.json)도 읽지 못했습니다: HTTP 404"**

**WebSocket 은 정상이다** — 같은 화면에 "WebSocket 연결됨"이 떠 있고 스냅샷도 온다.
즉 **아무 문제 없는 첫 실행에서 오류처럼 보이는 것**이고, 사용자는 이걸 "소켓 접속 오류"로 읽었다.

## 원인

- 서버는 §9.4 대로 **상태가 바뀔 때만** 파일을 쓴다. 아두이노가 안 붙었으면 **한 번도 안 쓴다.**
- 화면은 WS 가 붙기 전부터 폴백 폴링을 돌린다(설계상 의도 — 연결될 때까지 화면을 채우려고).

둘 다 각자는 맞는데 **기동 직후 구간에서 만나면 없는 파일을 읽는다.**

## 고칠 것

**기동 시 `data_log.json` 이 없으면 빈 배열 `[]` 로 만들어라.**

- `[]` 는 §9.1 형태(최신이 앞인 배열)에서 **"아직 기록이 없다"** 를 정직하게 표현한다.
  없는 파일보다 낫고, 지어낸 값을 넣는 것보다도 낫다.
- 기존 경로(임시파일 + 원자적 교체)를 그대로 쓴다. 별도 경로를 만들지 마라.
- **이미 파일이 있으면 덮지 마라** — 서버 재시작 때 직전 2건이 날아간다.

README 가 "서버를 돌린 폴더에 json 파일이 생긴다"고 약속하므로, 파일이 실제로 생기는 쪽이
문서와도 맞는다. 브라우저 말고 다른 것이 그 파일을 읽어도 유효한 JSON 을 본다.

> 참고: web-engineer 에게도 요청을 냈다 — **WS 가 살아 있는 동안의 폴백 404 를 빨간 오류로
> 띄우지 않는 것**이다. 네 쪽 수정이 들어가도 옛 서버나 파일 삭제 상황이 남으므로 둘 다 한다.

## 검증

- 빈 디렉터리에서 기동 → 즉시 `GET /data_log.json` 이 **200 이고 본문이 `[]`**
- 아두이노가 붙어 상태가 오면 정상적으로 2건 유지로 넘어간다
- **서버를 재시작해도 직전 기록이 남아 있다**(덮어쓰지 않는다)
- 기존 검증 회귀 없음

**명령을 엮지 마라(a && b).** 하나씩 실행한다.

## 왜 필요한가

문제 없는 첫 실행에서 빨간 오류가 뜬다. 이런 것이 쌓이면 진짜 오류가 떠도 사용자가 무시하게 된다. 그리고 README 는 파일이 생긴다고 약속하는데 실제로는 아두이노가 붙어야 생긴다.

## 대상 파일

- `조별과제샘플/server.cpp`
## 완료 기준

1) 빈 디렉터리 기동 직후 GET /data_log.json 이 200 · 본문 []
2) 기존 파일이 있으면 덮어쓰지 않는다 (재시작 후 직전 기록 유지 확인)
3) 아두이노 접속 후 정상적으로 최신 2건 유지로 전환
4) 원자적 교체 경로를 재사용했다 (별도 쓰기 경로를 만들지 않았다)
5) 빌드 경고 0 + --selftest + 기존 검증 회귀 없음

### ① 빈 디렉터리에서 기동 — `/tmp/pk-empty-test` (진짜 빈 디렉터리)

```
$ ls -la /tmp/pk-empty-test        → 비어 있음
$ cd /tmp/pk-empty-test; server
14:24:31  = data_log.json 이 없어 빈 배열로 만들었다

GET /data_log.json → 200 application/json; charset=utf-8
본문: b'[]\n'
유효 JSON: []
```

**404 가 사라졌다.** 화면의 빨간 오류가 나던 조건 그대로다.

### ② 기존 파일을 덮지 않는다 — 서버만 재시작

파일을 만든 뒤 내용을 떠 놓고, **서버를 껐다 켜서** 바이트로 비교했다:

```
재시작 전 파일: 2 건 · 최신 seq = 16 · ts = 1786685095670
재시작 후 파일: 2 건 · 최신 seq = 16 · ts = 1786685095670
내용 동일: True
14:25:08  = data_log.json 이 이미 있다 — 그대로 둔다(직전 기록 보존)
```

두 경로가 **서로 다른 로그**를 남기므로 어느 쪽으로 갔는지 로그만 봐도 안다.

### ③ 아두이노 접속 후 정상 전환

```
아두이노 접속 후 → 2 건 · 2건 이하: True · 최신 seq = 12
```

`[]` → 1건 → 2건 유지로 자연스럽게 넘어간다. `[]` 는 §9.1 형태(최신이 앞인 배열)를
그대로 만족하므로 읽는 쪽에 특별 처리가 필요 없다.

### ④ 쓰기 경로는 여전히 하나다

기존 `write_log_if_changed()` 안에 있던 tmp+원자적 교체 부분을 **`atomic_write_log()` 로 빼서
두 곳이 같이 쓰도록** 했다. 기동 초기화도 이 함수를 부른다 — 별도 쓰기 경로를 만들지 않았고,
윈도우 `MoveFileEx` 분기와 실패 로그도 그대로 공유한다.

### ⑤ 회귀

```
한글 번호판 예약 → ack result=0 · A3 res=1 user_id=980가4568
테스트 모드 무장 → armed = True
/ → 200 · data_log 2건 · test_mode 키 있음
빌드 -Wall -Wextra 0경고 · --selftest 18/18
```

> 회귀 시험을 처음엔 `B3` 로 했다가 `result=1`(이미 점유)을 받았다. **회귀가 아니라**
> 가짜 아두이노의 무작위 센서 변화로 그 칸이 차 있었던 것이다 — 서버 로그의
> `←ARD A,1,B3,1,30` 으로 확인하고, 스냅샷에서 빈자리를 골라 다시 했다.
> **실패를 봤을 때 코드부터 의심하지 않고 로그로 원인을 확인한 것**이 맞았다.

### 미검증

- **Windows 빌드 여전히 불가.** 이번 변경은 기존 원자적 교체 경로를 그대로 타므로
  윈도우 쪽 위험은 새로 늘지 않았지만, 확인은 못 했다.
- 실제 브라우저로 "빨간 오류가 사라졌는지"는 보지 않았다 — **HTTP 응답이 200 `[]` 인 것까지**
  확인했다. 화면 쪽은 web-engineer 요청(폴백 404 를 오류로 띄우지 않기)과 함께 봐야 한다.
