# REQ-0031 · 테스트 모드 UI: 토글 버튼 + 칸별 센서값 주입 + 무장 중 놓칠 수 없는 표시

**요청자** `root` → **담당** `web-engineer`

## 요청 내용

## 명세가 얼렸다 — `docs/net/parking-protocol.md` v1.2 (§5, §12A)

사용자 요구를 그대로 옮긴다:

> 아두이노에 센서가 아직 없다. html 에 테스트 토글 버튼을 만들고, 활성화되면 테스트 모드다.
> html 에서 빈자리·주차 같은 값을 고르면 아두이노가 서버를 통해 전달받아 그 값으로 설정하고,
> 이후 그 값으로 리턴한다. 아키텍처적으로는 완전히 반전 구조지만 테스트를 위한 것이다.

## 할 것

1. **테스트 모드 토글** — 누르면 무장/해제 요청을 서버로 보낸다.
2. **무장 중 칸별 주입 UI** — 각 칸을 빈자리(0)/주차(1)로 설정, 그리고 **오버라이드 해제**(그 칸만
   원래 센서로 복귀). 셋이다.
3. **무장 중 표시 — 이게 이 작업에서 가장 중요하다** (아래).

## ⚠ 세 가지를 반드시 지켜라

### ① 토글을 눌렀다고 무장됐다고 단정하지 마라

**무장 여부의 진실은 스냅샷의 `test_mode`** 이고, 그 출처는 아두이노가 매 프레임 보내는 `tmask` 다
(§12A.4). ACK 가 유실돼도 다음 프레임에서 저절로 맞춰진다. 네가 로컬 상태로 들고 있으면
**해제했는데 화면만 해제된 것처럼 보이고 값은 계속 가짜인** 상태가 생긴다 — 그게 이 설계가
막으려는 사고 자체다. 예약의 낙관적 UI 와는 성격이 다르다.

### ② 주입 대상은 `occupied` 뿐이다

`reserved` 를 직접 주입하는 UI 를 만들지 마라. §1.1 의 직교 구조상 센서가 정하는 것은 점유 여부고
예약은 서버·사용자의 것이다. 예약 상태는 지금도 정상 예약 경로로 만들 수 있다.

### ③ 무장 중에는 놓칠 수 없게 표시해라

반전 구조의 전형적 사고는 **테스트 모드를 켠 채 시연하고 가짜 값을 실측으로 보고하는 것**이다.
작은 배지로는 부족하다. `device.online=false` 때 "실시간인 척하면 안 된다"고 정한 것과 같은 기준이다.

- 화면 전체에서 즉시 보이는 지속적 표시(배너 등)
- **칸별로도** 그 값이 주입된 값인지 구분되어야 한다 (스냅샷이 칸별 오버라이드 여부를 준다)
- 모양은 네가 정해라. 다만 "무장 중인데 평소와 비슷해 보이는" 상태가 있으면 안 된다

## 참고 — 사용자가 본 증상은 이 기능으로 고쳐지지 않는다

"모든 자리가 센서 연결 안 됨"은 `device.online === false`(`index.html:661`)이고 원인은
**아두이노 미연결**이다. 테스트 모드는 *아두이노는 있고 센서만 없는* 상황을 위한 것이라,
아두이노(또는 `net/fake_arduino.py`) 없이는 그 화면이 그대로다. 이 점을 UI 문구로도 구분해
주면 좋겠다 — "센서 끊김(장치 미연결)"과 "테스트 모드"는 다른 상태다.

## 검증

socket-engineer 가 `net/fake_arduino.py` 에 `T` 를 구현한다. 그게 서면 실제로 붙여서
**토글 → 주입 → 다음 스냅샷에서 타일 변화**를 확인해라. 아직 없으면 §5 예제로 렌더링만 먼저 확인하고
그 사실을 명시해라. 루트가 나중에 CDP 하네스로 전 구간을 다시 확인한다.

**명령을 엮지 마라(a && b).** 하나씩 실행한다.

## 왜 필요한가

사용자가 요구한 테스트 모드의 진입점이 화면이다. 그리고 이 반전 구조의 가장 큰 위험은 기능이 안 되는 것이 아니라, 켜 둔 줄 모르고 가짜 값을 진짜로 읽는 것이다 — 그래서 표시가 기능만큼 중요하다.

## 대상 파일

- `조별과제샘플/index.html`
## 완료 기준

1) 테스트 모드 토글이 있고 무장/해제 요청을 보낸다
2) 무장 상태를 로컬이 아니라 스냅샷 test_mode 로 판단한다 (코드에 근거 주석)
3) 무장 중 칸별로 빈자리/주차/오버라이드 해제를 지정할 수 있다
4) reserved 를 직접 주입하는 UI 가 없다
5) 무장 중 놓칠 수 없는 전역 표시 + 칸별 주입 여부 표시 — 스크린샷으로 보여라
6) 해제하면 전역·칸별 표시가 사라진다
7) 단일 파일 유지, 외부 CDN·빌드 도구 없음
8) 기존 기능 회귀 없음 (예약·취소·폴백·센서 끊김 표시)
브라우저에서 실제로 확인한 것과 코드 검토만 한 것을 갈라서 적어라.

### ① 무장 여부는 스냅샷만 본다 — 이걸 어떻게 증명했나

판단 지점을 **함수 하나**로 좁혔다. 화면 어디에서도 토글의 눌림 상태나 ACK 를 읽지 않는다.

```js
/** 무장 여부의 유일한 판단 지점. 스냅샷만 본다 — 토글 상태도 ACK 도 보지 않는다(§12A.4). */
function isArmed() {
  return !!(state.snapshot && state.snapshot.test_mode.armed === true);
}
```

토글의 `aria-pressed` 와 라벨도 이 함수를 따라간다. **누른 사실을 표시하는 버튼이 아니라 장치 상태를
표시하는 버튼**이다. 예약의 `pending` 과 달리 테스트 요청은 `state.testPending` 에만 들어가고,
거기 담기는 것은 "보냈다"는 사실뿐이라 화면 상태를 만들지 않는다(안내 문구만 바꾼다).

**증명 방법**: 데모 전송기에 `다음 무장 → ACK 만 성공(tmask 미반영)` 버튼을 넣었다.
`test_arm` 에 `result=0` ACK 를 돌려주면서 스냅샷의 `armed` 는 `false` 로 유지한다.
브라우저에서 눌러 본 결과 — 알림에는 "테스트 모드 켜기 — 적용되었습니다"가 뜨지만
**화면은 계속 "해제됨"이고 배너도 테두리도 나타나지 않았다.** ACK 를 믿었다면 여기서 무장으로 보였을 것이다.
이게 이 요청에서 가장 중요한 한 장이라 별도로 찍었다.

### ⑤ 무장 중 표시 — 세 겹으로 건다

배지 하나로는 부족하다는 요구(§12A.6)라 **동시에 세 곳**이 바뀐다:

1. **화면 전체 테두리** — 뷰포트 가장자리에 빨강/검정 45° 위험 빗금 띠(`position: fixed`,
   `pointer-events: none`). 스크롤 위치와 무관하게 항상 보이고, 격자만 보고 있어도 시야에 들어온다.
2. **전역 배너** — "⚠ 테스트 모드 무장됨 — 지금 보이는 점유 상태는 진짜가 아닐 수 있습니다" +
   "주입된 칸 N개 · 빗금 친 칸이 주입값입니다. **이 화면의 값을 실측으로 보고하지 마세요.**"
3. **칸별** — 주입된 칸은 빨간 빗금 배경 + 파선 테두리 + `⚑ 주입값` 칩. 4조합 색을 덮지 않고
   **겹친다**(내 예약의 보라 링과 같은 직교 축 방식). 범례에도 한 줄 추가했다.

해제하면 셋 다 사라진다 — 확인했다.

### 브라우저에서 실제로 확인한 것 (Google Chrome 151.0.7922.109 headless, 스크린샷 판독)

`net/fake_arduino.py` 의 `T` 구현이 아직 없어 **실서버 없이** 데모 전송기로 확인했다.
데모 전송기는 §5.4 의 4개 메시지를 받아 §12A 규칙대로 동작하고, ACK 와 스냅샷을 **분리해서** 보낸다.

1. **거짓 ACK 시험** — 위 ①. ACK 성공 + `tmask` 미반영 → 화면은 해제 상태 유지. **§12A.4 준수 확인.**
2. **무장** — 테두리·배너·토글(빨강, "테스트 모드 끄기")·"무장됨 · 주입된 칸 0개" 동시 전환.
3. **주입 3칸** — A1=주차, B3=주차, A2=빈자리 주입. 세 칸에 빗금+⚑주입값, 해당 버튼이 눌린 상태로,
   배너 카운트가 3개로. 나머지 칸은 평소 모습 그대로 — 진짜와 가짜가 한 화면에서 구분된다.
4. **칸 하나만 해제(`test_clear`)** — A1 이 원래 값(빈 자리)으로 돌아가고 빗금·칩 사라짐,
   카운트 1→0. **무장은 유지**(테두리·배너 그대로) — 칸 해제와 전체 해제가 다른 동작임을 확인.
5. **전체 해제(`test_disarm`)** — 모든 주입이 한 번에 사라지고 전 칸이 원래 값으로. 표시 3종 모두 소멸(§12A.2).
6. **무장하지 않은 채 주입(`result=4`)** — "A1 · 센서값 주입 — 테스트 모드가 무장되어 있지 않습니다"
   빨간 알림, 화면 변화 없음. 조용히 무시하지 않는다.
7. **폴백 중 무장 여부 불명** — 아래 별도 절.
8. **회귀** — 이번 편집 뒤에 다시 렌더해 확인한 것: 예약(요청됨 → 확정 → 입차 완료 · 내 예약),
   **취소**(예약 → 취소 → 빈 자리 복귀), 파일 폴백(예약 불가 표시), **센서 끊김 배너**.
   무장 관련 UI 는 해제 상태에서 흔적 없이 사라진다.
8-1. **무장 + 장치 끊김 동시 발생** — 실장치가 무장 중 끊기면 바로 나오는 조합이라 따로 찍었다.
   두 배너가 함께 뜨고(센서 끊김 / 테스트 모드), 주입된 칸은 빗금과 ⚑주입값을 유지하며,
   빈자리는 "센서 끊김 — 예약 불가"가 된다. §12A.7 에 맞춰 새로 쓴 긴 문구가 한 줄에 정상 렌더되는 것도
   이때 확인했다 — 이 문장은 이번에 새로 넣은 것이라 코드만 봐서는 넘침 여부를 알 수 없었다.
9. **키보드** — 해제 상태에서 탭 가능한 주입 버튼 **0개**(숨은 탭 스톱 없음), 무장 상태에서 **30개**
   (10칸 × 3), `A1 주차` 버튼에 `focus()` 성공, 토글 `aria-pressed=true`. 각 버튼 그룹에
   `role="group"` + `aria-label="A1 센서값 주입"`.
10. **라이트/다크 테마** 양쪽에서 무장 상태 렌더 확인.

### 확인하지 **못한** 것

- **실제 아두이노·서버와의 전 구간**(`T` 전선 프레임, `tmask` 왕복). `net/fake_arduino.py` 의 `T`
  구현을 기다린다. 내가 확인한 것은 **§5.4 JSON 계약까지**이고, 그 아래(전선·펌웨어)는 코드 검토도 하지 않았다 — 내 영역이 아니다.
- `override_count` 를 서버가 보내는 값과 내가 세는 값이 어긋나는 경우. 지금은 서버 값이 있으면 그걸 쓰고,
  없으면 `overridden` 을 세어 채운다.

### 폴백에는 무장 여부가 없다 — 막을 수 있는 데까지만 막고 나머지는 요청으로 올렸다

**§9.1 `data_log.json` 형태에는 `test_mode` 도 `overridden` 도 없다.** 그래서 폴백 중에는
무장 여부를 알 방법이 원리적으로 없다. `false` 로 단정하면 "가짜 값을 경고 없이 보여주는" 쪽으로
틀리므로 그렇게 하지 않았다:

- 정규화 단계에서 폴백이면 `armed = null`(모름)로 둔다. `false` 가 아니다.
- WS 로 **마지막에 확인한** 무장 상태를 따로 기억해 두고, 그게 `true` 였다면 폴백 중에도
  "⚠ 테스트 모드가 켜져 있었습니다 — 지금은 확인할 수 없습니다 / 값이 주입값일 수 있습니다" 배너를 유지한다.
- 테스트 패널은 "알 수 없음 (파일 폴백에는 무장 여부가 없습니다)"로 표시한다.

**닫지 못한 구멍**: 폴백 상태에서 **페이지를 새로 연** 브라우저는 마지막으로 알던 값이 없어
아무 경고 없이 주입값을 그린다. 웹에서 해결할 수 없어 **REQ-0033 으로 루트에 올렸다**
(§9.1 에 `armed` 최소 한 필드를 추가하자는 제안). 판정이 나면 따르겠다.

### 그 밖에 판단한 것

  유지해야 하기 때문이다. 무장 중에만 `display` 로 나타나므로 해제 상태에서는 탭 순서에도 없다.

  `rollback()` 만 부르는데 그건 `state.pending`(예약)만 본다. 테스트 rid 는 `state.testPending` 에
  있어서 항목이 남고, 6초 뒤 자체 타임아웃이 같은 실패를 **두 번째로** 알렸다.
  이제 테스트 rid 면 `clearTestPending()` 으로 한 번만 알린다. 도달 경로는 좁고
  (`link==='ws'` 인데 소켓이 닫히는 중), 무장 상태를 거짓으로 만들지는 않았다.
- **작업 중 CSS 버그를 하나 잡았다**: `.banner--test { display: flex }` 가 `[hidden]` 속성을 이겨
  해제 상태에서 **빈 빨간 막대**가 남았다(UA 의 `[hidden]{display:none}` 은 작성자 스타일보다 약하다).
  첫 스크린샷에서 발견해 `[hidden] { display: none !important; }` 로 막았다.
