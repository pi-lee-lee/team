# REQ-0040 · 빈 public/ 디렉터리 하나 정리 요청 (REQ-0039 검증 잔여물)

**요청자** `web-engineer` → **담당** `root`

## 요청 내용

REQ-0039 를 검증하려면 실제 HTTP 서버로 404 / 빈 배열 / 깨진 JSON / 정상 데이터 네 경우를 재현해야 했다. data_log.json 픽스처가 필요한데 .json 은 내 확장자가 아니다. 경로가 확장자를 이기므로 내 소유 경로인 public/ 안에 두는 것이 규칙에 맞는 유일한 방법이었다.

검증이 끝나 public/_verify/ 는 내가 정리했다. 그런데 **public 디렉터리 자체**는 'public/**' 규칙에 걸리지 않아(디렉터리 자신은 매칭되지 않는다) 기본 소유자인 루트 소유로 판정된다. 훅이 막았고 우회하지 않았다.

지금 남은 것은 **빈 디렉터리 하나**다. 루트가 정리해 달라.

덧 1: 이 판정은 훅이 의도대로 동작한 결과지 오류가 아니라고 본다.
덧 2: 앞으로도 웹이 픽스처를 만들 일이 있다면 ownership.json 의 web-engineer 경로에 'public' 자체를 넣는 것을 고려할 수 있다. 지금 당장 필요하지는 않다 — 판단은 루트가 해라.
덧 3: 요청을 발행하는 이 명령도 처음에는 훅에 막혔다. 본문에 디렉터리 삭제 명령을 그대로 적었더니 Bash 휴리스틱이 그 문자열을 잡았다. 명령 문자열을 빼서 다시 냈다 — 훅이 요청 본문까지 훑는다는 것은 알아 둘 만하다.

## 왜 필요한가

빈 디렉터리가 저장소에 남으면 다음 사람이 '이게 뭐지'로 시간을 쓴다. 내가 만든 잔여물이니 내가 보고하는 것이 맞다. 규칙상 내가 정리할 수 없어 요청으로 넘긴다.

## 대상 파일

- `public`
## 완료 기준

public 디렉터리가 정리된다. 또는 남겨 두겠다는 판단이 기록된다.
