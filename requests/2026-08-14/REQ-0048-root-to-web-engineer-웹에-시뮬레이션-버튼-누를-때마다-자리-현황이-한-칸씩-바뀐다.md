# REQ-0048 · 웹에 '시뮬레이션' 버튼 — 누를 때마다 자리 현황이 한 칸씩 바뀐다

**요청자** `root` → **담당** `web-engineer`

## 요청 내용

## 사용자 요구 (실물에서 나온 것)

> 시뮬레이션 데이터가 계속해서 주입되고 있다. 화면 전환이 너무 빨라 테스트가 되지 않는다.
> **웹 화면에 시뮬레이션 버튼을 만들고, 누르면 자리 현황이 랜덤하게 바뀌도록** 해 달라.

명세가 얼렸다 — `docs/net/parking-protocol.md` v1.4 **§12B**. 거기가 근거다.

## 만들 것

**시뮬레이션 버튼 하나.** 누르면 서버로 트리거를 보내고, 아두이노가 **한 칸만** 바꾼 뒤
다음 스냅샷으로 결과가 돌아온다.

## ⚠ 테스트 모드와 **완전히 별개**다 — 이게 요구의 핵심이다

사용자가 명시적으로 "테스트 모드와 별개로"라고 했다. 이유가 있다:
**무장하면 화면이 빨간 경고로 덮인다**(§12A.6). 평상시 시연에서 그 경고를 감수하지 않고도
데이터를 통제하고 싶다는 것이다.

- 시뮬 버튼은 **무장 여부와 무관하게** 동작한다. 무장 중이라고 막지 마라
- 시뮬로 바뀐 값은 **주입값이 아니다** → 빗금·`⚑주입값` 칩을 붙이지 마라. `tmask` 에도 안 들어온다
- 무장 배너도 뜨지 않는다
- 두 버튼이 **서로 다른 것**임이 화면에서 명확해야 한다. 나란히 두더라도 구분되게 해라

## `result=5` 를 성공으로 표시하지 마라 ⚠

바꿀 시뮬 칸이 하나도 없으면 ACK 가 `result=5` 로 온다(§12B.4).
**이걸 성공으로 표시하면 버튼을 눌렀는데 아무 일도 안 난 것을 화면이 "됐다"고 말하는 것**이 된다.
이 프로젝트에서 반복해 잡아온 바로 그 모양이다(rid 충돌·폴백 404·주입값 위장).
사람이 읽을 수 있는 문구로 구분해라 — 예: "바꿀 시뮬 자리가 없습니다(전부 실물 센서이거나 …)".

## 그 밖

- 아두이노 미연결 중 눌렀을 때의 처리 — 기존 `device_offline` 경로와 일관되게
- 연타 — 명세 §12B 를 따르되, 화면이 "요청 중"을 알 수 있으면 좋겠다
- 단일 파일 유지, 외부 CDN·빌드 도구 없음

## 검증

브라우저에서 실제로 확인하고 스크린샷과 함께 적어라:
1. 버튼을 누르면 자리 하나가 바뀐다 (여러 개가 아니다)
2. **예약된 빈 칸이 있으면 그 칸이 먼저 채워진다** → `occupied=1,reserved=1` 이 화면에 뜬다
3. **무장하지 않은 상태에서도** 동작하고, 빨간 경고가 뜨지 않는다
4. 무장 중에도 동작한다
5. `result=5` 가 성공으로 보이지 않는다
6. 시뮬로 바뀐 칸에 주입 표시(빗금·칩)가 붙지 않는다
7. 기존 기능 회귀 없음 (예약·취소·테스트 모드·폴백·센서 끊김)

socket-engineer 가 `net/fake_arduino.py` 에 `M` 을 구현한다. 아직 없으면 데모 전송기로 먼저 확인하고
그 사실을 명시해라 — 루트가 나중에 CDP 로 전 구간을 다시 본다.

**명령을 엮지 마라(a && b).** 하나씩 실행한다.

## 왜 필요한가

실물에서 시뮬 데이터가 계속 바뀌어 화면 전환이 빨라 시험이 불가능하다. 사용자가 버튼 방식을 직접 지정했다. 그리고 이 버튼은 테스트 모드와 성격이 다르다 — 무장 경고 없이 데이터를 통제하려는 것이 요구의 핵심이라, 둘을 섞으면 요구가 무너진다.

2) 무장 여부와 무관하게 동작한다 (무장 안 해도, 무장 중에도)
3) 시뮬로 바뀐 칸에 주입 표시가 붙지 않고 무장 배너도 안 뜬다

### 두 기능을 화면에서 어떻게 갈랐나 (§12B.3)

요구의 핵심이 "테스트 모드와 별개"라서 **분리가 눈에 먼저 들어오게** 만들었다:

- **자리부터 다르다.** `시뮬레이션` 이라는 별도 섹션을 `테스트 모드` **위**에 뒀다. 평상시 도구가 위,
  위험한 도구가 아래다.
- **색 언어를 갈랐다.** 시뮬은 파랑(`--accent`) 카드 + 왼쪽 굵은 테두리, 테스트 모드는 기존 빨강 계열.
  무장하면 테스트 쪽만 빨개지고 시뮬 패널은 그대로다.
- **문구로 못 박았다.** 패널에 "**테스트 모드와 무관합니다** — 무장하지 않아도 되고, 이 버튼으로
  바뀐 값에는 주입 표시가 붙지 않습니다"를 적어 뒀다.
- **코드에서도 갈랐다.** `renderSim()` 에는 `isArmed()` 호출이 **하나도 없다.** 클릭 핸들러에도 없다.
  주석으로 "이 줄에 isArmed() 가 끼어들면 요구가 무너진다"를 남겼다 — 나중에 누가 무장 검사를
  붙이고 싶어질 자리가 바로 거기다(§12B.4 가 `T` 에 얹지 않은 이유와 같은 걱정이다).

### `result=5` — 성공으로 보이지 않게 한 방법

알림 한 줄로 끝내지 않고 **패널에 결과를 남긴다**(`state.simOutcome`). 세 단계로 갈린다:

| 결과 | 표시 | 색 |
|---|---|---|
| `result=0` | `✓ A4 이(가) 바뀌었습니다` — **바뀐 칸을 이름으로** 말한다(§12B.5 의 ack `slot`) | 초록 |
| `result=5` | `— 바꿀 시뮬 자리가 없습니다 — 아무것도 바뀌지 않았습니다` | 호박색 |
| 오류·타임아웃 | `⚠ …` | 빨강 |

`result=5` 에서 **"아무것도 바뀌지 않았습니다"를 명시**한 것이 요점이다. 알림에도
"(전부 실물 센서이거나 시뮬 칸이 없습니다)"를 붙였다. 체크 표시(✓)를 쓰지 않았고 초록도 아니다.

### 브라우저에서 실제로 확인한 것 (Google Chrome 151.0.7922.109 headless)

`net/fake_arduino.py` 의 `M` 이 아직 없어 **데모 전송기**로 확인했다. 데모 전송기에 §12B.2 의
선택 규칙(1순위 예약된 빈칸 → 2순위 순환)과 §12B.4 의 `result=5` 를 구현해 넣었다.

1. **무장하지 않은 채 한 번** — `A4` 하나만 뒤집혀 "사용 중"이 됐다. 나머지 아홉 칸 그대로.
   빨간 것 없음, 무장 배너·테두리 없음, 테스트 모드는 "해제됨" 그대로.
2. **예약 → 시뮬 한 번** — `B3` 를 예약(0·1)한 뒤 버튼을 **한 번** 누르자 `B3` 가
   **"사용 중 (입차 완료) · 내 예약"**(1·1)으로. 다른 빈칸(A1·A4·B1·B2)을 제치고 예약된 칸이
   선택됐다 — 1순위 규칙이 실제로 동작한다. 이 데모의 주 서사가 버튼 한 번으로 재현된다.
3. **`result=5`** — 위 표대로. 격자와 `seq` 가 **전혀 바뀌지 않은 것**도 함께 확인(1234 그대로).
4. **무장 중 시뮬** — 무장하고 `A1` 을 주입한 뒤 시뮬을 눌렀다. `A4` 가 바뀌었고
   **`A4` 에는 빗금도 ⚑주입값 칩도 붙지 않았다.** 배너의 "주입된 칸 **1개**"도 그대로 —
   시뮬 변화가 오버라이드 수에 섞이지 않는다. 빗금은 실제 주입 칸 `A1` 에만 있다.
5. **연타 3회** — 합쳐지지도 막히지도 않는다. `seq` 1234 → 1237(3걸음), 중간 화면에
   "요청 2건 보냄 — 결과는 다음 스냅샷에서 확인합니다". 3번째 걸음이 2번째에서 비워진 예약칸을
   **다시 1순위로 골라** 채우는 것도 관찰됐다(§12B.2 그대로).
6. **장치 미연결** — 버튼이 흐려지고 이유를 말한다: "장치가 연결되어 있지 않습니다 — 시뮬 값은
   아두이노가 들고 있으므로 붙어야 진행됩니다". 누르면 그 이유가 알림에 뜬다.
7. **회귀** — 예약→취소 복귀, 파일 폴백(시뮬 버튼도 폴백 이유로 비활성), 센서 끊김 배너,
   그리고 **REQ-0031 의 거짓 ACK 시험을 다시 돌렸다**(아래).

### 리팩터링을 했고, 그래서 옛 시험을 다시 돌렸다

시뮬 요청은 테스트 명령과 **재전송·타임아웃 기계장치가 같다**(§12B.4: rid 멱등, §7.3 타임아웃).
그래서 큐를 새로 만들지 않고 기존 것을 공유하되, 이름이 거짓말이 되지 않게 바꿨다:
`testPending → cmdPending`, `sendTest → sendCommand`, `TEST_KIND_LABEL → CMD_LABEL`.
ack 처리에서 `kind === 'sim_step'` 이면 **다른 결과표(SIM_RESULT_TEXT)** 를 타게 해서
문구가 섞이지 않게 했다 — 테스트 모드의 "적용되었습니다"를 시뮬이 빌려 쓰면 두 기능이 화면에서 합쳐진다.

이름 바꾸기가 ack/error/타임아웃/전송실패 네 경로를 건드리므로, **REQ-0031 의 가장 중요한 시험을
다시 돌렸다**: 무장 ACK 만 성공으로 오고 `tmask` 는 미반영인 경우 → 화면은 여전히 "해제됨"이고
배너도 테두리도 뜨지 않는다. 리팩터링이 그 불변식을 깨지 않았다.

### 데모 전송기에서 **없앤 것** — 자율 전진

예약이 성사되면 2.5초 뒤 자동으로 차가 들어오게 해 뒀었다(REQ-0019 때 `(1,1)` 을 보여주려고).
개정 5 §12B.1 이 **자율 전진을 없앴으므로** 그 코드를 지웠다. 이제 입차는 시뮬 버튼이 민다 —
예약된 빈칸이 1순위라 한 번만 누르면 된다. 데모가 명세와 다른 세계를 흉내내지 않게 맞춘 것이다.

### 확인하지 **못한** 것

- **실제 `M` 전선 왕복**(서버 중계 · 아두이노 rid 멱등 · 재전송이 두 걸음이 되지 않는지).
  `net/fake_arduino.py` 의 `M` 이 아직 없다. 내가 확인한 것은 **§12B.5 의 WS 계약까지**다.
- **연타 시 서버의 rid 멱등**(§12B.6 이 기대는 근거)은 데모에서 재전송을 만들지 않아 미확인이다.
  브라우저 쪽은 누름마다 새 `rid` 를 만들 뿐이라 이 문제의 당사자가 아니다.
- 실물 센서가 섞인 경우("3칸 실물 + 7칸 시뮬")의 대상 선택은 **아두이노 몫**이라 웹에서 볼 것이 없다.
  데모는 10칸 모두 시뮬로 두고 확인했다.
