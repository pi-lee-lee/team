# REQ-0053 · 최우선: 서버가 블로킹 send() 에서 행 — 상대가 안 빼가면 전체가 선다

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

## 실기 증상 (사용자 보고 — 최우선)

> 서버에 **행**이 발생해 동작하지 않는다. **아무런 오류 로그가 없다.**
> 마지막 로그는 아두이노로부터 `+ARD` 를 수신한 것. **종료가 아니라 행이다** —
> 아무 동작도 안 하고 죽지도 않았다.

## 원인 — 루트가 코드로 확인했다

```
logf("+ARD", "아두이노 접속");        ← 마지막 로그
...
resync_reservations("새 연결");       ← 바로 다음 줄. dispatch → send_ard → send_raw
```

`send_raw()` 는 이렇다:

```cpp
while (off < n) {
    int w = ::send(fd, p + off, n - off, 0);
    if (w <= 0) return;
    off += (size_t)w;
}
```

**`SO_SNDTIMEO` 도 논블로킹 설정도 파일 어디에도 없다**(grep 확인). 즉 전부 블로킹 소켓이다.
상대의 TCP 수신 창이 차 있으면 `send()` 는 **무한정 대기**한다. 서버는 단일 스레드라
**그 순간 전체가 선다.** 오류도 종료도 로그도 없다 — 증상과 정확히 일치한다.

방아쇠도 설명된다: 사용자의 아두이노가 꼬인 상태였고(전송 실패 반복), **ESP-01 이 수신 데이터를
빼가지 않으면** 창이 차서 서버의 재하달 `send()` 가 그대로 막힌다.

## ⚠ 아두이노 전용 문제가 아니다

같은 `send_raw()` 를 **WS 클라이언트와 폰 연결에도 쓴다.** 브라우저가 읽기를 멈춰도 같은 일이 난다.
탭을 정지시키거나 네트워크가 끊긴 클라이언트 하나가 **서버 전체를 세울 수 있다.**

## 어떻게 놓쳤는지 (탓이 아니라 재발 방지)

REQ-0021 검토에서 cpp-engineer 가 논블로킹에 대해 이렇게 적었다:

> "**쓰지 않는다.** `select` 로 준비된 fd 에만 `recv` 를 한 번씩 하므로 블로킹 소켓으로 충분하다."

그 판단은 **읽기에 대해서는 맞다.** `select()` 의 읽기 준비는 **쓰기에 대해 아무것도 보장하지 않는다.**
쓰기 쪽이 검토에서 통째로 빠졌다. 명세·검토 어디에도 "상대가 안 빼갈 때"가 없다.

## 고칠 것

### ① 즉시 — 전송에 타임아웃을 건다

**모든 소켓에 `SO_SNDTIMEO` 를 건다.** 그러면 `send()` 가 무한정 막히지 않고 오류로 돌아오며,
`send_raw()` 의 기존 `if (w <= 0) return;` 이 그대로 받는다.

⚠ **플랫폼이 다르다**: 윈도우는 `DWORD` 밀리초, POSIX 는 `struct timeval` 이다. `#ifdef` 로 갈라라.
기존 `setsockopt` 의 `(const char*)` 캐스트 패턴을 따르면 양쪽 다 맞는다.

### ② 타임아웃 = 그 연결을 버린다

**부분 전송 뒤 타임아웃이면 잘린 줄이 전선에 남는다.** 그대로 두면 상대가 깨진 줄을 받는다
(체크섬으로 걸러지긴 하지만 상태가 어긋난다). **타임아웃이 나면 그 연결을 끊어라.**

의미가 분명하다 — **정해진 시간 안에 프레임 하나를 못 밀어 넣으면 상대가 안 빼가는 것**이고,
그때는 붙들고 있을 이유가 없다. 아두이노 쪽은 자기 복구 사다리(CIPCLOSE→CIPSTART→RST)로
다시 붙는다. 브라우저는 재연결한다.

### ③ 타임아웃 값을 지어내지 마라

명세에 근거가 될 숫자가 이미 있다:
- 프레임은 최대 64바이트다(§2.1)
- ACK 대기 1500ms · 재전송 2회(§7.3)
- 오프라인 판정 3.5초(§3.4)

**64바이트를 정상 링크에서 못 밀어 넣는 시간**을 근거로 잡고, **§7.3/§3.4 와 어긋나지 않는지**
확인해라(예: 전송 타임아웃이 오프라인 판정보다 길면 그 사이 서버가 멈춰 있는 셈이다).
계산과 근거를 주석에 남겨라.

### ④ 행이 났다는 사실이 보여야 한다

타임아웃으로 연결을 끊을 때 **어느 상대에게 몇 바이트를 밀다 실패했는지** 로그로 남겨라.
지금은 아무 흔적 없이 서 버려서 원인을 찾을 단서가 0 이었다.

## 더 큰 구조 (지금 하지 마라, 판단만 적어라)

정석은 **논블로킹 + 연결별 출력 버퍼 + `select()` 쓰기 준비 감시**다. ①②는 무한 대기를
유한 실패로 바꾸는 그물이지 근본 구조는 아니다. 지금 그 재작성을 하면 검증된 것들이 흔들리므로
**하지 마라.** 다만 **왜 지금 안 하는지와 나중에 무엇을 해야 하는지**를 처리 결과에 적어라 —
루트가 `docs/parking-status.md` 에 남긴다.

## 검증

macOS 에서 실제로 재현하고 로그를 붙여라:
- **안 빼가는 상대를 만들어** 서버가 서지 않고 타임아웃 후 연결을 끊는지
  (수신만 안 하는 더미 클라이언트를 `net/` 에 만들면 된다 — 접속 후 `recv` 를 안 하고 잠자면 된다)
- 그 상황에서 **다른 클라이언트는 계속 정상 동작**하는지 ← 이게 요점이다
- 아두이노·WS·폰 **세 종류 모두**에 타임아웃이 걸렸는지
- 기존 검증 회귀 없음 (예약 왕복·테스트 모드·시뮬 트리거·번호판)

**명령을 엮지 마라(a && b).** 하나씩 실행한다.

## 왜 필요한가

서버가 아무 로그 없이 정지해 시스템 전체가 멈춘다. 단일 스레드라 상대 하나가 안 빼가면 전부 선다. 아두이노뿐 아니라 브라우저·폰 연결에도 같은 위험이 있어, 탭 하나가 서버를 세울 수 있다. 지금까지 명세·검토 어디에도 "상대가 안 빼갈 때"가 없었다.

2) 타임아웃 시 그 연결을 끊고, 어느 상대에 몇 바이트를 밀다 실패했는지 로그가 남는다
3) 타임아웃 값의 근거가 주석에 있고 §7.3·§3.4 와 어긋나지 않는다

5) 논블로킹+출력버퍼 재작성을 지금 하지 않은 판단과 나중에 할 일을 적어라
6) 기존 검증 회귀 없음 · 빌드 -Wall -Wextra 경고 0 · --selftest 통과

**담당** `socket-engineer` · 완료 — 진단이 맞았다. **내가 만든 버그다.**
`send_raw()` 를 블로킹 루프로 써 놓고 타임아웃을 걸지 않았다. `grep` 으로 직접 확인했다 —
`SO_SNDTIMEO`·`O_NONBLOCK`·`FIONBIO` 어느 것도 파일에 없었다.

### 고친 것

**① `SO_SNDTIMEO` 를 접속된 모든 소켓에** — 아두이노·HTTP/WS·폰 세 `accept()` 전부.
윈도우 `DWORD` 밀리초 / POSIX `struct timeval` 로 `#ifdef` 분기, 기존 `(const char*)` 캐스트 패턴 유지.

**② 실패하면 그 연결을 버린다.** `send_raw()` 가 `bool` 을 돌려주고 호출자가 끊는다.
부분 전송 뒤 실패면 전선에 잘린 줄이 남으므로 붙들 이유가 없다.
- 아두이노 → 소켓 닫고 `ard=BAD_SOCK`, 스냅샷 push(화면에 "센서 끊김")
- WS → **즉시 erase 하지 않고** `dead` 에 표시 후 루프 끝 `reap_dead()` 에서 정리.
  broadcast 순회 중 erase 하면 반복자가 무효화된다 — 예전에 SIGSEGV 를 냈던 그 실수다.

**③ 값의 근거**(주석에 남김): 64B 프레임을 9600bps 에서 밀어내는 데 약 80ms(§3.1) ≪
**1000ms** < ACK 타임아웃 1500ms(§7.3) ≪ 오프라인 판정 3500ms(§3.4).
길면 send() 안에 갇힌 채 재전송 타이머와 오프라인 판정이 제 시각을 놓친다.

**④ 로그**: 어느 상대에게 `밀어넣은/전체` 바이트와 `errno` 를 남긴다.

### ⚠ 검증 중에 내 설계의 결함을 하나 더 찾았다 — `SO_SNDTIMEO` 만으로는 부족하다

메커니즘을 확인하려고 독립 실험을 돌렸더니 **1초 타임아웃인데 1.93초가 걸렸다**:

```
send() 가 1.93초 만에 오류로 돌아왔다: errno=35 (EAGAIN)
   그때까지 밀어넣은 바이트: 327680
```

**`SO_SNDTIMEO` 는 `send()` 한 호출에 걸리는 것이지 `send_raw()` 루프 전체에 걸리는 것이 아니다.**
상대가 조금씩만 빼가면 매 호출이 조금씩 진전해 루프가 계속 돌고, **총 정지 시간은 얼마든지
길어진다.** 원래 주석에 "한 번의 정체로 최대 1초"라고 썼는데 **그 문장이 틀렸다.**

→ `send_raw()` 에 **전체 마감시각**을 따로 뒀다. 소켓 옵션은 한 호출을, 마감시각은 한 프레임 전체를 막는다.

### 검증

**메커니즘 (독립 실험, macOS 실측)** — 위 로그. `SO_SNDTIMEO` 가 무한 대기를 **유한 실패**로
바꾼다는 것, 그리고 그 실패가 `send_raw()` 의 기존 `w <= 0` 분기로 들어온다는 것을 확인했다.

**서버가 서지 않는다 (통합)** — 안 빼가는 WS 클라이언트를 붙여 둔 채 정상 클라이언트를 관찰:

```
     0.0s  스냅샷 #1  online=True
     4.6s  스냅샷 #6  online=True
    10.7s  스냅샷 #12 online=True
    16.7s  스냅샷 #18 online=True
20초 동안 받은 스냅샷: 21
=> 서버가 서지 않았다: True
```

**회귀 (전 기능)**

```
한글 번호판 예약 → res=1 user=980가4568
시뮬 트리거 → ack slot=A1 · A1 occ=1 res=1   (예약된 빈칸 우선 유지)
테스트 모드 무장 → armed=True
/ → 200
폰 → ✓ 예약 없음 → 빈자리 배정 111나2222 → A2
빌드 -Wall -Wextra 0경고 · --selftest 22/22
```

### 미검증 — **실패→로그→절단 분기가 실제로 도는 것은 못 봤다**

정직하게 남긴다. macOS 루프백에서 이 분기를 **밟게 할 수가 없었다.** 시도한 것:

1. 안 읽는 WS 클라이언트(수신 버퍼 512B) — 커널이 흡수, 미발동
2. 72KB 응답을 안 읽는 HTTP 클라이언트 — 미발동
3. 아주 느리게만 읽는 클라이언트(0.5초에 256B) — 미발동
4. **송신 버퍼를 2048B 로 줄이는 임시 빌드 훅** — `SO_SNDBUF` 가 실제로 2048 로 잡혔는데도
   미발동(85,712B 가 그대로 밀려 들어갔다). 루프백이 버퍼 설정과 무관하게 흡수한다.
   **효과가 없는 훅을 코드에 남기면 "이걸로 시험된다"는 거짓이 되므로 제거했다.**
5. RST 로 급단절 — 서버가 **읽기 경로에서 먼저** 감지해 정상 정리했다(그게 옳은 동작이다).

즉 이 환경에서는 send 가 막히지도 실패하지도 않는다. **실기 조건(ESP-01 이 9600bps 로
빼가는 WiFi 링크)에서는 발생한다** — 그게 사용자가 실제로 겪은 상황이다.
분기 자체는 `w <= 0` 하나이고 위 ①에서 그 조건이 실제로 만들어지는 것은 확인했지만,
**서버 안에서 그 줄이 실행되는 것을 본 것은 아니다.**

### 논블로킹 + 출력 버퍼를 지금 하지 않은 판단

**지금 하지 않는다.** 지시대로이고, 나도 같은 판단이다:

- 그 재작성은 `send_ard`/`ws_send`/`serve_file`/HTTP 응답 **모든 송신 경로**와 `select()` 루프를
  건드린다. 지금 그 위에 예약·테스트모드·시뮬트리거·번호판 매칭이 전부 얹혀 검증돼 있다.
- **①②는 무한 대기를 유한 실패로 바꾸는 그물이지 근본 구조가 아니다.** 느린 클라이언트는
  여전히 최대 1초씩 전체를 세우고, 그 사이 다른 클라이언트의 응답이 밀린다.

**나중에 해야 할 일** (루트가 `docs/parking-status.md` 에 남길 내용):
1. 모든 소켓을 논블로킹으로 (`fcntl(O_NONBLOCK)` / `ioctlsocket(FIONBIO)`)
2. **연결별 출력 버퍼**를 두고, 보내다 남으면 버퍼에 쌓아 둔다
3. `select()` 에 **쓰기 집합(write set)** 을 추가해 "쓰기 준비된 fd"에만 이어서 민다
4. 출력 버퍼가 상한을 넘으면 그 연결을 끊는다(느린 클라이언트가 메모리를 먹는 것 방지)

그때 함께 고칠 것: 지금은 **HTTP 응답 하나(72KB)가 한 번의 `send_raw()`** 라
느린 브라우저 하나가 최대 1초를 먹는다. 논블로킹이 되면 그것도 사라진다.

### 남은 것 하나

임시 검증용 바이너리 `조별과제샘플/server_test` 가 남아 있다. **루트 소유 경로라 내가 지울 수
없다**(확장자 없는 새 파일 → 기본 소유자 root). `.gitignore` 에 넣거나 지워 달라.
