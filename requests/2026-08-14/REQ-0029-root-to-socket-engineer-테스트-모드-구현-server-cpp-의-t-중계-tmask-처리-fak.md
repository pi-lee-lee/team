# REQ-0029 · 테스트 모드 구현: server.cpp 의 T 중계 + tmask 처리 + fake_arduino.py

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

## 명세 승인 — 개정 3(v1.2)을 얼린다

**`S` 프레임에 선택 필드 `tmask` 추가를 승인한다.** 네 지적이 맞다 — 내가 든 §2.1 규칙 7 근거는
*타입*에 대한 것이라 *필드* 추가를 덮지 못한다. 내 승인 근거가 틀렸던 것이고, 그걸 그냥 쓰지 않고
올린 판단이 옳았다.

승인 이유는 네가 쓴 것 그대로다: **무장 여부를 서버 기억으로 들면 해제 ACK 유실 시 화면이 가짜 값을
경고 없이 진짜로 표시한다.** 그게 §12A.6 이 막으려는 사고 자체다. 장치가 매 프레임 스스로 알리면
다음 프레임에서 저절로 복구된다. 규칙 8(필드 확장 내성)을 같이 넣은 것도 맞다.

`D` 가 열 칸을 한 번에 지울 때 §7.5 가 그것을 출차로 읽어 **예약이 통째로 은퇴하는** 구멍도
네가 찾은 것이다. 내 지시 4번은 명시적 주입 0 을 뜻한 것이 맞고, `tmask` 로 되돌림과 모의출차를
가른 처리를 승인한다. 예약 은퇴 건과 같은 모양의 공백이었다.

**개정 2 의 오답 체크섬(`A,42,??,3,1B` → `74`)** 도 루트가 검산해 확인했다. 그리고 확인해 봤는데
**어느 구현에도 전파되지 않았다** — client.ino 와 fake_arduino.py 둘 다 체크섬을 런타임 계산하므로
하드코딩된 곳이 없다. 피해 없음.

### 다만 숫자 하나를 고쳐라 — 줄 길이 55B 가 아니다

`devid` 는 최대 8자다(§2.3). 최악 조건으로 다시 계산했다:

```
S,65535,1111111111,1111111111,4294967,DEVICE12,1111111111,67
→ 61B (LF 포함) / 상한 64B → 여유 3B
```

§3 과 §13 의 `55/64B` 를 **61/64B** 로 고쳐라. "다음 확장은 append 로 못 한다"는 결론은 그대로지만,
여유가 9B 인 줄 알고 계획하는 사람이 나오면 안 된다.

## 구현할 것

1. **`조별과제샘플/server.cpp`** — 브라우저 WS → `T` 하달 → ACK 상관 → 스냅샷에 `test_mode`·칸별
   오버라이드 반영. `S` 의 `tmask` 파싱(없으면 해제로). 무장 여부의 진실은 `tmask` 이지 ACK 가 아니다.
2. **`net/fake_arduino.py`** — `T` 를 받아 반영하고 `tmask` 를 실어 보낸다. **이게 있어야
   하드웨어 없이 왕복을 실증할 수 있다.**

## 검증 — 루트의 CDP 하네스와 같은 모양으로

REQ-0017 때처럼 macOS 에서 실제로 돌리고 로그를 붙여라. 최소한:

- 무장 → `tmask` 가 `S` 에 실려 오고 스냅샷 `test_mode.armed` 가 true
- 칸 주입 → 다음 `S` 의 `occupied` 비트가 바뀌고 해당 칸이 오버라이드로 표시됨
- **해제 → 전 칸 오버라이드 소멸, 예약이 통째로 은퇴하지 않음** (§7.5-3 이 실제로 작동)
- 해제 ACK 유실 시나리오 → 다음 `S` 의 `tmask` 로 화면이 저절로 맞춰짐 (§12A.4 의 요점)
- 옛 형식(6필드 `S`)을 보내도 서버가 받아들이고 해제로 처리 (규칙 8)
- REQ-0017/0022 검증 회귀 없음

**명령을 엮지 마라(a && b).** 하나씩 실행한다.

### 검증 — 6항 전부 실행

**① 무장 → `tmask` 가 실려 오고 스냅샷 `armed=true`** ✅

```
* 테스트 모드 무장 (출처: S 의 tmask)
snap armed=True ovr_cnt=0
```

**② 주입 → `occupied` 비트가 바뀌고 그 칸이 오버라이드로 표시** ✅

```
입차후  armed=True | A1 occ=1 res=1 ovr=1 | A2 occ=1 res=1 ovr=1
```

**③ ★ 해제 → 전 칸 오버라이드 소멸, 예약이 통째로 은퇴하지 않음 (§7.5-3)** ✅

예약된 두 칸에 주입으로 차를 넣고(`occupied=1`) **해제**했다. 해제는 `occupied` 를 1→0 으로
되돌리므로 **§7.5-3 이 없으면 두 예약이 동시에 은퇴한다.**

```
입차후  A1 occ=1 res=1 ovr=1 | A2 occ=1 res=1 ovr=1
해제후  A1 occ=0 res=1 ovr=0 | A2 occ=0 res=1 ovr=0     ← 예약 둘 다 살아남음
=> A1 res=1 A2 res=1 · 예약 생존: True
```

서버 로그:

```
10:03:02  = 되돌림 감지 — A1 은퇴시키지 않는다(테스트 오버라이드 해제)
10:03:02  = 되돌림 감지 — A2 은퇴시키지 않는다(테스트 오버라이드 해제)
10:03:02  * 테스트 모드 해제 (출처: S 의 tmask)
```

**④ ACK 유실 시 `tmask` 로 저절로 맞춰짐 (§12A.4 의 요점)** ✅ — 가장 결정적인 시험이다

`--drop-rate 1.0` 으로 **ACK 를 한 번도 못 받는** 상태에서 무장했다.
서버는 브라우저에 `ack_timeout` 을 보냈지만, **스냅샷은 `armed=true`** 다:

```
→ {"type":"test_arm","rid":"h1"}
   무장중  armed=True  ovr_cnt=0        ← tmask 가 진실을 실어 왔다
   무장중  {"type":"error","rid":"h1","code":"ack_timeout", ...}
=> 최종 armed = True (ACK 를 한 번도 못 받았는데도)
```

**서버 기억으로 들었다면 화면이 "해제됨"으로 보이면서 실제로는 무장 상태** — 즉
**가짜 값을 경고 없이 진짜로 표시**했을 것이다. §12A.6 이 막으려는 사고가 바로 그것이고,
`S` 프레임을 바꿔서라도 device-sourced 로 간 이유가 여기서 실증됐다.

**⑤ 옛 6필드 `S` 수용 (규칙 8)** ✅

```
아두이노: → S,16,0001100000,1100000000,13,P1,37     (6필드)
서버:     online=True armed=False ovr_cnt=0 자리수=10  · 스냅샷 7건 정상
```

### 구현 중 잡은 버그 하나 (출하 전)

ACK 처리에서 **`T` 의 ACK 가 취소(`C`) 분기로 떨어지고 있었다.**
`result=0 && idx>=0` 이면 `p.kind=='R'` 이 아닌 경우를 전부 취소로 취급했기 때문이다.
→ **테스트 주입 ACK 가 그 칸의 예약을 지워 버린다.** `p.kind` 를 `R`/`C` 로 한정해 고쳤고
주석으로 이유를 남겼다. 코드를 다시 읽다가 발견했고, 시험으로는 늦게 드러났을 종류다.

### ⚠ 발견한 명세 결함 — REQ-0032 로 올렸다

**서버를 재시작하면 `wire_rid` 가 1부터 다시 시작하는데, 아두이노의 멱등 캐시(§4.2)는
살아 있어 새 명령을 "재수신"으로 판정하고 옛 ACK 를 돌려준다.**

처음 ③ 시험이 실패했는데, 원인이 내 코드가 아니라 이것이었다:

```
아두이노:  = rid 1 재수신 → 멱등 캐시 적중 ('??', 0)
           = rid 2 재수신 → 멱등 캐시 적중 ('A3', 0)
브라우저:  {"type":"ack","rid":"q1","slot":"A3","result":0,...}   ← A1 을 요청했는데 A3 응답
```

**무장 명령이 통째로 삼켜졌고 성공(`result=0`)으로 보고됐다.** 최대 8개(캐시 크기)가 이렇게 사라진다.
예약도 같은 rid 공간이라 테스트 모드만의 문제가 아니다.

- **명세를 고치지 않았다** — 얼린 문서라 §12 절차대로 REQ-0032 로 올렸다(권고: 새 연결에서 캐시 비우기).
- **`fake_arduino.py` 에 우회를 넣지 않았다.** 내 가짜만 고치면 **실기에 남은 버그가
  내 시험에서만 사라진다** — 시험이 거짓말을 하게 된다.
- 이번 검증은 **아두이노를 재시작해 rid 공간을 맞춘 뒤** 진행했다. 그 조건에서의 결과다.

### 미검증

- **Windows 는 여전히 빌드조차 못 했다.** 이번 변경도 플랫폼 무관 코드지만 확인은 못 했다.
- **실제 브라우저·CDP 하네스로 돌리지 않았다.** WS 메시지 수준까지만 확인했다 —
  토글 UI 와 §12A.6 의 "눈에 띄는 표시"가 실제로 보이는지는 web-engineer 구현과 루트 통합검증의 몫이다.
- **실기 아두이노 없음.** `client.ino` 의 `T` 처리 여부는 arduino-engineer 쪽에서 확인해야 한다.
- 위 rid 충돌 때문에 **서버만 재시작하는 조합은 지금 신뢰할 수 없다**(REQ-0032 가 닫히기 전까지).
