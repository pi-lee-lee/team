# REQ-0037 · 번호판 수신·매칭: 폰(digitcam) → 주차 서버 연결. 전선 프로토콜은 안 건드린다

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

## 사용자가 설명한 입차 흐름

> 사용자가 자리를 먼저 선택한다 (안 하면 빈자리). 이후 차단기 앞에 정차 → 카메라 촬영 →
> 번호판 등록 → 차단기 오픈 → 바닥 LED 로 해당 위치까지 가이드.

**이번 범위는 "수신·매칭"까지다** (사용자가 명시적으로 고름). 차단기·LED 액추에이터는
하드웨어가 생길 때 별도로 간다. 아두이노 5대 구성(다중 장치)도 이번이 아니다 — 아래 참조.

## 명세 개정이 필요 없다 — 왜인지 먼저 확인해라

양쪽 전선은 **이미 명세돼 있다**: digitcam 은 `docs/net/digitcam-protocol.md`(5500, JSON),
주차는 `docs/net/parking-protocol.md` v1.3. 없는 것은 그 둘을 잇는 **서버 내부 정책**이다.

**번호판은 전선(9991)에 태우지 않는다.** 아두이노가 하는 일은 "이 칸 예약됨 / 차단기 열어라 /
LED 켜라" 이고 **셋 다 번호판을 필요로 하지 않는다.** 그러니 §2.3 을 고칠 이유가 없다.

## ⚠ 그런데 지금 코드가 한글 번호판을 거절한다 — 루트가 확인했다

`server.cpp:314` 의 `valid_userid()` 가 ASCII·8자 이하만 통과시킨다(REQ-0023 에서 네가 넣은 것이고
전선 규격상 옳다). 그런데 번호판은 이렇다:

```
980가4568 → 8글자지만 UTF-8 로 10바이트, ASCII 아님 → valid_userid() 탈락
```

**즉 두 이름공간을 분리해야 한다** — `rid` 를 브라우저용/전선용으로 나눈 것(§4.1)과 같은 구조다:

| 구간 | 값 | 제약 |
|---|---|---|
| 브라우저 ↔ 서버 (WS JSON) · 서버 내부 저장 | **번호판 전체** | UTF-8, JSON 이므로 자유 |
| 서버 → 아두이노 (전선 `userid`) | 빈 값 또는 짧은 토큰 | ASCII 0*8 (§2.3) |

전선에 번호판을 넣으려다 `valid_userid()` 를 느슨하게 만들지 마라. **그건 REQ-0023 이 막은 버그를
되살리는 것이다.** 전선 쪽은 지금 그대로 두고, 번호판은 서버가 들고 있는다.

## 좋은 소식 — 스냅샷은 안 고쳐도 된다

`slots[].user_id` 가 **v1 부터 자리만 잡아 두고 값이 null 이던 필드**다(§5.3).
번호판이 그 자리에 들어가면 **스키마 변경이 없다.** 웹도 이미 "예약자 u17" 로 렌더한다.
처음부터 "사용자 체계가 생기면 값만 채우면 된다"고 만들어 둔 자리가 이제 채워지는 것이다.

## 만들 것

### 1) 5500 리스너 추가 — `net/test_server.py` 를 들어내 써라

**새로 쓰지 마라.** 그 파일이 digitcam 수신부를 이미 구현했고(스트림 조립, 경계가 줄 중간에서
갈리는 경우까지 자기 헤더에 문서화돼 있다) **소유자도 너다.** 검증된 코드를 옮기는 것이 맞다.

서버는 이제 리스너 셋이다: 9991(아두이노) · 9900(HTTP/WS) · 5500(폰). 같은 `select()` 루프에.

### 2) 매칭 정책

**키는 번호판이다.** 예약의 `user_id` 에 번호판이 들어 있으면 그것으로 찾는다.

- **예약 있음** → 그 예약의 자리로 확정. 안내 대상 자리가 정해진다.
- **예약 없음** → **빈자리를 배정한다**(사용자가 "안 하면 빈자리"라고 명시).
  어느 빈자리를 고를지 규칙을 정하고 **근거를 적어라**(앞에서부터/입구에서 가까운 순 등).
- **빈자리도 없음** → 배정 실패. 이 경우를 조용히 지나가지 마라.

> 브라우저에 번호판 입력 UI 는 **아직 없다**(이번 범위 밖). 그래서 "예약 있음" 경로는
> `ws_probe.py` 로 `user_id` 에 번호판을 넣어 예약을 만들어 시험해라. 웹 UI 는 다음에 간다.

### 3) 인식 실패 정책 — **새 임계값을 만들지 마라**

사용자 선택은 "열지 않고 재시도"다. 그런데 **그 정책이 이미 구조에서 나온다** — 루트가 확인했다:

- 폰이 `conf < vision.min_confidence`(기본 0.70) 인 결과를 **폰에서 버린다**(`reason=low_conf`).
- 전송 조건이 `fresh == true && value.isNotEmpty()` 라 **빈 값은 아예 안 나간다.**
- `fresh` 는 **상승 엣지**이고 `send.min_interval_ms`(기본 1000) 하한이 걸린다.

즉 **인식 실패 = 서버에 아무것도 안 온다 = 차단기가 안 열린다 = 카메라가 계속 재시도한다.**
정책이 저절로 성립하므로 서버가 판단할 것이 없다.

**서버에 절대 임계값을 두지 마라.** `conf` 는 문자별 신뢰도의 **최소값**이라
문자 수가 늘수록 낮아진다 — 명세가 "절대 임계로 비교할 때 감안하라"고 경고한 값이다.
서버가 그걸로 자르면 긴 번호판만 유독 거절된다.

### 4) 반드시 처리해야 할 경로 셋 (흐름 설명에 없던 것들)

- **같은 번호판이 또 온다.** `fresh` 상승 엣지라 연사는 안 나지만, 차가 서 있는 동안 인식이
  끊겼다 다시 잡히면 새 엣지가 뜬다. 두 번째를 새 입차로 처리하면 안 된다.
- **이미 주차된 차의 번호판이 게이트에 나타난다.** 오인식일 수도, 실제로 나갔다 다시 온 것일 수도 있다.
- **빈자리가 없다.**

각각 어떻게 하기로 했는지 **판단 근거와 함께** 적어라.

### 5) 결과가 보여야 한다

매칭 결과를 로그와 `slots[].user_id` 에 반영해라. 화면이 "이 칸은 980가4568 차"를 보여줄 수 있어야 한다.

## 검증

`net/` 에 폰을 흉내내는 스크립트가 필요하면 만들어라(`fake_phone.py` 등, 네 트리다).
`docs/net/digitcam-protocol.md` §의 실제 프레임 예시를 그대로 보내면 된다.

- 예약 있는 번호판 → 그 자리로 매칭
- 예약 없는 번호판 → 빈자리 배정
- 같은 번호판 재수신 → 중복 처리 안 됨
- 빈자리 없음 → 실패가 보임
- 한글 번호판이 `valid_userid()` 에 걸려 예약이 깨지지 않는다 (두 이름공간 분리 확인)
- 기존 검증 회귀 없음 (예약 왕복·테스트 모드)

**명령을 엮지 마라(a && b).** 하나씩 실행한다.

## 왜 필요한가

폰은 번호판을 인식해 보내고 있지만 받는 쪽이 테스트 수신기뿐이라 주차 시스템과 이어지지 않는다. 사용자가 설명한 입차 흐름의 중간 고리가 통째로 비어 있다. 그리고 지금 코드는 한글 번호판을 valid_userid() 에서 거절하므로, 그대로 두면 번호판을 사용자 식별자로 쓰는 순간 예약이 bad_request 로 깨진다.

### ⚠ 구현 중 **번호판이 전선에 새는 버그**를 냈고, 가짜 아두이노가 그걸 잡았다

두 이름공간을 설계해 놓고 **`dispatch()` 의 라인 조립부가 여전히 원본 인자를 쓰고 있었다.**

```
전선에 나간 것:  R,1,B2,980가4568,F7      ← UTF-8 번호판이 그대로 나갔다(§2.1 ASCII 전용 위반)
가짜 아두이노:   UnicodeEncodeError ... 'ascii' codec can't encode  → 프로세스 사망
```

`Pending` 필드는 맞게 채웠는데 `snprintf` 가 `p.user_id`(전선용)가 아니라 인자 `uid`(원본)를
쓰고 있었다. **루트가 미리 경고한 바로 그 사고**이고, 설계가 맞아도 조립부 한 줄에서 샜다.
고친 뒤 전선은 이렇게 나간다:

```
11:43:36  →ARD R,1,B2,,13        ← userid 는 빈 값. 번호판은 서버가 들고 있다
```

**가짜 아두이노를 엄격하게 만들어 둔 덕에 즉시 드러났다.** 다만 그때 스크립트가 **죽어 버린 것**은
그 자체로 결함이라 같이 고쳤다 — 진짜 아두이노라면 깨진 줄로 보고 버려야 한다.
`cksum()` 이 비 ASCII 에 `None` 을 돌려주고, 수신부가 비 ASCII 줄을 버리도록 했다.

### 정한 정책과 근거

**빈자리 선택 = §1 인덱스 순서에서 가장 앞(A1→A5→B1→B5).**
결정적이라 같은 입력이면 항상 같은 결과가 나오고(시험이 재현된다), **명세가 이미 정한 유일한
자리 순서**라 새 순서를 발명하지 않는다. "입구에서 가까운 순"은 **물리 배치도를 아무도 갖고 있지
않아** 지금 정할 수 없다 — 생기면 `pick_free_slot()` 하나만 바꾸면 된다.

**중복 판정은 시간이 아니라 상태로 한다.** `plate → 배정 자리` 표를 두고, 그 자리가 아직
그 번호판으로 살아 있으면(예약 또는 점유) 새 입차가 아니다. **시간 창을 두면 근거 없는 숫자가
생긴다** — §11 에서 노쇼 만료를 뺀 것, 신뢰도 임계를 안 만든 것과 같은 이유다.
그 사이 은퇴·취소됐으면 표에서 지우고 다시 배정 가능하게 한다.

**이미 주차된 차의 번호판이 게이트에 나타나면 새 자리를 배정하지 않는다.**
오인식인지 재진입인지 **서버는 구분할 수 없다.** 배정하면 같은 차가 두 칸을 먹는다.
사람이 보도록 `!` 로 로그에 올린다.
(이번 실측에서는 중복 판정이 먼저 걸렸다. 이 분기는 서버 재시작 등으로 표가 비었을 때 걸린다 —
**로그로만 확인했고 별도 시나리오로 발동시키지는 못했다.**)

**신뢰도 임계값은 만들지 않았다.** 폰이 `min_confidence` 로 이미 거르고, `conf` 는 문자별
최소값이라 문자 수가 늘수록 낮아진다 — 서버가 절대값으로 자르면 **긴 번호판만 유독 거절된다.**
코드 주석에도 이유를 남겨 다음 사람이 "임계값이 없네" 하고 넣지 않도록 했다.
