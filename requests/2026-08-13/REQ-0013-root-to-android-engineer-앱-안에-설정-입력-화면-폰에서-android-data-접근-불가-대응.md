# REQ-0013 · 앱 안에 설정 입력 화면 (폰에서 Android/data 접근 불가 대응)

**요청자** `root` → **담당** `android-engineer`

## 요청 내용

**계약 개정 7 · §6.1 을 먼저 읽어라.** 사용자가 결정한 사안이다.

문제: `getExternalFilesDir()` 는 Android 11+ 실기기에서 **폰만으로는 접근할 수 없다.** 파일 관리자도 다른 앱도 `Android/data/` 안을 못 연다. adb 로는 되지만 그러면 서버 IP 하나 바꾸려고 노트북을 들고 다녀야 한다 — 서버 주소 미정 상태에서 리빌드 없이 바꾸자던 취지가 폰에서 절반만 달성된다. 에뮬레이터는 adb 가 늘 붙어 있어서 이 문제가 안 보였다.

해결: **앱 안에 설정 입력 화면을 만든다.**

핵심 원칙 하나만 어기지 마라 — **화면이 파일을 대체하는 게 아니라, 화면이 그 파일을 편집한다.** 저장하면 `getExternalFilesDir()/server.properties` 에 써 넣고 기존 '설정 다시 읽기' 와 **같은 재적용 경로**를 탄다. adb 로 고치는 방법도 그대로 살아 있어야 한다. 두 경로가 같은 파일을 본다.

§6.1 에 적은 여섯 가지를 그대로 지켜라. 특히 두 개가 중요하다:

1. **주석과 모르는 키 보존** — 파일을 통째로 다시 쓰지 말고 **값 있는 줄만 제자리에서 교체**하라. 이 파일은 설정이자 설명서다(각 키가 왜 있는지 주석에 다 적혀 있고, 포트 5500 의 이유 같은 건 그 주석에만 있다). 저장 한 번에 날아가면 안 된다. 화면이 모르는 키가 파일에 있어도 남겨야 한다.
2. **`vision.*` 는 여전히 해석하지 마라** — 파일에 있는 `vision.` 줄을 읽어서 **키 이름 + 자유 입력칸** 목록으로 그려라. 값의 의미를 Kotlin 이 알면 안 된다. 그래야 cpp-engineer 가 `vision.` 키를 추가해도 네 코드를 안 고친다. `nativeConfigure` 를 문자열 하나로 받기로 한 것과 같은 이유다. 반대로 `server.*`·`send.*`·`socket.*` 은 네가 의미를 아는 값이니 형식에 맞는 입력칸을 써라.

나머지: 저장 시 검증(포트 1~65535, format 은 json|plain, 숫자칸에 숫자), 화면 열 때 파일에서 다시 읽어 채우기(화면과 실제 적용값이 어긋나면 그 화면은 거짓말이다), '기본값으로 되돌리기'(assets 사본으로 덮어쓰기 — 값을 잘못 만졌을 때의 탈출구), `server.host` 를 맨 위에.

⚠ **기기는 지금 동결 상태다.** 사용자가 에뮬레이터를 직접 쓰고 있다. **빌드까지만 하고 설치하지 마라.** 검증이 필요하면 루트에게 요청을 발행해라 — 사용자에게 확인하고 풀어 주겠다.

## 왜 필요한가

서버 IP·포트가 미정이라 리빌드 없이 바꿀 수 있어야 한다는 게 원래 요구였는데, 실기기에서는 그 파일에 손이 닿지 않는다. 폰만 들고 현장에 나가면 서버 주소를 못 바꾼다. 설정 파일 방식 자체는 유지하면서(요구사항) 폰에서 편집할 수단만 얹는 것이 이 요청이다.

## 대상 파일

- `android/app/src/main/java/com/example/digitcam/**`
- `android/app/src/main/res/**`
## 완료 기준

1) 앱에서 서버 IP·포트를 바꾸고 저장하면 노트북 없이 적용된다. 2) 저장 후 파일을 adb 로 꺼내 보면 **주석이 그대로 남아 있고** 바뀐 값만 바뀌어 있다. 3) 파일에 화면이 모르는 키(예: vision.새키=1)를 넣고 저장해도 그 키가 살아남는다. 4) vision.* 는 파일에 있는 키가 그대로 화면에 뜬다(Kotlin 에 키 목록이 하드코딩돼 있지 않다). 5) 잘못된 값(포트 99999 등)은 저장이 막히고 어디가 틀렸는지 알려준다.

### 요약: 완료 기준 5가지 전부 실측 통과. 단 **REQ-0015 를 거치고 나서야 실제로 쓸 수 있게 됐다.**

먼저 이것부터 적는다 — 이 요청을 처음 끝냈을 때 나는 "빌드 통과 + 파일이 올바르게 저장됨" 으로
검증을 마쳤다. 둘 다 사실이었지만 **화면을 눈으로 보지 않았다.** 그 상태의 화면은 `server.host`
입력칸이 상태바에 가려 손이 닿지 않았고, 그 칸이 이 화면의 존재 이유였으므로 실질적으로는
아무것도 해결되지 않은 상태였다(REQ-0015 로 사용자가 직접 겪었다). 아래 검증은 그 수정 이후의 것이다.

### 만든 것

| 파일 | 역할 |
|---|---|
| `PropertiesFile.kt` | 설정 파일을 **텍스트로** 다루는 계층. 제자리 교체·기본값 복원·병합 읽기 |
| `SettingsActivity.kt` | 입력 화면. 검증·저장·되돌리기 |
| `res/layout/activity_settings.xml` | 폼. `vision.*` 자리는 비워 두고 코드가 채운다 |
| `MainActivity` | **설정** 버튼 추가, 하단 버튼 2줄 배치, 결과 수신 시 재적용 |

**원칙 — 화면은 파일을 대체하지 않고 편집한다.** 저장하면 외부 `server.properties` 에 쓰고,
호출한 쪽이 **기존 "설정 다시 읽기" 와 똑같은 경로**(`reloadConfig`)로 재적용한다. 화면이 값을
들고 있다가 넘겨주지 않으므로, adb 로 고친 경우와 앱에서 고친 경우가 완전히 같은 흐름을 탄다.
`Properties.store()` 는 쓰지 않았다 — 그건 주석을 전부 버리고 키 순서까지 뒤집는다.

### 완료 기준 검증 (에뮬레이터 실측)

**1) 앱에서 서버 IP·포트를 바꾸고 저장하면 노트북 없이 적용된다 — 통과**

설정 화면에서 `192.168.0.42` 입력 → 저장 → 메인 화면이 `서버 연결중 192.168.0.42:5500` 으로 바뀌었다.
adb 로 파일을 밀어 넣지 않았다.

**2) 저장 후 주석이 그대로 남고 바뀐 값만 바뀐다 — 통과**

저장 전후 파일을 `diff` 한 결과가 **정확히 한 줄**이다:

```
16c16
< server.host=
---
> server.host=192.168.0.42
```

주석·빈 줄·키 순서가 전부 그대로다. 포트 5500 의 근거(macOS AirPlay 충돌)나 `min_sharpness`
눈금이 바뀐 경위 같은 설명이 살아남았다.

**3) 화면이 모르는 키가 살아남는다 — 통과**

검증용으로 파일에 손으로 심어 둔 것들이 저장 후에도 그대로다:

```
# ===== REQ-0013 검증용으로 손으로 넣은 줄 =====
# 이 주석이 저장 후에도 남아 있어야 한다.
vision.새키=1
custom.unknown=keepme
```

`custom.unknown` 은 화면에 아예 그려지지 않는 키인데도 보존됐다. 로그에도
`AppConfig: 알 수 없는 키 무시: custom.unknown` 이 찍혀 "무시하되 남긴다" 가 확인된다.

**4) `vision.*` 키가 파일에서 그대로 뜬다 (하드코딩 없음) — 통과**

`vision.새키` 가 화면에 **`vision.새키` 라는 이름 그대로** 입력칸으로 나타났다(`r15_vision.png`).
Kotlin 어디에도 vision 키 목록이 없다 — 접두어로 걸러 파일에 있는 것을 그리기만 한다.
한글 키 이름이 깨지지 않은 것으로 UTF-8 경로도 같이 확인됐다.

**5) 잘못된 값은 저장이 막히고 어디가 틀렸는지 알려준다 — 통과**

포트에 `99999` 를 넣고 저장 → 화면이 닫히지 않고 그 칸에 오류가 붙었다:
`server.port: 99999 는 허용 범위(1~65535) 밖이다` (`r15_invalid.png`)

**(추가) 기본값으로 되돌리기 — 통과**

`기본값으로 되돌리기` 후 기기 파일과 `assets/server.properties` 를 `diff` → **차이 없음**.
검증용으로 심었던 키들도 함께 정리됐다.

### 저장하다 발견해 고친 버그 하나

처음 구현은 `remaining.remove(key)` 로 **첫 번째 일치 줄만** 바꿨다. 같은 키가 파일에 두 번 있으면
(사용자가 파일 끝에 한 줄 덧붙이면 바로 생긴다) 앞줄만 바뀌고 **뒤에 남은 옛 줄이 이긴다** —
`Properties` 는 나중 값이 이기기 때문이다. 저장은 성공했는데 값은 안 바뀌는, 원인을 찾기 어려운
상태가 된다. 모든 일치 줄을 바꾸도록 고쳤다.

### 설계 메모

- 인라인 주석(`port=5500 # 이유`)은 보존하지 않는다. `Properties` 규격상 `=` 뒤는 전부 값이라
  그 줄의 값은 이미 `"5500 # 이유"` 로 깨져 있다. 되살리면 잘못된 값을 복원하는 셈이다.
- 화면에 채우는 값은 **실제 적용과 같은 병합 순서**(assets → 외부파일)로 읽는다. 표시용으로 따로
  계산하면 화면과 네이티브에 들어간 값이 어긋날 수 있고, 그러면 이 화면은 거짓말을 하게 된다.
- `SettingsActivity` 는 `exported="false"` 다. 확인 삼아 `adb am start` 로 직접 띄워 보니
  `SecurityException` 으로 막힌다 — 의도한 대로다(외부 앱이 설정을 못 연다).

### 확인하지 못한 것

- **소프트 키보드가 올라왔을 때의 가림** — `adb shell input text` 는 하드웨어 키보드 경로라
  에뮬레이터에서 소프트 키보드가 뜨지 않는다. `ime()` 인셋 + `adjustResize` 로 대응해 뒀지만
  실측은 못 했다. 사용자가 실기기에서 칸을 탭할 때 확인해야 한다.
- 실기기에서의 동작 전반(§11 4·5번)은 여전히 미확인이다.
