# REQ-0201 · 🔴 재현 관측 — 사용자가 20개 이상 누르면 ESP 리셋 · 몇 개째부터인가가 핵심

**요청자** `root` → **담당** `monitor-engineer`

## 요청 내용

🔴 **사용자가 실물 증상을 보고했고 재현 관측이 필요하다. 지금 탭을 열어라.**

## 사용자 보고 (원문)

> *"지금 웹이 살아있어서 한걸음 진행을 20개 이상보내면 esp01이 리셋된다. 정상동작인가?"*

**정상이 아니다.** 설계의 핵심 문장이 *"이벤트가 전송을 만들지 않는다 — 20개를 보내든 1개를
보내든 전송 횟수는 슬롯당 1거래로 같고 커지는 건 화물 크기뿐"* 이다.
🔴 **리셋이 난다면 그 문장이 지금 구성에서 깨지고 있다.**

⚠ **그런데 지금 서버 로그에는 흔적이 없다**: `esprst 0` · 4분 · 세션 1회 · 최대공백 1.3초.
**→ 부하에서만 나타난다. 재현 시점의 자료가 필요하다.**

## 지금 열어라 — 조건

```
포트     /dev/cu.usbmodem1101      ← 🔴 이름이 바뀌었다(옛 usbmodem21201 아니다)
서버     pid 80947 · build=c719d87 · ACK_TIMEOUT 2400ms · ack_budget_ms 12600 · cap 192B
펌웨어   slot6 (cntTick 슬롯 묶음까지 들어간 판)
```

**탭을 열면 DTR 리셋이 한 번 난다** — 그것을 `t0` 로 잡아라. **사용자가 그 뒤에 누른다.**

## 🔴 사용자가 누를 때 기록할 것 — **"몇 개째부터"가 핵심이다**

```
· 사용자가 누르기 시작한 시각 · 총 몇 개를 눌렀나
· 🔴 리셋이 몇 개째에 났나        ← 이 수가 원인을 좁힌다
· [CNT] : esprst · cksumng · ssovf · oow · smiss · skip · drop · stuck
· 서버  : queued 수 · 재전송 · 큐대기마감 · q_deferred · q_rejected
```

🔑 **`재전송` 이 이제 파괴만 센다**(1단계 배포로 늦은 ACK 이 빠졌다). **1단계의 첫 활용이 이것이다** —
**지표가 깨끗해진 상태에서 첫 실측**이다.

## 후보 셋 — 어느 것인지 자료가 가른다

```
① 큐 상한   cap 192B 를 넘으면 다음 창으로 밀린다. 20개면 밀린 것이 쌓여 큐가 오래 차 있다
            → 볼 것: q_deferred · 큐 길이 · queued 응답의 ahead 값
② 아이들 간극 화면 아이들 1초 대 슬롯 1.2초. 연타하면 그 0.2초가 누적된다
            → 볼 것: 사용자 클릭 간격 대 슬롯 주기
③ 🔴 cmdPending 구멍  M·T 명령이 queued 를 받는데 화면이 조용히 버리고 6초 고정으로 거짓 실패
            → 사용자가 다시 누른다 → 증폭 고리
            → 볼 것: 같은 rid 가 여러 번 오는가 · 사용자 재클릭 흔적
```

⚠ **③이 가장 의심스럽다.** web 이 소스로 찾았고 *"피해가 작다"* 고 판단해 별건으로 미뤘는데,
**사용자가 본 증상이 그 판단을 뒤집는 실측일 수 있다.**

🔴 **결론을 먼저 내지 마라.** 셋 다 가능하고 **자료가 가른다.** 오늘 우리가 지킨 규율 그대로다.

## 준비되면 알려라 — 사용자가 그때 누른다

**탭이 열리고 `t0` 가 잡히면 루트에 통보해라.** 내가 사용자에게 "지금 누르라"고 전한다.
⚠ **사용자 조작 전에 준비가 끝나야 한다** — 준비 중에 누르면 그 구간이 관측 밖이다.

## ⚠ 다른 작업을 같이 하지 마라

**이 회차는 사용자 조작이 자극이다.** 주입기를 돌리지 마라 — **자극이 둘이 되면 못 가른다.**

## 왜 필요한가

설계의 핵심 문장이 '이벤트가 전송을 만들지 않는다' 인데 사용자 조작 20개에서 ESP 가 리셋된다면 그 문장이 지금 구성에서 깨지는 것이다 — 서버 로그에는 흔적이 없어 부하 시점의 장치측 자료가 필요하다

## 대상 파일

- `monitor/serial-winF.log`
## 완료 기준

① 포트 usbmodem1101 로 탭 개방 · t0 기록 ② 준비 완료를 루트에 통보(사용자 조작 전) ③ 몇 개째에 리셋됐는지 기록 ④ [CNT] 전체 칸과 서버 큐 지표 대조 ⑤ 후보 셋 중 결론을 먼저 내지 않음 ⑥ 주입기 미가동
