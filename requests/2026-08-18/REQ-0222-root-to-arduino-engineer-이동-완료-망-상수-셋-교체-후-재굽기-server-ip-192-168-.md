# REQ-0222 · 🔴 이동 완료 — 망 상수 셋 교체 후 재굽기 (SERVER_IP 192.168.35.21 · SSID SK_WiFiGIGA50DC_2.4G)

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

🔴 **위치 이동 완료. 새 망 값이 확정됐다. 즉시 재굽기해라.**

## 사용자가 준 값 — **그대로 옮긴다**

```
SERVER_IP   192.168.35.21
WIFI_SSID   SK_WiFiGIGA50DC_2.4G
WIFI_PASS   2011050796
```

**루트 독립 확인**: `ipconfig getifaddr en0` → `192.168.35.21`. **사용자 진술과 일치한다.**

## 고칠 줄 — 확인해 뒀다

```
client.ino:91  WIFI_SSID    "3F_302"              → "SK_WiFiGIGA50DC_2.4G"
client.ino:92  WIFI_PASS    "0424719222!!"        → "2011050796"
client.ino:97  SERVER_IP    "192.168.0.29"        → "192.168.35.21"
```

⚠ **주석도 같이 고쳐라.** 91번 줄 주석이 *"서브넷도 192.168.0.x 로 바뀌었다"* 인데
이제 **192.168.35.x** 다. 주석이 값과 어긋나면 다음 사람이 어느 쪽을 믿을지 모른다.

🔑 **새 비밀번호에는 `!` 가 없다** — 예전 값의 셸 히스토리 확장 경고는 이번엔 해당 없다.
다만 **SSID 에 `.` 가 있다**(`2.4G`). 문자열 안이라 문제 없지만 오타 확인해라.

## 🔴 이건 **축이 하나인 굽기다 — 다른 것을 같이 넣지 마라**

**망 상수 셋만 바꾼다.** 상행 배치 상한도, 다른 개선도 넣지 마라.
**이유**: 창 H 에서 수정이 먹은 것이 확인됐다(`>=64B 1,025 거래 → T2 0건`).
**그 상태를 새 망에서 그대로 재현하는 것**이 다음 관측의 기준선이고,
**여기에 다른 변경이 섞이면 "망이 바뀌어서인지 코드가 바뀌어서인지" 를 못 가른다.**

## 절차

```
1. 세 줄 + 주석 수정
2. 빌드 -DBUILD_ID · --selftest 통과 · 회귀 134
3. monitor 에 굽기 통보 (탭 내리게) → 반납 확인 후 upload
4. hex 대조 (IDENTICAL 확인)
5. 🔴 완료 통보를 monitor 와 루트 **양쪽**에
6. INTERVENTIONS.md 에 사전·사후 기록
```

## 붙었는지 확인하는 법

```
서버 로그에 이 줄이 떠야 한다:
  +ARD 주차 노드 접속 — 세션#N · device=P1 · 상대 192.168.35.xxx:yyyyy
                                              ^^^^^^^^^^^^^^ 새 서브넷
```
🔑 **`상대` 칸이 오늘 socket 이 넣은 것이다** — 새 망에서 "우리 보드인가"를 첫 줄에서 가른다.
⚠ **서브넷이 `192.168.0.x` 로 나오면 옛 값이 살아 있는 것**이다.

## ⚠ 서버는 어떻게 되나

**socket 이 확인 중이지만**, `0.0.0.0` 바인딩이면 **PC IP 가 바뀌어도 서버는 그대로 돈다.**
다만 **PC 가 망을 옮겼으므로 서버를 한 번 재기동하는 편이 안전하다** — socket 이 판단한다.
**네가 굽기 전에 서버가 새 망에서 살아 있는지 확인해라.** 서버가 죽어 있으면 붙을 곳이 없다.

## 시간

**사용자가 18:00 종료라고 했다. 지금 약 17:50 이다.**
🔴 **굽기까지만 하고, 관측은 다음 세션이다.** 새 창을 열려고 하지 마라 —
**반쯤 관측하다 끊긴 창이 가장 나쁘다.** 붙는 것까지 확인하면 오늘 몫은 끝이다.

## 왜 필요한가

WIFI_SSID·WIFI_PASS·SERVER_IP 가 컴파일 상수라 망이 바뀌면 재굽기 없이는 장치가 서버에 못 붙는다. 루트가 ipconfig 로 PC IP 192.168.35.21 을 독립 확인했다
