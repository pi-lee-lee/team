# REQ-0206 · 🔴 서버에서 유입을 막는다 — 사용자/중요 이벤트를 갈라 차단 · 문턱은 실측으로 (사용자 결정)

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

🔴 **사용자가 대책 방향을 정했다. 그리고 문턱은 실측으로 정한다.**

## 사용자 진단 (원문) — **정확하고 자료가 그것을 증명한다**

> *"버퍼 크기보다 많은 요청이 웹 → 서버 → 아두이노까지 확산된 케이스 아닌가?
> 그리고 이 경우는 **서버에서 사용자 이벤트의 경우는 차단**하고 **중요 이벤트의 경우는
> 다음 사이클에 전송**하는 로직이 적합할 것 같은데?"*

**루트가 확인한 것:**
```
서버 큐넘침 거절 : **0건**      ← 서버는 하나도 안 막았다
장치 ACK 버림    : **43건**     ← 넘친 것은 장치였다
```

> ### **서버에 거절 장치(`queue_full`)가 있는데 문턱이 안 걸렸다. 전부 통과시켰고
> ### 가장 좁은 데(장치 RAM)에서 터졌다.**

## 🔴 "장치가 알아서 버린다"가 최악인 이유 셋

```
① 가장 늦게 버린다   — 웹·서버를 다 통과한 뒤라 그 사이 자원을 전부 썼다
② 아무도 모른다      — 장치의 ackdrop 은 USB 로만 나간다. 서버도 화면도 못 본다
③ 가장 오래된 것을 버린다 — 먼저 누른 것이 먼저 사라진다. 사용자에게 가장 나쁜 순서다
```

**서버에서 막으면 셋 다 뒤집힌다** — 즉시 · `queued`/`queue_full` 로 말할 수 있고 · 무엇을 남길지 서버가 정한다.

## 할 것 ① — **사용자 이벤트와 중요 이벤트를 가른다**

```
사용자 이벤트(한걸음 M · 예약 R/C)  잃어도 사용자가 다시 누른다. 그게 자연스럽다
중요 이벤트(재동기 · 상태 정정 등)   잃으면 서버와 장치 상태가 갈린다. 아무도 다시 안 누른다
```

🔴 **지금은 둘이 같은 큐에서 같은 규칙으로 다뤄진다 — 연타가 재동기 명령을 밀어낼 수 있다.**
**어느 것이 어느 계열인지 네가 분류해라** — 네 도메인이고 명세에 근거가 있다.

## 할 것 ② — **차단은 침묵이 아니라 `queue_full` 이다**

**거절도 사용자에게는 응답이다.** 화면이 이미 그 계약을 갖고 있다:
```
queued      "서버가 받았습니다 — 앞에 N건"
queue_full  거절 — "지금 다시 누르지 마라"
```
🔑 **`queue_full` 이 "안 먹혔나?" 하고 더 세게 누르는 것을 막는다.** 조용히 버리는 것과 정반대다.
⚠ **web 과 문구를 맞춰라** — 화면이 그것을 어떻게 그릴지는 web 몫이다.

## 🔴 할 것 ③ — **문턱을 실측으로 정한다 (사용자 확정)**

> 사용자: *"실측으로 정하자."*

**감으로 적지 마라.** 이 프로젝트가 그것으로 두 번 데었다(CLAUDE.md).

**쓸 수 있는 자료:**
```
장치 : ACKQ_N = 12 (큐 상한) · 배출 = 슬롯당 최대 6개(BATCH_CAP 160 − S 63 = 96B ÷ ACK 16B)
실측 : 15:09 구간 ackdrop 43 · 그때 하행 M 이 1초에 3~8건
       [SLOT] tx=149 ack=8 — 한 배치에 ACK 8개까지 실린 기록이 있다
```

**네가 계산할 것:**
```
· 정상 상태에서 장치가 감당하는 유입률은 얼마인가 (배출 6개/슬롯 = 5개/초 상한)
· 배출이 0 인 구간(TX_STALL_MS 10초)을 견디려면 문턱이 얼마여야 하는가
· 🔴 그 값이 정상 사용을 거절하지 않는가 — 아이들 1초면 초당 1건이 정상이다
```

⚠ **그리고 유도식으로 만들어라** — `ACKQ_N`·`DOWN_SLOT_MS` 가 바뀌면 따라와야 한다.
**리터럴로 박으면 다음에 누가 큐를 늘려도 문턱이 안 따라간다.**

🔑 **자료가 부족하면 "무엇을 더 재야 하는지"를 적어라.** 사용자가 다시 연타해 줄 수 있다 —
**추가 실측이 필요하면 그렇게 요청해라.** 감으로 채우는 것보다 낫다.

## ⚠ 그리고 고리 확인은 그대로 남는다 (REQ-0205)

```
ACK 이 밀린다 → 배치가 커진다 → S 가 늦는다 → 서버가 창을 포기한다 → 하행이 몰린다 → …
```
🔴 **문턱을 넣으면 이 고리도 끊긴다** — 유입이 제한되면 배치가 안 커진다.
**즉 ①이 ②를 같이 고칠 수 있다.** 그것도 판단에 넣어라.

## 하지 마라

- 🔴 **아직 코드 고치지 마라. 배포하지 마라.** **계산과 근거를 먼저 보고해라.**
- **`ACKQ_N` 을 더 올리자고 하지 마라** — 실측이 그 방향을 이미 닫았다.

## 왜 필요한가

서버 큐넘침 거절이 0건인데 장치가 43건을 버렸다 — 서버가 전부 통과시켜 가장 좁은 곳에서 터졌고 그 손실은 USB 로만 보여 아무도 모른다. 그리고 지금은 사용자 이벤트와 중요 이벤트가 같은 큐라 연타가 재동기 명령을 밀어낼 수 있다

## (1) 분류 — 가르는 기준은 **"버리면 무엇을 잃는가"**

| 계열 | 무엇 | 버리면 |
|---|---|---|
| **사용자** | 브라우저 예약/취소 · 시험 · 시뮬 | **사용자가 안다**(거절 응답) · 다시 누르면 된다 |
| **중요** | 재동기 재하달 · 불일치 감지의 치유 · 예약 은퇴 · 폰 경로 배정 | 🔴 **아무도 모르게 서버와 장치가 갈린 채 남는다** |

> ### **기준: "이 명령이 없으면 서버와 장치가 갈린 채로 남는가?" → 그렇다면 중요다.**
> 🔴 **치유 명령이 연타에 밀려나면 치유 자체가 죽는다** — 실측된 자가 치유가 무력해진다.

- **폰 경로 배정을 중요로 넣었다** — **물리 사건이고 사용자가 다시 누를 수 없다.**
- **재전송은 원 명령의 계열을 따른다.**
- 🔑 **큐를 둘로 나누지 않는다.** 항목에 **계열 표시 + 배출 시 중요 우선**.
  나누면 *"둘 중 어느 큐가 창을 쓰나"* 라는 새 규칙이 생겨 **창당 1거래가 흐려진다.**

## (2) 차단 = `queue_full` — **장치는 이미 있다. 문턱이 안 걸렸을 뿐이다**

```
서버 큐넘침 거절 0건   대   장치 ACK 버림 43건
→ 서버는 하나도 안 막았고 가장 좁은 곳에서 터졌다
```
🔑 그리고 **그 손실은 USB 로만 보인다** — 서버도 화면도 모른다. **거절로 바꾸면 사용자가 안다.**
문구는 web 과 이미 합의돼 있다(`queue_full` = 재시도가 의미 있는 계열).

## (3) 문턱 — **`min(192B, 4건)`** · arduino 유도 채택

⚠ **입력이 어긋나 있었고 arduino 가 확정했다:**
```
monitor 실측 8  →  🔴 조건부다. S 가 짧고 rid 가 3자리일 때만
설계 보장  **6**  →  tmask 가 붙거나 rid 5자리면 6으로 떨어진다
→ **설계값은 6.** 실측을 설계값으로 승격시키지 않는다
```

**여유가 왜 필요한가 — arduino 유도:**
```
유입 6 : 한 슬롯 놓침 → 12 쌓임 → 배출 6 → 6 남음 → 다음도 12 → 🔴 **영영 안 줄어든다**
유입 4 : 한 슬롯 놓침 →  8 쌓임 → 배출 6 → 2 남음 → 다음 6 → 배출 6 → **0. 2슬롯에 회복**
```
> ### **유입 = 배출이면 한 번만 밀려도 영구히 못 따라잡는다. `4` 는 한 슬롯 손실을 2슬롯에 흡수한다.**

⚠ **바이트 상한은 그대로 둔다 — 두 상한은 다른 축이다**(회선 대 ACK 배출).
**명령이 작으면 건수가, 크면 바이트가 먼저 걸린다**(시뮬 9B 면 4건=36B 로 **건수가 실질 상한** — 그게 목적이다).
🔑 **유도식으로 넣는다**: 건수 상한 = **장치 배출률에서 유도**(리터럴 금지 · 배출률이 바뀌면 따라 움직여야 한다).

## (4) 고리를 끊는가 — **끊는다. 다만 절반이다**

```
유입 제한 → 창당 하행 건수 ↓ → 장치가 만들 ACK 수 ↓ → 상행 배치 크기 ↓
          → S 지연 ↓ → 창 포기 ↓ → 하행 몰림 ↓      ← 고리의 **입력**이 막힌다
```
⚠ **이미 커진 배치가 만드는 지연 자체를 없애지는 않는다.** **입력을 막는 것이지 출력을 줄이는 게 아니다.**
**이미 돌고 있을 때 빠져나오는 속도는 위 "2슬롯 회복"이 정한다.**

## (5) 🔴 더 재야 하는 것 — **감으로 안 채운다**

1. **부하에서 배출률이 떨어지는가.** 관측 8·설계 6 은 **정상 구간 값**이다. **몰릴 때 줄면 4 도 크다.**
   → **연타 구간에서만 `ack=` 분포를 따로 내 달라**(monitor).
2. **사용자의 실제 연타 속도**(초당 몇 건). ⚠ 없으면 **문턱은 정할 수 있어도
   "얼마나 자주 거절될지"는 못 말한다.** 사용자가 다시 연타해 주면 그 값이 나온다.
3. **하행 미도착(`rid 479·480`)은 이 수정이 안 고친다.** 🔴 **반대 축이다** — 따로 가야 한다.
