# REQ-0207 · 🔴 구현 — 하행 유입 문턱 min(192B,4건) · 사용자/중요 분류 · queue_full (사용자 지시)

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

🔴 **사용자 지시: 원인 조사는 끝났다. 막는 코드를 쓴다.**

> *"죽은 원인 확인하지마라. 원인 안다. 많은 송신으로 오버플로로 리셋되는 것이다.
> 다시 살아나게끔 코딩되어 있다. **그게 문제가 아니고 이거 오버플로 나는 걸 막는 코드 작성 중이었다.**"*

**추가 조사 금지. 구현이다.**

## 문턱 — 네가 낸 계산 그대로 간다

```
문턱 = min(192B, 4건)   (유도식으로)
근거 : 배출 6/슬롯 · 유입 6 이면 한 슬롯 놓쳤을 때 영영 안 줄어든다
       유입 4 면 2슬롯에 0 으로 회복
```

**네가 요청한 실측 둘이 나왔다(monitor):**
```
연타 구간 [SLOT] ack= 분포 : {0:133, 3:1, 8:7}
  🔴 배출은 최대 8 에서 막히고 8짜리 배치 7건 중 대부분이 r=0(미전송)
  → **부하에서 배출률이 떨어진다**가 확인됐다
M 배치 도착 : 9초에 40~48 하행 (서버 창당 7~8건 × 6회)
```

⚠ **이 자료가 문턱 4 를 더 강하게 만든다** — **부하에서 배출이 6 밑으로 떨어지므로
유입 4 도 여유가 크지 않다.** **4 를 올리지 마라.**

## 구현할 것 셋

### ① 사용자/중요 이벤트 분류 — 네 안 그대로

```
사용자 : 예약 · 취소 · 시험 · 시뮬(M)   → 문턱 초과 시 queue_full 로 거절
중요   : 재동기 · 불일치 치유 · 은퇴 · 폰 배정 → 🔴 거절하지 않는다. 다음 사이클로
```
🔑 **큐를 둘로 나누지 않는다** — 항목에 계열 표시 + 배출 시 중요 우선. **네 판단 유지.**

### ② 차단은 `queue_full` 응답 — 침묵 금지

**web 과 문구는 이미 합의돼 있다.** 화면이 그것을 그린다.

### ③ 문턱을 유도식으로

**`ACKQ_N`·`DOWN_SLOT_MS`·배출률이 바뀌면 따라 움직여야 한다.** 리터럴 금지.

## 🔴 그리고 monitor 가 기전을 확정했다 — **네 설계 판단에 걸린다**

```
15:23:12  [SLOT] tx=80  ack=3 r=1   ← 정상
15:23:13  [SLOT] tx=150 ack=8 r=0   🔴 안 나갔다
15:23:14  [TX-WAIT] ★ T1 초과 · [SLOT] tx=150 ack=8 r=0
15:23:15  [SLOT] tx=150 ack=8 r=0 → 상행 공백 3.5초+ → 서버 오프라인 판정 → 재접속
```

> ### **고리: 하행 유입↑ → ACK 유입↑ → 배치 커짐(80→150B) → SEND OK 지연
> ### → 게이트 닫힘 → 슬롯 연속 건너뜀 → 상행 공백 → 오프라인 → 재접속·재전송 → 하행↑**

🔴 **설계가 *"이벤트가 전송을 만들지 않는다"* 로 없앤 그 고리가 ACK 배치 크기를 통해 되살아났다.**
**전송 횟수는 상수인데 한 번의 크기가 커져 시간 축에서 같은 폭주가 난다.**

⚠ **그래서 monitor 가 경고했다: 큐를 키우는 것도 ACK 을 더 묶는 것도 이 고리를 키운다.**
**묶을수록 한 번이 커지고 `SEND OK` 가 늦어진다.**

🔑 **네 하행 문턱이 그 고리의 입력을 막는다** — 유입이 4로 제한되면 ACK 도 4까지만 쌓이고
**배치가 150B 까지 안 커진다.** **그것이 이 구현의 실제 효과다.** 그 연결을 원장에 적어라.

## ⚠ arduino 쪽에 남는 축 하나 (네 몫 아니다)

**상행 배치 크기 상한**(`tx` 150B 가 `SEND OK` 를 늦춘다). **arduino 에 따로 낼 것이고
네 문턱과 같은 축에서 만난다.** **네 구현에 그것까지 넣지 마라 — 축이 둘이 된다.**

**코드 → `--selftest` → 나에게 배포 명령을 넘겨라.** 내가 친다(소유권 훅 밖).
⚠ **배포 전에 monitor 통보.** 지금 탭이 돌고 있다.

## 왜 필요한가

사용자가 원인 조사를 끝내고 막는 코드를 지시했다. 그리고 네가 요청한 실측 둘이 나와 문턱 4의 근거가 더 강해졌다 — 부하에서 배출이 6 밑으로 떨어진다

### ① 유도식 — 리터럴 금지 지시대로

```cpp
static const int  DEV_ACK_DRAIN_PER_SLOT = 6;   // arduino 확정 · REQ-0206
static const int  DOWN_BATCH_MAX_N = (2 * DEV_ACK_DRAIN_PER_SLOT) / 3;  // = 4
```
`3N − 2D ≤ 0 → N ≤ 2D/3 → 4`. **`6` 이 바뀌면 `4` 가 따라 움직인다.**
사용자 큐 깊이도 유도값: `DOWN_BATCH_MAX_N × (DOWNQ_WAIT_CAP_MS ÷ DOWN_SLOT_MS)` = **16건**
= 마감(4800ms) 안에 실제로 나갈 수 있는 양. 더 깊게 받으면 **받아 놓고 마감으로 버린다** —
사용자에겐 "받았다"고 해 놓고 사라지는 것이라 즉시 거절보다 나쁘다.

⚠ **monitor 실측 `8` 을 안 썼다.** 그건 조건부다(`S` 가 짧고 rid 3자리일 때만) —
`8` 로 잡으면 `N=5` 가 나오고 tmask 가 붙는 순간 유입>배출이 되어 **다시 안 줄어드는 큐**가 된다.

### ② 사용자/중요 분류 — 지시대로 비대칭

| 계열 | 판정 | 상한 초과 시 |
|---|---|---|
| 사용자(예약·취소·시험·시뮬) | `ws_fd != BAD_SOCK` | **거절** + `queue_full` 응답 |
| 중요(재동기·치유·은퇴·폰 배정) | `ws_fd == BAD_SOCK` | **거절 안 함** · 다음 사이클 |

🔑 **분류를 새로 만들지 않았다 — 이미 코드에 있었다.** 기준은 한 문장:
*"이 명령이 없으면 서버와 장치가 갈린 채로 남는가?"*

### ③ 큐는 안 나눴다 (지시대로)

한 큐 + 계열 표시 + **배출 시 중요 우선**(계열 안에서는 FIFO).
나누면 *"어느 큐가 이번 창을 갖는가"* 라는 새 규칙이 생겨 **창당 한 거래**(§7)가 흐려진다.
계열 사이 순서 보장은 필요 없다 — 상태 정정과 새 의도는 독립이다.

### ④ 침묵 금지 — `queue_full` 응답

`send_err(ws_fd, browser_rid, "queue_full", "요청이 밀려 있습니다. 잠시 후 다시 눌러 주세요")`.
web 과 합의된 문구를 그대로 쓴다.

### ⑤ 거절 계수기를 축별로 갈랐다 (지시에 없던 것 · 이유 기록)

```
큐넘침 N(건수축 a / 장치없음 b / 중복 c / 링크버림 d)
```
바이트 초과 → **`cap` 문제**(전선) · 건수 초과 → **장치 ACK 배출 문제**.
한 칸이면 **`cap` 을 올려 놓고 왜 안 낫는지 찾게 된다** — §8.23-(38) 과 같은 함정.

### ⑥ 검사 3건 신설 (⑩⑪⑫) — 없으면 다음 사람이 되돌린다

- ⑩ **건수 상한**: 작은 명령 6건 → 4건만 나가고 2건 남는다(바이트로는 못 막는 자리)
- ⑪ **중요 우선**: 사용자 3건 + 중요 1건 → 전선 첫 줄이 `C,`
- ⑫ **비대칭**: 사용자 16건에서 막히고 3건 거절 · 그 위에 중요는 통과 → 큐 17

### ⚠ 재전송은 상한을 안 탄다 — 의도적이다

재전송 경로는 `force=true` 로 들어간다. 안 그러면 **이미 전선에 나간 건**에 `queue_full` 이
붙어 브라우저가 "다시 누르라"를 받는데 그 사이 ACK 이 올 수 있다 — ⑨ 가 막는 그 형태다.
재전송은 **원래 명령의 계열을 그대로 물려받는다.**

### ⚠ 상행 배치 상한은 안 넣었다 (지시대로 · arduino 축)

### ⚠ 이 변경이 고치지 않는 것

**하행 미도착(rid 479·480 · 3회 전부 미도착)은 그대로다.** 이번 것은 **상행 ACK 포화 축만** 막는다.

### ⚠ 배포 뒤 비교 불가 칸 둘

1. `큐넘침` — 건수축이 새로 들어온다
2. 🔴 `배치 줄` — `R/C`(28B)도 192B 아래 **6건 → 4건**으로 끊긴다.
   **정상 경로의 배치 크기 분포가 통째로 이동한다** — monitor 가 경계 너머로 비교하면 없는 변화를 본다
