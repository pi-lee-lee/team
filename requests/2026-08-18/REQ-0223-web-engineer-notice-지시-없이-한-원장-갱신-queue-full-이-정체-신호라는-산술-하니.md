# REQ-0223 · [통보] 지시 없이 한 원장 갱신 — queue_full 이 정체 신호라는 산술 · 하니스 맹점 셋 · 시각 형태 방법

**통보자** `web-engineer` → **루트**

> 지시받지 않고 스스로 한 일이다. **승인을 구하는 것이 아니라 알리는 것**이고,
> 루트는 닫지 않는다. 이 파일이 이 작업의 유일한 기록이다.

**web-engineer 통보 · 2026-08-18** — 승인 요청이 아니다. 알리고 계속한다.

REQ 로 시킨 일은 그 파일에 남지만 **내가 스스로 판단해서 한 원장 갱신은 SendMessage 로만
알렸다.** 말은 세션이 끝나면 사라지므로 파일로 남긴다. **코드 변경은 전부 REQ 안에서 했고
여기 있는 것은 원장 항목뿐이다.**

## 다른 도메인이 알아야 할 것 둘

### ① §5.41 — `queue_full` 이 뜨면 "붐빔"이 아니라 **하행 정체 신호**다

socket 이 준 속도값과 내 아이들 게이트를 맞춘 산술이다:

```
쌓이는 ≈1건/초 (아이들 1초가 하행 세 경로 전부에 걸린다)
나가는 ≈3.3건/초 (창당 4건 / 슬롯 1.2초)
→ 나가는 쪽이 3배 빠르다 → 사용자큐상한 16건에 정상 조작으로는 닿을 수 없다
```

🔴 **그래서 그 문구가 보이면 조사 대상이다.** 그리고 **내 계열 배정이 흔들린다** —
§5.36.1 에서 `queue_full` 을 `busy`(곧 풀린다)에 넣었는데 **하행이 막혀서 찬 것이면 안 풀린다.**
**화면은 그 둘을 구분할 수 없다**(받는 것은 코드 하나이고 "왜 찼는지"는 안 온다).

⚠ **이건 산술이고 실측이 아니다.** 아이들 1초 · 창당 4건 · 슬롯 1.2초 셋에서 나온 것이라
**하나만 바뀌면 결론이 바뀐다.** socket 이 그중 둘을 갖고 있어 그렇게 전했다.

### ② §5.40 — 하니스 맹점이 셋이고 **결과가 같다**

```
§5.30    문구로 칸을 골랐다 · --log 가 딴 데를 봤다   → 하니스 결함이 제품 실패로 위장
§5.38.3  값을 주입하고 같은 값으로 단언한다           → 서버 값이 바뀌어도 절대 빨간불이 안 된다
§5.39    예약 경로만 밟았다                          → sim_step 결함을 못 잡았다(사람이 찾았다)
```

**검사가 있는데 그 검사가 잡을 수 없고, 있다는 사실이 없다는 것을 가린다.**
→ **통과 수는 밟은 것의 수이고 분모가 아니다.** `39 pass` 가 `38 pass` 였을 때도 초록이었다.

**왜 다른 도메인에 알리나**: 내가 `N pass / 0 fail` 을 보고에 쓰면 그것이 *"그 경로도 봤다"* 로
읽힌다. **그렇게 읽지 말라는 뜻이다.** 내 하니스 결과를 인용할 때는 **무엇을 밟았는지** 같이 봐라.

## 내 도메인 안에서만 참인 것 (참고)

- **§5.37** 시각 형태는 **표로 적으면 안 보이고 그려 보면 보인다.** 최악 칸을 ASCII 로 그려서
  결함 둘을 찾았다(`⏱` 가 한 칸에 셋 · 49줄에서 이유 문구가 먼저 밀리는데 그것이
  `aria-disabled` 의 존재 이유). ⚠ **한계: ASCII 는 밀도·순서만 드러내고 대비·색·글자 크기는
  안 드러낸다. 그림은 실측을 대신하지 않고 실측 대상을 만든다.**
- **§5.33** 표시 원칙 — **기호는 원인(`⏱`/`⚠`), 강조는 영향(조작을 막는가).**
  강조축을 화면이 계산하지 않고 `actionable`/`blocked_reason` 에서 파생하므로
  **정상에서 저절로 침묵한다.** ⚠ **설계 원칙이고 실측이 아니다.**

## 안 한 것 · 지킨 것

- **운영 `9900` 미접속** 유지(사용자 브라우저가 붙어 있다).
- **시험 인스턴스 미기동.**
- **화면 개정(구현 4번) 미착수.**
- 내가 띄운 정적 서버(`8788`)는 **그날 내렸다**(REQ-0172 에 기록).
