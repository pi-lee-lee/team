# REQ-0199 · 구현 1 — ACK_TIMEOUT 유도식 (web 과 같은 배포) · 재전송이 파괴만 세게 만든다

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

🔴 **구현 착수. 1단계다.** 계획 전문: `docs/IMPL-PLAN-2026-08-18.md`

⚠ **사용자가 한도 임박을 알렸다.** 세션이 끊겨도 이어받게 **진행 상황을 원장에 자주 남겨라** —
`req.sh progress` 한 줄이면 된다. **끊긴 뒤 다음 세션이 네 창을 이어받는다.**

## 왜 이것이 1번인가 — **측정 도구 복구**

```
지금  : 재전송 = 늦은 ACK + 파괴 (섞여 있다) → 판별자가 필요하고 그 판별자는
        파괴가 드물어질수록 오탐 비중이 커진다 (창 E 에서 이미 오탐 1건)
수정 후: 늦은 ACK 이 빠지고 재전송이 파괴만 센다 → 🔑 판별자가 필요 없어진다
```

**이후 모든 단계가 "안 깨졌나"를 이 지표로 본다.** 그래서 먼저 고친다.

## 할 것

### ① `ACK_TIMEOUT` 유도식 — **실측 입력이 있다**

```
왕복 마지막 : 1229 · 1225 · 1230   ← 세 창 · 두 망 · 두 펌웨어에서 고정
```

🔴 **`rtt_max` 를 쓰지 마라** — 창 D 최대가 `1599ms` 다. **최대에 문턱을 맞추면 실패 감지가
느려진다** — 그건 `ACK_TIMEOUT` 이 하려는 일의 반대다. **중앙값 + 한 슬롯 여유**가 맞고
**둘 다 실측으로 갖고 있다**(네가 §8.23 에 적어 뒀다).

⚠ **유도식으로 만들어라. 리터럴 상수로 박지 마라** — `ack_budget_ms` 때 배운 것 그대로다.
**나중에 슬롯 주기가 바뀌면 이 값도 따라와야 한다.**

### ② 🔴 web 화면 타이머와 **같은 배포**

**`ack_budget_ms` 가 이 값에서 계산된다.** 서버만 올리면 **화면이 옛 예산으로 돈다.**
네 원장 §8.23-(36) 에 그 제약이 있고 내가 *"서버만 올라가고 화면이 옛 예산으로 도는 구간이 생긴다"* 를
덧붙였다.

**web 에 같은 지시를 냈다**(REQ 별도). **너희 둘이 배포 시점을 맞춰라** — 내가 중계하면 늦는다.

### ③ 배포는 내가 친다 — 명령을 넘겨라

`~/parking-bin/**` 이 소유권 훅 밖이다((가) 갈래). **런북 형식 그대로**:
빌드 명령 · 해시 · 교체 순서 · 확인 grep.

⚠ **배포 전에 monitor 에 통보해라** — 관측이 지금 안 돌지만 **창 경계는 남는다.**

### ④ `재전송` 을 대조 불가 칸으로 표시

**네가 미리 예고한 그것이다** — *"내가 '창들을 잇는 유일한 칸'이라고 부르던 것을 내 손으로 끊는 것"*.
**끊기 전에 적어 뒀으니 이제 실행만 하면 된다.** 원장·명세 양쪽에.

## ⚠ 하지 마라

- **2단계(노드별 리팩터링)를 같이 하지 마라.** 축이 둘이 된다 — **이 배포의 효과를 못 가른다.**
- **새 관측을 열지 마라.** 검증은 배포 직후 `queued` 왕복 확인으로 충분하다.

## 끝의 조건

```
· 서버·화면이 같은 해시(또는 같은 시각)로 배포됨
· queued 왕복이 새 예산으로 도는 것 확인
· 재전송 대조 불가 표시가 원장·명세에 들어감
```

## 왜 필요한가

재전송에 늦은 ACK 이 섞여 있고 그것을 가르는 판별자가 파괴가 드물어질수록 오탐이 커진다 — 이후 모든 구현 단계가 '안 깨졌나'를 이 지표로 보므로 측정 도구를 먼저 복구한다
