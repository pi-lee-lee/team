# REQ-0210 · 🔴 문턱 ② — 서버 송신 시점에 속도 제한 (사용자 지시) · 창 포기 경로도 지켜라

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

🔴 **사용자 지시. 문턱을 두 지점에 만든다.**

> *"1. 스크립트에서 문턱 생성 2. 서버에서 송신 시점에 문턱 생성하라. 수치는 모두 확인되었을 것이다."*

## 왜 두 지점인가 — 지금 배포가 그 이유를 보여 준다

```
배포(50d2393) 후 : 배치는 150B → 36B 로 작아졌다 (큐 상한이 먹었다)
그런데          : queue_full 거절 0건 · 끊김은 계속 · esprst 2→7 · oow 8→47
```

🔴 **지금 문턱은 "큐에 넣을 때"만 본다. 나가는 속도는 안 막는다.**
**웹이 계속 밀어넣고 서버가 창마다 4건씩 계속 내보내면 유입 자체는 안 줄어든다.**

**→ 사용자 지시가 그 구멍을 정확히 짚었다: 들어오는 곳(①)과 나가는 곳(②) 둘 다 막는다.**

## ② 네 몫 — **서버 송신 시점 문턱**

**지금**: `flush_downq` 가 창마다 큐에서 최대 4건을 꺼내 보낸다.
**바꿀 것**: **송신 시점에 속도를 제한한다.**

```
· 창당 몇 건까지 실제로 전선에 내보낼 것인가
· 🔴 큐에 있어도 못 나가면 어떻게 되는가 — 다음 창으로 미룬다(버리지 않는다)
· 중요 이벤트는 그 제한 위에서도 우선 (기존 규칙 유지)
```

⚠ **큐 상한(넣을 때)과 송신 문턱(나갈 때)은 다른 것이다.** 지금 것을 대체하지 말고 **둘 다 둬라.**

### 🔴 수치 — **"모두 확인되었을 것"이라고 사용자가 말했다. 실측을 다시 쓰지 말고 있는 것으로 계산해라**

```
장치 배출  : 슬롯당 6개 (설계 보장) · ⚠ n 이 커지면 5로 떨어진다(arduino)
부하 실측  : [SLOT] ack= 분포 {0:133, 3:1, 8:7} — 8짜리 대부분이 r=0(미전송)
             → 부하에서 배출률이 6 밑으로 떨어진다
회복 조건  : 유입 4 면 한 슬롯 놓쳐도 2슬롯에 0 으로 회복 (네 유도)
현재 배치  : 4줄 36B 로 이미 작다 — 그런데도 끊긴다
```

🔴 **그러니 4 보다 낮춰야 할 수 있다.** **네가 그 값을 유도해라** — 그리고 **왜 그 값인지
회복 계산으로 보여라.** 리터럴 금지, 유도식.

⚠ **자료로 안 나오는 것이 있으면 "이 값은 유도 못 했고 이유는 이것"이라고 적어라.**
**감으로 채우지 마라** — 이 프로젝트가 그것으로 두 번 데었다.

## 🔴 그리고 이것을 같이 봐라 — 내 가설

```
oow 8 → 47   하행 유입을 줄였는데 창 침범이 늘었다
15:43:09     ⇉ 배치 4줄 36B (S 가 안 온다 — 창 포기)   ← 작은 배치인데도 창 포기
```

**가설**: **적게 보내니 서버가 `S` 를 기다리다 더 자주 포기하고, 포기하면 슬롯 밖에서 쏜다.**
**그러면 우리가 막으려던 것을 다른 방식으로 만든 셈이다.**

🔴 **송신 문턱을 넣을 때 `창 포기` 경로도 그 문턱을 지키는지 확인해라** —
**포기 경로가 문턱을 우회하면 이번 수정도 같은 결과가 난다.**

## ⚠ 배포 판단

**이번 수정이 ①(web)과 같은 배포여야 하는지 판단해서 알려라.**
**둘 다 유입을 막는 것이라 하나만 올리면 효과가 반쪽일 수 있다.**

**코드 → `--selftest` → 배포 명령을 나에게.** monitor 통보는 배포 전에.

## 왜 필요한가

지금 문턱은 큐에 넣을 때만 보고 나가는 속도는 안 막는다 — 배치는 36B 로 작아졌는데 끊김이 계속되고 esprst 가 2→7 로 올랐다. 그리고 oow 가 8→47 로 늘어 창 포기 경로가 문턱을 우회할 가능성이 있다

### 넣은 것 — 중단 전에 이미 손에 있던 것이라 마무리해서 커밋만 했다

**① 창 포기: 슬롯당 1회 → 침묵당 1회**
```
옛 : 8초 침묵 → 2.4초에 첫 포기, 그 뒤 슬롯(1.2초)마다 → **약 5회**
새 : 침묵 한 번에 **1회.** 장치가 한 줄이라도 말하면 재무장
```
🔑 **재시도는 조건이 바뀌었을 때 뜻이 있다. S 가 안 온 동안 조건은 안 바뀐다** —
같은 근거로 다시 쏘는 것은 새 시도가 아니라 같은 시도의 반복이다.
🔴 **하필 장치가 가장 못 받는 구간에서 가장 많이 쏘고 있었다.**

**② 창 포기 배치: 4건 → 1건(탐침)**
```
정상 창  : S 도착 = **증거 있음** → 4건 (유도값 유지)
창 포기  : **증거 없음** → 링크 판정에 필요한 최소 표본 = **1건**
```
⚠ **1 은 유도값이 아니라 정의다.** REQ 가 *"유도 못 한 것은 그렇게 적어라"* 를 요구했으므로
분명히 한다 — *최소 표본 = 1* 은 계산 결과가 아니라 **탐침의 뜻 자체**다.

**③ 송신 지점을 한 곳으로 모았다** — `flush_downq(why, ignore_window, max_n)`.
**창 포기 경로도 같은 함수를 지난다. 우회 경로가 없다**(REQ 의 핵심 요구).

### 🔴 요구받은 값을 **낮추지 않았다. 그 이유가 이 결과의 본체다**

REQ: *"4보다 낮춰야 할 수 있다. 유도해라."* → **자료가 그것을 지지하지 않는다.**

REQ 인용: `[SLOT] ack= {0:133, 3:1, 8:7}` → *"부하에서 배출률이 6 밑으로 떨어진다"*

🔴 **이 추론이 성립하지 않는다. ack= 는 배출 *능력*이 아니라 실제 *배출량*이다.**
```
0 이 133슬롯  = **뺄 것이 없었다**(수요 0). 능력이 0 이었다는 뜻이 아니다
8 이 7슬롯    = 한 슬롯에 8개를 뺐다 → **능력 >= 8.** 능력의 **하한**이지 상한이 아니다
```
### **능력의 하한을 능력의 상한으로 읽었다.**
같은 이름(ack)이지만 **정의가 다른 두 값**이다 — 팀 규약(CLAUDE.md) 비교 규칙 ①(무엇을 세는가).
**이 자료로 N 을 낮추면 근거 없이 낮추는 것이다.**

**그래서 N=4 를 유지한다.** 낮출 근거가 생기려면 **"장치가 슬롯당 몇 개까지 뺄 수 있는가"를
직접 재야** 하고, 그건 ack= 분포가 아니라 **포화 시험**이다. 지금 그것을 요구하지 않는다.

### 그리고 이 수정이 고칠 것으로 **기대하지 않는 것**

**분당 1회 8초 침묵은 안 고친다.** 배치 36B 에서도 나므로 유입 축이 아니다(루트·monitor 판정 동의).
이 수정이 줄이는 것은 **oow(창 침범) 한 가지**이고, 그것은 **내 회귀**다 — 아래.

### ⚠ 자기 회귀 보고 — oow 8 → 47 은 내 변경의 결과로 본다 (가설 · 기전 있음)

```
건수 상한 전 : 한 창에 큐가 통째로 빠졌다(M 9B 면 21건) → **큐가 자주 비었다**
건수 상한 후 : 창당 4건 → **큐가 상시 비어 있지 않다**
창 포기 조건 : (큐가 안 비었다) + (S 가 2.4초 없다)  → 🔴 **첫 항이 훨씬 자주 참이 됐다**
```
**즉 건수 상한이 창 포기 경로의 발동 빈도를 올렸다.** 위 ①②가 그 되돌림이다.
⚠ **가설이다.** 확정하려면 배포 후 oow 가 8 근처로 돌아오는지 봐야 한다 —
**지금은 배포가 금지돼 있으므로 미검증으로 남긴다.**
