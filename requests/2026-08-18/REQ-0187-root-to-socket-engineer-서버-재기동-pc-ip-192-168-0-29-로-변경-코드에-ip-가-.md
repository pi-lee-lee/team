# REQ-0187 · 서버 재기동 — PC IP 192.168.0.29 로 변경 · 코드에 IP 가 있는지 확인 후 재기동 · inj7 예측 채점

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

🔴 **사용자 지시**: *"서버 ip 변경, 아두이노 재 플래싱, 서버 인스턴스 재기동이 필요하다."*

## 확인한 것 (루트 실측)

```
맥 현재 IP   192.168.0.29        ← ifconfig. 서브넷이 바뀌었다(192.168.35.x → 192.168.0.x)
서버         pid 4029 · build=aeb5283 · 8시간 30분째 · 아직 살아 있다
```

## 할 것 — 셋

### ① 서버가 IP 를 어디서 쓰는지 확인해라

**서버는 `0.0.0.0` 바인드일 것으로 보이지만 확인 안 했다.** 만약 어딘가에 IP 가 박혀 있으면
(설정·로그 표시·WS 주소·`index.html` 의 접속 주소) **거기도 바꿔야 한다.**
⚠ **특히 브라우저가 붙는 주소** — 사용자가 화면을 열 때 쓰는 URL 이 낡으면 안 붙는다.

### ② 서버 인스턴스 재기동

**바이너리는 그대로다**(`aeb5283`). 재빌드가 필요한지는 ①의 답에 달렸다 —
**IP 가 코드에 없으면 재기동만으로 끝난다.**

```
1) 재기동 전 monitor 통보 (관측은 지금 안 돌지만 창 경계는 남는다)
2) kill -TERM 4029  →  INSTANCE-END reason=normal 확인
3) cd ~/parking-bin  →  기동  (🔴 cd 를 빼면 GET / 가 404 다)
4) INSTANCE 줄로 build·ports·offset 확인
```

⚠ **백업은 이미 있다**(`srv_parking.prev-22f788d`). 바이너리가 안 바뀌면 새 백업은 불필요하다.

### ③ 재기동 뒤 장치가 붙는지 확인

**arduino 가 REQ-0186 으로 `SERVER_IP` 를 `192.168.0.29` 로 굽는다.**
**그 굽기가 끝나야 장치가 붙는다** — 순서는 **서버 재기동 먼저, 장치 굽기 나중**이 낫다
(장치가 붙을 서버가 이미 떠 있어야 재접속 대기가 짧다).

## 🔴 그리고 창 C 결과 — **네 예측 1번이 빗나갔다**

```
01:19 주입 전   oow=0    ssovf=0   cksumng=0
01:34 주입 후   oow=304  ssovf=4   cksumng=4      ← inj7 300건. 주입 구간에서만 증가
inj7 종료      01:34:13 · 시도 300 · ACK 296 · 미주입 3 · 응답없음 1 · 큐대기통보 297
```

**네 예측**: ① `cksumng → 0` · ② `재전송 > 0` 유지 · ③ `왕복 최대` 상승.

🔴 **①이 빗나갔다. `sendAck` 을 슬롯에 묶어도 파괴가 4건 남는다.**

**그런데 이게 나쁜 소식만은 아니다** — arduino 가 ①만 굽기로 한 이유가 정확히 이 갈래였다:

> *"①을 고친 뒤에도 파괴가 남으면 **`[CNT]` 가 독립 원인임이 확정**되고,
> 그 사건은 60초 주기라 깔끔하게 보인다."*

**즉 예측이 빗나간 것이 다음 원인을 지목한다.** 그리고 **축을 하나로 유지한 판단이 값을 했다** —
둘을 같이 고쳤으면 지금 무엇이 남았는지 못 갈랐다.

⚠ **판정은 monitor 가 한다.** 네 ②③ 채점과 **`재전송` 이 60초 주기인지**를 확인해서 넘겨라 —
**`재전송` 은 계측기 변경과 무관해서 창들을 잇는 유일한 칸**이고, 그것이 `[CNT]` 주기와 정합하면
독립 원인 가설이 강해진다.

## ⚠ 창 C 는 그 뒤 5시간 반 더 돌았다 — 그 구간은 별개다

```
07:06:52  [CNT] up=20760 drop=19 esprst=13 resync=30 okto=64 stuck=9 ssovf=14 cksumng=4 skip=383
07:22:37  «tap» 포트 복구 실패 6회 → 창 C 종료
```

🔑 **`cksumng` 은 4 에서 안 늘었다** — 5시간 반 유휴 동안 파괴 0건. **하행이 없으면 안 깨진다**는
arduino 의 유휴 기준선과 정합한다. 반면 `esprst=13`·`drop=19`·`stuck=9` 는 늘었다 —
**유휴 장시간 구간의 다른 이야기이고, 주입 구간과 섞으면 안 된다.**

**포트 이름이 `usbmodem21201` → `usbmodem1101` 로 바뀌었다**(USB 재연결). 그것이 탭이 죽은 이유다.

## 왜 필요한가

사용자가 PC IP 를 바꿨고 서브넷까지 달라졌다 — 서버가 IP 를 어디서 쓰는지 확인하고 재기동해야 장치가 새 주소로 붙을 수 있다. 그리고 창 C 에서 예측 1번이 빗나가 그 채점이 필요하다

## 완료 기준

① 서버 코드·설정·화면 접속 주소에 IP 가 박혀 있는지 확인 ② 재기동(monitor 통보 → 정상 종료 → cd ~/parking-bin → 기동 → INSTANCE 확인) ③ inj7 예측 셋 채점 ④ 재전송이 60초 주기인지 확인해 monitor 에 전달

① 서버에 IP 없음 확인(INADDR_ANY · index.html 하드코딩 0건) → 재빌드 불필요. 기술적으로는 재기동조차 불필요했다(0.0.0.0 이라 새 IP 로도 이미 받았다) — 사용자 지시라 진행했고 낡은 소켓 정리·창 경계 이득이 있다. ② 09:04:19 INSTANCE-END reason=normal(frames=19810) → 09:04:39 재기동 pid=79844 build=aeb5283 · 세 포트 LISTEN · GET http://192.168.0.29:9900/ → 200 검증. cd ~/parking-bin 지켰다. ⚠ 훅이 stderr 리다이렉션을 프로젝트 루트 기준으로 해석해 막았다(원장 §8.6) — 리다이렉션 빼고 띄웠다. ⚠ nohup 이 아니라 세션 백그라운드라 장기 운영엔 루트가 다시 띄우는 것이 안전하다. ③ 장치는 arduino 굽기 뒤 접속 예정.
