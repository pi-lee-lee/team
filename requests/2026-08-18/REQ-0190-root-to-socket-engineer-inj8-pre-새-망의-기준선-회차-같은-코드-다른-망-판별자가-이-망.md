# REQ-0190 · inj8-pre — 새 망의 기준선 회차 · 같은 코드 다른 망 · 판별자가 이 망에서도 서는지

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

**장치가 살아났다**(09:16:08 ESP 전원 리셋 · 사용자 조작). **새 망에서의 기준선 회차를 돌린다.**

## 복구 확인

```
09:16:24  ★ IP 확보: 192.168.0.214       ← 새 AP(3F_302) · 새 대역
09:16:27  +ARD 주차 노드 접속 · 세션#1 · device=P1
09:16:44  [TX] S,14,… → SEND OK · [SLOT] due=0
서버      pid 82879 · build=aeb5283 · PPID=1 · 세 포트 LISTEN
```

## 🔴 왜 기준선이 필요한가 — **네 중심 지표가 흔들렸다**

바뀐 것: **AP · 서브넷 · USB · ESP 전원**. **넷 다 지연·재전송·링크 안정성에 걸린다.**

```
지금까지 대조 불가 : oow(정의 변경) · ack=(정의 변경)
🔴 새로 흔들림     : 재전송 · 왕복        ← 망이 다르면 이것도 창 C 와 직접 비교 불가
```

**`재전송` 이 창들을 잇는 유일한 칸이었는데 그것도 못 잇는다.**
→ **이 회차가 새 기준점을 만든다.** 그 값 위에서 `cntTick` 효과를 잰다.

⚠ **펌웨어 코드는 `slot4` 와 같다**(접속 대상 셋만 바뀌었고 거동 변경 없음).
**즉 코드 축은 창 C 와 동일하고 망 축만 다르다** — **그래서 이 대비가 망 효과를 분리해 준다.**
🔑 **버리는 회차가 아니라, 오늘 유일하게 "같은 코드 · 다른 망"을 재는 회차다.**

## 명령 — 런북 그대로, `--rid-prefix inj8pre` 만

```
--interval 1.15 --count 300 --slot A1 --ack-timeout 10 --start-delay 0 --rid-prefix inj8pre
```

🔴 **한 글자도 바꾸지 마라.**
⚠ **monitor 의 창 D 개방 통보를 받고 시작해라.** 탭은 이미 돌고 있지만(`serial-winD.log`)
**monitor 가 경계를 확정해야 네 구간이 그 창에 귀속된다.**

## 이 회차가 답하는 것 셋

```
1. 새 망에서 cksumng 이 얼마인가          창 C 는 4 (inj7 300건)
2. 새 망에서 재전송이 얼마이고 [CNT] 주기와 정합하는가   창 C 는 16 = 파괴 4 + 늦은 ACK 12
3. 네 판별자가 새 망에서도 작동하는가       "재전송 직후 ≈1초에 `! 모르는 rid 의 ACK` 유무"
```

**3번이 특히 중요하다** — 그 판별자로 파괴와 잡음을 갈랐고, **망이 바뀌어 지연 분포가 달라지면
"≈1초" 라는 창 자체가 안 맞을 수 있다.** **그러면 판별자를 새 망 값으로 다시 세워야 한다.**

## ⚠ 예측을 자료 전에 적어라

창 C 에서 네 예측 ①이 빗나갔고 **그것이 다음 원인을 지목했다.** 이번에도 적어라 —
특히 **"망이 바뀌면 무엇이 달라질 것으로 보는가"** 를. 안 적으면 나중에 값을 보고
"망 때문이다/아니다"를 사후에 고르게 된다.

## 그 다음 순서 (변경 없음)

```
이 회차(기준선) → arduino ② cntTick 굽기 → inj8 → 판정 → 파괴 0 이면 측정 종료
그 뒤 : ACK_TIMEOUT 유도식 · 계측 넷
```

## 왜 필요한가

AP·서브넷·USB·ESP 전원이 다 바뀌어 재전송·왕복이 창 C 와 직접 비교가 안 된다 — 재전송이 창들을 잇던 유일한 칸이었다. cntTick 효과를 재려면 같은 망의 전/후가 필요하고 이것이 그 전이다
