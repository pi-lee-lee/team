## 너의 몫 — **브릿지 명세** (사용자 지시 2번)

> *"서버측에는 파킹 클래스와 아두이노모듈 클래스를 연결하는 브릿지 명세가 확립되어야 한다."*

**설계 문서 하나를 써라.** 위치는 `docs/net/` (네 소유). 아래를 담는다.

### ① 세 층의 자료 구조

```
Node   (통신 단위 = ESP 하나 = 소켓 하나)
   devid · 소켓 · 수신버퍼 · last_ms · downq · downq_bytes
   rtt_max_ms · win_skips · dmax_flushes · 그 노드의 계수기 전부
   🔴 지금 Server 에 전역으로 있는 것을 여기로 내린다

Module (devid 안에서만 유효한 name)
   전역 신원 = (devid, name)      ← 복합 키다. name 만으로 조회 금지
   종류: 주차확인센서 · 안내등 · 유도등 · 차단봉 · 입출차센서

Zone   (격자 위의 자리 · 입구 · 출구)
   zone id (전역 고유) · kind: parking|entrance|exit
   modules: [(devid, name), …]    ← 여러 노드에 흩어질 수 있다
```

**격자**: `cell → zone id`. 좌표와 신원은 **독립**이다 — 자리를 옮겨도 같은 자리여야 한다.

### ② 🔴 큐 메커니즘은 **노드마다 복제한다. 약화 금지**

사용자가 못 박았다: *"작동은 해야 한다!! 없애는 것이 아니다."*
**소스 대조 결과 네 `flush_downq` 가 사용자 서술과 정확히 같다** — 모아서 한 거래로, 넘치면 다음 창.

```
지금 : 이 상태 한 벌이 Server 에 전역   →  1개 노드만 대상이 된다
개정 : 노드마다 한 벌. 각 노드가 자기 주기로 자기 창에 자기 큐를 비운다
       규칙은 한 글자도 바뀌지 않는다
```

**약화 금지 항목** — 개정 중 이것들이 사라지면 창4 기전이 돌아온다:
`DOWN_BATCH_CAP_B` 상한 · `q_deferred` 계수 · `D_max` 창 포기 박자 · `queued` 응답 ·
배포 순서(큐를 `queued` 보다 먼저 올리지 않는다).

🔑 **그리고 노드가 여럿이어도 동시 전송은 자유다**(사용자 확정): 슬롯이 막는 것은
**같은 ESP 에게 주기 안에 두 번**이고, **다른 ESP 들에게 같은 순간에 보내는 것은 안 막는다.**
서버는 N 개 소켓에 동시에 write 한다. **시계 동기가 필요 없다.**

### ③ 하행 라우팅 — 명세의 중심

```
"zone A1 의 안내등을 켜라"
  → zone A1 의 modules 에서 (devid, name) 를 찾는다
  → 그 devid 의 Node.downq 에 담는다
  → 그 노드의 S 가 도착하면 flush            ← 창당 1거래가 노드별로 지켜진다
```

🔴 **`zone → [module]` 을 `[name]` 으로 적으면 안 된다** — 어느 장치인지 사라지고 보낼 곳을 모른다.
그리고 web 의 판정이 여기 걸린다: **"거짓 허용이 더 나쁘다 — 닿지 않는 장치로 하행을 보낸다."**
→ **조작 가능성은 모듈 단위로 판정한다**(그 모듈의 노드가 살아 있는가).

### ④ 🔴 장치 독립 — 고장이 번지지 않게 (사용자 확정)

> *"하나의 아두이노에 설치된 esp01이 와이파이를 잡지 못한다고 다른 아두이노 esp01에 영향을 주는 일은 없다."*

**지금 `OFFLINE_MS`·`ARD_IDLE_CLOSE_MS`·`first-S-wins` 는 "주차 노드가 하나"라는 전제 위에 있어서
그 하나가 죽으면 전체가 오프라인이다.** → **노드별로 갈라라.**
**한 노드의 오프라인은 그 노드가 담당하는 모듈만 미상으로 만든다.**

✅ 그리고 **`first-S-wins`·`aux_conflicts` 는 필요가 없어진다** — 그것이 있는 이유가
*"전선에 '내가 주차 노드다'라고 말하는 필드가 없다"* 인데, **모듈 등록이 장치를 명시하면 그 추측이 사라진다.**
**`AuxNode` 가 이미 `fd`·`buf`·`last_ms`·`frames` 를 갖고 있으니 그것을 하행 가능하게 키우면 곧 `Node` 다.**

### ⑤ 🔴 전선 예산 — 이게 명세의 제약이다. **arduino 와 합의해라**

**한 줄 64B 상한**이고 지금 `S` 프레임이 **55B** 를 쓴다. **여유 9B.**

```
지금 : 비트열 10칸 = 10B 로 10개 자리 상태를 전부 나른다   ← 극도로 압축적
ID   : "A1:1" 하나가 5B → 5개만 실어도 25B. 여유를 넘는다
```

| 방식 | 대가 |
|---|---|
| **비트열 유지 + 접속 시 `M` 프레임으로 순서 등록** | 전선 비용 0 · 등록 프레임 하나 추가 ← **유력** |
| ID 를 1~2자 + 상태를 여러 줄 | 배치 크기 증가 |
| 델타(변한 것만) | **상태 프레임이 멱등성을 잃는다** — 재접속 시 전체 재동기 경로 필요 |

🔑 **`name` 이 장치 안에서만 유효한 것이 첫 번째를 더 싸게 만든다** — 등록 프레임이 자기 소켓으로
오므로 **`devid` 를 항목마다 반복할 필요가 없다.**
⚠ **등록이 유실되면 이후 모든 상태가 잘못 귀속된다** → **등록 확인·재시도 규약을 명세에 넣어라.**

### ⑥ web 에 줄 계약 — 이미 확정된 다섯 (web 원장 §5.32)

1. **맵 정의를 상태와 별개로 준다**(격자·칸 목록·`kind`·모듈 목록).
   지금 `slots[]` 하나가 정의와 상태를 겸해서 **"없는 ID"가 "데이터 없음"인지 "존재하지 않음"인지 못 갈린다.**
2. **조작 가능성은 모듈 단위 판정**(`device.online` 단일 불리언 금지).
3. **`known` 이 모듈 단위로 내려간다** — 일부만 아는 상태가 **상시 정상**이다.
4. **`kind: parking|entrance|exit`** — 입구에 "예약됨"이 없다. 동일한 것은 구조이고 다른 것은 상태 어휘.
5. 🔴 **기존 `slots[]` 항목에 필드를 넣어 뜻을 바꾸지 마라 — 별도 키로 추가**한다.
   새 타입은 옛 화면이 조용히 무시해 안전하지만, 뜻이 바뀌면 **서버 배포가 그 순간 옛 화면을 깨뜨린다.**

## 이 REQ 에서 하지 말 것

- 🔴 **코드를 고치지 마라.** 명세만이다. 구현 순서는 명세가 합의된 뒤 별도 REQ 로 낸다.
- **`server.cpp` 를 건드리지 마라** — 지금 창 B 가 그 바이너리로 돌고 있다(`build=aeb5283`).
- **`inj5` 주입(REQ-0178)이 우선이다.** 그것과 이 문서 작업의 순서는 네가 정해라 —
  다만 **주입 중에 문서를 쓰는 것은 괜찮다**(자원이 다르다).

## 합의가 필요한 상대

- **arduino**: ⑤ 전선 예산 · `M` 프레임 형식 · 등록 재시도 규약
- **web**: ⑥ 계약 (web 이 요구로 올린 것이고 **합의는 아직이다** — web 이 그 구분을 지켰다)
- **루트**: 이름 갈래(`노드`/`자리`/`주기`)는 내가 정했다. 다르게 부르고 싶으면 말해라.

## 왜 필요한가

사용자 지시 2번(브릿지 명세 확립)이고, 지금 서버는 '주차 노드는 하나이고 그것이 모든 자리를 안다'를 79곳의 상태에 얽어 두었다 — 모듈이 여러 장치에 흩어지면 그 가정이 무너진다. 명세 없이 구현하면 그 79곳을 짐작으로 고치게 된다
