# REQ-0192 · 기록 공백 — cntTick 굽기 경과를 원장에 올리고 소스를 커밋하라 (착수 금지·정리만)

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

🔴 **원장이 `10:19` 에서 멈춰 있고 그 뒤 굽기가 REQ 없이 진행됐다. 그것만 메운다.**

## 내가 아는 것과 모르는 것

```
✅ 안다  : REQ-0186(IP·WiFi 재플래싱) 완료 10:19:07 · 칩 = slot4 + 접속 대상 셋
✅ 안다  : 창 E 판정문이 존재하고 파괴 0 이다. cntTick 이 슬롯에 묶인 것으로 보인다
🔴 모른다: cntTick 굽기가 언제였나 · 무엇을 정확히 바꿨나 · hex 대조 결과
🔴 모른다: 그 굽기에 다른 것이 같이 들어갔나 (계측 넷 중 무엇이든)
```

⚠ **누군가 네 창에 직접 지시를 넣은 것으로 보인다.** **탓하려는 게 아니다** — 결과는 좋다.
**문제는 "칩에 지금 무엇이 올라가 있나"가 다시 미상이 된 것**이고, 오늘 아침에 그것으로
반나절을 태운 기록이 `INTERVENTIONS.md` 첫 절에 있다.

## 할 것 ① — `req.sh notice` 로 굽기 경과를 올려라

```
· 굽기 시각 · 무엇을 바꿨나 (cntTick 만인가, 다른 것도 들어갔나)
· hex 대조 결과 (IDENTICAL 인가 · 어느 빌드와 대조했나)
· 회귀 시험 결과
· 굽기 직전 통보를 했나 · monitor 정지 확인을 했나
· INTERVENTIONS.md 에 기록했나
```

⚠ **모르는 칸은 "모른다"로 적어라.** 채우지 마라.

## 할 것 ② — 🔴 지금 칩 상태를 확정해라

**창 E 판정이 "이 펌웨어에서 파괴 0" 이라고 말하는데, 그 펌웨어가 무엇인지 원장에 없다.**
**판정과 대상이 연결되지 않으면 그 판정을 나중에 인용할 수 없다.**

**덤프 대조를 다시 할 필요는 없다** — 굽기 때 했으면 그 결과를 적으면 된다.
안 했으면 **지금 하지 마라**(개입이 하나 늘어난다). **"대조 안 했다"를 적는 것으로 충분하다.**

## 할 것 ③ — 소스를 커밋해라

`slot1`~`slot4` + 이번 굽기까지 **다섯 판이 미커밋 상태로 구워졌다.**
**주입이 끝났으니 지금이 커밋 시점이다**(편집 중 스냅샷 위험이 없다).

```
· 조별과제샘플/client.ino
· arduino/INTERVENTIONS.md
· arduino/.burn/ 의 hex (추적 대상이다 — .gitignore 예외로 넣어 뒀다)
· docs/arduino/ 원장
· REQ-0180 명세 (쓴 데까지 · 이어 쓰지 마라)
```

🔴 **`git commit -m "..." -- <경로>` 형태로 쳐라** — `add` 로는 남의 staged 가 딸려 온다(CLAUDE.md).

## 할 것 ④ — 다음 굽기 목록을 정리만 해 둬라 (착수 금지)

**측정이 끝나면 설계로 넘어간다.** 지금 남은 굽기 후보를 **목록으로만** 남겨라:

```
· 계측 넷 (lag · txdrop · ssovf 문맥) — 🔑 손실원이 없어졌으므로 이제 얹어도 안전한 국면이다
· 액추에이터 에코 (n 폭 비트열) — 설계 개정 항목
```

⚠ **굽지 마라.** 사용자가 측정 마무리를 지시했고, **계측기를 더 넣는 것은 새 측정을 여는 것**이다.
**목록과 근거만 남기면 재개할 때 그대로 쓴다.**

## 왜 필요한가

창 E 판정이 '이 펌웨어에서 파괴 0' 이라고 말하는데 그 펌웨어가 무엇인지 원장에 없다 — 판정과 대상이 연결되지 않으면 나중에 인용할 수 없다. 그리고 다섯 판이 미커밋으로 구워졌고 주입이 끝나 지금이 커밋 시점이다
