# REQ-0198 · 설계 재개 — 표시량 A 확정(칸 안에 다) · §5 시각 형태를 채워라

**요청자** `root` → **담당** `web-engineer`

## 요청 내용

**사용자 지시: "설계 진행하자" → "재개해라."** 그리고 **네 미결 하나가 답을 받았다.**

## ✅ 모듈 표시량 — **A(칸 안에 다 보이기) 확정**

```
┌─ 격자 ──────────────────────────┐
│ [입구]      [A1]       [A2]     │
│  차단봉 ○    센서 ●     센서 ○   │
│  입차센서 ●  안내등 ○   안내등 ● │
│             유도등 ⏱   유도등 ○ │
└──────────────────────────────────┘
```

**자리마다 모듈 상태를 전부 칸 안에 표시한다. 클릭·펼치기 없다.**
전문: `docs/DECISIONS-pending-user-2026-08-18.md` §①

## 🔴 대가는 알고 고른 것이다 — **그 대가를 설계로 다뤄라**

**자리 5개 × 모듈 3~4개 + 입출구 → 한 화면에 20~30개 상태.**
**요소 수가 많다는 것은 안 바뀐다.** 그것이 **읽을 수 없는 화면**이 되지 않게 하는 것이 네 몫이다.

🔑 **네가 이미 만든 규칙 둘이 그 일을 한다:**

1. **기호축 × 강조축**(원장 §5.33) — **강조축을 화면이 계산하지 않고 `actionable`/`blocked_reason`
   에서 파생으로 얻으므로 정상에서는 저절로 조용해진다.**
   → **20~30개가 다 떠 있어도 눈에 걸리는 것은 막힌 것뿐이다.**
   ⚠ **이 선택지에서 그 규칙의 값이 가장 크다.** 없으면 화면이 점 30개짜리 소음이 된다.

2. **미상 집계 한 줄**(§2.3) — 🔴 **"다 보이니 집계는 필요 없다"로 읽지 마라.**
   **20~30개 중 2개가 미상인 것을 눈으로 세는 것과 수로 읽는 것은 다르다.**

⚠ **§5.34.2 의 층 규칙이 문구를 정한다**: 액추에이터는 에코가 있어도
**"켜졌습니다"가 아니라 "장치가 켰다고 보고합니다"** 다.
🔴 **칸이 좁을수록 그 구분이 뭉개지기 쉽다** — **기호로 어떻게 가를지 네가 정해라.**

## 할 것 — §5 의 명시적 빈칸을 채운다

**규칙은 정해졌고 시각 형태가 남았다.** 네가 §5 에 격리해 둔 그 자리다:

```
· 칸 하나의 레이아웃 (자리 이름 · 모듈 목록 · 상태 기호)
· kind 별 차이 (parking 은 예약 상태가 있고 entrance/exit 은 없다)
· 빈 칸 / 미상 자리 / 정상 자리 셋을 시각으로 어떻게 가르나
· 미상 집계 한 줄의 위치와 문구
· 액추에이터 문구가 "보고한다"임을 기호로 어떻게 전달하나
```

⚠ **그리고 네 한계 서술을 유지해라**: *"원칙이 옳아도 형태가 그것을 전달하지 못할 수 있다."*
**형태를 정하는 것과 그것이 읽히는지는 다르다** — **브라우저로 보는 것은 구현 뒤다.**
**명세에는 "이 시점에 실측이 필요하다"를 적어라.**

## 🔑 서술 층을 갈라 적어라 — 사용자가 정한 형태다

```
✅ 확정  : 실측되거나 결정된 것
🔮 추론  : 근거를 같이 적는다 (근거 있는 추론은 자산이다)
⚠ 미측정: 안 재 본 것 — 시각 형태는 전부 여기다
```

## 참고 — socket 쪽 상태

**`kind` 별 유효 조작 표가 이미 도착했다**(명세 §6.5 · 커밋 `9b61c1b`). 그리고 socket 이
**REQ-0197 로 "자리가 여러 노드에 걸칠 때의 완료 판정"** 을 쓰고 있다 — **부분 완료를 화면에
어떻게 주는지가 거기서 나온다.** ⚠ **그 답이 오기 전에 부분 완료 표시를 확정하지 마라.**

## ⚠ 하지 말 것

- **코드를 고치지 마라.** 명세만이다.
- **시험 인스턴스를 띄우지 마라.** 임계값 스윕은 구현 단계다.

## 왜 필요한가

사용자가 표시량을 A(칸 안에 다 보이기)로 확정해 네 §5 명시적 빈칸을 채울 수 있게 됐다. 그리고 이 선택지는 한 화면에 20~30개 상태가 뜨므로 네가 만든 두 축 규칙과 집계 한 줄의 값이 가장 커지는 구성이다

### 0. 🔴 쓰다가 찾은 것 — `⏱` 가 **한 칸에서 세 뜻**이다

네가 요구한 *"기호로 어떻게 가를지 정해라"* 를 풀다가 나왔다. **이미 화면에 둘 있었다:**

| # | 어디 | 뜻 | 범위 |
|---|---|---|---|
| 1 | `.tile__stale` 칩 `⏱ N 전 값` | 화면 자료가 오래됐다 | 칸 · 일시 |
| 2 | 폴백 신선도(§5.31) | 장치 침묵의 **상한** | 장치 · 일시 |
| 3 | **모듈 미상(신규)** | 그 모듈 값이 안 온다 | 모듈 · **상시** |

**내가 §5.31 에 "이름이 비슷해서 섞기 쉬운 자리"라고 적어 둔 그 자리이고 `cap` 사고(§5.27)의
시각 판본이다.**

**결정: 겹쳐 쓴다. 기호를 늘리지 않는다.** 세 뜻이 전부 *"시간 때문에 확신할 수 없다"* 이고,
세 기호로 가르면 범례가 셋 는다 — **같은 생각에 다른 기호를 붙이는 것이 겹쳐 쓰는 것보다 나쁘다.**
대신 **다른 축으로** 갈랐다: **범위는 위치가**(칸 칩 대 모듈 행), **크기는 텍스트가** 말한다.
🔑 **그리고 강조축이 방어를 준다** — 조작을 막지 않는 `⏱` 는 조용하므로 **20~30개가 다 떠 있어도
눈에 걸리는 `⏱` 는 막는 것 하나다.** ⚠ **이 논거를 명세에 남겼다** — 안 적으면 다음 사람이
*"기호가 겹친다"* 만 보고 하나를 바꾼다. **`⚠` 를 오래됨에 쓰지 않는다**도 못 박았다.

**판별 시험을 문서에 박았다**: *칸 하나를 한 번 보고 `⏱` 의 범위가 구분되나.*
**텍스트를 읽어야 갈리면 30개 규모에서 기호가 일을 못 한다** → §11 의 첫 실측 대상이다.

### 1. 요구한 다섯 빈칸

| | |
|---|---|
| 칸 레이아웃 | §3 — 1행 요약 + 모듈 행 + 조작 버튼. **최악 칸을 ASCII 로 그렸다**(§3.2) |
| `kind` 별 차이 | §4.1 — `parking` 은 예약 어휘, `entrance`/`exit` 는 **차단봉 상태**. 🔴 §4.2 참조 |
| 빈 칸/미상/정상 | §5 — 테두리 없음 / 점선(현행 관습) / 실선. 🔴 §5.1 참조 |
| 미상 집계 | §6 — **기존 `#slots-banner` 자리**(새 자리를 만들지 않는다) · `unknown` 계열만 센다 |
| 액추에이터 "보고" | §7 — **기호가 아니라 이름에 `*`** |

### 2. 🔴 새로 나온 결론 — **칸이 버튼인 구조를 버려야 한다** (§4.2)

`actions` 가 조작별이 된 순간 **"칸 = 조작 하나"가 깨졌다.** 입출구는 조작이 둘이고
**버튼 안에 버튼을 넣을 수 없다**(HTML 무효 · 키보드·보조기술이 깨진다).
→ **칸은 컨테이너, 조작은 명시적 버튼.** ⚠ 대가(*"칸 아무 데나 눌러 예약"* 상실)를 적고
**뒤집힐 수 있는 자리로 표시**했다.

🔴 **그리고 이 전환에 하니스 셋이 걸린다**(§4.3): `e2e.mjs` · `queue-contract.mjs` ·
`queued-live.mjs` 가 전부 `.tile[data-slot=…]` + `data-action` 으로 고른다.
**§5.30 이 방금 가르친 것이라 명세에 박았다** — 구현 때 같은 커밋에서 고치고,
**고치기 전 판본에 돌려 빨간불을 먼저 확인한다**(§5.31 절차).

### 3. 🔴 접근성 — 빈 칸 18개가 탭 정지점이면 결함이다 (§5.1)

`5×5` 에 자리 5 + 입출구 2 → **빈 칸 18개**(**`칸수 − zone수` 파생값 · 격자 크기가 바뀌면 이 수도
바뀐다**). **전부 초점을 받으면 키보드 사용자는 자리에 닿기까지 18번 탭한다** —
시각 문제가 아니라 **접근성 결함**이다. → **빈 칸은 `aria-hidden` 장식**이고 초점을 안 받는다.
⚠ **빈 칸에 "상태 미상"을 쓰지 않는다** — 쓰면 **§6 집계가 18로 튀어 쓸모없어진다.**

### 4. ✅ 부분 완료 — **socket 답이 와서 구멍이 닫혔다** (§7.4)

REQ-0197 이 처리 중에 도착했다(명세 §3.5 · 커밋 `569b514`).

🔑 **A 안에는 펼치기가 없어서 `missing` 의 자리를 다시 정했다.** socket 은 *"펼쳤을 때만 쓰라"* 고
적었는데 **A 는 이미 모듈 행이 전부 보인다** → `missing` 은 **어느 행에 표식을 붙일지 알려 주는
입력**이다. **A 를 고른 대가가 여기서 이득으로 돌아왔다**(B 라면 *"부분 완료인데 어느 모듈인지
보려면 눌러야 한다"* 가 된다).

- **`ok/total` 은 `partial` 일 때만** 표시(socket 이 내 판단으로 남긴 것). **표에서 파생시켰다** —
  `total === 1` 이면 **`partial` 이 구조적으로 불가능**하므로 수가 정보를 더하지 않는다.
- **`partial` 은 일시 상태**라 **`busy` 표시 언어**를 쓴다(§5.36.1 · 선례는 아이들 1초).
  🔴 **미상 집계에 넣지 않는다.**
- 🔑 **화면이 "오래 남았다"를 스스로 판정하지 않는다** — 타임아웃 휴리스틱은 **화면이 짐작하는 것**
  이고(§5.14), **오래 남으면 서버가 `blocked_reason` 으로 말해 준다.**

### 5. 대가를 세어 뒀다 — 범례 부하 아홉 (§8)

색 4계열 · 점선 · 파선+맥동 · `⚑` · `⏱` 칩 · mine inset · `● ○` · `⏱` · `⚠` · `*`.
**§3.1 의 형제 명제다: 배울 것이 많은 범례는 아무도 안 읽는다.** **옵션 A 의 대가로 세어 적었다.**
🔮 그래서 **범례를 안 읽어도 통하는 하나**가 있어야 하고 그것이 **강조축**이다.

### 6. 서술 층 · 실측 시점 (요구대로)

**항목마다 `✅ 확정` / `🔮 추론` / `⚠ 미측정` 을 붙였다.** 🔴 **시각 형태 결정은 전부 `⚠` 다.**
§11 에 **실측이 필요한 시점**을 표로 박았다(판별 시험 · 범례 부하 · 49줄 밀도 · 스크린리더).

마지막에 규율 하나를 적었다: **하나라도 §11 을 통과하지 못하면 형태만 바꾼다 — 규칙(§5.33 두 축 ·
§5.34.2 층)은 그대로 둔다.** **규칙과 형태를 같이 흔들면 무엇이 틀렸는지 못 가른다.**

### 7. 남은 구멍 하나 (§10)

**`prefers-reduced-motion` 대체 신호.** 지금 `pending` 이 **맥동 하나**에 걸려 있는데
**§7.4.3 으로 대상이 늘었다** — `pending`·`busy`·`partial` 이 **전부 "곧 풀린다" 계열**이라
같은 전달자를 쓴다. **맥동 하나에 셋을 걸면 reduced-motion 에서 셋이 동시에 사라진다.**
**밀도와 겹치는 자리라 §11 실측에서 같이 본다.**
