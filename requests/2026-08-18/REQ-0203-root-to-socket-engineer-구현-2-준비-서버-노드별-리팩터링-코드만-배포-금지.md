# REQ-0203 · 구현 2 준비 — 서버 노드별 리팩터링 (코드만 · 🔴 배포 금지)

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

🔴 **2단계 준비 착수. 코드는 써라. 🔴 배포는 하지 마라.** (사용자 지시)

## 왜 지금은 준비만인가

**web 이 `cmdPending` 구멍을 고치는 중이고(REQ-0202), 사용자가 그것을 20개 연타로 검증한다.**
🔴 **그 검증 중에 서버가 바뀌면 검증이 흐려진다** — *"고쳐서 안 나는 건가 서버가 바뀌어서인가"*.

**파일은 안 겹친다**(화면 vs 서버)라 **코드 작성은 병행해도 안전하다.**
**배포만 막는다.** 검증 통과하면 내가 배포 신호를 준다.

## 할 것 — 명세대로 구현

**원본**: `docs/net/DESIGN-bridge-node-module-zone.md` (네가 쓴 것)
**계획**: `docs/IMPL-PLAN-2026-08-18.md` §2

### ① 전역 상태를 `Node` 로 내린다

```
ard_last_ms · ard_buf · downq · downq_bytes · rtt_max_ms · rtt_last_ms · rtt_n
win_skips · dmax_flushes · last_dmax_ms · q_deferred · q_rejected · q_nodev · q_dup
batch_count · batch_lines · q_dropped_link  …  그 소켓의 것 전부
```

🔑 **개념 변경이 아니라 그릇 변경이다.** 이미 "그 소켓의" 값이고 전역 변수에 담겨 있을 뿐이다.
**그래서 이 단계는 동작이 바뀌면 안 된다.**

### ② 🔴 약화 금지 — 사용자가 강조했다

> *"작동은 해야 한다!! 없애는 것이 아니다."*

```
DOWN_BATCH_CAP_B 상한 · q_deferred 계수 · D_max 창 포기 박자 · queued 응답 · 배포 순서
```

**규칙은 한 글자도 안 바뀐다. 한 벌을 N 벌로 만들 뿐이다.**

### ③ 같이 들어가는 것 (명세에 있다)

```
· Zone / Module 자료 구조 — 전역 신원은 (devid, name) 복합 키
· 하행 라우팅 — zone → (devid,name) → 그 노드의 큐
· actionable / blocked_reason 계산 (web 계약 · 네가 계산 주체다)
· 맵 정의를 상태와 별도 키로 (기존 slots[] 에 얹지 마라 — 옛 화면이 깨진다)
· 완료 판정 — 대상 모듈 전부 에코 일치일 때만 done · partial 을 감추지 않는다
```

⚠ **`first-S-wins`·`aux_conflicts` 는 없어진다** — 모듈 등록이 장치를 명시하므로 추측이 불필요하다.
**지우면서 그 이유를 주석에 남겨라** — 그 규칙이 왜 있었는지가 소스에 적혀 있다.

## 🔴 끝의 조건 — **노드 1대로 지금 동작이 그대로 유지되는 것**

```
· --selftest 전부 통과 (지금 44건)
· 회귀가 먼저다. 새 기능 검증을 시도하지 마라 — 보드가 한 대뿐이다
· 🔴 재전송이 회귀 지표다 (1단계 배포로 파괴만 센다 · 깨끗해졌다)
```

⚠ **"2대에서 되는가"는 이 단계의 질문이 아니다.** 그건 실측이 필요하고 보드가 없다.
**명세에 그렇게 적혀 있고 그대로 지켜라.**

## ⚠ 하지 마라

- 🔴 **배포 금지.** 빌드·`--selftest` 까지만. **내가 신호를 준다.**
- **운영 서버(`pid 80947` · `build=c719d87`)를 건드리지 마라.** 사용자가 지금 그것으로 검증한다.
- **시험 인스턴스도 띄우지 마라** — 사용자 브라우저가 `9900` 에 붙어 있고 검증 중이다.
- **커밋은 해도 된다**(배포와 별개다). `git commit -m "..." -- <경로>` 형태로.
