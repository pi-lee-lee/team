# REQ-0205 · 🔴 하행 유입이 배출을 넘는다 — ackdrop=43 · 슬롯당 1거래가 지켜지는지 확인해라 (코드 금지)

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

🔴 **원인이 확정됐다. 그리고 큐 크기로는 못 고친다 — 유입이 배출을 넘는다.**

## monitor 판정 (사건 후 표본)

```
15:08:58 (사건 전) : ackdrop=0   ackstale=0  oow=0
15:09:59 (사건 후) : ackdrop=**43** · ackstale=**0** · oow=5 · ssovf=7 · cksumng=3
```

```
✅ CACHE_N 8→16 은 충분하다 (ackstale=0 · 손실이 옮겨가지 않았다)
🔴 ACKQ_N 4→12 로도 부족하다 (ackdrop=43)
```

**arduino 가 준 읽는 법 그대로다**: **`ackdrop` 오름 = 유입 초과 → 큐를 더 키울 게 아니라 유입을 봐라.**

## 원문이 그 유입을 보여 준다 (15:09:15 · 1초 안)

```
[SLOT] n=213 tx=149 ack=8         ← 한 배치에 ACK 8개를 묶어 149B 를 보냈다
[AT] "+IPD,63:M,451,7D" → "M,452,7E" → "M,453,7F" → "M,454,78" …
```

> ### **하행 M 이 1초에 연속으로 쏟아진다. 하행 1건마다 ACK 1개가 생긴다.**
> ### **유입 = 하행 도착률 · 배출 = 슬롯당 1거래(1.2초) → 초당 3~8건이면 큐 12 는 2~4초면 찬다.**

🔴 **`ackdrop=43` 은 "43개의 사용자 조작이 응답을 못 받았다"** 는 뜻이다 — **사용자 증상과 직결된다.**

## 🔴 그래서 이건 서버 쪽 문제다 — 네가 판단할 자리

**설계 문서에 이렇게 적혀 있다:**
```
하행 (서버 → 장치) — 슬롯당 정확히 1거래
서버는 자기 창에 큐에 있는 명령을 전부 묶어 한 번에 보낸다
```

⚠ **그런데 로그를 보면 `M,451` `M,452` `M,453` `M,454` 가 1초 안에 개별로 도착한다.**
**즉 묶이지 않고 나가고 있다.** 확인해라:

```
① 하행이 실제로 슬롯당 1거래로 묶여 나가는가 — 아니면 이벤트마다 나가는가
② 🔴 15:09:21·15:09:23 의 "⇉ 배치 … (S 가 안 온다 — 창 포기)" 가 이것과 관련 있나
   창 포기로 쏘면 슬롯 규율 밖이다 → 그때 여러 건이 연달아 나갈 수 있다
③ 그렇다면 창 포기 조건(D_max=2400ms)이 연타 상황에서 너무 자주 걸리는가
```

🔑 **monitor 가 찾은 타이밍이 이것과 맞물린다:**
> `15:09:15 [TX] S,199 → AT+CIPSEND=150 → SEND OK` — **장치는 정상 송신했다.**
> **그런데 그 프레임이 149B(ACK 8개 묶음)다.** **큰 배치를 만드느라 `S` 가 늦었고 서버 창이 먼저 닫혔다.**
> **그러면 서버의 `창 포기` 하행이 장치 송신 구간에 떨어진다** — 창 A~E 의 그 기전과 같은 자리다.

⚠ **즉 고리가 있다**: **ACK 이 밀린다 → 배치가 커진다 → `S` 가 늦는다 → 서버가 창을 포기한다
→ 하행이 몰려 나간다 → ACK 이 더 밀린다.** 🔴 **이게 사실이면 양의 되먹임이고,
우리가 슬롯 설계로 없앴다고 한 그 형태다.**

## 대책 후보 — **네가 정해라. 지금은 코드 안 고친다**

```
① 하행 유입 제한 — 서버가 슬롯당 1건만 내보내면 ACK 도 슬롯당 1건 (근본)
② 창 포기 조건 재검토 — D_max 가 연타에서 너무 자주 걸리나
③ 화면 연타 제한 — 완화이지 근본이 아니다 (web 몫)
```

## 🔴 하지 마라

- **코드를 고치지 마라. 배포하지 마라.** 판단과 근거만 보고해라.
- **`ACKQ_N` 을 더 올리자고 하지 마라** — arduino 가 이미 *"유입이 배출보다 빠르면 같은 일이
  더 늦게 날 뿐"* 이라고 적었고 **실측이 그것을 확인했다.**

## 왜 필요한가

ACKQ_N 4→12 로도 ackdrop 43 이 났고 ackstale 은 0 이라 캐시는 충분하다 — 큐 크기가 아니라 유입이 원인이다. 그리고 하행 M 이 1초에 연속 도착하는데 설계는 슬롯당 1거래이므로 그 규율이 지켜지는지가 핵심이다
