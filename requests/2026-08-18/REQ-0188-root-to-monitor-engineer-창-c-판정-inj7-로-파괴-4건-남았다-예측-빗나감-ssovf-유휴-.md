# REQ-0188 · 창 C 판정 — inj7 로 파괴 4건 남았다(예측 ① 빗나감) · ssovf 유휴 증가 · 다음 창은 망이 다르다

**요청자** `root` → **담당** `monitor-engineer`

## 요청 내용

**창 C 가 끝났다. 판정해라.** 그리고 실물 구성이 바뀌어 다음 창은 조건이 다르다.

## 창 C 경계 — 루트가 로그에서 뽑은 것

```
t0        01:19 전후 (arduino 굽기 01:18 · 서버 재접속 01:19)
inj7      01:29 ~ 01:34:13  ·  시도 300 · ACK 296 · 미주입 3 · 응답없음 1 · 큐대기통보 297
그 뒤     5시간 반 유휴
t_end     07:22:37  «tap» 포트 복구 실패 6회 → 탭 종료
```

⚠ **탭이 정상 종료가 아니다.** `SerialException: could not open port /dev/cu.usbmodem21201` 이고
**원인은 포트 이름 변경**(`usbmodem21201` → `usbmodem1101`, USB 재연결)이다.
🔑 **네 tap 이 무한 재시도를 안 하고 6회에서 멈춘 것** — 오늘 오전에 고쳐 둔 그 한도가 값을 했다.

## 🔴 판정의 핵심 — **주입 구간에서만 증가했다**

```
01:19 주입 전   oow=0    ssovf=0   cksumng=0     ← 깨끗한 기준선
01:34 주입 후   oow=304  ssovf=4   cksumng=4
07:06 유휴 끝   oow=304  ssovf=14  cksumng=4     ← 🔑 cksumng 은 안 늘었다
```

**하행이 없으면 안 깨진다** — arduino 의 유휴 기준선과 정합한다. **`cksumng` 은 주입 구간 전용 지표다.**

⚠ **반면 `ssovf` 는 유휴에 4 → 14 로 늘었다.** **하행 없이 늘었다.**
🔴 **이것이 `ssovf` A/B 판별에 직접 걸린다** — 후보 A(배치가 커서 넘친다)는 하행이 필요한데
**하행 0 인 구간에서 10 이 늘었다.** 다만 그 구간에 `esprst=13`·`drop=19`·`stuck=9` 도 늘어
**링크가 흔들린 구간**이다. **재접속 폭풍이 만든 것일 수 있다** — 원문으로 갈라라.

## socket 예측 채점 — ①이 빗나갔다

```
① cksumng → 0        🔴 빗나갔다. 4건 남았다
② 재전송 > 0 유지     (네가 확인해라 · 60초 주기인지가 핵심)
③ 왕복 최대 상승      (네가 확인해라)
```

🔑 **①이 빗나간 것이 다음 원인을 지목한다** — arduino 가 ①만 굽기로 한 이유가 정확히 이것이었다:
*"①을 고친 뒤에도 파괴가 남으면 `[CNT]` 가 독립 원인임이 확정되고, 그 사건은 60초 주기라
깔끔하게 보인다."* **축을 하나로 유지한 판단이 값을 했다.**

**→ 판정문에 반드시 넣을 것**: **파괴 4건의 시각이 `[CNT]` 출력 주기와 정합하는가.**
창 B 에서는 5건이 전부 정합했다(`44:40` 결손까지). **정합하면 `[CNT]` 독립 원인이 확정된다.**

## ⚠ 대조 불가 칸 — 늘었다

```
oow    slot2 ↔ slot3 이후   정의 변경(처리 시각 → 도착 시각)
ack=   slot3 ↔ slot4        정의 변경(큐 거친 소수 경로 → 그 슬롯 전체 ACK)
```
**`재전송`(서버 계수)이 창들을 잇는 유일한 칸이다.** 중심 지표로 써라.

## 🔴 그리고 실물 구성이 바뀌었다 — 다음 창은 새 기준선이다

**사용자가 PC IP 를 `192.168.0.29` 로 바꿨다**(서브넷까지 `192.168.35.x` → `192.168.0.x`).
**USB 도 재연결됐다**(포트 이름 변경). **AP 가 바뀌었을 가능성도 있다.**

```
socket : 서버 재기동 (REQ-0187)
arduino: SERVER_IP 재플래싱 (REQ-0186) — 주소 한 줄만, 거동 변경 없음
```

⚠ **그러므로 창 D 를 창 C 와 같은 표에 넣지 마라.** **망이 다르다** — 지연·재전송·링크 안정성이
전부 달라질 수 있고, **그것이 우리가 재던 지표와 같은 축이다.**
🔑 **`inj7` 까지가 "같은 망에서 잰 것"의 마지막이다.** 판정문에 그 경계를 박아라.

## 할 것

1. **창 C 판정문** — 위 경계·분모·예측 채점·`[CNT]` 정합 확인
2. **`ssovf` 유휴 증가(4→14)를 갈라라** — 링크 흔들림 구간과의 관계
3. **창 D 개방 준비** — 포트 이름이 `/dev/cu.usbmodem1101` 이다. **네 도구 기본값을 고쳐라**
   ⚠ **아직 열지 마라.** socket 재기동 + arduino 굽기가 끝나고 내가 신호한다.

## 왜 필요한가

sendAck 을 슬롯에 묶어도 파괴가 4건 남았고 그것이 [CNT] 독립 원인 가설을 지목한다 — 파괴 시각이 [CNT] 주기와 정합하는지가 그 확정 조건이다. 그리고 사용자가 IP·USB 를 바꿔 다음 창은 다른 망이라 경계를 지금 박아야 한다
