# REQ-0196 · 설계 재개 — ESP 클래스 명세(REQ-0180)를 마저 써라 · cntTick 자리도 표에 넣어라

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

**사용자 지시: "설계 진행하자."** 측정이 종료됐다. **REQ-0180(ESP 클래스 명세)을 재개해라.**

## 측정 종료 상태 — 네 명세가 딛고 설 바닥

```
✅ 확정 : 하행 파괴의 원인은 [CNT] UART 블로킹. 슬롯에 묶으니 0 (분모 300 · 세 회차)
✅ 확정 : 큐가 링크 붕괴를 막았다 · 왕복은 슬롯 대기가 정한다(1229·1225·1230)
🔮 추론 : 노드가 독립이므로 N 개로 늘려도 각 노드 안에서는 같을 것이다
          근거 — 충돌은 장치 내부 UART 를 둘이 다툴 때 생겼고, 노드가 분리되면 그 자원이 각자다
⚠ 미측정: 다중 노드를 실제로 돌린 적이 없다. WiFi 대역 공유가 유일한 미지수다
```

🔑 **사용자가 이 형태를 원했다**: *"이 구조면 예상은 문제가 없어야 하는데 실제는 다를 수 있다."*
**명세에도 그 층을 갈라 적어라** — 확정 · 추론(근거 포함) · 미측정.

## 할 것 — REQ-0180 의 셋을 마저 쓴다

### ① ESP 클래스 — `init` / `read` / `write` / `reset`

**확정 사항**(사용자·루트):
- **`reset()` 의 정의를 좁히지 마라**: *"링크 상태를 유지한다 — 안 서 있으면 세우고,
  오래 서 있었으면 방어를 낮춘다."* 🔴 조기 반환 앞의 하강 로직(30초 온라인 → 0단)이 갈 곳이다.
- **`init` 은 사다리만 시작한다**(안 A). **`init()` 이 진짜로 아는 것은 "UART 를 열었다"뿐**이다.
- **3단 게이트·`busy` 대응은 `write` 안**, **리셋 계단은 `reset`**.

🔴 **명세의 중심은 경계 표다**: 지금 `netTick`·`sendLine` 에 섞여 있는 것을 **넷 중 어디로 나누는가.**

⚠ **그리고 측정이 그 표에 항목을 하나 추가했다**: **`cntTick`(디버그 출력)이 어디 사는가.**
**그것이 손실원이었고 슬롯에 묶어서 고쳤다.** 넷 중 어디에도 안 들어가면 다시 밖으로 샌다.

### ② 자리·모듈 유동화

**지금 `S` 프레임은 자리 ID 를 안 싣고 비트 순서가 신원을 대신한다.**
→ **개수를 바꾸면 같은 비트가 다른 자리를 뜻하고 서버와 조용히 어긋난다.**
**장치가 아는 것은 `(자기 name) → pin` 뿐이고 `zone` 을 모른다.**

### ③ 전선 예산 — **socket 명세 §5 에 등록 규약이 이미 확정돼 있다**

`docs/net/DESIGN-bridge-node-module-zone.md` §5 를 읽어라 — **`D`/`Q` 프레임 · `n` 종료 조건 ·
`REG_TIMEOUT = 3 × 슬롯주기` · `Q` 3회 상한**이 들어가 있고 **네 합의가 반영된 것으로 보인다.**
**그러면 네 명세는 그것을 참조하고 장치 쪽 구현 관점만 적으면 된다** — **복사하지 마라**(두 곳에 있으면 하나가 낡는다).

## 🔴 그리고 socket 명세 §7 의 미결 다섯 중 둘이 네 도메인이다

```
3. 노드 수 상한 — 🔴 계산으로 못 닫는다. WiFi 공유 매체라 실측이 필요하다 (네 §3 과 같은 축)
4. cap 이 노드마다 다를 수 있는가 — 회선 속도가 다르면 그렇다. 지금은 전역 하나다
```

**답을 지금 내지 마라.** **"실측이 필요하다"를 명세에 그대로 적고 무엇을 재야 하는지만 적어라** —
**보드가 한 대뿐이라 지금 못 잰다.** 그 사실도 같이 적어라.

## 하지 말 것

- 🔴 **굽지 마라. 코드를 고치지 마라.** 명세만이다.
- **계측 넷도 아직 굽지 마라** — 재개 순서상 `ACK_TIMEOUT` 수정이 먼저다(socket).
- **관측은 지금 안 돌고 있다.** 새로 열지 마라.

## 왜 필요한가

측정이 끝나 사용자가 설계 재개를 지시했다. 그리고 측정이 경계 표에 항목을 하나 추가했다 — cntTick 이 손실원이었고 넷 중 어디에도 안 들어가면 다시 밖으로 샌다

**처리자** `arduino-engineer` · 2026-08-18 · 📄 **`docs/arduino/DESIGN-esp-class-and-modules-2026-08-18.md`**

### ① ESP 클래스 — 넷의 경계 표 ✅

`init` / `read` / `write` / `reset`. **3단 게이트·`busy` 대응·프롬프트 대기는 `write` 안**(§6.1 —
실패 모드별 제어 경로를 밖으로 꺼내지 않는다).

🔴 **`reset()` 정의를 좁게 쓰지 말라고 못박았다** — *"링크가 죽었을 때 세운다"* 로만 적으면
**온라인 경로의 일**(30초 연속 온라인 시 사다리 하강)이 갈 곳을 잃는다. 그건 "세우는 것"이 아니라
**"안 세워도 된다는 판정"** 이다. **사라지면 사다리가 영원히 높은 단에 머물러 다음 사고 때
4단(하드리셋)부터 시작한다.**
★ 일반화: **함수를 쪼갤 때 "온라인일 때 하는 일"도 세어라. 조기 반환 앞의 코드는 눈에 안 띈다.**

**`init()` 반환값**: ⚠ **진짜로 아는 것은 "UART 를 열었다"뿐이다**(사다리 1단 응답은 비동기).
그 이상을 담으면 거짓이다. 둔다면 **"모듈 기동 실패"와 "아직 링크 없음"을 갈라야** 한다.

### ② 🔴 측정이 추가한 항목 — `cntTick` 은 **ESP 클래스 밖, 슬롯 규율 안**

```
[CNT] 는 하드웨어 Serial(USB)로 나간다 → ESP 클래스의 일이 아니다
그런데 60초마다 하행을 깼다(창 B 5 · C 4 · D 3, 전부 정합) → 슬롯 규율의 대상이다
```
> ### **그래서 규율의 정의가 넓어진다: ~~"ESP UART 를 쓰는 것"~~ → "loop 를 막는 모든 것".**

**두 축이 직교한다**는 표를 명세에 넣었다(ESP 클래스 / 슬롯 규율).
⚠ **`reset()` 의 사다리 명령이 슬롯 규율 대상인지는 안 쟀다** — 🔮 대상일 것이나 **미측정**으로 표시.

### ③ 자리·모듈 유동화

**장치는 `name → pin` 과 `kind` 만 안다. 구역은 서버가 조립한다.**
🔴 **장치가 구역을 알면 배선이 바뀔 때마다 펌웨어를 다시 굽는다** — `SERVER_IP` 사고(§5.7)와 같은 형태.
**출력 모듈도 상태 비트열에 넣는다**(ACK 은 "받았다"이지 "됐다"가 아니다).
⚠ **다만 출력 핀은 되읽기가 없으면 장치도 조작 실패를 모른다** — 상태 비트는 **"우리가 그렇게 썼다"**
까지다. 그 한계를 계약에 적어야 한다.

### ④ 전선 예산 — **socket 명세 참조. 복사 안 했다**

`docs/net/DESIGN-bridge-node-module-zone.md` §5. **두 곳에 있으면 하나가 낡는다.**

### ⑤ 미결 — **실측 필요 · 지금 못 잰다**

| 미결 | 왜 지금 못 하나 | 무엇을 재야 하나 |
|---|---|---|
| 노드 수 상한 | 🔴 **보드가 한 대뿐이다** | 노드를 늘리며 `[SLOT] due=` 분포 · 서버 `왕복 최대` |
| `cap` 이 노드마다 다른가 | 〃 | 두 대 이상에서 같은 주입 → 노드별 왕복 비교 |
| `reset()` 이 규율 대상인가 | 안 재 봤다 | 사다리 구간의 하행 도착 겹침 |
| **하행 동시성(최대 1.2초)** | **사용자 결정이 먼저다** | 1.2초를 허용하면 아무 작업도 필요 없다 |

🔑 **서술 층을 갈라 적었다**(✅확정 / 🔮추론+근거 / ⚠미측정) — 사용자가 정한 형태 그대로.

### 하지 않은 것

**굽지 않았다 · 코드 안 고쳤다 · 관측 안 열었다.** 명세만이다.
