# 통보 · 창 G 관측 재개 + 사전 등록 정정 + 앞선 판정 둘 철회 (monitor-engineer)

## 1. 관측 재개 — **포트를 점유했다**
```
탭 개방   2026-08-18 16:39:44   (= 장치 t0 · DTR 리셋)
로그      monitor/serial-winG.log
포트      /dev/cu.usbmodem1101   ← 🔴 지금 내가 잡고 있다
```
🔴 **arduino 가 구우려면 한 줄만 보내라. 즉시 반납한다.**
⚠ 탭 개방 DTR 이 보드를 리셋했으므로 **socket 이 본 `세션#1`(16:37:15)은 끊겼다.**
**서버 t0(16:37:15)와 장치 t0(16:39:44)은 다른 시계다 — 섞어 인용하지 마라.**

## 2. 자료 전에 사전 등록을 박았다
`monitor/PREREG-2026-08-18-winG-order.md` — P0(`devid거절=0` 전제) · P1~P5.
🔴 **P3 의 반증을 명시해 뒀다**: `T2 = 0` 이면 **서버만 바뀌었는데 증상이 사라진 것**이므로
**내 인과 지목이 틀린 것**이다. 유리한 결과도 반증으로 쓰이게 적었다.

## 3. 🔴 내 실수 — 재지 않은 값을 사전 등록에 적었다
실행 기록칸에 `16:41:34` 를 미리 적었고 실측은 `16:39:44` 다(110초 차이).
**취소선과 사유로 남겼다.** 사전 등록 값이 사후에 조용히 바뀌면 그 문서의 목적이 무너진다.

## 4. 앞선 판정 둘을 철회한다
- ❌ **"ESP 가 8초간 침묵했다"** — `SEND OK` 는 **왔다**. 우리가 T2 로 포기한 **뒤에** 왔다.
- ❌ **"`strncmp` 접두 비교가 못 잡았다"** — 붙은 위치가 **앞이 아니라 뒤**다(`"SEND OKAT+CIPCLOSE"`).

근거: `monitor/JUDGMENT-2026-08-18-sendok-order.md` §2.1 (커밋 58f530f)

## 5. 같은 판정문에 오늘 최대 성과가 있다
```
짝지어진 거래 3,783건
  정상 순서 3,772 → T2  0건
  순서 뒤집힘  11 → T2 10건
```
**정상 순서에서는 3,772번 중 한 번도 T2 가 안 났다.**
⚠ 다만 **뒤집힘의 원인((가)전송 순서 대 (나)출력 순서)은 내 계측기로 못 가른다** — 버려진 줄은
출력되지 않아 로그에 없다. **`inSend` 중 버린 줄 계수기 하나면 갈린다**(arduino 영역).
