# REQ-0200 · 구현 1 — ack_budget_ms 경로 확인 · socket 과 같은 배포 (화면 개정은 4번이다)

**요청자** `root` → **담당** `web-engineer`

## 요청 내용

🔴 **구현 착수. 1단계다.** 계획 전문: `docs/IMPL-PLAN-2026-08-18.md`

⚠ **사용자가 한도 임박을 알렸다.** 세션이 끊겨도 이어받게 **진행 상황을 원장에 자주 남겨라.**

## 이번엔 화면 개정이 아니다 — **타이머 하나다**

socket 이 `ACK_TIMEOUT` 유도식을 고친다(REQ-0199). **`ack_budget_ms` 가 그 값에서 계산되므로
화면 타이머가 같이 움직인다.**

🔴 **같은 배포여야 한다.** 서버만 올라가면 **화면이 옛 예산으로 돈다** —
socket 원장 §8.23-(36) 이 그 제약을 적어 뒀고 내가 *"그 구간이 생긴다"* 를 덧붙였다.

## 할 것

1. **`ack_budget_ms` 를 받아 쓰는 경로가 새 값에 그대로 대응하는지 확인해라.**
   ⚠ **네 §5.28 처리가 이미 "서버가 값으로 준다"라면 화면 코드 변경이 없을 수도 있다** —
   **그러면 "변경 없음"을 확인하고 그렇게 보고해라.** 없는 작업을 만들지 마라.
2. **socket 과 배포 시점을 직접 맞춰라.** 내가 중계하면 늦는다.
3. **배포 뒤 실측**: `queued` 왕복이 새 예산으로 도는가.
   ⚠ **시험 인스턴스가 필요하면 socket 에 요청해라** — 운영에 붙지 마라.

## 🔴 그리고 2단계 이후를 미리 알아 둬라 — **네 차례는 4번이다**

```
1. ACK_TIMEOUT (지금 · 너와 socket)
2. 서버 노드별 리팩터링 (socket)
3. 펌웨어 (arduino)
4. 🔴 화면 — 격자 · 모듈 행 · 버튼 분리 · 하니스 셋   ← 네 큰 작업
```

**4번이 3번 뒤인 이유**: **서버가 새 계약(맵 정의·모듈 목록·`actions`)을 주기 시작해야 그릴 것이 있다.**
⚠ **지금 화면 개정에 착수하지 마라** — 계약이 안 오는 상태에서 만들면 **가짜 자료로 만든 화면**이 된다.

**다만 준비는 해도 된다**: **하니스 셋의 선택자 변경**(`.tile[data-slot]` → 새 구조)은
**네 명세 §4.3 에 이미 적혀 있고 서버 계약과 무관하다.** **그 계획을 다듬어 두면 4번이 빨라진다.**
🔴 **코드는 고치지 마라** — 지금 하니스가 도는 화면은 아직 옛 구조다.

## 끝의 조건

```
· ack_budget_ms 경로 확인 (변경 필요/불필요 판정)
· socket 과 같은 시점에 배포
· queued 왕복이 새 예산으로 도는 것 확인
```

## 왜 필요한가

socket 이 ACK_TIMEOUT 을 고치면 ack_budget_ms 가 그 값에서 계산되므로 화면 타이머가 같이 움직인다 — 서버만 올라가면 화면이 옛 예산으로 도는 구간이 생긴다

### 1. ① 경로 확인 — ✅ **화면 코드 변경 불필요** (전수 grep 근거)

`grep ACK_TIMEOUT|ack_budget_ms|deadlineAt` 로 전수 확인했다. 화면 상수 `ACK_TIMEOUT`(6000)이
살아 있는 곳은 **셋뿐이고 예약 경로의 서버 예산과 무관하다:**

| 어디 | 무엇을 재나 | 서버 예산 |
|---|---|---|
| `markPending` 최초 타이머 | **서버가 아무 말도 안 할 때** | ❌ `queued` 는 서버-로컬 |
| `onSelfTimeout` 문구 | 위 타이머의 사유 | ❌ |
| `cmdPending`(테스트·시뮬) | 그 명령 응답 대기 | 🔴 **걸린다 — §3** |

**예약 타이머는 `exp + budget` 이고 둘 다 서버가 프레임마다 주는 값이다**(원장 §5.26).
→ socket 이 `ACK_TIMEOUT_MS` 를 1500→2400 으로 올려 `ack_budget_ms` 가 **9900→12600** 이 돼도
**화면은 받은 값을 그대로 쓴다.**

### 2. 🔴 ② 배포 조율 — **"같은 배포" 제약이 화면에는 없다** (정정)

네가 걸어 둔 제약(*"서버만 올라가면 화면이 옛 예산으로 돈다"*)을 확인해 보니 **그 구간이 없다.**
화면은 예산을 **캐시하지 않는다** — `Number(msg.ack_budget_ms)` 를 **`queued` 프레임마다** 읽는다.
→ **배포 직후 첫 `queued` 부터 새 값이다.** 남는 창은 **배포 순간 이미 날아가 있던 요청 한 건의
수명**뿐이고 지속되지 않는다.

🔑 **REQ-0166 에서 "서버가 계산해 값으로 준다"로 정한 설계의 배당금이다** — 그 결정이
**오늘 화면 변경을 0으로 만들었다.** → **socket 에 "나를 기다리지 말고 배포하라"고 직접 전했다.**

### 3. 🔴 인접한 구멍 — 테스트·시뮬 경로에 REQ-0166 구멍이 남아 있다 (소스 판독)

`queued` 분기가 **`state.pending` 만 보고 `state.cmdPending` 은 안 본다.** 그런데 socket 명세는
**`M`·`T` 도 같은 큐를 탄다**고 정했다 → **그 명령은 큐에 담기고 `queued` 가 오는데 화면이 조용히
버리고 6초 고정 타이머로 거짓 실패 문구를 낸다.**

⚠ **실측이 아니라 소스 판독이다.** 피해는 예약보다 작다(진단 기능이고 화면 상태를 안 바꾼다).
🔴 **이번 배포에 끼워 넣지 않았다** — **한 교체에 변경 둘을 넣지 않는다**(socket 이 REQ-0166 때
`ACK_TIMEOUT_MS` 를 일부러 안 건드린 것과 같은 이유). **별건으로 처리한다.**

### 4. 🔴 socket 이 확인해 달란 것 — 하니스의 `9900` 한 곳 · **깨져서 고친 게 아니다**

`queue-contract.mjs` 의 `SRV_BUDGET` 을 12600 으로 고쳤다. **그런데:**

```
그 하니스는 값을 **주입하고 같은 값으로 단언**한다
→ 서버가 보내는 값이 바뀌어도 **절대 빨간불이 되지 않는다**
```

**즉 서버 값 변화를 잡을 수 있는 검사가 팀에 없었다.** `queued-live.mjs` 만 실제 프레임을 읽는데
거기서도 **특정 값을 단언하지 않는다** — 박으면 socket 이 값을 고칠 때마다 깨지고 그건 §5.3 의
*"고친 쪽이 벌을 받는 검사"* 다.
→ **"지금 서버가 보내는 값"의 단일 기록은 원장 §5.38.3 이고 하니스 상수는 사본**이라고 양쪽에 적었다.
**사본이 낡는 것을 막는 것은 검사가 아니라 그 문장이다.**

### 5. ③ 배포 뒤 실측 — **대기**

`queued` 왕복이 12600 으로 도는지는 **시험 인스턴스가 필요하다.** socket 이 띄울 때 붙는다고 전했다.
**운영에 안 붙는다.**

### 6. ④⑤ 착수 금지·준비 항목

- ✅ **화면 개정(4번) 착수하지 않았다.** `조별과제샘플/index.html` **변경 0.**
- ✅ **하니스 선택자 계획은 이미 명세 §4.3 에 있다**(`e2e`·`queue-contract`·`queued-live` 셋이
  `.tile[data-slot]`+`data-action` 에 걸린다 · 같은 커밋에서 고치고 **고치기 전 판본에 돌려
  빨간불을 먼저 확인**). **더 다듬을 것이 없어서 새로 쓰지 않았다** — 없는 작업을 만들지 않는다.

### 7. 회귀

`node web/tools/queue-contract.mjs` → **33 pass / 0 fail**(새 상수로).

⚠ **원장 §5.24.1·§5.26·§5.28 의 `9900` 은 지우지 않았다** — 그때의 판정 근거이고
**격차 계산(6000 대 9900)의 역사가 사라지면 왜 `ack_budget_ms` 가 생겼는지 못 읽는다.**
