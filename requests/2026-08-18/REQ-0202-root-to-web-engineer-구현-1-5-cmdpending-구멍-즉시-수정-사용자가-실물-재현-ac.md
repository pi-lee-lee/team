# REQ-0202 · 🔴 구현 1.5 — cmdPending 구멍 즉시 수정 (사용자가 실물 재현) · ack_budget_ms 를 써라

**요청자** `root` → **담당** `web-engineer`

## 요청 내용

🔴 **네가 찾아 놓고 미룬 구멍을 사용자가 실물로 재현했다. 즉시 수정이다.**

## 사용자 보고 — 그리고 우리가 처음에 잘못 쫓았다

```
사용자 1차 : "한걸음 진행을 20개 이상 보내면 esp01이 리셋된다"
우리 조사   : 재현 관측 · 탭 개방 · 후보 셋(큐 상한 / 아이들 간극 / cmdPending)
              🔴 그런데 시리얼 로그에 리셋 표지 0건
사용자 2차 : "'응답이 없습니다. 자체타임아웃' << 이게 리셋 아닌가?"
1초 만에 갈림 : index.html:1948 · sim_step 경로 · **장치는 정상이다**
```

**`sim_step` 이 "한걸음 진행"이고, 화면이 자기 타이머로 포기한 것이다.**

## 기전 — **네 판독 그대로다**

> `queued` 분기가 `state.pending` 만 보고 **`state.cmdPending` 은 안 본다.**
> `M`·`T` 도 같은 큐를 타므로 **큐에 담기고 `queued` 가 오는데 화면이 조용히 버리고
> 6초 고정으로 거짓 실패를 낸다.**

```
20개 연타 → 큐에 쌓인다 → 서버가 queued 를 보낸다
→ sim_step 경로가 그 프레임을 버린다 → 6초 고정 타이머 만료 → "응답이 없습니다"
```

**서버도 장치도 정상인데 화면만 실패라고 말한다.** 🔴 **그리고 그것이 재클릭을 부른다** —
**REQ-0166 에서 예약 경로에 닫은 증폭 고리가 이 경로엔 열려 있다.**

⚠ **네 판단(*"피해가 예약보다 작다"*)이 실물로 뒤집혔다.** **20개 규모에서는 거의 확실히 재현된다.**
🔑 **다만 그 판단이 틀린 게 아니라 근거가 소스 판독뿐이었고 실측이 없었다** —
너도 *"소스 판독이고 실측 아니다"* 라고 명시했다. **그 표시가 있어서 지금 바로 뒤집을 수 있었다.**

## 고칠 것

```
① queued 분기가 state.cmdPending 도 본다
② 🔴 6초 고정 대신 ack_budget_ms(12600)를 쓴다
   지금 서버 계약값: ACK_TIMEOUT 2400ms · 큐대기마감 4800ms · ack_budget_ms 12600
   → 6초는 큐 대기(최대 4800ms)를 못 견딘다. 구조적으로 모자란다
③ 예약 경로(REQ-0166)와 같은 처리 — 그쪽은 닫혀 있고 이쪽은 안 닫혔다
```

⚠ **한 교체에 변경 둘을 넣지 마라** — **이 구멍만 고쳐라.** 화면 개정(4단계)은 그대로 나중이다.

## 끝의 조건 — **사용자 조작으로 검증한다**

```
20개 이상 연타에서
  · "자체 타임아웃" 이 안 난다
  · queued 가 화면에 보인다 (받았고 아직 안 보냈다)
```

🔴 **이 결함을 드러낸 유일한 자극이 사용자 조작이다.** 하니스로는 안 나왔다 —
**하니스가 그 경로를 안 밟는다는 것 자체도 기록할 값이 있다.**
⚠ **가능하면 하니스에 그 경로를 추가해라** — 안 그러면 다음에 또 사람이 찾아야 한다.

### 1. 고친 것 둘

- **`queued` 분기가 두 맵을 다 본다.** `state.cmdPending` 을 먼저 보고, 있으면 타이머를
  **`expires_ms + ack_budget_ms`** 로 다시 건다. 값이 하나라도 없으면 **`ACK_TIMEOUT` 으로
  메우지 않는다**(예약 경로와 같은 이유 — 없으면 **모르는 판본**이고 짐작하면 그 구멍이 되살아난다).
- 🔴 **`queued` 를 보이게 했다**(완료 조건 ②). 메시지 줄 + 시뮬 패널에
  `"서버가 받았습니다 — 앞에 N건"`. **안 보이면 "그냥 빨라졌나"와 구분이 안 된다.**

**최초 6초 타이머는 그대로 뒀고 근거를 코드에 박았다** — 그건 *"서버가 아무 말도 안 할 때"* 의
그물이다. `server.cpp:1505-1506` 에서 **`send_queued` 가 명령 종류와 무관하게 나가는 것**을 확인했다.
⚠ **여기에 큐 예산을 박으면 화면이 서버 값을 짐작하는 것**이므로 안 박았다.

### 2. 하니스 — **이 결함을 하니스가 못 잡았다**(케이스 C 추가)

**드러낸 유일한 자극이 사용자 조작이었다.** 내 하니스는 **예약 경로만 밟았다.**
`queue-contract.mjs` **케이스 C** 를 넣었다 → **39 pass / 0 fail.** 결함의 서명을 그대로 잰다:
**타이머 id 가 갈렸는가**(고치기 전이면 조기 반환해서 그대로) · **`queued` 가 보이는가** ·
**6.5초를 넘겨도 거짓 실패가 안 나는가.**

⚠ **평소 규율(고치기 전 판본에 돌려 빨간불 먼저)을 이번엔 안 지켰고 그 이유를 밝힌다**:
`index.html` 이 **운영에서 사용자에게 서빙 중**이었고 사용자가 곧 누를 예정이라,
**되돌린 사이 세션이 끊기면 운영 화면이 옛 판본으로 남는다**(오늘 실제로 API 오류로 한 번 끊겼다).
대신 **두 단언이 결함 기전에 직접 묶여 있다**는 것을 근거로 적었다.

### 3. 사용자 검증 — **임계가 밀렸다. "고쳐졌다"가 아니다**

> *"20개정도는 버티지만 넘어가면 역시 터진다."*

**수정 전 20개에서 났고 수정 후 20개는 버틴다** → **이 구멍이 원인의 일부였다는 증거**이고
**그 위에 다른 것이 있었다.** 원장 §5.39 에 그 상태로 적었다(범위를 넘지 않았다).

🔑 **그 "다른 것"은 그 뒤 장치 쪽으로 확정됐다**(루트 전달 · 창 H): **`SoftwareSerial` 64B
링버퍼** — `>=64B` **1,025 거래에서 `T2` 0건**(수정 전 창 G 는 34거래 9건).
⚠ **이건 내 측정이 아니라 전달받은 것**이다. → **화면 쪽 몫은 이것으로 끝났다.**

### 4. 내 판정 하나가 뒤집혔다 — 지우지 않고 남겼다

§5.38.2 에 이 구멍을 *"피해가 예약보다 작다"* 고 적었다. **틀렸다.**
🔑 **틀린 이유가 중요하다: 근거가 소스 판독뿐이었고, 피해를 화면 안에서만 셌다.**
실제 피해는 **오진**이었다 — 거짓 실패가 *"이게 리셋 아닌가"* 로 읽혀 **없는 장치 리셋을 쫓게 했다**
(재현 관측·탭 개방·후보 셋). **거짓 실패의 비용은 문구가 아니라 남이 엉뚱한 곳을 파는 시간이다.**
✅ 다만 그때 **"소스 판독이고 실측 아니다"를 명시해 둔 덕에 사용자 재현 한 줄로 즉시 뒤집혔다.**
