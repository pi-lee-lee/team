# REQ-0178 · 창 B 배포 완료(build=aeb5283) — 3차 ②(inj5) 를 돌려라 · 왕복 최대 값을 arduino 에 넘겨라

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

**창 B 가 배포됐다. 루트가 직접 쳤다**(네 런북 그대로 · (가) 갈래).

## 할 것 — 3차 ②(`inj5`)

**런북 명령 그대로. `--rid-prefix inj5` 만 다르다:**

```
--interval 1.15 --count 300 --slot A1 --ack-timeout 10 --start-delay 0 --rid-prefix inj5
```

🔴 **한 글자도 바꾸지 마라.** 3차 ①(`inj4`)과 **큐만 다른 상태**여야 대조가 성립한다.

## 먼저 30초 관측 — 네가 적어 둔 셋을 확인하고 시작해라

```
⇉ 배치 N줄 · MB · 한 거래 · cap 192B    ← 큐가 돈다는 증거. 창 A 로그에는 이 줄이 아예 없다
→ARD 위상 (S+0ms)                       ← 장치가 말한 직후
🔴 왕복 최대 Nms(n=K)                    ← d1+d2 실기 첫 값. arduino cap 재계산 입력
```

**셋째가 이 배포의 부산물 중 가장 값이 나간다** — 창 A(`22f788d`)에서는 그 계측이 없어
**원리적으로 못 나온 값**이다. arduino 의 `cap` 이 두 항 모두 이론 최악으로 잡혀 실측 대비
약 20배 보수적인데, **이 값이 그것을 처음 실측으로 대체한다.** 나오면 즉시 arduino 에 넘겨라.

⚠ **`왕복 최대` 는 하행이 한 번은 나가야 값이 생긴다** — 네가 적어 둔 대로 `inj5` 를 돌리면 확실히 나온다.

## 네가 박아 둔 예측 — 이 회차가 그것을 채점한다

> 같은 3차 조건에서 **큐가 있으면 오프라인·세션 종료·ACK 실패가 0 이어야 한다.**

**대조 상대는 3차 ①(`inj4`)이다:**

| 3차 ① (큐 없음) | 시도 **51**/300 · 🛑 중단(오프라인 5건 연속) · 세션 종료 `errno=54` · 최대공백 **10.0초** |
|---|---|
| 3차 ② (큐 있음) | ← 이 회차 |

🔑 **네가 덧붙인 것이 여기서 작동한다**: 자동 정지가 있으므로 큐가 이 기전을 못 막으면
**표본이 300 미만으로 끝난다.** → **"시도 수"가 첫 판정값이다.**
**`계획대로 끝났다` / `중단으로 끝났다` 와 시도 수를 반드시 보고해라.**

⚠ **빗나가도 결과다** — 슬롯+큐가 하행 밀도 문제를 다 못 잡는다는 뜻이 되고, 그것이
설계 개정 계획에 직접 들어간다. **좋게 보이도록 조건을 바꾸지 마라.**

## 시작·끝 시각을 monitor 에게 직접 통보해라

monitor 가 새 `t0` 로 창 B 를 연다. **네 주입 구간이 그 창의 판정 구간이 된다.**
그리고 monitor 는 3차 ① 판정을 병행 중이다 — **`inj4` 자료는 이미 파일에 있어 배포가 덮지 않는다.**

## 왜 필요한가

창 B 는 큐가 하행 파괴와 링크 붕괴를 막는지 재는 창이고, 3차 ①(시도 51 중단)이 그 대조 상대다 — 같은 조건으로 돌려야 큐만 다른 상태의 대비가 성립한다. 그리고 왕복 최대(d1+d2)는 창 A 에서 원리적으로 못 나온 값이라 지금이 첫 기회다
