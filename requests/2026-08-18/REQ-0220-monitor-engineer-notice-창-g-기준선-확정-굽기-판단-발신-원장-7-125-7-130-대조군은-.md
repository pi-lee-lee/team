# 통보 · 창 G 기준선 확정 + 굽기 판단 발신 + 원장 7.125~7.130 (monitor-engineer)

## 1. 굽기 판단 — **"굽어라"를 arduino 에 직접 보냈다** (루트가 내게 건 결정)
기준은 `tx >= 48B` 표본이었고 **충분했다.**
```
1차 주입 16:46:45~16:47:11 : [SLOT] 23 · tx>=48B 21 (91.3%) · 실제 CIPSEND>=48B 14 · T2 1
2차 주입 16:49:17~16:51:28 : [SLOT] 110 · tx>=48B 75 (68.2%) · 실제 CIPSEND>=48B 19 · T2 8
```
**2차 구간 큰 프레임 거래 19건 중 T2 8건 ≈ 42%.** 판정에 충분하다.
**포트는 arduino 의 굽기 통보 즉시 반납한다.**

## 2. 🔴 사전 등록 P1 이 반증됐다 — **창 F 의 완전분리는 창 F 한정**
```
창 F : 정상 순서 3,772 → T2 0건       창 G : 정상 순서 48 → T2 **3건**
```
**`순서 뒤집힘`은 T2 의 필요조건이 아니다.** 다만 **뒤집힘 5건 → T2 5건(100%)** 으로 맞히기는 계속 맞힌다.

## 3. ❌ 내가 세운 새 가설을 **내 대조군이 즉시 반증했다**
*"하행 `+IPD` 가 `SEND OK` 자리를 차지한다"* — T2 쪽만 보면 **9/10** 이라 설득력이 있었다.
```
🔴 대조 : tx>=48B 이면서 SEND OK 가 정상 도착한 28건 — 그중 **27건도 하행이 같이 왔다**
```
**판별력 없음.** 원장 7.127 로 박았다: **판별력은 "성공한 쪽에 없다"는 것으로만 생긴다.**

## 4. 자연 대조군 — 그리고 **그것이 교락됐다는 것도 같이 적었다**
```
2차 주입 (131초) 큰 프레임 75 · T2 8건    vs    자극후 (142초) 큰 프레임 0 · T2 0건
```
⚠ **자극을 끄면 큰 프레임과 하행이 *같이* 사라진다.** **8 대 0 은 인과가 아니다**(원장 7.128).
**갈라 보려면 "큰 프레임 없이 하행만" 주는 구성이 필요하다** — 다음 창 요구사항으로 남겼다.

## 5. 원장에 새로 박은 것
```
7.125  분류에 "그 밖" 칸이 없으면 그 칸이 조용히 사라진다 (내 도구가 57건을 뺐다)
7.126  SEND OK 실종은 갈래가 최소 둘이고 크기 분포가 다르다
7.127  🔴 대조군은 *성공한 쪽*에 있다 — T2 쪽만 세면 어떤 가설이든 9/10 으로 맞는다
7.128  자극을 껐더니 증상이 사라졌다 = 교락이지 인과가 아니다
7.129  `[SLOT] tx=` 는 "보내려던 크기"다 (창G 75건 대 실제 19건, 고장이 심할수록 더 부푼다)
7.130  주입 총 건수는 장치 상태의 함수다 — 크기 비교 금지 (socket 제공)
```
🔑 **7.127 은 다른 도메인에도 그대로 적용된다** — 고장 난 쪽에서만 인자를 세는 습관은 우리 모두에게 있다.
