# REQ-0189 · 창 D 개방 — 장치 복구됨(09:16:08 전원 리셋) · 새 망이라 창 A~C 와 합산 금지 · 기준선 회차

**요청자** `root` → **담당** `monitor-engineer`

## 요청 내용

**장치가 살아났다. 창 D 를 연다.** 실물 복구 사슬이 로그에 남았다.

## 복구 확인 (루트 실측 · `monitor/serial-winD.log`)

```
09:16:08  [AT] "System Ready, Vendor:ai-thinker"      ← ESP 부팅. 복구 시각
09:16:24  [NET] ★ IP 확보: 192.168.0.214              ← 새 AP · 새 대역
09:16:26  [DIAG] rx=411 lines=18                      ← rx 가 0 에서 벗어났다
09:16:27  +ARD 주차 노드 접속 — 세션#1 · device=P1     ← 서버 등록
09:16:44  [TX] S,14,… → SEND OK · [SLOT] n=310 tx=36 due=0
```

**원인은 ESP-01 전원 단이었다** — 사용자가 전원 리셋했다. `CH_PD`·배선이 아니라 **모듈이 걸려 있던 상태**.
🔑 **arduino 의 "굽기로 못 고친다" 판단이 맞았다** — 재굽기했으면 관측 경계만 늘고 그대로 막혔다.

## 🔴 창 D 는 **새 기준선이다. 창 A~C 와 합산 금지**

바뀐 것이 셋이고 **셋 다 우리가 재던 지표와 같은 축**이다:

```
① AP 변경        SK_WiFiGIGA50DC_2.4G → 3F_302   (지연·재전송·링크 안정성이 달라질 수 있다)
② 서브넷 변경     192.168.35.x → 192.168.0.x
③ USB 재연결      포트 usbmodem21201 → usbmodem1101
④ ESP 전원 리셋   모듈이 걸린 상태에서 복구
```

**펌웨어는 `slot4` + 접속 대상 셋만 바뀐 판이다**(거동 변경 없음). **즉 코드 축은 창 C 와 같고 망 축이 다르다.**
⚠ **그래서 `inj7`(창 C)과 이 창을 직접 대비하면 "망이 바뀐 것"과 "코드가 같은 것"이 섞인다.**
**판정문에 그 경계를 먼저 박아라.**

## 할 것 — 이 망의 기준선 회차

**socket 에게 `inj8-pre` 를 지시했다**(REQ 별도). 같은 조건: `1.15s · 300건 · rid inj8pre`.

**이 회차가 답하는 것**: **새 망에서 `cksumng`·`재전송` 이 얼마인가.**
창 C 는 `cksumng 4` · 재전송 16(파괴 4 + 늦은 ACK 12)이었다. **같은 코드·다른 망의 값이 필요하다.**

🔴 **그 다음에야 `cntTick` 굽기가 의미를 갖는다** — 같은 망의 전/후가 있어야 효과가 갈린다.

## 네가 확인할 것 넷

1. **창 D 경계**: `t0` = ESP 부팅(`09:16:08`) 또는 탭 개방 중 **어느 것을 쓰는지 명시**해라.
   ⚠ 이번엔 **탭이 먼저 열려 있었고 장치가 나중에 살아났다** — 지금까지와 순서가 반대다.
2. **`INSTANCE` 경계가 셋 늘었다**(`4029` 종료 · `79844` 58초 · `82879` 현재). 창을 자를 때 봐라.
   `79844` 는 `frames=0 sessions=0` 이라 **잃은 자료는 없다.**
3. **복구 전 구간(`09:0x~09:16:08`)은 장치 침묵 구간**이다 — `rx=0`·사다리 4단.
   **그 구간을 유휴 기준선으로 쓰지 마라.** 장치가 정상 유휴인 것과 죽어 있는 것은 다르다.
4. **포트 이름을 네 도구 기본값에서 고쳤는지 확인**해라(`/dev/cu.usbmodem1101`).

## ⚠ 그리고 대조 불가 칸이 하나 더 늘 수 있다

**`oow`·`ack=` 는 이미 대조 불가**(정의 변경). 여기에 **망 변경이 얹히면 `재전송`·`왕복` 도
창 C 와 직접 비교가 안 된다.** 🔴 **`재전송` 이 창들을 잇는 유일한 칸이었는데 그것도 흔들린다** —
**그래서 이 망의 기준선 회차가 필요하다.** 그 값이 새 기준점이 된다.

## 참고 — 하드리셋선 미배선의 비용이 실측됐다

```
[LADDER] → Uno A2 를 ESP 의 RST 에 물리고 ESP_RST_WIRED 를 1 로 바꿔 다시 구워라
```
**사다리가 4단까지 갔는데 살릴 수단이 없어 사람이 전원을 껐다 켰다.** 장치가 스스로 그 문장을 남겼다.
**배선 여부는 사용자 결정**이라 확인 목록에 올려 뒀다. 판정문에 **"이 창에서 자가 복구가 불가능하다"** 를
조건으로 적어라 — 링크가 죽으면 사람을 기다린다.

## 왜 필요한가

AP·서브넷·USB·ESP 전원이 다 바뀌어 창 C 와 직접 비교가 안 된다 — 재전송이 창들을 잇는 유일한 칸이었는데 망 변경이 그것도 흔든다. cntTick 효과를 재려면 같은 망의 전/후가 필요하고 이 회차가 그 전(前)이다
