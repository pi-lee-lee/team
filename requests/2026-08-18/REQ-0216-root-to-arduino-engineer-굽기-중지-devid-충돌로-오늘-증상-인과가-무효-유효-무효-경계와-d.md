# REQ-0216 · 🔴 굽기 중지 — devid 충돌로 오늘 증상 인과가 무효. 유효·무효 경계와 devid 대응을 답하라

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

🔴 **사용자 확정: 같은 망에서 조원들이 동일 카피 보드(`device=P1`)를 돌리고 있었다.**

> *"**특정할 수 없다. 해당 이슈는 모두 다른 사람 접속으로 처리하라.** 지금 네트워크에 동일 조원들이 테스트 중이었다."*

서버는 `first-S-wins` 를 **devid 로** 판정한다. 둘 다 `P1` 이라 **서버가 구분하지 못했고
충돌 로그조차 0건**이다. **우리 시리얼 탭은 우리 보드만 보는데, 서버는 둘을 섞어 보고 있었다.**

## 🔑 무효인 것과 살아남는 것 — 네 자료는 **경계가 다르다**

**네 시리얼 탭은 우리 보드의 UART 를 직접 읽는다.** 그래서 **보드 내부에서 닫히는 것은 유효하다.**
**무효인 것은 "서버가 무엇을 보냈나"에 의존하는 것이다.**

```
✅ 유효 : 주기 1.2056초 실측 (400 프레임) — 우리 보드 자신의 송신 간격이다
✅ 유효 : 슬롯 구조 점검 결과 — 소스 판독 + 자기 UART 관측
✅ 유효 : ACKQ_N=4 가 부족했다는 판정 — 코드로 확인된 결함
✅ 유효 : sendAck 우회 · cntTick 블로킹 — 소스 결함이고 고친 것이 맞다

❌ 무효 : "20연타 하면 리셋된다" 의 인과 — 🔴 하행이 남의 트래픽이었을 수 있다
❌ 무효 : esprst / stuck / ackdrop 증가의 원인 귀속
❌ 무효 : T2 8초 침묵의 원인 — 서버가 다른 보드에 응답 중이었을 수 있다
❌ 무효 : 15:44:54 순서 뒤집힘 판독 — 그 시각 서버 상태를 우리가 모른다
```

⚠ **"결함이었는가"와 "그 결함이 증상을 만들었는가"는 다르다.**
**전자는 살아 있다. 후자만 무효다. 고친 것을 되돌리지 마라.**

## 🔴 지금 할 것

```
1. 굽기·플래싱 중지 — 관측 기반이 없다. 승인 나면 재개한다
2. 위 경계대로 네 보고·통보에 무효 표시 (지우지 말고 사유와 함께)
3. 아래 ①에 답하라
```

### ① 🔑 **우리 보드의 devid 를 다르게 만들 수 있나**

**관측 재개의 전제다.** 조원 협조 없이 우리 쪽만으로 되는 유일한 방법일 수 있다.
```
· client.ino 의 devid 가 상수라면 → 바꾸는 비용은?
· 서버가 그 값을 받는 자리는 socket 몫이다 (REQ-0215 로 같이 나갔다)
· ⚠ 다만 조원들도 카피를 고칠 수 있다 — 충돌은 언제든 재발한다
  → 🔴 근본은 "충돌을 감지해서 알려주는 것"이지 "값을 피하는 것"이 아니다
```

### ② 이 사건이 설계에 주는 문장

**`devid` 전역 고유는 우리가 이미 개정 항목으로 알고 있었다.**
🔴 **그런데 "기능 요건"으로만 알았다. 실제로는 관측 요건이다 —**
**devid 가 충돌하면 무엇을 고쳐도 검증이 안 된다.** 오늘이 그 증명이다.
**네 명세에 이 문장을 넣어라.**

## ⚠ 마지막으로

**오늘 네가 찾은 결함 셋은 진짜였다.** 그것을 의심하게 만들 생각이 없다.
**문제는 "고쳤는데 왜 증상이 남나"를 반복해 쫓은 것이고, 그 답이 "우리 것이 아니었다"였다.**
**이건 네 판독의 실패가 아니라 관측 경계의 실패다 — 그리고 그 경계는 내가 봤어야 했다.**

## 왜 필요한가

같은 망의 조원 카피가 모두 device=P1 이라 서버가 두 보드를 구분 못 했다. 시리얼 탭은 우리 보드만 보므로 보드 내부에서 닫히는 자료는 유효하지만, 서버 하행에 의존하는 인과 판정은 전부 무효다
