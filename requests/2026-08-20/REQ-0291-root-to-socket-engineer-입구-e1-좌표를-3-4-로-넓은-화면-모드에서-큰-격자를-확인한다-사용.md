# REQ-0291 · 입구 E1 좌표를 (3,4)로 — 넓은 화면 모드에서 큰 격자를 확인한다 (사용자 지시)

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

사용자 지시:
> *"넓게 나온다. **이모드에서는 입구 위치를 3,4로 보내서 확인할 필요가 있다.**"*

REQ-0289(넓은 화면 3열)가 14:07:16 에 배포됐고 사용자가 실물에서 확인했다.
**이제 격자를 크게 만들어 그 모드를 확인한다.**

## 할 것 — 한 줄이다

```cpp
lot.cpp:40   lot.spot("E1").at(0, 2)   →   .at(3, 4)
```

## 왜

지금 격자는 **1행 3열**이라 넓은 화면에서도 격자가 작다. 입구를 `(3,4)` 로 보내면
**4행 5열 = 20칸**이 되어, 넓은 모드에서 격자가 커진 상태와 **빈 칸이 어떻게 그려지는지**를
사용자가 실물로 확인할 수 있다.

## 🔴 딸린 것 — 미리 알아 둬라

```
· 자리는 여전히 둘(A1 parking · E1 area)이고 **빈 칸이 18개** 생긴다
  → 빈 칸 렌더링이 이 확인의 대상이다. 이상해 보이면 그것이 소득이다
· `at` 은 사용자 인식용이고 엔진은 안 쓴다 → **점유·예약·명령 거동은 안 바뀐다**
· `lot.cpp` 는 컴파일된다 → **서버 재배포가 필요하다**
```

## 범위

```
✅ 조별과제샘플/server/lot.cpp 의 좌표 한 줄 (+ dev_server 사본이 있으면 같이)
❌ 엔진 · 계약 · 봉투 · 화면 — 하나도 안 바뀐다
❌ 판정 문서 · 관측 — 확인은 사용자가 화면으로 한다
```

배포 직전 한 줄을 monitor 와 루트에게. 장치 세션이 끊기는 것은 알고 있다.

## 왜 필요한가

격자가 1행 3열이라 넓은 화면 3열 모드를 실물로 확인할 수 없다. 입구를 (3,4)로 보내 4행 5열을 만들면 큰 격자와 빈 칸 렌더링을 사용자가 직접 본다

## 대상 파일

- `조별과제샘플/server/lot.cpp`
## 완료 기준

배포 후 화면 격자가 4행 5열로 그려지고 입구가 (3,4)에 있다. 점유·예약·명령 거동은 그대로다
