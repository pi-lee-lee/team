# REQ-0311 · 🔴 pin() 이 여러 핀을 받는다 — 2핀 센서에서 모양이 갈린다 (사용자 지적)

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

사용자 지적:
> *"**왜 `pin()`을 호출하지 않는가? 이것만 모양이 다르면 이상하다.** 그리고 **pin 2개 이상 쓰는경우는?**"*

## 루트가 준 형태가 일관성을 깼다 — 인정하고 고친다

```c
node.sensor("A1").on(readUltrasonic);   // 🔴 `.pin()` 이 없다
node.sensor("B1").pin(9);               //    있다
```
**같은 자리에서 모양이 다르면 기여자가 규칙을 못 배운다.** 그리고 **2핀 이상은 지금 구조에 답이 없다.**

## 목표 형태

```c
node.sensor  ("A1").pin(2, 4).on(readUltrasonic);   // 🔓 Trig 2 · Echo 4
node.sensor  ("B1").pin(9);                        // 🔓 한 핀
node.actuator("LD").pin(13).on(cmdLed);
node.actuator("L2").on(cmdL2);                     // 핀 없음 — 이건 원래 없는 것이라 예외가 아니다
```
```
✅ `pin()` 을 **항상 부른다**(핀이 있으면). 모양이 하나다
✅ 핀 수가 늘어도 같은 자리에 적는다
```

## 🔴 그래서 프레임워크가 바뀐다 — 그리고 이유가 초음파가 아니다

사용자가 앞서 *"`Module.h` 쪽에 수정사항이 있는 것처럼 말해서 미리 말한 것"* 이라고 했다.
**초음파 때문에 고치는 것이 아니다. `pin()` 이 한 핀만 받는 것이 지금 구조의 한계고, 사용자가 그것을 짚었다.**

## 값으로 답할 것 넷

```
① `pin()` 오버로드 : `pin(a)` · `pin(a,b)` · 그 이상?
   🔑 판별자 : **모양이 일관되는가.** `pin(a,b,c)` 까지 열지, 2 에서 멈출지 값으로 정해라
   ⚠ 실제 2핀 센서 : 초음파 · 로터리 엔코더 · 조이스틱(아날로그 둘)
     3핀 이상은 대개 라이브러리를 쓴다 — **우리는 라이브러리를 안 쓴다**(사용자 확정)

🔴 ② 훅 시그니처가 따라 바뀐다
   지금 : `typedef bool (*SensorFn)(uint8_t pin);`   ← 핀 하나
   → 두 핀을 어떻게 넘기나. **오버로드냐 · 배열 포인터냐 · 개수를 같이 넘기나**
   🔑 판별자 : 기여자가 쓰는 훅 선언이 **읽어서 뜻이 통하나**
     `bool readUltrasonic(uint8_t trig, uint8_t echo)` 는 통한다. `(const uint8_t* p)` 는 안 통한다

🔴 ③ RAM 비용 — 문턱이 있다
   지금 `pin` 1바이트/모듈. 2핀이면 2바이트. **분모는 `ramLow` 537B 다**(602 아니다)
   ⚠ 모든 모듈이 2핀 자리를 갖는 것과, 2핀 모듈만 갖는 것은 비용이 다르다. **재고 정해라**
   🔴 문턱을 재기 **전에** 사전 등록하고 알려라

④ `pinMode` 를 누가 잡나
   `pin(2, 4)` 에서 **2는 OUTPUT · 4는 INPUT** 이다(초음파). 🔴 프레임워크가 그것을 알 수 없다
   🔑 그러면 **기여자가 `setup()` 에서 직접 잡거나**, `pin()` 이 방향을 같이 받아야 한다
     `pin(2, OUTPUT, 4, INPUT)` 은 길다 — **더 나은 형태가 있으면 값으로 대라**
   ⚠ 이것이 이 REQ 의 가장 어려운 자리다. **못 정하면 그 자리에서 멈추고 알려라**
```

```
❌ 전선·서버·화면 계약 — 바뀌면 착수 전에 알려라

```

## 성공 조건
```
🔴 기여자가 **`client.ino` 만** 고쳐서 자기 2핀 센서를 붙일 수 있다
🔴 `pin()` 을 부르는 모양이 **하나**다
🔴 실물(Trig 2 · Echo 4)로 A1 점유가 화면에 뜬다
```

## 왜 필요한가

루트가 준 형태가 2핀 센서에서 .pin() 을 빼서 같은 자리의 모양이 갈렸다. 기여자가 규칙을 못 배우고, 2핀 이상은 지금 구조에 답이 없다

## 대상 파일

- `조별과제샘플/ardu/client.ino`
## 완료 기준

pin() 을 부르는 모양이 하나다. 기여자가 client.ino 만 고쳐 2핀 센서를 붙인다. 훅 선언이 읽어서 뜻이 통한다. RAM 증분이 사전 등록한 문턱 안(분모 537B). 실물 초음파로 A1 점유가 화면에 뜬다

사용자가 더 나은 답을 찾아 취소. pinMode 를 기여자가 직접 선언하면 pin 호출이 불필요하다 — Slots.h:148 이 modPin PIN_NONE 아님 OR senseOf 로 이미 훅 단독을 허용한다. 프레임워크 변경 0. 규칙: 프레임워크에 맡긴다 → pin(9) / 직접 다룬다 → pinMode + on(hook). 모양이 아니라 맡기는 범위가 다른 것이다
