# REQ-0299 · 🔴 client.ino 의 자리배치 로직을 없앤다 — 모듈 표가 유일한 원천이 된다 (사용자 지시)

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

사용자 지시:
> *"client.ino에 큰 수정이 필요하다. **자리배치로직이 여전히 남아있다.**
> 그 구조때문에 **오히려 코드이해가 어렵다.** 해당 구조를 삭제하고 **현재 아키텍쳐에 적합하게** 수정해라."*

## 루트가 잰 것 — 진실이 두 곳에 있다

```
SENSOR_N  39회   MODULE_N  19회   slotStart 12   simOcc 12
SLOT_PIN  11     occMask   11     slotPin    8   SLOT_SRC_DEFAULT 5   applySlotPinMode 5
```
```
🔴 MODULE_TABLE  {"A1","IP",**2**}   ← 핀이 여기 있다
🔴 SLOT_PIN[]                        ← 핀이 여기도 있다
Slots.h:16 주석 : *"늘리려면 `SLOT_PIN[]` 과 `MODULE_TABLE` 을 **같이** 늘려라.
                   셋이 어긋나면 컴파일이 막는다"*
```
> ### **모듈 하나를 늘리려고 세 곳을 맞춰 고쳐야 한다. 사용자가 말한 "이해가 어렵다"가 이것이다.**
> **컴파일이 막아 주는 것은 사고를 막는 것이고, 구조가 쉬운 것과는 다른 일이다.**

🔑 그리고 `Slots.h:127` 에 이미 이렇게 적혀 있다 —
*"예전에는 `SLOT_SRC_DEFAULT` 라는 **두 번째 진실**이 따로 있었다."*
**한 번 고쳤는데 같은 부류가 남았다.** 원장 §"고친 것은 그 자리이지 습관이 아니었다".

## 현재 아키텍처 — 장치는 자리를 알 필요가 없다

```
자리 배치·좌표·자리 종류  → **서버 조립 표(lot.cpp)** 가 정한다
장치가 아는 것            → **자기 모듈 목록: 이름 · 종류 · 핀. 그것뿐이다**
자리 결속                 → 서버가 `D,<name>` 의 name 을 자리 id 와 맞춰 붙인다
                            ⚠ 이 규칙은 서버에 있다. 장치는 이름만 보낸다
```
> ### **그러므로 장치에 "자리 수"·"자리 행수"·"자리별 핀 표" 가 있을 이유가 없다.**
> **필요한 것은 `idx`(모듈 표 순서)뿐이고 그것은 표가 이미 준다.**

## 방향 — **모듈 표가 유일한 원천이 된다**

`SENSOR_N`·`SLOT_PIN[]`·`SLOT_SRC_DEFAULT` 같은 것을 **표에서 파생**시켜라.
설계는 네 몫이다. 다만 판별자를 아래처럼 잡아라.

## 🔴 판별자를 산출물에서 **전선 바이트**로 옮겨라

```
❌ hex 대조   — 삭제·통합이므로 **반드시 바뀐다.** 이 축은 이 작업에서 쓸 수 없다
✅ 등록 프레임 바이트가 같다     `D,*,7,4,` · `D,A1,IP` · `D,B1,IP` · `D,LD,OG` · `D,L2,OL`
✅ `S` 프레임이 같다             (같은 입력에 같은 바이트)
✅ 부팅 표지가 같다              `[SENS] A1=핀2 B1=핀9` · 배너의 수치
✅ 자가검증(host_test) 통과
✅ 플래시·RAM 증분을 값으로 적어라 — **줄어야 정상이다.** 늘면 그것이 신호다
```
원장 §"산출물 대조는 조건부 판별자다" — **인터페이스가 바뀌는 변경에서는 판별자를 다른 축으로 옮긴다.**

## 🔴 단계로 쪼개라. 한 번에 하면 무엇이 무엇을 깼는지 못 가른다

```
① 파생만 넣고 옛 것을 남긴다   → 두 값이 **같은지 컴파일 시점에 단언**(static_assert)
                                  🔑 이 단계는 **거동 변화 0 을 목표로 걸 수 있다**
② 옛 것을 지운다               → 여기서부터 hex 가 바뀐다
③ 자리 어휘를 모듈 어휘로 바꾼다 (이름·주석)
```
**①에서 두 진실이 같다는 것을 값으로 증명하고 나서 ②로 가라.**
⚠ 그리고 **`occMask` 비트 위치는 건드리지 마라** — 전선 `idx` 가 그 순서다. 바꾸면 서버 결속이 어긋난다.

## ⚠ 굽기

거동 변화 0 을 목표로 하지만 **산출물이 바뀌므로 굽기가 필요하다.**
🔴 **착수를 미루라는 뜻이 아니다** — 굽기는 제약이 아니라고 사용자가 확정했다.
다만 **굽기 직전 한 줄**을 monitor 와 루트에게. 그리고 굽기 전에 위 판별자를 값으로 적어 둬라.

## 범위
```
✅ 조별과제샘플/ardu/** — client.ino · Slots.h · Modules.h · 그 밖 자리 어휘가 있는 곳
❌ 서버 · 화면 · 계약 — 전선 바이트가 같으므로 **아무것도 안 바뀐다**
   ⚠ 만약 전선이 바뀌어야 한다고 판단되면 **착수 전에 알려라.** 그건 다른 작업이다
❌ 관측 · 판정 문서
```

## 곁들여

`REQ-0298`(KIND_* 잔재)과 **같은 파일들을 만진다.** 순서는 네가 정해라 —
0298 을 먼저 닫고 오는 것이 깔끔하다고 본다(문서만이라 굽기 경계 밖이다).

## 왜 필요한가

핀이 MODULE_TABLE 과 SLOT_PIN[] 두 곳에 있고 모듈 하나를 늘리려면 세 곳을 맞춰 고쳐야 한다. 자리 배치는 서버 조립 표가 정하는데 장치가 자리 수·행수·자리별 핀 표를 들고 있어 코드 이해를 막는다

## 대상 파일

- `조별과제샘플/ardu/client.ino`
## 완료 기준

SENSOR_N·SLOT_PIN[]·SLOT_SRC_DEFAULT 가 모듈 표에서 파생되거나 사라졌다. 등록·S 프레임 바이트와 부팅 표지가 그대로다. 자가검증 통과. 플래시·RAM 증분이 값으로 적혀 있다. occMask 비트 위치 불변

### ② 없앤 것 / 파생시킨 것

```
🔴 삭제 : SENSOR_N(하드코딩) · SLOT_PIN[] · SPOT_N · slotCol · slotRow · slotIndexOf(산술)
          simOcc · simCandidate · simPair · simStep · srcReal · slotSourceSet
          static_assert 둘(짝수 · MODULE_N>=SENSOR_N — 파생이라 성립할 수밖에 없다)
✅ 파생 : 센서 수  ← 표의 `I*` 앞쪽 연속 줄 수 (constexpr 재귀)
          핀       ← MODULE_TABLE[i].pin
          자리 토큰 ← MODULE_TABLE[idx].name 두 글자
          이름→idx  ← 표 검색 (센서 범위만 도니 액추에이터로 예약이 안 걸린다)
```
**사용자가 지적한 세 곳이 하나가 됐다**: `client.ino`·`GUIDE.md` 의
*"`SENSOR_N`·`SLOT_PIN[]` 도 같이 늘려라(셋이 어긋나면 컴파일이 막는다)"*
→ **"이 표에 한 줄. 그것이 전부다"**.

### ③ 🔴 실측이 설계를 정했다 — 추측하지 않았다

```
❌ static const     ModuleDef T[] PROGMEM  → "the value of 'T' is not usable in a constant expression"
✅ static constexpr ModuleDef T[] PROGMEM  → **exit=0**
툴체인 : avr-g++ 7.3.0 · **-std=gnu++11** → constexpr 함수에 루프 못 씀 → **재귀로 썼다**
```
안 됐으면 파생을 런타임으로 밀어야 했고 **그러면 층이 하나 늘어난다** — 사용자가 지적한 "지저분함"이 그것이다.

### ④ 🔴 시뮬 점유는 **실기에서 도달 불가**였다 (지우는 근거)

```
readSlotSensor 갈래 : ㉠ 오버라이드(T) → ㉡ srcReal 이면 실물 → ㉢ simOcc
srcReal = `slotPin(i) != PIN_NONE` 인 칸 = **핀 적은 칸 전부.** 지금 센서 둘은 다 핀이 있다
→ ㉢ 은 한 번도 안 탄다 → simCandidate 항상 false → simStep 항상 0xFF → **`M` 은 항상 result=5**
srcReal 을 내리는 유일한 함수 slotSourceSet → **호출부가 host_test 뿐**(원장 §59 그 함수)
```
**전선을 안 바꾸고 없앤 방법**: ㉢ → `return 0`(simOcc 는 0 으로 시작하고 바꿀 경로가 없었다) ·
`M` → 상수 `result=5`. 🔴 **`M` 타입은 남겼다** — 지우면 5→3 이라 **값이 바뀐다.**

### ⑤ ⚠ 내 첫 안이 틀렸고 루트가 값으로 반증했다

*"짝을 표의 `name[1]` 에서 읽자"* → `lot.cpp` 의 `.module("P1","B1")` **명시 결속**을 보니
*"이름이 자리 id 와 같으면 붙는다"* 는 **v1 부트스트랩 규칙**이었다.
🔑 루트의 문장이 정확하다: *"그러면 코드는 남고 근거만 바뀐다."*
→ `Modules.h` 의 그 낡은 결속 주석을 **명시 결속으로 고쳤다**(범위에 포함하라는 지시대로).
