# REQ-0288 · 격자 칸을 요약만으로 — 모듈이 여러 개면 화면이 늘어나 깨진다 (사용자 확정 ③안)

**요청자** `root` → **담당** `web-engineer`

## 요청 내용

사용자 확정: **③ 안으로 진행.** 격자 칸은 요약만, 상세는 오른쪽 패널.

## 지금 무엇이 깨지나 (루트가 값으로 확인)

```
line 203  grid-template-columns: repeat(var(--zcols,1), minmax(0,1fr))
🔴 행 높이 제약이 없다 → 칸 내용이 늘면 그 행 전체가 늘어난다 (grid 는 행을 최대 칸에 맞춘다)
line 275  .zone__acts { display:flex; flex-wrap:wrap }
          → 조작 버튼이 칸 안에서 줄바꿈되며 칸을 밀어 올린다
```

**모듈 많은 자리 하나가 그 행 전체를 늘린다.** 자리마다 모듈 수가 다를 수밖에 없으니
격자가 울퉁불퉁해지고, 심하면 깨진다. 사용자가 실물 화면에서 관측했다.

## 왜 이렇게 되었나 — 격자에 두 일을 시키고 있다

```
격자의 일   = 물리적 배치를 보여주는 것 (어느 자리가 어디 있나)
지금의 일   = 배치 + 모듈 목록 + 조작 UI 전부
→ 칸 크기가 내용에 딸리면 그것은 도면이 아니다
```

## 할 것

```
칸(격자)  : 상태색 + 라벨 + **모듈 수 배지**(예: `4`) 만.
            🔴 **크기·종횡비 고정.** 모듈이 몇 개든 칸이 안 변한다
패널(우측): 선택한 자리의 모듈 목록 + control 위젯(toggle/number/choice) 전부
선택      : 칸 클릭 → 패널이 그 자리를 그린다. 선택 표시가 칸에 보인다
```

🔑 **오른쪽 패널은 이미 있다** — `main { grid-template-columns: minmax(0,1.55fr) minmax(230px,1fr) }`.
새 레이아웃을 만드는 것이 아니라 **있는 자리를 쓰는 것**이다.

## 범위 — 넘지 마라

```
✅ 화면 CSS · 렌더링 · 선택 상태
❌ 서버 계약 · 봉투 · control 선언 형식 — 하나도 안 바뀐다
❌ 관측 · 측정 · 판정 문서 · 실기 하니스 — 사용자가 검토 중단을 지시했다
```

배포 단위는 `index.html` 하나다.

## 왜 필요한가

한 자리에 모듈이 여러 개 붙으면 그 칸이 세로로 늘어나고 grid 가 행 전체를 그 높이에 맞춰 격자가 깨진다. 자리마다 모듈 수가 다를 수밖에 없어 구조적으로 재발한다

## 대상 파일

- `조별과제샘플/web/index.html`
## 완료 기준

한 자리에 모듈 10개를 넣어도 격자 칸의 크기·종횡비가 변하지 않는다. 조작(toggle/number/choice)은 우측 패널에서 되고 칸에는 모듈 수 배지만 있다

### 완료 — 칸은 요약만, 상세·조작은 우측 패널 (2026-08-20 14:0x)

배포 단위 `조별과제샘플/web/index.html` 하나. **서버 계약은 한 줄도 안 건드렸다.**

## 무엇을 고쳤나

```
격자 : grid-auto-rows: var(--zrowh, 92px)   ← 🔴 행 높이를 내용에서 뗀다
       칸은 <button class="zone"> — 상태색 + 이름/id + 요약 + **모듈 수 배지** + (겹침 경고)
       🔴 모듈 목록·control 위젯·예약 버튼은 칸에서 **빠졌다**
패널 : #zone-detail (.side 첫 블록) ← 노드 박스 > 모듈 행 > control 위젯 + 자리 조작 버튼
선택 : 칸 클릭 → state.selZone → 패널. 칸에 outline + `▸ 오른쪽에 상세` + aria-current
```

**`aspect-ratio` 를 안 썼다**: `span 2` 인 칸이 **두 배로 높아져** 행이 다시 울퉁불퉁해진다.
**고정 행 높이 + 요약만** 이 짝이어야 한다 — 고정 높이에 늘어나는 내용을 넣으면 잘림이고,
**잘린 정보는 없는 정보**다. 그래서 목록을 뺀 것이 이 수정의 본체다.

**상태색**은 옛 격자(`.tile`)의 **같은 변수**를 쓴다(`--free-*`·`--resv-*`·`--occ-*`·`--done-*`).
새 이름을 만들면 범례가 두 벌이 된다. `parking` 이 아닌 자리는 예약 어휘가 없어 색을 칠하지 않는다.

## 놓칠 수 있었던 것 셋 — 다 막았다

```
① 🔴 입력 칸 보존이 조용히 죽는다
   renderZoneGrid 의 보존 루프가 `el.zoneGrid` 를 걷고 있었다. 입력 칸이 패널로 갔으므로
   **그대로 두면 "치는 중에 글자가 사라진다"(오늘 고친 그 결함)가 되살아난다.** 걷는 곳을 패널로 옮겼다
② 🔴 칸이 버튼이 되면서 **초점이 매 렌더마다 날아간다** — 격자는 초당 한 번 이상 다시 그려진다
   → keepCell 로 자리 id 기준 복원. 없으면 키보드로 격자를 훑을 수 없다
③ 🔴 조작 버튼 클릭 리스너가 격자에 붙어 있었다 → 패널에도 붙여야 예약이 동작한다
   ⚠ 요청 경로·확인 대화상자·낙관적 UI·타이머는 **한 줄도 안 바꿨다.** 붙는 자리만 옮겼다
```
그리고 **선택한 자리가 지형에서 사라지면 첫 자리로 떨어진다** — 패널이 비면 사용자가
*"조작이 어디 갔지"* 를 먼저 겪는다. 없는 자리를 계속 그리는 것은 더 나쁘다.

## 합격선 — 값으로

```
zone-nodes.mjs   43 pass / 0 fail / 1 미측정   (합격선 검사 6개를 새로 넣었다)
  ✅ 🔴 모듈 10개 자리와 1개 자리의 **칸 높이가 같다**    ← REQ 의 합격선
  ✅ 🔴 칸에는 모듈 행이 하나도 없다 (요약만)
  ✅ 모듈 수 배지가 칸에 있다 (10 / 1)   · ✅ 칸이 button 이다
  ✅ 🔴 옛 선택이 사라지면 첫 자리로 떨어진다 · 패널에 모듈 10행
mod-control.mjs  36 pass / 0 fail / 3 미측정   (패널에서 위젯·입력 보존이 그대로 된다)
```
🔑 **음성 대조를 했다** — 수정 전 판(`dev_server` 옛 사본)에 대고 돌리면
`#zone-detail 이 없다 — REQ-0288 이전 판이다` 로 **멈춘다.** 실패할 수 없는 검사의 초록은 아무 말도 안 한다.
⚠ **브라우저에서 사람 눈으로는 안 봤다** — 잰 것은 헤드리스 DOM·경계 상자다.
