# REQ-0314 · 🔴 센서 변화 콜백 — 초음파에 잡힐 때마다 pin13 LED 토글 (사용자 지시 · 다음 작업의 메인)

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

사용자 지시:
> *"콜백과 구현후 **초음파센서에 물체 잡힐때 마다 pin13 led가 토글**되도록 해달라.
> **첫번째 잡히면 on 다시 두번째 잡히면 off**"*

## 목표 — 이것이 이 콜백의 첫 실물 사용례다

```
초음파에 물체가 잡힌다  →  pin13 LED **토글**
  1번째 잡힘 → ON  ·  2번째 잡힘 → OFF  ·  3번째 → ON …
🔑 **잡힐 때만**(0→1 상승) 세다. 물체가 **사라질 때(1→0)는 아무것도 안 한다**
```

## ✅ 장치 변경 0 — 배포만이다

```
`LD` = `LED_BUILTIN` = **pin 13** 이 이미 등록돼 있다(`node.actuator("LD").on(cmdLed)`)
`send(devid, module, value)` 도 이미 있다(parking.h:213)
🔴 빠진 것은 **센서 변화를 잡는 훅** 하나뿐이다 → **굽기 불필요 · 서버 배포만**
```

## 형태 — `onCommandResult` 와 같은 모양

```cpp
// lot.cpp — 기여자가 쓰는 파일
void onOccupancyChanged(ParkingServer& srv, const std::string& spot, bool occupied) {
  static bool ledOn = false;
  if (occupied) {                              // 🔑 잡힐 때만
    ledOn = !ledOn;
    srv.send("P1", "LD", ledOn ? 1 : 0);
  }
}
```
**이름·시그니처는 네가 정해라.** 다만 기존 훅(`onTick`·`onCommandResult`)과 **같은 계열로 보이게** 해라 — 기여자가 한 번만 배운다.

## 🔴 판단해서 값으로 답할 것 넷

```
① **자리 단위냐 모듈 단위냐**
   지금 자리 `A1` 에 초음파가 **둘**(A1·B1) 붙어 있다
   자리 단위 : 둘 중 하나라도 잡히면 1번 → 🔑 사용자가 어느 센서를 만져도 토글된다
   모듈 단위 : 센서마다 따로 → 두 센서를 각각 만지면 각각 토글
   🔴 사용자 원문은 *"초음파센서에 물체 잡힐때마다"* 다 — **어느 쪽이 그 뜻인지 값으로 판단해라**
   ⚠ 자리 점유를 두 센서에서 어떻게 합치는지(OR/AND)도 같이 적어라. 그게 답을 정한다

② **변화 판정이 지금 어디서 일어나나**
   🔑 서버는 이미 그 변화를 안다(화면 방송용). **그 자리에서 콜백을 부르면 된다**
   ⚠ 없던 판정을 새로 만들지 마라 — 그러면 판정자가 둘이 된다

③ **에코와 겹치나**
   🔴 `LD` 는 액추에이터라 `occ` 비트열에 **에코 비트**를 갖는다(비트 1)
   → LED 를 켜면 `occ` 가 `2` 만큼 오른다 → 🔴 **그것이 또 "변화" 로 읽혀 콜백이 재귀할 수 있다**
   ⚠ **이것이 이 작업의 진짜 위험이다.** 센서 비트만 보는지 값으로 확인해라
   무한 토글이 나면 사용자가 즉시 본다(LED 가 깜빡인다)

④ 재진입·순서
   콜백 안에서 `send` 를 부른다 → 그 명령이 같은 박자에 나가나 다음 박자인가
   🔑 `serveOneTick` 의 네 박자 중 어디서 부르는지가 그것을 정한다
```

## 판별자

```
🔑 **실물로 판정한다** — 초음파에 손을 대면 pin13 LED 가 켜지고, 다시 대면 꺼진다
자가검증 : 콜백이 상승에서만 불리는가 · 하강에서 안 불리는가 · **에코로 재귀하지 않는가**
🔴 ③의 재귀는 **음성 대조**로 확인해라 — LED 를 켠 직후 콜백이 또 불리는지
전선·장치 불변 : `[REG] 54B` · 모듈 4 · 등록 그대로
```

```

❌ 장치 — 굽기 없다
❌ 화면 — 안 바뀐다(LED 에코는 이미 화면에 뜬다)

```

## 왜 필요한가

지금 onTick 에서 점유를 읽을 API 가 0 이라 기여자가 센서 변화에 반응할 수단이 없다. send 는 이미 devid 를 받으므로 장치 간 연동이 구조상 가능한데 첫 칸이 비어 있다
