# REQ-0301 · sim_step 버튼을 뺀다 — 누르면 반드시 거절되는 버튼이 배포본에 있다 (socket 발견)

**요청자** `root` → **담당** `web-engineer`

## 요청 내용

socket 이 자기 경로를 재다가 찾았다(원장 `docs/net/LEDGER.md` §107).

## 🔴 누르면 반드시 거절되는 버튼이 화면에 있다

```
화면 {"type":"sim_step"} → wsapi.h:206 dispatch_sim() → downlink.h:58 → 전선 `M,<rid>,`
→ 장치가 **항상 result=5**
```
```
조별과제샘플/web/index.html   `sim_step` **8곳**
~/parking-bin/index.html      **배포본에 있다**  ← 🔴 사용자가 지금 이 화면을 보고 있다
```

**지금도 이미 무효다.** 장치의 시뮬 갈래는 `srcReal=0b11`(핀 둘) 때문에 **도달 불가**이고,
arduino 의 REQ-0299 뒤에도 같다(`M` 타입을 남기므로 값이 안 바뀐다).

> ### 우리 원칙은 *"`actions` 가 있는 이유가 **실패할 것을 안 내놓는 것**"* 이다.
> **이 버튼은 그 원칙의 정확한 반례다.**

## 할 것

**화면에서 그 버튼(과 관련 경로)을 뺀다.**

```
✅ 뺀다 : sim_step 버튼 · 전송 경로 · 그 결과를 그리는 부분
⚠ 확인 : 테스트모드/폴백이 이것을 쓰는가
         🔑 `sim_step` 은 **실기 서버에 요청을 보내는 것**이라 테스트모드와 무관할 것이다
         쓰고 있으면 그 사실을 값으로 대고 **어떻게 갈랐는지 적어라**
❌ 서버 계약 · `M` 프레임 타입 — 안 건드린다. 🔴 타입을 지우면 result 5→3 으로 값이 바뀐다
```

## 왜 서버 쪽(㉡)을 안 고르나

socket 이 *"지금도 거절이라 값이 안 바뀐다 → 뜻이 약하다"* 고 스스로 적었다. **버튼이 사라지면 요청이 안 온다.**
⚠ 기여자가 자기 화면을 만들어 `sim_step` 을 보내는 경우는 남는다 — 그건 **보류 목록**에 두고
다음 배포 경계에서 socket 이 판단한다(REQ-0294 와 같은 취급).

## 범위
```
✅ 조별과제샘플/web/index.html
❌ 서버 · 장치 · 계약
❌ 관측 · 판정 문서
```
배포는 루트가 한다. 화면만이라 서버·장치는 안 끊긴다. 커밋하고 알려라.

## 왜 필요한가

장치의 시뮬 갈래가 도달 불가라 sim_step 은 항상 result=5 로 거절된다. 사용자가 지금 그 화면을 보고 있고 누를 수 있다. actions 를 두는 이유가 실패할 것을 안 내놓는 것인데 그 반례다

## 대상 파일

- `조별과제샘플/web/index.html`
## 완료 기준

배포본 화면에 sim_step 버튼과 전송 경로가 없다. 테스트모드·폴백이 그것을 쓰는지 확인한 결과가 적혀 있다. 서버 계약과 M 프레임 타입은 불변

## ⚠ 확인 요청에 대한 답 — **데모가 그것을 쓰고 있다. 값으로 댄다**

```
실기 (link=ws)   화면 {"type":"sim_step"} → 서버 → 전선 `M,<rid>,` → 장치 **항상 result=5**
                 🔴 누르면 반드시 거절된다 (socket 실측 · docs/net/LEDGER.md §107)
데모 (link=demo) 로컬 `handleSimStep()` 이 **실제로 처리한다**:
                 예약된 빈 칸을 먼저 채우고, 없으면 순환으로 골라 occupied 를 뒤집는다
                 → `{"type":"ack","result":0}` · 화면이 바뀐다  ✅ **동작한다**
                 (`noSimSlots` 일 때만 스스로 `result:5` 를 낸다 — 데모 안에서 정직하다)
테스트모드       🔑 **안 쓴다.** `test_set`/`test_clear`/`arm` 은 다른 경로이고
                 시뮬 주석이 그것을 이미 명시한다: *"테스트 모드와 무관합니다"*
폴백(파일 폴링)  WS 가 없어 애초에 못 보낸다 — 그쪽에서도 무효다
```
> ### **그래서 지우지 않았다. 지우면 되는 기능(데모)을 죽이는 것이다.**
> **뺀 것은 "실기에서 반드시 거절되는 버튼"이고, 남긴 것은 "데모에서 동작하는 같은 버튼"이다.**

## 어떻게 갈랐나 — **문이 둘이다**

```
① 보이지 않게   renderSim() : el.simBlock.hidden = (state.link !== 'demo')
                🔑 `hidden` 은 display:none 이라 **초점도 안 잡힌다**(키보드로도 도달 불가)
② 나가지 않게   클릭 핸들러 첫 줄 : link !== 'demo' 면 **보내지 않고 이유를 말한다**
                ⚠ ①만 두면 **데모 → ws 로 링크가 바뀌는 순간의 경합**에서 요청이 전선에 실린다
```
🔑 **판별자는 `state.link === 'demo'` 하나다** — 데모 전송기만 이 명령을 처리할 수 있고,
그 밖(ws·폴백·미접속)에서는 **아무도 처리하지 못한다.** 조건을 두 곳에서 다르게 쓰지 않았다.

🔴 **서버 계약과 `M` 프레임 타입은 안 건드렸다**(루트 조건). 타입을 지우면 `result` 가 5→3 으로 바뀐다.
