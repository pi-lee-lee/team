# REQ-0296 · 비활성 자리를 회색으로 — unknown 색과 갈라라 (사용자 지시)

**요청자** `root` → **담당** `web-engineer`

## 요청 내용

사용자 지시(실물 화면 확인 뒤):
> *"모듈이 안붙은 자리는 **비활성화된자리는 회색으로 표시**되어야한다."*

## 할 것

`active.ok:false` 자리(지금 A2~A5)를 **회색**으로 그린다.

REQ-0293 에서 `unknown` 색으로 두었는데 사용자가 **회색**을 원한다.
점선·흐림·사선과 사유 문구(`⏸ 모듈이 없어 점유를 알 수 없습니다`)는 **그대로 둬라** —
사용자가 바꾸라고 한 것은 색 하나다.

## ⚠ `unknown` 색과 갈라야 한다

```
`value_state="unknown"`  = 모듈은 있는데 값이 아직 안 왔다   → 지금 색 그대로
`active.ok:false`        = 모듈이 아예 없다                  → 🔴 **회색**
```
**둘을 같은 색으로 두면 "값을 기다리는 자리"와 "영원히 값이 없는 자리"가 구분되지 않는다.**
색을 하나 더 만드는 것이 아니라 **이미 갈려 있던 두 상태에 색을 갈라 주는 것**이다.

범례(legend)도 같이 맞춰라 — 범례가 색을 설명하는데 색이 바뀌면 범례가 낡는다.

## 범위
```
✅ 조별과제샘플/web/index.html — 색 · 범례
❌ 서버 · 봉투 · active 판정 — 하나도 안 바뀐다
❌ 관측 · 판정 문서
```
배포는 루트가 한다. 커밋하고 알려라.

## 왜 필요한가

사용자가 실물 화면에서 확인하고 회색을 요구했다. 그리고 지금 색이 value_state=unknown 과 같으면 '값을 기다리는 자리'와 '영원히 값이 없는 자리'가 구분되지 않는다

## 대상 파일

- `조별과제샘플/web/index.html`
## 완료 기준

active.ok:false 자리가 회색으로 보이고, value_state=unknown 자리와 색이 다르다. 범례가 그 색을 설명한다

### 완료 — 비활성은 **무채색 회색**, 미상과 값으로 갈린다 (2026-08-20 14:5x)

색 하나만 바꿨다. 점선·흐림·사선·`⏸` 문구는 그대로다.

## 두 색을 값으로 갈랐다

```
                     밝은 테마                어두운 테마
비활성 active.ok:false  rgb(222,222,222) 회색   rgb(48,48,48) 회색     ← 🔴 새것. dashed + 사선
상태 미상 (state 없음)  rgb(236,239,244)        rgb(32,38,49)          ← 그대로. dotted
빈 자리                 rgb(255,255,255)        rgb(22,36,29)          ← 그대로. solid
```
🔴 **무채색(R=G=B)으로 뒀다.** 살짝 푸른 회색을 쓰면 옆의 미상 색(`--occ-*`, 푸른 기가 있다)과
**눈에서 다시 붙는다** — 색을 가른 목적 자체가 없어진다. 시험이 `max-min ≤ 2` 로 그것을 강제한다.

## 🔴 단축 속성 함정 하나를 잡았다 — REQ-0293 의 사선이 실제로는 안 그려졌을 수 있다

```css
.zone[data-view="unknown"] { background: var(--occ-bg); … }   /* 단축 속성 */
.zone[data-active="0"]     { background-image: 사선 … }        /* 🔴 이게 **먼저** 있었다 */
```
`background` **단축**은 `background-image` 를 `none` 으로 되돌린다. 즉 뒤에 오는 `data-view` 규칙이
앞의 사선을 지웠다. **REQ-0293 의 시험은 사선을 안 봤기 때문에 초록이었다.**
→ 이번에 비활성 블록을 **`data-view` 규칙들 뒤로** 옮기고 `background-color`/`background-image` 를
**따로** 주고, **계산된 값**으로 사선 유무를 단언했다(`has-stripes`).
🔑 **CSS 를 문자열로 읽으면 "그렇게 적혀 있다"까지다.** 순서가 규칙의 일부다.

## 범례도 맞췄다 (루트 지시)
두 항목을 **나란히** 넣었다 — 떨어뜨리면 읽는 사람이 둘을 같은 것으로 읽는다:
```
회색 + 사선 + ⏸ = 모듈이 없어 사용할 수 없는 자리 — 기다려도 값이 오지 않는다
점선           = 상태 미상 — 모듈은 있는데 값이 아직 안 왔다 (오면 채워진다)
```
견본(`.swatch--*`)은 **칸과 같은 CSS 변수**를 쓴다 — 색을 따로 박으면 칸 색을 바꿀 때 범례만 낡는다.

## 값 (주입 · 트래픽 0)
```
zone-nodes 77 pass / 0 fail / 1 미측정   ← REQ-0296 검사 10개 신설(밝은·어두운 각 5)
  ✅ 비활성 색 != 미상 색      (두 테마 다)
  ✅ 비활성 색이 무채색 회색   (두 테마 다 · R=G=B)
  ✅ 회색으로 바꿔도 사선이 살아 있다 · dashed/dotted 구분도 남아 있다
map-epoch 59 / 0 · mod-control 36 / 0  (회귀 없음)
```
🔴 **밝은 테마를 처음으로 밟았다** — 이 하니스는 그동안 어두운 테마만 재고 있었다.
`Emulation.setEmulatedMedia` 로 두 테마를 다 돌린다. 한쪽만 재면 다른 쪽이 조용히 깨진다.
⚠ **사람 눈으로는 안 봤다.** 잰 것은 `getComputedStyle` 값이다.
