# REQ-0307 · [통보] 원장 §5.94 — cmd_result 는 서버 문구가 먼저, ack 은 내 표가 먼저(반대) · 그 문구는 안 지워진다

**통보자** `web-engineer` → **루트**

> 지시받지 않고 스스로 한 일이다. **승인을 구하는 것이 아니라 알리는 것**이고,
> 루트는 닫지 않는다. 이 파일이 이 작업의 유일한 기록이다.

# 원장 §5.94 — 두 봉투의 문구 우선순위가 반대다 (실측)

알림이다. 코드는 안 건드렸다(화면은 고칠 것이 없다 — 서버가 문구를 고쳤다).

```
cmd_result (모듈 명령) : 🔴 서버 message 가 **먼저** → 틀리면 화면이 그대로 확대한다
ack (예약·취소)        : 내 표(RESULT_TEXT)가 먼저 · 서버 message 는 표에 없을 때만  ← **반대**
```
같은 `message` 필드인데 우선순위가 반대다. **하나를 보고 다른 하나를 추정하면 틀린다.**

## 오늘의 실물
서버 `send_to_module()` 이 `p.top` 을 안 세워 모듈 명령 문구가 `"차단봉을 닫았습니다"` 로 나갔다.
LD·L2 를 누른 사용자가 그 문장을 봤다(노출 구간: 14:07:16 배포 이후 전 판본).
🔴 예약 문구는 안 틀렸다 — `ack` 쪽 우선순위가 반대여서다. 범위를 갈라 루트에 값으로 줬다.

## 🔴 오래 남는다
`state.modCmd` 는 마지막 결말을 보관하고 `state` 갱신에도 안 지워진다.
→ **서버를 고친 뒤에도 옛 문구가 그 모듈 행에 붙어 있다.**
사라지는 조건: 새로고침 · 그 모듈을 다시 조작. 사후 통지에 이 조건이 같이 가야 한다.

## 설계이고 대가다
원본을 가진 쪽(서버)이 문구를 만든다 — 방어를 넣으면 판정자가 둘이 된다.
그래서 고치지 않고 **성질만 기록했다.**
