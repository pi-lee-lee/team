# REQ-0303 · 🔴 client.ino 를 아두이노 표준 스케치로 — setup/loop 에 기여자 줄만 남긴다 (사용자 지시)

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

사용자 질문과 지시:
> *"client.ino에 과거에는 **핀설정과 setup loop에 아두이노 기본 과정만 하면 동작**하도록 구성된 적이 있다.
> 지금처럼 복잡해진 이유는 무엇인가 **과거처럼 단순한 구조로 지원 불가한가?**"*  → *"**요청하라.**"*

## 루트가 값으로 답한 것 — 복잡함의 원인은 기능이 아니라 **경계 없음**이다

```c
void setup() {
  Serial.begin(115200);
  espInit();                              ← 프레임워크
🔴 slotStart = millis();                   ← **내부 상태** · 주석: "반드시 여기서 잡는다"
  randomSeed(analogRead(A1) ^ micros());  ← 프레임워크 요구
  node.begin();                           ← 프레임워크
  pinMode(PIN_SAMPLE_LED, OUTPUT);        ← ✅ 기여자
  router.on("LD", cmdLed);                ← ✅ 기여자
  router.on("L2", cmdL2);                 ← ✅ 기여자
🔴 node.testArmed = false;                 ← **내부 상태**
🔴 node.slotOverrideClearAll();            ← **내부 상태**
  pinMode(PIN_ESP_RST, INPUT);            ← 프레임워크
  Serial.print(F("\n[NET] 대상 …"));       ← 진단 배너
}
void loop() { wdt_reset(); espReset(now); espRead(); drainPending(); … }   ← 전부 프레임워크
```
> ### **기여자 줄은 셋이고 나머지는 전부 프레임워크다. 그런데 같은 함수에 있다.**
> **그리고 그 위험을 설명하는 주석이 길어져서 코드가 더 안 읽힌다.**

🔑 **우리 규칙이 이미 답을 갖고 있다**(CLAUDE.md):
> **판별자는 "그 순서를 호출자가 *바꿀 수 있는가*" 다. 바꿀 수 없다 → 🔒 함수 안에 넣어라.
> 드러내 봐야 *지킬 의무* 만 생기고 얻는 것이 없다.**

`slotStart = millis()` 의 주석이 스스로 *"**반드시** 여기서 잡는다"* 라고 말한다. **바꿀 수 없는 순서다.**

## 목표 형태

```c
void setup() {
  Serial.begin(115200);
  ParkingNode.begin();            // 링크·슬롯 원점·시드·리셋선·오버라이드 초기화 전부
  pinMode(13, OUTPUT);            // 🔓 내 핀
  ParkingNode.on("LD", cmdLed);   // 🔓 내 모듈
}
void loop() { ParkingNode.tick(); }
```
아두이노 관용(`Servo.h`·`LiquidCrystal.h`)과 같은 모양. **기여자가 배우는 것이 `begin`·`on`·`tick` 셋.**

## 🔴 두 단계로 갈라라 — 묶을 이유가 없다

```
A단계  setup()/loop() 의 **경계 세우기** — 프레임워크 줄을 begin()/tick() 안으로
       → RAM 비용 ~0. 🔑 **이것만으로 setup() 이 다섯 줄이 된다.** 사용자 요구의 대부분이 여기서 끝난다
B단계  MODULE_TABLE 을 **런타임 등록**으로(`ParkingNode.module("A1","IP",2)`)
       → 🔴 RAM 비용이 있다(지금 PROGMEM 상수). **A 를 끝내고 재고 나서 판단한다**
       🔴🔴 **선행 조건: `ramLow` 실측** — 아래 정정 참조. 그 값 없이는 착수 금지
```
**A 를 먼저 해라.** B 는 값이 나온 뒤 별건으로 정한다.

## 🔴🔴 A 단계의 가장 큰 위험 — `espInit` 이 물린 그 형태다

```
`slotStart = millis()` 를 `begin()` 안으로 옮기면 **millis() 호출 시점이 바뀐다**
→ 원장 §"흩어진 것을 모으면 그것이 곧 거동 변경이다" — espInit 이 정확히 이것으로 물렸다
🔴 그리고 `slotStart` 와 `netStepAt` 의 **선후가 바뀔 수 있다**(원장 §26 의 그 항목)
```
**옮기는 순서를 원래 순서와 같게 유지해라.** 그리고 **무엇과 무엇의 선후가 바뀌는지 값으로 적어라** —
"몇 줄 이동"으로만 적으면 그 축이 안 세어진다.

## 사전 등록 — **네가 문턱을 정하고 나에게 알려라**

B단계 착수 여부를 정할 RAM 증분 문턱을 **재기 전에** 박아라. 앞서 `AckQueue` 파일럿에서 한 그 형식이다.
🔴 **결과를 보고 해석을 고치지 마라.** 문턱을 바꿀 근거가 생기면 **새 수를 만들어** 재논의한다.

### 🔴🔴 정정 — 루트가 쓴 `여유 837B` 는 **예산이 아니다** (arduino 가 발행 직후 반증했다)

~~여유 837B~~ 를 RAM 예산으로 쓰면 안 된다. **정의가 다른 두 수다:**
```
컴파일러 : `지역변수 837B 남음` = 2048 − 1211(**정적** 사용량)
           → 🔴 **실행 중 스택이 그 안으로 내려간다. 예산 상한이 아니라 *시작점* 이다**
실측     : `Diag.h` 의 `ramLow` = 가장 깊은 호출 지점에서 관측된 **최저 여유**
           → 🔴 **지금 판(543fbe7)은 미계측** — 시리얼 `[RAM]` 줄에만 있고 탭이 안 열렸다
⚠ `-fstack-usage` 는 이 툴체인에서 `.su` 가 비어 나온다 — 정적 분석으로 못 메운다
```
> ### **§"숫자 둘을 비교하기 전에 정의를 맞춰라" 의 이 도메인 판본이다.**
> **둘 다 'B' 이고 둘 다 'RAM 여유'다. 그래서 그냥 대 보게 된다.**

**그래서 B단계의 1단계를 이렇게 잡는다:**
```
1-a  `ramLow` **실측을 먼저 얻는다** — 다음 굽기 세션의 부팅 로그 + 몇 분 관측 (🔑 D5 와 같은 기회다)
1-b  그 값을 예산으로 잡고 런타임 등록 증분을 잰다
⚠ 1-b 를 먼저 하면 "여유가 있다"를 837 기준으로 판단하게 된다
```
🔑 **A단계는 이 제약과 무관하다**(코드 이동이라 RAM 이 안 늘어난다). **A 는 지금 진행해라.**

## 왜 필요한가

setup() 에 프레임워크 내부 상태(slotStart·testArmed·slotOverrideClearAll)가 기여자 줄과 섞여 있고, 그 위험을 설명하는 주석이 길어져 코드가 더 안 읽힌다. 기여자 줄은 셋인데 나머지 전부가 같은 함수에 있다

### 🔴 표지 하나를 **일부러 고쳤다** — REQ 판별자("표지 불변")의 예외다

```
전 : [BOOT] 사다리 4단(ESP 하드리셋선) 미배선 — A2 를 ESP RST 에 물리고 ESP_RST_WIRED=1
후 : [BOOT] 사다리 4단(ESP 하드리셋선) 배제(설계) — hang 을 없애 불필요
```
🔑 **옛 문구가 거짓이다.** 사용자가 하드 리셋을 **설계로 배제**했다(송수신 재설계로 펌웨어 hang 이
사라졌고, 하드 리셋으로만 풀리는 고장이 그 hang 뿐이었다). 옛 문구는 *"물리고 1 로 바꿔라"* 라는
**할 일 목록**으로 읽혀 **다음 사람이 되살리게 만든다** — CLAUDE.md §"아직 안 했다와 안 하기로 했다를
로그가 구분해야 한다" 의 실물 사례가 정확히 이 문구다. 되살릴 조건(`hang 이 다시 관측되면`)을
주석에 박았다. **monitor 에 표지 변경으로 예고한다.**

### 🔴 내가 저지른 것 하나 — 함수 둘을 삼켰다 (컴파일러가 잡았다)

`setup()` 을 통째로 교체할 때 범위를 `void setup()` ~ `void loop()` 로 잡았는데
**그 사이(352·373행)에 `diagTick`·`ramTick` 정의가 있었다.** 둘이 사라졌다.
```
🔴 줄 수를 봤는데도 안 걸렸다 : 395 → 283. setup 축약분으로 대충 설명이 됐다
✅ 컴파일러가 잡았다 : `'diagTick' was not declared in this scope`
✅ git 에서 원문 그대로 복구해 `Runtime.h` 로 옮겼다
```
🔑 §"상태를 바꾸는 명령 뒤에는 상태를 조회하는 명령을 붙인다" — **줄 수 판본**이다.
**"큰 구간을 통째로 대체"할 때는 그 구간에 무엇이 있었는지 먼저 세라.** 원장에 넣는다.

### 사전 등록 — B단계 RAM 문턱 (🔴 **재기 전에 박는다**)

```
선행 조건 : `ramLow` **실측**. 없으면 착수 금지 (다음 굽기 세션 = DEFERRED D5 와 같은 기회)
           ⚠ 컴파일러의 `여유 836B` 는 **정적**이다. 예산이 아니다
문턱 (런타임 등록의 RAM 증분을 `ramLow` 실측 대비 비율로 본다) :
   ≤ 25%      → 진행한다
   25 ~ 50%   → **계획을 줄인다** (표만 런타임으로, 이름·kind 는 PROGMEM 유지)
   > 50%      → **접는다.** 재개 조건 = RAM 여유가 늘어나는 다른 변경이 들어올 때
🔴 결과를 보고 이 문턱을 고치지 않는다. 고칠 근거가 생기면 **새 수를 만들어** 재논의한다
```
⚠ 절대값이 아니라 비율로 박은 이유: `ramLow` 를 아직 모른다. **모르는 값에 절대 문턱을 박으면
그 문턱이 곧 낡는다.**

### 범위 — 전선·서버·화면 **아무것도 안 바뀐다**

`GUIDE.md` 에 `setup`/`loop` 절을 넣었다(기여자가 배우는 것이 바뀐다). `⚠ node.tick() 을 빼거나
delay() 로 막지 마라` 도 같이 적었다 — 한 줄이 되면서 **지워도 컴파일은 되는** 형태가 됐기 때문이다.
