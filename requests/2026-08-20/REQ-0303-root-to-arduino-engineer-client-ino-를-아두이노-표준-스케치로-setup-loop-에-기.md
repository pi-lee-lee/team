# REQ-0303 · 🔴 client.ino 를 아두이노 표준 스케치로 — setup/loop 에 기여자 줄만 남긴다 (사용자 지시)

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

사용자 질문과 지시:
> *"client.ino에 과거에는 **핀설정과 setup loop에 아두이노 기본 과정만 하면 동작**하도록 구성된 적이 있다.
> 지금처럼 복잡해진 이유는 무엇인가 **과거처럼 단순한 구조로 지원 불가한가?**"*  → *"**요청하라.**"*

## 루트가 값으로 답한 것 — 복잡함의 원인은 기능이 아니라 **경계 없음**이다

```c
void setup() {
  Serial.begin(115200);
  espInit();                              ← 프레임워크
🔴 slotStart = millis();                   ← **내부 상태** · 주석: "반드시 여기서 잡는다"
  randomSeed(analogRead(A1) ^ micros());  ← 프레임워크 요구
  node.begin();                           ← 프레임워크
  pinMode(PIN_SAMPLE_LED, OUTPUT);        ← ✅ 기여자
  router.on("LD", cmdLed);                ← ✅ 기여자
  router.on("L2", cmdL2);                 ← ✅ 기여자
🔴 node.testArmed = false;                 ← **내부 상태**
🔴 node.slotOverrideClearAll();            ← **내부 상태**
  pinMode(PIN_ESP_RST, INPUT);            ← 프레임워크
  Serial.print(F("\n[NET] 대상 …"));       ← 진단 배너
}
void loop() { wdt_reset(); espReset(now); espRead(); drainPending(); … }   ← 전부 프레임워크
```
> ### **기여자 줄은 셋이고 나머지는 전부 프레임워크다. 그런데 같은 함수에 있다.**
> **그리고 그 위험을 설명하는 주석이 길어져서 코드가 더 안 읽힌다.**

🔑 **우리 규칙이 이미 답을 갖고 있다**(CLAUDE.md):
> **판별자는 "그 순서를 호출자가 *바꿀 수 있는가*" 다. 바꿀 수 없다 → 🔒 함수 안에 넣어라.
> 드러내 봐야 *지킬 의무* 만 생기고 얻는 것이 없다.**

`slotStart = millis()` 의 주석이 스스로 *"**반드시** 여기서 잡는다"* 라고 말한다. **바꿀 수 없는 순서다.**

## 목표 형태

```c
void setup() {
  Serial.begin(115200);
  ParkingNode.begin();            // 링크·슬롯 원점·시드·리셋선·오버라이드 초기화 전부
  pinMode(13, OUTPUT);            // 🔓 내 핀
  ParkingNode.on("LD", cmdLed);   // 🔓 내 모듈
}
void loop() { ParkingNode.tick(); }
```
아두이노 관용(`Servo.h`·`LiquidCrystal.h`)과 같은 모양. **기여자가 배우는 것이 `begin`·`on`·`tick` 셋.**

## 🔴 두 단계로 갈라라 — 묶을 이유가 없다

```
A단계  setup()/loop() 의 **경계 세우기** — 프레임워크 줄을 begin()/tick() 안으로
       → RAM 비용 ~0. 🔑 **이것만으로 setup() 이 다섯 줄이 된다.** 사용자 요구의 대부분이 여기서 끝난다
B단계  MODULE_TABLE 을 **런타임 등록**으로(`ParkingNode.module("A1","IP",2)`)
       → 🔴 RAM 비용이 있다(지금 PROGMEM 상수). **A 를 끝내고 재고 나서 판단한다**
       🔴🔴 **선행 조건: `ramLow` 실측** — 아래 정정 참조. 그 값 없이는 착수 금지
```
**A 를 먼저 해라.** B 는 값이 나온 뒤 별건으로 정한다.

## 🔴🔴 A 단계의 가장 큰 위험 — `espInit` 이 물린 그 형태다

```
`slotStart = millis()` 를 `begin()` 안으로 옮기면 **millis() 호출 시점이 바뀐다**
→ 원장 §"흩어진 것을 모으면 그것이 곧 거동 변경이다" — espInit 이 정확히 이것으로 물렸다
🔴 그리고 `slotStart` 와 `netStepAt` 의 **선후가 바뀔 수 있다**(원장 §26 의 그 항목)
```
**옮기는 순서를 원래 순서와 같게 유지해라.** 그리고 **무엇과 무엇의 선후가 바뀌는지 값으로 적어라** —
"몇 줄 이동"으로만 적으면 그 축이 안 세어진다.

## 판별자 — hex 는 못 쓴다

```
❌ hex 0   — 코드 이동이므로 반드시 바뀐다
✅ 전선 바이트 불변 : stage1_test 전선 기대값 **diff 0** (REQ-0299 에서 쓴 그 방법)
✅ stage1_test **343 PASS** 유지
✅ 부팅 표지 불변 : [REG] 54B · D,*,7,4, · 네 줄 · [NET] 대상 · [SENS] 핀번호
✅ flash·RAM 증분을 값으로 (줄면 정상, 늘면 그것이 신호)
🔴 선후 교체 목록 — 위 위험 때문에 **따로 적어라**
```

## 사전 등록 — **네가 문턱을 정하고 나에게 알려라**

B단계 착수 여부를 정할 RAM 증분 문턱을 **재기 전에** 박아라. 앞서 `AckQueue` 파일럿에서 한 그 형식이다.
🔴 **결과를 보고 해석을 고치지 마라.** 문턱을 바꿀 근거가 생기면 **새 수를 만들어** 재논의한다.

### 🔴🔴 정정 — 루트가 쓴 `여유 837B` 는 **예산이 아니다** (arduino 가 발행 직후 반증했다)

~~여유 837B~~ 를 RAM 예산으로 쓰면 안 된다. **정의가 다른 두 수다:**
```
컴파일러 : `지역변수 837B 남음` = 2048 − 1211(**정적** 사용량)
           → 🔴 **실행 중 스택이 그 안으로 내려간다. 예산 상한이 아니라 *시작점* 이다**
실측     : `Diag.h` 의 `ramLow` = 가장 깊은 호출 지점에서 관측된 **최저 여유**
           → 🔴 **지금 판(543fbe7)은 미계측** — 시리얼 `[RAM]` 줄에만 있고 탭이 안 열렸다
⚠ `-fstack-usage` 는 이 툴체인에서 `.su` 가 비어 나온다 — 정적 분석으로 못 메운다
```
> ### **§"숫자 둘을 비교하기 전에 정의를 맞춰라" 의 이 도메인 판본이다.**
> **둘 다 'B' 이고 둘 다 'RAM 여유'다. 그래서 그냥 대 보게 된다.**

**그래서 B단계의 1단계를 이렇게 잡는다:**
```
1-a  `ramLow` **실측을 먼저 얻는다** — 다음 굽기 세션의 부팅 로그 + 몇 분 관측 (🔑 D5 와 같은 기회다)
1-b  그 값을 예산으로 잡고 런타임 등록 증분을 잰다
⚠ 1-b 를 먼저 하면 "여유가 있다"를 837 기준으로 판단하게 된다
```
🔑 **A단계는 이 제약과 무관하다**(코드 이동이라 RAM 이 안 늘어난다). **A 는 지금 진행해라.**

## 🔴🔴 B단계를 **바꾼다** — 런타임 등록이 아니라 **표 한 줄에 핸들러까지** (사용자 지시 2026-08-20)

> 사용자 원문: *"**Ram문제가 있다면 코드 작성을 더 직관적이고 쉽게** 만들어달라.
> **`LD` 같이 고정된 이름이 아닌 `a1` `b1` 이런식으로 센서에 이름을 정하고
> 서버에서 `p1 a1`, `b1` 으로 받아 이용할수 있는 구조이다.**"*

### 루트가 잰 것 — `LD` 하나에 **네 곳**이다

```
client.ino:112  {"LD", "OG", PIN_SAMPLE_LED}    ← 이름 · 종류 · 핀
client.ino:199  static bool cmdLed(uint32_t arg) ← 핸들러
🔴 client.ino:266  pinMode(PIN_SAMPLE_LED, OUTPUT);  ← **표에 핀이 있는데도 기여자가 또 잡는다**
🔴 client.ino:270  router.on("LD", cmdLed);          ← **이름이 두 번째로 등장한다**
```
> ### **오늘 `SLOT_PIN[]` 을 없앤 것과 같은 부류가 액추에이터 쪽에 남아 있다.**
> 센서는 `begin()` 이 표에서 핀을 읽어 `pinMode` 를 잡는다. **액추에이터는 안 잡아 준다.**

### 목표 — 표가 핸들러까지 갖는다

```c
static const ModuleDef MODULE_TABLE[] PROGMEM = {
  {"A1", "IP", 2},                    // 센서 — 핀만
  {"B1", "IP", 9},
  {"LD", "OG", 13,       cmdLed},     // 🔓 액추에이터 — **핸들러까지 한 줄**
  {"L2", "OL", PIN_NONE, cmdL2},
};
```
```
기여자가 고치는 곳 : **표 한 줄 + 핸들러 함수.** 그것이 전부다
사라지는 것       : `router.on(...)` · 액추에이터의 `pinMode(...)`
`begin()` 이 한다  : 센서 핀 INPUT · **액추에이터 핀 OUTPUT** · 핸들러 결속
```

### 🔑 그리고 이것이 런타임 등록보다 낫다 — **RAM 증분 0**

```
표가 PROGMEM 이므로 **함수 포인터도 플래시에 간다**(AVR 함수 포인터 2B/모듈)
→ 🔴 `ramLow` 실측을 기다릴 필요가 없다. **B단계의 선행 조건이 사라진다**
→ 그리고 결과가 런타임 등록보다 **더 단순하다**(등록 호출이 아예 없다)
```
⚠ **`ramLow` 실측은 여전히 해라**(DEFERRED D5). 이 작업의 전제가 아니라 **별건의 미계측**이다.

### ⚠ 값으로 확인할 것

```
· PROGMEM 함수 포인터 읽기(`pgm_read_ptr`)가 이 툴체인에서 되는지 — **실측해라**
  🔑 오늘 `constexpr` 파생을 그렇게 재서 설계를 정했다. 같은 방식으로
· 플래시 증분 (RAM 이 아니라 플래시가 늘어난다)
· 센서 훅(`sensors.on`)도 같은 형태로 합칠 수 있는가 — 다만 센서는 기본이 `digitalRead` 라
  훅이 **선택적**이다. 합치면 빈 칸이 생긴다. **판단해서 값으로 답해라**
```

### 이름에 대한 사용자 확인

*"서버에서 `p1 a1`, `b1` 으로 받아 이용할 수 있는 구조"* — **이미 그렇다.** 서버는 `(devid, name)` 쌍으로 받는다(`lot.module("P1","A1")`). **이름은 지금도 기여자가 자유롭게 정한다**(2글자).
🔴 다만 `PIN_SAMPLE_LED` 같은 매크로가 이름과 얽혀 **고정처럼 보인다.** 그것도 걷어라.

## 🔴🔴 B단계 재갱신 — **`kind` 문자열을 기여자에게서 감춘다** (사용자 지시)

> 사용자 원문: *"**그런식으로 옵션을 체크해서 사용하는방식이 힘들다.
> 모든 옵션을 `IP` `OG` 등 낯선 설정이다.**"*

### 무엇이 문제인가 — 기여자가 **계약이 안 보는 값**을 외워야 한다

```
서버 : nodes.h:522  kind_commandable(k) { return k[0] == 'O'; }   ← **첫 글자만** 본다
장치 : Modules.h:185  if (k4[0] != 'O') return false;             ← **첫 글자만** 본다
🔴 그런데 기여자는 `"IP"`·`"IX"`·`"OG"`·`"OL"`·`"OB"` 다섯을 골라야 한다
   → **둘째 글자는 아무도 안 읽는다.** 사람이 로그에서 읽는 표시일 뿐이다
```
> ### **계약이 안 보는 값을 기여자에게 고르게 하고 있다. 그것이 "낯선 설정" 의 정체다.**

### 목표 형태 — 종류가 **이름으로** 드러난다

```c
static const ModuleDef MODULE_TABLE[] PROGMEM = {
  SENSOR  ("A1", 2),                  // 관측만 한다
  SENSOR  ("B1", 9),
  ACTUATOR("LD", 13,       cmdLed),   // 명령을 받는다
  ACTUATOR("L2", PIN_NONE, cmdL2),
};
```
```
기여자가 배우는 것 : **SENSOR · ACTUATOR 둘.** `IP`/`OG` 를 몰라도 된다
전선은 불변       : 매크로가 `"I…"`·`"O…"` 를 채운다 → `D,A1,IP` 그대로
RAM 증분          : **0** (PROGMEM 상수 그대로)
```

### 🔑 그리고 이것은 서버의 v2 결정과 **모순이 아니다**

socket 이 v2 에서 `sensor()/actuator()` 를 `module()` **하나로 합쳤다.** 근거는
*"장치가 `kind` 첫 글자로 이미 말한다 — 조립 표에서 또 가를 이유가 없다"* 였다. **그것은 그대로 맞다.**

```
서버 : 장치가 말해 주니 **안 가른다** → `module()` 하나  ✅
장치 : 🔴 **자기가 말하는 쪽이다.** 여기서 가르는 것이 그 정보의 **원천**이다  ✅
```
**받는 쪽에서 합치고 보내는 쪽에서 가르는 것이 맞는 방향이다.** 반대면 서버가 짐작해야 한다.

### 판단해서 값으로 답할 것

```
① 둘째 글자를 무엇으로 채우나
   · 기본값 하나로 고정할지, 아니면 `ACTUATOR_AS("DR","OB",7,gate)` 처럼 **선택 인자**로 둘지
   🔑 판별자 : 그 글자를 **사람이 로그에서 읽는 값**으로 쓸 가치가 있는가.
     있으면 선택 인자, 없으면 고정. **없는 것을 남기지 마라**
② `IX`(입출차센서)를 쓰는 자리가 실제로 있는가 — 있으면 `SENSOR` 하나로 못 덮는다
③ 매크로냐 constexpr 함수냐 — 🔑 **오류 문구가 짧은 쪽을 골라라.**
   기여자가 처음 만나는 컴파일 오류가 여기서 난다
④ 플래시 증분
```

### ⚠ 이것과 앞 절(표에 핸들러)은 **같은 한 줄을 만진다**

**따로 하지 마라.** 표 형태를 한 번에 정해라 — 두 번 고치면 기여자 문서도 두 번 낡는다.

## 범위
```
✅ 조별과제샘플/ardu/** · GUIDE.md (기여자가 배우는 것이 바뀐다)
❌ 전선 · 서버 · 화면 — 아무것도 안 바뀐다. 바뀌어야 한다고 판단되면 **착수 전에 알려라**
❌ 차단봉 DR · 값 에코 C — 사용자 답 대기 그대로
⚠ 굽기가 필요하다. 굽기 직전 한 줄을 monitor 와 루트에게
🔑 `hex 0` 인 부분(주석·개명)이 섞여 있으면 **그것부터 따로 커밋해라** — 창을 안 깨는 일이 먼저다(네 규칙)
```

## 왜 필요한가

setup() 에 프레임워크 내부 상태(slotStart·testArmed·slotOverrideClearAll)가 기여자 줄과 섞여 있고, 그 위험을 설명하는 주석이 길어져 코드가 더 안 읽힌다. 기여자 줄은 셋인데 나머지 전부가 같은 함수에 있다

## 대상 파일

## 완료 기준

setup() 이 Serial.begin + begin() + 기여자 핀·모듈 줄만 남고 loop() 가 tick() 한 줄이다. 전선 바이트 불변(stage1_test diff 0) · 343 PASS · 부팅 표지 불변 · 선후 교체 목록이 값으로 적혀 있다. B단계 RAM 문턱이 재기 전에 등록돼 있다
