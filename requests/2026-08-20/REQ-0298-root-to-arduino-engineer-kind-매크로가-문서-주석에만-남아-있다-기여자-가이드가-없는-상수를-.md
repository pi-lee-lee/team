# REQ-0298 · KIND_* 매크로가 문서·주석에만 남아 있다 — 기여자 가이드가 없는 상수를 가르친다 (사용자 지적)

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

사용자 지시:
> *"`KIND_GUIDE_LIGHT` 이거 없애기로 했는데 **여전히 남아있다.**"*

## 🔴 하나가 아니다 — 루트가 전수로 쟀다

```
#define KIND_*                코드에 **0건**. 매크로가 전부 사라졌다
🔴 GUIDE.md:66-70            매크로 **다섯**을 표로 나열한다
                             (KIND_PARK_SENSOR · KIND_GATE_SENSOR · KIND_GUIDE_LIGHT
                              · KIND_LEAD_LIGHT · KIND_BARRIER) — **전부 존재하지 않는다**
🔴 FrameCodec2.h:6, 16       주석이 여전히 `KIND_*` 를 참조한다
실제 코드                     `{"A1", "IP", 2}` — **문자열 리터럴**이다
```

**사용자가 하나를 짚었고 전수를 재니 부류였다.** 같은 검사를 옆에 돌려서 나온 것이다.

## 왜 이 문서가 특히 나쁜 자리인가

`조별과제샘플/ardu/GUIDE.md` 는 **기여자 배포 단위 안**이다(네가 오늘 밖 참조를 없애려고 옮긴 그 파일).
🔴 **기여자가 존재하지 않는 매크로를 쓰라고 배운다. 그대로 따라 하면 컴파일 오류다.**
원장: *"연습 파일의 결함은 제품의 결함보다 오래 산다 — 읽는 사람이 그것을 정답으로 베낀다."*

## 할 것

```
① GUIDE.md 표 : 매크로 열을 없애고 **전선 값(문자열)** 기준으로 다시 써라
                지금 계약은 **첫 글자만**이다(`I` 관측 · `O` 명령) — 표가 그것을 말해야 한다
                🔑 그 아래 "첫 글자 O 가 명령을 뜻한다" 문장은 **이미 맞다.** 표만 어긋났다
② FrameCodec2.h 주석 둘 : `KIND_*` 참조를 지금 구조로 고쳐라
③ 같은 검사를 네 트리 전체에 한 번 더 돌려라 — 내가 잰 것은 확장자 넷뿐이다
```

## ⚠ 왜 이것이 잊혔는지도 적어 둘 값이 있다

CLAUDE.md 에 이미 적혀 있다: *"socket 이 '계약을 좁히는 변경이라 굽기를 안 막는다' 고 했고,
그것이 루트에게 '지금 안 해도 된다' 로 읽혀 우선순위에서 밀렸고 **잊혔다**."*
**이번엔 사용자가 다시 짚어서 살아났다.** 남은 것이 있으면 목록에 남겨라 — 대화 안에만 두면 또 잊힌다.

## 범위
```
✅ 조별과제샘플/ardu/GUIDE.md · FrameCodec2.h 주석 · 같은 부류 전수
❌ 코드 거동 — 매크로는 이미 없다. 🔑 **굽기 불필요**(문서·주석은 hex 에 안 들어간다)
   ⚠ 그래도 `hex` 대조는 해라 — "주석만 고쳤다"의 증거가 그것이다
❌ 관측 · 판정 문서
```

## 왜 필요한가

코드에 #define KIND_ 가 0건인데 기여자 가이드가 매크로 다섯을 표로 가르친다. 그대로 따라 하면 컴파일 오류이고, 기여자는 왜 안 되는지 모른다

## 대상 파일

- `조별과제샘플/ardu/GUIDE.md`
## 완료 기준

GUIDE.md 표가 전선 값(문자열) 기준이고 첫 글자 계약을 말한다. FrameCodec2.h 주석의 KIND_* 참조가 없다. 같은 부류 전수 확인 결과가 적혀 있다. hex 차이 0

### 고친 것 셋 — 하나는 루트가 안 잰 자리다

```
① 조별과제샘플/ardu/GUIDE.md:66-72   매크로 5행 표 → **전선 값 기준 표**로 다시 씀
② 조별과제샘플/ardu/FrameCodec2.h:6,16  `KIND_*` → `ModuleDef 정의` (지금 앞에 오는 것이 그것이다)
🔴 ③ 조별과제샘플/ardu/client.ino:72  **치환 잔재** — 루트의 전수에 없던 자리
     `종류 : "IP"(`IP` 관측) · "IX"(`IX`) · "OB"(`OB` 명령)`
     ↑ 매크로를 문자열로 일괄치환하면서 **같은 말을 두 번 하는 문장**이 됐다.
       `"IX"(`IX`)` 는 뜻이 통째로 사라진 칸이다 — 옛 `KIND_GATE_SENSOR`(`IX`) 의 흔적
     → `첫 글자만 뜻이 있다 — I=관측 전용("IP" "IX") · O=명령 받음("OG" "OL" "OB")`
```
🔑 **§"치환으로 리팩터링할 때 새 정의가 자기 패턴에 걸린다" 의 *주석* 판본이다.**
매크로 이름을 값으로 바꾸면 **그 이름을 설명하던 문장이 자기 설명을 잃는다.** 컴파일은 통과한다.

### 표를 무엇 기준으로 다시 썼나 — **정본은 코드다**

```c
client.ino:80  char kind[4];   // 🔴 첫 글자만 뜻이 있다: I=관측 전용 · O=명령 받음
                               //   둘째 글자부터는 자유다(서버는 안 본다). 2~3글자 + NUL
Modules.h:185  if (k4[0] != 'O') return false;      // ← 판정은 이 한 줄이다
```
그래서 새 표는 **전선 값 다섯을 관례로** 싣고 *"계약이 아니다"* 를 명시했다.
⚠ 옛 표는 매크로가 **다섯 종류를 정의하는 것처럼** 보이게 만들었다 — 실제로는 `I`/`O` **둘**이다.
🔑 `IX` 는 지금 샘플 표에 **한 줄도 없다**(쓰이는 것은 `IP`·`OG`·`OL`, 그리고 `VIRTUAL_MODULES=1` 일 때 `OB`).
   표에 남긴 이유는 서버·화면의 `MOD_KIND_ORDER` 가 그 값을 알고 있기 때문이다.

### ③ 전수 — 확장자 제한 없이 저장소 전체(`grep -rI`)

**내 소유 · 지금을 설명하는 것 → 고쳤다** (위 셋)

**내 소유 · 안 고친 것과 그 이유**
```
docs/arduino/PLAN-class2-2026-08-19.md:153   날짜 붙은 과거 계획. **그 시점 진술**이므로 둔다
arduino/.burn/{client,rf1,rf2,rf3,split1,split3,split4,splitC}/…  (10파일)
   → 굽기 스테이징 사본 = **과거에 실제로 구운 판본의 기록**이다.
     고치면 "그때 구운 것"과 갈린다. 다음 굽기의 `cp` 가 덮는다(cmp 가드가 불일치를 짚는다)
```

🔴 **내 소유가 아닌데 *지금* 을 가르치는 것 둘 — REQ 를 냈다**
```
docs/DESIGN-contributor-guide-2026-08-19.md:18   {"A1", KIND_PARK_SENSOR, 2} …
   → **기여자 가이드 설계 문서**다. GUIDE.md 와 정확히 같은 결함이 root 소유 문서에 있다

```
**시점 진술이라 안 급한 것**(socket·root 소유, 알림만): `docs/net/DESIGN-node-ledger.md:187` ·
`docs/net/LEDGER.md:4655`(둘 다 `FrameCodec.h:85` 위치 참조가 낡음) · `CLAUDE.md:2955`(과거 사례 서술).

⚠ **오검출을 걸러냈다**: `MOD_KIND_LABEL`·`MOD_KIND_ORDER`·`TEST_KIND_LABEL`(web·server·net 도구 다수)은
**실재하는 JS/C++ 식별자**다. `KIND_` 가 부분 문자열로 걸린 것이고 **결함이 아니다.**
🔑 §"패턴을 짓기 전에 도구의 출력을 눈으로 봐라" — `grep -c` 만 봤으면 이 열몇 건을 결함으로 셌다.

### 검증 — hex 대조 **네 방향**(기준을 문장에 담는다 · §39)

빌드 플래그는 칩과 같게 맞췄다: `-DSERVER_PORT="8888"` · `arduino:avr:uno` · 응용영역만(`APP_END=32256`)
```
① 수정후 vs **HEAD(d41ad13) 빌드**        : 0 바이트 상이   ← 주석만 고쳤다의 증거
② HEAD 빌드 vs **.burn/l2v**(칩에 올린 산출물) : 0 바이트 상이   ← HEAD == 칩 판본
③ 수정후 vs **.burn/l2v**                  : 0 바이트 상이   ← **지금 소스와 칩이 같다**
④ 음성대조 HEAD vs .burn/burn0010          : **25,311 바이트 상이**  ← 대조기가 차이를 실제로 잡는다
빌드 수치도 10:42 굽기 기록과 같다 : flash 27,172(84%) · RAM 1,215 · 프로그램 27,039B
```
🔑 **④ 를 같이 돌린 이유**: 셋이 다 `0` 이면 *"항상 0 을 뱉는 스크립트"* 와 구별이 안 된다(§32).
**굽기 불필요**가 값으로 확정됐다. **보드·포트는 건드리지 않았다**(컴파일만).
