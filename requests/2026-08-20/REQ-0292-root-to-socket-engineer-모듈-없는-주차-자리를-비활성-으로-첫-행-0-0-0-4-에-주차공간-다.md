# REQ-0292 · 모듈 없는 주차 자리를 '비활성'으로 — 첫 행 (0,0)~(0,4) 에 주차공간 다섯 (사용자 지시)

**요청자** `root` → **담당** `socket-engineer`

## 요청 내용

사용자 지시:
> *"모듈연결없이 주차공간만 할당하면 **비활성된 주차공간으로 표시**되도록 해서
> **0,1,2,3,4 자리에 주차공간을 할당**해달라."*

## 할 것 둘

### ① `lot.cpp` — 첫 행에 주차 자리 다섯
```
(0,0) A1  parking · 모듈 있음(기존 그대로 — P1 A1/B1/LD/L2)
(0,1) …   parking · **모듈 없음**
(0,2) …   parking · **모듈 없음**
(0,3) …   parking · **모듈 없음**
(0,4) …   parking · **모듈 없음**
```
자리 id·label 은 네가 정해라. E1 은 REQ-0291 로 (3,4)로 간다 — 첫 행이 비어 있다.

### ② 🔴 봉투에 "모듈 0개" 를 실어라 — **계산 주체는 서버다**

```
조립 표를 가진 것은 서버다. 화면이 모듈 수를 세서 조합하게 하지 마라
→ 화면이 조합하면 같은 규칙이 두 곳에 생긴다(원장 §"계산 주체를 적어라")
```
**이름은 네가 정하고 명세에 박아라.** 그리고 **web 에게 REQ 로 넘겨라** — 화면이 그것을 보고
"비활성" 으로 그린다. 내가 이름을 지어 주지 않는 이유는 §"쓰기 전에 남의 이름을 먼저 찾아라" 다.

## 🔑 이건 이미 우리가 아는 함정이다 — 이제 보이게 만드는 것이다

원장에 적혀 있다:
> *"센서가 하나도 없는 주차 자리 → 점유가 영원히 `unknown`.
>  ⚠ 화면에는 자리가 보이는데 값이 안 채워진다 → **'센서가 고장났나'를 쫓게 된다**"*

**`unknown` 을 없애지 마라.** 값 경로가 없는데 값을 만들면 그것이 지어내는 것이다
(원장 §"`known:false` 를 `known:true`(틀림)로 바꾸지 마라"). **비활성은 그 무지의 *이유* 를 보여 주는 것이다.**

## ⚠ 갈라야 하는 두 상태 — 같은 이름으로 부르지 마라

```
모듈이 **0개**        → 조립 시점에 안다        → 이번에 만드는 "비활성"
모듈은 있고 센서가 없다 → **등록 뒤에** 안다      → v2 에서 bind_modules 로 옮긴 그 검사
```
v2 가 `sensor()/actuator()` 를 합쳐서 **등록 전엔 센서를 못 가른다.** 하지만 *"module() 호출이 0개"* 는
조립 시점에 안다. **둘은 다른 시점의 다른 사실이다.**

## 배포

**REQ-0291(E1 좌표)과 같은 배포에 태워라.** 같은 파일이고 같은 확인 대상이다 — 개입을 아낀다.
배포 직전 한 줄만 monitor 와 루트에게.

## 범위
```

❌ 엔진 점유·예약 판정 로직 — 안 바꾼다. unknown 은 unknown 이다
❌ 판정 문서 · 관측 — 확인은 사용자가 화면으로 한다
```

## 왜 필요한가

모듈 없는 주차 자리는 점유가 영원히 unknown 인데 화면에는 평범한 자리로 보인다. 그러면 센서 고장을 쫓게 된다. 무지의 이유를 화면이 보이게 해야 한다

#### 🔑 `unknown` 을 안 지웠다
그 자리의 점유는 여전히 모르는 것이 맞다. `active` 는 **그 무지의 *이유*** 를 말한다 —
*"센서가 고장난 게 아니라 애초에 아무것도 안 붙였다."* 엔진 점유·예약 판정은 한 줄도 안 바꿨다.
