# REQ-0309 · 🔴 주석을 걷고 그 자리에 검증받는 예제를 둔다 — 코드보다 주석이 많다 (사용자 지시)

**요청자** `root` → **담당** `arduino-engineer`

## 요청 내용

사용자 지시:
> *"지금 싹다 감춰졌는데 **주석정리는 좀 해야겠다. 코드보다 주석이 많다.**"*

앞서 확정한 규칙의 집행이다:
> *"**주석 문제는 모든 코드에 심각하다. 주석이 아니라 작업일지다.** 그런 건 주석이 아니다. **일괄로 정리가 필요하다.**"*

## 루트가 잰 값 — 사용자 말이 그대로 맞다

```
조별과제샘플/ardu/ 주석 2,421 / 코드 1,898 = **1.28  ← 🔴 코드보다 주석이 많다**
최악 : EspLink_gate.h **주석 120 / 코드 9** = 13.3 · FrameCodec.h 103/8 = 12.9 · LinkGate.h 122/11 = 11.1 · Boot.h 3.78 · Config.h 3.35 · RxBuf.h 2.67
```

## ★ 판별자 — CLAUDE.md 에 있는 그대로

> **현재형으로 다시 쓸 수 있으면 주석, 과거형이어야 하면 작업일지다.**

```
✅ 남긴다 : 불변식 · 값의 뜻 · 함정 · 금지와 그 이유
           (예: "이 include 순서를 바꾸면 hex 가 달라진다" · "arg 1=열기 2=닫기"
                "이름이 곧 자리 결속 키다" · "OUTPUT HIGH 로 두지 마라 — 5V 가 3.3V 핀에 실린다")
❌ 걷는다 : 날짜 · REQ 번호 · "오늘" · "~가 잡았다" · "전에는 ~였다" · 실측 이력 · 사고 경위
           · 단계 번호("★ 2단계") · 커밋 해시 · 판정 이력
```
🔑 **지우지 말고 옮겨라** — 값 있는 것은 원장·판정문·커밋 메시지로. **옮길 곳이 없는 것만 지운다.**
   (`"2026-08-20 이동"` 같은 것은 `git log` 가 이미 답한다 → 지운다)

## 🔴 왜 이게 급한가 — 오늘 그 비용을 실제로 치렀다

`Modules.h` 주석이 *"이름이 자리 id 와 같아야 한다"* 를 **경고하고 있었다. 아무도 안 읽었다.**
주변이 전부 작업일지라 그 한 줄이 묻혔고, 그래서 **그 함정을 서버가 말하게** 만드느라 반나절을 썼다.

> ### **주석이 길면 안 읽힌다. 안 읽히면 *정작 필요한 경고* 가 같이 묻힌다.**
> ### **작업일지를 걷는 것은 정보를 버리는 것이 아니라 — 경고를 보이게 하는 것이다.**

## 순서 — **비율 높은 파일부터.** 파일 머리의 긴 서사도 같은 대상이다

목표 비율을 숫자로 박지 않는다(임의 문턱은 낡는다). **대신 이렇게 판단해라:**
```
비율 3 이상인 파일 → 🔴 그건 파일이 아니라 문서다. 먼저 해라
파일 머리 서사     → 그 파일을 **처음 여는 사람에게 필요한 것만** 남긴다
                     *왜 이렇게 됐나* 는 원장으로
```

## 판별자 — **`hex` 0 (구운 산출물 대비)**

```
✅ `hex` 0 (구운 산출물 대비) = "주석만 고쳤다" 의 증거다. 값으로 적어라
✅ 코드 줄 수 불변도 같이 적어라 — 증거가 둘이 된다
✅ 시험 통과 수 불변
🔴 무엇과 대조했는지 같이 써라 — `exit=0` 은 문장이 아니다
```


## 🔴🔴 그리고 이것이 이 작업의 절반이다 — **샘플 코드가 없다** (사용자 지시)

> 사용자 원문: *"**어떻게 사용해야하는지 샘플코드가 전혀 없다.**"*

주석이 많은데 **정작 "이렇게 쓰면 된다" 가 없다.** 예시가 전부 주석 처리되어 있다:
```
// sensors.on("A1", readA1);        ← 주석
// router.on("G1", myGate);         ← 주석
// {"A2","IP",3}, {"B2","IP",10}    ← 주석
초음파 예시                          ← 주석 (하드웨어가 없어 일부러 안 켰다 — 그 판단은 맞다)
`choice`(옵션 위젯) 예시             ← 🔴 **어디에도 없다**
켜져 있는 것 : `LD`(내장 LED) · `L2`(숫자) **둘뿐**
```

> ### **주석 안의 예시는 아무 검사도 안 받는다. 컴파일도 안 되고 시험도 없다.**
> ### **코드가 바뀌면 조용히 낡고, 기여자는 그것을 정답으로 베낀다.**
🔑 오늘 socket 이 `parking.h` 헤더 예시에서 정확히 그것을 찾았다 — *"이 파일만 읽으면 된다"* 고
선언한 파일의 예시가 **1인자 `sensor("A1")` · `main()` 안의 `openPorts`** 로 낡아 있었다.

### 그래서 걷어낸 자리에 **동작하는 예제**를 둬라

```
✅ 컴파일되는 완전한 예제로 옮긴다 — 주석이 아니라 코드
✅ `client.ino` 는 **최소 동작**만 유지 (지금처럼 LED 하나)
✅ 예제마다 하나의 개념 : 디지털 센서 · 아날로그/초음파 센서 · 토글 · 숫자 · **옵션(choice)**
🔴 형태는 네가 정해라 — 아두이노 관용은 `examples/` 지만 지금은 단일 스케치다.
   **판별자: 그 예제가 컴파일 검증을 받는가.** 받지 못하는 형태면 고르지 마라
⚠ 없는 하드웨어를 흉내 내지 마라 — 초음파를 안 켠 네 판단이 맞다.
   **예제는 "이렇게 쓴다"를 보여 주면 되고, 그것이 지금 보드에서 돌아야 하는 것은 아니다.**
   다만 **컴파일은 되어야 한다** — 그것이 낡음을 막는 유일한 장치다
```

### ⚠ 그러므로 이 REQ 의 성공 조건이 둘이다

```
① 작업일지를 걷었다        → 산출물 불변으로 증명
🔴 ② 걷어낸 자리에 **검증받는 예제**가 생겼다 → 컴파일 통과로 증명
```
**①만 하면 사용법이 통째로 사라진다.** 주석이 나빴던 것은 *양* 이 아니라 **검증받지 않는다**는 것이다.

## ⚠ 지키라

```
· include 순서·위치 안 건드린다
· 잠금 파일이 대상에 든다 → 검사가 발화하면 **정상이다**(차단이 아니라 설명 요구).
  답은 산출물 불변이고 커밋 메시지에 이 REQ 를 참조한다
· 🔴 **곧 다시 쓰일 구역은 건너뛰어라** — 두 번 일하게 된다. 새로 쓰는 구역은 처음부터 규칙대로
· 관측 창이 돌고 있다. 산출물이 안 바뀌므로 **창을 깨지 않는다** — 굽기·배포 불필요
```

## ⚠ 순서 — **이것이 지금 1번이다**

컴포넌트 작업(REQ-0304)이 **끝났다**(칩 `f5a3f13` · 311 PASS · `GUIDE.md` 갱신). 그래서
*"곧 다시 쓰일 구역은 건너뛰어라"* 조건이 **사라졌다.** 전 구역이 대상이다.
🔑 그리고 **`hex 0` 인 일이라 관측 창을 안 깬다** — 네 규칙대로 창이 열려 있을 때 먼저 하는 일이다.
D7·D1·D2 는 그 뒤다(D7·D2 는 굽기가 필요해 한 경계로 묶는다).

## 왜 필요한가

ardu 주석/코드 비가 1.28 로 코드보다 주석이 많고 최악은 13.3(주석 120/코드 9)이다. 그래서 정작 필요한 경고가 묻힌다 — Modules.h 의 결속 경고가 그렇게 묻혀 반나절을 썼다. 그리고 예시가 전부 주석 처리되어 검증을 안 받는다
