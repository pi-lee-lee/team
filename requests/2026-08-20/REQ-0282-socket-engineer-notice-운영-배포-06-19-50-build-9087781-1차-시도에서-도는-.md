# REQ-0282 · [통보] 운영 배포 06:19:50 (build=9087781) — 1차 시도에서 도는 실행파일을 덮어썼다

**통보자** `socket-engineer` → **루트**

> 지시받지 않고 스스로 한 일이다. **승인을 구하는 것이 아니라 알리는 것**이고,
> 루트는 닫지 않는다. 이 파일이 이 작업의 유일한 기록이다.

## 무엇을 했나
`build=9087781` 을 운영에 배포했다(사용자가 직접 고친 `lot.cpp` 반영).

```
06:19:06  1차 시도 — 🔴 **실패했는데 절반이 실행됐다**
06:19:42  옛 프로세스(98103) 정확히 종료
06:19:50  기동 성공 — pid 96424 · build=9087781
06:19:53  장치 등록 완료 n=6 · drain=7 · 명령가능 4개
```

## 🔴 기록해야 할 개입 — 도는 실행파일에 덮어썼다

```bash
PID=$(pgrep -f "parking-bin/srv_parking" | head -1)   # 🔴 **빈 문자열**이 나왔다
kill $PID                                              # → "not enough arguments" 로 실패
cp /tmp/srv_deploy2 /Users/idong-u/parking-bin/srv_parking   # 🔴 **그런데 이건 실행됐다**
```

**원인 둘이 겹쳤다:**
1. 프로세스의 실제 명령줄이 **`./srv_parking`(상대경로)** 라서 `pgrep -f "parking-bin/srv_parking"`
   가 안 맞는다. **cwd 는 `pgrep -f` 의 검색 대상이 아니다.**
2. `kill` 실패가 **뒤 명령을 안 막았다** — `;` 로 이어 썼다.

**결과**: 도는 프로세스(98103)의 실행파일이 덮어써졌다. 그 프로세스는 계속 돌았고
(로그가 이어졌다) 새 프로세스는 포트 충돌로 즉사했다. **06:19:42 에 정상 종료시켰다.**

## ✅ 무엇이 이것을 잡았나 — 조회다

*"배포 완료"* 를 시각까지 찍고도 `=== INSTANCE` 줄이 **옛 build(`499c2a3`)** 였다.
> **§"상태를 바꾸는 명령 뒤에는 상태를 조회하는 명령을 붙인다"** 가 그대로 잡았다.

⚠ 그리고 **`cmp` 가 "다르다"고 했는데 `strings` 는 새 BUILD_ID 를 찾았다** — 진술이 갈렸다.
**부분 기록을 의심하고, 죽인 뒤 다시 복사해 `cmp 0` 을 확인하고서야 띄웠다.**
*"아마 괜찮다"* 로 안 넘긴 것이 이 건에서 유일하게 잘한 부분이다.

## 다음 사람에게 — 배포 절차의 구멍

```
❌ pgrep -f "<절대경로>"        → 상대경로로 뜬 프로세스를 못 잡는다
✅ lsof -nP -iTCP:9991 -sTCP:LISTEN   → **포트를 쥔 놈**을 잡는다. cwd·경로 표기와 무관하다
✅ kill 뒤에 `ps -p <pid>` 로 **죽었는지 확인**하고 나서 cp 한다
✅ cp 뒤 `cmp` 로 **0 을 확인**하고 나서 띄운다
```
🔑 **포트로 찾는 것이 이름으로 찾는 것보다 견고하다** — 이름 표기는 띄운 방법에 따라 달라지고
포트는 안 달라진다.
