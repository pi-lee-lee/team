# 앱이 네이티브에 실제로 넘긴 그레이 바이트 (android-engineer 제공)

`DigitVision.nativeProcessGray` 에 넘어간 **바로 그 버퍼**를 재변환 없이 떠 놓은 것이다.
PGM(P5) 이라 헤더 세 줄(`P5` / `너비 높이` / `255`) 뒤부터 원본 바이트가 그대로 이어진다.
이미지 라이브러리로 다시 디코딩하지 말고 헤더만 건너뛰고 읽으면 값이 변형될 여지가 없다.

## 왜 만들었나

REQ-0012 에서 내가 "입력 문제가 아니라 분할 단계 문제다" 라고 단정했는데 **그건 과한 결론이었다.**
당시 근거는 그레이 버퍼의 평균·최소·최대가 그럴듯하다는 것뿐이었고, 그건 "내 입력이 하네스 입력과
같다" 는 증명이 못 된다. 실제로 루트가 확인한 대로 앱과 데스크톱 하네스의 BT.601 구현이 다르다.

| | 구현 | 반올림 |
|---|---|---|
| 데스크톱 하네스 | PIL `convert("L")` | 반올림 |
| 앱 (`SampleImages`) | `(r*299+g*587+b*114)/1000` | 절삭 |

## 여기 있는 파일

| 파일 | 앱에서의 결과 | 비고 |
|---|---|---|
| `scene-03-persp-60.pgm` | **FAIL** (`segment_fail`) | 640×480 |
| `scene-04-far-28.pgm` | **FAIL** (`segment_fail`) | 640×480 |
| `scene-01-front-45.pgm` | **PASS** (`123가4568`) | 640×480 · **대조군** |

대조군을 같이 넣은 이유는 아래 측정 때문이다.

## 내가 측정한 것

원본 PNG 를 두 방식으로 변환해 이 덤프와 화소 단위로 비교했다.

| 샘플 | 앱 vs PIL `convert("L")` | 앱 vs 절삭 공식 재현 | 앱 결과 |
|---|---|---|---|
| `scene-01-front-45` | 87.0% 가 다름 (최대차 1) | **0.0% (완전 일치)** | PASS |
| `scene-03-persp-60` | 80.3% 가 다름 (최대차 1) | **0.0% (완전 일치)** | FAIL |
| `scene-04-far-28` | 83.4% 가 다름 (최대차 1) | **0.0% (완전 일치)** | FAIL |

여기서 두 가지가 나온다.

1. **덤프는 신뢰할 수 있다.** 절삭 공식으로 재현한 값과 완전히 일치하므로, `Bitmap.getPixels` 나
   PNG 디코딩 단계에서 예상 밖의 변형이 끼어들지 않았다. 앱이 넘기는 바이트는 문서화된 그 공식의
   결과 그대로다.
2. **차이의 크기는 성패와 상관이 없다.** 통과하는 `scene-01` 이 87.0% 로 **실패하는 두 장보다 더 많이**
   다르다. 반올림 차이가 원인이라면 반대 방향이어야 자연스럽다.

그래서 나는 반올림 차이가 이번 실패의 원인일 가능성은 낮다고 본다. **다만 이것도 정황이지 증명이
아니다** — 임계값 경계에 걸친 화소 하나가 이진화 결과를 뒤집을 수는 있고, 그 한 장에서만 그런 일이
일어났을 수도 있다.

## 결론을 내는 방법 (이게 갈림길이다)

**이 PGM 을 하네스에 그대로 먹여 보면 된다.**

- 하네스가 이 바이트로도 **통과**한다 → 입력은 동치이고, 앱과 하네스를 가르는 것은 그레이 변환이
  아니라 다른 무엇이다(설정값·해상도 처리·호출 경로 등). 내 쪽부터 다시 판다.
- 하네스가 이 바이트로 **실패**한다 → 두 실패는 하네스 재현 가능한 인식기 문제다. 하네스가 통과했던
  이유는 하네스 입력이 실기 조건보다 유리했기 때문이고, 하네스 쪽 입력 생성을 앱과 맞춰야 한다.

어느 쪽이든 한 번에 갈린다.

## 다시 뜨는 방법

앱에서 샘플 모드로 해당 샘플을 한 번 띄우면 자동으로 다시 떨어진다.

```
adb shell ls /storage/emulated/0/Android/data/com.example.digitcam/files/sample-dumps/
adb pull /storage/emulated/0/Android/data/com.example.digitcam/files/sample-dumps/<파일> .
```

26장 전부 같은 방식으로 뜬다(하위 폴더는 `_` 로 평탄화된다 — 예: `scenes_scene-03-persp-60.pgm`).
