# 묶음 하행 (batch downlink) — 설계 요청

**사용자 지시 2026-08-19 (원문 인용)**

> *"우리 네트워크 환경 특성상 서버에서 노드(아두이노)로 송신하는 경우 **send함수 외에 묶음으로
> send하는 함수**가 필요하다. 동일시점에 3개의 명령이 들어가야한다면 최악의 ?? 거의 희박하지만
> **1개당 1.2초씩 밀린다.** 하나의 윈도우프래임에 3명령어를 담아서 보낼수 있어야한다.
> **딱 3개가 아니다 예를 든것이다. 최대 명령어 갯수가 필요하고** 해당 명령을 한윈도우에 묶어서
> 보낼수 있는 기능이 필요하다."*

## 🔴 이번 굽기에 넣지 않는다

```
지금 굽기의 목적 : **샘플이 성립하는가** — 항목 다섯을 값으로 확인한다
축을 하나 더 넣으면 : ⑤(왕복)가 실패했을 때 **원인 후보가 둘**이 된다
```
사용자가 *"**미리** 지정한다"* 고 했다 — **지금 만들라는 뜻이 아니라 설계에 넣으라는 뜻이다.**
**다음 굽기 경계로 묶는다.** 전선이 바뀌면 양쪽이 같이 움직여야 하므로 같은 경계다.

## 🔴 먼저 답할 것 — 이게 굽기 필요 여부를 가른다

### Q1. 지금 장치가 **한 번의 읽기에서 여러 줄**을 처리하는가 (arduino)

```
갈래 (B) 여러 줄을 한 번에 write     →  전선 형식 **무변화**
   `G,r1,3,1,ck\nG,r2,4,0,ck\nG,r3,5,7,ck` 를 한 AT+CIPSEND 로
   🔑 참이면 **장치 굽기가 필요 없다.** 서버만 고치면 된다 — 가장 싼 길

갈래 (A) 한 줄에 여러 명령           →  전선 형식 **변경** · 양쪽 굽기·배포
   `G*,<rid>,<idx>:<arg>,<idx>:<arg>,…,<ck>`
```
**(B)가 되면 (A)는 안 만든다.** 되는지부터 값으로 답해라 — 추정하지 마라.
확인할 것: `RxBuf` 가 한 읽기에서 여러 `\n` 을 끊어 내는가 · 버퍼 크기가 상한을 얼마로 만드는가.

### Q2. 🔴 **ACK 도 같이 밀리는가** (arduino)

사용자가 말한 것은 하행이다. 그런데 **ACK 가 슬롯마다 하나씩 올라가면 왕복은 그대로 밀린다.**
```
`AckQueue` 가 한 슬롯에 **여러 ACK** 를 싣는가?
🔑 이미 싣고 있으면 하행만 고치면 끝이다. 아니면 그쪽도 축이다
```
⚠ **묶음 하행을 만들고 ACK 가 직렬이면 사용자가 겪는 지연은 안 없어진다.**

### Q3. **최대 명령어 개수** — 사용자가 명시적으로 요구했다 (socket + arduino)

**추정하지 말고 계산해서 값으로 내라.** 상한을 만드는 것이 무엇인지 같이 적어라:
```
(B) 라면 : 장치 수신 버퍼 · 한 AT+CIPSEND 의 상한
(A) 라면 : MAX_LINE 64 — 머리 `G*,999,` + 체크섬을 빼고 항목당 최악 `255:4294967295`
```
🔴 **최악값과 실제값을 갈라 적어라.** `3:1` 같은 실제 명령은 훨씬 짧다.
**API 에 박는 상한은 최악 기준이어야 한다** — 안 그러면 긴 인자에서 조용히 잘린다.

### Q4. **부분 실패를 어떻게 답하는가** (socket)

```
3개 중 2번이 `result=3` 이면? 나머지 둘은 수행됐나 안 됐나
```
- **원자적이어야 하나, 각각 독립인가.** 정하고 **명세에 적어라.**
- 🔑 **`send()` 하나의 반환값으로는 못 나른다.** 묶음의 반환 모양을 따로 정해라.

## API 모양 — 사용자 요구를 지켜라

> *"복잡한 구조는 **은닉화** 하여 개발자에게는 **간단한 구조로**"* ·
> *"코드 작성 시점에 해당 코드의 **흐름이 보인다**"*

```
🔒 감춘다  : 포장·분할·재시도·슬롯 배치 — **호출자가 바꿀 수 없는 순서**
🔓 보인다  : **무엇을 묶는가** — 그건 호출자의 선택이다
```
- 🔴 **상한을 넘기면 조용히 자르지 마라.** 거절하거나 나눠 보내되 **어느 쪽인지 명세에 적어라.**
- ⚠ **`send()` 를 없애지 마라.** 하나 보낼 때 묶음 문법을 쓰게 하면 샘플이 어려워진다.

## 계산 주체

**최대 개수를 누가 계산하나** — 서버 상수인가, 장치가 등록 때 선언하나.
🔑 **장치 버퍼가 상한을 만든다면 장치가 선언하는 것이 맞다.** 정하고 적어라.

# 서버 쪽 콜백 — 설계 요청 (같은 경계)

**사용자 지시 2026-08-19 (원문 인용)**

> *"콜백함수는 아두이노쪽에서도 필요한진 모르겟는데 **우선적으로 필요한쪽은 서버**이다.
> 서버는 아두이노에 명령을 보내면 **리턴을 바로 받는게 아니라** 아두이노 사이클에 일괄로
> 들어오는 정보를 보고 확인해야한다. 그 콜백을 말한것이다. 예를 들어 주차센서 on/off 상태를
> 체크하기 위해 아두이노에 확인을 보냈는데 즉시 리턴되지 않는다. 그리고 리턴이 다음 아두이노
> 서버 정기 송신 사이클에 포함되어 나간다. 그래서 콜백이 필요하다고 판단한다."*

## ✅ 검토 결과 — **판단이 맞다. 다만 갈래가 둘이고 이유가 다르다**

### ① 명령 결과 — **사용자가 말한 그대로다**
```
srv.send(...) 의 반환은 **"전선 큐에 넣었다"** 이지 "수행됐다"가 아니다 (샘플에 이미 그렇게 적혀 있다)
ACK 은 **장치의 다음 슬롯**에 실려 온다 — ACK_TIMEOUT_MS = 2 × DOWN_SLOT_MS = **2,400ms**
🔴 그러므로 **호출부에서는 결과를 알 방법이 원리적으로 없다.** 콜백이 유일한 길이다
```

### ② 센서 상태 — **필요하지만 이유가 다르다. 여기를 정확히 해야 API 가 안 틀어진다**
```
🔴 센서는 **폴링이 아니다.** 장치가 매 슬롯 `S` 프레임으로 **밀어 올린다**
   → 서버는 값을 **이미 갖고 있다.** "확인을 보내고 기다리는" 왕복이 없다
✅ 그래도 콜백이 필요하다 — 이유는 지연이 아니라 **"바뀐 순간에 무엇을 하고 싶다"** 이다
```
🔑 **이 구분을 안 하면 "센서 읽기 요청" API 를 만들게 되고, 그건 있지도 않은 왕복을 만든다.**
**있는 것은 값이 아니라 *변화* 다.**

## 🔴 반드시 정할 것

### Q5. **불리는 시점** — `serveOneTick()` 안이어야 한다
```
✅ 그래야 호출자가 루프 본문에 아무것도 안 써도 콜백이 돈다
   while (srv.serveOneTick()) { }        ← 이 모양이 유지된다
🔴 호출자가 직접 펌프를 돌리게 하면 **한 박자의 고정 순서를 호출부에 넘기는 것**이다
   (§"바꿀 수 없는 순서를 드러내는 것은 짐을 넘기는 것이다")
```

### Q6. 🔴🔴 **ACK 이 영영 안 오면 콜백이 불리는가**
```
🔴 이게 이 설계에서 가장 중요한 칸이다
안 부르면 : 기여자는 **"안 불린다"만 안다** — 실패인지 지연인지 못 가른다
           그리고 그 상태를 **감시할 방법이 없다** (§"감시할 수 없는 것은 조건으로 적지 마라")
```
✅ **타임아웃 갈래를 반드시 두고, 콜백 인자로 결과를 갈라 줘라.**
`ACK_TIMEOUT_MS × ACK_MAX_TRIES` 를 다 쓰고 나서 **한 번은 불려야 한다.**
⚠ **`result` 값 하나로 나르지 마라** — `0`/`3` 은 장치가 답한 것이고 **타임아웃은 장치가 답을 안 한 것**이다.
**"거절"과 "무응답"은 다른 사건이고, 섞으면 기여자가 장치 고장을 콜백 로직으로 쫓는다.**

### Q7. **모양** — 장치 쪽과 **대칭**이면 기여자가 한 번만 배운다
```
장치 :  router.on("DR", cmdDoor);            bool cmdDoor(uint32_t arg)
서버 :  ????
```
🔑 **`router.on` 과 같은 모양으로 가는 것이 가장 싸다.** 이름·인자·반환의 뜻이 이미 학습돼 있다.
- 명령 결과는 **보낼 때 다는 것**과 **모듈에 상시로 다는 것** 중 무엇인가. 정하고 적어라.
- ⚠ **둘 다 만들지 마라** — 같은 개념에 두 입구가 생기고, 그건 오늘 `LED1`/`LD` 와 같은 부류다.

### Q8. **묶음 하행과 어떻게 맞물리나**
```
묶음 3건 중 2번만 실패하면 콜백이 **몇 번** 불리나 — 3번인가 1번인가
```
🔑 **Q4(부분 실패)와 같은 물음이다. 답을 하나로 맞춰라.**

## 샘플에 반드시 나타나야 한다

사용자가 **`"콜백도 !!!!"`** 라고 명시했다. 지금 샘플에는 **장치 쪽만** 있다.
- 서버 샘플(`main.cpp`)에 **콜백 등록 한 줄과 그 핸들러**가 보여야 한다.
- ⚠ **주석으로만 두지 마라** — 컴파일러가 안 본다. **켜서 빌드해 본 뒤** 주석 처리해라.

## 🔴 이번 굽기·배포에는 안 들어간다

**서버 쪽 변경이라 굽기는 필요 없다.** 다만 지금은 **⑤(왕복) 측정이 먼저**다 —
축을 더 넣으면 ⑤ 실패 시 원인이 갈라지지 않는다. **⑤ 가 끝나고 착수한다.**
