# 사용자 확인이 필요한 것 — 모아 둔다 (2026-08-18)

**사용자 지시**: *"작업간 나의 확인이 필요한 사항들은 정리만 해두고 확인없이 진행할수 있는
일들을 처리한다."* → **이 문서가 그 "정리만 해 둔 것"이다.**

각 항목은 **왜 물어야 하는지**(내가 정할 수 없는 이유)와 **답에 따라 무엇이 달라지는지**를 적는다.
답이 없어도 진행 가능한 것은 여기 두지 않는다 — **여기 있는 것은 답이 결정을 바꾸는 것들뿐이다.**

---

## ✅ ① 모듈 표시량 — **A(칸 안에 다 보이기) 확정** (사용자 결정 2026-08-18)

```
┌─ 격자 ──────────────────────────┐
│ [입구]      [A1]       [A2]     │
│  차단봉 ○    센서 ●     센서 ○   │
│  입차센서 ●  안내등 ○   안내등 ● │
│             유도등 ⏱   유도등 ○ │
└──────────────────────────────────┘
```

**자리마다 모듈 상태를 전부 칸 안에 표시한다.** 클릭·펼치기 없이 한눈에 본다.

### ⚠ 대가는 알고 고른 것이다 — 그 대가를 설계로 다뤄라

**자리 5개 × 모듈 3~4개 + 입출구 → 한 화면에 20~30개 상태.**
**요소 수가 많다는 것은 바뀌지 않는다.** 다만 그것이 **읽을 수 없는 화면**이 되지 않게 하는 것이
web 의 설계 몫이다. 이미 있는 규칙 둘이 그 일을 한다:

1. **기호축 × 강조축**(원장 §5.33) — `⏱`(모른다)/`⚠`(고장)은 **원인**, 강조는 **영향**(조작을 막는가).
   🔑 **강조축을 화면이 계산하지 않고 `actionable`/`blocked_reason` 에서 파생으로 얻으므로
   정상에서는 저절로 조용해진다.** 20~30개가 다 떠 있어도 **눈에 걸리는 것은 막힌 것뿐**이다.
2. **미상 집계 한 줄**(§2.3) — 칸 안에 다 보여도 **집계는 남긴다.**
   🔴 **"다 보이니 집계는 필요 없다"로 읽지 마라** — 20~30개 중 2개가 미상인 것을
   **눈으로 세는 것과 수로 읽는 것은 다르다.**

⚠ **그리고 §5.34.2 의 층 규칙이 여기서 문구를 정한다**: 액추에이터는 에코가 있어도
**"켜졌습니다"가 아니라 "장치가 켰다고 보고합니다"** 다. **칸이 좁을수록 그 구분이 뭉개지기 쉽다** —
기호로 어떻게 가를지 web 이 정한다.

### 남은 것 — 형태는 web 이 정한다

**규칙은 정해졌고 시각 형태(점선·흐림·칩·배치)는 아직이다.** web 이 §5 에 명시적 빈칸으로
격리해 뒀으므로 **그 위에 얹으면 된다.** ⚠ **그리고 그때 브라우저로 봐야 한다** —
web 이 자기 한계로 적어 둔 것: **"원칙이 옳아도 형태가 그것을 전달하지 못할 수 있다."**

## (원문 · 결정 전 정리) 모듈을 화면에 얼마나 보여 주나 (web 발의)

**왜 내가 못 정하나**: 기술 문제가 아니라 **표시 문제**다. 셋 다 구현 가능하고 대가가 다르다.

| 안 | 보이는 것 | 대가 |
|---|---|---|
| **A. 칸 안에 다** | 자리마다 모듈 전부(주차센서·안내등·유도등…) | 🔴 **요소 수 폭발.** 자리 5개 × 모듈 3~4개 + 입출구 → 한 화면에 20~30개 상태 |
| **B. 눌러서 펼친다** | 기본은 자리 요약, 클릭하면 그 자리의 모듈 | 한 번에 하나만 보인다 — **여러 자리를 동시에 비교 못 한다** |
| **C. 집계만** | "미상 2 · 이상 1" 같은 수만 | **어느 모듈인지 안 보인다** — 고치러 갈 때 다시 찾아야 한다 |

⚠ **B·C 는 조합 가능하다**(집계 배너 + 클릭 상세). web 이 §3.1 에서
*"칸 문구만으로 부족해 집계 배너를 넣었다"* 는 교훈을 이미 갖고 있다.

**답이 없으면**: web 이 개정 착수를 못 한다(화면 구조가 이 답에 달렸다).
**우회 가능성**: 데이터 계약(`kind`·모듈 목록·`known` 모듈 단위)은 이 답과 무관하므로 **먼저 만들 수 있다.**
→ **그래서 이 항목은 web 의 진행을 완전히 막지는 않는다.**

## ② 하행 동시 동작의 편차 허용치 — **거의 닫혔다. 확인만**

사용자가 이미 정정해 줬다: *"1.2초는 esp01 단위다. 10개의 esp01에게는 동시에 보내도 된다."*
→ **같은 아두이노의 모듈은 한 프레임에 실려 편차 0** · **다른 아두이노는 각 소켓에 동시 전송.**

**남은 확인 하나**: 다른 아두이노에 흩어진 모듈이 **동시에 움직여야 하는 조합인지.**

- 사용자 말: *"다른 아두이노에 실장되어 있으면 더 문제되지 않는다."*
- 두 가지로 읽힌다:
  **(가)** 그런 조합은 자연히 같은 아두이노에 배선한다(차단봉과 그 입차 센서처럼)
  **(다)** 조합은 있을 수 있지만 편차가 실사용에 문제가 아니다

**어느 쪽이든 추가 작업은 없다** → **진행에 지장 없음.**
다만 **(가)면 배선 지침으로 적을 값이 있다**:
> **동시에 움직여야 하는 모듈은 같은 아두이노에 붙여라. 그러면 한 프레임에 실려 편차가 0 이다.**

**성능을 배선으로 보장하는 규칙**이 되므로 설계서에 넣을 값이 있다.

## ✅ ③ 격자 — **자리 하나 = 격자 한 칸 확정** (사용자 2026-08-18)

> 사용자 원문: *"현재는 격자하나가 1칸이다. 이후에 확장될수는 있다 하지만 현 시점에서는
> 자리하나가 격자한칸으로 한다."*

```
✅ 확정 : 자리 : 격자칸 = **1 : 1**
🔮 여지 : 나중에 큰 자리가 여러 칸을 차지할 수 있다 — **구조가 그것을 막지는 말 것**
❌ 하지 마라 : 지금 N:1 을 구현하지 마라. 쓰이지 않는 일반화는 검증되지 않은 코드다
```

🔑 **"막지 마라"와 "미리 만들어라"는 다르다.** 좌표를 `(row, col)` 한 쌍으로 두고
**자리 식별자와 칸 좌표를 분리해 두면** 나중에 `자리 → 칸 목록`으로 넓힐 때 형이 안 깨진다.
**지금은 그 목록의 길이가 1일 뿐이다.** 그 이상은 하지 않는다.

**나머지(격자 크기·초기 배치)는 기본값으로 진행한다** — `5x5`, 입구·출구는 가장자리,
**전부 설정 파일로 변경 가능**하게. 사용자가 *"유동적"* 을 요구했으므로 **초기 배치는 예시**이고
구조가 거기 묶이지 않는다.

---

## (원문 · 결정 전) 격자 크기·초기 배치 — 값이 필요하다

**"주차구역 5개 + 입구 + 출구"** 는 받았다. 격자에 대해 아직 없는 것:

| 미상 | 예 | 왜 필요한가 |
|---|---|---|
| 격자 크기 | `5×5`? `4×3`? | 화면 레이아웃과 좌표 범위 |
| 초기 배치 | 어느 칸에 무엇이 | 첫 설정 파일에 들어간다 |
| 자리 한 칸이 격자 한 칸인가 | 큰 자리가 2칸을 차지할 수 있나 | 사용자가 *"크기"* 도 유동적이라고 했다 → **차지 칸 수가 가변일 수 있다** |

**답이 없으면**: **기본값으로 진행한다.** 격자를 `5×5`, 자리 하나가 한 칸, 입구·출구를 가장자리에 두고
**설정 파일로 바꿀 수 있게** 만든다. 사용자가 *"유동적으로 변경 가능"* 을 요구했으므로
**초기 배치는 예시일 뿐이고 구조가 그것에 묶이지 않는다.** → **이 항목은 진행을 막지 않는다.**

⚠ 다만 **"자리 크기 가변"이 참이면 구조가 달라진다**(칸→자리가 N:1). **그것만 확인이 값을 한다.**

## ④ 이름 갈래 — 내가 정하고 진행한다 (확인 아님 · 통보)

`슬롯` 이 두 가지를 뜻하고 있어 갈라야 한다(CLAUDE.md §정의를 맞춰라).

```
노드(node)      자기 1.2초 주기를 갖는 통신 단위 = ESP 하나 · 소켓 하나
자리(space)     격자 위의 주차 자리
주기(cycle)     1.2초 그 자체
```

**이건 내부 용어라 내가 정하고 진행한다.** 사용자가 다른 이름을 원하면 바꾼다 —
**바꾸는 비용이 작은 시점에 정해 두는 것**이 목적이다.

## ⑤ 전류 감지를 넣을 것인가 — **하드웨어 결정이라 우리가 못 정한다** (2026-08-18 추가)

**액추에이터 확인 문제는 설계로 한 칸 좁혀졌다.** 출력 모듈(차단봉·안내등·유도등)도
상태 비트열에 실려 **에코가 생긴다** — 그러면 이 셋이 갈린다:

```
ack + 다음 S 비트 변화   → 동작이 났다
ack + 비트 변화 없음     → 🔴 받았지만 못 했다 (핀 조작 실패)
ack 없음 + 비트 변화     → ACK 만 유실됐다 (동작은 났다)
```

🔴 **그런데 에코로도 안 되는 것이 남는다:**

| 층 | 말할 수 있는 것 |
|---|---|
| `ack` | 프레임을 받았다 |
| **에코(상태 비트)** | **장치가 그 핀을 그렇게 설정했다** |
| **전류 감지(없음)** | 전구가 실제로 켜졌다 · 차단봉이 물리적으로 올라갔다 |

**전류 감지가 없으면 끊긴 배선·나간 전구는 어디에도 안 나타난다.**
→ 화면은 **`"켜졌습니다"` 가 아니라 `"장치가 켰다고 보고합니다"`** 여야 한다.

**시연에서 이 한 칸이 실제로 갈린다**(web 지적): 전구가 안 켜졌는데 화면이 *"켜졌습니다"* 면
보는 사람은 **화면을 의심하지 않고 자기 눈을 의심하거나 엉뚱한 곳을 본다.**
*"장치가 켰다고 보고합니다"* 는 **다음에 볼 곳을 가리킨다.**

**답이 없으면**: **전류 감지 없이 진행한다.** 그 한계가 계약에 남고 화면 문구가 정직하게 말한다.
→ **진행을 막지 않는다.** 다만 시연에서 액추에이터가 눈에 보이는 것이면 **넣는 값이 있다.**

## ✅ ⑥ ESP 하드리셋선 — **배제 확정. 사람이 직접 리셋한다** (사용자 결정 2026-08-18)

> *"리셋선은 일단 배재한다. 사람이 직접 리셋하는걸로 확정"*

**`ESP_RST_WIRED 0` 을 유지한다.** `client.ino:781` 그대로이고 **코드 변경 없음.**
2026-08-15 에 의도적으로 분리한 상태가 그대로 확정됐다.

### 🔴 그러므로 이것이 시스템의 확정된 한계다 — 판정문·설계서가 전제로 삼는다

```
링크가 죽으면 장치는 스스로 못 살아난다.
사다리가 4단(하드 리셋)까지 올라가도 실행할 수단이 없고, 30초마다 AT+RST 만 되풀이한다.
→ 복구는 사람이 전원을 껐다 켜는 것뿐이다.
```

**실측 사례**(2026-08-18): ESP 무응답 `rx=0` 이 약 9분 지속 → 사용자가 전원 리셋 →
`09:16:08` 부팅 → `09:16:27` 서버 등록. **19초 만에 복구됐지만 그 앞의 9분은 사람을 기다린 시간이다.**

⚠ **관측·판정에 미치는 영향:**
- **긴 소크에서 링크 사망은 곧 관측 종료다.** 사람이 없으면 그 뒤 구간은 전부 `rx=0` 이고
  **"유휴"가 아니라 "죽어 있음"이다.** 두 가지를 같은 기준선으로 쓰면 안 된다.
- **자가 치유 논의는 링크가 살아 있을 때만 유효하다** — 모듈이 죽은 경우는 그 바깥이다.
- **시연 중 링크가 죽으면 사람이 손을 대야 한다.** 그 사실을 시연 계획에 넣어야 한다.

⚠ **뒤집을 조건**: 장치를 여러 대로 늘리면(설계 개정 7번) **사람이 N 대를 돌아다녀야 한다.**
그때 비용이 배선 한 줄보다 커지면 다시 본다. **지금은 1대라 배제가 합리적이다.**

## 요약 — 진행을 실제로 막는 것은 **없다**

| # | 항목 | 진행 막나 |
|---|---|---|
| ① | **모듈 표시량** | ✅ **결정됨 — A(칸 안에 다).** 형태는 web 이 정한다 |
| ② | 편차 허용 | ❌ 안 막는다(어느 쪽이든 작업 없음) |
| ③ | 격자 크기·배치 | ❌ 안 막는다(기본값 + 설정 파일). **단 "자리 크기 가변"만 확인 값 있음** |
| ④ | 이름 | ❌ 내가 정한다 |
| ⑤ | **전류 감지** | ❌ 안 막는다(없이 진행 · 한계를 계약에 남긴다). **시연 가치는 있다** |
| ⑥ | **하드리셋선** | ✅ **결정됨 — 배제.** 사람이 리셋한다. 코드 변경 없음 |

**→ 설계 계획을 지금 발행한다.** 위 넷은 답이 오면 반영한다.
