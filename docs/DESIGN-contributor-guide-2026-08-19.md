# 다인원 기여를 **코드로** 가이드한다 — 관리자 화면 없이 (2026-08-19)

> 사용자: *"이 프로젝트가 나 혼자 진행하는 것이 아니다. **다른 인원의 작업을 반영**하고 싶다.
> 그러면 **작업 방식을 가이드해야 한다.** 아두이노를 만들어서 서버에 접속하면 주차장 맵과 모듈을
> 매핑하여 동작하게 만든다. … 하지만 [화면 매칭은] **부수적인 작업이 너무 많다.** 웹 화면과 관리자 페이지 등.
> 그러면 **코딩으로 가이드할 수 있는 방법은 없는가?**"*

## 답: **있다. 그리고 절반은 이미 있다.** 관리자 화면은 필요 없다.

---

## 1. 🔴 지금 기여자가 부딪히는 진짜 벽 — 화면이 아니다

**기여자가 고쳐야 하는 것(실측):**
```cpp
// 조별과제샘플/ardu/Modules.h — PROGMEM 배열
static const ModuleDef MODULE_TABLE[] PROGMEM = {
  {"A1", KIND_PARK_SENSOR,  2}, {"A2", KIND_PARK_SENSOR,  3}, …
};
// ⚠ 주석에만 있는 규칙 셋:
//   · **끝에만 붙인다. 중간 삽입 금지** (idx 가 밀려 결속이 조용히 깨진다)
//   · **이름은 자리 id 와 같아야 한다**
//   🔴 · "다른 이름을 쓰면 **등록은 성공하고 자리에는 아무것도 안 붙는다. 오류가 안 뜬다**"
```

> ### **기여자가 겪을 일: 코드는 컴파일되고, 장치는 붙고, 등록도 성공하고 — 화면에 아무것도 안 나온다.**
> ### **그리고 왜인지 *아무도 안 알려 준다.***

**이것이 다인원 협업의 벽이다. 관리자 화면이 없어서가 아니다.**

---

## 2. 경계 — 누가 무엇을 선언하나

```
🏢 프로젝트 오너 → **주차장 지형**   자리가 몇 개고 무엇이 있나
                    (이미 있다: server/main.cpp 의 `lot.spot("A1").sensor("A1").sensor("B1")`)
🔧 기여자        → **내 장치의 배치**  내 모듈이 **어느 자리의 무엇**인지
                    (지금은 `MODULE_TABLE` 배열 · 암묵 규칙)
```
🔑 **매칭은 이름으로 자동이다 — 그게 지금 이미 하는 일이다.** 새 구조가 필요 없다.

---

## 3. 기여자가 쓰는 코드 — 목표 모양

```cpp
// 기여자는 **이 파일 하나만** 만진다
#include "ParkingKit.h"

ParkingNode node;

void setup() {
    node.sensor("A1", 2);      // 자리 A1 의 점유센서 = 디지털 2번
    node.sensor("B1", 9);      // 자리 A1 의 둘째 센서 (지형이 A1↔B1 을 안다)
    node.gate("E1", 7);        // 입구 차단봉
    node.begin();              // 여기서 등록·접속이 시작된다
}
void loop() { node.tick(); }
```
**지금과의 차이는 문법이 아니라 *실수가 어디서 잡히는가* 다:**
```
지금 : 배열 · 규칙은 주석 · 어기면 **조용히 안 붙는다**
목표 : 함수 · 규칙이 **인자에 있다** · 어기면 **서버가 이유를 말한다**
```

---

## 4. 그래서 관리자 화면이 왜 필요 없나 — 사용자 판단이 맞다

```
기여자는 **어차피 자기 장치를 굽는다** → 배치를 코드에 두는 추가 비용 **0**
화면 매칭은 : UI + 인증 + 동시 편집 충돌 + 영속 + 그 화면의 시험 = **전부 새 작업**
🔑 그리고 배치가 코드에 있으면 **git 이 이력과 충돌을 관리한다.**
   화면으로 하면 그 둘을 **처음부터 다시 만들어야 한다**
```
> ### **"누가 언제 이 자리를 이 장치에 줬나"는 git 이 이미 답한다. 화면은 그것을 다시 발명하는 것이다.**

⚠ **대가**: 배치를 바꾸려면 다시 굽는다. **그런데 기여자가 자기 장치를 바꾸는 일이니 어차피 굽는다.**

---

## 5. 그러면 무엇이 필요한가 — 셋뿐이다

### ① 선언 API (arduino) — 배열을 함수로
```
node.sensor(자리id, 핀) · node.gate(자리id, 핀)
🔑 `idx` 는 **호출 순서**로 내부에서 정해진다 — 기여자가 idx 를 몰라도 된다
⚠ "중간 삽입 금지"가 **호출 순서**로 자연히 지켜진다. 주석으로 지키던 것을 구조가 지킨다
```

### ② 🔴 서버가 **거절하고 이유를 말한다** — 이게 제일 중요하다
```
· 자리에 없는 이름     → "모듈 `B7` 은 어떤 자리에도 안 붙는다 (지형에 그 이름 없음)"
· 같은 자리를 둘이 주장 → 지금 `mod_name_conflict` 가 **세기만 하고 말은 안 한다**
· 한 노드 안 이름 중복  → 지금 **아무도 안 본다**
```
> ### **지금은 전부 조용하다. 조용한 실패가 기여자를 막는 유일한 것이다.**

### ③ 기여 가이드 문서 한 장
```
· 지형에 어떤 자리가 있나 (오너가 갱신)
· 스케치 템플릿 + 예시
· 🔴 **"안 되면 서버 로그의 이 줄을 봐라"** — ②가 만드는 그 줄
```

---

## 6. ⚠ 지금 샘플 모듈은 지운다 (사용자 지시)

> *"차단봉 이런 모듈들은 **테스트 출력을 위해서 설정해 둔 것**이다. 실제 이용할 방식이 아니다. **삭제해야 된다.**"*

```
Modules.h : `VIRTUAL_MODULES 1` 아래의 가상 모듈(E1·X1 등)
⚠ 지우면 등록 모듈 수가 12 → 10 이 되고 **지문이 바뀐다** → 대장이 한 번 `needs_review` 로 간다
   → 정상이다. **미리 알고 있으면 한 줄로 끝난다**(socket 이 `OBV→OB` 에서 같은 것을 미리 적어 뒀다)
⚠ 그리고 서버 지형의 `lot.gate("E1"…)` 도 같이 볼 것 — **한쪽만 지우면 "붙을 자리는 있는데 모듈이 없다"** 가 된다
```

## 7. 순서 — 이 안에서 다시 짠다

```
1. 🔴 **서버가 거절하고 말한다**       굽기 불필요 · 창 Z 무관 · **혼자서 값이 있다**
                                      (지금도 기여자가 있으면 바로 도움이 된다)
2. 샘플 모듈 정리                      굽기 필요 · 지문 변경 1회
3. 선언 API (`ParkingKit.h`)          굽기 필요 · 기존 배열과 **같은 결과를 내는지 hex 로 확인 가능**
4. 기여 가이드 문서                    코드 무관
❌ 관리자 화면                         **안 만든다**
⏸ devid 고유화 · 대장 · 카탈로그       **살아 있다** — 여러 장치가 붙는 순간 필요해진다
                                      다만 **1~4 가 먼저다**
```
🔑 **1 번이 가장 싸고 가장 크다** — 코드 한 줄도 안 굽고, 기여자가 벽에 부딪히는 그 지점을 없앤다.

# 🔴 개정 1 — **자리 클래스의 함수를 기여자가 구현한다** (사용자 안, 2026-08-19)

> *"현재 주차장 자리 클래스는 분리되어 있다. **기여자들이 주차장 자리 클래스만 편집**하여
> 해당 자리에 대한 기능을 편집·생성하는 방식은 가능한가? **클래스의 함수로 동작 방식은 미리 정해 두고
> 해당 함수를 구현**하여 자신이 구현한 모듈과 매칭하는 방식이다."*

## 답: **가능하다. 그리고 앞서 내가 제안한 "유한한 정책 목록"보다 낫다 — 내 전제가 틀렸다**

```
🔴 내가 깔았던 전제 : "관리자는 코딩을 못 한다" → 그래서 **고르게** 하자고 했다
✅ 사실            : 여기 기여자는 **아두이노를 만드는 사람이다. C++ 를 쓴다**
→ **고르게 할 이유가 없다. 쓰게 하면 된다.**
```
🔑 **유한 목록은 표현력의 상한이 있다.** 새 판정이 필요하면 오너가 정책을 추가해야 했다.
**함수를 구현하게 하면 그 상한이 사라진다.**

## 지금 구조가 그 직전이다 — 값으로

```cpp
zone.h    struct Zone { id · kind · cells · modules }   ← **자료만. 행위가 없다**
wsjson.h:145~155  점유 유도가 **여기 하드코딩**돼 있다 (모듈을 훑어 OR)
```
> ### **판정 로직 한 덩어리를 `Zone` 의 가상 함수로 옮기면 그대로 된다. 새 구조가 아니라 이동이다.**

---

## 인터페이스 — 🔒 오너가 정하고 🔓 기여자가 채운다

```cpp
// 🔒 오너 — 뼈대. 기여자가 못 바꾼다
class Spot {
public:
    virtual ~Spot() {}
    const std::string& id() const;

    // 🔒 읽기 도구
    Tri  sensor(const char* name) const;   // YES / NO / **UNKNOWN**
    int  sensorCount() const;

    // 🔓 기여자가 구현
    virtual Tri  occupied() const = 0;                 // **필수**
    virtual bool reservable() const { return occupied() == Tri::NO; }
    virtual void onOccupiedChanged(Tri now) {}
};
```
```cpp
// 🔓 기여자가 만드는 파일 — contrib/SpotA1.h
class SpotA1 : public Spot {
public:
    Tri occupied() const override {
        return sensor("A1") && sensor("B1");   // 둘 다일 때만 (AND)
    }
};
```
```cpp
// 🔒 오너가 한 줄 — main.cpp
lot.spot<SpotA1>("A1").sensor("A1").sensor("B1");
```

### 🔴 반환형을 `bool` 이 아니라 `Tri`(YES/NO/UNKNOWN)로 하는 이유
```
`bool` 이면 기여자가 **`unknown` 을 `false` 로 읽는다** → **"모른다"가 "비었다"가 된다**
🔑 오늘 우리가 배운 그것 — **정직한 무지를 없애는 수정은 신호 없이 거짓이 된다**
→ `Tri` 로 두면 기여자가 **unknown 을 명시적으로 다루도록 강제**된다
```

---

## 🔴 위험 셋 — 미리 못 박는다

```
① 기여자 코드가 **서버 프로세스 안에서 돈다**
   예외    → try/catch 로 감싸고 그 자리를 `UNKNOWN` 으로. **대책 있다**
   🔴 무한루프 → **못 막는다.** PR 리뷰가 유일한 방어. **문서에 크게 적어라**
② 서버를 **다시 빌드·배포**해야 한다 (기여자가 자기 장치만 굽는 게 아니다)
   🔑 그런데 조립 표(`lot.spot(...)`)도 이미 서버 코드다. **새로 생기는 부담이 아니다**
③ 인터페이스를 잘못 정하면 **모든 구현이 깨진다**
   ✅ 대책: **작게 시작한다.** `occupied()` **하나만** 필수. 나머지는 기본 구현
```

---

## 순서

```
1. `wsjson.h` 의 점유 유도를 `Spot::occupied()` 로 **옮긴다**  ← 이동. 기본 구현 = 지금과 같은 OR
   판별자: **화면 봉투가 한 바이트도 안 바뀐다**(골든 대조)
2. `Tri` 도입 + `sensor()` 읽기 도구
3. 예외 격리(try/catch → UNKNOWN)
4. 기여자 파일 자리(`contrib/`) + 예시 하나
5. 문서 — **"무한루프는 서버를 죽인다"를 맨 앞에**
```
🔑 **1 이 가장 크고 가장 안전하다** — 지금 동작을 그대로 옮기고, 봉투가 안 바뀌는 것으로 증명한다.
**그 뒤에야 기여자가 갈아끼울 자리가 생긴다.**

⚠ **그리고 이 안은 앞서 쓴 "① 서버가 거절하고 말한다"와 충돌하지 않는다** — 그건 *배치* 검사이고
이건 *판정* 구현이다. **둘 다 필요하고 순서는 거절이 먼저다**(지금 기여자가 벽에 부딪히는 것은 배치다).

# ✅ 개정 2 — **안드로이드 액티비티 비유** (사용자, 2026-08-19)

> *"약간 **안드로이드 액티비티 같은 개념**으로 주차 자리를 보는 것이다."*

## 사상이 정확히 맞는다

```
Activity                   ↔  Spot (주차 자리)
생명주기 콜백               ↔  occupied() · onOccupiedChanged() · onReserved()
🔑 **프레임워크가 언제 부를지 정한다** ↔  **서버가 박자를 정한다.** 기여자는 안 정한다
Manifest 등록              ↔  lot.spot<SpotA1>("A1")
findViewById(R.id.x)       ↔  sensor("A1")
Context                    ↔  Spot 의 🔒 읽기 도구 — **시스템 접근은 이것으로만**
```

## 🔑 이 비유가 주는 것 — 셋

### ① **"언제 불리는가"를 기여자가 몰라도 된다**
Activity 가 자기 `onResume` 이 언제 불리는지 모르듯, `occupied()` 도 그렇다.
> ### **서버가 정한다 — 매 박자인지, 상태 변화 시인지, 방송 직전인지.**
🔑 **오늘 세운 판별자 그대로다**: *"호출자가 순서를 바꿀 수 있으면 밖, 없으면 안."*
**기여자는 그 순서를 바꿀 수 없다 → 안에 감춘다. 비유가 그 결정을 확인해 준다.**

### ② 🔴 **ANR — "무한루프는 못 막는다"에 대한 답이 여기 있다**

앞서 나는 *"무한루프는 못 막는다. PR 리뷰가 유일한 방어"* 라고 적었다. **안드로이드는 다르게 푼다:**
```
안드로이드 : 콜백이 5초를 넘으면 **ANR** — 앱을 죽이고 **무엇이 느렸는지 말한다**
             🔑 루프를 *막는* 것이 아니라 **재서 드러내고 격리**한다
```
**우리도 같은 것을 할 수 있다:**
```
· `occupied()` 호출 **시간을 잰다**
· 문턱을 넘으면 → 그 자리를 **`UNKNOWN` 으로 두고 로그에 이름과 시간을 찍는다**
· 반복되면 → **그 자리만 호출에서 뺀다.** 나머지 자리는 계속 돈다
⚠ 진짜 무한루프(반환 자체를 안 함)는 **여전히 못 막는다** — 단일 스레드라 선점이 없다
   🔑 그런데 **대부분은 무한이 아니라 느린 것**이고, 그건 전부 잡힌다
```
> ### **"못 막는다"에서 **"재서 드러내고 그 자리만 격리한다"** 로 내려왔다. 비유가 한 칸을 벌어 줬다.**

### ③ **격리 단위가 자리다**
Activity 하나가 죽어도 다른 Activity 는 산다. **자리 하나의 판정이 실패해도 다른 자리는 돈다.**
```
try/catch → 그 자리만 UNKNOWN · 시간 초과 → 그 자리만 제외
🔑 **자리를 격리 단위로 잡은 것이 이 설계의 핵심 이득이다**
```

## ⚠ 비유가 **안 맞는 곳** — 미리 적는다

```
❌ 안드로이드는 **프로세스 격리**가 있다. 우리는 **같은 프로세스**다
   → 진짜 무한루프·세그폴트는 **서버 전체를 죽인다.** 그건 안 바뀐다
❌ Activity 는 **자기 UI 를 그린다.** Spot 은 **값만 낸다** — 그리는 것은 화면이다
   🔑 기여자가 "여기서 화면을 바꾼다"로 오해하지 않게 문서에 적어라
❌ 안드로이드는 **재시작**으로 복구한다. 우리는 자리를 **뺀 채로 계속 돈다**
```

## 그래서 인터페이스에 붙는 것

```cpp
class Spot {
public:
    // 🔒 오너 — 프레임워크
    Tri  sensor(const char* name) const;
    int  sensorCount() const;

    // 🔓 기여자 — 콜백
    virtual Tri  occupied() const = 0;                  // **필수** · 🔴 빨리 끝나야 한다
    virtual bool reservable() const { return occupied() == Tri::NO; }
    virtual void onOccupiedChanged(Tri now) {}
    // 🔴 서버가 재는 것 : occupied() 소요 시간. 문턱 초과 → UNKNOWN + 로그 + 반복 시 제외
};
```
