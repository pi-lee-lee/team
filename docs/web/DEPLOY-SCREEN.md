# 화면(index.html) 배포 절차 — 누가·언제·어디로

> **정본은 이 문서다.** REQ-0240(2026-08-19)로 만들었다.
> 시간이 지나도 참인 것은 `docs/web/LEDGER.md` §5.85 에 있고, 여기는 **절차**다.

## 0. 한 줄

**`serve_file()` 은 `index.html` 을 cwd 상대경로로 연다. 그래서 "서버를 어느 디렉터리에서
띄웠는가"가 곧 "어느 화면이 나가는가"다.** 바이너리를 배포해도 화면은 안 따라간다.

## 1. 무엇이 실제로 서빙되는지 **먼저 값으로 확인한다**

```bash
node web/tools/deploy-screen.mjs --check            # :9900 기본
node web/tools/deploy-screen.mjs --check --port 10000
```

이 명령은 **파일시스템만 읽는다. 서버에 접속하지 않는다** — 관측 창이 도는 동안에도 안전하다.
하는 일:

1. 포트를 듣는 pid 를 찾고 → 그 pid 의 **cwd** 를 읽고 → `cwd/index.html` 이 **실제 서빙 파일**임을 특정
2. 그 파일과 저장소 원본을 **내용 해시로 대조**(표지 자리는 정규화해서 뺀다)
3. 표지(`<meta name="screen-build">`)가 **자기 내용과 맞는지**까지 본다(배포 뒤 손댄 흔적)

⚠ `--url http://…` 을 주면 **HTTP 요청이 나간다.** 창이 열려 있으면 루트에 시각을 알리고 해라.

## 2. 배포 — **root 또는 socket-engineer 가 실행한다**

```bash
node web/tools/deploy-screen.mjs --deploy --port 9900
```

🔴 **실행 주체는 socket-engineer 또는 root 다** (절차서 §0.5.3 에도 명시됨).
`~/parking-bin` 은 프로젝트 밖이라 소유권이 `outside_project_owner: root` 로 판정된다 —
**web-engineer 의 `Edit`/`Write` 는 막힌다.**

⚠ **정확히 적는다**: 훅의 Bash 검사는 휴리스틱이라 `cp` 같은 것은 통과할 수 있다
(socket 은 오늘 실제로 통과했다 — 절차서 §4.2 정정). **즉 "칠 수 있다"와 "쳐도 된다"는 다르다.**
**web-engineer 는 우회하지 않는다** — 훅은 실수를 막는 그물이지 샌드박스가 아니고(CLAUDE.md),
그것을 돌아가는 순간 소유권 구조가 장식이 된다. **그래서 이 명령은 socket 이나 root 가 친다.**

도구가 하는 일:
- 직전 판을 `index.html.prev-<해시>` 로 보관한다(socket 이 `srv_parking.prev-*` 에 하는 것과 같은 규율)
- 표지에 `src=<내용해시> git=<짧은해시> at=<현지시각>` 을 찍는다
- **쓴 뒤 되읽어 확인**한다 — 배포하고 끝내지 않는다

⚠ **서버 재기동은 필요 없다.** `serve_file()` 이 요청마다 파일을 연다.

## 3. 언제 하나

| 시점 | 왜 |
|---|---|
| **`index.html` 을 고친 뒤** | 당연 |
| 🔴 **서버를 재기동한 뒤 — 고친 게 없어도** | **cwd 가 다르면 서빙 파일이 통째로 바뀐다.** 2026-08-19 에 `index.html` 을 아무도 안 건드렸는데 재기동 하나로 08-17 판이 나왔다(원장 §5.85) |
| 배포 전후 관측 창을 열 때 | 낡은 화면을 재면 남의 판을 재고 내 것이라고 보고한다 |

## 4. 볼 자리 — 절차만 적으면 아무도 안 본다

| 자리 | 무엇이 보이나 | 누가 본다 |
|---|---|---|
| `deploy-screen.mjs --check` | 어느 파일이 서빙되는지 + 원본과 같은지 | 사람(수동) · 오프라인 |
| **`live-map.mjs` 안의 하니스 검사** | 서빙 HTML == 저장소 원본. **다르면 대조를 멈춘다** | 자동 — 낡은 화면으로 판정하는 것을 **구조적으로 막는다** |
| **페이지의 `<meta name="screen-build">`** | `curl` 한 번으로 판본 | 누구나 |
| `docs/net/DEPLOY-CHECKLIST.md` §0.5.1 | 배포 의례 안의 확인 | socket (REQ-0243 발행함 — §6) |

```bash
curl -s http://127.0.0.1:9900/index.html | grep -o 'name="screen-build" content="[^"]*"'
```

## 5. 표지를 읽는 법

```
__UNSTAMPED__                              저장소 원본이 그대로 서빙 중(배포 도구를 안 거쳤다)
src=973695a76d90 git=be7ba68 at=…          배포본. src 는 정규화 후 내용 sha256 앞 12자리
(표지 자체가 없다)                          08-17 이전 판이다 — 표지는 REQ-0240 에서 들어갔다
```

⚠ `src=` 는 **표지 자리를 `__UNSTAMPED__` 로 되돌린 뒤** 잰 값이다.
자기를 포함해서 재면 찍는 순간 값이 바뀌어 **영원히 안 맞는다**.

## 6. 남은 구멍 — 이 절차가 없애지 못하는 것

- 🔴 **`--webroot` 가 없다.** cwd 의존이 근본 원인이고, 그게 있으면 이 문서의 절반이 사라진다.
  socket 의 미해결 항목이다(`docs/net/ARCHITECTURE.md`). **REQ-0243 으로 요청했다.**
- **표지는 화면이 스스로 말하는 값이다.** 서버가 어느 파일을 열었는지는 여전히 cwd 로만 안다.
  🔴 **그리고 cwd 는 사후에 복원할 수 없다** — `learn`·`조별과제샘플`·`parking-bin` 셋 다 여러 프로세스가
  드나들어서 그 안의 파일로는 못 가른다(원장 §5.85.1, 내가 한 번 틀렸다).
  → socket 이 다음 배포에서 기동 줄에 `cwd=` 를 찍는다. **그때까지는 `--check` 가 lsof 로 살아 있는
  프로세스에게 직접 묻는 것이 유일하게 믿을 수 있는 경로다**(죽은 프로세스는 답이 없다).
- ⚠ **이 절차는 사람이 실행해야 한다.** 배포 의례에 묶이기 전까지는 잊힐 수 있다 — §6 의 REQ 가 그것을 묶는다.

## 7. `dev_server` 사본 갱신 — **한 줄** (2026-08-20)

`조별과제샘플/dev_server/` 는 socket 이 단독 구동용으로 만든 서버다(dev 포트). 거기 `index.html` 이
없으면 `GET /` 가 404 다. **그 사본의 소유자는 web 이다** — 규칙이 그렇게 열렸다.

```bash
node web/tools/deploy-screen.mjs --deploy --target 조별과제샘플/dev_server/index.html
```

🔴 **왜 socket 이 안 들고 web 이 드나**: **갱신 주체와 소유자를 갈라 놓으면 반드시 낡는다**
(socket 이 스스로 짚었다). 화면을 고치는 사람이 사본도 갱신해야 안 낡는다.

⚠ **손으로 `cp` 하지 마라.** 위 명령은 **판본 표지를 심고 되읽어 확인**한다.
`cp` 는 표지가 옛 값으로 남아 **화면이 자기 판본을 거짓으로 말하게** 만든다.

### 판본이 갈리면 화면이 스스로 말한다

푸터에 `화면 <내용해시> · <커밋>` 이 뜬다(`<meta name="screen-build">` 를 읽어서 보일 뿐이다).
```
6b2461ca7f58 · b9d501c      배포 도구를 거친 사본
개발본 (배포 도구를 안 거침)   저장소 원본을 그대로 연 것 — 개발 중엔 정상이다
(표지 없음)                  표지가 지워졌거나 아주 옛 판이다
```
🔑 **서버 판본과 비교해 경고까지는 하지 않는다.** 과하면 개발에 방해가 된다 —
**화면은 "내가 무엇인지"만 말하고 판단은 사람에게 남긴다.**
