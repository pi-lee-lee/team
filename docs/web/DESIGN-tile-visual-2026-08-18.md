# web 설계 — 칸의 시각 형태 (REQ-0198 · 2026-08-18)

**명세다. 코드는 한 줄도 고치지 않았다.** 시험 인스턴스도 띄우지 않았다.
`DESIGN-module-state-2026-08-18.md` **§5(표시량 의존부 · 명시적 빈칸)** 를 채우는 문서다.

## 0. 서술 층 표기 — 이 문서 전체에 붙인다 (사용자가 정한 형태)

```
✅ 확정   : 실측되거나 결정된 것
🔮 추론   : 근거를 같이 적는다 (근거 있는 추론은 자산이다)
⚠ 미측정 : 안 재 본 것
```

🔴 **이 문서의 시각 형태 결정은 전부 `⚠ 미측정` 이다.** 형태를 정하는 것과 **그것이 읽히는지**는
다르고, 후자는 브라우저로 봐야 안다(§11). 원장 §5.33 의 한계 서술을 그대로 유지한다:
**원칙이 옳아도 형태가 그것을 전달하지 못할 수 있다.**

## 1. 확정 입력 (내가 정한 것이 아니다)

- ✅ **표시량 A** — 자리마다 모듈 상태를 **전부 칸 안에** 표시. 클릭·펼치기 없다(사용자 확정).
- ✅ **`actions` 닫힌 집합 넷** — `reserve`·`cancel`·`open_gate`·`close_gate`(원장 §5.36).
- ✅ **계열 셋** — `unknown`/`fault`/`busy`(§5.36.1).
- ✅ **층 규칙** — 액추에이터는 `"켜졌습니다"` 가 아니라 **`"장치가 켰다고 보고합니다"`**(§5.34.2).
- ✅ **기호축 × 강조축** — 기호는 원인, 강조는 영향. 강조축은 `actionable`/`blocked_reason` 에서
  **파생**이고 화면이 계산하지 않는다(§5.33).

## 2. 🔴 먼저 풀어야 하는 것 — `⏱` 가 **한 칸에서 세 뜻**이다

**이 문서를 쓰다 발견했다.** 지금 화면에 `⏱` 가 이미 둘 있고, 모듈 층이 셋째다:

| # | 어디 | 뜻 | 범위 |
|---|---|---|---|
| 1 | `.tile__stale` 칩 `⏱ N 전 값` | **화면 자료가 오래됐다** | 칸 전체 · 일시 |
| 2 | 폴백 신선도(§5.31) `⏱ 침묵 최대 …` | **장치 침묵의 상한** | 장치 · 일시 |
| 3 | **모듈 상태(신규)** | **그 모듈 값이 안 온다** | 모듈 · **상시** |

⚠ **내가 §5.31 에 "이름이 비슷해서 섞기 쉬운 자리"라고 적어 둔 그 자리다.** 그리고 `cap` 사고
(한 이름 세 뜻 · §5.27)의 **시각 판본**이다.

### 2.1 판별 시험 — 통과시켜야 하는 조건

> **칸 하나를 한 번 보고, `⏱` 가 "이 모듈 값이 안 온다"(상시)인지 "이 칸 전체가 오래됐다"(일시)인지
> 읽는 사람이 구분되나?**

**텍스트를 읽어야 갈린다면 20~30개 규모에서 기호가 일을 못 한다.**

### 2.2 결정 — 🔮 **겹쳐 쓴다. 기호를 늘리지 않는다** (근거 있는 추론)

**세 뜻이 전부 "시간 때문에 확신할 수 없다"** 이고, 그것을 세 기호로 가르면 **범례가 셋 늘어난다**
(§8 의 부하 계산). **같은 생각에 다른 기호를 붙이는 것이 겹쳐 쓰는 것보다 나쁘다.**

**대신 셋을 다른 축으로 가른다:**

```
범위는 위치가 말한다   : 칸 오른쪽 위 칩 = 칸 전체 · 모듈 행 안의 기호 = 그 모듈
크기는 텍스트가 말한다 : 칩과 폴백 줄은 숫자를 달고, 모듈 기호는 맨몸이다
```

🔑 **그리고 강조축이 이미 방어를 준다** — **조작을 막지 않는 `⏱` 는 조용하다**(낮은 대비).
그러므로 **20~30개가 다 떠 있어도 눈에 걸리는 `⏱` 는 막는 것 하나**다.
**이 논거를 명세에 남기는 이유**: 안 적으면 다음 사람이 *"기호가 겹친다"* 만 보고 하나를 바꾼다.

🔴 **`⚠` 를 "오래됨"에 절대 쓰지 않는다.** 오래됨은 고장이 아니다 — §5.31 에서 `⚠`→`⏱` 로 바꾼
것이 그 이유였고, 여기서 되돌리면 그 수정이 무의미해진다.

## 3. 칸 하나의 레이아웃

### 3.1 구조 (⚠ 미측정)

```
┌──────────────────────────┐
│ A1        예약됨      ⏱ 3분 전 값 │   ← 1행: 자리 이름 · 상태(kind 별) · 칸 칩
│ ─────────────────────── │
│ 주차확인센서      ●      │   ← 모듈 행들 (A 안: 전부 보인다)
│ 안내등*           ●      │
│ 유도등*           ○      │
│ ─────────────────────── │
│ [예약 취소]              │   ← 조작 버튼 (§4)
└──────────────────────────┘
```

- **1행은 요약**이다 — 지금 `tile__id` + `tile__state` 가 하는 일. `kind` 별로 어휘가 다르다(§4.1).
- **모듈 행은 `이름 + 상태 기호`.** 이름은 짧게, 기호는 오른쪽 정렬(눈이 한 열을 훑는다).
- **`*` 는 액추에이터 표시** — §7.

### 3.2 🔴 최악 칸을 그려 본다 — **"좁으면 뭉개진다"는 그려 봐야 보인다**

모듈 4개 · 미상 1(조작 막음) · 액추에이터 켜짐 1 · 칸 자료도 오래됨:

```
┌──────────────────────────┐
│ A3    예약 판정 불가  ⏱ 2분 전 값 │
│ ─────────────────────── │
│ 주차확인센서      ⏱  ←── 막는 미상 (강조: 진하게)
│ 안내등*           ●      │
│ 유도등*           ⏱  ←── 안 막는 미상 (조용: 흐리게)
│ 차단봉*           ⚠      │
│ ─────────────────────── │
│ [예약]  ← aria-disabled  │
│ 센서 값이 오지 않아 지금 판정할 수 없습니다 │
└──────────────────────────┘
```

⚠ **여기서 보이는 문제 둘 — 형태 판단의 근거로 남긴다:**

1. **`⏱` 가 한 칸에 세 개**(칩 1 + 모듈 2)다. 2.2 의 판별 시험이 **이 칸에서 가장 위태롭다.**
   강조축(진하게/흐리게)이 유일한 구분자다 → **§11 의 첫 실측 대상이다.**
2. **모듈 4개 + 요약 + 이유 문구 + 버튼 = 7줄.** 자리 5 + 입출구 2 면 **한 화면에 7×7 = 49줄**이다.
   🔮 **격자를 2열로 접거나 칸 높이를 줄이면 이유 문구가 먼저 밀린다** — 그런데 **그 문구가
   `aria-disabled` 의 존재 이유**다(§3.2 원장: *"왜 못 누르는지를 들을 수 있게"*).
   → **문구를 지우는 대신 접근 이름으로 옮기는 것**이 §9 다.

## 4. `kind` 별 차이

### 4.1 상태 어휘 (✅ 계약 · ⚠ 문구는 미측정)

| `kind` | 1행 요약 | 조작 |
|---|---|---|
| `parking` | 지금 7개 view 그대로(`빈 자리`·`예약됨`·`사용 중`…) | `reserve` / `cancel` |
| `entrance`·`exit` | **차단봉 상태**(`열림`·`닫힘`·`미상`) — **예약 어휘가 없다** | `open_gate` / `close_gate` |

🔴 **입출구를 `unknown` 으로 떨어뜨리면 존재하는 것을 없다고 말한다**(설계서 §3.3). 1행 어휘를
`kind` 로 먼저 갈라야 한다.

### 4.2 🔴 **칸이 버튼인 구조를 버려야 한다** (🔮 추론 · 근거는 계약 변경)

지금은 **칸 자체가 `<button class="tile">`** 이고 클릭 위임이 `closest('.tile')` + `dataset.action`
으로 조작을 고른다. **`actions` 가 조작별이 된 순간 "칸 = 조작 하나"가 깨졌다**(§5.36).

- `entrance`/`exit` 는 조작이 **둘**(`open_gate`·`close_gate`)이다 → 칸 하나로 못 가른다.
- **버튼 안에 버튼을 넣을 수 없다**(HTML 무효 · 키보드·보조기술이 깨진다).

→ **칸은 컨테이너(`<li>` + `<section>`)로, 조작은 그 안의 명시적 버튼으로.**

⚠ **대가를 적는다**: `parking` 에서 *"칸 아무 데나 눌러 예약"* 이 사라진다. **두 구조를 섞는 것보다
낫다고 본다** — 섞으면 사용자가 *"어디는 칸을 누르고 어디는 버튼을 누른다"* 를 배워야 한다.
🔮 **이 판단은 뒤집힐 수 있다**(시연 편의가 더 중요하다고 판단되면). 그때는 **`parking` 만 칸=버튼**
으로 두되 **`actions` 가 둘 이상인 kind 와 시각적으로 구분**되어야 한다.

### 4.3 🔴 이 전환에 **하니스 셋이 걸린다** (✅ 확인함)

```
e2e.mjs           .tile[data-slot=…] 클릭 · dataset.action 으로 대상 칸 선택
queue-contract.mjs 같은 선택자로 타일 상태를 읽는다
queued-live.mjs    같은 선택자로 클릭·확인 대화상자를 연다
```

**구조를 바꾸면 셋 다 깨진다.** 🔑 **§5.30 이 방금 가르친 것이 이것이다** — 하니스가 조용히
엉뚱한 것을 보면 제품 실패로 위장한다. **구현 때 하니스를 같은 커밋에서 고치고, 고치기 전
판본에 돌려 빨간불을 먼저 확인한다**(§5.31 에서 한 절차).

### 4.4 🔴 구현 때 **같이 고칠 것** — `cmdPending` 이 `queued` 를 안 받는다

**별건으로 남겼는데 잊히기 쉬운 형태라 여기 박는다**(루트 지시: *"별건"이 "안 함"이 되지 않게*).
**4번에서 어차피 이 코드를 만진다.**

```
handleServerMessage 의 queued 분기가 state.pending 만 본다 (state.cmdPending 은 안 본다)
그런데 socket 명세는 M·T 도 같은 큐를 탄다고 정했다
→ 테스트·시뮬 명령이 큐에 담겨 queued 가 오는데 화면이 조용히 버리고
  cmdPending 의 6초 고정 타이머로 **거짓 실패 문구**를 낸다
```

**REQ-0166 에서 예약 경로에 닫은 구멍이 이 경로엔 그대로다**(원장 §5.38.2).
⚠ **소스 판독이고 실측이 아니다.** 피해는 예약보다 작다(진단 기능 · 화면 상태를 안 바꾼다).

**고칠 형태**(⚠ 미측정): `queued` 분기가 **두 맵을 다 보게** 하고, `cmdPending` 타이머도
**`exp + budget` 으로** 건다. 🔑 **여기서도 `ACK_TIMEOUT` 으로 메우지 않는다** — 같은 이유다
(§5.26: 값이 없으면 **모르는 판본**이라는 뜻이고 짐작하면 구멍이 되살아난다).

## 5. 빈 칸 / 미상 자리 / 정상 자리 (⚠ 미측정)

셋을 **다른 것으로** 그린다. 기존 관습을 잇는다 — 새로 발명하지 않는다.

| | 시각 | 근거 |
|---|---|---|
| **정상 자리** | 실선 테두리 + `kind` 색 | 현행 `data-view` 관습 |
| **미상 자리** | **점선 테두리 + 흐린 글자** | 현행 `data-view="unknown"` 이 이미 그렇다 |
| **빈 칸** | **테두리 없음 · 격자 배경만 · 내용 없음** | 신규 |

### 5.1 🔴 빈 칸은 **버튼도 타일도 아니다** — 키보드 순서에서 빠진다

**`5×5` 에 자리 5 + 입출구 2 면 빈 칸이 18개다**(원장 §5.29 계열 · **`칸수 − zone수` 파생값 ·
격자 크기가 바뀌면 이 수도 바뀐다**).

🔑 **18개가 전부 탭 정지점이면 키보드 사용자는 자리에 닿기까지 18번 탭한다.** 그건 시각 문제가
아니라 **접근성 결함**이다. → **빈 칸은 `aria-hidden` 인 순수 장식 칸으로 두고 초점을 받지 않는다.**

⚠ 그리고 **빈 칸에 `"상태 미상"` 을 절대 쓰지 않는다** — 존재하지 않는 것을 "모른다"고 말하는 것이고,
그러면 **§6 의 집계가 18로 튀어 쓸모없어진다.**

## 6. 미상 집계 한 줄 (⚠ 미측정)

**위치**: 격자 **위**, 기존 `#slots-banner` 자리. 🔑 **새 자리를 만들지 않는다** — 그 배너가
§3.1 에서 *"칸 문구만으로 부족해서"* 생긴 것이고 **같은 문제의 확장**이다.

**세는 규칙**(§2.3 그대로): 🔴 **`blocked_reason` 이 `unknown` 계열인 zone 의 수만 센다.**

```
정상(안내등만 미상)      → 침묵                    ← 상시 상태가 경고를 만들지 않는다
주차확인센서 미상 2자리  → "⏱ 2자리는 지금 예약 판정을 할 수 없습니다"
```

- 🔴 **`busy` 는 세지 않는다** — 곧 풀리는 정상 상태다(§5.36.1).
- 🔴 **조작을 막지 않는 미상도 세지 않는다** — 세면 **정상 운영이 경고를 만든다.**
  ⚠ **그렇다고 감추는 것이 아니다**: 그것은 모듈 행에 **조용히** 보인다(A 안이라 이미 다 보인다).
  **집계에서 빠지는 것과 화면에서 사라지는 것은 다르다.**
- ✅ **"다 보이니 집계는 필요 없다"로 읽지 않는다**(루트 지적). **20~30개 중 2개가 미상인 것을
  눈으로 세는 것과 수로 읽는 것은 다르다.**

## 7. 액추에이터 — "보고한다"를 기호로 · 그리고 부분 완료

### 7.1 결정 — 🔮 **기호가 아니라 이름에 붙인다** (`*`)

**근거의 층(§5.34.2)은 그 모듈의 성질이지 그 순간의 상태가 아니다.** 그러므로 **상태 기호가 아니라
이름 쪽에 붙는 것이 맞다.** 상태 기호 어휘는 `● ○ ⏱ ⚠` 넷으로 유지된다.

```
주차확인센서   ●      ← 관측된 사실
안내등*        ●      ← 장치가 그렇게 보고한다
```

**범례 한 줄**: `* = 장치가 보고한 값. 실제로 켜졌는지(전구·배선)는 확인할 수 없습니다.`

### 7.2 🔑 좁은 곳은 기호, 넓은 곳은 문장

**칸이 좁을수록 뭉개진다는 문제의 답이 여기다.** 같은 사실을 **자리에 따라 다른 길이로** 말한다:

| 어디 | 표현 |
|---|---|
| 모듈 행(좁다) | `안내등* ●` |
| 접근 이름·상세(넓다) | `"안내등: 장치가 켰다고 보고합니다"` |

→ **기호는 축약이고 문장이 원본이다.** 축약만 남는 자리를 만들지 않는다(§9).

### 7.3 대안을 왜 안 골랐나 (기록)

- **다른 기호 계열**(`▣/□`): 범례가 **둘** 늘고, **근거 층을 상태 축에 얹는다**(축 혼합 · §5.33 위반).
- **표시 안 함**: 층 규칙(§5.34.2)을 화면이 안 지키는 것이 된다.

### 7.4 ✅ 부분 완료 — **계약이 도착했다** (socket 명세 §3.5 · 커밋 `569b514`)

REQ-0197 답이 왔으므로 §10 의 구멍 하나가 닫혔다. 받는 자료:

```
zone.action_state = { state: done|partial|failed|pending, ok: n, total: m,
                      missing: [(devid, name, blocked_reason?)] }
```

✅ **`done` 은 대상 모듈 전부 에코 일치일 때만이다.** 근거가 내 판정이다 —
*"거짓 완료는 안 된 것을 됐다고 말한다"* → **하나라도 미확인이면 완료가 아니다.**

#### 7.4.1 🔑 A 안에는 **펼치기가 없다** — `missing` 의 자리를 다시 정한다

socket 은 *"`missing` 은 펼쳤을 때만 쓰라"* 고 적었다. **그런데 표시량 A 는 클릭·펼치기가 없다.**

→ **A 안에서는 `missing` 을 따로 그릴 필요가 없다.** **모듈 행이 이미 전부 보이므로**
`missing` 은 **어느 행에 표식을 붙일지 알려 주는 입력**이다. 그 행에 `⏱`(미상 계열) 또는
`⚠`(고장 계열)가 붙는다 — **`blocked_reason` 이 계열을 정한다**(§5.36.1).

🔑 **A 안을 고른 대가가 여기서 이득으로 돌아온다**: 펼치기가 있는 안(B)이라면 *"부분 완료인데
어느 모듈인지 보려면 눌러야 한다"* 가 되는데, **A 는 이미 보인다.**

#### 7.4.2 🔮 `ok/total` 은 **`partial` 일 때만** 표시한다 (socket 이 내 판단으로 남긴 것)

socket 이 *"`1/1` 을 숨길지 표시할지는 네 판단"* 이라 했다. **정상에서 침묵** 규칙에서 파생된다:

| 상태 | 수를 보이나 | 왜 |
|---|---|---|
| `done` | ❌ | 수가 정보를 더하지 않는다 |
| `partial` | ✅ `2/3` | **"몇 개가 남았나"가 유일하게 수로만 전달된다** |
| `failed`·`pending` | ❌ | 계열 표시가 그 일을 한다 |
| `total === 1` | ❌ | **`partial` 이 구조적으로 불가능하다** — 하나는 되거나 안 된다 |

→ **규칙: 수는 "부분"일 때만 의미가 있다.** 임의로 정한 것이 아니라 위 표에서 나온다.

#### 7.4.3 🔴 `partial` 은 **일시 상태다** — `busy` 표시 언어를 쓴다

socket 이 준 성질: 에코가 있으니 **서버가 남은 모듈만 재하달한다**(자가 치유의 확장) →
**정상 경로에서 다음 창에 해소된다**(그 노드 기준 ≤1 주기). 그리고
**오래 남으면 `blocked_reason` 이 같이 오므로 — 계약상 오래 남는 `partial` 은 존재하지 않는다.**

🔑 **그래서 `partial` 은 `busy` 와 같은 계열로 그린다**(§5.36.1). 선례가 또 그 자리다 —
하행 아이들 1초에서 *"곧 풀리는 상태를 '연결 없다'로 말하면 고장으로 읽힌다"* 로 만든 제3의 표시다.

- 🔴 **`partial` 을 미상 집계에 넣지 않는다.** 일시 정상 상태다 — 세면 정상 운영이 경고를 만든다.
- 🔑 **화면이 "오래 남았다"를 스스로 판정하지 않는다.** 타임아웃 휴리스틱을 두면 **화면이 짐작하는 것**
  이고(§5.14), 그럴 필요가 없다 — **오래 남으면 서버가 `blocked_reason` 으로 말해 준다.**
  그때 계열이 `unknown`/`fault` 로 바뀌고 **비로소 강조·집계 대상이 된다.**

⚠ **`≤1 주기` 는 socket 이 준 설계값이고 내가 잰 것이 아니다.** 그리고 **내 `≈1초`(센서 방향)를
여기 인용하지 않는다** — 액추에이터 방향 치유 시간은 아직 아무도 안 쟀다(원장 §5.34.1).

## 8. 🔴 범례 부하 — **옵션 A 의 대가로 세어 둔다** (✅ 세어 봄)

**배울 것을 다 세면 아홉이다**: 색 4계열 · 점선(미상) · 파선+맥동(pending) · `⚑`(주입값) ·
`⏱` 칩(오래됨) · mine inset · `● ○`(on/off) · `⏱`(모듈 미상) · `⚠`(모듈 고장) · `*`(보고값).

⚠ **§3.1 의 형제 명제다: 배울 것이 많은 범례는 아무도 안 읽는다.**
🔮 **그래서 범례에 의존하지 않는 것이 하나는 있어야 한다** — **강조축**이 그 역할이다.
**범례를 안 읽어도 "진한 것부터 보면 된다"는 하나는 통한다.**

⚠ **이것은 추론이다. 실제로 통하는지는 사람이 봐야 안다**(§11).

## 9. 접근성 — 이름을 **의도적으로** 만든다 (⚠ 미측정)

칸이 컨테이너가 되면 모듈 행은 **정적 텍스트**가 되고, 조작 버튼의 접근 이름이 **우연히** 정해진다.

🔑 **§3.2 가 `disabled` 대신 `aria-disabled` 를 고른 이유가 *"왜 못 누르는지를 들을 수 있게"* 였다.**
그 약속을 지키려면 **자리마다 요약 문자열을 의도적으로 조립해야 한다:**

```
버튼 접근 이름 : "A3 예약 — 지금 할 수 없습니다: 센서 값이 오지 않았습니다"
자리 요약      : "A3, 예약 판정 불가. 주차확인센서 값 없음. 안내등 켜짐(장치 보고). 차단봉 이상."
```

- **기호는 접근 이름에 넣지 않는다** — `⏱` 를 읽어 주면 뜻이 전달되지 않는다. **문장으로 쓴다**(§7.2).
- **`aria-disabled` 유지**(진짜 `disabled` 는 초점을 못 받아 이유를 들을 수 없다 · §3.2).
- **모듈 행은 목록으로**(`<ul>`) — 나열이라는 것이 보조기술에 전달된다.

## 10. 🔴 구멍 — 여기는 설계하지 않는다

- ~~**부분 완료 표시**~~ → ✅ **닫혔다. §7.4 를 봐라**(socket 명세 §3.5 · REQ-0197 답이 왔다).
- **`prefers-reduced-motion` 대체 신호**: 지금 `pending` 이 **맥동 하나**에 걸려 있다
  (`animation: pulse`). 🔴 **모듈 층에서 pending 이 둘이면 위상이 어긋나 두 번 맥동하고,
  reduced-motion 사용자에게는 신호가 아예 없다.** → **비-모션 전달자가 필요하다**(파선 테두리 +
  텍스트). ⚠ **형태 미정.**
  🔑 **§7.4.3 으로 대상이 늘었다**: `pending` · `busy` · `partial` 이 **전부 "곧 풀린다" 계열**이라
  같은 전달자를 쓴다. → **맥동 하나에 셋을 걸면 reduced-motion 에서 셋이 동시에 사라진다.**
  **밀도(20~30개)와 겹치는 자리이므로 §11 의 실측에서 같이 본다.**
- **색만으로 구분하지 않는다**: `tileView` 주석의 약속을 **모듈 층까지 내린다.**
  🔴 **on/off 를 색으로만 가르면 조용히 어긴다** — 채움(`●`/`○`)이 그 방어이고 **색은 보조**다.

## 11. ⚠ 실측이 필요한 시점 — **명세가 정할 수 없는 것**

**형태를 정하는 것과 그것이 읽히는지는 다르다.** 아래는 **구현 뒤 브라우저로** 확인한다.

| # | 무엇 | 왜 지금 못 하나 |
|---|---|---|
| 1 | **§2.1 판별 시험** — 한 칸에 `⏱` 셋이 있을 때 범위가 구분되나 | 그릴 것이 없다 |
| 2 | **§8 범례 부하** — 범례를 안 읽고도 진한 것부터 읽히나 | 사람이 봐야 안다 |
| 3 | **§3.2 최악 칸이 7줄인데 49줄 격자가 읽히나** | 실제 밀도가 필요하다 |
| 4 | 접근 이름이 스크린리더에서 뜻이 통하나 | 보조기술로 들어야 안다 |

🔑 **절차는 §5.31 에서 쓴 것을 그대로 쓴다**: **고치기 전 판본에 검사를 먼저 돌려 빨간불을 확인**한
뒤 고친다. 그리고 **하니스 셋(§4.3)이 이 구조 변경에 걸리므로 같은 커밋에서 고친다.**

⚠ **이 문서의 시각 결정은 전부 `⚠ 미측정` 이다.** 하나라도 §11 을 통과하지 못하면 **형태를 바꾼다 —
규칙(§5.33 두 축 · §5.34.2 층)은 그대로 두고 형태만 바꾼다.** 규칙과 형태를 같이 흔들면 무엇이
틀렸는지 못 가른다.
