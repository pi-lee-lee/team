## 1. 화면이 붙는 곳

### 1.1 서버는 HTTP 와 WS 가 **같은 포트 하나**다 — 오프셋은 둘을 같이 옮긴다 (실측)

`server.cpp` 의 리스너 하나가 `index.html` 정적 서빙과 `GET /ws` 업그레이드를 겸한다
(`lsn_http = listen_on(PORT_HTTP + g_port_offset)`, 2102행 / `path == "/"` → `/index.html`, 1855행).

- 운영: **9900** · 시험 인스턴스(`--port-offset=100`): **10000**
- 실측 근거: `http://127.0.0.1:10000/` 이 페이지를 주고, 같은 포트로 `ws://127.0.0.1:10000/ws`
  업그레이드가 성사됐다(CDP `Network.webSocketCreated` 로 확인, 2026-08-16 19:07).

**따라서 "페이지를 준 포트 = WS 포트"가 이 시스템의 불변식이다.** 화면이 WS 포트를 따로
정하려 들면 그 순간 두 서버를 섞을 수 있다 — 실제로 그랬다(§1.2).

### 1.2 🔴 함정 — 화면이 `location.port` 를 무시하고 상수 9900 을 쓰면 **운영으로 샌다**

2026-08-16 이전의 `index.html` 이 그랬다. 호스트만 `window.location` 에서 가져오고
포트는 `const WS_PORT = 9900` 이었다.

결과(코드 판독 + 그 뒤 실측으로 확인):

> 시험 서버(:10000)가 준 페이지를 열면 **WebSocket 은 운영(:9900)** 으로 붙는다.
> 폴백 폴링만 상대경로라 :10000 으로 간다 → **한 화면이 두 서버를 섞는다.**
> 그 화면에서 예약을 누르면 **운영 장치로 하행 명령이 내려간다.**

**이 함정의 지독한 점**: 시험 인스턴스 로그에는 아무것도 안 남는다. 흔적은 운영 로그에만
생기므로 **깨진 줄도 모른다.** 포트·`flock`·로그 분리를 아무리 겹쳐도 화면에 박힌 상수
하나가 전부 통과했다.

지금은 `resolveWsPort()` 가 `?ws=` → `location.port` → 9900 순으로 정한다.
회귀 검사: `node web/tools/check-index.mjs` §5.

### 1.3 함정 — 리버스 프록시·80/443 뒤에서는 `location.port` 가 **빈 문자열**이다 (추정, 미실측)

그 경우 §1.2 의 규칙이 문서화된 기본값 9900 으로 떨어진다. 프록시가 WS 를 다른 데로
넘긴다면 `?ws=` 로 명시해야 한다. **이 구성은 이 프로젝트에 아직 없어서 실측하지 않았다.**

### 1.4 폴백은 상대경로 `data_log.json` 이다 → 기본 경로에서는 WS 와 항상 같은 오리진 (실측)

둘이 다른 서버를 가리킬 수 있는 유일한 경우는 `?ws=` 를 명시했을 때이고, 그때 화면이
빨간 경고를 띄운다(실측: `web/artifacts/4-fallback.png`).

## 2. 서버가 화면에 주는 것

### 2.1 WS 스냅샷의 `device` 에는 `last_frame_ts` 가 **없다** (실측)

> ⚠ **이 항목은 빌드에 딸린 사실이다. `build=22f788d` 부터는 아니다 — §5.1 을 먼저 읽어라.**
> (아래 내용은 그 빌드 **이전**에 대해 여전히 참이고, 운영에 무엇이 올라가 있는지는 별개다.)

2026-08-16 19:07, 시험 인스턴스에서 받은 실제 프레임(`web/artifacts/ws-snapshot.json`):

```
WS   device = { online, device_id, uptime, seq }
파일 device = { online, last_frame_ts }
```

→ **신선도 표시는 폴백 경로에서만 동작한다.** 정상 운영 중에는 화면이 계속
`"알 수 없음 (이 경로에는 이 정보가 없습니다)"` 를 띄운다(실측한 DOM 문자열).

REQ-0132 로 socket 에 요청했다. 오면 화면은 그날로 동작한다(이미 그 키를 읽고 있다).

### 2.2 🔴 함정 — `GET /?쿼리` 는 **404** 다. `GET /index.html?쿼리` 는 200 (실측)

> ⚠ **이 항목도 빌드에 딸린다. `build=22f788d` 부터는 200 이다 — §5.1.**
> 그리고 **이 응답 코드 자체가 빌드 판별자다**: 붙은 서버가 REQ-0132 이전인지 이후인지
> `GET /?demo=1` 한 줄로 갈린다(404 = 이전 · 200 = 이후).

```
GET /                  → 200
GET /index.html?demo=1 → 200
GET /?demo=1           → 404
```

원인(판독): `serve_file()` 이 `path == "/"` → `/index.html` 매핑을 **쿼리 제거보다 먼저**
한다. `/?demo=1` 은 `"/"` 와 다르므로 매핑을 놓치고, 쿼리를 자르면 파일명이 빈 문자열이 된다.

**시연에서 `호스트:9900/?demo=1` 을 치면 빈 페이지가 뜬다.** 주소에 `/index.html` 을 반드시
넣어라. REQ-0132 로 요청했고, 고쳐지면 `web/tools/e2e.mjs` §9 가 저절로 초록이 된다.

### 2.3 화면은 서버 **로그**를 읽지 않는다 (REQ-0122 에서 확인, 여전히 참)

입력 경로는 WS JSON 과 `data_log.json` 둘뿐이다. 그래서 로그 줄의 지표 이름이 바뀌는
`오프라인` → `무프레임` 개명에 화면은 걸리지 않는다.

### 2.4 화면은 최상위 `occupied`/`reserved` **비트열을 읽지 않는다.** `slots[]` 만 본다 (실측)

비트열이 멀쩡히 있어도 `slots` 가 비면 10칸 전부 "상태 미상"이 된다
(측정: `web/artifacts/probe-slots.json` 의 `bits` 사례). 서버가 지금 둘 다 보내므로 문제는
없지만, **`slots[]` 를 빼는 변경은 화면을 조용히 눈멀게 한다.**

## 3. 화면이 상태를 말하는 방식

### 3.1 `slots[]` 결손은 "빈 자리"로 보이지 **않는다** — 통념 정정 (실측)

> ~~"slots 가 없으면 10칸이 조용히 빈자리로 보인다"~~ — **틀렸다.**
> 2026-08-16 실측: 결손 칸은 `상태 미상 / 데이터 없음`(점선 테두리)으로 그려진다.
> 근거는 `normalizeSnapshot()` 이 칸마다 다는 `known: bySlot.has(id)` 이고,
> `tileView()` 가 `!slot.known` 이면 `view:'unknown'` 을 돌려준다.
> 측정 원문: `web/artifacts/probe-slots.json` (5개 사례 · `web/artifacts/slots-*.png`).

**다만 진짜 빈틈은 다른 데 있었다**: 그 말이 **칸 안에만** 있었다. 10칸 중 3칸만 미상이면
나머지 7칸이 정상이라 화면 전체는 멀쩡해 보인다. 그래서 같은 날 격자 위에 **집계 배너**를
추가했다(`#slots-banner`). 배너는 집계만 하고 칸의 문구를 대신하지 않는다.

### 3.2 함정 — 이 화면의 "누를 수 없음"은 `disabled` 가 아니라 `aria-disabled` 다 (실측)

`t.button.setAttribute('aria-disabled', …)` 만 쓰고 `button.disabled` 는 건드리지 않는다.
**의도된 설계다**: 진짜 `disabled` 로 만들면 키보드·스크린리더 사용자가 그 칸에 도달조차
못 해서 "왜 못 누르는지"를 들을 수 없다. 클릭 핸들러가 `aria-disabled` 를 보고 이유를 띄운다.

→ **자동 검사에서 `el.disabled` 를 읽으면 항상 `false` 라 "막힘이 안 먹는다"고 오판한다.**
실제로 이날 그 오판을 한 번 했다. 반드시 `getAttribute('aria-disabled')` 를 읽어라.

### 3.3 소켓이 끊겨도 화면은 비지 않는다 — 폴백이 이어받는다 (실측)

살아 있는 WS 를 끊으면 **2ms 안에** 연결 표시가 "연결 끊김 — N초 후 재연결 시도"로 바뀌고,
칸 10개는 **직전 상태를 유지**한다("상태 미상"으로 떨어지지 않는다). 그 뒤 자동 재연결된다.
즉 이 화면의 실패 모드는 "빈 화면"이 아니라 "오래된 값 + 그렇다는 표시"다.
(측정 절차: `e2e.mjs` §6 — 브라우저에서 `transport.ws.close()` 로 소켓만 끊는다)

### 3.4 예약 왕복은 브라우저 클릭에서 화면 반영까지 **약 205ms** (실측 2회)

시험 인스턴스 + `fake_arduino`(로컬) 기준이다. 실물 ESP·무선이 들어가면 달라진다 —
**이 숫자를 실물 경로의 기대값으로 옮겨 쓰지 마라.**
구간 정의: `#confirm-dialog` 의 확인 버튼 클릭 → 그 칸의 상태 문구가 "내 예약"으로 바뀜.

## 4. 시험 방법에 대해 참인 것

### 4.1 브라우저 검증은 의존성 없이 된다 — CDP 직접 (실측)

node 22 의 전역 `WebSocket`·`fetch` 로 크롬 DevTools 프로토콜을 직접 말한다
(`web/tools/cdp.mjs`). puppeteer 같은 것을 들이지 않았다.
`--headless=new` + **매번 새 임시 `--user-data-dir`**(사용자 프로필을 재사용하면 잠금 충돌).

### 4.2 함정 — 상태 문구를 `waitFor` 로 기다리면 **바뀌기 전 값에 즉시 걸린다** (실측)

빈 문자열이 아닌 모든 문자열은 참이다. `waitFor("…textContent")` 는 "빈 자리"에 즉시
성공하고, 그러면 4ms 만에 "화면이 안 바뀌었다"는 **거짓 실패**가 난다.
반드시 **불리언**을 기다려라: `/예약/.test(…)`.
이날 이 한 줄 때문에 종단 시험이 두 번 잘못된 결론을 냈다.

### 4.3 시험 인스턴스의 `data_log.json` 은 오프셋으로 갈리지 않는다 (실측)

`atomic_write_log()` 가 **cwd 상대경로**로 쓴다. `--port-offset` 이 갈라 주는 것은
**로그 파일 경로뿐**이다(`.test+100`).

- 운영 인스턴스의 cwd 는 `/Users/idong-u/parking-bin` 이라 **운영 파일과는 안 부딪친다**
  (`lsof -p <pid> -a -d cwd` 로 확인).
- cwd 를 `조별과제샘플` 로 잡는 시험 인스턴스는 `조별과제샘플/data_log.json` 을 덮어쓴다.
  ~~그 파일은 git 추적 대상이라 커밋에 딸려갈 수 있다~~ — **틀렸다.** `.gitignore:53` 에
  있어 추적되지 않는다(socket-engineer 정정, `git ls-files` 로 확인). **되돌릴 것이 없다.**
  내가 `git ls-files` 를 돌려 보지 않고 "추적 파일"이라 단정한 것이 원인이다.

### 4.4 🔴 화면이 서빙되는지는 **서버를 어디서 띄웠느냐**로 결정된다 (실측 — 단, 근거는 GET 이 아니다)

`serve_file()` 은 `index.html` 을 **cwd 상대경로**로 연다. 즉 **바이너리 위치가 아니라
작업 디렉터리에 `index.html` 이 있어야 화면이 나온다.** 없으면 그 포트는 404 만 준다.

2026-08-16 시점의 실제 상태:

```
/Users/idong-u/parking-bin/     ← 운영(pid 75781)의 cwd
  srv_parking · data_log.json · stderr.log      ← index.html 이 **없다**
```

> ⚠ **`pid 75781` 은 낡았다** (2026-08-16 23:5x 정정). 21:05:10 머신 재부팅으로 종료됐다 —
> 비정상 종료가 아니라 SIGTERM 정상 종료다(root 확인 · 운영 로그 13608행
> `INSTANCE-END reason=normal frames=10176 sessions=11`). 나는 23:47 에 프로세스·LISTEN 이
> 비어 있는 것만 봤고, 경위는 root 가 로그로 채웠다.
>
> **이 항목의 결론은 그대로 참이다** — 낡은 것은 pid 하나뿐이고, "그 디렉터리에 `index.html`
> 이 없어서 운영은 화면을 못 준다"는 결론은 pid 와 무관하다.
>
> 교훈: **원장에 pid 를 적으면 반드시 썩는다.** 재부팅 한 번이면 끝이다. 경로·cwd·포트는
> 안 썩는다. 다음부터는 프로세스를 가리킬 때 pid 대신 **cwd 와 포트**로 적는다.

→ **운영 인스턴스는 관측용이고 화면을 서빙하지 못한다.**

**이 결론의 근거가 무엇인지가 결론만큼 중요하다** — 세 가지이고, **셋 다 운영 포트를 건드리지
않는다**(관측 창 규칙):

1. `server.cpp:1892` `std::ifstream f(fn.c_str(), std::ios::binary)` — 상대경로다(소스)
2. `~/parking-bin/` 의 파일 목록에 `index.html` 이 없다 (`ls`, web·root 가 각각 독립 확인)
3. 같은 방식으로 쓰는 `data_log.json` 이 **그 디렉터리에 실제로 생겨 있다** — cwd 상대라는 방증

즉 근거는 **소스와 파일 목록**이지 *GET 응답*이 아니다. GET 은 일부러 안 보냈다 —
얻을 것이 없고 운영 로그에 accept 한 줄이 남아 monitor 의 계수에 섞인다.
(**"필요 없으면 안 건드린다"** 가 이날 지킨 규율이다. 확인하고 싶은 충동이 관측을 오염시킨다.)

시연에서 화면을 띄우려면 **`index.html` 이 있는 디렉터리에서 서버를 띄워야 한다** —
지금 그런 곳은 `조별과제샘플/` 이다. 루트 판단으로 **사본을 두지 않고**
`--webroot` 로 경로 해석을 고치는 방향이 socket 에 넘어가 있다(사본이 둘이면 갈라진다).

**이 함정이 지독한 이유**: 서버는 정상 기동하고 로그도 정상이며 WS 도 열린다.
화면만 안 나온다. "서버는 떴는데 왜 페이지가 없지"를 시연장에서 만나게 된다.

### 4.5 `?demo=1` 은 서버에 트래픽을 만들지 않는다 (코드 판독 + 실측)

`transport.start()` 가 `connect()`·`startPolling()` **앞에서** 반환한다.
관측 창이 걸려 있을 때 화면 검증에 쓸 수 있는 유일한 경로다.
단, 주소는 `/index.html?demo=1` 이어야 한다(§2.2).

### 4.6 브라우저 검증을 다시 돌리는 절차

```bash

#    선례: REQ-0128

  → 서버 배포가 **그 순간 옛 화면을 깨뜨린다**

REQ-0155(하행 큐의 "접수됨") 때 이 판정이 실제로 방향을 정했다. `ack` 에 상태 필드를 넣는
안이었으면 옛 화면이 `type==='ack'` 만 보고 **전선에 나가지도 않은 요청을 "예약되었습니다"로
선언**했을 것이다.

⚠ **근거 정정 이력**: 처음에는 `msg.type` 세 곳만 grep 하고 이 결론을 적었다. **그건 "세 타입을
검사한다"만 증명하지 "끝에 else 가 없다"를 증명하지 않는다.** 함수 끝까지 읽어 확인한 뒤
근거를 바꿨다 — **결론은 같았지만 근거가 부실했다.** 캐치올이 있었다면 위험의 크기가 달랐다
("조용히 무시" 가 아니라 "시끄럽게 오작동").

### 5.14 🔴 화면의 자체 타임아웃이 **짧으면 서버 큐를 키운다** (설계 함정)

REQ-0155 에서 나온 것. 서버가 하행을 큐에 담게 되면 이 연쇄가 생긴다:

```
큐 대기 → 화면 자체 타임아웃(ACK_TIMEOUT)이 먼저 터짐 → 롤백
→ 사용자가 다시 누름 → 새 rid (서버 pending 은 이미 풀려 has_pending_for 도 안 막는다)
→ 큐에 한 건 더
```

**즉 화면이 "안전하게" 되돌리는 동작이 시스템 부하를 키운다. 타임아웃이 짧을수록 더 쌓인다.**
socket 이 "같은 자리 중복은 서버가 막는다"고 적어 뒀던 항목이 이것 때문에 취소선으로 정정됐다 —
**그 방어는 pending 이 살아 있는 동안만 유효하다.**

→ **규칙**: 화면의 타임아웃은 **서버가 준 상한에 묶는다. 화면이 짐작하지 않는다.**

### 5.18 🔴 **예외로 죽은 실행이 "통과"로 찍혔다** — 집계기는 예외도 세야 한다

2026-08-17 실측. `blink.mjs` 의 `failed` 는 `check()` 만 올리는데, 실행이 예외로 중단되면
**`check()` 가 한 번도 안 돈다 → 실패 0건 → "통과"** 였다. 화면 첫 줄에 `💥` 가 떠 있는데
**마지막 줄이 "통과"** 이고 구간 기록 파일에도 `종료 (통과)` 로 남았다.

**즉 아무것도 못 쟀는데 초록을 내는 검사기다.** §5.3 과 같은 뿌리다 — **검사기가 틀렸는데
대상이 틀렸다고(또는 맞다고) 말하는 상태는 그 자체로는 절대 안 드러난다.**

`process.exitCode = 1` 은 걸려 있었지만 **사람이 읽는 줄과 파일에는 안 반영**됐다.
종료 코드는 셸이 보고 사람은 마지막 줄을 본다 — **둘이 다른 말을 하면 사람 쪽이 이긴다.**

→ **규칙: 실패 집계는 `catch` 에서도 올린다.** 그리고 **"통과/실패"를 적는 곳이 여럿이면
전부 같은 값을 봐야 한다**(콘솔·로그 파일·구간 기록·종료 코드).

**어떻게 찾았나가 중요하다**: monitor 의 규칙 — *"도구를 만들면 실제로 돌아간 증거 한 줄을
보고에 같이 넣어라. 출력이 없으면 안 돈 것이다"* — 를 따라 **아무도 안 듣는 포트로 한 번
돌려 봤더니** 나왔다. **안 돌려 봤으면 못 봤다.**

### 5.17 도구의 기본값이 **딴 데를 가리키면 조용히 틀린 답을 낸다** — 없애지 말고 **유도해라**

2026-08-17 실측. `e2e.mjs` 의 `--log` 기본값이 `test+100` 이었는데 시험 인스턴스가 `+600` 이라
**엉뚱한 로그 파일을 조용히 읽고** *"서버가 R 을 안 내보냈다"* 는 **거짓 실패**를 냈다.
예약은 멀쩡히 성공했고 화면도 "내 예약"이었다 — **제품이 아니라 하니스가 틀린 것**이다.

같은 뿌리의 사고가 하루에 셋이었다(socket 확인): `ws_probe` 의 기본 포트가 운영 · `frame_gaps`
의 경로 하드코딩 · 이것. **공통점은 "도구가 자기가 어디를 보는지 말하지 않는다"** 이다.

→ **해법 둘 중 유도가 낫다:**

| | 방식 | 대가 |
|---|---|---|
| 없애기 | 필수 인자로 만든다(`--port` 처럼) | 매번 쳐야 한다. **다른 값을 넣을 여지는 남는다** |
| **유도하기** | **대상에서 계산한다**(`포트 10500 → test+600.log`) | **틀릴 수가 없다** |

**운영을 건드릴 수 있는 것(포트)은 없애고, 대상에서 정해지는 것(로그 경로)은 유도한다.**

### 5.15 확정된 계약 — `queued` (REQ-0155)

**원본은 socket 의 `docs/net/DESIGN-server-slot-queue.md` §4-B**(커밋 `3cf6ed9`·`8ba70cb`)다.
여기에는 **화면 쪽이 지켜야 할 것만** 적는다. 값이 갈리면 원본이 이긴다.

```json
{"type":"queued", "rid":"…", "slot":"A1", "ahead":2, "expires_ms":<남은 지속시간 ms>}
```

- **`expires_ms` 는 "이 프레임을 받은 시점 기준 남은 상한"**(지속시간). 절대 시각이 아니다.
  서버는 `deadline = enqueue + cap` 을 항목마다 한 번 박고 낼 때마다 `deadline − now` 를 보낸다
  → **단조 비증가가 구조상 보장된다.** 🔑 **두 시계를 안 섞는 방식이다** — 서버는 자기 시계로
  차이만 내고, 화면은 받은 지속시간을 자기 시계로 잰다. **어느 쪽도 상대 시계를 안 읽는다.**
- **화면 규칙**: `queued` 를 받을 때마다 **타이머를 다시 건다**(`expires_ms + ACK_TIMEOUT`).
- **`queued` 뒤에는 반드시 `ack` 또는 `error` 가 온다** — 서버가 지키기로 한 보장이다.
  **이게 없으면 중간 상태가 영구가 된다**(타일이 영원히 맥동한다).
- **거절 코드 둘을 다른 문구로 그린다**: `queue_full`(시스템 사정 — "지금 붐빕니다") ·
  `already_pending`(**사용자 잘못이 아니다** — "이미 처리 중입니다").
- **`ahead` 로 시간을 환산하지 않는다.** 그러려면 창당 처리 건수(`rxmax`)를 화면이 들고 있어야
  하는데 그건 실측 중이고 내 도메인도 아니다 — **화면에 그 상수를 박는 순간 전제가 바뀌면
  조용히 틀린다.** 화면은 **"앞에 N건"까지만** 말한다.

⚠ **`cap` 의 값은 `rxmax` 실측에 종속이다. 의미는 확정, 값은 미정.**
~~**`cap` 은 서버의 큐 깊이(언제 `queue_full` 을 돌려주나)이지 화면 값이 아니다**~~
🔴 **이 정의는 틀렸다 — §5.27 참조.** `cap` 은 팀 전체에서 세 가지 뜻으로 쓰인다(ms·B·건수) — 화면은
`expires_ms` 를 **받아서 쓰므로** 이 대기에 안 걸린다(socket 이 자기 "값 나오기 전에 만들지
마라"를 `cap` 한정으로 정정했다).

#### 5.15.1 화면 쪽 구현 상태 (2026-08-17 · **주입으로 확인, 실제 서버 수신은 미확인**)

> 🔎 **이어지는 항목**(2026-08-17 19:5x): 이 표의 뒤를 §5.19(거절 코드 둘) · §5.20(타이머
> 재설정을 **시계로** 확인) · §5.21(그 측정에서 나온 하니스 함정)이 잇는다.
> 재현 도구는 `web/tools/queue-contract.mjs` 하나다(서버 없이 돈다).

`queued` 수신 처리를 넣었다. 서버는 아직 `queued` 를 안 보내므로 **주입으로 확인**했다
(데모 모드 · 트래픽 0):

| 경우 | 화면 |
|---|---|
| `ahead:2, expires_ms:4800` | `접수됨 · 전송 대기…` / `서버가 받았습니다 — 앞에 2건` · 타이머 재설정됨 |
| `ahead:0` | `… — 다음 차례입니다` |
| **`expires_ms` 없음** | 타이머를 **안 건다** · `(언제까지인지는 서버가 알려 주지 않았습니다)` |
| 그 뒤 `ack` | `예약 확정됨`(status `confirmed`) — **`queued` 를 안 거친 보통 경로와 동일** |

🔴 **`expires_ms` 가 없을 때 숫자를 지어내지 않는다**(루트 지시). 짐작한 상한으로 되돌리면
**지금 고치는 거짓 롤백이 다른 모양으로 돌아온다.** 대신 타이머를 안 걸고 "모른다"를 적는다 —
계약상 `queued` 뒤에는 반드시 `ack`/`error` 가 오므로 그때 끝나고, 그 보장이 깨지면 타일이
대기로 남는데 **그건 조용한 거짓말보다 낫다.**

⚠ **마지막 줄("보통 경로와 동일")은 비교로 확인한 것이다** — `queued` 를 거친 rid 와 안 거친
rid 를 같은 화면에서 각각 `ack` 시켜 둘 다 `confirmed` 인 것을 봤다. **"안 깨졌겠지"로 넘기면
회귀를 못 본다.**

### 5.16 하행 아이들 1초 — **전역**이고 `canAct()` 하나에 걸린다 (사용자 지시 · 실측)

**값의 근거**: 하행은 **전송 슬롯 주기 1.2초** 안에서 서버 차례에만 나간다. **1초 아이들이면
슬롯당 최대 1건**이 되어 전송 구조와 맞는다. **주기보다 짧게 잡은 것은 의도**다 — 길게 잡으면
보낼 수 있는 슬롯을 비우게 되고, 짧게 잡아 큐가 한 칸 차는 편이 낫다(큐는 서버가 비운다).

**전역인 이유**: 사용자가 재현한 모양이 **서로 다른 자리를 연달아 누르는 것**이라 자리별로 걸면
10칸을 돌아가며 눌러 그대로 통과한다. 그리고 막는 대상이 자리가 아니라 **전선 하나**다 —
슬롯 주기는 자리마다 있는 것이 아니라 링크에 하나 있다.

**붙인 자리가 둘뿐인 것이 요점이다**:

| 무엇 | 어디 | 왜 거기 하나로 되나 |
|---|---|---|
| 차단 | `canAct()` | 타일·시뮬 버튼이 **전부 이것을 본다** → 한 줄로 전체가 걸린다 |
| 시작점 | `transport.send()` | 하행 세 경로(reserve·cancel·sendCommand)가 **전부 지나간다** → 새 경로가 생겨도 저절로 걸린다 |

⚠ **실제로 나간 경우에만 찍는다.** 전송 실패까지 아이들로 세면 연결이 끊긴 동안 누른 것 때문에
**복구 직후 1초를 못 누르게 된다.**

⚠ **조용히 무시하면 안 된다** — 안 먹혔다고 생각하면 **더 세게 누르고**, 그러면 막으려던 것을
화면이 만든다. 그래서 누르지 않아도 보이는 자리(칸 보조 문구)에 남은 시간을 넣는다.
그리고 아이들 문구를 **다른 차단 사유보다 먼저** 본다 — 이 상태는 **곧 풀린다**는 점에서
성격이 다른데 "연결이 없다"로 말하면 고장으로 읽혀 사용자가 엉뚱한 곳을 본다(§5.10 과 같은 형태).

```

18:5x 에 실측했다. ⚠ **나는 그 낡은 문장을 그대로 루트에 보고했다**(기동 보고) — 정정을

### 5.23 🔴 §1.2 의 보호는 **사용자가 운영 URL 을 직접 열면 지나간다** (실측 · socket 통보)

못 가른다.** 운영 로그를 읽을 때 **사람이 열어 둔 탭**을 후보로 두지 않으면, 설명 안 되는
세션 하나를 고장으로 쫓게 된다.

### 5.24 화면 타이머 발화 시각은 **`expires_ms + 6000`** 이다 — 시계로 확정 (실측)

```
B6  expires_ms=300  주입 → 실제 발화 **6362ms**   (기대 300+6000=6300)
B4  expires_ms=4800 주입 → 자체 6초를 넘겨 6500ms 뒤에도 여전히 queued
```

`node web/tools/queue-contract.mjs` · 27 pass / 0 fail · `file://` 데모 · 트래픽 0.

🔑 **여기서 파생되는 성질**: `expires_ms = deadline − now` 이고 `deadline = enqueue + cap` 이므로
**발화 시각은 마지막 `queued` 가 언제 왔든 `deadline + 6000` 으로 고정된다.** 서버가 단조 비증가를
공짜로 얻은 그 구조의 부산물이다 — 화면이 `queued` 를 몇 번 받든 절대 시각이 안 움직인다.

#### 5.24.1 ~~🔴 미해결 —~~ **해결됨. 격차는 900ms 가 아니라 3900ms 였다** (socket 확인 · REQ-0166 done)

> ✅ **socket 이 확인했다: 출발점은 이탈 기준이다. 겹침은 실재했다.**
> 그리고 **숫자가 더 나빠졌다** — socket 이 자기 6.9초를 **두 번 잘못 셌다**고 정정했다
> (틱 해상도 `3×200` 과 창 대기 상한이 `D_max`(2400)인 것을 빼먹었다). **최종 9900ms.**
> ```
> ack_budget = 3 × (ACK_TIMEOUT 1500 + 틱 200) + 2 × (D_max 2400) = 9900ms   ← 이탈 기준
> ```
> → 같은 기준으로 세우면 **화면 6000 대 서버 9900 = 3900ms 부족.** `cap`(큐 대기 예산)이
> 3900ms 보다 작으면 **큐를 탄 항목이 거의 다 겹친다** — 내가 "좁다"고 쓴 것은 **틀렸다.**
> **`cap` 값을 모르는 상태에서 폭을 좁다고 단정한 것이 잘못이다**(아래 §5.24.2).
> **해법은 §5.26 으로 구현했다.**

⚠ **아래는 확인 전에 쓴 내 계산이다. 방향은 맞았고 폭은 틀렸다** — 지우지 않는다.

socket 통보(2026-08-17, 서버가 `queued` 를 보내기 시작했다 · `docs/net/LEDGER.md` §8.23):

| socket 이 알려 준 것 (그쪽 실측·설계) | |
|---|---|
| `expires_ms` 가 재는 것은 **큐에서 나갈 때까지**다 | 최종 결말까지가 아니다(넣으면 내 `+6000` 과 **이중 계산**) |
| 재전송도 큐를 타서 **이탈 후 최악이 4.5초 → ≈6.9초** | `ACK_TIMEOUT_MS` 1500 + 창 대기 ≤1200, 3회 |

**①이 이탈 후 예산을 `expires_ms` 에서 뺐으므로 그 몫을 덮는 것은 내 `ACK_TIMEOUT`(6000) 하나다.
그런데 6000 < 6900.** `T_exit ≤ deadline` 이라 하면:

```
겹침 ⟺ T_exit + 6900 > deadline + 6000 ⟺ T_exit > deadline − 900
```

→ **큐가 자기 마감 직전 900ms 안에 빠져나간 항목에서만** 겹친다. 좁지만 실재하고
**하필 혼잡할 때** 걸린다. 🔑 **`cap` 값과 무관하다** — 900 은 `6900 − 6000` 에서만 나온다.

**겹치면**: 화면이 서버보다 900ms 먼저 롤백 → 재클릭 → **새 rid 로 큐에 한 건 더**
(`has_pending_for` 도 안 막는다, 그 pending 은 이미 풀렸다) = **REQ-0155 §5-(2) 증폭 고리 재발.**

⚠ **비교 규칙을 여기서 한 번 밟을 뻔했다**(CLAUDE.md). socket 은 `10.8초`(= `cap` 4800 **큐 대기** +
6000 **이탈 후**)와 `6.9초`(**이탈 후만**)를 비교해 "여유 3.9초"로 봤다. **출발점이 다르다.**
같은 기준(큐 이탈)으로 정렬하면 **6000 대 6900** 이다. **이름도 단위도 같아서 더 위험했다.**

🔴 **`ACK_TIMEOUT` 을 내가 올려서 막지 않았다** — §5.14 가 *"화면의 타임아웃은 서버가 준 상한에
묶는다. 화면이 짐작하지 않는다"* 다. 올리면 비큐 경로의 정상 타임아웃도 같이 늘어난다.

⚠ **`onQueueExpired` 문구는 겹침이 일어나는 바로 그 경우에 거짓이 된다** —
`"상한 시간 안에 장치로 보내지 못해"` 인데 실제로는 **보냈고** 장치가 ack 를 안 준 것이다
(§5.10 과 같은 계열). **REQ-0166 의 결정 뒤에 고친다** — 서버가 항상 먼저 답하게 되면 그 경우가
사라지므로 지금 고치면 검증 없는 변경이다.

### 5.25 서버가 보내는 `message` 보다 **화면의 `ERROR_TEXT[code]` 가 이긴다** (코드 판독 · 2075행)

```js
const text = ERROR_TEXT[code] || (typeof msg.message === 'string' ? msg.message : '오류가…');
```

→ **코드가 표에 있으면 서버 문구는 안 쓰인다.** 실례: `already_pending` 에 서버는
`"그 자리는 이미 처리 중입니다"` 를 보내는데(socket 통보) 화면에는 내 문구가 나간다.
socket 도 이 구조를 확인하고 **"내 message 는 폴백"** 으로 정리했다(REQ-0166).

**의도된 것이고 이유가 있다**: 문구는 화면 소유다 — 서버 문구는 **다음 행동**을 말하지 않는다.
`already_pending` 에 "다시 눌러라"를 안 넣은 것이 그 예다(또 거절될 뿐이고 그게 연타를 부른다).

⚠ **함정**: 그래서 **서버 문구를 고쳐도 화면은 안 바뀐다.** 표에 있는 코드의 문구를 바꾸려면
`ERROR_TEXT` 를 고쳐야 한다. 반대로 **표에 없는 코드는 서버 문구가 그대로 사용자에게 보인다** —
서버가 새 코드를 추가하면 화면은 조용히 서버 문구를 쓰게 된다(깨지지는 않는다 · §5.13 과 같은 성질).

### 5.26 확정된 계약 — 화면이 기다리는 전부는 **`expires_ms + ack_budget_ms`** (실측)

원본은 socket 의 `docs/net/DESIGN-server-slot-queue.md` §4-B. 값이 갈리면 원본이 이긴다.

```json
{"type":"queued","rid":"…","slot":"A1","ahead":2,"expires_ms":4800,"ack_budget_ms":9900}
```

| 구간 | 값 | 무엇을 덮나 |
|---|---|---|
| `expires_ms` | 서버가 준다 | **큐 이탈까지** (남은 지속시간 · 단조 비증가) |
| **`ack_budget_ms`** | 서버가 준다 | **이탈 후 결말까지** (재전송·창 대기 포함) |

**🔴 `ACK_TIMEOUT`(6000)은 이 산식에서 빠졌다.** 그것이 §5.24.1 의 3900ms 구멍이었다.

**실측**(`node web/tools/queue-contract.mjs` → **33 pass / 0 fail** · `file://` · 트래픽 0):

```
B6  expires_ms=300 + ack_budget_ms=500 → 실제 발화 821ms (기대 800)
    🔑 6000 이 아직 섞여 있으면 6800ms 가 된다 — 빠진 것이 이 한 줄로 증명된다
B1  deadlineAt − expiresAt = 9900 (준 값 그대로)
B7  expires_ms 만 오고 ack_budget_ms 가 없으면 → 타이머 안 걸고 "모른다"를 적는다
```

🔴 **한쪽만 온 경우에 `ACK_TIMEOUT` 으로 메우지 않는다.** 이유가 있다: 그 값을 **계산해서**
보내는 서버라면 항상 싣고, **안 싣는 서버는 큐가 없어 `queued` 를 아예 안 보낸다.**
→ `queued` 가 왔는데 이 값이 없으면 **모르는 판본**이라는 뜻이고, 그 자리에서 짐작한 상수를
쓰는 것이 정확히 §5.24.1 로 막은 실수다.

⚠ **`expiresAt` 과 `deadlineAt` 은 다른 값이다.** "모른다" 판정은 **`deadlineAt`** 으로 한다 —
이탈 시각만 알고 결말 상한을 모르면 **여전히 모르는 것**이다. 둘을 헷갈리면 모르는 것을
안다고 말한다(B7 이 그 케이스다).

#### 5.26.1 `onQueueExpired` 문구를 고쳤다 — 서버에는 **"큐에서 못 나가서 취소"라는 결말이 없다**

~~`"서버가 접수했지만 상한 시간 안에 장치로 보내지 못해 …"`~~ → **틀렸다.**
socket 확인: **서버는 큐 마감을 넘겼다고 항목을 버리지 않는다.** 마감은 `queue_full` 판정과
`expires_ms` 계산에만 쓴다(버리면 "버림"이 되고 어차피 다음 창에 나간다).

→ **그런 결말이 서버에 없으므로 화면이 그 원인을 말하면 무조건 거짓이다.** 이 타이머가 터지면
그건 **진짜로 답이 안 온 것**이고, 어느 구간에서 막혔는지는 화면이 모른다.
현재 문구: `"서버가 접수했지만 알려 준 상한 시간 안에 결과가 오지 않아 요청을 되돌렸습니다"`.

🔑 **미룬 판단이 옳았던 사례다.** §5.24.1 을 쓸 때 이 문구를 같이 고치려다 "결정 뒤에"로
미뤘는데, 그 사이에 **고칠 이유 자체가 바뀌었다**(겹침 때문 → 그런 결말이 없기 때문).
먼저 고쳤으면 맞는 문구를 틀린 이유로 적었을 것이다.

### 5.27 🔴 `cap` 은 **한 문서 안에서 두 가지, 팀 전체로 세 가지**다 (문서 판독)

| 어디 | 뜻 | 단위 |
|---|---|---|
| socket §4-B `deadline = enqueue_ms + cap` | 큐 대기 예산 | **ms** |
| socket §8 "값이 채워졌다 — `cap` · 채택 320B" · §1 "`cap` 은 건수가 아니라 바이트다" | 창당 전송 한도 | **B** |
| ~~내 원장 §5.15 "`cap` 은 서버의 **큐 깊이**"~~ | — | **틀렸다** |

**§5.15 의 정의를 정정한다** — 내가 "큐 깊이(언제 `queue_full` 을 돌려주나)"라고 적었는데
그건 셋 중 어느 것도 아니다. `queue_full` 문턱은 별개 값이고, `deadline` 에 들어가는 `cap` 은
시간이다. 원장 규칙 ②대로 지우지 않고 여기 남긴다.

⚠ **왜 위험한가**: `deadline = enqueue + cap` 에 **바이트 값(320)** 을 대입하면 마감이
**320ms** 가 된다 — 그럴싸한 숫자라서 안 걸린다. §5.24.1 의 겹침 폭도 이 값에 종속인데,
나는 그 값을 모르는 채 "좁다"고 썼고 그것이 틀렸다.

→ **규칙: `cap` 이라는 낱말을 단위 없이 인용하지 마라.** 시간·바이트·건수가 전부 `cap` 으로
불린다. CLAUDE.md 의 비교 규칙이 **한 이름 안에서** 걸린 사례다.

> ✅ **socket 이 고쳤다**(2026-08-17): 코드는 처음부터 이름이 갈려 있었다 —
> `DOWNQ_WAIT_CAP_MS`(ms · 4800) 대 `DOWN_BATCH_CAP_B`(B · 320). **섞인 것은 문서였다.**
> 🔑 그리고 그 애매함이 **내 원장에 틀린 항목을 만들었다**(§5.15 의 "큐 깊이"). 남의 문서의
> 모호함은 내 원장으로 번진다 — 옮겨 적을 때 단위를 확인하는 것이 그래서 값이 있다.

### 5.28 🔴 **서버가 `queued` 를 실제로 보낸다 — 브라우저 종단으로 확인** (실측 · 시연 구성)

지금까지 화면 쪽 계약 검증은 **전부 주입**이었다(§5.26). 그 칸이 채워졌다.
`node web/tools/queued-live.mjs --served 10500` → **17 pass / 0 fail** · 독립 3회 실행.
구성: 서버(`build=bf84e00`)가 **페이지도 WS 도** 준다 = 시연 구성 · `fake_arduino` 1.2초 주기.

```
서버가 보낸 프레임 : {"type":"queued","slot":"A2","ahead":0,"expires_ms":4800,"ack_budget_ms":9900}
화면 pending       : {"status":"queued","hasDeadline":true,"gap":9900}
그 뒤              : {"type":"ack","result":0}   → 타일 "예약됨 (입차 전) / 내 예약"
```

**`deadlineAt − expiresAt` = 서버가 보낸 `ack_budget_ms` 그대로다.** 화면이 짐작하지 않고
받아서 쓴다는 것이 실측으로 확인됐다(§5.26 의 산식이 실제 프레임에서도 성립).

~~⚠ **조건 — 이 값들은 flush 시점 (A) 전제다**~~ → **조건이 해제됐다. (A) 로 확정됐다.**
(socket·arduino 확인 · `docs/net/LEDGER.md` §8.23-(17)) **근거가 값이 아니라 구조다**:
장치 코드에 **"수신 창"이라는 상태가 없다** — 송신 창 하나뿐이고 수신은 `loop()` 마다 무조건이다.
🔑 **서버가 `S` 를 받은 순간 장치는 이미 송신을 끝낸 뒤다 — TCP 로 왔다는 것 자체가 증거다.**
→ 아래 간격에 조건을 붙이지 않아도 된다.

#### 5.28.1 🔴 `queued`→`ack` 간격은 **고정 한 슬롯이 아니다 — 위상에 따라 갈린다** (실측 3표본)

```
594ms · 982ms · 1030ms      n=3
(정의: queued 프레임 도착 → ack 프레임 도착 · 브라우저 시계 · fake_arduino 1.2초 주기)
```

socket 은 자기 실왕복에서 **1.206초**를 보고 *"정확히 한 슬롯"* 으로 적었다 — **`n=1` 이었고
그 사실이 안 적혀 있었다.** 내 `n=3` 이 갈리므로 **"다음 창까지 남은 시간"**(0~1200ms)이다.

> ✅ **socket 이 철회했다**(`docs/net/LEDGER.md` §8.23-(22) 취소선 · 커밋 `913b7e8`).
> **정의는 둘이 같았다 — 갈린 것은 해석이다.**
> 🔑 **구조가 강제하는 것은 값이 아니라 상한이다: `≤ 한 슬롯`은 참, `= 한 슬롯`은 거짓.**
> **상한을 값으로 바꿔 말한 것이 오류의 전부다.** 그리고 그 값이 *"구조가 강제한 값"* 으로
> 보고되어 **루트 문서에 "이 설계가 도는 증거"로 옮겨 적혔다** — 틀린 상수가 남의 문서로
> 전파되는 경로가 정확히 이 모양이다.
>
> ⚠ **그래서 표본 수를 반드시 적는다.** socket 이 `n=1` 을 안 적은 것이 이 사고의 입구였다.
> **분포를 말하려면 `n` 이 필요하고, `n` 없는 값은 상수로 읽힌다.**

**왜 원장에 남기나**: 이것을 상수로 굳히면 **화면이 "몇 초 걸린다"를 예측하려는 유혹**이 생기고,
그 예측은 위상에 따라 틀린다. §5.15 가 이미 `ahead` 로 시간을 환산하지 말라고 했는데 **같은
함정의 다른 입구**다. 🔑 **화면은 남은 시간을 짐작하지 않는다 — `expires_ms` 를 받아서 쓴다.**

### 5.29 §5.2 · §5.7 이 **실측으로 승격됐다** — 파일의 `last_frame_ts` 는 진짜로 얼어 있다

**서버는 고칠 것이 없다**(초당 쓰기를 되살리는 셈이라 더 나쁘다 · socket 동의).

### 5.30 🔴 하니스 결함 둘 — **둘 다 "제품 실패"로 위장했다** (실측)

e2e 를 이 인스턴스에 처음 돌렸을 때 34/36 이었고 **두 실패 다 내 하니스였다.** 고친 뒤 **36/36.**

**(1) 칸을 문구로 골랐다.**

cells.find(c => c.state.includes('빈자리')) || cells[0]      // 실제 문구는 '빈 자리' (공백)

`find` 가 **한 번도 안 맞았고** `|| cells[0]` 폴백이 그것을 가렸다. A1 이 우연히 빈 날에는
**36/0 으로 통과**해서 깨진 줄 몰랐다. A1 이 "사용 중"인 날 비로소 *"확인 대화상자가 안 뜬다"*

🔑 **문구는 바뀌고 동작은 계약이다.** 내가 이 세션에 문구를 여럿 고쳤으니 특히 그렇다.

포트에서 유도한 `~/parking-logs/…test+600.log` 가 맞았을 때조차, 서버가 `net/slotq-test-*.log`
로 쓰기 시작하자 깨졌다. 그리고 없는 파일이 **조용히 빈 배열**이 되어
`❌ 서버가 장치로 R 을 내보냈다 → 없음` 으로 나왔다 — **하니스 결함이 제품 판정으로 위장했다.**

→ 고친 형태 둘:
1. **경로를 항상 찍는다**(`· 서버 로그 = …`). §5.17 의 뿌리가 *"도구가 자기가 어디를 보는지
   말하지 않는다"* 였는데 **정작 그 한 줄이 없었다.**
2. **없으면 "제품 실패"가 아니라 "하니스 실패"라고 말한다.** 여전히 빨강이다 — "검사 못 했다"를
   초록으로 넘기면 분모가 사라진다. 달라진 것은 **누가 틀렸는지 문장이 말한다**는 것이다.

> 커밋이고 메시지도 무관하다**(루트가 `git add` 로 쓸어 담았다고 확인 · REQ-0172).
> **코드는 온전하지만 "왜"가 그 커밋에 없으므로 근거는 이 절이 유일한 기록이다.**

**전부 제품이 아니라 도구가 틀렸고, 셋 다 초록이나 엉뚱한 빨강으로 나왔다.**
→ **규칙: 하니스가 낸 빨강을 제품 판정으로 쓰기 전에 "도구가 본 것"을 먼저 확인한다.**
`❌` 하나가 나왔을 때 물을 첫 질문은 *"제품이 틀렸나"* 가 아니라 **"내가 맞는 데를 봤나"** 다.

### 5.31 §5.7 을 고쳤다 — 폴백은 이제 **침묵을 단정하지 않고 상한으로 말한다** (실측 전후)

`renderFrameAge()` 를 **파일 경로에만** 갈랐다(`snap.source === 'file'`).
검사: `node web/tools/fallback-age.mjs` — **고치기 전 5 pass / 6 fail → 고친 뒤 11 pass / 0 fail.**

**고치기 전**(§5.29 에서 실제로 관측한 모양을 주입: 기록 80초 묵음 · `ts == last_frame_ts`):

```
"1분 전 수신 · 기록 시점에 이미 0초 침묵"          ← 장치는 그때 1Hz 로 보내고 있었다
```

**고친 뒤**:

```
"⏱ 침묵 최대 1분 (상한 — 지금 보내고 있는지는 이 경로로 모릅니다) · 기록은 1분 전
 · 기록 시점에 이미 0초 침묵"
```

**무엇을 근거로 이 문구인가**: 폴백에서 화면이 아는 것은 **`침묵 ≤ now − last_frame_ts`** 뿐이고
**아래 경계는 0** 이다(장치가 방금 보냈어도 상태가 안 바뀌면 파일은 안 써진다 · §5.2).
그래서 상한이라고 적고 나머지는 모른다고 적는다 — §5.7 의 표 마지막 줄("지금 장치의 침묵 =
모른다")을 화면이 드디어 그대로 말한다.

**같이 고친 것 둘**:
- `online === false` 를 `"그 뒤로 장치 프레임 없음"`(지금에 대한 단정) → **`"기록 시점엔 오프라인"`**.
  **그 값도 같은 얼어붙은 기록에서 온다** — 하나만 고치면 다른 하나가 같은 거짓말을 계속한다.
- 경보 기호 `⚠` → **`⏱`**. **이 상태는 고장이 아니라 모르는 것**이고, 경보를 붙이면
  멀쩡한 장치에 경보가 뜬다 — 그게 고치려는 결함 자체다.

🔴 **WS 주 경로는 일부러 안 건드렸다.** 거기서는 값이 프레임마다 새로 만들어져 실시간이라
`"N 전 수신"` 이 **참**이고, 상한 문구로 바꾸면 **정확한 정보를 잃는다.**
`fallback-age.mjs` [3] 이 그 대조군이다 — WS 에 `상한` 이 **안** 붙는 것을 단언한다.
**"고치는 것"과 "번지게 하는 것"을 가르는 검사가 없으면 정확한 경로까지 흐려진다.**

⚠ **반대 방향(REQ-0067)을 되살리지 않았는지 확인했다.** REQ-0067 은 *"죽은 데이터를 살아있는
것처럼 보이지 않기"* 인데, 새 문구는 **살아 있다고 말하지 않는다 — 모른다고 말한다.**
그리고 화면이 오래된 값을 쓰고 있다는 신호는 **다른 축**이 담당한다(`silenceMs()` 는
`receivedAt` 기준 = 화면이 마지막으로 무언가를 받은 뒤 경과 · 칸마다 `⏱ N 전 값` 칩 + 흐린 격자).
🔑 **두 축이 다른 것을 잰다**: 하나는 *장치의 침묵*, 하나는 *화면 자료의 나이*.
이번 수정은 앞의 것만 건드렸다 — **이름이 비슷해서 섞기 쉬운 자리다.**

### 5.32 설계 개정 — **루트가 확정한 계약 항목** (2026-08-17 · 구현 전)

조사서는 `docs/web/ANALYSIS-redesign-impact-2026-08-17.md` 다. 그쪽은 **web 의 요구**이고,
아래는 그중 **루트가 확정으로 올린 것**만이다. **둘을 갈라 적는다 — 요구와 확정은 다르다.**

> ⚠ **상태 표기를 정확히 한다**: 아래는 **루트 확정**이고 **socket 의 구현 합의는 계획 REQ 에서
> 받는다.** 서버 쪽 형태(키 이름·전선 형식)는 **아직 아무것도 정해지지 않았다.**
> 값이 갈리면 그때 나온 원본이 이긴다(§5.15·§5.26 과 같은 규율).
> 🔑 **이 절이 필요한 이유**: 이 확정들은 **대화로만 왔다.** 원장에 옮기지 않으면
> 세션이 죽는 순간 없어진다 — 오늘 그 형태로 문맥을 잃은 일이 이미 있었다.

| # | 확정된 것 | 왜 (내가 낸 근거) |
|---|---|---|
| ① | **서버가 "맵 정의"를 상태와 별개로 준다** — 격자 · 칸 목록 · 칸마다 `kind` · 칸마다 모듈 목록 | **"없는 ID"의 뜻이 뒤집힌다.** 지금은 *데이터 없음*(점선)인데 자리가 유동이면 *존재하지 않음*이다. **화면에서 반대로 말해야 하는 두 가지를 지금 코드는 하나로만 안다** |
| ② | **조작 가능성을 모듈 단위로 판정한다** (그 모듈이 속한 장치가 사는가) | 단일 `device.online` 이면 **거짓 허용**이 생기고, 그 하행은 **닿지 않는 장치로 나가 큐·재전송까지 돈다** |
| ③ | **`known` 을 자리 단위 → 모듈 단위로 내린다** | 장치가 완전 독립이라 **"일부만 아는 상태"가 상시 정상**이다. 지금은 자리 하나 = 상태 하나 |
| ④ | **`kind: parking\|entrance\|exit`** | 사용자의 *"이름만 다르다"* 는 **구조에는 참, 화면 상태 어휘에는 거짓**이다 — 입구에 "예약됨"이 없다 |
| ⑤ | **맵 정의는 기존 `slots[]` 를 고치지 말고 별도 키로 추가한다** | §5.13 — 새 타입/새 키는 옛 화면이 조용히 무시해 안전하지만, **기존 항목의 뜻을 바꾸면 서버 배포가 그 순간 옛 화면을 깨뜨린다** |

**④의 정확한 표현**(루트 정정): 사용자 지시를 뒤집는 것이 아니다 —
**"동일한 것은 구조이고 다른 것은 상태 어휘"** 로 갈린다.

#### 5.32.1 아직 안 정해진 것 — **여기를 확정으로 읽지 마라**

- **자리 ID 와 격자 좌표를 가르는가** — 내 의견은 "가른다"(좌표를 ID 로 쓰면 자리를 옮길 때
  예약이 따라 움직인다). **미확정.**
- **모듈을 화면에 얼마나 보여 주나** — 칸 안에 다 · 눌러 펼치기 · 집계만. **사용자에게 물을 것**이고
  루트가 **다른 질문과 묶어서** 낸다(질문을 겹쳐 보내면 답이 섞인다).
- **미상 표시의 형태** — `⏱`(조용) 대 `⚠`(경보)를 갈라야 하고 **미상 모듈 집계 한 줄**이 후보.
  ⚠ **두 힘이 서로 민다**: 상시 상태라 조용해야 하지만 **너무 조용하면 REQ-0067**(모르는 것을
  아는 것처럼)로 돌아간다. **"조용하되 반드시 보여야 한다"** 가 요구다. **형태 미정.**
- **모듈 상태의 나이** — 장치가 N 대면 `last_frame_ts` 도 N 개다.
  **§5.31 의 상한 문구는 장치 하나를 전제한다** → 모듈 단위로 다시 풀어야 할 수 있다. **미정.**

#### 5.32.2 개정에도 **안 깨지는 것** — 다시 만들지 마라

루트가 계획서에 넣기로 한 목록이다(§4 조사서에 근거).

| 그대로 가는 것 | 왜 |
|---|---|
| WS/폴백 이중 경로 · `resolveWsPort` | 자리 구조와 무관 (§1.1·§1.2) |
| `queued` · `expires_ms` · `ack_budget_ms` 타이머 계약 | **rid 단위**다. 자리 수와 무관 (§5.26·§5.28) |
| **하행 아이들 1초** (`canAct()` · `transport.send()` 두 지점) | **전선 하나**에 걸린 것이라 자리가 늘어도 그대로 (§5.16) |
| 폴백 신선도 상한 문구 (§5.31) | 장치 축이다 — 단 위 "모듈 상태의 나이"가 열려 있다 |

🔑 **이 목록의 값은 "안 바뀐다"가 아니라 "왜 안 바뀌는지"다.** 아이들 1초가 살아남는 이유는
그것이 **자리가 아니라 전선**에 걸려 있기 때문이고, 그 근거가 없으면 다음 사람이 다시 본다.

### 5.33 표시 원칙 — **기호는 원인을, 강조는 영향을 나타낸다** (두 축을 섞지 마라)

REQ-0181 에서 나왔지만 **그 개정에 딸린 것이 아니라 이 화면의 표시 원칙**이라 원장에 둔다.
(개정 문맥과 상세는 `docs/web/DESIGN-module-state-2026-08-18.md` §2. **여기 복사하지 않는다.**)

| 축 | 무엇 | 값 |
|---|---|---|
| **기호축** | **원인** | `⏱` 모른다 · `⚠` 고장·차단 확정 · (없음) 정상 |
| **강조축** | **영향** | **조작을 막는가** — 막으면 눈에 띄게, 안 막으면 조용한 배경 |

**왜 이것이 원칙인가**: 두 요구가 서로 미는 자리가 반복해서 나온다 —
**상시 켜진 경고는 아무도 안 읽는다**(§3.1 이 배너를 정상에서 침묵시킨 이유) 대
**모르는 것을 아는 것처럼 보이면 안 된다**(REQ-0067). **한 축으로 풀려고 하면 둘 중 하나를
버리게 되고, 그때 나오는 답이 "적당히 조용하게" 같은 조정값이다.**

🔑 **두 축으로 갈라 두면 조정값이 필요 없다** — 강조축은 **`actionable`/`blocked_reason` 에서
파생으로 나오므로**(§5.32 ② · 서버가 계산) 화면이 아무것도 짐작하지 않고, **집계가 정상에서
저절로 침묵한다.** 미학 판단이 정의에서 나오는 결과로 내려온다.

**적용 이력**: §5.31(폴백 문구)에서 `⚠`→`⏱` 로 바꾼 것이 이 원칙의 첫 사례다 — 그때는
"고장이 아니라 모르는 것"이라는 **기호축만** 썼고, 강조축은 폴백이 드물어서 필요가 없었다.
**미상이 상시가 되는 구성에서 두 번째 축이 필요해졌다.**

⚠ **한계**: 지금은 **설계 원칙이고 실측이 아니다.** 사람이 이 구분을 실제로 읽어 내는지는
확인하지 않았다 — 시각 형태(점선·흐림·칩)는 표시량 확인 뒤에 정해지고, **그때 브라우저로 봐야
한다.** 원칙이 옳아도 형태가 그것을 전달하지 못할 수 있다.

### 5.34 🔴 **화면의 정상은 서버의 정상이다. 장치의 정상이 아니다** (소스 판독 · 확정)

화면의 입력은 **WS 스냅샷**과 **`data_log.json`** 둘뿐이고(§2.3 · 여전히 참) **둘 다 서버가
만든다.** → **화면은 장치가 겪은 것을 볼 통로가 없다.** 이것은 추정이 아니다:

- `arduino/.slotbuild/client/client.ino` 의 계수 출력이 **전부 `Serial.print`**(USB)다.
  `cksumng` 줄에 **장치 스스로 적어 뒀다**: *"체크섬 불일치(하행 프레임 파괴).
  **서버 계수로는 안 보이는 손실이다.**"*
- 전선의 S 프레임에는 그 계수가 **없다**(`docs/net/parking-protocol.md`):
  `S,<seq>,<occupied>,<reserved>,<uptime>,<devid>[,<override>],<cksum>`

**실증 사례**(루트 전달 · 창 B): 같은 구간을 **서버는 실패 0**, **장치는 `cksumng=5` ·
`ssovf=5` · `oow=304`** 로 봤다. **둘 다 맞다 — 다른 것을 세기 때문이다.**

🔴 **그래서 이 문장을 조심해야 한다: "화면이 정상이었으니 그 구간은 정상이었다."** 틀렸다.
화면이 본 것은 **서버가 아는 범위의 정상**이다. 오독을 막을 유일한 방법이 이 항목이다.

#### 5.34.1 센서에는 자가 치유가 있고 **액추에이터에는 없다** — 구조적 차이

| | 에코 | 결과 |
|---|---|---|
| 센서(`occupied`) · `reserved` | **매 슬롯 올라온다** | 틀리면 다음 프레임에 드러나고 **서버가 `C` 재하달로 치유**(실측 ≈1초 · `FINDING-link-blink-2026-08-17.md` §8) |
| **액추에이터**(안내등·유도등·차단봉) | 🔴 **없다**(프레임에 필드가 없고 REQ-0179 완료 기준에도 에코 항목이 없다) | **아무도 되짚지 않는다.** 하행 프레임은 실제로 파괴되는데(`cksumng=5`) 그것을 드러낼 값이 없다 |

**자가 치유가 액추에이터에 안 걸리는 이유도 구조적이다**: 그 기전은 *"장치의 값과 서버의 값이
다르다"* 를 비교하는 것인데 **비교할 값이 안 올라오면 비교가 없다.**

→ **화면 규율**: 에코가 없는 모듈은 **"켜짐"으로 그리지 않는다. "켜라고 보냈음"까지만** 말한다.
§5.31 의 규율(모르는 것을 단정하지 않는다)과 같고, **이름을 붙이면 "거짓 완료"** 다 —
루트가 채택한 **"거짓 허용"의 사촌**이다(그쪽은 못 갈 명령을 보내는 것, 이쪽은 안 된 것을
됐다고 말하는 것). **시연에서 안내등이 안 켜졌는데 화면은 켜졌다고 하는 모양이다.**

⚠ **계약 판정 대기**: REQ-0184 로 socket 에 올렸다 — (가) 전체 에코 · (나) `ack` 만 ·
(다) 일부 모듈만. **어느 쪽이든 괜찮고 계약에 적히기만 하면 된다.** 안 적히면 다음 사람이
*"당연히 에코가 있겠지"* 로 읽고 화면이 단정한다.

### 5.35 🔴 `ack_timeout` 이 **드물게 뜨는 것은 알려진 상태다 — 새 고장으로 쫓지 마라**

socket 창 B 실측(2026-08-18 · REQ-0183 회신): **장치의 주기 디버그 출력(`[CNT]`)이 60초마다
하행 한 건을 깨뜨린다.** 서버가 전송 창을 지켜도 **장치 내부에서 일어나므로 막을 수 없다.**
재전송이 대부분 살려낸다(같은 창에서 **ACK 실패 0** · 300/300 완주 ×2회).

→ **화면에 `error/ack_timeout` 이 아주 드물게(≈60초에 1건 이하) 뜰 수 있다.**

**왜 원장에 넣나**: 이것은 **회귀가 아니다.** 안 적어 두면 다음 사람이 드물게 뜨는 그 한 건을
새 고장으로 쫓는다 — 오늘 이 팀이 그 형태로 여러 번 시간을 썼다(없는 고장 추적).

⚠ **문구는 고칠 것이 없다.** `ERROR_TEXT.ack_timeout` = `"장치가 응답하지 않았습니다"` 이고
**실제로 장치가 ack 를 못 준 것**이므로 거짓이 아니다. §5.31 과 달리 여기서는 화면이 단정해도
맞는다 — **서버가 재전송을 소진한 뒤 준 사유**이기 때문이다(경우 C 실측 · `FINDING` §8.1 C2).

🔑 **구분해 둘 것**: 이 `ack_timeout` 은 **서버가 준 사유**이고, 화면의 **자체 타임아웃**은
다른 사건이다(`onSelfTimeout` — 서버가 아무 말도 안 했을 때). 로그·보고에서 섞으면 원인을 못 가른다.
