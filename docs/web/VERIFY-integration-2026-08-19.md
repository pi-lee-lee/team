**대상**: 장치 인스턴스 `9900` · 서버 `a3cbf40`(`a3cbf40-1787084177650`) · 화면 `조별과제샘플/index.html`

## 1. 무엇을 검증했나 — ①~⑥

| # | 항목 | 결과 | 근거 |
|---|---|---|---|
| ① | `map`·`state` 봉투 키가 내 가정과 같은가 | ✅ | `map`: `epoch·grid·srv_id·type·zones` · `zone`: `cells·id·kind·modules` · `state.zone`: `actions·completion·id·modules·occupied·reserved` · `module`: `devid·idx·kind·name` / 상태쪽 `devid·name·value·known` |
| ② | `srv_id`·`epoch` 이 두 봉투에서 일치하는가 | ✅ | 같은 `srv_id`·`epoch 2`. 세계 변경(재기동) 시 재청 경로도 실제로 밟혔다 |
| ③ | 옛 `slots[]` 와 새 `state` 가 같은 말을 하는가 | ✅ | 10자리 대조 · 차이 0 |
| ④ | 모듈 상태 키 | ✅ | `value:null`·`known:false` 를 **실물에서** 확인 — "안 오는 것"과 "없다고 오는 것"이 갈린다 |
| ⑤ | 예약·취소가 전선까지 나가는가 | ✅ | `{type:"reserve",slot:"A1",user_id,rid}` → **`queued` → `ack`** · 취소 왕복 완료 |
| ⑥ | 거절 코드가 구성·고장·일시를 갈라 주는가 | ✅ | 한 창에서 **세 코드 전부** 관측(§3) |

### 점유 — 층을 갈라 적는다

```
"화면이 서버 값을 그대로 그린다"   ← 내가 확인: 주차 10자리 요약 문구 == 전선 (occupied,reserved), 불일치 0
"서버 값이 장치 비트와 맞다"       ← socket 이 확인: 장치 hex 0x182 → A2·A3·B4
```
🔴 **둘 다 있어야 합쳐서 "점유가 옳다"가 된다.** 어느 한쪽만으로 그 문장을 쓰면
확인하지 않은 것을 확인했다고 적는 것이다.
⚠ **수정 전에는 서버가 `A1` 하나로 읽었다** — 폭 검사·체크섬이 **다 통과하는 동안** 값이 틀렸다.

## 3. ⑥ 상세 — 세 코드를 한 창에서 봤다

```
20:19:17.092  node_unregistered  ← 14개 조작 전부(12자리) · 재접속 직후 등록 중
그 순간 화면 : 배너 보임 · "⏱ 12자리는 지금 조작 판정을 할 수 없습니다 (A1 … X1)
                          — 12자리는 필요한 장치의 상태를 모릅니다"
              잠긴 버튼 14 · 기호 ["⏱"]
5장 종합    : node_offline 20 · node_unregistered 14 · module_absent 16
```

**분류(원장 §5.59)**: `node_offline`·`node_unregistered` → `unknown`(⏱ · 배너가 센다) ·
`module_absent` → `fault`(⚠ · 배너는 침묵).

🔑 **관측된 우선순위가 옳다**: 노드가 없을 때도 차단봉 자리(E1·X1)는 `node_offline` 이 아니라
`module_absent` 로 왔다 — **그 자리는 모듈이 아예 결속되지 않았으므로 더 강한 진술이 맞다.**

### 어떻게 잡았나 — 순서를 뒤집었다

등록 창이 **1초**여서(`접속` → `등록 완료`) `live-map.mjs` 로는 **다섯 회차 전부 놓쳤다.**
붙는 데 그보다 오래 걸리기 때문이다. 그래서 **먼저 붙어 기록을 켜고 기다리는 도구**를 만들고,
socket 에 세션 절단을 요청했다(`REQ-0230`).

> **잴 창이 짧은 것은 "나중에 재기"가 아니라 "그 순간 표본 뜨기"다.**

⚠ **못 잡았을 때 이 도구는 "없다"가 아니라 "미측정"이라고 말한다** — 코드가 안 온 것과
내가 그 창에 없던 것은 다른 사실이고, 전자는 **서버 로그만 답할 수 있다.**

## 4. 관측에 섞일 수 있는 축 — 보고에 남긴다

- 🔴 **150ms 티커가 도는 중이다.** 하행을 보낸 뒤 1초 동안 격자가 초당 일곱 번 다시 그려진다.
  ⑥ 측정은 **순수 읽기**(클릭·하행 없음)라 이 축이 안 돌았지만, **앞으로 조작이 섞인 창에서는
  프레임·렌더 수가 늘어 보인다.**
- ⚠ `get_map` 상한이 **연결별**로 바뀌었다(socket). 하니스가 회차마다 새로 붙으므로 **전역이었을 때는
  내가 그 거절을 맞을 수 있었고**, 그게 *"화면이 지도를 못 받는다"* 로 보였을 것이다.
- ⚠ 빈 지형이면 서버가 `map` 을 **안 보낸다**(socket). 내 쪽은 `mapUsable()` 이 거짓이 되어
  **옛 격자로 물러난다 — 0개로 그리지 않는다.**

## 5. 남은 미측정 — ①~⑥ 밖

| 무엇 | 왜 못 쟀나 | 언제 열리나 |
|---|---|---|
| `V` 접미(가상 모듈) 표시 | `OBV` 가 오는 실기 자료가 없다 | arduino 굽기 직후 |
| 차단봉 조작(`open_gate`/`close_gate`)이 전선을 지나 장치까지 | 가상 모듈이 없어 `actions` 가 안 열린다 | 같음 |

**그리고 결정이 안 된 것 하나**: `module_absent`(영구·구성 문제)를 알릴 자리가 배너에 없다.
버튼에만 ⚠ 로 뜬다. 조용한 한 줄이 필요한지는 **가상 모듈이 채워진 뒤 흔한 상태인지 보고 정한다**(루트).

## 6. 이 검증에서 배운 것 (원장에 올린 것 요약)

- **§5.43** `GET /index.html → 200` 은 "내 코드가 서빙된다"가 아니다 — **판본 지표를 보고 멈춘다.**
  이 가드가 **두 번** 거짓 결과를 막았다.
- **§5.47 / §5.56** 검사는 **결과를 박지 말고 규칙을 단언한다.** 다만 **규칙이 바뀌면 규칙 검사도 바뀐다.**
- **§5.50** 층을 갈라 적는다 — 합쳐서 참이 되는 것은 두 확인이 다 있을 때뿐이다.
- **§5.51** **주석에 적힌 전제는 코드가 지켜 주지 않는다.**
- **§5.52** **판정자가 둘이면 "열려 보이는데 거부되는" 창이 반드시 생긴다.**
- **§5.55** **빈도를 올리는 변경은 있던 결함을 증폭해서 드러낸다.**
- **§5.57 / §5.60** 시간에 걸린 것은 나중에 확인할 수 없고, **"그 순간"은 사건의 신호로 정의해야 한다.**
- **§5.59** **분류는 그 상태가 광고대로 행동할 때가 아니라 붙어 있을 때를 기준으로 고른다.**
