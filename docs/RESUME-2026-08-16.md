## 4. 🔴 다음 세션이 모르면 사고가 나는 것 넷

1. **운영 서버(pid 75781)는 검증된 수정들 없이 돌고 있다** — 그리고 **이제 그 사실이 안 보인다.**
   예전에는 소스가 dirty 라 눈에 띄었는데 지금은 **동결 대상이 전부 깨끗하게 커밋돼 있다.**
   누가 평범하게 빌드·배포하면 A 창 한가운데로 들어간다.
   → **기계 잠금을 걸어 뒀다: `chmod a-w ~/parking-bin/srv_parking`** (지금 `-r-xr-xr-x`).
     덮어쓰기가 EACCES 로 실패한다. 도는 프로세스는 inode 를 쥐고 있어 영향 없다.
     **A 가 끝나면 루트가 푼다.** 잠금이 못 막는 것은 `mv` 덮기와 `kill 75781` 둘 —
     그 둘은 규칙으로만 막힌다.
2. **`arduino/test/run.sh`(옛 종합 회귀)는 낡아서 못 쓴다.** 수정 전 판본도 62/138 로 떨어진다.
   펌웨어 회귀가 아니라 하네스가 접속 사다리를 못 따라가는 것이다.
   **그 결과를 회귀 판정 근거로 인용하지 마라.** 대신 `arduino/test/run_stage1.sh`(28 PASS).
3. **지금 칩은 EspLink 가 아니라 `조별과제샘플/client.ino`(커밋 `fa52a51`) 계열**이다.
   `W` 프레임과 `server_wire.h` 디코더는 이 칩에 없다. 하행은 `R·C·T·M` 만 받는다.
4. **커밋 제목으로 "무엇이 언제 들어갔나"를 읽으면 틀린다.** 예: `5e0b05c` "단계 C 조각 1·2" 는

## 5. 서버 리팩터링 — 이름 체계와 현재 위치

**글자(A·B·C·D)를 더 쓰지 마라.** REQ-0096 의 A·B·C 와 `plan-windows-and-mapping.md` §5.7 의
A~D 가 이미 섞여 사고가 났다. 서술형 이름으로 간다.

| 이름 | 내용 | 상태 |
|---|---|---|
| **이음매 1 — 아두이노 상행** | `DeviceEvent` 6종 이관 (= 옛 "단계 C") | **4/6 · 하행 대기** |
| **이음매 2 — 아두이노 하행** | `DeviceCommand`/`CMD_*`. `dispatch`·재전송·ACK 대기가 딸려온다 | 미착수 |
| **이음매 3 — 폰** | `on_phone_line()` 의 파싱과 도메인 호출 분리 | 미착수 |

**이음매 1 의 상한이 6/6 이 아니라 4/6 인 이유** — 막힌 것이 아니라 구조가 그렇다:
남은 `DEV_CONNECT`(932) · `DEV_SENSORS`(1598·1637-1642)는 도메인 응답이
`resync_reservations` → `dispatch('R'/'C')` 로 **전선에 하행을 쏜다.** 이벤트로 미루면
송신 순서가 뒤집힌다(`→ARD R` 이 첫 `←ARD S` 보다 먼저인 것이 실측 기준선이다).
단계 계약이 "구조만 바꾸고 동작은 안 바꾼다"이므로 둘은 **이음매 2 에서 함께** 푼다.

⚠ `DEV_ACK` 는 **"완료"가 아니라 "무회귀 확인 · 격리 미확인"** 이다. 예약 왕복이 되는 것은
drain 이 돌았다는 증명이 아니다 — 장치가 상태 변경 즉시 S 를 보내서 ACK 가 만든 스냅샷과
S 가 만든 스냅샷이 안 갈린다. 가르려면 상태를 안 바꾸는 `T` 프레임 ACK 경로가 필요하다.

## 7. A 창이 끝나면 (약 01:53) — 순서

1. **monitor** — A 8시간분 판정(λ·기전 갈래·`busy` 런 분포). 이 값이 다음 단계의 기준선이다.
2. **전원 가설 확인** — 판정이 전원을 지목하면 **보드 구성 확인이 플래싱보다 먼저다.**
   리셋이 전원이면 펌웨어를 구워도 안 고쳐지고, 구운 뒤에 보면 두 변경이 섞여 못 가른다.
3. **socket** — 미배포 변경 배포. 루트가 `chmod` 잠금 해제 → **커밋 먼저**(`build=` 가 깨끗한
   해시여야 한다) → SIGTERM → 새 인스턴스 → 세 포트·실왕복 → monitor 에 시각 통보.
4. **arduino** — 플래싱. 굽기 전 루트 통보 → `INTERVENTIONS.md` 기록 → monitor 에 포트 통보 →
   굽고 hex 대조 → 결과 보고. 그 뒤 같은 규칙으로 재계수(B 팔도 8시간).

**3 과 4 를 같은 창에 하지 마라.** 둘 다 관측 경계를 만든다 — 섞으면 어느 쪽 효과인지 못 가른다.
