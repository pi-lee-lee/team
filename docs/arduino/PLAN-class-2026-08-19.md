# 펌웨어 2단계(은닉) 분해안 — **착수 전 검토용** (REQ-0275)

> 사용자: *"아두이노도 리팩토링 해야겠는데? 서버랑 동일한 리팩토링을 했다."*
> 🔴 **아직 아무것도 안 만졌다.** 루트 승인 뒤 착수한다.

## 0. 🔴 먼저 — **AVR 에서만 생기는 위험 하나를 재고 시작해야 한다**

서버에는 없던 것이다. **`static` 전역을 클래스 멤버로 옮기면 접근 방식이 바뀐다:**
```
지금  static 전역     → 절대 주소 접근 (`lds`/`sts`, 2워드)
뒤    클래스 멤버      → `this` 기준 간접 (`ldd`/`std` + Z 레지스터 세팅)
```
**단일 인스턴스면 컴파일러가 `this` 를 상수로 접어 같은 코드를 낼 수도 있고, 아닐 수도 있다.**
🔴 **이건 판독으로 못 정한다. 재야 한다.**
> ### **그래서 1단계를 *가장 작은 덩어리* 로 잡고 플래시·RAM 증분을 먼저 값으로 본다.**
> ### **증분이 크면 그 자리에서 분해안을 줄인다** — 전부 만들어 놓고 되돌리지 않는다.

⚠ **REQ 가 "hex 차이 0 을 목표로 삼지 마라"고 한 것은 맞다.** 다만 **증분은 판별자다** —
`0` 을 노리는 게 아니라 **얼마나 늘었는지를 매 단계 보고**한다.

## 2. 목표 — `setup()`/`loop()` 를 **시그니처로** 제시한다

> 🔴 **사용자 확정**: *"ino 기본 구조는 `setup()` `loop()` 이다. **이 구조를 유지**하고
> 나머지는 클래스로 작성하여 **해당 구조 내에서 클래스 생성과 멤버 함수 호출 방식**으로
> 흐름이 보이는 구조로 작성하는 것이다."*
> → **`setup()`/`loop()` 를 없애거나 감싸지 않는다. 그 안이 조립 코드가 된다.**
> 🔑 **`loop()` 가 서버의 `serveOneTick()` 자리다** — 한 박자가 여기 보여야 한다.

```cpp
// ── 전역은 셋뿐. 전부 값(포인터·new 없음) ─────────────────────────────
ParkingNode  node;                    // 자리 · 센서 소스 · 오버라이드 · 시뮬 · 모듈 표
EspLink      link;                    // 🔒 잠금 영역의 **파사드만**. 내부는 그대로
NodeSession  sess(node, link);        // 프레임 · ACK · 슬롯 규율 · 계수

void setup() {
  Serial.begin(115200);
  link.begin();                       // ← espInit()
  node.begin();                       // ← 핀 모드 · 시뮬 초기값 · 슬롯 위상 원점
  sess.begin();                       // ← 등록 예약 · 계수 초기화 · 배너
}

void loop() {
  const uint32_t now = millis();
  link.tick(now);                     // ← espReset + espRead + drainPending
  node.readSensors();                 // ← sensorTick
  sess.tick(now);                     // ← statusTick + cntTick (+ diag/ram)
}
```
### `loop()` 의 크기 — 판별자는 줄 수가 아니다

```
호출자가 **바꿀 수 있는 것**  → `loop()` 에 보인다 (순서·무엇을 도는가)
호출자가 **못 바꾸는 것**      → 멤버 안에 감춘다 (내부 절차·타이밍)
```
⚠ **열 줄이 되면 흐름이 아니라 절차다.** ⚠ **세 줄로 줄이려고 *선택* 까지 감추지 마라.**
🔑 **지금 `loop()` 도 이미 8줄이라 "짧아지는 것"이 목표가 아니다.**
**목표는 *무엇이 무엇을 소유하는가* 가 보이는 것**이다 — 지금은 8개 자유 함수가 104개 전역을
공유하고, **누가 무엇을 바꾸는지 서명에 안 나온다.**

## 🔴 4-b. **사전 등록 — 증분이 얼마면 계획을 줄이는가** (재기 *전에* 적는다)

**외삽 근거**: 클래스로 옮길 총량 ≈ **1,566줄**(ParkingNode 546 + AckQueue 120 + FrameCodec 300 + NodeSession 600).
**`AckQueue` 120줄 = 그 7.7%.** 그러므로 **전체 예상 증분 ≈ 파일럿 증분 × 13.**

```
✅ 플래시 **≤ +48B**     → 계획 그대로 5단계  (외삽 ~620B · 여유 5,936B 의 10%)
⚠ **+49 ~ +150B**       → **4단계로 줄인다** — `NodeSession`(600줄, 가장 큼)을 뺀다
                            (외삽 ~1,950B 까지 갈 수 있어 3분의 1을 먹는다)
🔴 **> +150B**          → **중단하고 루트에 재논의.** 외삽 2KB 이상은 이 보드에서 살 값이 아니다
🔴 RAM **> +16B**       → 그 자체로 재논의 (참조 멤버 몇 개로는 안 나오는 수다 —
                            나오면 컴파일러가 `this` 를 못 접고 있다는 뜻)
```
⚠ **이 표는 결과를 보기 전에 적었다.** 보고 나서 고치면 사전 등록이 아니다.
🔑 **파일럿의 값은 "된다/안 된다"가 아니라 *남은 계획의 크기를 정하는 수* 다**(루트).

## ✅ 4-c. **1단계 결과 — 사전 등록 표에 그대로 대입한다** (2026-08-19)

```
플래시 26,454 → **26,530**  = **+76B**
RAM    1,199 → **1,199**    = **+0B**   ✅ 예상대로(같은 저장소 · NSDMI 없음 · 참조 멤버 0개)
회귀   **241 PASS / 0 FAIL**
외삽   +76 × 13 ≈ **988B**
```
> ### **판정: `⚠ +49~150B` 구간 → 계획을 *4단계로 줄인다*. `NodeSession`(600줄)을 뺀다.**
**사전 등록한 규칙 그대로다.** 남은 3단계 외삽 ≈ 76 × (966/120) ≈ **612B**.

### ⚠ 한 가지 관찰 — **그러나 이것으로 판정을 뒤집지 않는다**

`AckQueue` 는 **작은 배열을 도는 조밀한 루프**라 `this` 간접의 **최악에 가까울 수 있다.**
`ParkingNode`·`FrameCodec` 은 줄당 비용이 더 쌀 가능성이 있다.
> ### 🔴 **그래도 지금 규칙을 바꾸지 않는다.** 숫자를 보고 해석을 고치면 사전 등록이 무의미해진다.
✅ **대신 2단계에서 *줄당 비용* 을 다시 잰다.** 그것이 새 근거이고, **그때 루트와 함께** 재논의한다.
**혼자 되돌리지 않는다.**

### `+76B` 이 어디서 왔나 (추정 · 확정 아님)

`this` 기준 간접(`ldd`/`std` + Z 세팅)이 배열 인덱싱마다 붙는 것으로 **추정**한다.
⚠ **역어셈블로 확인하지 않았다.** 확인이 필요하면 2단계 전에 한다 — 지금은 **판정에 필요 없다**
(판정은 증분 값 하나로 정해져 있고, 원인은 계획 축소 여부를 안 바꾼다).

## 🔴 4-d. **2단계 사전 등록 — 기준값을 재기 전에 박는다**

```

```

### 🔴 `NodeSession` — **"다음에 한다"가 아니라 "예산 때문에 뺐다"다**

§"아직 안 했다와 안 하기로 했다를 구분해라"(§37.1) 를 여기에도 적용한다.
```
상태 : **예산 때문에 뺐다**(외삽 988B 가 여유 5,936B 의 17%)
재개 조건 : ✅ 2단계 줄당 비용이 **0.45 B/줄 미만**으로 나오고, 루트가 동의하면 다시 연다
```
