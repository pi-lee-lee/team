## D8 · ㉠ `readSensors()` 를 슬롯 기반으로 — **조건이 둘이다**

**무엇**: `readSensors()` 가 지금 **매 `loop()`** 돈다. 전송이 1.2초마다인데 읽기를 매 루프
하는 것 자체가 낭비이고, **블로킹 센서가 있으면 그 낭비가 곧 위험이 된다.**

```
              매 루프      ㉠(슬롯 기반)
초음파 1개     3.4%        0.58%
초음파 3개    10.4%        1.7%
초음파 8개    27.8%        4.6%   · UART 유입 53B → **6.7B**
🔑 ㉠ 은 **N 에 무관하다**(슬롯당 N회를 1200ms 에 한 번). 매 루프는 **N 배로 는다**
```

### 되살리는 조건 — **둘 중 하나라도 참이면 착수한다**

```
① `ssovf` 가 실물에서 오른다                          ← 증상
🔴 ② **블로킹 읽기 센서가 2개 이상 등록된다**          ← 예측
```

### ⚠ ②를 왜 증상 대신 예측으로 적었나 — 우리 규칙의 **예외**다

우리는 *"방아쇠는 증상으로 적어라"* 를 쓴다. **여기는 예외다:**
```
`ssovf` 가 오르는 순간은 **이미 하행 바이트를 잃은 뒤**다. 되돌릴 수 없다
→ 🔑 **되돌릴 수 없는 증상은 예측으로 막는다**
```
**그리고 예측의 근거가 실측이다** — 위 표의 1개 줄이 시험 [45] 실측이고 나머지는 선형이다.
⚠ 근거가 추정이면 이 예외를 쓰지 마라. **되돌릴 수 없다는 것만으로는 부족하다.**

### 🔴 착수할 때 확인할 것 (축이 하나 는다)

```
`occMask` 갱신 시점이 바뀐다 → 주입(`T`)·에코와 상호작용
  `ovrActive` 는 서버가 주니 매 루프 갱신이고 `occMask` 만 슬롯 단위가 된다
  → **두 시점이 갈리면 `tmask` 판정이 흔들리나** 를 봐야 한다
`Session.h:26` 의 변화 감지(`changed`)가 그 순서에 의존하는지
🔑 읽기를 **송신 직전**에 둔다 — 읽고 바로 보내야 최신 값이 나간다
```

### 🔴 그리고 ②를 **장치가 스스로 판정할 수 없다**

루트가 *"블로킹 센서가 2개 이상이면 부팅에 `[CFG] ⚠` 한 줄"* 을 제안했다.
**장치는 그것을 알 수 없다** — 함수 포인터만 있고 그 함수가 블로킹하는지 모른다.
`.slow()` 같은 표시를 기여자에게 요구하면 **배울 것이 하나 늘어난다**(지금 없애려는 것이다).

✅ **답은 선언이 아니라 실측이다**:
```c
const uint32_t t0 = micros(); readSensors(); const uint32_t dt = micros() - t0;
if (dt > <문턱>) { if (sensSlow < 65535) sensSlow++; }   // [CNT] 에 싣는다
```
🔑 **함수가 블로킹하는지를 재서 안다. 기여자는 아무것도 안 배운다.**
그리고 그 계수가 `[CNT]` 에 있으면 **monitor 가 본다** — 조용한 열화가 값이 된다.
⚠ 비용: `micros()` 두 번 + 비교. **이것을 ㉠ 과 같은 경계에 넣지 마라** —
계측은 축이 아니고(측정 대상에 안 닿는다) ㉠ 은 축이다.

### 🔴 D8 우선순위를 내렸다 (2026-08-20 · 사용자 값)

> 사용자: *"나중에 많이 쓰는 센서는 **적외선**"*

```
IR 디지털 ~4µs · IR 아날로그 ~104µs  →  초음파(6.96ms)보다 **70~1,700배 빠르다**
IR 8개 = 32µs = 예산의 **0.05%**   →  🔴 **예산 설계가 필요 없어진다**
```
> ### **예산 강제는 초음파를 4개 넘게 쓸 때만 값이 있다.**
🔑 그리고 **자리마다 초음파를 쓸 이유가 없다** — 거리가 필요 없는 자리는 IR·리드가 더 낫다.
**초음파는 "얼마나 가까운가"를 알아야 할 때만 쓴다.** `GUIDE.md` §4 표에 적었다.
⚠ **지금 초음파 둘이므로 `ssovf` 는 여전히 봐야 한다**(monitor 몫). 오르면 조건 ①이 참이 된다.

## D10 · 🔴 초음파가 "안 읽힌다" 를 가르는 진단 — **필요해지면 켠다**

타임아웃(6,960µs = 60cm)을 넘으면 `pulseIn` 이 `0` 을 돌려주므로
**"배선이 없다"와 "물체가 60cm 밖이다"가 같은 모양(`0`)이다.**

```c
#if DEBUG
  Serial.print(F("[US] B1 ")); Serial.println(us);   // 왕복 µs (0 = 타임아웃)
#endif
```
```
값이 나온다(0 이 아니다)  →  배선 OK. 문턱·거리 문제다
0 만 계속 나온다          →  🔴 Echo 핀에 신호가 없다 (배선·센서)
```
⚠ **타임아웃을 임시로 크게** 해야 이 판별이 성립한다(작으면 먼 반사도 0 이 된다).
🔴 **굽기가 필요하다.** 그래서 *"손을 댔는데 안 뜬다"* 가 확인된 뒤에만 한다.

### 되살리는 조건
```
"센서 앞에 손을 댔는데 그 자리 비트가 안 뜬다" 가 **확인되면**
⚠ 자극 부재(아무도 안 만졌다)와 섞지 마라 — 그건 미계측이고 굽기가 필요 없다
```

### ⚠ 2026-08-20 의 B1 건은 이 진단이 **필요 없었다** — 더 싼 판별이 있었다

```
사용자가 **핀을 바꿔** 판별했다 → **센서가 자리를 따라갔다** → 센서 불량
🔑 진단 코드를 넣고 굽는 것보다 **부품을 바꿔 보는 것이 싸다.** 굽기가 0회다
```
> ### **소프트웨어 판별을 설계하기 전에 "부품을 바꿔 볼 수 있나"를 물어라.**
**교체가 가능하면 그것이 항상 더 싸고 더 확실하다** — 우리 판별은 코드를 의심하는데,
**교체는 코드·핀·전원을 한꺼번에 배제한다.**
⚠ 그리고 그것은 **사람만 할 수 있다.** 그래서 이 판별을 우리가 먼저 떠올리지 못한다.

## D11 · 🔴 새 자리에서 `occ` 기준선이 `0` 이 아니면 — **선택지 둘. 값을 미리 계산해 뒀다**

`US_NEAR_CM = 60` 이라 **센서 앞 60cm 안에 벽·책상이 있으면 그 센서는 영구 점유**다.
⚠ **셋업 잡음이 아니다** — 새 자리에서 계속 참인 상태라 5분 안정 구간으로 안 사라진다.

**판정**: 붙은 뒤 **손 안 댄 상태**의 `occ` 를 서버 로그로 뜬다.
`0` → 그대로 쓸 수 있다 · `4`·`8`·`C` → 🔴 그 비트는 이 자리에서 못 쓴다.

### ㉠ 센서를 옮긴다 / 방향을 돌린다 — **굽기 0회**

```
🔑 사람이 한다. 우리 개입 0. **가장 싸다**
⚠ 다만 주차장 모형이면 센서 위치가 설계의 일부다 — 옮기면 그 자리를 안 재게 된다
```

### ㉡ `US_NEAR_CM` 을 줄인다 — **굽기 필요. 다만 예산 개선을 겸한다**

`US_TIMEOUT_US = NEAR_CM × 58 × 2` 이므로 **타임아웃이 따라 줄어든다**:

| `NEAR_CM` | 타임아웃 | 초음파 2개 연속 | 유입 / 64B | 슬롯당 누적 |
|---|---|---|---|---|
| **60** (지금) | 6,960 µs | 13.92 ms | 13.4 B | 83.5 ms (7.0 %) |
| 40 | 4,640 µs | 9.28 ms | 8.9 B | 55.7 ms (4.6 %) |
| **30** | 3,480 µs | 6.96 ms | 6.7 B | 41.8 ms (3.5 %) |
| 20 | 2,320 µs | 4.64 ms | 4.5 B | 27.8 ms (2.3 %) |

🔑 **30cm 로 줄이면 예산이 정확히 절반이 된다** — 문턱 축소가 성능 개선을 겸한다.
⚠ **대신 차가 30cm 안에 와야 검출된다.** 모형 규모에 달렸고 **그것은 사용자만 안다.**

### ❌ 안 권하는 것 — 자동 교정

```
부팅 때 빈 상태를 재서 기준으로 삼는다(auto-calibration)
🔑 자리를 옮겨도 자동으로 맞는다
🔴 그런데 **부팅 때 차가 있으면 그것을 "빈 것"으로 학습한다** — 조용히 반대로 동작한다
⚠ 그리고 코드가 는다. 사용자가 없애려는 방향이다(*"기여자는 아두이노 기본만"*)
```
> **틀렸을 때 조용한 쪽을 기본값으로 두지 마라** — §"기본값은 틀렸을 때 어느 쪽이 조용한가로 정한다".

### 🔑 판별 순서

```
① 기준선을 뜬다 → `0` 이면 **아무것도 안 한다**
② `0` 이 아니면 **어느 비트인가**를 본다 — `4`(B1) 만? `8`(A1) 만? 둘 다?
   → 한쪽만이면 ㉠(그 센서만 옮긴다)이 가장 싸다
③ 둘 다면 자리 자체가 좁다 → ㉡ 을 사용자에게 값과 함께 제안한다(위 표)
```
⚠ **②를 건너뛰고 ㉡ 로 가지 마라** — 한 센서 문제를 전체 문턱 변경으로 풀면 **굽기 하나에
검출 거리 축소라는 대가가 붙는다.** 그리고 그 대가는 우리가 판단할 수 없다.
