# 펌웨어 리팩터링 검토 — **①(무료)과 ②(굽기 필요)를 갈랐다** (REQ-0273)

> 사용자 지시: *"펌웨어쪽도 리팩토링할 작업이 있는지 검토해라"* ·
> *"**사용 코드 구조가 간단하게 나와야 함을 꼭 명시**해달라"* ·
> *"**복잡한 구조는 기본적으로 은닉화**하여 개발자에게는 **간단한 구조로 이용 가능**해야 한다."*

## 0. 🔑 판별자 — **`hex` 가 답한다**

```
① 연속 구역을 **원래 자리에 include**   → hex 0 → **굽기 불필요. 위험 0**
🔴 ② 모으기·쪼개기·함수 추가            → hex 바뀜 → **굽기 축이 하나 는다**
```
**모든 항목을 실제로 빌드해서 쟀다. 코드 판독으로 갈음한 것은 하나도 없다.**

## 1. ✅ ① — **이미 했다** (hex 차이 0 · 회귀 237 PASS)

```
Slots.h        243줄   자리·센서 소스(실물/시뮬)·수동 오버라이드·시뮬 한 걸음
AckQueue.h     110줄   rid 멱등 캐시 · ACK 보류 큐
Modules.h      270줄   모듈 표(자리 유동화의 단일 원천) · 가상 차단봉
EspLink_at.h   586줄   AT 응답 어휘 해석 · handleLine — **링크 계층**
────────────────────────────────────────────────
client.ino  2,980줄 → **1,775줄**  (1,209줄 이동)   hex **cmp exit=0**
```

### 🔑 `handleLine` 424줄에 대한 판단 — **쪼개는 게 아니라 옮기는 것이었다**

**속을 보니 거의 전부가 링크 계층이다**: 사다리 응답 처리 176줄 · `ALREADY CONNECT`/`CONNECT`/
`CLOSED` 분기 · 송신 오류 응답 · WIFI 줄. **슬롯·프레임 로직이 아니다.**
> ### **그래서 함수를 쪼개(②) 값을 얻는 대신, 구역째 `EspLink_at.h` 로 옮겨(①) 같은 격리를 공짜로 얻었다.**
⚠ **함수 자체는 아직 424줄이다.** 줄 수는 안 줄었고 **경계만 생겼다.** 그 사실을 숨기지 않는다.

## 2. 🔴 ② — **굽기가 필요하다. 다음 굽기에 묶어라**

### 2-A. `commitAck()` — **은닉. 값어치가 가장 크다** (실측 +6B)

```c
// 지금 (5곳 반복 · 순서를 호출부가 지켜야 한다)
cachePut(rid, s0, s1, result);
sendAck (rid, s0, s1, result);
// 뒤 (한 줄)
commitAck(rid, s0, s1, result);
```
**소스 주석이 그 위험을 이미 적고 있었다**: *"호출부가 `cachePut` 을 먼저 부르므로 …"*
> ### 🔴 **"이걸 부르기 전에 저걸 먼저"가 코드에 실재했다. 사용자가 없애라고 한 바로 그것이다.**
**빠뜨리면 캐시 없는 재전송이 *다른 답*을 받는다**(§4.2 멱등 파손) — **조용히 틀린다.**
**측정**: 26032 → **26038B (+6)** · hex 다름 → **②**.

### 2-B. 이미 대기 중인 것 (루트 목록)
```
ESP_RST_WIRED 0 → 1   · 배너 "10 slots" → 파생값   · 시뮬 지형 · 모의구분 제거
```

## 3. 🔴 **안 하겠다고 정한 것과 이유** — 다 하지 않는다

```
❌ handleLine 424줄을 함수로 쪼개기
   이유: 대부분이 링크 계층이라 **①로 격리가 이미 됐다.** 쪼개면 hex 가 바뀌어 굽기 축이 늘고,
        얻는 것은 "읽기 편함"뿐이다. **관측 창이 도는 지금 그 값은 비용보다 작다.**
        🔮 링크 계층을 손볼 REQ 가 따로 생기면 **그때 같은 경계에서** 한다.

❌ statusTick(133줄)·feedRxChar(100줄)·sendSlotBatch(95줄) 쪼개기
   이유: 셋 다 **슬롯 규율의 심장**이고 창 P/R 에서 확인된 거동이 여기 걸려 있다.
        §"묶는 것은 경계이고 줄이는 것은 축"에 따르면 **이건 축을 늘리는 쪽**이다.
        **검증된 것을 미관을 위해 건드리지 않는다.**

❌ 체크섬(39줄)·부팅 원인(46줄) 같은 작은 구역 추가 분리
   이유: **파일 수만 늘고 격리 이득이 없다.** 잠금 대상이 늘면 정상 작업이 더 자주 막힌다
        (§"금지의 범위는 그 금지가 막으려는 사고의 범위와 같아야 한다").

❌ 전역 상태를 구조체로 묶기
   이유: AVR 은 전역 직접 접근이 가장 싸다. 묶으면 **RAM·코드가 늘고**(지금 RAM 58% 사용)
        얻는 것은 이름뿐이다. **측정 없이 "깔끔함"을 위해 자원을 쓰지 않는다.**
```

## 4. 🔴 **은닉화 판정 — 사용자가 두 번 강조한 것**

**판정 기준**: *"헤더만 읽고 쓸 수 있는가"* · *"이걸 부르기 전에 저걸 먼저 가 없는가"*

| 자리 | 지금 | 판정 |
|---|---|---|
| **모듈 추가** | `Modules.h` 의 `MODULE_TABLE` 한 곳만 고친다 | ✅ **이미 은닉돼 있다** |
| **센서 배선** | `Slots.h` 의 `SLOT_PIN[]`·`SLOT_SRC_DEFAULT` 만 고친다. 절차가 주석에 4단계로 있다 | ✅ |
| **ACK 발행** | 🔴 `cachePut` → `sendAck` **순서를 호출부가 지켜야 한다** | 🔴 **2-A 로 고친다** |
| **링크 계층** | `EspLink_*.h` 다섯으로 격리됨. 슬롯 수정이 안 닿는다 | ✅ |
| **T 무장 선행** | `T,A` 를 먼저 보내야 주입이 먹는다 | ✅ **전선 규약이다**(내부 API 아님) — 대상 아님 |

> ### ⚠ **감출 것은 *복잡함* 이고 드러낼 것은 *상태* 다.**
> **계수기(`[CNT]`)·`[LADDER]`·`[TX]` 로그는 하나도 안 감쌌다.** 오늘 하루가 **그 관측 가능성 덕에**
> 세 번 구제됐다(축 오기재 · 세션 절단 귀속 · 결합유지 하한). **은닉의 대상이 아니다.**

## 5. ⚠ 이 작업에서 실제로 터진 것 — **자동 치환이 자기 코드를 먹었다**

`commitAck` 실험에서 **정의를 먼저 넣고 치환을 나중에** 했더니,
**새로 넣은 함수 본문이 내 치환 패턴에 걸려 자기 자신을 부르게 됐다:**
```c
static void commitAck(...) { commitAck(...); }   // 🔴 무한 재귀
```
**컴파일은 통과한다.** ACK 마다 스택이 터졌을 것이다.
> ### ★ **텍스트 치환으로 리팩터링할 때는 *치환 먼저, 삽입 나중*.**
> ### **그리고 생성된 파일을 눈으로 봐라 — 패치 스크립트를 읽어서는 안 잡힌다.**
🔑 **`hex` 대조 이전에 이걸 잡은 것은 `grep -A4` 로 생성물을 본 것**이다.
