# 새 분해안 — **`client.ino` 에 전역·`setup`·`loop` 만** (REQ-0275 개정)

> 사용자: *"리팩토링할 거면 **깔끔하게** 하자. `client.ino` 에는 **전역 변수와 `setup` `loop` 만
> 보이도록** 구성해 달라."*
> 🔴 **아직 아무것도 안 만졌다.** 승인 뒤 착수한다.

## 0. 🔑 이 안의 뼈대 — **이동과 클래스화를 따로 센다** (루트 지시)

```
① **이동**(헤더로 빼고 원래 자리에서 include)  → **비용 0.** 846줄로 이미 실증했다(hex 차이 0)
② **클래스화**                                  → **0.63 B/줄** (1단계 실측)
```
> ### **사용자 요구는 "`client.ino` 에 *보이는* 것"이다 — 그건 ①만으로 달성된다.**
> ### **②는 별개 축이고, 예산이 허락하므로 같이 하되 *따로 센다*.**

**단계마다**: `a)` 옮기고 **hex 0 을 값으로 증명** → `b)` 클래스화하고 **증분을 값으로 보고**.
🔑 **그러면 "옮기기"와 "고치기"가 한 커밋에 안 섞인다** — `espInit` 이 정확히 그것으로 물렸다(§19).

## 1. 왜 문턱을 다시 세우나 — **재해석이 아니라 새 입력이다**

```
❌ 재해석 : 같은 +76B 를 보고 "AckQueue 는 최악이니 괜찮다"   → **이건 금지다. 아침에 안 했다**
✅ 새 입력 : ① 사용자가 요구를 바꿨다  ② 여유가 **5,726B** 라는 새 측정이 들어왔다
```
```
전체 클래스화 외삽 ≈ 1,125B = 여유의 **20%**   (옛 문턱은 여유를 모르는 상태에서 세웠다)
```
> ### **사전 등록은 *결과* 앞에서 지키는 것이고, *입력* 이 바뀌면 다시 세우는 것이다.**

## 2. 목표 — `client.ino` 최종 모습

```cpp
#include "Config.h"  "Boot.h"  "Slots.h"  "Modules.h"  "Checksum.h"  "RxLine.h"
#include "EspLink_*.h"  "AckQueue.h"  "FrameCodec.h"  "Commands.h"  "Session.h"

ParkingNode node;  EspLink link;  NodeSession sess(node, link);   // 전역

void setup() { Serial.begin(115200); link.begin(); node.begin(); sess.begin(); }
void loop()  { const uint32_t now = millis();
               link.tick(now); node.readSensors(); sess.tick(now); }
```
**지금 `setup()` 이 1,672행 · `loop()` 가 1,782행. 앞의 1,671줄이 전부 나간다.**

## 4. 클래스화 범위 — **전부 하지 않는다** (②단계)

```
✅ 클래스로  ParkingNode(Slots+Modules 표) · FrameCodec · NodeSession · AckQueue(완료)
🔴 자유 함수로 남긴다  Checksum(순수) · Boot(1회) · Config(상수)
🔴 **손대지 않는다**   RxLine.h(704줄) · EspLink_*(1,577줄)
```
> ### **`RxLine.h` 는 옮기기만 하고 클래스화하지 않는다.**
> **`espRead` 와 한 몸으로 도는 링크 성질이고, 잠금의 목적은 파일이 아니라 그 성질이다**(§오늘).
🔴 **그리고 루트에게: 이동 뒤 `RxLine.h` 를 잠금 목록에 넣을지 판단해 달라.** 성질이 같다.

## 5. 단계와 판별자 — **재기 전에 적는다**

```
A. 이동 전부 (1,632줄)          판별자: 🔴 **hex 차이 0** · 회귀 241/241
                                 ⚠ 0 이 아니면 **멈추고 왜인지 보고**
B. ParkingNode  (Slots 266 + Modules 표 110)   판별자: 증분 · 줄당 비용 · 241/241
C. FrameCodec   (271줄)                        판별자: 증분 · 등록 143B·`D,E1,OB` 리터럴 시험
D. NodeSession  (172줄)                        판별자: 증분 · 굽고 나서 기준선 유지
```
**새 문턱(입력이 바뀌어 다시 세운다):**
```
✅ B~D 합계 **≤ 700B**(여유의 12%)  → 계획대로
⚠ 700~1,200B                        → D(NodeSession)를 뺀다
🔴 > 1,200B (여유의 21%)             → 멈추고 재논의
```

## 6. 🔴 안 하겠다고 정한 것

```
❌ RxLine·EspLink 클래스화 — 링크 성질. **옮기기만** 한다
❌ 계수기 은닉 — 감출 것은 복잡함이고 드러낼 것은 상태다
❌ 상수를 클래스로 — `Config.h` 의 `#define` 은 전역으로 보는 것이 사용자 요구에도 맞는다
❌ 18:00 이동 굽기에 싣기 — **망 이동과 축이 겹친다.** 이동 뒤 단독 경계
```
