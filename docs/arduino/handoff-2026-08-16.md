## 보존해야 할 핵심 결론 — DNS Fail 의 원인은 서버가 아니었다

지난 세션이 `avrdude` 로 **보드 플래시를 덤프해서** 실제로 구워진 문자열을 읽어 확인한 것:

```
AT+CIPSTART="TCP"," 192.168.35.21",9991      ← ★ IP 앞에 공백 하나
```

`SERVER_IP` 매크로가 AT 명령에 그대로 이어붙는데 앞에 공백이 하나 들어가서
**ESP 가 IP 리터럴로 파싱하지 못하고 호스트명으로 해석 → `DNS Fail`** 이었다.

> **socket-engineer 에게 그대로 전한다**: 서버를 되살려도 그 펌웨어로는 똑같이 실패한다.
> REQ-0077 의 서버 재기동은 필요하지만 **이 증상의 원인은 아니다. 서버를 계속 의심하지 마라.**

이 결론은 현재 **REQ-0078 md 와 이 문서에만** 존재한다. 소스 주석에도 재발 방지용으로 남아 있다.

### 현재 client.ino 에 반영된 상태 (실측 확인)

| 항목 | 값 | 위치 |
|---|---|---|
| `ESP_RST_WIRED` | `0` ✅ 되돌림 완료 | `client.ino:653` |
| `WIFI_SSID` | `SK_WiFiGIGA50DC_2.4G` | `client.ino:84` |
| `WIFI_PASS` | `2011050796` | `client.ino:85` |
| `SERVER_IP` | `192.168.35.21` — **앞 공백 없음** ✅ | `client.ino:90` |

`ESP_RST_WIRED` 를 0 으로 되돌린 근거: A2↔ESP RST 선이 **물리적으로 분리돼 있다.**
1 로 두면 4단 사다리가 "하드웨어 리셋했다"는 **거짓 로그**를 남겨 다음 판정을 오염시킨다.

## 빌드/시스템 동작 여부 — **빌드는 GREEN (실제로 돌려서 확인)**

```
arduino-cli compile --fqbn arduino:avr:uno   (2026-08-16 실행)

스케치        19706 / 32256 바이트  (61%)
전역 변수      1017 /  2048 바이트  (49%)   지역변수 여유 1031
```

**단, 저장소 경로 그대로는 컴파일되지 않는다.** 알려진 툴체인 제약:

```
Can't open sketch: main file missing from sketch: 조별과제샘플/조별과제샘플.ino
```

arduino-cli 는 **스케치 폴더명 == 스케치 파일명**을 요구하는데 `조별과제샘플/client.ino` 는
이를 어긴다. 위 GREEN 수치는 `/tmp/ardbuild/client/client.ino` 로 복사해서 얻은 것이다.

⚠ **이 문제를 고치겠다고 `조별과제샘플/` 을 재구성하지 마라.** 그 디렉터리는 공용 표면이고
다른 도메인(server 등)이 함께 쓴다. 우회 빌드로 충분하다.

## 사라진 산출물 — 무엇이 없어졌고 어떻게 되살리는가

### 1. `arduino/aptest/aptest.ino` — **복원 가능** ✅

내 도메인에서 사고로 사라진 유일한 파일이다. HEAD 히스토리에는 없지만
**체크포인트 커밋에 살아 있다.** 확인된 복구 명령:

```bash
git show dacddfd:arduino/aptest/aptest.ino > arduino/aptest/aptest.ino
```

`dacddfd` = `WIP: Claude Code rate-limit checkpoint (7fb8eb20)` · 08-15 16:06 —
**REQ-0078 헤더가 언급한 바로 그 16:06 체크포인트**이며 aptest 를 담은 가장 최신 스냅샷이다.
(다른 후보: `add822f`·`a538c09`·`d2d7985`, 전부 08-15 16:02~16:03)

⚠ 복원 전 `mkdir -p arduino/aptest` 가 필요하다 — 디렉터리째 사라졌다.
**REQ-0057 이 "사라진 파일을 급하게 재작성하지 마라 · 목록만 남겨라"라고 했으므로
나는 복원하지 않았다.** 명령만 검증해서 남긴다.

### 2. `docs/arduino/` — 원래 존재한 적 없음

사고로 사라진 게 아니다. 이 문서를 쓰면서 처음 만들었다. 혼동하지 마라.

## 다음 한 걸음 — 재기동 후의 내가 이어받을 것

순서대로. **전부 루트의 순서 지정을 기다린다** (REQ-0057 이 자율 착수를 금지했다).

1. **루트 결정 대기** — `client.ino` 의 uncommitted 수정을 커밋할 것인가.
   (내 판단: 먼저 해야 한다. 위 "가장 먼저 볼 것" 참조)
2. `git show dacddfd:...` 로 **aptest.ino 복원**
3. **REQ-0078 ② 마무리** — aptest 판정 블록 버그: 시행 B 를 **미시행**했는데
   "MAC 을 바꿔도 못 붙었다"는 결론을 낸다. **실행되지 않은 시행으로 결론 내지 않도록** 고칠 것.
   → 복원 전에는 손댈 수 없어서 미완이다.
4. **REQ-0078 ③** — `client.ino` 플래싱(`/dev/cu.usbmodem21201`) → 시리얼에서 `[TX] S,...` 확인
   → 서버에 `+ARD` 적재 확인. **socket-engineer 의 서버(REQ-0077)가 살아 있어야 한다.**
   사용자가 플래싱·시리얼 사용 권한을 이미 명시적으로 허가했다(REQ-0078).

### REQ-0078 항목별 현황

| # | 항목 | 상태 |
|---|---|---|
| ① | `ESP_RST_WIRED` 1→0 | ✅ 완료 (uncommitted) |
| ② | aptest 판정 블록 버그 | ⛔ **차단** — 대상 파일이 사고로 삭제됨, 복원 후 가능 |
| ③ | 플래싱 → 시리얼 → S 프레임 확인 | ⬜ 미실시 (동결) |
| ④ | 될 때까지 자율 반복 | ⏸ REQ-0057 이 동결 |

> **REQ-0078 의 "한 턴 돌고 멈추지 마라"는 지금 유효하지 않다.**
> REQ-0078 은 08-15 16:02 발행, REQ-0057 은 **08-16 15:26 발행으로 하루 더 최신**이다.
> ID 가 더 낮은 이유는 사고로 `.claude/team/` 의 **ID 카운터가 초기화**됐기 때문이지
> 더 오래돼서가 아니다. **번호가 아니라 날짜로 판단하라.**
> 그리고 REQ-0057 은 "새 작업 착수 금지 · 서버와 시리얼 캡처를 되살리지 마라"라고 명시했다.
