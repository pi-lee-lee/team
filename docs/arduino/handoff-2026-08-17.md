## 3. 🔴 미검증으로 남은 것 — **"고쳤다"고 쓰지 마라**

**기전 C 수정(`0fba51f`)은 실기에서 확인된 적이 없다.** 호스트 회귀 **64 PASS** 가 전부다.

> **검증 조건: `[TX] A,` ≥ 1 **그리고** `★ 정지 감지` = 0.**
> 창4 는 `[TX] A,` 가 **0** 이라 **0/0** 이었다 — 시험이 성립하지 않았다.

**그리고 지금은 그 시험을 할 수 없다** — 하행을 넣으면 기전 B(모듈 리셋)로 링크가 끊겨
`+IPD` 가 온전히 도착하지 못한다. **B 가 C 의 시험을 막고 있다.**

### 소스에 있으나 안 구운 것 둘

1. **주기 재장전** — `lastStatusAt = millis()` 를 `+= HEARTBEAT_MS` 로(§3.4).
   ⚠ **이걸 고치면 활성 구간 실측 수단(주기−1000ms)이 같이 사라진다.** 알고 고쳐라.
2. **더미 전략** — 프롬프트 놓침 시 더미 주입. **설계 미완**(§7.1 계열).
   ⚠ 핵심 입력은 **"`SEND OK` 는 안 왔는데 `busy` 로 답한 4건"**(`§8.6-2`)이다. 그 갈래를 빠뜨리지 마라.

**둘은 같은 굽기에 묶는 것이 맞다** — 개입을 쪼개지 마라.

## 4. 지금 무엇을 기다리나 — **사용자 결정**

```
상행만 쓰면 하룻밤 안 끊긴다        7.37h · 끊김 0건
하행을 넣으면 끊긴다                2/2
→ 시연에 하행이 필요한가?            ← 루트가 사용자에게 묻는 중
```

- **필요 없다** → 하행을 빼고 시연한다. 장치 쪽 할 일 없음.
- **필요하다** → **내 차례가 다시 온다.** 흐름 제어(socket)와 함께 **장치 쪽에서 무엇을 할 수 있나**.

⚠ **"무엇이 ②를 ③으로 번지게 하나"는 루트가 중지시켰다.** 1순위 후보가 **ESP AT 펌웨어 내부**라
**우리가 못 닫는 것**에 닿는다. **재개 지시 없이 파지 마라.**

## 5. 준비만 해 둔 것

**`docs/arduino/RSTCAUSE-TAP-PLAN.md`** — ESP TX 를 **74880 으로 병렬 관측**해 리셋 원인을
**글자로** 읽는 계획. **자료가 오기 전에 해석 규칙을 고정해 뒀다.**

- **우선순위는 내려갔다** — 전원이 닫혔으니 이제 *"전원이냐 펌웨어냐"* 가 아니라
  *"워치독이냐 예외냐"* 를 가르는 것이다.
- **실물 요청은 내지 않는다.** 사용자가 USB-시리얼 어댑터를 먼저 말하면 그때 꺼낸다.
- ⚠ **관측 추가도 개입이다.** 순서는 루트가 잡는다.
