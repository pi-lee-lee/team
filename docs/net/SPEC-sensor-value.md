# 상행 센서 값 — 잡힌 것만 말고 **얼마인지도** 나른다

> 사용자 요구(2026-08-20): *"센서에서 보내오는 값도 필요하다. 만약 초음파센서가
> **잡을때 거리를 리턴**한다면 **거리까지 받아야한다.**"*

작성: socket-engineer · **이름·형식·시점·계산 주체를 여기서 못 박는다.**
🔴 **arduino·web 이 지어내지 않게 하는 것이 이 문서의 목적이다.**
🔑 **지금은 명세뿐이다. 코드 0줄 · 굽기 0 · 배포 0.**

---

## §0 지금 무엇이 있고 무엇이 없나 — 값으로

```
장치 : pulseIn → `us / 58` 로 **cm 를 만든다** → 문턱과 비교하고 **버린다**
       `SensorFn` 이 `bool` 을 돌려준다 → 값이 통과할 통로가 **함수 서명에 없다**
전선 : `S,<seq>,<occ>,<res>,<up>,<devid>,<ck>` — `occ` 는 **모듈당 비트 하나**
서버 : `SensorReading{known, value(bool)}` — 숫자를 담을 자리가 없다
화면 : `modules[].value` 는 **비트**다(액추에이터 에코와 같은 필드)
```
> ### **정보는 이미 장치 안에 있고, 계약이 그것을 버린다.**
🔑 **하행은 어제 7자리로 넓혔고(`parseU32`) 상행은 여전히 1비트다.** 그 비대칭이 오늘의 요구다.

## §1 🔴 계약의 뿌리 — **서버는 그 숫자의 뜻을 모른다**

우리 제1계약은 하행에 대해 이렇게 되어 있다:
> *"값의 뜻을 서버도 프로토콜도 모른다. 뜻을 정하는 것은 기여자이고, 정한 표를 양쪽에 적는다."*

**상행도 같게 간다.**
```
✅ 전선은 **부호 없는 정수 하나**를 나른다. 단위·의미는 **기여자의 것**이다
❌ `unit:"cm"` 같은 필드를 만들지 않는다 — 서버가 모르는 것을 아는 척하게 된다
🔑 초음파는 cm 이고 조도 센서는 lux 다. **그 표는 기여자가 자기 코드 옆에 적는다**
```
⚠ **단위를 전선에 넣고 싶어지면** 그때는 이 절을 고치는 것이 아니라 **왜 서버가 알아야 하는지**를
먼저 적어라. 지금은 알 이유가 없다.

## §2 값이 **없을 수 있다** — 🔴 마법값을 쓰지 않는다

```
버튼·스위치      : 값이라는 것이 없다
🔴 초음파도 그렇다 : 반사가 없으면 `pulseIn` 이 **0(타임아웃)** 을 준다.
                    그건 "0cm" 가 아니라 **"못 쟀다"** 이다
```
> ### **`-1`·`0`·`9999` 로 "없음"을 말하지 않는다. 그건 값의 범위를 잡아먹고, 언젠가 진짜 값과 겹친다.**

✅ **우리는 이미 이 어휘를 갖고 있다** — `SensorReading{known, value}` 의 `known` 이 그것이다.
같은 규칙을 그대로 쓴다: **값이 없으면 필드를 안 보낸다**(존재/부재 규칙).

```
전선 : 값이 없으면 그 모듈의 값 항목을 **안 싣는다**
서버 : `has == false`. `value` 는 **뜻이 없다**
화면 : "모름" 으로 그린다. **숫자를 지어내지 않는다**
```
🔑 §"`known:false` 를 `known:true`(틀림)로 바꾸지 마라" 의 상행 판본이다.

## §3 콜백 — **불리는 조건은 안 바뀐다. 정보만 는다**

루트 확정: *"콜백이 불리는 조건은 점유 변화 그대로다. value 는 그 순간의 값이다."*

```cpp
void onOccupancy(ParkingServer& srv, const std::string& spot,
                 const std::string& module, bool occupied,
                 const SensorMeasure& measure);      // 🔴 늘어나는 것은 이것 하나
```
```cpp
struct SensorMeasure {
    bool has;     // 🔴 값이 있나. false 면 아래는 뜻이 없다
    long value;   // 장치가 준 정수. **단위는 기여자가 안다**(§1)
};
```

### 왜 값 둘을 묶었나 — 그리고 **무엇을 안 했나**
```
❌ 파라미터를 여섯으로 늘리지 않았다   (…, bool occupied, long value, bool hasValue)
   → `hasValue` 를 안 보고 `value` 를 쓰는 코드가 반드시 나온다. **둘은 붙어 다녀야 한다**
❌ 기존 파라미터를 구조체로 **갈아치우지** 않았다 — 사용자가 "파라미터 추가"를 골랐다
✅ **하나를 더한다.** 콜백은 여전히 하나이고 기여자가 배우는 것은 그대로다
```
🔑 **`has` 와 `value` 를 한 덩어리로 묶는 것이 이 설계의 요점이다** —
갈라 두면 §2 의 규칙(모름을 숫자로 바꾸지 마라)이 **호출부에서 무너진다.**

### ⚠ 거리 변화마다 부르지 않는다
```
초음파는 가만히 있어도 값이 흔들린다 → 거리 변화로 콜백을 부르면 **LED 가 미친다**
✅ 콜백은 **점유가 바뀔 때만.** `measure` 는 **그 순간의 값**이다
```
🔑 사용자 원문이 *"**잡을 때** 거리를"* 이다. 문장이 이미 시점을 말하고 있다.

## §4 전선 — **`V` 프레임을 새로 만든다** (arduino 예산 확인 필요)

```
V,<v1>,<v2>,…,<vk>,<ck>
   k     : **그 노드의 센서 모듈 수** — 🔴 **센서만. 등록(`D`) 순서 그대로**
   각 항목 : hex **3자리** 고정, 또는 🔴 **빈 칸**(= 값 없음 · §2)
   예 : `V,3C0,05F,7A` · 두 번째 센서에 값이 없으면 `V,3C0,,B2`
   ⚠ `seq` 를 안 넣는다 — **`S` 와 같은 배치(한 `+IPD`)로 나가므로** 짝지을 것이 없다
```

### 🔴 왜 `S` 에 안 싣고 별도 프레임인가 — **`S` 에는 이미 선택적 꼬리가 있다**
루트·arduino 둘 다 *"`S` 에 붙이면 ACK 손실 0 이라 그쪽이 낫다"* 로 왔다. **값은 맞다.**
**그런데 `S` 를 읽는 코드가 내 쪽에 있고, 거기에 둘이 못 본 것이 있다:**
```
uplink.h:168  "f 는 체크섬을 뺀 필드들이므로 **7번째(index 6)가 있으면 그것이 tmask 다**"
              → `tmask` 는 **선택 필드**다(없으면 해제로 본다 · 옛 펌웨어 수용)
🔴 여기에 값을 또 붙이면 : tmask 를 **안 보내는** 장치의 첫 값이 **index 6** 에 온다
                          → 서버가 그것을 **tmask 로 읽는다**
```
> ### **위치로 뜻을 정하는 꼬리가 이미 하나 있는 자리에 또 하나를 붙이면, 두 뜻이 같은 칸에 겹친다.**
> ### **그리고 tmask 를 쓰는 장치가 나타나기 전까지 **아무도 못 본다.** 오늘 `n` 이 우리를 문 그 부류다.**

**별도 프레임은 그 자리가 없다.** 그리고 옛 서버는 `V` 를 **`drop_unknown` 으로 조용히 버린다** —
`S` 형식을 바꾸면 옛 서버가 **틀리게 읽는데**, 모르는 타입은 **안 읽는다.** 안전 방향이 다르다.

### 대가는 값으로 안다 — 그리고 **우리 유도 안쪽이다**
```
ACK 여유 : V 없음 10건 → 🔴 별도 V(n=2) **9건**   (arduino 실측 분모: CAP 160B · ACK 13B · S 21B)
우리 하행 유도 : `DOWN_BATCH_MAX_N = 2D/3`, **D(배출) = 6** 에서 나왔다 → **9 > 6**
🔑 즉 ACK 하나를 잃어도 **우리가 세운 전제(6)는 안 깨진다**
⚠ 다만 n 이 크면 다르다 : 별도 V(n=8) → ACK 7건. **7 > 6 이지만 여유가 1이다**
```
🔴 **그래서 `DEV_S_WORST_ASSUMED_B` 를 갱신해야 한다** — 그 상수는 *"배출 6 의 전제가 깨졌나"* 를
감지하는 자리다. **`V` 가 실리는 슬롯의 최악**을 반영하지 않으면 **전제가 깨져도 안 뜬다.**

### hex 3자리 — 🔴 **부품이 아니라 예산에서 유도됐다**(arduino)
```
타임아웃 = NEAR × 58 × 2 µs · 연속 블로킹 예산 66ms
센서 2개 → 문턱 상한 **284cm = hex 11C**  🔴 **2자리(0~255)로 못 담는다**
```
🔑 초음파 사거리 4m(=`190`)도 같은 답을 주지만 **그것은 부품이 바뀌면 낡는다.**
**예산 근거는 우리 링크 구조에서 나오므로 부품과 무관하다** — 그래서 이쪽을 적는다.

### ⚠ 위치가 뜻을 정한다 — **그 규칙을 여기서 못 박는다**
`occ` 도 위치로 말한다. **그런데 폭 규칙이 다르다:**
```
`occ` : **모든 모듈**(센서+명령) 폭. `ceil(n/4)` hex
🔴 `V` : **센서만.** 명령 모듈은 자리를 **차지하지 않는다**
```
> ### **둘을 같은 규칙으로 읽으면 어긋난다. `V` 의 k 는 `n` 이 아니다.**
⚠ **§"두 뜻을 겸한 이름"의 재발 자리라고 arduino 가 짚었다.** 그래서 파서가 `k` 를
**등록에서 센 센서 수**와 대조하고, 안 맞으면 **그 프레임을 버리고 계수를 올린다**(조용히 넘기지 않는다).

### 🔴 왜 hex 3자리인가 — 근거는 "안전"이 아니라 **공짜**다 (arduino 예산)
```
S= 23B → ACK 10건   ← 지금
S= 28B → ACK **10건** ← n=2 · hex3.  🔑 **ACK 손실 0. 공짜다**
S= 31B → ACK  9건   ← 십진.  🔴 ACK 하나를 잃는다
S= 46B → ACK  8건   ← n=8 · hex3      S= 61B → ACK 7건 ← n=8 · 십진
```
🔴 **진짜 비용은 바이트가 아니라 `BATCH_CAP` 160B 안에서 ACK 자리를 먹는 것이다.**
🔑 §"한 도메인이 번 것을 다른 도메인의 곱이 먹는다" — **장치 프레임이 커지면 내 처리량이 준다.**
✅ 창 침범은 구조가 막는다(`slotUsed+200 <= 600` · 400+167=567 < 600). **시간 축은 안 열린다.**
⚠ **범위가 4095 다.** 초음파 cm 에는 충분하지만 **더 큰 값이 필요한 센서는 이 형식에 안 들어간다** —
  그때는 자릿수를 늘리는 것이 아니라 **왜 그 범위가 필요한지**를 먼저 적어라.

### 왜 `S` 에 안 싣나
```
`S` 에 센서마다 값을 붙이면 **n 에 비례해 는다.** 전선 상한은 `n ≤ 15` 이고
지금도 `S최대 23B / 가정 60B` 다 — 15자리 지형에서 매 슬롯 그 비용을 낸다
✅ `V` 는 **말할 것이 있을 때만** 나간다. 조용하면 비용이 **0** 이다
```

### 🔴 언제 보내나 — **두 조건. 첫째가 이 명세의 핵심이다**
```
① 🔴 **그 모듈의 점유 비트가 바뀌는 슬롯에는 반드시 보낸다**
   근거 : 콜백이 그 순간에 불린다. 값이 없으면 사용자가 요구한 "잡을 때 거리" 가 빈다
   ⚠ 그리고 **같은 창에서 `S` 보다 먼저** 나가야 한다 —
     `S` 가 먼저 오면 서버는 **낡은 값(또는 없음)** 으로 콜백을 부른다
② 그 밖에는 **문턱을 넘게 변했을 때만**
   ⚠ 문턱이 없으면 초음파 잡음으로 **매 슬롯 상행이 는다.** 문턱 값은 **장치가 정한다**(예산이 그쪽에 있다)
```
🔑 **①이 없으면 이 기능은 요구를 만족하지 못한다.** ②는 있으면 좋은 것이다.

### 순서를 보장 못 하면 — **거짓말하지 말고 비워라**
```
서버는 콜백 직전에 그 모듈의 값이 **이번 창에서 갱신됐는지**를 본다
갱신 안 됐으면 `measure.has = false`  ← **낡은 값을 그 순간의 값이라고 하지 않는다**
```
⚠ 이것이 §2 와 같은 규칙이다. **모르면 모른다고 한다.**

#### 🔴 그런데 **"언제 그 조건이 참인가"를 양쪽이 맞춰야 한다**
규칙만 있고 조건이 안 맞으면 **한쪽은 보냈다 하고 한쪽은 안 왔다 한다.**
**arduino 가 답해야 하는 것**(이 명세는 자리만 비워 둔다):
```
① 한 슬롯에 `V` 를 **몇 개까지** 낼 수 있나 — 센서가 둘인데 둘 다 바뀌면?
② 배치가 꽉 찬 슬롯에서 `V` 가 **밀리나 버려지나**
   🔴 밀리면 다음 창에 오고, 그때는 이미 늦다 → 서버는 `has=false` 로 본다
   🔑 **버리는 쪽이 낫다** — 늦게 온 값은 "그 순간의 값" 이 아니고, 오면 오히려 헷갈린다
③ `V` 와 `S` 가 **같은 전송 단위**(한 `+IPD`)로 나가나
   ✅ 나가면 순서가 구조로 보장된다. 아니면 타이밍에 달린다
```
⚠ **②·③ 이 정해지기 전에는 `has=false` 가 얼마나 자주 나올지 아무도 모른다.**
그 비율을 **요약 계수로 낼 것**(`값없음 N/M`)을 구현 때 같이 넣는다 —
안 그러면 *"값이 가끔 안 온다"* 를 사람이 눈으로 세게 된다.

## §4.5 🔴 **문턱은 지금 못 정한다 — 미상으로 적는다**

`V` 를 *"문턱을 넘게 변했을 때만"* 보내라고 했다. **그 문턱 값을 지금 정할 수 없다.**
```
arduino : **cm 흔들림 폭을 잰 적이 없다.** `us/58` 을 만들고 비교만 하고 버려서
          그 숫자가 로그에 **한 번도 안 찍혔다**
계산으로 나오는 것 : pulseIn 해상도 0.017cm · 데이터시트 ±3mm · 온도 0.17%/°C
🔴 미상 : 인터럽트 왜곡 — **방향은 안다(값이 는다)** · **크기는 모른다**
```
> ### **추측한 문턱을 이 문서에 박지 마라. 박히면 다음 사람이 그것을 근거로 읽는다.**

**🔑 무엇이 이 미상을 닫나**: **굽기 후 cm 실측.**
이 작업이 **어차피 굽기를 만든다** → 그 굽기에 **cm 를 찍는 진단을 같이 싣는다**(arduino 확정).
```
그때까지 : 장치가 **자기가 고른 값**으로 보낸다. 명세는 값을 안 박고 **"장치가 정한다"만** 박는다
그 뒤   : 실측 분포를 보고 정한다. 그 값도 **장치 상수**다(예산이 그쪽에 있다)
```
⚠ 그리고 그 실측 전까지는 **`V` 빈도를 판정 근거로 쓰지 마라** — 문턱이 임의값이라
"많이 온다/적게 온다"가 센서 특성인지 문턱 탓인지 안 갈린다.

## §4.6 🔴 **문턱이 없는 관측 모듈** — 장치가 새로 만드는 상태다

arduino 확정: `.near()` 를 **안 부른 값 훅**은 **판정을 안 한다** — 값만 보내고
부팅 로그가 `🔴문턱없음` 이라고 말한다. **그러면 그 모듈의 점유 비트는 항상 `0` 이다.**

### 🔴 서버는 그것을 "비었다"로 읽으면 안 된다
```
비트가 0 이지만 그건 **"비었다"가 아니라 "이 센서는 점유를 말하지 않는다"** 다
그대로 읽으면 : value_total 에 들어가고 · value_known 에 들어가고 · **확실히 비었다**로 보고된다
🔴 = 모름을 거짓으로 무너뜨리는 것. §2 와 같은 잘못이다
```
✅ **답은 등록에 오는 문턱이 준다** — `.near(60)` 이 전선에 실리므로 서버가 **갈라 볼 수 있다**:
```
문턱 있음 → 점유 계산에 **든다**(지금과 같다)
🔴 문턱 없음 → 점유 계산에서 **뺀다.** 값만 나른다. `value_total` 에도 안 넣는다
```
🔑 **arduino 가 문턱을 전선에 올린 결정이 이 구분을 가능하게 했다.** 숨어 있었으면 서버가 못 갈랐다.

### 🔴🔴 호환 — **"필드가 없다"를 "문턱이 없다"로 읽으면 옛 장치가 통째로 죽는다**
```
옛 판 장치는 등록에 그 필드가 **아예 없다**
그것을 "문턱 없음" 으로 읽으면 → **모든 센서가 점유 계산에서 빠진다** → 주차장이 전부 unknown
```
> ### **필드 부재 = "옛 판. 문턱은 장치 안에 있다. 판정한다"** 로 읽는다.
> ### **"판정 안 함" 은 *명시적 표지가 있을 때만* 이다.**
⚠ 이것은 §"기본값은 틀렸을 때 어느 쪽이 조용한가로 정한다" 다 — 반대로 두면
**옛 장치가 조용히 전부 죽고**, 증상은 "센서가 고장났나" 로 보인다.

### ⚠ 그리고 새 조용한 실패가 하나 생긴다 — 말하게 해야 한다
```
주차 자리의 관측 모듈이 **전부 문턱 없음**이면 → 점유가 영원히 `unknown`
자리도 있고 센서도 있고 값도 오는데 **아무도 판정을 안 한다**
```
🔑 이미 있는 검사(`센서가 하나도 없다`)의 형제다. **같은 자리에서 같은 꼴로 말한다** —
*"자리 A1 의 관측 모듈에 **문턱이 하나도 없다**. 값은 오지만 점유는 영원히 모른다"*

```
🔴 지금은 **안 한다** — 판정자가 둘이 되고, 장치가 이미 하고 있다
되살리는 조건 : **굽지 않고 문턱을 바꾸고 싶어질 때.** 그때 이 절을 다시 연다
```
🔑 §"기각의 근거가 '필요 없다'였으면 필요해진 날 되살아나야 한다" — 그래서 조건을 적어 둔다.

## §6 화면 — 🔴 **`modules[].value` 에 얹지 않는다. 그리고 지금 정하지 않는다**

```
🔴 `modules[].value` 는 **비트**다(액추에이터 에코가 같은 필드를 쓴다)
   거기에 센서 숫자를 얹으면 **두 뜻을 겸하는 필드**가 또 생긴다 —
   오늘 `occ` 에서 그 비용을 **4.25배 과대**로 쟀다(원장 §111)
```
### ✅ 확정 형태 (web 회신 반영 · 2026-08-20)
```json
{"devid":"P1","name":"A1","kind":"IP","idx":0,"value":true,"known":true,
 "measure":{"value":32,"age_ms":1200}}   ← 🔑 값이 없으면 **키 자체가 없다**(존재/부재 규칙)
```

#### ① 그릴 자리 — **모듈 행**(web)
```
✅ 모듈 행의 값 기호 옆 한 칸. 구조를 안 바꾼다
❌ 자리 요약에는 **안 넣는다** — 사용자가 *"라벨이 너무 많다"* 로 칸에서 문구를 뺐다(REQ-0297).
   거기에 숫자를 넣으면 **그 판정을 되돌리는 것**이다
🔴 제약(알아야 한다) : 모듈 행은 **선택한 자리의 우측 패널에만** 있다 →
   `measure` 는 **한 번에 한 자리**만 보인다. 격자에는 안 보인다
   ⚠ *"여러 자리의 거리를 한눈에"* 가 요구가 되면 **그건 다른 설계다.** 지금 화면에 그 자리가 없다
```

#### ② 단위 — 🔴 **계약을 넓히지 않는다. 라벨이 이미 답이다**(web)
```
❌ `32` 만 그리면 사용자는 **cm 로 읽는다**(가장 흔한 추측) → 화면이 뜻을 만든 것이다
✅ 뜻을 아는 사람이 선언한다 : `lot.label("P1","A1","앞쪽 거리(cm)")`
   → 화면은 숫자를 **라벨 문맥 안에서** 그린다 : `앞쪽 거리(cm) … 32`
🔑 `control`·`label` 에서 이미 쓰는 형태다. **새 키가 없다**
```
**넓힐 방아쇠를 증상으로 적어 둔다**: *"같은 값을 **화면 밖의 다른 소비자**가 재해석해야 할 때."*
그때 `unit` 을 넣는다. 🔑 §"기각의 근거가 '필요 없다'였으면 필요해진 날 되살아나야 한다".

#### 🔴 ③ 신선도 — **web 이 찾은 빈 자리다. 서버가 나이를 계산해 준다**
```
문제 : `V` 는 **점유가 바뀔 때만** 온다(§4) → 봉투의 숫자는 **낡는다**
      화면이 `32` 를 계속 보여 주면 사용자는 **"지금 32"** 로 읽는다
      ⚠ web 의 신선도 표시는 **화면 전체 하나**뿐이고 **모듈별은 없다**
```
✅ **`age_ms` 를 서버가 계산해서 같이 보낸다.**
```
계산 주체 : 🔴 **서버.** 값을 받은 시각을 서버가 갖고 있다
왜 `ts` 가 아니라 나이인가 : `ts` 면 **화면이 시계 차이를 계산**해야 한다 —
   오늘 우리는 UTC/로컬 어긋남으로 한 번 데었다. **차이를 서버가 계산해 주면 그 축이 없다**
   (`ack_budget_ms` 를 서버가 계산해 내려보낸 것과 같은 형태다)
화면 : `앞쪽 거리(cm) … 32 (3초 전)` 처럼 **나이를 같이 그린다**
```
🔑 **이것이 없으면 화면은 "지금 32" 라고 못 쓴다** — web 이 정확히 그렇게 적었고,
빈 자리를 **지어내지 않고 물어 온 것**이 이 필드를 만들었다(§"계약에 빈 자리가 있으면 받는 쪽이 메운다").

⚠ **`age_ms` 는 "그 값을 받은 뒤 흐른 시간"이지 "센서가 잰 시각"이 아니다.**
장치 안의 지연(슬롯 대기 등)은 안 들어 있다. 그 차이가 문제가 되면 그때 장치가 자기 시각을 실어야 한다.

## §7 판별자

```
✅ 실물 : `= 자리 A1 · 모듈 A1 점유 → 찼다 · **32cm**` 꼴로 로그에 뜬다
   ⚠ 서버는 `cm` 을 모른다 → 로그에는 **숫자만** 찍고 단위는 기여자 주석에 있다
     (`· 값 32` 로 찍는다. `32cm` 로 찍으면 서버가 단위를 아는 척하는 것이다)
✅ 값이 없는 센서(버튼) : 콜백이 `measure.has == false` 로 온다. **숫자가 안 찍힌다**
✅ 자가검증 : has=false 갈래 · 같은 창 갱신 없음 → has=false · 점유 변화 없을 때 콜백 없음
🔴 전선 불변 확인 : `V` 를 **안 보내는 장치**(옛 판)와 붙어도 서버가 그대로 돈다
   → `measure.has = false` 로만 온다. **옛 장치를 깨지 않는다**
🔴🔴 **호환 음성 대조**(§4.6) : 등록에 문턱 필드가 **없는** 장치를 붙여
   **모든 센서가 점유 계산에 그대로 남는지** 본다. 빠지면 옛 장치가 통째로 죽은 것이다
   ⚠ 이 갈래는 **양성만 재면 안 보인다** — 새 장치로만 시험하면 영원히 초록이다
✅ `값없음 N/M` 계수가 요약에 있다 — `has=false` 비율을 **사람이 눈으로 세지 않게**
🔴🔴 **빈 칸 음성 대조** : `V,3C0,,B2` 처럼 **빈 항목**을 주고 `has=false` 가 나오는지 본다
   ⚠ `,,` 를 `0` 으로 읽으면 **0cm 로 오독한다** — 값이 있는 경우로만 시험하면 **영원히 초록**이다
🔴 **필드 수 불일치** : `k` 가 등록에서 센 센서 수와 다르면 **버리고 계수를 올린다.**
   그 갈래도 시험한다 — 조용히 넘기면 위치가 밀린 값을 그대로 쓴다
```

## §9 🔴 **센서가 늘면 무엇이 먼저 깨지나** — 사용자 물음에 값으로 답한다

> 사용자: *"지금 환경이 고정이 아니다. **센서는 더 추가될 수도 있다.** 최대 환경은?"*

### 🔴 병목은 등록 프레임이 아니라 **한 배치(`BATCH_CAP` 160B)** 다
`S` · `V` · ACK 들이 **한 `espWrite` 안에서 같은 160B 를 나눠 쓴다.**
배출 `D` 는 상수가 아니라 함수다(`config.h`):
```
D = (BATCH_CAP − S_worst − V − 1) ÷ (ACK_worst + 1)      ACK_worst+1 = **16**
DOWN_BATCH_MAX_N = 2D/3
V(k) = 4k + 5   (`V,<3자리>×k` + ck + LF)
```

| 센서 k | S_worst | V | 남는 ACK 예산 | 배출 D | **하행 묶음 N** |
|---|---|---|---|---|---|
| 2 | 21 | 13 | 125 | 7 | **4** ✅ 지금 |
| 4 | 31 | 21 | 107 | 6 | **4** ✅ |
| 6 | 40 | 29 | 90 | 5 | **3** ⚠ |
| 8 | 50 | 37 | 72 | 4 | **2** 🔴 |
| 10 | 60 | 45 | 54 | 3 | **2** 🔴 |
| 13 | 69 | 57 | 33 | 2 | **1** 🔴🔴 |

⚠ **`S_worst` 는 arduino 실측 앵커(21@2 · 60@10 · 75@15)를 선형 보간한 값이다** —
그 사이 값은 **내 보간이지 실측이 아니다.** 쓰기 전에 arduino 에게 확인해라.

> ### **센서 6개에서 하행 묶음이 4 → 3 으로, 8개에서 2 로 준다.**
> ### **등록 상한(13)에 닿기 훨씬 전에 *하행 처리량* 이 먼저 무너진다.**

🔑 **그래서 "최대 몇 개"의 답은 하나가 아니다:**
```
전선이 담는 한계        : n ≤ 15 (occ 폭) · 등록 배치 n ≤ 13
🔴 쓸 만한 한계         : **k ≤ 4~6.** 그 위로는 하행이 느려진다
서버 방어 상한          : REG_MODS_MAX = 32 (전선이 먼저 막으므로 안 닿는다)
```
⚠ **N 을 안 내려도 된다** — ACK 은 **밀린다**(버리지 않는다 · arduino 확인).
밀리면 우리 `ACK_TIMEOUT = 2슬롯` 의 **여유 한 슬롯을 먹는다.** 그것이 이 표의 진짜 대가다.

### 🔴 그리고 이것이 §"한 도메인이 번 것을 다른 도메인의 곱이 먹는다" 다
**arduino 가 센서를 늘리면 내 하행 처리량이 준다.** 각자 자기 축만 보면 아무도 못 본다.
그래서 **`DEV_S_WORST_ASSUMED_B` 가 그 전제를 감지하는 자리**이고, `V` 를 반영해 갱신해야 한다.

## §10 🔴 문턱을 등록에 올리지 않는다 — **필요한 것은 숫자가 아니라 한 비트였다**

§4.6 에서 *"문턱이 등록에 오니 서버가 판정 모듈을 갈라 볼 수 있다"* 라고 썼다.
**그런데 4B 를 쓸 이유가 없다** — 등록 배치 상한이 `11n+11` 에서 `15n+11` 로 바뀌어
**모듈 상한이 13 → 9 로 준다.** 위 §9 를 보면 그 축은 이미 빠듯하다.

> ### **내가 물은 것은 "문턱이 얼마인가" 가 아니라 "이 모듈이 점유를 말하는가" 였다.**

✅ **그 구분은 이미 계약에 있다 — `kind` 첫 글자다.**
```
`I*` 관측 → 점유 계산에 든다        `O*` 명령 → 안 든다
🔴 제안 : **`M*` = 값만 낸다.** 점유 계산에 **안 든다**
→ 서버 필터는 이미 `첫 글자 == 'I'` 다. **한 줄도 안 고치고 자동으로 빠진다**
→ 전선 비용 **0B** · 등록 상한 **13 유지** · 옛 장치 호환 문제도 **생기지 않는다**
```
⚠ **첫 글자 집합이 `I`/`O` 둘에서 셋으로 는다** — 계약 확장이다. 작지만 확장이므로 적어 둔다.
🔑 **그리고 `V` 프레임의 `k` 는 "값을 내는 모듈"** = `I*` + `M*` 순서다. `occ` 폭(`n`)과 다르다.

⚠ **arduino 확인 필요**: 장치가 `.near()` 없는 훅의 `kind` 를 `M*` 로 낼 수 있나.
못 하면 §4.6 의 원안(등록에 표지)으로 돌아가되 **숫자가 아니라 한 글자**로 한다.

### 🔑 왜 이 절이 §4.6 을 고치는가
§4.6 은 **arduino 가 "문턱을 전선에 올린다"고 한 것을 받아서** 쓴 것이다. 그 위에서 설계하니
**등록 상한이 깎였다.** 루트가 그 대가를 값으로 짚어 줬고, 다시 보니 **내가 필요 이상을 요구했다.**
> **받은 것에 맞춰 설계하기 전에 "내가 무엇을 알아야 하는가"를 먼저 좁혀라.**

## §11 ~~천장을 정하는 것은 회선 속도다~~ 🔴 **전제가 거짓이었다. 남는 것만 읽어라**

> ### 🔴 **`38400` 은 못 쓴다. `SoftwareSerial` 이다**(사용자 정정).
> 비트 타이밍을 **소프트웨어로** 만들고 그 위에서 **동시 송수신 + `pulseIn` 인터럽트**가 돈다.
> **9600 이 천장이고, 그래서 이 슬롯 구조가 존재한다.**
> Uno 의 하드웨어 UART 는 하나뿐이고 디버그·플래싱이 쓴다 — **나눌 것이 없다.**
> ⚠ `AT+CIPSEND 300B` 실측은 **ESP 쪽 버퍼 축**이다. **Uno↔ESP 구간과 다른 축**인데 한 회선으로 읽었다.

**아래 표는 "baud 를 올릴 수 있다면" 의 가정 위에 있다. 지금 조건에서는 못 쓴다.**
🔑 **그래도 지우지 않는다** — 보드를 바꿔 하드웨어 UART 를 얻는 경로가 언젠가 오면 이 계산이 그대로 쓰인다.
**그리고 그때도 참인 것이 아래 두 줄이다:**
```
🔴 ① 하행은 baud 로 안 늘어난다 — `DEV_RX_RING_B 64` 는 안 커지고 **4배 빨리 찬다**
🔴 ② `DOWN_BATCH_CAP_B 192` 의 근거가 **시간에서 링으로 옮겨 간다**
      → 그 주석을 같이 안 고치면 다음 사람이 "시간 여유가 있으니 올려도 된다"로 읽는다
```
> ### **손잡이가 한 방향에만 듣는다. 그것이 이 절에서 살아남는 값이다.**

## §11(옛) 계산 — **가정 위의 값이다** (baud 를 올릴 수 있는 경우에만)

`BATCH_CAP = 160` 의 근거는 용량이 아니라 **시간**이다: `160 + CIPSEND 18 = 178B @9600bps ≈ 185ms`
≤ 예약 200ms. 🔑 **그러므로 baud 가 바뀌면 이 상수가 통째로 움직인다.**

```
CAP 160 @  9600 → 185ms      CAP 160 @ 38400 → **46ms**
CAP 240 @ 38400 →  67ms      CAP 300 @ 38400 →  83ms      (전부 200ms 예산 안)
```

### `N=4`(=`D≥6`)를 유지하는 데 필요한 `CAP` — 유도식으로 냈다
`CAP ≥ S_worst(k) + V(k) + 1 + 6×16`
```
k= 2 → 131      k= 6 → 166      k=10 → 202
k= 4 → 149      k= 8 → 184      k=13 → 223      k=15 → 237
```
### `CAP = 240` 일 때 (38400 에서 67ms — 지금의 3분의 1)
| 센서 k | 2 | 4 | 6 | 8 | 10 | 13 | 15 |
|---|---|---|---|---|---|---|---|
| **N** | 8 | 7 | 6 | 6 | 5 | **4** | **4** |

> ### **`9600 → 38400` 하나가 "센서 6개부터 하행이 준다"를 "15개까지 N=4"로 바꾼다.**
> ### **같은 변경이 지연 축(1.4초)과 확장 축을 **둘 다** 푼다.**

### 🔴 그런데 **하행은 이렇게 안 늘어난다** — 내 주석이 그 경고를 하고 있다
```
`DEV_RX_RING_B = 64` : 장치 `SoftwareSerial` **수신 링**. 🔴 baud 를 올려도 **안 커진다**
config.h 주석 : *"loop() 가 충분히 자주 비우면 더 흘릴 수 있지만 **그건 타이밍 종속이지 보장이 아니다**"*
🔴 그리고 38400 이면 링이 **4배 빨리 찬다** → 드레인 여유가 **줄어든다**
```
> ### **상행(배치)은 baud 로 늘어나고, 하행(링)은 안 늘어난다. 같은 변경이 두 방향에 다르게 작용한다.**
⚠ `DOWN_BATCH_CAP_B = 192` 는 **시간**으로 유도했다(209ms). 38400 이면 52ms 로 떨어져 **시간 축은 열리는데**
**링 64B 가 남는다** — 그때 `192` 의 근거가 시간에서 **링으로 바뀐다.** 근거가 바뀌면 그 주석도 바뀌어야 한다.

### ⚠ 그리고 이것은 **전선 변경이다**
```
🔴 baud 는 양쪽이 같이 바뀌어야 한다 — 한쪽만 바꾸면 **아무것도 안 통한다**(부분 고장이 아니다)
✅ 안전 방향 : 완전히 안 되면 즉시 드러난다. **조용히 틀리지 않는다**
⚠ 실측 한계 : `AT+CIPSEND` 는 **300B 까지** 조용한 잘림 없음이 확인됐다(18/18).
  **240 은 그 안이고 300 은 경계다.** 경계값을 상수로 박지 마라
```

**🔑 이 절은 "지금 하자"가 아니다.** 센서를 늘리려는 요구가 왔을 때 **먼저 볼 손잡이가 baud** 라는 것이고,
그 값이 여기 있다. **바이트를 쥐어짜기 전에 회선을 보라는 뜻이다.**

## §12 🔴 **확장은 가로다 — 그리고 노드 상한은 *이미 있다***

루트: *"노드 수 상한이 안 걸려 있다"* → 🔴 **틀렸다. 값으로 정정한다.**
```
config.h  static const size_t MAX_ARD_NODES = 8;      · MAX_UNKNOWN_SOCKS = 8
nodes.h:705  if (total >= MAX_ARD_NODES) { admit_rejects++; … closesock(c); return false; }
🔑 **강제된다.** 그리고 **살아 있는 노드를 쫓아내지 않고 새 연결을 거절한다** —
  확실한 것을 버리고 불확실한 것을 얻지 않는다
근거(주석에 이미 있다) : 조별 4~6대 + 개발 예비 2. 초당 8프레임. 그 위는 단일 스레드 select 가 아니라
                        **다른 구조를 논할 규모**다
```

### 무엇이 먼저 걸리나 — 값으로
```
① 🔴 **방송이 곱이다** : 노드 N 이 각자 1Hz 로 말하고, 프레임마다 화면 M 개에 방송한다 → **N × M**
   실측 앵커 : 자리 6 · 모듈 5 → `map` **1,070B**
   보수 추정 : 노드 8 × 모듈 6 = 48개 → map 약 **7KB** · 화면 3개면 초당 약 **169KB/s**
   ⚠ 로컬에서는 안 아프다. **그런데 이것이 노드 수에 대해 유일하게 *곱* 인 항이다**
② 대장 파일 · 요약 줄 : 노드당 한 줄. **선형이고 작다**
③ `WS_MAX_FRAME 64KB` : 모듈 256개(=8×32)에서 map 이 약 37KB — **아직 안이지만 그 축이 유일하게 벽에 닿는다**
④ `select()` fd 집합 : 8노드 + 화면 몇 개는 문제 아니다
```
> ### **상한을 올리려면 ①을 먼저 재라. 바이트가 아니라 *방송 곱* 이 먼저 아프다.**
⚠ **상한이 없는 것이 "무제한"이 아니라 "모르는 지점에서 깨진다"** 는 루트 말은 맞다 —
그래서 **8 이 값으로 박혀 있고 거절 로그가 남는다.**

### ✅ 확장 방향 — **세로가 아니라 가로**
```
❌ 한 보드에 센서 13개  → 회선이 못 버틴다(§9 표: 센서 6부터 N 이 준다) · 그리고 baud 로 못 푼다(§11)
✅ **보드 N대 × 센서 4~6개** → 🔑 **회선이 장치마다 따로다.** 배치 예산이 노드별로 독립이다
구조가 이미 한다 : `lot.spot("A6").parking().module("KIM01","C1")` · `srv.send("KIM01","LD",1)`
```
🔑 **조별과제 구조와 그대로 맞는다** — 각자 자기 보드에 자기 센서를 붙이고 `devid` 로 갈린다.
**우리가 새로 만들 것이 없다. 이미 그렇게 설계돼 있다.**

⚠ **다만 지금 그 예시가 `lot.cpp` 주석 안에만 있다** — 주석은 컴파일러가 안 본다.
→ `EXAMPLES.cpp` 에 **여러 보드 조립 예제를 코드로** 넣는다(§"주석 안의 예시는 조용히 낡는다").

## §13 🔴🔴 **"못 쟀다"가 `occ` 에서는 "비었다"가 된다 — 둘이 갈린다**

루트가 물었다: *"값이 **못쟀다** 로 왔을 때 점유 비트는 어떻게 오나. 둘이 갈릴 수 있나."*
🔴 **갈린다. 그리고 이미 갈리고 있다.**

### 값으로
```
장치  : lastVal = (us != 0) && ((us/58) < NEAR)
        🔴 타임아웃(`us == 0` = 못 쟀다) → `false` → **occ 비트 0**
서버  : nodes.h:406  known = (mi < mn->mod_bits_n)   ·   val = known && mod_bits[mi]
        🔴 **`known` 은 "센서가 쟀나" 가 아니다** — **"비트열 폭이 이 모듈까지 왔나"** 다
→ 결과 : 못 쟀다 → `known = true` · `value = false` → 서버는 **"확실히 비었다"** 로 읽는다
⚠ 빈도 : 🔴 **분모가 안 갈렸다. 값으로 쓰지 마라.**
         `못쟀다 36/124` 라는 수가 있는데 **그 36 이 A1 것인지 B1 것인지 미확인**이다 —
         **A1 은 설계상 항상 빈 칸이다**(120cm 안에 아무것도 없다). 그러면 B1 의 못쟀다는
         0 에 가깝고 **이 진동은 실재하지 않는다**
🔑 **그래도 처방은 옳다** — 빈 칸이 **한 건이라도** 오면 판정을 건너뛰는 것이 맞다.
   **비율이 바꾸는 것은 심각도뿐이지 설계가 아니다**
```
> ### **같은 사건을 두 필드가 다르게 말한다 — `V` 는 "없다", `occ` 는 "비었다".**
> ### **비트는 두 값뿐이라 "모름"을 담을 자리가 없고, 그래서 `0` 으로 접힌다.**

### 🔴 이것이 진동의 **두 번째 원천**이다 — 히스테리시스가 못 막는다
```
경계 진동   : 49~60cm 가 문턱 60 을 넘나든다 → ✅ **장치 히스테리시스가 막는다**(원천)
🔴 못쟀다 진동 : 반사 실패 → 0 → 다시 재면 1 → **상승 → 토글**
              히스테리시스는 **값이 있을 때** 동작한다. 값이 없으면 지나간다
```
⚠ **내 하강 디바운스(2프레임)도 못 막는다** — 못쟀다가 **연속 2회**면 하강이 확정된다.
빈도가 높으면 연속 2회가 드물지 않다(위 ⚠ 대로 그 빈도는 아직 모른다).

### ✅ 답은 이미 보내기로 한 것 안에 있다 — **`V` 의 빈 칸**
```
그 프레임의 `V` 에서 그 모듈이 **빈 칸**이면 → 🔑 **그 슬롯의 점유 판정을 건너뛴다**
   (`occ` 비트를 안 읽는다 · 직전 확정값을 유지한다 · 콜백을 안 부른다)
✅ 새 필드가 필요 없다. **§2 에서 이미 정한 "부재 = 빈 칸" 이 그 정보를 나른다**
✅ 히스테리시스와 **다른 축**이라 둘 다 있어야 한다 — 하나가 다른 하나를 대신 못 한다
```
⚠ **`V` 가 없는 옛 장치에서는 이 보정이 안 걸린다** — 그때는 지금과 같다(못쟀다=비었다).
**퇴행이 아니라 개선이 안 닿는 것**이고, 그 사실을 로그로 말한다.

### 🔴 그리고 이름을 갈라야 한다 — `known` 이 두 뜻을 겸하고 있다
```
지금 `SensorReading.known` = **"비트열 폭이 닿았나"**(전송 계층)
필요한 것                  = **"센서가 값을 얻었나"**(측정 계층)
🔴 두 뜻이 한 이름에 있고, 지금까지 값이 같아서 안 보였다 — 오늘 `n` 이 우리를 문 그 부류다
```
**구현 때 갈라라**: `known`(폭) 과 `measured`(측정) 를 따로 든다.
합쳐 두면 **`V` 빈 칸 보정을 넣을 자리가 없다.**

### ⚠ 판별자
```
✅ `V` 에 빈 칸 → 그 슬롯 판정 건너뜀 → **콜백 0회** (음성 대조)
✅ 빈 칸 뒤 값이 오면 → 직전 확정값과 비교해서만 콜백
🔴 `못쟀다` 비율을 **모듈별로** 요약에 낸다(`값없음 N/M`) —
   ⚠ **모듈을 안 가르면 지금과 같은 일이 또 난다**: 항상 빈 A1 이 분모를 채워
     B1 의 진짜 비율을 가린다. **분모를 가르는 것이 이 계수의 존재 이유다**
   숫자가 있어야 다음에 그것을 판정할 수 있다
```
