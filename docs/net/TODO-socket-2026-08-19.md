## 🔴 web 실기 대조가 끝난 뒤에 (루트 보류)

**보류 이유가 같다: 지금 서버를 바꾸면 web 의 대조 중간에 조건이 달라진다.**

| 항목 | 내용 | 근거 |
|---|---|---|
| **빈 지형이면 `map` 을 안 보낸다** | 지형이 비면 송신 생략 + 기동 로그에 크게 남긴다 | "0자리"는 정상 상태가 아니다. 화면이 그리면 **사고가 정상처럼 보인다**(첫 배포가 그 증명) |
| **`get_map` 상한 우회** | `srv_id` 가 바뀐 직후 한 번은 통과시킨다 | **세계 변화는 고리가 아니라 한 번 있는 사건**이다(web). 보호용 상한이 정합성을 깨면 상한이 잘못 걸린 것 |

⚠ **둘 다 정상 경로에서 안 걸린다.** 그래서 급하지 않다.
⚠ **`get_map` 쪽은 지금 web 의 `force` 로 동작 중이다** — **양쪽을 동시에 고치면 어느 쪽이 들었는지 안 갈린다.**

## ⏸ 미룬 것 — **버린 것이 아니다**

### `3b` — `map<devid, Node>`
**`4` 가 끝났으니 이제 순수한 정리다.** `3a` 의 `all_nodes()` 가 필요한 것을 이미 준다.
⚠ **`park` 별칭 7줄이 깨진다**(맵 원소를 참조로 못 묶는다) → **접근자 함수로 바꿔야 한다.**
🔴 **접근자로 바꾸면 인라인 여부가 달라져 출력이 같아도 성능이 달라질 수 있다** —
**출력 대조는 그것을 안 잡는다.** 그 한계를 판정에 적어야 한다.

### 손잡이 조정 — `rid` 폭 고정 → `N` 감소 (순서 있음)
**근거는 원장 §8.23-(58)에 다 있다.** 🔴 **미루는 이유는 "급하지 않아서"가 아니다:**
> **실사용 부하 자료가 하나도 없다.** 가진 것은 전부 주입 창이고 **그건 상한을 재는 자료**다.
**얼마나 돌려야 하는지 모르는 채로 돌리면 감이다.**

### 모듈 값 · 완료 판정
`state` 의 모듈 `value` 가 `known:false`, `completion` 이 `unknown` 뿐이다.
**비트열을 모듈 `idx` 에 연결하면 채워진다.** ⚠ **지금 채우면 지어내는 것이다.**

### 차단봉 전선 명령
`open_gate` 가 **`not_supported`** 로 거절된다. **전선에 `R`·`C`·`T`·`M` 뿐이고 차단봉 프레임이 없다**(arduino 축).
🔑 **조용히 성공으로 답하지 않는 것**이 지금의 정답이다 — 그러면 **아무 일도 안 일어난 것을 사람이 모른다.**

## ⚠ 설정 적재가 들어올 때 같이 볼 것

1. **모듈-자리 결속이 지금 이름 기반이다**(`name` == 자리 `id`). **설정이 대체하면 이 종속이 사라진다** —
   **그때 arduino 의 시험 [34](이름 리터럴 고정)의 *이유*도 바뀐다. 알려야 근거가 안 낡는다.**
2. 🔴 **결속 실패를 `module_absent` 와 갈라야 하는가**(web 제기).
   설정에 오타가 나면 **"모듈이 없다"로 조용히 표시되고 아무도 오타를 못 찾는다.**
   ⚠ **"기대한다"를 서버가 알아야 성립하고, 그건 설정이 있어야 한다.**
