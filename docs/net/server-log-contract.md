# 서버 로그 계약 (초안 v0.1) — 인스턴스 경계와 절대시각

> socket-engineer 작성 · 2026-08-16 · **초안이다. monitor 의 확인을 받아야 확정된다.**
> 루트 지시(REQ-0099 후속): "다음 인스턴스부터 고정 경로 + 기동 시 인스턴스 경계 한 줄을 남겨라."
> 형식 권한은 소비자(monitor)에게 있다 — 이 문서는 **생산자가 무엇을 낼 수 있는지**를 확정해
> 협의를 한 번에 끝내려는 초안이다.
>
> **적용 시점**: 사용자 작업이 끝난 뒤. 지금은 코드를 바꾸지 않는다(루트 지시).

---

## 1. 왜 필요한가 — 오늘 실제로 두 번 오독됐다

추측이 아니라 오늘 일어난 일이다.

**(1) 날짜가 없어서 어제 로그를 오늘 것으로 읽었다.**
`monitor` 와 `root` 가 **각자 독립적으로** "16:00~16:14 에 두 프로세스가 같은 파일에 동시 기록했다"고
판단했다. 실제로는 그 두 줄이 **08-15** 것이고, 서로 다른 인스턴스가 **순차로** 끝난 기록이다.
`13:10:59` 기동분이 `소크 02:49:08` 뒤인 `16:00:07` 에 끝나고, 다음이 `00:13:57` 뒤인
`16:14:05` 에 끝난다 — 산술이 맞물린다. **동시 기록은 없었다.**

원인은 단순하다. `server.cpp:231` 이 이렇게 찍는다:

```cpp
char ts[16]; strftime(ts, sizeof(ts), "%H:%M:%S", localtime(&tt));
```

**날짜가 없다.** 21시간짜리 로그가 자정을 넘는데 `HH:MM:SS` 만 있으니, 읽는 사람이
자정 넘김을 손으로 복원하지 않으면 어제와 오늘이 겹쳐 보인다. 같은 함정을 오늘 두 명이 밟았다.

**(2) 로그 경로가 서버 밖에 있어서 누가 어디에 쓰는지 아무도 모른다.**
서버는 `std::cout` 으로만 찍는다(파일 열기 코드가 없다). 경로는 **띄우는 사람의 셸 리다이렉션**이
정한다. 그래서 `16:19` 에 뜬 `pid 6697` 이 `/tmp/parking-soak.log` 에 **안 썼고**, 관측이 끊겼다.
관측자가 "그 프로세스는 어디에 쓰고 있나"를 물어야 하는 상태 자체가 결함이다.

**(3) 기동 배너에 신원이 없다.** 현재 배너는 포트 3개와 명세 경로만 찍는다.
`pid`·`기동시각`·`바이너리 경로`·`빌드 식별자`가 전부 없어서, 로그만 보고
**어느 프로세스가 어느 바이너리로 무엇을 썼는지 재구성할 수 없다.**
오늘 `/tmp/srv_parking`(08-15 18:42 빌드)과 소스가 어긋난 것을 `mtime` 비교로 알아냈는데,
빌드 식별자가 로그에 있었다면 즉시 보였을 일이다.

## 2. 계약 — 생산자(서버)가 보장하는 것

### 2.1 절대시각 — **이것이 가장 중요하다**

모든 로그 줄의 타임스탬프에 **날짜를 포함한다.**

```
2026-08-16 15:47:19  +? 연결 수락 — …
```

- 형식: `YYYY-MM-DD HH:MM:SS` (로컬 시각, 24시간)
- 대상: `logf()` (231행) 와 소크 요약(439행) **둘 다.** 한쪽만 고치면 문제가 남는다.
- 이유: 소비자가 자정 넘김을 복원하지 않아도 되게 한다. **복원은 오늘 두 번 실패했다.**

> ⚠ 협의 필요: 줄이 길어지는 것을 monitor 가 꺼리면 **대안**은 "날짜가 바뀔 때
> `── 2026-08-16 ──` 구분선 한 줄"이다. 다만 **잘라 읽기(tail·grep)에 약하다** —
> 구분선 위쪽을 못 보면 날짜를 다시 잃는다. **전 줄 날짜를 권한다.**

### 2.2 인스턴스 경계 한 줄

기동 직후, 배너보다 **먼저** 한 줄을 찍는다. 기계가 파싱하는 줄이므로 형식을 고정한다.

```
=== INSTANCE pid=36998 start=2026-08-15T18:42:39+0900 bin=/tmp/srv_parking build=2026-08-15T18:42:10 ports=9991,9900,5500 offset=0 ===
```

| 필드 | 뜻 | 출처 |
|---|---|---|
| `pid` | 프로세스 id | `getpid()` |
| `start` | 기동 시각(ISO 8601, 오프셋 포함) | `epoch_ms()` |
| `bin` | 실행 파일 실제 경로 | macOS `_NSGetExecutablePath` / Linux `/proc/self/exe` |
| `build` | **빌드 식별자** | `__DATE__ " " __TIME__` (기본) 또는 `-DBUILD_ID=...` |
| `ports` | 실제 리슨 포트 3개 | `PORT_* + g_port_offset` |
| `offset` | 포트 오프셋 | `g_port_offset` (0 이 아니면 시험 인스턴스) |

- `build` 는 **바이너리가 어느 소스에서 나왔는지**를 로그만으로 잇기 위한 것이다.
  오늘처럼 "도는 바이너리가 현재 소스의 산출물이 아님"을 `mtime` 으로 추리하는 일이 없어진다.
  가능하면 빌드 시 `-DBUILD_ID="$(git rev-parse --short HEAD)"` 를 넘긴다.
- `offset != 0` 이면 **시험 인스턴스**다. 소비자는 이 줄만 보고 운영/시험을 가를 수 있어야 한다.
  (지금은 별도 한글 배너로 찍고 있어 파싱하기 나쁘다)

### 2.3 종료 경계

기존 `▣ 소크 종료` 를 유지하되 같은 형식의 기계 판독 줄을 덧붙인다.

```
=== INSTANCE-END pid=36998 stop=2026-08-16T16:15:37+0900 reason=signal uptime=21:32:57 ===
```

⚠ **한계를 명시한다**: `SIGKILL` 이나 정전은 이 줄을 남길 수 없다. 그러므로
**소비자는 "END 줄이 없음"을 "아직 살아 있음"으로 읽으면 안 된다** — 비정상 종료와 구별되지 않는다.
**살아 있는지는 로그가 아니라 `pid` 로 확인해야 한다.** (오늘 pid 36998 이 END 없이 죽었다)

### 2.4 고정 경로 — 서버가 자기 로그를 연다

셸 리다이렉션에 의존하지 않는다.

- 기본 경로: `/tmp/parking-soak.log` (저장소 밖 — `git clean` 을 피한 실적이 있다)
- `--log=<경로>` 로 덮어쓸 수 있다
- 열기 모드는 **`O_APPEND`** 다. 두 인스턴스가 같은 파일을 잡아도 **줄이 섞이되 잘리지는 않는다.**
  (`O_APPEND` 쓰기는 `PIPE_BUF` 이하에서 원자적이다. 한 줄은 그 안에 든다)
- 표준출력에도 그대로 내보낸다(사람이 창에서 보는 용도). **파일이 정본이다.**

> 이것이 (2) 를 구조적으로 없앤다. 누가 어떻게 띄우든 로그는 정해진 곳에 쌓인다.

## 3. 소비자(monitor)가 기대할 수 있는 것

이 계약이 적용되면 다음이 **로그만으로** 가능해진다. 지금은 전부 불가능하거나 손 추론이 필요하다.

1. **인스턴스 분리** — `=== INSTANCE` 로 잘라 구간을 나눈다. 누적 카운터를 구간 안에서만 읽으면 된다.
2. **자정 넘김 무관** — 모든 줄에 날짜가 있으므로 `tail` 로 잘라 봐도 시각이 확정된다.
3. **바이너리 추적** — `build` 로 어느 소스에서 나온 산출물인지 잇는다.
4. **운영/시험 구별** — `offset` 필드 하나로 갈린다.
5. **동시 기록 판별** — 줄이 섞여도 `pid` 로 귀속시킬 수 있다.
   (여러 인스턴스가 정말 겹쳤는지 여부를 **추론이 아니라 확인**으로 답할 수 있다)

---

## 4. 열린 항목 — monitor 가 정해 달라

1. **전 줄 날짜 vs 날짜 구분선.** 나는 전 줄을 권한다(§2.1 이유). 파일 크기가 늘어난다
   (약 11바이트/줄 · 오늘 로그 73,393줄 기준 약 800KB 증가).
2. **`pid` 를 매 줄에 넣을 것인가.** 넣으면 섞임 귀속이 완전해지지만 줄이 더 길어진다.
   나는 **경계 줄에만** 넣는 것으로 충분하다고 본다 — 겹치는 일이 정상 운영에서는 없어야 한다.
3. **`INSTANCE-END` 의 `reason` 값 목록.** 최소 `signal` / `listen-fail` 정도를 생각한다.
4. 기존 한글 배너(`주차 관제 서버 — …`)를 남길 것인가 없앨 것인가. 사람이 읽기엔 유용하다.

## 5. 적용 절차

1. monitor 가 §4 를 확정한다.
2. 사용자 작업이 끝나고 루트가 순서를 주면 `조별과제샘플/server.cpp` 에 한 번에 반영한다.
   (내 소유다. 코드 변경은 그때 한다 — 지금은 하지 않는다)
3. 빌드 → `--selftest` → 실왕복 검증 후 기동. 기동 시 **로그 경로를 monitor 에게 먼저 알린다.**
4. 이 문서를 v1.0 으로 올리고 `docs/net/parking-protocol.md` 에서 참조한다.
