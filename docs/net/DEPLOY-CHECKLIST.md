### 🔴 0.5.1 **운영 cwd 에 `index.html` 이 있어야 화면이 나온다** — 배포마다 확인할 것

`serve_file()` 은 **cwd 기준 상대경로**로 연다(§4.3). 운영 cwd 는 `~/parking-bin` 인데
**거기에 `index.html` 이 없으면 `GET /` 가 404 다.** 서버는 아무 잘못 없이 정상 동작한다 —
**증상은 "웹으로 접속하면 화면이 안 나온다"** 이고, 원인이 서버 코드에 없어서 찾기 어렵다.

**2026-08-17 에 실제로 그랬다.** 배포 때 cwd 를 유지하기로 정했고(변경을 하나만 넣으려고),
그 결정의 부작용을 아무도 안 적었다. 루트가 `조별과제샘플/index.html`(127KB, 외부 참조 없는
단일 파일)을 `~/parking-bin/` 에 복사해서 해결했다 — **서버 재기동 없이** 해결된다
(`serve_file` 이 요청마다 파일을 연다).

```bash
# ~~ls -l ~/parking-bin/index.html~~                                  ← 🔴 낡은 사본을 통과시킨다
# ~~curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:9900/~~ ← 🔴 같은 이유로 통과시킨다
node web/tools/deploy-screen.mjs --check --port 9900

### 🔴 0.5.3 실행 주체 — **화면 배포는 socket 또는 root 가 친다. web 이 아니다**

`~/parking-bin` 은 프로젝트 밖이라 **web-engineer 는 소유권 훅에 막힌다**(`outside_project_owner: root`).
**주체를 안 적으면 "웹이 하겠지"로 읽히고 아무도 안 한다.**

확인 : node web/tools/deploy-screen.mjs --check    ← 누구나(읽기만 한다)
```
⚠ **socket 이 `cp` 를 칠 수 있다는 것은 오늘 실측으로 확인됐다**(§4.2 정정). 그러나
**칠 수 있다는 것과 쳐도 된다는 것은 다르다** — 실물 교체는 루트 신호를 받고 한다(§0).

⚠ **`--webroot` 가 들어가면 §0.5.1~0.5.3 이 전부 사라진다.** 근본 대책이고
`docs/net/ARCHITECTURE.md` 에 미해결로 올라 있다. **A[1]·A[2] 배포·측정 뒤 순서다**(루트 확정).

⚠ **`--webroot` 가 생기면 이 항목은 사라진다.** 그전까지는 **배포마다 확인한다.**

🔴 **그리고 이것이 §4-5 의 "보호"를 없앴다.** 예전에는 운영에서 화면이 안 떠서
**브라우저가 운영 WS 에 못 붙는 것이 사고 방지로 작동**했다. 이제 붙는다 —
**정상 사용이지만, 예약을 누르면 하행이 나가고 하행은 링크를 끊는다**(원장 §8.14).
**관측 창이 도는 동안 운영 화면에서 예약을 누르지 마라.**

⚠ **이 트레이드는 창 안에서만 성립한다.** 창 밖이면 **반대로 정한다** —
**소스에 남은 틀린 근거는 그것을 읽고 고칠 사람에게 직접 간다.**
**명세를 안 읽고 코드만 보는 사람이 정상이다.**

## 0.6 🔴 **"이 커밋들 배포해야 하나?"** — 산출물로 답한다 (2026-08-19 신설)

**미배포 커밋 목록을 보고 판단하지 마라.** 커밋이 있다는 것과 **거동이 바뀌었다**는 것은 다른 진술이다.
리팩터링·시험 추가·문서만 있는 커밋이 섞이면 목록은 길고 기능 변화는 `0` 일 수 있다.

```bash
DEPLOYED=<도는 build= 해시>        # ← `=== INSTANCE` 줄에서 값으로 읽어라. 기억 말고
rm -rf /tmp/dep_a /tmp/dep_b; mkdir -p /tmp/dep_a /tmp/dep_b
git archive $DEPLOYED 조별과제샘플/server | tar -x -C /tmp/dep_a
git archive HEAD     조별과제샘플/server | tar -x -C /tmp/dep_b

# 🔴🔴 **이 단계가 핵심이다** — 시험 코드를 배포본 것으로 되돌린다.
#   안 하면 시험 변경이 `.o` 를 흔들어 **답을 가린다**(시험은 같은 TU 에 컴파일된다).
#   ⚠ **파일 이름을 목록으로 적지 마라 — 낡는다.** 범위로 잡아라:
cp /tmp/dep_a/조별과제샘플/server/selftest*.h /tmp/dep_b/조별과제샘플/server/

cd /tmp/dep_a/조별과제샘플/server; c++ -std=c++11 -O2 -w -DBUILD_ID='"X"' -c -o /tmp/dep_a.o server.cpp
cd /tmp/dep_b/조별과제샘플/server; c++ -std=c++11 -O2 -w -DBUILD_ID='"X"' -c -o /tmp/dep_b.o server.cpp
cmp /tmp/dep_a.o /tmp/dep_b.o
```
```
cmp exit 0  → **기능 변화 0. 배포할 이유가 없다** (창을 깨지 마라)
cmp 차이    → 무언가 바뀌었다. 무엇인지는 이것이 안 알려 준다 — 그건 별개의 조사다
```

### ✅ 이 판별자는 **양쪽 다 실측했다** (2026-08-19)

**한 방향만 본 판별자는 검증된 것이 아니다.** `cmp 0` 만 계속 보면
*"이 절차가 차이를 잡을 수 있는가"* 는 **한 번도 안 물어본 것**이 된다.
```
순수 이동 12커밋 (server.cpp 6,321→262줄, 파일 17개로 분해)  → cmp **exit 0**
진짜 변경 1커밋  (노드 대장 · 코드 +625줄)                    → cmp **exit 1**
                                                              .o 가 515,184 → 550,872B
```
> ### **`0` 도 내고 `1` 도 낸다. 그래야 `0` 이 의미를 갖는다.**

🔑 §"조건을 적었으면 그것을 보는 감시를 만들어라" 의 짝이다 —
**감시를 만들었으면 그것이 *울리는 것* 도 봐야 한다.** 오늘 자가검증 ㉟ 에도 같은 것을 했다
(사고를 일부러 재현해서 빨강이 뜨는 것을 확인했다).

### 왜 `git diff` 로 안 되나

**된다. 다만 그건 다른 질문에 답한다.**
> ### **`git diff` 는 "내가 무엇을 바꿨나"의 기록이고, `.o` 는 *산출물* 의 기록이다.**
> ### **`.o` 에는 주체가 없다 — 컴파일러가 답한다.**

⚠ 우리는 **"내가 안 했다"** 형태로 2026-08-19 하루에 두 번 틀렸다
(§"'안 했다'는 자기 행동의 기록이지 시스템 상태의 기록이 아니다" · 원장 (97)).
`diff` 도 **여전히 "내 행동"** 이다. 한 겹 더 내려가면 주체가 사라진다.

### ⚠ `.o` 대조가 **못 잡는 것**

```
· 바이너리 배치 변화(캐시·정렬) — `.o` 가 같아도 링크 결과는 49바이트 다르다(§2.1)
  🔑 그래서 **"배포해도 안전하다"가 아니라 "배포할 이유가 없다"** 로만 쓴다
· `-DBUILD_ID` 로 심는 해시 — 그래서 위에서 양쪽 다 `"X"` 로 고정한다
· 헤더가 아닌 자원(index.html · data_log.json) — §0.5.1 계열이 따로 본다
```

### 🔑 범위로 적는 이유 — 그리고 **범위를 넓히지 말고 이름을 맞춰라**

시험 파일이 **하나였다가 여섯 개가 됐다**(2026-08-19). **파일 목록을 적으면 그날부터 낡고,
낡은 목록은 조용히 통과한다** — 안 되돌린 시험 파일이 `.o` 를 흔들면 **"기능이 바뀌었다"는
거짓 양성**이 나오고, 그러면 **필요 없는 배포를 한다.**

🔴 **그런데 범위도 낡는다.** 실제로 그랬다:
```
범위를 `selftest*` 로 적었다  →  같은 날 쪼갠 조각들을 `st_downq.h` 로 이름 지었다
→ **범위가 새 파일을 하나도 안 잡는다.** 절차서를 쓴 사람이 한 시간 뒤에 만든 구멍이다
```
> ### **고칠 때 범위를 `st_*` 까지 넓히는 것은 잘못된 수리다. 다음에 또 다른 접두사가 생긴다.**
> ### **범위를 넓히지 말고 *이름이 범위를 만족하게* 고쳐라.**

**그래서 다섯 파일을 `selftest_downq.h` … 로 바꿨다.** 이제 `selftest*` 가 **구조적으로** 전부 잡고,
**앞으로 만드는 시험 조각도 그 이름 규칙만 지키면 자동으로 잡힌다.**

### ⚠ 이 절차의 **암묵 전제** — 실제로 돌려 보고 찾았다 (2026-08-19)

되돌리기는 **파일을 덮어쓰는 것**이지 지우는 것이 아니다. 배포본에 없던 조각 파일들은
`/tmp/dep_b` 에 **그대로 남는다.** 그래도 답이 맞는 이유는 하나다:

> **되돌린 `selftest.h` 가 그 조각들을 `#include` 하지 않으므로 컴파일에 안 들어간다.**

🔴 **그러니 이 전제가 규칙이 된다:**
> ## **시험 조각은 시험 파일에서만 `#include` 되어야 한다.**
> 실기 파일이 시험 조각을 하나라도 include 하면 **되돌려도 안 되돌아간다** —
> 그리고 그때 `.o` 차이는 **"기능이 바뀌었다"로 읽힌다.** 원인이 반대인데 결론이 같은 모양이다.

🔑 **적어만 두지 말고 한 번 돌려 봐라.** 이 전제는 절차를 *쓸 때* 는 안 보였고
**실제로 실행해서 `/tmp/dep_b` 안을 눈으로 보고서야** 나왔다.

### 🔴 그러므로 이것이 규칙이다

> ## **자가검증 코드가 들어가는 파일은 이름이 `selftest` 로 시작해야 한다.**
> **이 절차의 정확성이 그 이름에 걸려 있다.**

🔑 §"조건을 확인하는 것보다 조건이 성립할 수밖에 없게 만드는 쪽이 낫다" 의 적용이다
(web 이 `open_gate` 검사를 고친 방식과 같다 — 검사가 조건을 고르게 만들었다).
⚠ **확인으로 막으면 다음 사람이 확인을 잊는다. 이름으로 막으면 잊을 것이 없다.**

## 1. 커밋이 먼저다 — `build=` 가 깨끗한 해시여야 한다

LEDGER §6.1. `build=<sha>-dirty` 면 **도는 것이 어느 소스인지 특정할 수 없다.**

```bash
git status --porcelain 조별과제샘플/     # 비어 있어야 한다
git rev-parse --short HEAD               # ← 이 값을 BUILD_ID 로 넘긴다
```

⚠ **`git rev-parse` 는 워킹트리가 더러워도 `-dirty` 를 안 붙인다.** 다른 도메인 파일
(`monitor/**` 등)이 수정 중인 것은 상관없지만, **`조별과제샘플/` 이 더러우면 그 해시는 거짓말이다.**
그래서 위 두 명령을 **반드시 짝으로** 친다.

3. 🔴 **`PPID=1`** — 이게 아니면 세션이 죽을 때 서버가 같이 죽는다. **다시 띄워라**
4. **실왕복 1회** — 실물 보드가 붙어 있으면 `←ARD S` 프레임이 들어오는 것으로 갈음한다.
   보드가 없으면 `fake_arduino` 를 **운영 포트에 붙이지 마라.** 그건 가짜 자료를 운영
   로그에 남기는 짓이다(도구가 이제 거부한다 — 원장 §8.2). 보드 접속을 기다린다.
5. 🔴🔴 **봉투를 떠서 키 목록을 눈으로 본다** — "서버가 떴다"로는 이 부류가 안 잡힌다

```bash
python3 net/ws_probe.py --port 9900 --allow-production --raw --listen 3 \
  | grep -a '"type":"map"' | head -c 400
```
**보여야 하는 것**: `"type":"map"` · `"epoch":` · `"grid":` · **`"zones":[`**
(`state` 는 `"ts_ms":` 와 `"zones":[`)

**왜 이게 §4.4 에 있나** — 2026-08-19 `572a4cb` 이 **`"zones"` 대신 `"lot.zones()"`** 를
키로 내보냈다. **위 1~4 가 전부 통과했다**: 해시 깨끗, 세 포트 리슨, `PPID=1`, `←ARD S` 정상.
**프레임도 정상적으로 나갔다. 그 안이 틀렸다.** 화면 격자가 10분 27초 동안 통째로 안 보였고
**잡은 것은 web 이 전선 원문을 뜬 것**이었다.

> ### **§0.5.1-정정("존재형은 유물을 통과시킨다")의 한 겹 안쪽이다.**
> **거기서는 *파일이 있다*가 통과시켰고, 여기서는 *프레임이 나간다*가 통과시켰다.**
> ### **존재를 묻지 말고 내용을 봐라.**

⚠ **자가검증으로 갈음하지 마라.** 서버는 자기 JSON 을 자기가 파싱하지 않는다(web 이 짚었다).
**그리고 더 나쁜 경우가 있다** — 시험의 기대값이 코드와 *같은 도구로* 바뀌면 **둘이 같이 틀린다.**
그때 자가검증은 초록이다(그날 114개 전부 초록이었다). 🔑 **받는 쪽만 볼 수 있다.**

세션을 가로지르는 재부팅을 **서버가 실시간으로 갈랐다.** 예전에는 `ard_uptime` 을 버려서

## 8. 하면 안 되는 것

- **오프셋 없이 시험 인스턴스를 띄우는 것** — 실물 보드가 붙는다
- **`ws_probe`/`fake_arduino` 를 `--port` 없이 실행** — 기본값이 운영 포트다
- **운영 포트에 `fake_arduino` 를 붙이는 것** — 가짜 자료가 운영 로그에 남는다
- **재빌드해서 배포** — 검증한 산출물이 아니게 된다
- **`INSTANCE-END` 부재를 "살아 있다"로 읽는 것** — pid 로 판정한다(LEDGER §1.2)
- **A 창 자료와 새 창을 한 표에 넣는 것**

## 9. 이 절차서를 쓰면서 실제로 잡은 것 셋

절차서를 **실행하며** 썼기 때문에 나온 것들이다. 읽고 썼으면 셋 다 놓쳤다.

1. **`reason=signal` 은 존재하지 않는다** — `REQ-0118` §3-2 가 틀렸다(§4.1).
   그대로 따랐으면 정상 종료를 실패로 오판했을 것이다. 루트가 정정했다(취소선 + RESUME §7.0).

   ⚠ **그리고 나는 이 지적을 하면서 귀속을 절반 틀렸다.** 처음에 *"RESUME §7 과 REQ-0118 둘"*
   이라고 적었는데 **RESUME 에는 그 문장이 없었다**(루트가 `grep` 으로 반증 · 나도 재확인).
   **열어 보지 않고 셌다.** 내용이 맞아도 위치가 틀리면 다음 사람이 **없는 문장을 찾는다** —
   결함을 지적할 때도 근거를 세는 규칙은 똑같이 적용된다(LEDGER 규칙 ①).
2. **`ws_probe.py` 의 포트 기본값이 운영 포트(9900)** — 시험 절차 안에 운영 접촉 경로가
   숨어 있었다(§3.1).
3. **cwd 가 `GET /` 의 성패를 가른다** — `--webroot` 부재의 실제 영향이 "화면이 안 뜬다"라는
   것이 배포 직전에야 드러났다(§4.3). 결정이 필요한 항목이라 루트에 올린다.
