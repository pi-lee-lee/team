## 1. 커밋이 먼저다 — `build=` 가 깨끗한 해시여야 한다

LEDGER §6.1. `build=<sha>-dirty` 면 **도는 것이 어느 소스인지 특정할 수 없다.**

```bash
git status --porcelain 조별과제샘플/     # 비어 있어야 한다
git rev-parse --short HEAD               # ← 이 값을 BUILD_ID 로 넘긴다
```

⚠ **`git rev-parse` 는 워킹트리가 더러워도 `-dirty` 를 안 붙인다.** 다른 도메인 파일
(`monitor/**` 등)이 수정 중인 것은 상관없지만, **`조별과제샘플/` 이 더러우면 그 해시는 거짓말이다.**
그래서 위 두 명령을 **반드시 짝으로** 친다.

## 2. 빌드 — 경고 0

```bash
cd /Users/idong-u/learn/조별과제샘플
c++ -std=c++11 -O2 -Wall -Wextra -DBUILD_ID='"<sha>"' -o server_test server.cpp
```

- **`-DBUILD_ID` 를 빼지 마라.** 빼면 `unknown-source(compiled …)` 로 찍혀
  귀속이 끊긴다(§L280 주석이 그 사실을 값 자체로 드러내게 해 뒀다).
- `-Wall -Wextra` 로 **경고 0** 이어야 한다(REQ-0118 조건). 2026-08-16 `22f788d` 실측 0건.
- 산출물 이름 `server_test` 는 `.gitignore` 에 있다. **레포에 커밋되지 않는다.**

```bash
./server_test --selftest
```

→ 마지막 줄이 **`자가검증 통과`** 여야 한다. RFC 6455 §1.3 벡터 · 라인 체크섬 22종 ·
§7.4-A 재부팅 판정식 8종 · §7.4-B `resync` 호출 횟수 4종이 전부 `✓` 다.

## 3. 🔴 시험 인스턴스에서 먼저 돌린다 — 운영 포트를 절대 먼저 잡지 않는다

```bash
cd /Users/idong-u/learn/조별과제샘플
./server_test --port-offset=100          # 10091 · 10000 · 5600
```

**왜 오프셋이 필수인가**: 지금 이 순간에도 실물 ESP 가 **9991 로 재접속을 재시도 중**이다.
오프셋 없이 뜨면 그 보드가 시험 서버에 붙는다 — **기록되지 않은 개입 + 가짜 관측 경계**이고,
2026-08-16 에 4시간을 잃은 것이 정확히 그 형태다.

포트가 실제로 갈렸는지 **눈으로 확인한다**(경계 줄만 믿지 마라):

```bash
lsof -nP -iTCP -sTCP:LISTEN -p <pid>
```

기대: `*:10091` · `*:10000` · `*:5600`. **9991 이 보이면 즉시 죽여라.**

### 3.1 시험 왕복 — 넷 다 통과해야 한다

```bash
python3 net/fake_arduino.py --port 10091 --start-empty --interval 1.0   # 별도 창
python3 net/ws_probe.py --port 10000 --reserve A1 --listen 4
```

| 확인 | 기대 |
|---|---|
| WS 핸드셰이크 | `Accept … → 일치` |
| 예약 왕복 | `{"type":"ack",…,"result":0}` **그리고 그 뒤 `A1:01`** |
| `last_frame_ts` | 13자리 epoch ms, 매 프레임 갱신 |
| HTTP 세 줄 | 아래 |

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:10000/
curl -s -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:10000/index.html?demo=1"
curl -s -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:10000/?demo=1"
```

→ **200 · 200 · 200.** 세 번째가 REQ-0132 로 고친 것이다(전에는 404).

🔴 **`ws_probe.py` 의 `--port` 기본값은 9900 — 운영 포트다.** 빼먹으면 시험한다고 치면서
운영에 붙는다. **매번 명시해라.** (`fake_arduino.py` 도 기본값 9991 로 같은 함정이다.)

### 3.2 도달 확인은 ACK 가 아니라 마스크로 한다

LEDGER §3.1. ACK 는 "받았다"까지만 말하고, `reserved` 마스크 변화가 "그에 맞게 동작했다"를 말한다.
`ws_probe` 출력의 `slots =A1:01` 이 그 증거다.

## 4. 배포 — 신호를 받은 뒤에만

### 4.1 구 인스턴스 정지

**지금(2026-08-16 23:5x)은 선행 인스턴스가 없다.** pid 75781 은 **21:05:10 머신 재부팅으로
이미 죽었다.** 그러므로 이번 배포는 **아래 (b) 갈래**다.

**(a) 살아 있는 인스턴스가 있을 때**

```bash
kill -TERM <pid>
```

→ 로그 마지막에 `=== INSTANCE-END … reason=normal … ===` 이 남는다.

> 🔴 **`reason=signal` 을 찾지 마라. 그런 값은 존재하지 않는다.**
> `REQ-0118` §3-2 가 *"`INSTANCE-END reason=signal` 이 남아야 한다"* 고 적었는데
> **소스에 그 문자열이 없다.** 실제 값은 둘뿐이다:
> `reason=normal`(L2556) · `reason=port_bind_fail`(L2151).
> SIGTERM·SIGINT 는 둘 다 `g_stop=1` 로 정상 루프 종료를 태우므로 **`normal` 이 정상이다.**
> 실측 확인 2026-08-16 23:35:31 (`pkill -TERM` → `reason=normal frames=0 sessions=0`).
> **`signal` 을 기다리면 멀쩡한 종료를 실패로 오판한다.**

**(b) 선행 인스턴스가 없을 때 — 이번이 그렇다**

죽었다는 것을 **pid 와 포트로** 확인한다. **로그로 확인하지 마라** — LEDGER §1.2:
`SIGKILL`·정전·재부팅은 `INSTANCE-END` 를 남길 기회를 주지 않는다. 21:05 이 정확히 그 경우라
**그 인스턴스에는 END 줄이 영원히 없다.**

```bash
ps -p 75781                              # 없어야 한다
lsof -nP -iTCP -sTCP:LISTEN              # 9991·9900·5500 이 없어야 한다
```

### 4.3 🔴 기동 — **어느 디렉터리에서 띄우는지가 동작을 바꾼다**

`serve_file()` 과 `data_log.json` 쓰기가 **둘 다 현재 작업 디렉터리 기준 상대경로**다.
`--webroot` 옵션은 **아직 없다**(REQ-0135 §3-(7) 의 "아직 안 고친 것").

| cwd | `data_log.json` | `GET /` |
|---|---|---|
| `~/parking-bin` (**직전 운영과 같음**) | `~/parking-bin/data_log.json` | **404** — index.html 이 거기 없다 |
| `조별과제샘플/` | 레포 안에 쓴다 | 200 |

🔴 **이건 내가 임의로 정하지 않는다 — 루트가 정할 것이다.**
바꾸면 `data_log.json` 경로가 이동해 **폴백 경로와 관측 기준선이 같이 움직인다.**
**기본은 직전과 동일하게(`~/parking-bin`) 간다** — 배포에 변경을 하나만 넣기 위해서다(LEDGER §6).
화면 서빙은 별도 건으로 `--webroot` 를 넣어 고친다.

```bash
cd ~/parking-bin
./srv_parking
```

### 4.4 확인 — 셋 다

```bash

```

1. **경계 줄**에 `build=<sha>` 가 **깨끗한 해시**로 찍혔는가(`-dirty` 없음)

3. **실왕복 1회** — 실물 보드가 붙어 있으면 `←ARD S` 프레임이 들어오는 것으로 갈음한다.
   보드가 없으면 `fake_arduino` 를 **운영 포트에 붙이지 마라.** 그건 가짜 자료를 운영

## 5. 통보 — 배포는 통보까지가 한 단계다

`req.sh notice` 로 남기고 monitor·루트에 포인터를 보낸다. **반드시 들어갈 것:**

- **기동 시각**(초 단위) · 새 pid · `build=<sha>`
- **이 창은 A 창과 합산 금지**라는 것과 **그 이유**:
  이음매 1 이 **아두이노 상행 경로**(`DeviceEvent` 4/6)를 건드렸고, **바로 그 경로의 거동을
  재고 있다.** "안 바뀔 것이다"는 "안 바뀐다"가 아니다.
  → **λ 를 배포 경계 너머로 합치지 마라.**
- 무엇이 새로 들어갔는가(아래 §6)

## 8. 하면 안 되는 것

- **오프셋 없이 시험 인스턴스를 띄우는 것** — 실물 보드가 붙는다
- **`ws_probe`/`fake_arduino` 를 `--port` 없이 실행** — 기본값이 운영 포트다
- **운영 포트에 `fake_arduino` 를 붙이는 것** — 가짜 자료가 운영 로그에 남는다
- **재빌드해서 배포** — 검증한 산출물이 아니게 된다
- **`INSTANCE-END` 부재를 "살아 있다"로 읽는 것** — pid 로 판정한다(LEDGER §1.2)
- **A 창 자료와 새 창을 한 표에 넣는 것**

## 9. 이 절차서를 쓰면서 실제로 잡은 것 셋

절차서를 **실행하며** 썼기 때문에 나온 것들이다. 읽고 썼으면 셋 다 놓쳤다.

1. **`reason=signal` 은 존재하지 않는다** — `REQ-0118` §3-2 가 틀렸다(§4.1).
   그대로 따랐으면 정상 종료를 실패로 오판했을 것이다. 루트가 정정했다(취소선 + RESUME §7.0).

   ⚠ **그리고 나는 이 지적을 하면서 귀속을 절반 틀렸다.** 처음에 *"RESUME §7 과 REQ-0118 둘"*
   이라고 적었는데 **RESUME 에는 그 문장이 없었다**(루트가 `grep` 으로 반증 · 나도 재확인).
   **열어 보지 않고 셌다.** 내용이 맞아도 위치가 틀리면 다음 사람이 **없는 문장을 찾는다** —
   결함을 지적할 때도 근거를 세는 규칙은 똑같이 적용된다(LEDGER 규칙 ①).
2. **`ws_probe.py` 의 포트 기본값이 운영 포트(9900)** — 시험 절차 안에 운영 접촉 경로가
   숨어 있었다(§3.1).
3. **cwd 가 `GET /` 의 성패를 가른다** — `--webroot` 부재의 실제 영향이 "화면이 안 뜬다"라는
   것이 배포 직전에야 드러났다(§4.3). 결정이 필요한 항목이라 루트에 올린다.
