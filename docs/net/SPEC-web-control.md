# 화면에서 모듈을 직접 조작한다 — 계약 (1단계)

> 사용자 ①: *"web을 통해서 **직접 컨트롤** 할 수 있도록 해달라."*
> 사용자 ②: *"만들 때 **모든 센서에 활용가능**하도록 만들자. 혹시 **기여자 코드에서 작성된 코드를
> 기준으로 호출하는 방식**이 이용가능한가?"*

작성: socket-engineer · 2026-08-20 · **이름·형식·시점·계산 주체를 전부 여기서 못 박는다.**
🔴 **빈 자리를 남기지 않는 것이 이 문서의 목적이다** — 비면 화면이 메우고, 그 순간 정의가 둘이 된다.

---

## §0 🔴 설계의 중심 — **뜻을 아는 사람이 선언한다**

우리 계약은 *"값의 뜻을 서버도 프로토콜도 모른다"* 이다. 그래서 막혔었다:
**화면이 뜻을 모르는데 UI 를 어떻게 정하나.**

```
❌ 화면이 `kind` 로 정한다 (`OG`=토글 · `OL`=숫자 · `OB`=열기/닫기)
   → 🔴 kind 가 늘 때마다 **화면을 고쳐야 한다.** 그리고 뜻은 화면 것이 아니다
❌ 화면에 "숫자 한 칸 + 보내기" 를 박는다
   → 안 깨지지만 **`DR` 에 1/2/3/4 를 외워서 쳐야 한다.** 명령표가 코드 주석에만 있다
✅ 🔴 **기여자가 `lot.cpp` 에서 선언하고, 화면은 그대로 그린다**
```

> ### **`choice` 선언이 곧 명령표다.**
> 지금은 그 표를 **서버 주석과 장치 주석 두 곳**에 똑같이 적으라고 했다.
> **선언으로 만들면 화면이 그것을 그리고, 표가 한 곳이 된다.**

🔑 그리고 `router.on(...)`·`sensors.on(...)` 과 **같은 계열**이라 기여자가 한 번만 배운다.

### ⚠ "모든 센서에 활용 가능하도록" 을 이렇게 읽었다
**`control` 은 모듈 종류를 안 가린다** — `kind` 가 `IP`(센서)든 `OG`든 선언할 수 있다.
*"차단봉 전용이던 조작 경로를 모든 모듈로 넓혀라"* 로 읽은 것이다.
🔴 **다르게 뜻한 것이면 말해 달라** — 지어내지 않고 읽은 방식을 적어 둔다.

## §1 기여자가 쓰는 것 (`lot.cpp`)

```cpp
lot.control("P1","LD").toggle("표시등");                       // 0 / 1
lot.control("P1","LC").number("표시기", 0, 9999999);           // 숫자 칸 + 범위
lot.control("P1","DR").choice("차단봉")                        // 🔑 이것이 명령표다
        .option(1,"열기").option(2,"닫기").option(3,"잠금").option(4,"해제");
```
- **선언하지 않은 모듈은 화면에 조작 UI 가 없다.** `state` 에 표시만 된다.
  🔑 `sensor`/`actuator` 의 *"선언 안 한 것은 꺼진 것"* 과 같은 규칙이다.
- **위젯은 셋뿐이다.** 늘리지 마라 — 화면이 아는 것은 **입력 형태**뿐이고 **뜻은 라벨로만** 온다.

⚠ `option()` 을 `{{1,"열기"},…}` 대신 **연쇄**로 둔 이유: 초기화 리스트는 초급자가
중괄호를 틀리기 쉽고 오류 문구가 길다. **`sensor().actuator()` 와 같은 모양**이 낫다.

## §2 화면 → 서버

### §2.1 `send_cmd` — 단건
```json
{"type":"send_cmd","rid":"<화면이 만든 요청 id>","devid":"P1","module":"LD","value":1}
```
| 키 | 형 | 규칙 |
|---|---|---|
| `rid` | 문자열 | 화면이 만든다. 응답이 이 값을 그대로 돌려준다 |
| `devid` | 문자열 | 1~8자. `map` 의 `modules[].devid` 를 그대로 |
| `module` | 문자열 | **정확히 2바이트 ASCII**. `map` 의 `modules[].name` |
| `value` | 정수 | 서버가 **선언된 범위**로 검사한다(§5) |

🔴 **선언 안 된 모듈에 보내면 거절한다**(`not_declared`). 화면 버그가 조용히 통과하지 않게.

### §2.2 `send_batch` — 묶음
```json
{"type":"send_batch","rid":"w2","devid":"P1",
 "items":[{"module":"LD","value":1},{"module":"LC","value":1234567}]}
```
🔴 **상한을 넘기면 한 건도 안 나간다. 자동 분할 안 한다** — 쪼개면 두 창에 걸쳐 나가고
**묶은 뜻이 사라진다.** 상한은 화면이 상수로 갖지 마라 — `state.max_per_batch` 가 그 순간 값이다.

## §3 서버 → 화면

### §3.1 `map` 의 모듈에 붙는 것 — **조작 선언**
```json
{"devid":"P1","name":"DR","kind":"OB","idx":4,
 "control":{"widget":"choice","label":"차단봉",
            "options":[{"value":1,"label":"열기"},{"value":2,"label":"닫기"}]}}
```
| `widget` | 같이 오는 키 | 화면이 그리는 것 |
|---|---|---|
| `"toggle"` | — | 켬/끔 두 버튼 (`1`/`0` 을 보낸다) |
| `"number"` | `min`,`max` | 숫자 칸 + 보내기. 범위 밖은 화면이 먼저 막아도 된다 |
| `"choice"` | `options[]` | 버튼 N개. **`label` 을 그리고 `value` 를 보낸다** |

- 🔴 **`control` 키는 선언된 모듈에만 있다.** 없으면 조작 UI 를 그리지 않는다(존재/부재 규칙).
- **언제 오나**: `map` 봉투 — **접속 시 1회 + `get_map` 요청 시**. 선언은 기동 후 안 바뀐다.
- **계산 주체**: **서버**. 화면은 `kind` 를 해석하지 않는다.

### §3.2 `state` 의 모듈에 붙는 것 — **지금 값**
```json
{"devid":"P1","name":"LC","idx":3,"known":true,"value":false,
 "requested":1234567,
 "confirmed":"partial",
 "cmd":{"ok":true,"reason":null}}
```
| 키 | 계산 주체 | 뜻 |
|---|---|---|
| `value` | 서버 | 🔴 **장치가 에코한 비트.** `known:false` 면 뜻이 없다 |
| `requested` | 서버 | 서버가 **마지막으로 보낸 값**. **보낸 적 없으면 키가 없다** |
| `confirmed` | 서버 | 🔴 **§4.** 화면은 **이 키 하나로 분기한다** |
| `cmd` | 서버 | `{"ok":bool,"reason":null\|"코드"}` — 지금 보낼 수 있나 |
| `max_per_batch` | 서버 | 봉투 **최상위**. 묶음 상한(지금 4) |

**언제 오나**: `state` 는 **주기적으로** 온다. 접속 시 1회가 아니다 — 사본이 안 낡는다.

### §3.3 🔴 `cmd_result` — **새 타입이다. `ack` 에 얹지 않는다**
```json
{"type":"cmd_result","rid":"w1","devid":"P1","module":"LD","value":1,
 "outcome":"ok","result":0,"message":"명령이 적용되었습니다"}
```
| `outcome` | 뜻 | 🔴 **고치는 곳이 다르다** |
|---|---|---|
| `"ok"` | 장치가 받았고 콜백이 `true` 를 냈다 | — |
| `"rejected"` | 장치가 **답했고** 거절했다 | 값·등록을 고쳐라. **재시도는 뜻이 없다** |
| `"no_answer"` | **답이 없다**(재전송 소진) | 장치·링크 문제다. **화면 로직을 고쳐도 안 낫는다** |

- `result` : 장치가 준 `result`. `no_answer` 면 **-1**
- **언제 오나**: 장치 ACK 도착 시(보통 1~3초) 또는 재전송 소진 시
- 🔴 **`ack` 에 얹지 않는 이유가 이 코드에 이미 적혀 있다**(seam.h §4-B):
  *"옛 화면이 `type==='ack'` 만 보고 pending 을 지우며 '예약되었습니다'를 띄운다 —
  **전선에 나가지도 않은 요청을 성공으로 선언한다.**"* **같은 함정이라 같은 답을 쓴다.**

### §3.4 `batch_result` — 묶음의 **접수** 결과 (즉시)
```json
{"type":"batch_result","rid":"w2","devid":"P1","queued":2,"rejected":0,"max":4}
```
⚠ **"보냈다"이지 "됐다"가 아니다.** 건별 결말은 `cmd_result` 로 따로 온다(`rid`+`module` 로 짝지어라).

### §3.5 재사용하는 것 — **새로 만들지 않았다**
`queued`(⚠ `slot` 이 **`null`** 일 수 있다 — 모듈 명령은 자리가 없다) · `error`

## §4 🔴 `confirmed` — web 이 찾은 빈 자리에 답한다

> web: *"`value` 가 `bool` 이라 **7654321 을 보냈는데 그렇게 됐나**를 못 잰다."*
> ### **맞다. 그리고 지금은 넓힐 수 없다 — 서버 선택이 아니라 전선 사실이다.**

```
상행 `S` 의 모듈 상태는 **비트마스크**다 — `decode_mod_bits(f[2], mod_state)`
🔴 **모듈당 1비트.** 숫자를 실을 자리가 전선에 **없다**
```

### 닫힌 값 다섯
```
"pending"   내가 건 명령이 아직 떠 있다
"settled"   🔴 에코가 요청과 **완전히** 부합한다 — 값이 0/1 인 모듈만 여기 올 수 있다
"partial"   🔴 **숫자 모듈.** 에코 비트가 "0이 아니다"만 말한다.
            **"1234567 이 됐다"는 확인되지 않았다**
"mismatch"  요청과 에코가 다르다. 장치가 못 했거나 되돌아갔다
"unknown"   보낸 적이 없거나 비트를 못 읽었다
```
- ✅ **`pending`·`settled`·`mismatch`·`unknown` 은 자리(`zone.completion`)의 어휘를 그대로 썼다.**
  **`partial` 만 새로 붙였다** — 그 사실을 여기 적어 둔다(나중에 충돌하면 이게 근거다).
- 🔴 **숫자 모듈은 `settled` 를 절대 내지 않는다.** 낼 수 없으니까.

### ⚠ 왜 `value` 를 숫자로 안 넓혔나
넓히면 **`known:false`(모른다)를 `known:true`(안다·틀림)로 바꾸는 것**이다.
값 경로가 없는데 값을 만들면 그게 **지어내는 것**이다.
🔑 **정직한 무지를 없애는 수정은 값 경로를 먼저 만들고 해야 한다.**

### 화면이 그릴 것 (권고)
```
❌ "표시기: 1234567 로 설정됨"        ← 🔴 **거짓 완료다**
✅ "표시기: **1234567 보냄** · 장치 에코 **켜짐** · ⚠ **값 확인 불가**"
```

### 🔴 2단계 — 이건 "언젠가"가 아니라 **닫는 조건이 있는 미결**이다
값 에코 줄(`E,<idx>,<val>,<ck>`)을 넣으면 `confirmed` 가 완전해진다.
**arduino 실측 비용: 평상 0B · 실릴 때 21B · RAM +22B.**
🔴 **상행 프레임 변경 = arduino 와 한 계약의 양끝**이라 **굽기가 필요하다. 1단계에 안 넣는다.**
**닫는 조건**: *"다음 굽기 경계."*

⚠ **이 요구는 어제 한 번 기각됐다** — 루트: *"요구가 없다. 7자리를 되돌릴 필요가 지금 없다."*
그리고 **arduino 가 그때 경고했다**: *"비트는 숫자를 못 나른다."*
🔑 **경고는 있었고 요구가 없어서 넘어갔다. 요구가 생기면 경고가 결함이 된다** —
**기각의 근거가 "필요 없다"였으면, 필요해진 날 그 항목이 자동으로 되살아나야 한다.**

## §5 거절 사유 코드 — **기존 어휘를 먼저 쓰고 없는 것만 새로 만들었다**

| `code` | 언제 | 새것? |
|---|---|---|
| `module_absent` | 그 `devid` 에 그 이름의 모듈이 없다 | 기존 |
| `device_offline` | 장치가 안 붙어 있다 | 기존 |
| `node_unregistered` | 등록(`D`)이 아직 안 끝났다 | 기존 |
| `bad_request` | 이름이 2바이트가 아니다 · `items` 가 비었다 | 기존 |
| `not_supported` | `idx` 가 자리 구간(0~9)이다 | 기존 |
| `rate_limited` | 너무 잦다 | 기존 |
| `ack_timeout` | 무응답 | 기존 |
| 🔴 `not_declared` | **`lot.cpp` 에 `control` 선언이 없는 모듈** | **새것** |
| 🔴 `out_of_range` | 선언된 `min~max` 나 `option` 값 밖 | **새것** |
| 🔴 `batch_too_big` | 묶음이 상한을 넘었다 | **새것** |

### ⚠ web 의 전제 하나를 정정한다
> web: *"**8자리**를 넣으면 `거절` 이 보여야 사용자가 연습이 된다"*

🔴 **8자리 자체는 안 거절된다** — 전선은 32비트를 나른다.
**거절을 밟는 길은 셋이다:** 선언 범위 밖(`out_of_range`) · 선언 안 된 모듈(`not_declared`) ·
묶음 5건(`batch_too_big`).
🔑 **"거절이 보여야 연습이 된다"는 web 의 지적은 맞다. 밟는 길만 바꿨다.**

## §6 화면이 확인할 것 — **긍정형으로 써라**
```
❌ "오류 문구가 안 뜬다"        → 대상이 없어도 참이다. **부정형을 쓰지 마라**
✅ `cmd_result.outcome` 이 셋 중 하나로 실제로 온다
✅ 보낸 건수 == `queued + rejected`
✅ 🔴 **분모가 0 이 아님을 따로 단언해라** — 모듈 목록이 비면 모든 대조가 공허하게 참이 된다
✅ 🔴 **숫자 모듈에서 `confirmed` 가 `settled` 로 온 적이 없다** — 오면 서버 결함이다
```

## §7 안 하는 것
- **자동 분할** · **`rejected` 의 자동 재발행**(재시도해도 같다) · **`value` 의 뜻 해석**
