# 개발자용 샘플 — 실기 검증 판정문

작성: socket-engineer · 2026-08-19 22:0x · **사용자 검토용**

## 0. 🔴 무엇을 배포하고 무엇을 쟀나 — 판이 둘이다

```
커밋       b15343b   (트리에 커밋된 판 = **기여자가 받는 것**)
칩         73868c4   (arduino 굽기 · 21:52:47 · hex 다른 바이트 0)

측정용 판  `b15343b+live2`   🔴 **루프 본문 주석 해제 1건**이 더 있다
           21:59:03 기동 · 6초마다 `LD`/`LC` 에 명령을 쏜다
정리 판    `b15343b`         22:00:07 기동 · **주석 처리된 판**(트리와 같다)
```
> ### 🔴 **재는 데 쓴 것과 커밋된 것이 다르다.** 차이는 **그 한 덩어리뿐**이다.
**켠 채로 커밋하면 기여자가 받는 샘플이 멋대로 명령을 쏜다.** 그래서 되돌렸다.

⚠ **21:57:19~22:00:07 구간은 서버가 스스로 하행을 냈다. "무자극"으로 읽지 마라.**

## 1. 판정 — 항목별

| | 항목 | 값 | |
|---|---|---|---|
| ① | 장치 등록 | `등록 완료 — n=5 · drain=7 · 명령가능 3개 (device=P1)` | ✅ |
| ② | 자리 하나 | `map` 의 `zones` = **1개**(`A1`) | ✅ |
| ③ | 센서 둘 결속 | `value_known 2 · value_total 2 · value_state "known"` | ✅ |
| ④ | 미결속 없음 | `미결속모듈 0/5` | ✅ |
| ⑤-a | 전선에 `G` | `→ARD G,932,3,1234567,7C` | ✅ |
| ⑤-b | 장치 콜백 | `←ARD A,932,G3,**0**` — **7자리가 성공했다** | ✅ |
| ⑤-c | ACK `result=0` | 위와 같음 · `LD` 도 `←ARD A,934,G2,0` | ✅ |
| ⑤-d | 거절 갈래 | `→ARD G,933,3,12345678` → `←ARD A,933,G3,**3**` | ✅ |
| — | 에코 | **재지 않았다** — 계약이 없다(아래 §3) | ⏳ |

**A1 에 붙은 모듈 5개**: `A1`·`B1`(IP, 센서) + `LD`(OG)·`LC`(OL)·`DR`(OB, 액추에이터).
🔑 **`value_total` 이 2 다** — 액추에이터가 점유 판정에서 정확히 빠진다.

## 2. 🔴 ⑤-d 의 함정을 순서로 닫았다

`result=3` 은 두 이유로 나올 수 있다:
```
ⓐ 8자리라서 장치가 거절했다        ← 확인하려던 것. **정상**
🔴 ⓑ 32비트 확장이 안 실렸다        ← 그러면 7자리도 못 받는다. **결함**
```
**가르는 것은 `1234567`(7자리)이 성공하는가다.** 그것을 **먼저** 쟀다:
```
21:59:10  →ARD G,932,3,**1234567**   →  21:59:11  ←ARD A,932,G3,**0**   ✅ ⓑ 배제
21:59:16  →ARD G,933,3,**12345678**  →  21:59:17  ←ARD A,933,G3,**3**   ✅ ⓐ 확정
```
> ### **순서가 거꾸로였으면 `result=3` 하나를 보고 잘못 안심했다.**
🔑 `1234567 > 65535` 이므로 **옛 16비트 인자로는 나올 수 없는 값**이다.
**서버의 `g_arg` 확장과 장치의 `parseU32` 가 짝으로 성립한 것이 이 한 줄로 증명된다.**

## 3. ⚠ **재지 않은 것** — 검토할 때 알아야 한다

```
🔴 에코(다음 상태 프레임으로 실제 적용 확인) — **계약이 없다.**
   `LD`·`LC`·`DR` 은 `occ` 비트에 상태를 안 싣는다(싣는 것은 가상 차단봉뿐).
   → 서버는 **"명령이 도착해 콜백이 성공했다"까지만** 안다.
   ⚠ *"표시등이 실제로 켜졌는가"* 는 **눈으로 보는 수밖에 없다.**
```
**이것을 어떻게 할지가 다음 설계 항목이다**(에코 비트를 액추에이터에도 두나 · ACK 로 충분한가 ·
별도 상태 칸인가). **계산 주체까지 같이 정해야 한다.**

```
그 밖에 안 잰 것
· 여러 장치 동시 접속 — 지금 보드가 하나다
· 자리 여럿 — 샘플이 하나만 켠다(주석을 풀면 늘어난다)
· 기여자가 `.behavior(...)` 를 실제로 꽂은 경우 — 자가검증으로만 봤다
```

## 4. 축 — 이상이 나오면 후보

이 창에는 **장치 축 셋 + 서버 축 하나**가 같이 실렸다.
```
장치 : dca2aa7 명령 수신을 CommandRouter 로 · 54bb00a 샘플 구성 + **인자 16→32비트** ·
       23b6465 샘플 액추에이터 셋 + 가상 차단봉 비트 위치
서버 : b15343b (샘플 · 대장 · 결속 검사 여섯 · 발행 API · 지형 7→1 · 모듈 12→5)
```
🔑 **셋을 못 나눈 이유는 "한 산출물의 부분"이라서다.** 서버 쪽은 나눌 수 있었지만
**전선 인자 확장이 장치 축 ②와 짝이라 같은 경계여야 했다.**
