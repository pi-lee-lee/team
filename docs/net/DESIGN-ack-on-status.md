# ACK 를 `S` 프레임에 얹는다 — 와이어 계약 변경 (설계)

> **사용자 결정**: *"ACK 로 동작을 확인하지 마라. ACK 는 수신 여부 확인용이다.
> 동작은 별도로 판단하라. 그리고 ACK 송신까지 시간을 짧게 만드는 게 핵심이다."*
>
> 작성 2026-08-17 · socket-engineer · **설계만. 구현·배포는 승인 뒤.**

## 0. 왜 — **장치 송신 횟수를 줄이는 것이 목적이다**

```
지금    하행 1건 → ACK 송신(약 113ms) + 다음 S 송신(약 113ms) = 장치 송신 **2회**
바꾸면  하행 1건 → 다음 S 에 얹는다                            = 장치 송신 **0회 추가**
```

🔑 **연속 예약 6건/10초 재현이 아예 안 생긴다.** 지금은 추가 송신 12회가 몰려 무너지는데,
바꾸면 추가 송신이 **0** 이다.
→ **우리가 설계하던 ACK 보류 큐는 우회이고, 이것은 원인을 없앤다.**

⚠ **`DESIGN-downlink-window.md`(하행 창)와 겹치지 않는다.** 그건 **서버→장치** 방향의
착지 위상 문제이고, 이건 **장치→서버** 송신 횟수 문제다. **다만 장치 송신이 줄면
UART 점유(duty 10.2%)도 줄어 하행 충돌 확률이 같이 내려간다** — 부수 효과다.

## 1. 필드 형식 — `@<rid>` **태그 방식**

```
지금   S,16626,0110000010,1000000000,19675,P1,3D
얹으면 S,16626,0110000010,1000000000,19675,P1,@31,3D
여러 건 S,16626,0110000010,1000000000,19675,P1,@31.32.33,3D
실패   S,16626,0110000010,1000000000,19675,P1,@31:2,3D
```

**문법**: `ack ::= "@" rid [":" result] *("." rid [":" result])`
`result` 는 **0 이 아닐 때만** 적는다(성공이 대부분이므로 바이트를 아낀다).

### 🔴 왜 `a<rid>` 가 아니라 `@<rid>` 인가

`devid ::= 1*8( ALPHA / DIGIT / "_" / "-" )` — **`devid` 가 `a` 로 시작할 수 있다**
(`server.cpp:890` · 명세 §2.3). `a31` 을 쓰면 **devid 와 구별이 안 되는 경우가 생긴다.**
**`@` 는 devid 문자집합에도, tmask(`0`/`1`/`-`)에도 없다** → **모호성이 원천적으로 없다.**

🔑 **위치가 아니라 태그로 식별한다.** `tmask` 가 이미 선택 필드라 위치 기반 파싱은
필드가 늘 때마다 깨진다. 태그 방식이면 **순서·존재 여부와 무관하게 찾을 수 있고,
옛 장치의 프레임은 그 필드가 없어서 자동으로 구 형식으로 읽힌다.**

### 용량 — **한 주기에 3건까지**

```
현재 S = 42바이트 · 한도 63바이트 → 여유 21바이트
@31       = 3바이트      @31.32.33   = 9바이트      @31:2.32.33 = 11바이트
```
→ **3건이면 넉넉하고 4~5건도 들어간다.**
⚠ **넘치면 오래된 것부터 싣고 나머지는 다음 `S` 로 미룬다.** 버리지 않는다.
→ 실무상 넘칠 일은 드물다 — 서버가 한 번에 그만큼 미결로 두지 않는다.

## 2. 🔴 `result` 를 어디로 — **루트 제안(별도 NAK)에 반대한다. 같은 필드에 넣자**

루트 제안: *성공 = 마스크가 증명 · 실패 = 별도 프레임(NAK)*.

**반대 이유 셋:**

1. 🔴 **NAK 는 "추가 송신"이다.** 이 설계의 목적이 **장치 송신 횟수를 0 으로 만드는 것**인데,
   실패 경로에서 송신이 되살아난다. **그리고 실패는 링크가 나쁠 때 몰린다** —
   **가장 붐빌 때 추가 송신이 생기는 구조**가 된다. 없애려던 것과 같은 모양이다.
2. **마스크가 증명하지 못하는 것이 있다.** `T`(무장 안 됨 `result=4`)는 **상태를 안 바꾼다** —
   마스크로는 성공/실패가 **원리적으로 구별 불가**다(원장 §7.6 이 그 성질을 이용했다).
3. **실패 코드가 사용자 문구를 가른다.** `1`(이미 점유) · `2`(이미 예약) · `3`(잘못된 자리)는
   **화면에 다른 말을 해야 한다.** NAK 가 유실되면 서버는 **"실패했는데 이유를 모름"** 이 된다.

**대안: `@<rid>[:<result>]` 한 필드로 끝낸다.**

| 경우 | 실린 것 | 바이트 |
|---|---|---|
| 성공(`result=0`) | `@31` | 3 |
| 실패 | `@31:2` | 5 |

→ **추가 송신 0회가 성공·실패 모두에서 유지된다.** 이것이 사용자 지시의 핵심을 지킨다.

⚠ **그래도 사용자 원칙은 지켜진다**: `@<rid>` 는 **"받았다"** 를 말하고,
**"동작했다"는 여전히 마스크가 증명한다.** `result` 는 **거절 사유**일 뿐 성공의 근거가 아니다.
→ 🔑 **서버는 성공을 `result=0` 으로 확정하지 않는다. 마스크 변화로 확정한다**(`5b9d967` 기준).

## 3. 재전송 판정 — **주기 단위로 바뀐다**

지금은 `A` 프레임을 **2초** 기다리고 3회 재전송한다. 바꾸면 **`@<rid>` 를 실은 `S`** 를 기다린다.

```
기대 지연 : 최대 1주기(약 1.113초) — 다음 S 에 실린다
재전송 문턱 : **2주기** (약 2.3초)   ← 1주기면 정상 지연에 걸려 헛재전송이 난다
최대 시도  : 3회 → 총 약 7초         ← 지금 ACK 타임아웃 6초와 같은 자리
```

🔴 **주기를 상수로 박지 마라.** 주기는 빌드·페이로드·ESP 응답의 함수다(원장 §8.11).
**`ard_last_ms` 로 실측 간격을 쓴다** — 서버가 이미 갖고 있다.

⚠ **장치가 조용하면(busy·리셋) `S` 가 안 오고 ACK 도 안 온다.** 지금도 같다 —
**새로 나빠지는 것은 없다.** 다만 **`ack_timeout` 의 의미가 "장치가 말을 안 한다"로 바뀐다.**

## 4. 멱등 캐시 — **그대로. 충돌 없다**

장치의 `rid` 캐시(§4.2)는 **중복 수신 방지**용이고 **ACK 를 어디에 싣는지와 무관**하다.
서버의 `wire_rid` 발급·`pend` 표도 안 바뀐다. **바뀌는 것은 "어느 프레임에서 읽는가" 뿐이다.**

⚠ 다만 **재수신 시 캐시가 돌려주는 것도 `@<rid>` 로 나가야 한다**(지금은 `A` 프레임 재전송).

## 5. 체크섬과 구/신 판별 — **판별이 체크섬보다 먼저다**

`verify_line()` 은 **첫 바이트부터 체크섬 앞 쉼표까지 XOR** 이라 **필드가 늘어도 그대로 성립**한다.
→ **체크섬 알고리즘 변경 없음.**

**순서**: ①길이 ②체크섬 ③타입 ④**`@` 필드 유무**(원장 §3.4 의 검사 순서 뒤에 붙는다).
🔑 **구 형식은 `@` 필드가 없을 뿐이라 지금 파서가 그대로 읽는다** —
**서버가 둘 다 받는 데 분기 하나면 된다.**

---

## 6. `M`·`T` 도 같은 처리 — 다만 `T` 에 주의

**같게 한다.** 경로를 나누면 **"어느 명령이 어느 방식으로 응답하나"를 아무도 못 외운다.**

🔴 **다만 `T` 는 이 변경으로 원장 §7.6 의 격리 검증 방법을 무효로 만든다:**

> §7.6 은 *"무장 안 한 `T,S` → `result=4` → **상태 불변 → 뒤따르는 `S` 가 없다** → 그래서
> 스냅샷을 만든 것은 `DEV_ACK` drain 뿐"* 이라는 논증이었다.
> **ACK 가 `S` 에 실리면 "ACK 만 오고 `S` 는 안 오는" 상황 자체가 사라진다.**

→ ⚠ **`DEV_ACK` 이관의 격리 검증을 다른 방법으로 다시 세워야 한다.**
**지금 당장 깨지는 것은 아니다**(이미 검증은 끝났다) — 하지만 **그 논증을 앞으로 인용할 수 없다.**
**원장 §7.6 에 이 사실을 적어야 한다.**

## 7. 내 1단계 — **서버가 구/신 둘 다 받는다**

원장 §6: **구/신 동시 수용 → 시각 통보 → 변경.**

- 서버는 `A` 프레임과 `@<rid>` **둘 다** 받아 같은 `pend` 처리로 보낸다
- **거동은 안 바뀐다** — 옛 장치는 `A` 를 계속 보내고 서버가 그대로 처리한다
- 🔑 **그래서 이 배포는 되돌릴 필요가 없고, 장치 굽기 순서와 무관해진다**

**남은 것(2단계, arduino)**: 장치가 `@<rid>` 로 보내고 `A` 를 멈춘다.

⚠ **배포는 관측 창 안이다** — `build=` 해시와 시각을 monitor 에 통보한다.
