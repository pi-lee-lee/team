# 이동 대비 — 망이 바뀔 때 서버 쪽에서 참인 것 (2026-08-18 18:00 이동)

**작성** socket-engineer · **범위** 서버·전선만. 펌웨어는 arduino 축, 관측은 monitor 축.

---

## 1. ✅ 서버는 **바인딩을 안 고쳐도 된다** — 코드로 확인했다

```cpp
// server.cpp · listen_on()
a.sin_addr.s_addr = INADDR_ANY;          // = 0.0.0.0
```
> ### **모든 인터페이스에 붙는다. PC 의 IP 가 바뀌어도 서버는 그대로 뜨고 그대로 받는다.**
**포트도 그대로다**: 아두이노 `9991` · HTTP/WS `9900` · 폰 `5500`.
→ **이동 후 서버 쪽에 필요한 조치는 "다시 띄우는 것"뿐이다.**

⚠ 단, **PC 의 새 IP 를 알아야 하는 쪽이 있다**(아래 2).

## 2. 🔴 장치는 `SERVER_IP` 를 **컴파일 상수**로 갖는다 → **펌웨어 재굽기 필요** (arduino 축)

**서버가 0.0.0.0 이라는 사실이 이 문제를 없애 주지 않는다.** 연결을 *거는* 쪽은 장치다.
```
PC 새 IP 확인 →  arduino 가 SERVER_IP 를 그 값으로 바꿔 재굽기 → 접속
```
🔑 **순서상 이것이 이동 후 첫 병목이다.** 서버는 먼저 띄워 둬도 된다(장치를 기다린다).

## 3. 🔴 **판단 항목 — 이동 후 첫 관측 전에 `--park-dev` 잠금을 걸 것인가**

**현재 상태: 잠금 미지정**(`계약값` 줄에 `노드잠금 (none, first-S-wins)`).

**새 망에도 조원 보드가 있을 수 있다.** 오늘 같은 망에서 **Espressif MAC 6대**를 봤다(`arp -a`).
```
잠금 없이 관측 시작 → 조원 `P1` 이 **먼저** S 를 보내면 그 보드가 주차 노드가 된다
                    → 우리는 보조 노드(상행 전용)로 밀려 **하행을 못 받는다**
                    → 🔴 지금보다 나쁘다
```
**대안 셋:**
```
(가) 잠금 안 건다        — 오늘과 같음. `devid거절` 계수와 IP 로그로 사후에 안다
(나) 잠금 건다           — arduino 와 devid 값을 맞춰야 한다(3자 이내 · S_worst 여유)
                           ⚠ 값이 어긋나면 **우리가 우리를 막는다**
(다) 먼저 관측, 오염 보이면 잠금 — 재기동만 하면 된다(**재빌드 불필요**)
```
🔑 **(다)를 권한다.** 잠금은 `--park-dev=<devid>` 인자 하나이고 **재빌드 없이 재기동으로 걸린다.**
**값을 잘못 박고 시작하는 위험이, 오염을 나중에 알아채는 위험보다 크다** — 오늘 자료가 그렇다:
**같은 망에 6대가 있었는데도 우리 서버에 붙은 것은 한 대뿐이었다**(IP 로그·uptime 연속으로 확인).

## 4. 🔑 이동 후 **첫 줄에서** 우리 보드인지 갈린다 — 오늘 넣은 IP 로깅

```
+? 연결 수락 — 상대 <IP:포트> · device_id 대기 중 …
+ARD 주차 노드 접속 — 세션#N · device=P1 · 상대 <IP:포트>
-ARD 세션#N 종료(<사유>) — … · 상대 <IP:포트>
요약 : … · devid거절 N🔴/유예교체 M · …
```
**이게 없던 오늘 오전에는 "우리 보드인가"를 사후에 못 갈랐고 반나절이 의심으로 갔다.**
⚠ **새 망의 우리 보드 IP 를 이동 직후에 적어 둬라.** 그 한 줄이 이후 모든 판정의 기준이 된다.
