## 0. 🔴 계획에서 바꾼 것 넷 — 값과 함께

### 0.1 저장 위치를 `data_log.json` 에서 **뺐다**

계획: *"`data_log.json` 에 추가"*. **네 가지 이유로 안 된다:**
```
① config.h:245  LOG_KEEP = 2 · persist.h:67  while (size > LOG_KEEP) pop_back()
   🔴 최신 2건만 남기고 **버리는 구조다.** 대장은 버려지면 안 된다
② persist.h:83  dst = "data_log.json"          ← **cwd 상대**
   🔴 §0.5.2 의 함정. 다른 디렉터리에서 띄우면 **대장이 조용히 새로 생긴다**
   증상은 "재기동했더니 등록이 다 사라졌다"이고 **원인이 코드에 없어서 못 찾는다**
③ http.h:296   이 파일은 브라우저에 그대로 서빙된다(`/data_log.json`)
   🔴 devid·지문·모듈 목록이 인증 없이 공개된다
④ persist.h:29  쓰기 조건이 **자리 비트열**이다(`key == last_bits` 면 안 쓴다)
   🔴 대장만 바뀌면 **조용히 안 저장된다**
```
> ### **`data_log.json` 은 *회전하는 로그* 이고 대장은 *신원* 이다. 수명이 다르면 같은 파일에 못 둔다.**

**대신**: `~/parking-logs/parking-nodes.json` — **절대경로**. rid 커서와 같은 형태이고,
그 방식이 재기동을 건너 살아남는 것은 실측으로 확인됐다(2026-08-19 `이어받음 4420`).

### 0.2 `last_peer_ip` 를 대장에 넣는다 — **관측 요건이다**

`devid` 가 지금 전부 `P1` 이다. 그 상태에서 두 보드가 번갈아 붙으면:
```
같은 P1 행에 서로 다른 보드의 모듈 목록이 번갈아 덮인다
→ 🔴 지문이 매번 바뀌어 대장이 **"구성이 바뀌었다"를 계속 보고한다**
→ ⚠ 원인은 구성 변경이 아니라 **다른 보드**인데 대장에 그 구분이 없다
```
🔑 **`devid` 가 고유하지 않을 때 남는 유일한 구분자는 커널이 주는 주소다**(REQ-0217 에서 배운 것).
⚠ **08-18 에 "그 일이 일어났는가"를 답하는 데 반나절이 들었다. 그때 없던 것이 접속 IP 였다.**

### 0.3 지문은 **서버가 계산한다** — 전선 필드는 전제가 아니다

계획은 지문을 장치가 접어 `D,*` 에 싣는 것(3단계·굽기 필요)으로 뒀다.
**그런데 서버는 이미 모듈 목록 전부를 갖고 있다**(`Node::mods` = `(name,kind)` 벡터).
```
→ 서버가 그 목록을 **순서대로** 접으면 지문이 나온다. **전선 필드 없이 성립한다**
→ 즉 이 단계만으로 신규/기존/구성변경 판정이 된다
```
> ### **전선 지문은 전제가 아니라 *최적화* 다** — "모듈 줄을 다 모으기 전에 안다"는 이득뿐.

⚠ **한계를 같이 적는다**: 등록이 중간에 끊기면 목록이 부분이다. 그때 접으면 **거짓 "구성 변경"** 이다.
🔴 **그래서 `reg_done` 이 참일 때만 접는다.** 미완 등록은 대장을 안 건드린다.

### 0.4 **쓰는 시점**을 정했다 — 계획에 없던 빈 자리

계획에 `최종접속` 이 있는데 **갱신 시점이 없었다.** 비워 두면 매 프레임이 되고 1Hz 로 파일을 쓴다.
```
✅ 쓴다 : ① 등록 완료  ② 세션 종료  ③ 지문 변경  ④ 할당 변경    ← **사건이 있을 때만**
❌ 안 쓴다 : 매 프레임 · 매 슬롯
→ 정상 운영에서 파일 쓰기가 **세션당 두 번**이다
```
⚠ **대가**: SIGKILL 로 죽으면 마지막 세션의 `최종접속` 이 안 남는다.
**받아들인다** — 대장의 목적은 *누가 있었나*이지 *언제까지 있었나*가 아니다.
🔑 `INSTANCE-END` 가 없는 것과 같은 성질이다(§"생존 판정은 로그가 아니라 pid 로").

## 1. 파일

```
경로   ~/parking-logs/parking-nodes.json
       포트 오프셋이 있으면 ~/parking-logs/parking-nodes.test+300.json
쓰기   임시파일 → rename (원자적). 중간에 죽어도 반쪽 파일이 안 남는다
HOME 없음 → 영속 불가. **로그에 크게 남기고 메모리로만 돈다** (rid 커서와 같은 규율)
no_disk(자가검증) → 파일을 안 건드린다
```
🔴 **`data_log.json` 과 달리 브라우저에 서빙하지 않는다.** 서빙 경로에 넣지 마라.

## 2. 형식

```json
{
  "v": 1,
  "srv_id": "<마지막으로 쓴 인스턴스>",
  "nodes": [
    {
      "devid":      "P1",
      "label":      "",                    // 사람이 붙이는 표시 이름. 4단계에서 쓴다
      "first_seen": 1787131565605,         // epoch ms
      "last_seen":  1787131643698,
      "last_peer":  "192.168.0.31",        // §0.2 — IP 만. 포트는 매번 바뀌므로 뺀다
      "fp":         "a3f19c2e",            // §3 지문
      "mods":       [{"name":"A1","kind":"IP"}, …],   // 순서가 의미다
      "state":      "assigned",            // §4
      "sessions":   12                     // 누적 접속 수 — 대장이 얼마나 근거 있는지의 분모
    }
  ],
  "assignments": [
    { "devid":"P1", "idx":0, "zone":"A1", "role":"occ_primary" }
  ]
}
```
🔴 **할당의 키는 `(devid, idx)` 다. 이름이 아니다.** 이름으로 걸면 지금 문제가 그대로 남는다.

⚠ **`idx` 는 등록 순서로 정해진다.** 순서가 바뀌면 같은 `idx` 가 다른 물건을 가리킨다 —
그래서 **지문에 순서가 들어가고**(§3), 지문이 바뀌면 §4 가 `needs_review` 로 간다.
🔑 서버에 이미 `mod_order_changed` 계기가 있다(약속이 깨진 횟수). **그 계기와 이 판정은 같은 것을 본다.**

## 3. 지문(`fp`)

```
입력 : (name, kind) 를 **등록 순서대로** 이어 붙인 문자열   "A1:IP|A2:IP|…|B5:IP"
접기 : 기존 `cksum` 과 **다른 함수를 쓰지 않는다** — 32비트 FNV-1a. 8자리 hex
조건 : 🔴 `reg_done == true` 일 때만 계산한다 (§0.3 의 부분 목록 함정)
```
⚠ **`fp` 는 충돌할 수 있다**(32비트). **충돌하면 "안 바뀐 것으로 보인다"** —
그래서 `mods` 전체를 같이 저장한다. **`fp` 는 빠른 비교용이고 정본은 `mods` 다.**
🔑 §"판별자를 쓰기 전에 그 판별자가 성립하는지 봐라" — 여기서는 **정본을 따로 두는 것**이 그 답이다.

## 4. 상태

```
new           대장에 없던 devid. 할당이 하나도 없다
unassigned    대장에 있고 할당이 없다
assigned      할당이 하나 이상 있다
needs_review  🔴 지문이 대장과 다르다. **사람이 봐야 한다**
```
🔴 **`needs_review` 를 `assigned` 로 자동 승격시키지 마라.** 모듈이 빠졌는데 옛 할당이 남으면
**없는 모듈을 가리키는 자리**가 생긴다.
⚠ **그리고 지문 변경의 원인이 "다른 보드"일 수 있다**(§0.2). `last_peer` 를 같이 보고 판단한다.

## 5. 대장이 답하지 **않는** 것 — 미리 적는다

```
· 대장은 **판정에 관여하지 않는다.** 지금 결속은 여전히 이름 일치다(설계서 §6 "강등"은 4단계)
  🔑 이 단계의 값은 **기억**이지 **동작 변경**이 아니다. 그래서 굽기가 필요 없고 창을 안 건드린다
· `label` 은 비어 있다. 붙이는 화면이 4단계다
· `assignments` 는 **기록만 된다.** 아무것도 그것을 읽지 않는다 — 읽는 것이 4단계다
· 권한·동시 편집·모듈 제거·정책 변경 시점 → 설계서 §7 그대로 **미해결**
```
> ### ⚠ **`assignments` 가 파일에 있는데 아무도 안 읽는다는 것을 여기 적어 두지 않으면,**
> ### **다음 사람이 "할당이 동작한다"고 읽는다.** (오늘 §3.5 에서 정확히 그 일이 있었다)

## 6. 🔴 확정·**미구현** — 다음 단계가 할 것

```
· 관리자 화면이 대장을 읽고 할당을 쓴다 (4단계)
· 결속이 할당을 먼저 보고, 없으면 이름 일치로 강등 (4단계)

```
**적혀 있다고 있는 것이 아니다** — 이 절의 것은 **코드가 없다.**
