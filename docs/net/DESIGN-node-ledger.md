## 0. 🔴 계획에서 바꾼 것 넷 — 값과 함께

### 0.1 저장 위치를 `data_log.json` 에서 **뺐다**

계획: *"`data_log.json` 에 추가"*. **네 가지 이유로 안 된다:**
```
① config.h:245  LOG_KEEP = 2 · persist.h:67  while (size > LOG_KEEP) pop_back()
   🔴 최신 2건만 남기고 **버리는 구조다.** 대장은 버려지면 안 된다
② persist.h:83  dst = "data_log.json"          ← **cwd 상대**
   🔴 §0.5.2 의 함정. 다른 디렉터리에서 띄우면 **대장이 조용히 새로 생긴다**
   증상은 "재기동했더니 등록이 다 사라졌다"이고 **원인이 코드에 없어서 못 찾는다**
③ http.h:296   이 파일은 브라우저에 그대로 서빙된다(`/data_log.json`)
   🔴 devid·지문·모듈 목록이 인증 없이 공개된다
④ persist.h:29  쓰기 조건이 **자리 비트열**이다(`key == last_bits` 면 안 쓴다)
   🔴 대장만 바뀌면 **조용히 안 저장된다**
```
> ### **`data_log.json` 은 *회전하는 로그* 이고 대장은 *신원* 이다. 수명이 다르면 같은 파일에 못 둔다.**

**대신**: `~/parking-logs/parking-nodes.json` — **절대경로**. rid 커서와 같은 형태이고,
그 방식이 재기동을 건너 살아남는 것은 실측으로 확인됐다(2026-08-19 `이어받음 4420`).

### 0.2 `last_peer_ip` 를 대장에 넣는다 — **관측 요건이다**

`devid` 가 지금 전부 `P1` 이다. 그 상태에서 두 보드가 번갈아 붙으면:
```
같은 P1 행에 서로 다른 보드의 모듈 목록이 번갈아 덮인다
→ 🔴 지문이 매번 바뀌어 대장이 **"구성이 바뀌었다"를 계속 보고한다**
→ ⚠ 원인은 구성 변경이 아니라 **다른 보드**인데 대장에 그 구분이 없다
```
🔑 **`devid` 가 고유하지 않을 때 남는 유일한 구분자는 커널이 주는 주소다**(REQ-0217 에서 배운 것).
⚠ **08-18 에 "그 일이 일어났는가"를 답하는 데 반나절이 들었다. 그때 없던 것이 접속 IP 였다.**

### 0.3 지문은 **서버가 계산한다** — 전선 필드는 전제가 아니다

계획은 지문을 장치가 접어 `D,*` 에 싣는 것(3단계·굽기 필요)으로 뒀다.
**그런데 서버는 이미 모듈 목록 전부를 갖고 있다**(`Node::mods` = `(name,kind)` 벡터).
```
→ 서버가 그 목록을 **순서대로** 접으면 지문이 나온다. **전선 필드 없이 성립한다**
→ 즉 이 단계만으로 신규/기존/구성변경 판정이 된다
```
> ### **전선 지문은 전제가 아니라 *최적화* 다** — "모듈 줄을 다 모으기 전에 안다"는 이득뿐.

⚠ **한계를 같이 적는다**: 등록이 중간에 끊기면 목록이 부분이다. 그때 접으면 **거짓 "구성 변경"** 이다.
🔴 **그래서 `reg_done` 이 참일 때만 접는다.** 미완 등록은 대장을 안 건드린다.

### 0.4 **쓰는 시점**을 정했다 — 계획에 없던 빈 자리

계획에 `최종접속` 이 있는데 **갱신 시점이 없었다.** 비워 두면 매 프레임이 되고 1Hz 로 파일을 쓴다.
```
✅ 쓴다 : ① 등록 완료  ② 세션 종료  ③ 지문 변경  ④ 할당 변경    ← **사건이 있을 때만**
❌ 안 쓴다 : 매 프레임 · 매 슬롯
→ 정상 운영에서 파일 쓰기가 **세션당 두 번**이다
```
⚠ **대가**: SIGKILL 로 죽으면 마지막 세션의 `최종접속` 이 안 남는다.
**받아들인다** — 대장의 목적은 *누가 있었나*이지 *언제까지 있었나*가 아니다.
🔑 `INSTANCE-END` 가 없는 것과 같은 성질이다(§"생존 판정은 로그가 아니라 pid 로").

## 2. 형식 — **줄 단위 텍스트**. (개정 1: JSON 에서 바꿨다)

### 🔴 왜 JSON 이 아닌가 — 초안에서 바꾼 이유

초안은 JSON 이었다. **쓰는 것은 쉽지만 *읽는 것*이 문제다** — 서버에 중첩 JSON 파서가 없다.
`jget` 은 평평한 객체용이고, 대장은 배열 안에 배열이 있다. **그러면 파서를 새로 써야 하고,
그 파서의 버그는 "대장이 조용히 비어서 돌아온다"로 나타난다.** 그게 이 단계에서 가장 나쁜 고장이다.

```
🔑 판단의 근거: **이 파일은 내 코드끼리만 왕복한다.**
   화면에 줄 것은 서버가 `wsjson.h` 에서 새로 만들어 보낸다(다른 봉투 전부가 그렇게 한다).
   그러니 **파일 형식이 JSON 일 이유가 없다** — JSON 은 *남에게 줄 때* 필요한 것이다.
```
> ### **자기만 읽는 파일에 파서가 필요한 형식을 고르지 마라.**

**대신 줄 단위 탭 구분.** 우리가 이미 쓰는 형태다(rid 커서도 텍스트 파일이다).
```
장점 : ① 파서가 `split('\t')` 하나다 — 버그가 들어갈 자리가 없다
      ② **줄마다 독립**이라 마지막 줄이 잘려도 그 줄만 버리면 된다
      ③ 사람이 `cat` 으로 읽는다. 대장은 디버깅할 때 눈으로 볼 일이 많다
      ④ 새 필드를 뒤에 붙일 수 있다 — 옛 판이 읽어도 안 깨진다
```

### 형식

```
v	1
srv	005a24b-1787131565605
N	<devid>	<label>	<first_seen>	<last_seen>	<last_peer>	<fp>	<sessions>	<state>
M	<devid>	<idx>	<name>	<kind>
A	<devid>	<name>	<zone>	<role>
```
```
N  노드 한 줄.  M  그 노드의 모듈 하나(순서가 곧 idx).  A  할당 하나
⚠ 값 안의 탭·개행은 쓸 때 공백으로 바꾼다 — 안 그러면 칸이 밀린다
⚠ 모르는 첫 글자의 줄은 **버리지 말고 무시한다**(앞으로 늘 수 있다)
🔴 `M` 은 `N` 뒤에 온다. 순서가 곧 `idx` 이므로 **파일 안의 순서가 의미다**
```
### 🔴 개정 2 — **할당의 키를 `(devid, idx)` 에서 `(devid, name)` 으로 바꿨다**

초안(과 온보딩 설계서)은 `idx` 였다. **배제 근거가 틀렸다:**
```
초안의 이유 : "이름으로 걸면 지금 문제가 그대로 남는다"
🔴 지금 문제는 `name` 이 아니라 **`name == 자리 id` 라는 *암묵 규칙*** 이다
```
> ### **명시적으로 사상하면(이름 `B7` → 자리 `A3`) 그 결합은 `name` 으로도 똑같이 끊긴다.**
> **`idx` 여야 할 이유가 아니었다.** — 루트가 정정을 받았다(2026-08-19).

**`idx` 를 안 쓰는 적극적 이유 둘:**
```
① `idx` 는 **등록 순서**로 정해진다 → 순서가 바뀌면 **같은 idx 가 다른 물건을 가리킨다**
   할당이 조용히 딴 데를 가리킨다. 그래서 `mod_order_changed` 계기가 따로 있는 것이다
② web 이 REQ-0179 §① 에서 **`(devid, name)` 을 전역 신원으로 이미 쓴다**
   키가 둘이면 화면이 매핑을 만들고 **그 매핑은 등록이 바뀔 때마다 낡는다**
```
🔑 **명세를 쓰기 *전* 에 남의 도메인 문서를 찾아본 것이 이걸 잡았다.**

⚠ **전선은 여전히 `idx` 로 주소를 정한다**(`downlink.h:81` — `G,<rid>,<idx>,<val>`).
**보낼 때 현재 등록에서 `name`→`idx` 로 푼다.** 그 이름이 지금 등록에 없으면 **보내지 않고 사유를 준다.**

🔴 **그래서 새 전제가 생겼다: 한 장치 안에서 `name` 이 고유해야 한다.**
```
`mod_name_conflict` 는 **노드 *사이*** 충돌만 본다(두 노드가 같은 자리를 주장)
🔴 **한 노드 *안* 의 중복은 아무도 안 봤다** → `mod_dup_name` 을 새로 만들었다
```
🔑 **감시할 수 없는 것을 키로 쓰지 않는다.** 키를 바꾸면서 그 감시를 같이 만들었다.
⚠ 그리고 이 중복은 **오늘 이미 결함이었다** — web 이 `(devid,name)` 으로 조회하는데
중복이 있으면 **화면이 둘 중 하나를 임의로 집는다.** 증상이 *"가끔 엉뚱한 모듈이 보인다"* 라서 안 보인다.

⚠ **`idx` 는 등록 순서로 정해진다.** 순서가 바뀌면 같은 `idx` 가 다른 물건을 가리킨다 —
그래서 **지문에 순서가 들어가고**(§3), 지문이 바뀌면 §4 가 `needs_review` 로 간다.
🔑 서버에 이미 `mod_order_changed` 계기가 있다. **그 계기와 이 판정은 같은 것을 본다.**

## 3. 지문(`fp`)

```
입력 : (name, kind) 를 **등록 순서대로** 이어 붙인 문자열   "A1:IP|A2:IP|…|B5:IP"
접기 : 기존 `cksum` 과 **다른 함수를 쓰지 않는다** — 32비트 FNV-1a. 8자리 hex
조건 : 🔴 `reg_done == true` 일 때만 계산한다 (§0.3 의 부분 목록 함정)
```
⚠ **`fp` 는 충돌할 수 있다**(32비트). **충돌하면 "안 바뀐 것으로 보인다"** —
그래서 `mods` 전체를 같이 저장한다. **`fp` 는 빠른 비교용이고 정본은 `mods` 다.**
🔑 §"판별자를 쓰기 전에 그 판별자가 성립하는지 봐라" — 여기서는 **정본을 따로 두는 것**이 그 답이다.

## 4. 상태

```
new           대장에 없던 devid. 할당이 하나도 없다
unassigned    대장에 있고 할당이 없다
assigned      할당이 하나 이상 있다
needs_review  🔴 지문이 대장과 다르다. **사람이 봐야 한다**
```
🔴 **`needs_review` 를 `assigned` 로 자동 승격시키지 마라.** 모듈이 빠졌는데 옛 할당이 남으면
**없는 모듈을 가리키는 자리**가 생긴다.
⚠ **그리고 지문 변경의 원인이 "다른 보드"일 수 있다**(§0.2). `last_peer` 를 같이 보고 판단한다.

## 4.5 ⚠ `kind` 가 바뀌면 그 장치가 한 번 `needs_review` 가 된다

대장은 `kind` 를 **전선 문자 그대로** 저장한다. 그래서 `kind` 표기가 바뀌면 지문이 바뀌고
그 장치는 한 번 `needs_review` 로 간다. **결함이 아니다** — 대장이 보기에 구성은 실제로 바뀌었다.

### 🔴 개정 3 — **초판의 이 절은 틀렸다. 근거가 mock 이었다**

초판에 이렇게 썼다: *"지금 장치가 보내는 것은 `OBV` 다. `OB` 로 바뀌면 전원이 재확인이 된다."*
**둘 다 틀렸다. 값으로 확인했다:**
```
펌웨어 원문 : FrameCodec.h:85  #define KIND_BARRIER_V "OB"   ← REQ-0271 에서 이미 `V` 를 뺐다
도는 보드   : 모듈 **10개 전부 `IP`**. 차단봉 모듈이 **아예 없다**(운영 map 프레임 실측)
`OBV` 를 보내는 것 : 🔴 **우리 `net/mock_node.py` 하나뿐**이었다
```
> ### **나는 `mock` 이 만든 값을 읽고 "장치가 보내는 것"이라고 적었다.**
> ### **fixture 를 실기 근거로 쓰면 이렇게 된다.**

⚠ **자료는 진짜였다** — `~/parking-logs/parking-nodes.test+300.txt` 에 `OBV` 가 정말로 있었다.
**틀린 것은 값이 아니라 그 값의 *출처에 대한 진술*** 이다.
🔑 §"관측 대상이 우리 것인지 확인해라" 의 축소판이다. 거기서는 *남의 보드*였고 여기서는 **내 도구**다.

**같이 고친 것**: `net/mock_node.py` 의 기본값을 `OB` 로 바꿨다(`--gate-kind` 로 `OBV` 도 보낼 수 있다 —
화면의 `V` 제거 방어 경로를 시험해야 하므로 **지우지는 않았다**).

### 그래서 지금 참인 것

```
· 실기에서 이 사건은 **아직 안 일어났다.** 도는 보드에 차단봉 모듈이 없다
· 가상 차단봉이 켜진 펌웨어가 붙으면 `OB` 로 들어온다 → 대장에 처음 보는 구성 → **한 번 재확인**
· `mock` 으로 만든 대장과 실기 대장을 **같은 파일에 섞지 마라** — 지문이 달라 재확인이 뜬다
  🔑 시험 인스턴스는 `.test+N` 으로 경로가 갈리므로 **구조적으로 안 섞인다**
```
🔑 **`fp` 만 보면 원인을 못 가른다. `mods` 를 같이 저장하는 이유가 이것이다** —
`kind` 만 바뀐 것인지 모듈이 빠진 것인지 **눈으로 보면 즉시 갈린다.**

⚠ **정규화하지 않는다.** 서버가 `OBV` 를 `OB` 로 접어 저장하면 그 전환이 안 보이고
**"장치가 무엇을 보냈나"를 대장이 더 이상 증언하지 못한다.**

## 5. 대장이 답하지 **않는** 것 — 미리 적는다

```
· 대장은 **판정에 관여하지 않는다.** 지금 결속은 여전히 이름 일치다(설계서 §6 "강등"은 4단계)
  🔑 이 단계의 값은 **기억**이지 **동작 변경**이 아니다. 그래서 굽기가 필요 없고 창을 안 건드린다
· `label` 은 비어 있다. 붙이는 화면이 4단계다
· `assignments` 는 **기록만 된다.** 아무것도 그것을 읽지 않는다 — 읽는 것이 4단계다
· 권한·동시 편집·모듈 제거·정책 변경 시점 → 설계서 §7 그대로 **미해결**
```
> ### ⚠ **`assignments` 가 파일에 있는데 아무도 안 읽는다는 것을 여기 적어 두지 않으면,**
> ### **다음 사람이 "할당이 동작한다"고 읽는다.** (오늘 §3.5 에서 정확히 그 일이 있었다)

## 6. 🔴 확정·**미구현** — 다음 단계가 할 것

```
· 관리자 화면이 대장을 읽고 할당을 쓴다 (4단계)
· 결속이 할당을 먼저 보고, 없으면 이름 일치로 강등 (4단계)
· 정책(자리 판정·차단봉) 선택 (5단계)
```
**적혀 있다고 있는 것이 아니다** — 이 절의 것은 **코드가 없다.**
