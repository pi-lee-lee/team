## 1. 계층 셋 — 각자가 **모르는 것**으로 정의된다

이 구조의 요점은 각 계층이 아는 것이 아니라 **모르는 것**이다. 모르는 것이 곧 경계다.

```
   ┌──────────────────────────────────────────────────────────┐
   │  주차 도메인                                              │
   │    slots[10] · 예약 · 번호판 · 브라우저 WS · data_log.json │
   │    ✗ 소켓 · 프레임 · 체크섬 · 레지스트리를 모른다           │
   └───────────────▲──────────────────────┬───────────────────┘
                   │ DeviceEvent          │ DeviceCommand
                   │ (상행 · 구현됨)       │ (하행 · **아직 없다**)
   ┌───────────────┴──────────────────────▼───────────────────┐
   │  이음매  server_seam.h — 값 구조체 둘 + 도우미 셋          │
   └───────────────▲──────────────────────┬───────────────────┘
                   │                      │
   ┌───────────────┴──────────────────────▼───────────────────┐
   │  디바이스 계층                                            │
   │    TCP 9991 · 라인 프레이밍 · 체크섬 · 재전송 · ACK 대기    │
   │    ✗ 주차공간 · 예약 · 번호판을 모른다                     │
   └──────────────────────────────────────────────────────────┘
```

**규칙 셋** (정본은 `server_seam.h` 머리말):

1. **도메인은 소켓·프레임·체크섬·레지스트리를 모른다.** `device_id` 도 **문자열 값**으로만
   받는다. 소켓 핸들이나 노드 포인터가 넘어오면 그 순간 도메인이 전송 계층에 묶인다.
2. **디바이스는 주차공간·예약·번호판을 모른다.** 센서 인덱스와 채널 번호만 안다.
   그래서 `sensors` 는 **"칸이 찼다"가 아니라 "내 센서 N번이 눌렸다"** 이다.
3. **값만 오간다. 포인터로 서로의 내부를 만지지 않는다.** 구조체가 그대로 바이트로
   직렬화될 수 있어야 나중에 루프백 TCP 로 갈아탈 수 있다 —
   그래서 `std::string`·컨테이너·가상함수를 쓰지 않는다.

⚠ **지금은 한 프로세스 안이다.** 프로세스 분리는 이번 범위가 아니다.
다만 그때가 오면 **`server_seam.h` 만 두고 양쪽을 떼면 된다** — 그게 이음매의 값이다.

## 2. 파일 배치 — 무엇이 왜 그 파일에 있나

| 파일 | 행 | 무엇 | include |
|---|---|---|---|
| `server.cpp` | 2728 | 나머지 전부. 디바이스 계층과 도메인이 **아직 한 파일에 같이 산다** | — |
| `server_device.h` | 175 | 디바이스 계층 **잎 유틸**: SHA-1 · base64 · `ws_accept` · `cksum` · `build_line` · `verify_line` | ✅ |
| `server_seam.h` | 121 | **이음매 계약.** `DeviceEvent` · `DeviceCommand` + 값 채우기 도우미 | ✅ |
| `server_wire.h` | 213 | 전선 프레임 encode/decode. **freestanding** (AVR 8비트에서 컴파일되게 `char[]`·정수만) | ❌ **안 쓴다** |

### 🔴 `server_wire.h` 가 include 되지 않은 이유 — 결함이 아니다

**지금 칩이 그 프레임을 모른다.** 현재 펌웨어는 `조별과제샘플/client.ino` 계열이고
**`R`·`C`·`T`·`M` 만 받고 `W` 는 버린다**(`client.ino:1514`). `server_wire.h` 는 EspLink
계열 산물이다(LEDGER §3.2).

> **칩이 아는 말로 걸어야 경로를 재는 것이지, 모르는 말로 걸면 파서를 재는 것이다.**

즉 이 헤더는 **미래의 하행 일반화(`W` 프레임)를 위해 준비된 것**이고, 지금 include 하면
쓰이지 않는 코드가 빌드에 들어올 뿐이다. **지우지도 말고 켜지도 마라.**

⚠ 딸린 미해결 항목: 규약상 장치는 배너에 `wire=N`, 서버는 기동 로그에 자기 `WIRE_VERSION` 을
찍기로 했는데 **서버가 안 찍는다.** 그래서 대조 규약이 사실상 안 지켜지고 있다.

## 3. 이음매를 넘는 흐름

### 상행 (장치 → 도메인) — **구현됐다**

```
디바이스 계층에서 사건 발생
        │
        ▼
  emit_dev(kind, dev, reason)          server.cpp:1233   ← 이벤트를 만들어 큐에 넣기만 한다
        │                              (emit_dev_ack 는 1255 — ACK 전용 래퍼)
        ▼
  pending_events  (std::vector)        server.cpp:557
        │
        ▼
  drain_dev_events()                   server.cpp:1265   ← run() 루프 끝(2533)에서 한 번
        │
        ├─ need_log      → write_log_if_changed()
        └─ need_snapshot → push_snapshot()               ← 순서: **기록 먼저, 그다음 화면**
```

**같은 틱 안에서 소비한다.** 지연이 생기지 않고 브라우저가 보는 것은 옮기기 전과 동일하다 —
이 단계의 계약이 **"구조만 바꾸고 동작은 안 바꾼다"** 이기 때문이다.

⚠ `drain_dev_events()` 의 `default:` 는 **아직 안 옮긴 종류**다. 그 종류들은 여전히
직접 호출이 담당한다. **`switch` 에 case 가 없다고 그 이벤트가 안 온다는 뜻이 아니다.**

### 하행 (도메인 → 장치) — **아직 없다**

`DeviceCommand` 구조체는 `server_seam.h` 에 **정의만 돼 있고 아무도 안 쓴다.**
지금 도메인은 `dispatch('R'/'C')` 로 **전선에 직접 쏜다.** 이것이 이음매 2 다.

## 4. 어디까지 왔나 — 상행 **4/6**, 하행 대기

| 이벤트 | 이관 | 비고 |
|---|---|---|
| `DEV_DISCONNECT` | ✅ | 3곳 — 송신 실패(1135) · 수신 실패(2313) · 유휴 마감(2469) |
| `DEV_ONLINE` / `DEV_OFFLINE` | ✅ | 오프라인 엣지(2525). **파일 쓰기까지** 해야 한다 |
| `DEV_ACK` | ✅ | 1722. **격리 검증까지 통과**(아래) |
| `DEV_CONNECT` | ❌ | **하행을 쏜다** |
| `DEV_SENSORS` | ❌ | **하행을 쏜다** |

### `DEV_ACK` 의 "격리 검증"이 무슨 뜻인가

**"예약 왕복이 되더라"는 이관의 증명이 아니다.** 장치는 상태가 바뀌면 즉시 `S` 를 보내므로,
ACK 가 만든 스냅샷과 그 `S` 가 만든 스냅샷을 **구별할 수 없다.**

가른 방법(LEDGER §7.6): **무장하지 않은 상태의 `T,S` 명령** → 장치가 `result=4` 로 거절하고
**아무 상태도 안 바꾼다** → **뒤따르는 `S` 가 없다** → 그런데도 스냅샷이 왔다
→ **그것을 만들 수 있는 것은 `DEV_ACK` drain 뿐이다.**

⚠ 여전히 남은 것: `DEV_ACK` 이관은 **기록·화면만** 옮겼다.
**예약 상태 변경(`slots[]`)은 아직 `A` 분기에 그대로 있다.** 그것까지 옮기면
`send_ack` 와 상태 변경의 순서가 바뀌므로, `DEV_SENSORS` 와 **함께** 다룬다.

## 5. 🔴 왜 4/6 이 상한인가 — **이 문서에서 제일 중요한 줄**

**가르는 축은 단계 이름도 코드량도 아니다. "그 자리가 전선에 하행을 쏘느냐" 하나다.**
(LEDGER §7.1, 실측으로 갈림)

- `DEV_CONNECT` 자리 → `resync_reservations()` → **`dispatch('R')` 로 전선에 하행**
- `DEV_SENSORS` 자리 → 〃 + 불일치 시 **`dispatch('C')`**

이벤트로 미루면 **송신 순서가 뒤집힌다.** 실측 기준선이 이렇다:

```
+ARD 접속 → ⟳ 재하달 → →ARD R,2,B3,…  →  ←ARD S,0,…  →  ←ARD A,2,B3,0
                        ^^^^^^^^^^^^^ 이것이 첫 ←ARD S 보다 **먼저**여야 한다
```

`adopt_as_parking()` 이 `resync_reservations()` 를 **동기로** 부르고 그 직후
`drain_ard_buf()` 가 첫 프레임을 같은 틱에서 처리하는데, `drain_dev_events()` 는 **훨씬 뒤**다.
이벤트로 바꾸면 `R` 이 `S` 뒤로 밀린다.

> ### 🔴 그러므로 **4/6 은 "하다 말았다"가 아니다. 구조가 그렇게 생긴 것이다.**
> 나머지 둘은 **이음매 2(하행)와 같이** 풀린다. 따로 풀 방법이 없다.
> 단계 계약이 "구조만 바꾸고 동작은 안 바꾼다"인 한, 지금 옮기는 것은 **계약 위반**이다.

⚠ **함정**: `resync_reservations` 는 이름이 로그 계열로 읽히지만 **송신기다.**
이름만 보고 "작은 항목"으로 분류했다가 순서 위험을 놓칠 뻔했다.
**함수 이름이 아니라 그 함수가 전선에 무엇을 내보내는지 따라가라.**

## 7. 아직 안 고친 것

| 항목 | 증상 | 상태 |
|---|---|---|
| **`--webroot` 없음** | `serve_file()` 이 **cwd 기준 상대경로**로 연다. 운영 cwd(`~/parking-bin`)에 `index.html` 이 없어 **`GET /` 가 404** | 결정 대기(DEPLOY-CHECKLIST §4.3) |
| 서버가 `WIRE_VERSION` 미출력 | `wire=N` 대조 규약이 사실상 안 지켜진다 | 미착수 |
| 지표 이름 `오프라인` → `무프레임` | 측정값은 "3500ms 무프레임"인데 이름이 해석("오프라인")이다. monitor 는 구/신 동시 수용 완료 | **서버 변경만 남음** |
| WS 스냅샷 `last_frame_ts` | REQ-0132 | ✅ 고침 — **미배포** |
| `GET /?x` 404 | REQ-0132 | ✅ 고침 — **미배포** |

⚠ **이름 변경은 계약 변경이다.** 소비자(관측 도구)가 그 문자열에 걸려 있으므로
**구/신 동시 수용 → 시각 통보 → 변경** 순서로 간다. 뒤집으면 판정이 그 순간 끊긴다.

## 8. 이 문서를 고칠 때

- **프로토콜 명세를 여기에 다시 쓰지 마라.** `parking-protocol.md` 가 정본이다.
- **LEDGER 를 옮겨 적지 마라.** 사실 목록은 거기 두고 여기서는 가리킨다.
- **미래 계획을 상세히 적지 마라.** "무엇이 남았고 왜 묶여 있나"까지가 이 문서의 범위다.
- 규칙 셋을 바꿀 때는 **`server_seam.h` 를 먼저 고치고** 여기를 맞춘다.
