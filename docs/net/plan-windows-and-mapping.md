**작성** `socket-engineer` · 2026-08-15 · **구현 금지 상태. 루트 승인 후 착수.**

두 요청을 한 문서로 낸다. 서로 얽혀 있기 때문이다 — **윈도우 여부가 IPC 선택을 정하고,
매핑 개편은 윈도우 이전과 검증 자원을 두고 경쟁한다.**

## 0. 전제 — 두 번 바뀌었다. **최종본은 이것이다**

**기본 환경 전체가 윈도우다**(맥은 개인 개발기). 다만 루트가 처음 낸 위험 평가
*"서버 바이너리가 한 번도 컴파일 안 됨"* 은 **과장이었고 1차 증거로 정정됐다.**

### 사용자 1차 증거 — 윈도우는 대부분 이미 검증돼 있다

- GitHub 기준 코드로 **윈도우에서 빌드·동작 시험 완료**
- 조원이 **윈도우 브라우저**로 화면 확인
- **여러 폰·패드에서 HTTP 접속**해 모니터링 데모 확인
- Windows Defender 문제 없음

| 오늘 검증한 것 | 윈도우로 넘어가는가 |
|---|---|
| ESP·아두이노 동작, 결합·재접속 | ✅ 서버 OS 와 무관 |
| 와이어 프로토콜, 프레임 무결성 | ✅ 무관 |
| **서버 빌드·HTTP·정적 서빙·다중 클라이언트** | ✅ **이미 검증됨(사용자 실측)** |
| **오늘 변경분(975행)** | ❌ 윈도우에서 안 돌려봤다 |
| 파이썬 관측 도구 | ❌ POSIX 경로 7곳/3파일 |

## 1. 진짜 미검증 표면 — **내가 직접 세어 확인했다. 2곳이고, 둘 다 안전하다**

```
git diff HEAD -- 조별과제샘플/server.cpp  →  975 insertions
그중 새 _WIN32 지점: **정확히 2곳**
```

**그리고 그 2곳을 열어 보니 루트가 확인하라고 한 대상이 애초에 존재하지 않는다:**

| # | 위치 | 내용 | 위험 |
|---|---|---|---|
| 1 | `set_keepalive()` 윈도우 분기 | **문자열 하나를 반환할 뿐이다.** `mstcpip.h` 포함도, `WSAIoctl` 호출도 **코드에 없다** — 검증할 수 없어 일부러 안 넣었기 때문 | **컴파일 위험 없음** |
| 2 | `err_is_timeout()` | `return e == WSAETIMEDOUT;` 한 줄. 상수는 이미 포함된 `winsock2.h` 에 있다 | **컴파일 위험 없음** |

→ **오늘 변경분의 윈도우 컴파일 위험은 사실상 0 이다.** 루트의 정정보다 한 단계 더 좁다.

> ⚠ **다만 "컴파일된다"가 "동작한다"는 아니다** — 오늘 하루의 교훈 그대로다.
> 나머지 973행은 플랫폼 중립 C++ 이지만 **윈도우에서 돌려본 적은 없다.**
> 특히 다중 노드(REQ-0083)의 `select` fd_set 확장은 윈도우에서 `fd_set` 구현이 다르다
> (배열+개수 방식). `FD_SETSIZE` 를 256 으로 올려 뒀고 최대 8노드+8대기 이므로 여유는 충분하지만,
> **실행 확인 전까지는 "될 것 같다"이지 "된다"가 아니다.**

### 🔑 윈도우에서 실제로 다른 것 — 컴파일이 아니라 **동작**이다

**keepalive 가 윈도우에서는 사실상 무효다.** `SIO_KEEPALIVE_VALS` 를 안 넣었으므로 기본 유휴가
**2시간**이다. 오늘 실기로 두 번 확증한 **25초 회수가 윈도우에는 없다.**
→ 윈도우에서는 **유휴 마감 60초가 유일한 좀비 회수 장치**가 된다.

이건 결함이 아니라 **알고 남긴 한계**이고 §3.5 에 이미 적혀 있다. 다만 조원 배포 시
"맥에서는 35초에 회수되는데 윈도우에서는 60초"라는 차이가 실재하므로 **알고 있어야 한다.**
`SIO_KEEPALIVE_VALS` 구현은 PAL 분리(§3) 때 `server_win.cpp` 에서 하는 것이 자연스럽다.

### 기존 빌드가 이미 답한 것

사용자가 윈도우에서 **빌드하고 화면까지 확인했다면**, 내가 앞서 예측한
"MSVC 가 한글 문자열을 깨뜨린다 / 링크 옵션 / 보안 경고" 는 **그 툴체인에서 이미 해소된 것**이다.
→ **그 예측 목록은 폐기한다.** 남는 확인 항목은 **컴파일러가 무엇인지**(PAL 빌드 스크립트를
쓰려면 알아야 한다) 하나뿐이다.

## 2. 파이썬 관측 도구 이식 — **윈도우에서 눈을 확보한다**

관측 도구가 안 돌면 윈도우에서 우리는 **다시 눈이 먼다.** 오늘 하루가 증명했듯 눈이 없으면
가설만 쌓인다.

현재 POSIX 경로 **7곳 / 3파일**: `net/soak_report.py` · `net/reconnect_stats.py` · `net/uptime_anchor.py`

**다행히 구조는 이미 이식 가능하다** — 세 도구 모두 로그 경로를 `argv[1]` 로 받고
`/tmp/...` 는 **기본값일 뿐**이다. 그리고 파일 읽기는 전부 `open(..., errors="replace")` 라
인코딩 사고가 없다(오늘 `grep -a` 함정을 겪고 파이썬으로 통일해 둔 것이 여기서 값을 한다).

**할 일**: 기본값만 플랫폼 중립으로.

```python
import os, tempfile
DEFAULT_LOG = os.path.join(tempfile.gettempdir(), "parking-soak.log")
```

- `net/swap_server.sh` 는 bash 다 → **윈도우용 `.bat` 등가물이 필요**하다(3절 빌드 스크립트와 묶는다).
- `net/*.py` 중 소켓 도구(`ws_probe`·`fake_phone`·`fake_arduino`·`zombie_probe`)는
  경로를 안 쓰므로 **그대로 돈다**(표준 라이브러리만 쓴다).

**비용이 작고 이득이 크다 — PAL 분리보다 먼저 한다.**

## 3. PAL 분리 (REQ-0086 본안)

### 파일 구조

```
조별과제샘플/server_platform.h    선언만. #ifdef 없음. 양쪽이 지키는 계약
조별과제샘플/server_posix.cpp     POSIX 구현만 (윈도우 코드 0줄)
조별과제샘플/server_win.cpp       윈도우 구현만 (POSIX 코드 0줄)
조별과제샘플/server.cpp           도메인 로직 (OS 코드 0줄)
```

**파일명을 `server` 로 시작시킨다** — 소유권 규칙(`조별과제샘플/server*`)이 그렇게 잡혀 있어
다른 이름을 쓰면 확장자 규칙에 걸려 cpp-engineer 소유가 되고 내가 못 고친다.

### `server_platform.h` 계약 목록 (현재 분기 10곳에서 도출)

| 함수 | POSIX | 윈도우 |
|---|---|---|
| `net_startup()` / `net_cleanup()` | no-op | `WSAStartup` / `WSACleanup` |
| `closesock(fd)` | `close` | `closesocket` |
| `sock_errno()` | `errno` | `WSAGetLastError` |
| `err_is_timeout(e)` | `ETIMEDOUT` | `WSAETIMEDOUT` |
| `err_is_reset(e)` | `ECONNRESET` | `WSAECONNRESET` |
| `set_send_timeout(fd)` | `timeval` | `DWORD ms` |
| `set_keepalive(fd)` | `TCP_KEEPALIVE/IDLE/INTVL/CNT` | **`SIO_KEEPALIVE_VALS`** ← 미구현. 여기서 처음 구현된다 |
| `now_ms()` / `epoch_ms()` | `gettimeofday` | `GetTickCount64` / `FILETIME` |
| `ignore_sigpipe()` | `signal(SIGPIPE, SIG_IGN)` | no-op |
| `atomic_replace(tmp, dst)` | `rename` | `MoveFileEx(REPLACE_EXISTING)` ← §9.3 이 이미 경고한 자리 |

> **계약이 잡아내는 것**: 지금은 "윈도우에서 뭐가 미검증인지"가 10곳에 흩어져 안 보인다.
> 파일을 가르면 **`server_win.cpp` 한 파일이 곧 미검증 표면**이 된다. 그게 이 리팩터링의 본질적 이득이고,
> "취향"이 아닌 이유다.

### 빌드 스크립트 — 선택은 빌드가 한다

`#ifdef` 로 파일을 고르지 않는다. **빌드가 어느 `.cpp` 를 넘길지 정한다.**

```
build.sh   : g++ -std=c++11 -O2 server.cpp server_posix.cpp -o srv_parking
build.bat  : (MSVC)  cl /utf-8 /EHsc /D_CRT_SECURE_NO_WARNINGS server.cpp server_win.cpp /Fe:srv_parking.exe
             (MinGW) g++ -std=c++11 -O2 server.cpp server_win.cpp -o srv_parking.exe -lws2_32
```

⚠ **컴파일러가 정해지기 전에는 둘 다 적어 둔다.** 기존 윈도우 빌드가 이미 성공했으므로
그 툴체인의 명령을 그대로 받아 쓰는 것이 가장 안전하다 — 새로 지어내지 않는다.

**지금 `/tmp/srv_parking` 을 어떻게 빌드하는지가 문서에 없다** — 이 스크립트가 그 문서화를 겸한다.

## 4. IPC 선택 — **루프백 TCP. Unix 도메인 소켓이 아니다**

REQ-0086 이 물은 것에 답한다. **환경이 윈도우이므로 결론이 정해진다:**

| | Unix 도메인 소켓 | **루프백 TCP(127.0.0.1)** |
|---|---|---|
| 윈도우 | ⚠ Win10 1803+ 부분 지원, `select` 통합이 까다롭다 | ✅ 완전 지원 |
| 코드 공유 | OS별 분기 필요 | **양쪽 동일** |
| 기존 select 루프 | 별도 처리 | **그대로 재사용** |
| 격리 | 파일 권한 | `127.0.0.1` **명시 바인드**면 외부 접근 불가 — 실질적으로 동등 |

→ **루프백 TCP.** `0.0.0.0` 이 아니라 **`127.0.0.1` 에 명시 바인드**하는 것이 조건이다.
(지금 서버는 세 리스너 모두 와일드카드 바인드다. IPC 포트를 추가한다면 그것만 루프백으로 묶는다.)

## 5. 센서-공간 매핑 (REQ-0085 본안)

### 5.1 원칙 — 동의한다

지금은 **장치가 도메인을 안다**(`SLOT_PIN[]` 이 A1~B5 를 알고, 프레임이 "칸 점유"를 보낸다).
자리 배치가 바뀌면 펌웨어를 다시 굽는다. **장치가 알아야 할 이유가 없는 지식이다.**

### 5.2 와이어 개정안 — **비트열은 그대로, 의미만 바꾼다**

```
현재: S,seq,occupied10,reserved10,uptime,devid[,tmask],cksum
          └ "칸 A1..B5 가 찼다"        ← 장치가 도메인을 안다

개정: S,seq,sensor10,uptime,devid[,tmask],cksum
          └ "내 센서 0..9 가 눌렸다"   ← 장치는 자기 센서만 안다
```

- **고정 크기 유지**(사용자 요구·EspLink 전제). 비트열 폭은 그대로 10.
- **`reserved` 비트열은 상행에서 뺀다.** 예약은 **서버 상태**다. 장치가 되돌려 보낼 이유는
  "표시등 구동" 하나뿐인데, **그건 하행으로 주면 되고 상행에 실을 이유가 없다.**
  빼면 프레임이 11바이트 줄어 §3.2 시리얼 링크 점유가 7.92% → 약 6.8% 로 내려간다(부수 이득).
  ⚠ 다만 **§7.6 의 불일치 감지**(장치 reserved vs 서버 reserved)가 이 필드를 쓴다.
  그 기능을 버릴지 하행 ACK 로 대체할지 **결정이 필요하다 — 지금 답을 정하지 않는다.**

### 5.3 매핑은 코드가 아니라 설정

```
# 조별과제샘플/mapping.conf  (재빌드 없이 바뀐다)
P1,0 -> 1F-A1
P1,1 -> 1F-A2
P2,0 -> 2F-A1        ← 2층을 올려도 이 파일만 는다
```

**검증 규칙**(로드 시 전부 확인, 하나라도 걸리면 **기동 거부**):
- 중복 매핑: 같은 `(device,sensor)` 가 둘 이상 → 거부
- 같은 `space_id` 에 센서 둘 이상 → **금지**. 합의·투표는 필요 없고, 있으면 "둘이 다를 때
  무엇이 참인가"라는 답 없는 질문이 생긴다. **금지하고 그렇게 적는다.**
- `sensor_index` 범위 밖(0..9) → 거부
- **재적재**: 재시작만으로 반영. 무중단 재적재는 2단계로 미룬다(파일이 반쯤 쓰인 순간을
  읽는 사고를 막으려면 원자적 교체가 필요한데, 그건 §9.2 와 같은 설계가 또 필요하다).

### 5.4 판정 규칙 — **여기가 진짜 설계다**

| 상황 | 판정 | 근거 |
|---|---|---|
| 미매핑 센서 수신 | **로그 후 무시 + 카운터** | 조원이 새 노드를 올리면 **반드시** 생긴다. 조용히 버리면 "왜 안 보이지"가 되고, 거부하면 노드 하나가 전체를 막는다. 카운터가 있어야 "매핑을 안 넣었다"가 보인다 |
| 매핑은 있는데 장치 오프라인 | **"비었다"가 아니라 "모른다"** | 지금은 단일 장치라 마지막 값을 유지했다. 다중이 되면 **공간마다 신선도가 다르다.** `unknown` 상태를 새로 만들어야 한다 |
| 장치가 살아 있고 센서가 0 | 비었다 | |

> ⚠ **`unknown` 은 화면 계약을 바꾼다.** 지금 `data_log.json`·WS 스냅샷은 `occupied 0/1` 뿐이다.
> 3-상태가 되면 **web-engineer 에게 요청을 발행해야 한다.** 내가 일방적으로 바꾸지 않는다.

**공간 단위 신선도** = 그 공간에 매핑된 장치의 `last_frame_ts`. REQ-0083 에서 장치별로 갈라
뒀으므로 접기만 하면 된다.

### 5.5 하행도 장치 좌표로 번역

서버가 `space_id` 를 알고, 장치에는 **`(device, sensor_index)`** 로 번역해 내린다.
다만 **장치가 표시등을 안 쓰면 하행 자체가 필요 없어진다** — 현재 `R`/`C` 는 장치의 예약 캐시를
갱신할 뿐이고, 5.2 에서 `reserved` 상행을 빼면 **그 캐시의 존재 이유가 사라진다.**
→ **하행이 통째로 없어질 수 있다.** 그러면 오늘 종일 다룬 재전송·ACK 기전도 함께 불필요해진다.
**확인 필요**: 장치에 표시등/부저가 있는가? 없으면 이 단순화가 가능하다.

### 5.6 "2층을 추가하려면?" — 목표 절차

```
1. 2층 노드에 EspLink 를 올리고 device_id 를 P2 로 둔다   (펌웨어 재빌드 없음. 설정만)
2. mapping.conf 에 P2 줄을 10개 추가한다
3. 서버 재시작
끝.
```

**서버 코드 변경 0줄 · 장치 코드 변경 0줄.** 이게 안 되면 설계가 목표를 달성하지 못한 것이다.

### 5.7 이행 단계 — 각 단계가 **끝났을 때 동작하는 상태**

| 단계 | 내용 | 끝났을 때 |
|---|---|---|
| A | 매핑 로더 + 검증 추가. **매핑이 없으면 기존 항등 매핑**(P1,i → A1..B5)으로 동작 | 지금과 완전히 동일하게 동작 |
| B | 서버 내부를 `space_id` 기준으로 전환(상행 해석만) | 동일 동작, 내부만 바뀜 |
| C | `unknown` 3-상태 도입 + **web-engineer 요청 발행** | 화면이 "모른다"를 표시 |
| D | 와이어에서 `reserved` 제거 + **arduino-engineer 요청 발행** | 프레임이 짧아짐 |

**A 단계가 핵심이다** — 항등 매핑 기본값 덕에 **현재 시연 가능 상태가 한순간도 깨지지 않는다.**

---

## 6. 두 작업의 순서 — **동시에 바꾸지 않는다**

오늘 가장 비싸게 배운 것: **변수를 둘 이상 동시에 바꾸면 무엇이 원인인지 못 가른다.**
(97% → 2.7% 가 망 때문인지 펌웨어 때문인지 지금도 못 가른다.)

**윈도우 이전과 매핑 개편은 둘 다 큰 변경이다. 겹치면 안 된다.**

```
1. 윈도우에서 현재 코드 빌드 시도        ← 사용자 필요. 최우선
2. 파이썬 도구 경로 이식                 ← 내가 지금 가능. 비용 작음
3. 윈도우에서 종단 검증 재실행           ← 대상 환경의 기준선을 처음 확보
4. PAL 분리 + 양쪽 빌드 확인
5. (여기서부터) 매핑 개편 A→B→C→D
```

**3번이 이 계획의 분기점이다.** 대상 환경에서 한 번도 돌려본 적 없는 것을 리팩터링하는 것보다,
**돌려보고 나서** 리팩터링하는 것이 훨씬 싸다.

## 7. 사용자·루트에게 물어야 할 것 (추측하지 않는다)

1. **컴파일러**: MSVC 인가 MinGW 인가? — 1절 예측이 갈린다
2. **현재 코드의 윈도우 빌드 결과**: 오류 전문
3. **장치에 표시등/부저가 있는가?** — 5.5 의 "하행 제거 가능성"이 여기 달렸다
4. **`reserved` 상행 제거 시 §7.6 불일치 감지를 버려도 되는가?**
5. 시연 서버를 윈도우에서 돌리는 것이 확정인가 (추가 절이 사실상 답했으나 확인)

**답이 오기 전에는 구현하지 않는다.** 특히 1·2 없이 PAL 을 시작하면 1절이 경고한
"리팩터링 탓인지 원래 그랬는지 못 가른다"에 그대로 빠진다.
