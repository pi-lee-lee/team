> 루트 승인 하에 **시험 인스턴스(`--port-offset=100`)로만** 실행했다.
> 운영 서버(pid 75781) · 운영 포트 · 시리얼 미접촉.
>
> **왜 지금 만드나**: 이음매 2(하행 이관)에서 `DEV_CONNECT`·`DEV_SENSORS` 를 옮기면
> `resync_reservations()` → `dispatch('R')` 의 **실행 시점이 바뀐다.**
> 옮기기 전 순서를 지금 찍어 두지 않으면, 나중에 "달라진 것 같다" 밖에 말할 수 없다.

## 1. 절차 (그대로 복사해 쓴다)

```bash
# ① 시험 서버 — 포트 +100(10091/10000/5600), 로그 경로 자동 분리
cd 조별과제샘플
c++ -std=c++11 -O2 -Wall -Wextra -DBUILD_ID='"<sha>"' -o server_test server.cpp
./server_test --port-offset=100 > /tmp/baseline-srv.out 2>&1 &

# ② 가짜 장치 — 빈 상태로 붙고 18초 뒤 재부팅(연결 끊고 재접속)
python3 net/fake_arduino.py --port 10091 --start-empty --reboot-after 18 > /tmp/baseline-ard.out 2>&1 &

# ③ 예약을 하나 심는다 — **이게 이 시험의 전제다**(살아 있는 예약이 없으면 R 이 안 나간다)
python3 net/ws_probe.py --port 10000 --reserve B3 --user u17 --listen 2

# ④ 재부팅을 기다렸다가 서버 로그의 재접속 구간을 본다
#    ⚠ 시각을 박아 넣지 마라 — 아래는 "마지막 재접속 구간"을 시각과 무관하게 뽑는다.
grep -n "주차 노드 접속\|재하달\|→ARD\|←ARD" \
     /Users/idong-u/parking-logs/parking-server.test+100.log | tail -20

# ⑤ 정리 — 운영 pid 를 절대 건드리지 않는다
pkill -f "fake_arduino.py --port 10091"
pkill -TERM -f "server_test --port-offset=100"
```

⚠ `--port-offset` 없이 띄우면 **`flock` 이 거부한다**(운영 로그를 이미 다른 인스턴스가 쥐고 있다).
이건 사고가 아니라 LEDGER §1.3 이 설계한 동작이다 — 실제로 이번에 걸렸고 정상이다.

## 2. 🔴 기준선 — 옮기기 **전**의 실제 순서 (2026-08-16 18:43:46, 실측)

```
109  +ARD 주차 노드 접속 — 세션#2 · device=P1              ← adopt_as_parking()
110  ⟳ 재부팅 감지(새 연결) — 살아 있는 예약 1건 재하달      ← resync_reservations("새 연결")
111  →ARD R,2,B3,u17,62                                   ← dispatch('R')  **전선 송신**
112  ←ARD S,0,0000000000,0000000000,1,P1,-,32             ← 첫 S 프레임 (drain_ard_buf)
113  ⟳ 재연결 판정: **재부팅** — uptime 17 → 1 · 공백 2초 (되감김)
114  = 은퇴 기준선 설정 — 이 프레임은 전이 판정을 건너뛴다
116  ←ARD A,2,B3,0,32                                     ← 장치 ACK
```

### 이 표에서 고정해야 할 사실 하나

> **`R` 송신(111)이 첫 `S` 프레임 처리(112)보다 먼저다.**

이음매 2 에서 `DEV_CONNECT` 를 `drain_dev_events()`(2481행)로 옮기면 **이 두 줄의 순서가 뒤집힌다.**
대조는 이 한 줄만 보면 된다.

**`C` 프레임은 나가지 않았다**(장치가 `reserved=0` 으로 돌아왔고 서버는 1이라 불일치 검사
조건 `slots[i].reserved == 0` 이 거짓). → 이 시나리오의 기준선에 `C` 는 없다.
`C` 까지 보려면 장치가 `reserved=1` 을 들고 돌아오게 만들어야 한다(`--real-slots`).

## 3. 덤으로 확정된 것 — (A) 판정이 **실왕복에서 처음으로 동작했다**

113행이 그것이다:

```
⟳ 재연결 판정: **재부팅** — uptime 17 → 1 · 공백 2초 (되감김)
```

지금까지 (A) 수정은 **재현 검증**(손으로 만든 입력)까지만 확인돼 있었다.
이번에 **진짜 소켓 재접속**에서 세션 경계를 넘어 판정이 났다:

- 세션#1 의 마지막 uptime 17 을 세션#2 까지 들고 갔다(`xs_uptime`)
- 되감김(17 → 1)을 잡아 **재부팅**으로 분류했다
- 같은 줄의 `재연결내역(재부팅 …/링크재접속 …/미상 …)` 카운터가 올라간다

⚠ 다만 이번 표본은 **되감김 경로만** 탔다. LEDGER §4.2 가 경고한 **`up < G`(공백보다 짧은
가동시간)** 경로는 이번에 안 탔다 — 그쪽은 여전히 재현 검증만 있다.
그것까지 실왕복으로 보려면 **옛 uptime 이 작고 공백이 긴** 시나리오가 필요하다
(예: 3초 가동 → 21초 끊김 → uptime 8 로 복귀). **다음에 이 절차로 만들 것.**
