> 쓸 수 있는 깨끗한 구간: **08-15 20:32~08-16 10:27(13.92h)** · **08-16 11:27~15:30(4.05h)**.
> 두 번째는 monitor 의 "11:27~15:27 4시간" 과 일치한다. ⚠ 무재부팅 ≠ 무중단(링크 단절 별도).

**소크 카운터에 미치는 영향(중요)**: 지금 카운터는 8/15 18:42 기동분 누적이라
**공백 버그가 살아 있던 구간을 포함한다.** 그 구간의 오프라인·재연결·미복구 수치는
**서버 회귀의 근거가 될 수 없다** — 원인이 장치 쪽이었다. 펌웨어가 고쳐진 정확한 시각을
나는 모르므로 **오염 구간의 경계를 확정하지 못한다**(arduino-engineer 가 특정할 수 있다).
→ §5 의 "새 기준선" 항목은 망 혼재뿐 아니라 **이 이유로도** 필요하다.

또한 이 카운터들은 **8/15 18:42 기동분 누적이라 두 망(192.168.50.x → 192.168.35.x)이 섞여 있다.**
REQ-0077 2번("소크 기준선을 새로 잡아라")은 여전히 미해결로 봐야 한다 — 단, 기준선을 새로
잡으려면 서버를 재기동해야 하고, §3 때문에 **지금은 재기동이 곧 영구 손실**이다.
**순서가 뒤집혔다: 헤더 복구 → 재빌드 성공 확인 → 그 다음에 재기동/기준선.**

## 5. 다음 한 걸음 (루트가 순서를 정할 것 — 내가 임의로 시작하지 않았다)

## 6. 재발 위험 — ✅ 이미 해소됐다 (루트가 먼저 고쳐 놨다)

**초안에서 나는 "`.gitignore` 를 먼저 고쳐라"라고 썼다. 확인해 보니 이미 고쳐져 있었다.**
직접 읽고 검증한 현재 `.gitignore` 43~50행:

```
# 검증 중에 만드는 임시 빌드(server_test 등). **소스는 추적한다.**
# ⚠ 2026-08-16: 이 규칙이 `조별과제샘플/server_*` 였다가 server_wire.h·server_seam.h·
#   server_device.h 같은 **소스까지 무시**했다. git status 에 안 보이니 아무도 몰랐고,
#   git clean 이 돌자 통째로 사라졌다(REQ-0054). 확장자를 가려서 바이너리만 막는다.
조별과제샘플/server_test
조별과제샘플/server_*.exe
조별과제샘플/server_*.o
조별과제샘플/server_*.out
```

즉 사고 원인 규칙은 **확장자 한정으로 좁혀졌고, 사고 경위까지 주석으로 남아 있다.**
→ **지금 `server_device.h` 를 다시 만들면 그 파일은 추적된다.** 같은 사고는 반복되지 않는다.
→ 헤더 복구 전에 `.gitignore` 를 손볼 필요가 **없다.** §5 의 순서를 막는 선행 조건은 사라졌다.

**교훈 하나**: 이 항목의 초안은 REQ-0055 본문을 그대로 믿고 쓴 것이었다. 그런데 같은 본문의
"서버 프로세스 죽음"은 §1 에서 이미 거짓으로 판명됐다. **사고 직후에 쓰인 피해 목록은
그 자체가 검증 대상이다** — 인용하지 말고 매번 원본을 직접 확인하라.

남은 노출: **이 인수인계 문서와 복원할 `net/` 도구 6종은 아직 untracked 다.** 커밋을 권한다.
`.gitignore` 는 루트 소유이며 내가 손대지 않았다.

## 7. 이 세션이 실행한 명령 전부 (전부 읽기 전용)

`ps aux` · `lsof -nP -iTCP -sTCP:LISTEN -p 36998` · `ipconfig getifaddr en0` ·
`curl -s -o /dev/null http://192.168.35.21:9900/` · `tail -40 /tmp/parking-soak.log` ·
`date` · `ls -l` · `grep -n '#include "' 조별과제샘플/server.cpp` ·
`grep -n -E 'struct SHA1|std::string base64|ws_accept' 조별과제샘플/server.cpp` ·
`.gitignore` 통독 · `git log/status/show/ls-tree/for-each-ref`

**파괴적 명령은 하나도 실행하지 않았다.** 파일 생성은 이 문서 하나뿐이다.
서버·시리얼 캡처를 되살리지 않았고, 사라진 파일을 복원하지 않았다 — REQ-0055 지시대로 목록만 남겼다.
