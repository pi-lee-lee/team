## 0. "전수"의 뜻과 목록의 출처

> ### **표본을 늘리는 것이 아니라 *목록에서 빠진 것이 없게* 하는 것이다.**
> **각 기능을 한 번씩만 밟아도 전수다. 대신 하나도 안 빠져야 한다.**

🔴 **목록은 기억이 아니라 소스에서 뽑았다** — `parking.h` 의 public 전부 + `spot.h`·`cmdresult.h`.
그 파일이 자기 머리에 *"이 파일만 읽으면 주차장을 만들 수 있어야 한다"* 고 적었으므로
**그 public 이 곧 기능 목록이다.**

## 5. 🔴 아직 한 번도 안 밟은 것 — 밟는 방법

```
A5 gate + 차단봉   `lot.cpp` 주석을 켠다. E1 을 자리로 만들고 `E1` 모듈을 붙인다
                   ⚠ 지금 칩에 `E1` 모듈이 없다(가상 차단봉을 껐다) → **미결속으로만 확인**되고
                     실제 조작은 못 한다. **그 한계를 명시한다**
A6 behavior        `lot.cpp` 에서 A1 에 AND 판정을 꽂고, 센서가 갈린 상태에서
                   `occupied` 가 **false** 인지 본다(기본 OR 이면 true)
B6 deviceReady F   기동 직후(등록 전)에 부른 결과를 로그로 찍는다 — **재기동만 하면 밟힌다**
🔴 B11 무응답      **장치가 ACK 을 안 보내야** 한다. 개입이 필요하다:
                   (가) 명령 직후 **장치 전원/연결을 끊는다** — 사용자 조작
                   (나) 없는 모듈 idx 로 억지 발행 — 🔴 **API 가 막는다**(이름을 먼저 푼다)
                   (다) `--max-line` 등으로 프레임을 깨뜨린다 — 🔴 **다른 축을 오염시킨다**
                   → **(가) 외에는 방법이 없다.** 사용자 조작이 없으면 **미측정으로 낸다**
```

⚠ **못 밟은 것은 "미측정"으로 낸다.** §*"선행 조건이 깨졌으면 항목 판정을 내지 마라"* —
**틀린 ✅ 는 사람을 안심시키고, 미측정은 아무도 안 속인다.**

## 6. 측정 판과 커밋 판이 다르다

```
측정 : `lot.cpp` 의 `onTick`·`onCmdResult`·gate·behavior 를 **켠 판**
커밋 : **주석 판**(기여자가 받는 것)
🔴 판정문에 두 판 차이를 값으로 적는다
```
