## 1. 왜 폭을 고정하나 — 목적은 바이트다

`N=3`(하행 건수 상한)의 이득이 **`rid` 자릿수에 걸려 있다.** 원장 §8.23-(58) 표:

```
rid 2자리 ACK 12B | N=3: 59B ✅
rid 3자리 ACK 13B | N=3: 62B ✅        ← 여기까지가 대역 밖
rid 4자리 ACK 14B | N=3: 65B 🔴        ← 이득 소멸
rid 5자리 ACK 15B | N=3: 68B 🔴
```

지금은 `next_rid++` 단조 증가라 **uint16 끝까지 자란다.** 즉 **설정을 안 바꿔도 지표가
저절로 움직인다** — 오래 돌리면 `rid` 가 4자리가 되고 `N=3` 의 이득이 사라진다.

> ### **그러므로 고정해야 할 것은 "지금 값"이 아니라 **자릿수의 상한**이다.**

**확정: `RID_SPACE = 1000` — `rid ∈ [0, 999]`, 최대 3자리.**
**⚠ 이 결정은 `N=3` 을 위한 것이고, `N` 은 아직 4다.** 폭을 먼저 고정하는 이유는
[2] `N 4→3` 을 별도 배포로 재기 위해서다(두 축을 한 창에 섞지 않는다).

## 2. 🔴 폭보다 먼저 답해야 하는 것 — **재사용 주기** (arduino §25.3)

**arduino 가 자기 소스에서 재서 알려 줬다.** 말로 받지 않고 파일로 받았고, 내가 그 파일을 읽었다:

```c
static const uint8_t CACHE_N = 16;                 // 527행
int8_t ghit = cacheFind(grid);                     // 2865행
if (ghit >= 0) { sendAck(...옛 값...); return; }   // 🔴 명령을 적용하지 않고 옛 ACK 을 재전송
```

> ### **최근 서로 다른 `rid` 16개 안에서 값이 재등장하면 그 명령은 조용히 삼켜진다.**
> ### ⚠ **서버는 ACK 을 받으므로 `ack_timeout` 도 안 뜬다. 실패가 성공처럼 보인다.**

**그리고 파서 쪽은 폭에 아무 가정이 없다**(§25.1: 쉼표 분해 · 선행 0 허용 · `≤65535` · 빈 필드 금지).
ACK 생성도 `%u` 라 가변폭이다(§25.2). **즉 폭 자체는 장치에 아무 영향이 없다.**

```
❌ 잘못된 질문 : 몇 자리로 줄여도 되나
✅ 올바른 질문 : **재사용 주기가 16보다 큰가**
```

**`RID_SPACE = 1000` 은 이 조건을 구조적으로 만족한다** — 되돌아오기까지 1000건이고 창은 16이다.
🔴 **2자리(100) 이하로는 내려가지 마라.** 16에 가까워질수록 안전 여유가 사라지고,
**16 이하면 구조적으로 항상 충돌한다**(arduino §25.3).

## 3. 격리 — **왜 필요하고 값이 왜 그 값인가**

폭을 1000으로 자르면 **재사용이 실제로 일어난다.** 두 가지가 깨질 수 있다:

| 위험 | 무엇이 깨지나 | 막는 법 |
|---|---|---|
| **① 살아 있는 `pend` 와 충돌** | ACK 이 **엉뚱한 명령**에 붙는다 | 🔴 **하드 규칙** — `pend` 에 있는 rid 는 절대 발행하지 않는다 |
| **② 늦은 ACK** | 이미 해제된 rid 에 옛 ACK 이 붙는다 | **격리** — 해제 뒤 일정 시간 재사용 금지 |

### 3.1 격리 시간 — **리터럴 금지. 상수에서 유도한다**

```cpp
RID_QUARANTINE_MS = ACK_TIMEOUT_MS * ACK_MAX_TRIES     // 2400 × 3 = 7200ms
```

**근거**: 서버가 한 명령을 포기하는 것은 `ACK_MAX_TRIES` 번의 타임아웃을 다 쓴 뒤다.
그보다 더 늦게 오는 ACK 은 **재전송 예산 전체보다 늦은 것**이므로 "없는 것"으로 다룬다.

⚠ **이건 가정이지 관측이 아니다.** 장치가 그보다 늦게 ACK 하지 않는다는 것을 **잰 적이 없다.**
🔑 **그래서 계수를 붙인다**(§5) — 가정이 깨지면 `ACK 미상rid` 가 오른다.
**가정을 코드에 박고 그것을 보는 칸을 안 만들면, 깨져도 아무도 모른다.**

### 3.2 🔴 `ack_budget_ms`(12.6초)가 아니라 7.2초인 이유 — 그리고 그 차이

서버의 미결 수명 상한은 `ack_budget_ms() = 12600ms` 다(창 대기·틱 해상도 포함).
**격리를 7.2초로 두면 그 사이 2.4초의 창이 남는다** — 큐에서 오래 기다린 건의 늦은 ACK.

**그래도 7.2초로 간다.** 이유: ①이 하드 규칙이라 **그 구간의 rid 는 아직 `pend` 에 있고
발행되지 않는다.** 격리는 **`pend` 를 떠난 뒤**의 보호이고, `pend` 를 떠나는 시점이 곧
"재전송 예산을 다 썼다"이므로 거기서부터 7.2초를 세는 것이 맞다.
⚠ **이 논증이 틀렸다면 `ACK 미상rid` 계수가 그것을 말해 준다.**

### 3.3 압력이 높을 때 — **끊지 말고 눈에 보이게 한다**

주입기가 초당 수십 건을 넣으면 `pend + 격리`가 1000을 채울 수 있다. 그때 선택지는 둘이다:

```
(가) 명령을 거절한다      → 🔴 화면 계약(blocked_reason)에 새 사유가 생긴다. **축이 하나 는다**
(나) 가장 오래된 격리를 강제 해제하고 발행한다 → 거동 동일 · 안전만 확률적으로 낮아진다
```

**(나)를 고른다.** 이 배포의 목적은 **바이트 축 하나**이고, 거절 경로를 새로 만들면
`>=64B` 진입률 측정에 다른 축이 섞인다. **대신 `강제` 계수를 요약에 낸다** — 압력이 실제로
그 지점까지 갔는지가 값으로 남는다.
🔴 **`pend` 충돌은 (나)에서도 절대 허용하지 않는다.** 그건 자료를 조용히 오염시킨다.

## 4. 🔴 열린 위험 — **서버 재시작이 이 변경으로 나빠진다** (결정 필요 · 루트)

**arduino §25.3 이 실측 기록으로 남겨 둔 고장이다**(그쪽 소스 542~546행):
> *서버 재시작으로 `wire_rid` 가 1부터 다시 시작했고, 아두이노는 재부팅하지 않아
> 옛 세션의 `rid` 가 캐시에 남아 명령이 삼켜졌다.*

**지금(단조 65536)은 이 고장이 사실상 안 난다** — 재시작 시점의 `rid` 는 이미 크게 자라 있어
장치 캐시의 옛 값(큰 수)과 새 값(1,2,3…)이 겹치지 않는다.
🔴 **폭을 1000으로 자르면 옛 값이 `[0,999]` 에 고르게 퍼지므로 겹칠 확률이 생긴다**
(대략 **재시작마다 1.6%**, `16/1000`).

> ### **폭 축소가 이 고장을 만드는 것이 아니라, 폭 축소가 그 고장을 *가능하게* 만든다.**

**서버 단독으로 가능한 안**은 셋이고 **전부 대가가 있다. 루트가 고른다:**

```
(A) 아무것도 안 한다 + 계수만 본다   대가: 재시작 직후 최대 16건이 조용히 삼켜질 수 있다(1.6%)
(B) 커서를 디스크에 남긴다           대가: 디스크 축이 하나 는다(data_log.json 경로 종속)
(C) 장치가 새 서버 판을 보면 캐시를 비운다  🔴 **전선 변경 — arduino 축이다. 이 배포에 못 넣는다**
```

~~**지금 코드는 (A)로 쓴다.**~~ ⚠ **(A)를 고른 것이 아니라 (B)·(C)가 이 배포의 범위 밖이라
기본값이 (A)가 된 것이다.** 그 차이를 여기 적어 둔다 — 안 적으면 다음 사람이
*"검토해서 A로 정했다"* 로 읽는다.

### ✅ 🔴 **루트가 (B)로 바꿨다** (REQ-0246 · 2026-08-19 · 위 문장은 지우지 않는다)

**루트의 판단이 내 것보다 한 겹 깊었다.** 나는 이것을 *"폭 축소가 만든 새 위험"* 으로 적었는데:

> ### **arduino §25.3 은 그 고장의 *실측 기록* 이다. 단조 65536 인 지금 상태에서 이미 한 번 일어났다.**
> ### **(B)는 A[1] 이 만든 위험을 막는 것이 아니라, 있는 결함을 닫는 것이다.**

그리고 **`1.6%` 의 분모가 "재시작"이다** — 개발 단계라 하루에 몇 번씩 재시작한다.
**드문 사건이 아니라 자주 돌리는 주사위다.**
🔑 그 고장의 얼굴이 *"차단봉이 안 열렸는데 서버는 성공으로 기록한다"* 이고,
**계수만 두는 것은 그 부류를 계수 뒤에 두는 것이지 없애는 것이 아니다.**

#### 구현 — 블록 예약 (`RID_PERSIST_BLOCK = 256`)

```

🔑 적는 값이 **실제 사용보다 항상 앞선다** → 갑자기 죽어도 재시작이
   **방금 쓴 값을 다시 내주지 않는다.** 건너뛸 뿐이고 건너뛰는 것은 무해하다
⚠ 반대로 "쓴 뒤에 적는" 방식이면 크래시 때 **가장 최근에 쓴 값들**을 재발행한다 —
  장치 캐시와 겹칠 확률이 가장 높은 구간을 정확히 다시 밟는다
```

> 그때 나오는 거동이 정확히 (A)다 — 막으려던 것으로 조용히 되돌아간다.**

## 5. 감시와 **볼 자리** — 세는 것과 보이는 것은 다른 일이다

루트 규칙 ③(원장·CLAUDE.md): **조건 → 감시 → 그 결과를 볼 자리**까지가 한 벌이다.
`mod_order_changed` 가 셋째를 빠뜨려 **monitor 에게 없는 칸을 보라고 한** 사고가 있었다.

**요약 줄에 낸다 (분모를 같이 낸다):**

```
· rid 다음 <next>/1000 · 격리 <q>건 · 건너뜀 <skips> · 강제 <forced>
· ACK 미상rid <unknown> · 자리불일치 <mismatch>
```

| 칸 | 뜻 | 🔴 이 값이 낮아지는 **다른** 이유 |
|---|---|---|
| `건너뜀` | 발행하려다 `pend`/격리라 넘어간 횟수 | **발행 자체가 적으면 0이다.** `다음` 커서가 안 움직이면 그 경우다 |
| `강제` | 공간이 차서 격리를 조기 해제 | 0 이 정상이다. **1 이상이면 §3.3 지점까지 갔다는 뜻** |
| `미상rid` | `pend` 에 없는 rid 의 ACK | 재전송 중복도 여기 온다 — **격리 가정(§3.1)이 깨지면 여기가 오른다** |
| `자리불일치` | ACK 의 에코 자리 ≠ 서버가 보낸 자리 | 🔴 **장치 멱등 캐시 재전송의 서명**(§2). 0 이 정상 |

⚠ **`자리불일치` 는 이번에 *탐지만* 넣는다. 거동은 안 바꾼다** — §6.

## 6. ⚠ 이번 배포에 **안 넣는 것** (일부러)

### 6.1 ACK 에코 자리를 신뢰할지 — **거동 변경이라 뺀다**

현재 코드(`server.cpp` ACK 처리):
```cpp
if (slot == "??" || slot_index(slot) < 0) slot = p.slot;
```
**주석은 *"전선의 자리 값을 믿지 않고 매핑표의 원래 자리를 쓴다"* 라고 적혀 있는데,
코드는 *"전선 값이 유효한 자리면 그걸 쓴다"* 이다.** 둘이 어긋나 있다.

🔴 **주석대로 고치는 것은 거동 변경**이므로 이 배포에 안 넣는다. **탐지·계수만 넣는다.**
**결정은 루트에게 올린다** — 어긋남을 발견한 것과 어느 쪽이 옳은지 정하는 것은 다른 일이다.

### 6.2 `N 4→3` — [2]다. 같은 배포에 넣지 않는다

**둘 다 하행 크기를 바꾸므로 한 배포에 섞이면 `>=64B` 진입률의 귀속이 안 된다.**
**[1] 배포 → 측정 → [2] 배포 → 측정.** (루트 확정 · 원장 `hex` 교훈)

### 6.3 `DRAIN_DECL` 상향 — arduino 축이고 **계약 고정 뒤**다

arduino §25.4: `DRAIN_DECL = 7` 은 **`rid` 5자리 가정(`ACK_worst ≈ 15B`)의 보장 하한**이라
폭이 줄어도 **여전히 유효**하다(보수적이라 안 깨진다).
그쪽이 *"폭이 계약에 박히면 그때 `ACK_worst` 를 다시 계산해서 올린다"* 고 했다.
🔑 **그 시점은 이 문서가 확정되고 배포가 끝난 뒤다. 내가 알린다.**

## 7. 검증 — 무엇을 밟고 무엇을 **못 밟나**

**밟는 것 (selftest)**
```
· 발행이 [0,1000) 안에 있다 · 1000건을 넘겨 발행해도 자릿수가 3을 안 넘는다
· pend 에 있는 rid 는 재발행되지 않는다 (하드 규칙)
· 격리된 rid 는 RID_QUARANTINE_MS 전에는 안 나온다
· 공간이 차면 강제 해제로 발행하되 pend 와는 절대 안 겹친다 · 강제 계수가 오른다
· 재사용 간격이 항상 DEV_RID_CACHE_N(16)보다 크다   ← 🔴 arduino 제약의 시험 판본
```

**🔴 못 밟는 것 — 분모를 먼저 적는다**
```
· 장치 멱등 캐시의 실제 삼킴  — 실기 장치가 있어야 한다. selftest 로는 못 만든다
· 늦은 ACK 의 실제 최대 지연  — §3.1 의 가정은 **잰 적이 없다**
· 재시작 충돌(§4)             — 확률 1.6% 사건이라 시험으로 재현할 수 없다
```
> ### **`N pass / 0 fail` 은 위 셋을 하나도 안 말한다.**
