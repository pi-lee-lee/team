# 조립 API v2 — 기여자가 배우는 것을 **다섯**으로 줄인다

> 사용자 확정(2026-08-20): *"내부 로직적으로는 **스폿이 뭔지 몰라도 된다.** 모듈과 연동하여
> 동작만 하면 된다. 맵에서의 위치도 **사용자 인식용**이다. `at` 과 `spot` 이
> **주차영역인지 일반영역인지 구분하는 구분자만** 추가하자."*

작성: socket-engineer · 2026-08-20 · **이름·형식·시점·계산 주체를 여기서 못 박는다**
🔴 **web 이 지어내지 않게 하는 것이 이 문서의 목적이다.**

---

## §1 기여자가 쓰는 것 — 다섯

```cpp
lot.spot("A1").at(0,0).parking()           // 🔴 주차영역 — 점유·예약이 뜻이 있다
      .label("1번 자리")
      .module("P1","A1").module("P1","B1").module("P1","LD").module("P1","L2");

lot.spot("E1").at(0,2)                      // 일반영역 (**기본값**)
      .label("입구").module("P1","DR");
```
**`spot` · `at` · `parking` · `label` · `module` — 다섯. 그 밖은 없다.**

### 🔴 `parking()` 이 **유일하게 엔진 동작을 바꾼다**
```
① 점유 계산에 든다   ② 예약 대상이다   ③ 옛 격자(폴백)에 든다
그 밖에는 **엔진이 자리가 무엇인지 몰라도 된다** — 사용자 말 그대로다
```
⚠ **기본값은 "일반영역"이다.** `parking()` 을 **적어야** 주차 자리가 된다.
🔑 **왜 그 방향인가**: 안 적었을 때 **점유·예약이 안 생기는 쪽**이 조용히 틀리지 않는다.
반대로 두면 입구가 *"비어 있는 주차 자리"* 로 화면에 뜬다.
> **틀렸을 때 조용한 쪽을 기본값으로 두지 마라.**

---

## §2 없앤 것과 그 근거

| 없앤 것 | 근거 |
|---|---|
| `sensor()` / `actuator()` → **`module()` 하나** | 🔑 **장치가 `kind` 첫 글자로 이미 말한다**(`I` 관측 · `O` 명령). 서버가 그것을 보고 가른다. **조립 표에서 또 가를 이유가 없다** |
| `gate(id, Gate::Kind)` · 🔴 **`Gate` enum 통째로** | 입구/출구는 **표시**일 뿐이고 `label` 이 그것을 한다 |
| `entrance` / `exit` 자리 종류 | `kind` 가 **`"parking"` / `"area"`** 둘로 줄어든다 |

### 🔴 `Gate` 를 없애면 Windows 충돌이 **원인부터** 사라진다
`<windows.h>` 가 `IN`·`OUT` 을 빈 매크로로 정의해 `enum Kind { IN, OUT };` 이 깨졌다.
**`#undef` 는 증상 대처였고, enum 이 사라지면 그 증상이 안 생긴다.**
⚠ **그래도 `#undef` 는 남긴다** — `windows.h` 는 짧은 이름을 많이 정의하고
**다음에 다른 이름이 걸릴 수 있다.** 🔑 **비용이 두 줄이고, 없앴을 때의 손실은 조용한 빌드 실패다.**

## §3 🔴 딸린 결과 — **등록 전에는 무엇이 센서인지 모른다**

```
지금  : `sensor()`/`actuator()` 가 **선언 시점**에 갈랐다
v2   : 🔴 **장치 등록(`D`)이 와야** `kind` 를 알고, 그때 갈린다
```
**그래서 등록 전에는 `value_total`(센서 수)을 셀 수 없다.**
- 등록 전 : `value_state:"unknown"` · `value_known:0` · **`value_total:0`**
- 🔑 **그게 정직한 답이다.** 선언만 보고 센서 수를 세면 **장치가 다른 것을 보고해도 안 바뀐다** —
  그건 *"아는 척"* 이다.
- ⚠ **web 은 등록 전 자리를 "센서 0개"로 그리지 말고 "아직 모름"으로 그려라.**

## §4 `at(행, 열)` — **사용자 인식용. 엔진은 안 쓴다**

```cpp
lot.spot("A1").at(0, 0);      // 0-기준 행·열
```
- **격자 좌표다. 자유 좌표가 아니다** — 주차장은 격자다.
- 🔴 **안 적으면 지금처럼 선언 순서대로 자동 배치**된다. 기존 샘플이 안 깨진다.
- **격자 크기는 서버가 계산한다** — `rows = max(행)+1` · `cols = max(열)+1`(최소 1×1).
  ⚠ 화면이 상수로 갖지 마라. `map.grid` 가 그 순간 값이다.

### ⚠ 좌표가 겹치면 — **말한다. 막지 않는다**
```
기동 로그가 **두 자리 id 를 지목해** 말한다:
  🔴 자리 `A1` 과 `B1` 이 같은 칸 (0,0) 에 있다 — 화면에서 하나가 가려진다
```
🔑 **막지 않는 이유**: 겹침은 **표시 문제**이고 서버 동작은 멀쩡하다.
기동을 막으면 기여자가 *"내 것 때문에 서버가 안 뜬다"* 로 겁을 먹는다 —
§"증상이 보이면 말하고, 안 보이면 막아라".
🔴 **다만 겹침의 증상이 *가려짐* 이라 조용할 수 있다.** 그래서 **로그가 반드시 지목해야** 하고,
**web 은 칸이 유일하다고 가정하지 마라** — 겹치면 겹친 것을 보이게 그려 달라.

## §5 봉투 — 무엇이 바뀌나

### `map` 의 자리
```json
{"id":"A1","kind":"parking","label":"1번 자리","cells":[[0,0]],
 "modules":[{"devid":"P1","name":"A1","kind":"IP","idx":0,"label":"왼쪽 센서"}]}
```
| 키 | 변화 |
|---|---|
| `kind` | 🔴 **`"parking"` 또는 `"area"` 둘뿐.** `entrance`·`exit` 는 **안 나온다** |
| `cells` | 그대로. `at()` 이 정하거나 자동 배치 |
| `label` · `modules[]` | 그대로 |
| `grid` | 그대로. 다만 **`at()` 에서 계산된다** |

### 🔴 `map.zones[].active` — **모듈이 하나도 안 붙은 주차 자리** (REQ-0292 · 2026-08-20)

```json
{"id":"A2","kind":"parking","active":{"ok":false,"reason":"no_modules"},"cells":[[0,1]],"modules":[]}
{"id":"A1","kind":"parking","active":{"ok":true,"reason":null},  …}
{"id":"E1","kind":"area",   "active":{"ok":true,"reason":null},  …}
```

| 항목 | 값 |
|---|---|
| **계산 주체** | 🔴 **서버.** 조립 표를 가진 것이 서버다. **화면이 모듈 수를 세지 마라** |
| **전달 시점** | `map` — 접속 시. **조립 시점 사실이라 런타임에 안 바뀐다** |
| **모든 자리에** | 🔴 항상 싣는다. 선택적이면 화면이 안 본다 |
| **모양** | `actions.*` 와 같은 `{ok, reason}` — 화면이 이미 아는 꼴이다 |
| **`reason` 닫힌 집합** | 지금은 `"no_modules"` 하나. `ok:true` 면 `null` |
| 판정 | `kind == "parking"` 이고 **조립 표의 선언 모듈 수가 0** |

#### 🔑 `value_state:"unknown"` 을 **대체하지 않는다**
그 자리의 점유는 여전히 모르는 것이 맞다. `active` 는 **그 무지의 *이유*** 를 말한다 —
*"센서가 고장난 게 아니라 애초에 아무것도 안 붙였다."*
> **`known:false` 를 `known:true`(틀림)로 바꾸지 않는다. 무지에 이유를 붙일 뿐이다.**

#### ⚠ 갈라야 하는 두 상태 — 같은 이름으로 부르지 마라
```
모듈이 **0개**            → 조립 시점에 안다  → 이 필드(`active`)
모듈은 있고 **센서가 없다** → 등록 뒤에 안다   → `bind_modules()` 의 기동 로그 경고
```

#### 🔴 구현 함정 (실제로 밟았다 — 시험이 잡았다)
**`Zone::modules` 로 세면 안 된다.** 그것은 *결속된* 모듈이라 **장치 등록 전에는 비어 있다** —
그걸로 판정하면 자리가 부팅 직후 "비활성"이었다가 등록되면 살아난다. **없는 결함을 화면에 만든다.**
✅ 세는 곳은 **`ParkingLot::areas()[].modules`**(조립 표)다.
⚠ 조립 표가 없는 경로(기본 지형 · 자가검증)에서는 **판정하지 않는다**(`ok:true`) — 셀 것이 없는데
"0개"라고 말하는 것은 지어내는 것이다.

### `state` 의 자리
- `actions` : `parking` 이 아니면 **`reserve`/`cancel` 이 안 나온다**(지금과 같은 규칙, 조건만 바뀜)
- 🔴 **`open_gate`/`close_gate` 는 이미 없앴다**(2026-08-20 앞선 변경)
- `occupied`·`value_*` : **`parking` 자리에만** 뜻이 있다

### 🔴 자리의 `completion` 을 **없앤다** — 이미 죽어 있었다

게이트 내장 조작을 없앤 뒤로 **`gate_want` 에 값을 쓰는 곳이 하나도 없다**(전수 확인).
그래서 자리의 `completion` 은 **`pending` 아니면 `unknown`** 만 나온다 —
```
"settled" · "mismatch" 는 **도달 불가**다. 실기 실측도 `unknown` 2건뿐이었다
```
🔴 **닫힌 집합 넷이라고 적어 둔 명세가, 일어날 수 없는 상태 둘을 계속 말하고 있었다.**
§"발생 불가능한 상태를 세라" · §"적혀 있다를 있다로 읽는다" 그대로다.

→ **자리 `completion` 을 봉투에서 뺀다.** 그 질문의 답은 이제 **모듈의 `confirmed`** 다.
🔑 자리는 여러 모듈을 갖는데 `completion` 은 **하나뿐**이었다 — 애초에 자리 단위로 답할 수 없는 물음이다.

### ⚠ web 이 고쳐야 하는 것
```
① `kind === 'entrance' || 'exit'` 로 분기하는 곳 → **`kind !== 'parking'`** 으로
② 입구/출구를 이름으로 구분하던 곳 → 🔑 **`label` 을 쓴다**
③ 등록 전 `value_total:0` 을 "센서 없음"으로 읽지 마라 → **"아직 모름"**
④ 격자 칸이 **겹칠 수 있다**
🔴 ⑤ **`zone.completion` 이 사라진다** — 자리 요약은 **모듈들의 `confirmed`** 로 만들어라
```

## §6 판별자 — 🔴 **봉투 sha256 은 못 쓴다**

이번엔 **봉투가 일부러 바뀐다.** 그래서 그 대조는 판별자가 아니다.
```
✅ 자가검증 통과
✅ 기동 로그의 **자리 수 · 모듈 수**가 같다
✅ `sync_check.sh` — 새 `lot.cpp` 가 **양쪽 트리에서** 컴파일·링크된다
✅ 🔴 실기 : **지금과 같은 화면** — 이름 · 토글 · 숫자 칸 · 자리 둘
   그리고 `send_cmd` 왕복(LD 1 · L2 1234567 · 범위 초과 거절)이 그대로 돈다
```
⚠ **"같은 화면"을 눈으로만 보지 마라** — `map`/`state` 의 **키와 값을 뽑아 대조**한다.
