# 주차 관제 데모 — 진행 상황 (인수인계)

> 대상: `조별과제샘플/client.ino`, `조별과제샘플/server.cpp`, `조별과제샘플/index.html`
> 원본은 그대로 개선한다 — 새 트리로 옮기지 않는다(README 의 실행 절차가 깨진다).
> 프로토콜 원본: `docs/net/parking-protocol.md` (socket-engineer 소유, 작성 중)

## 무엇을 만드는가

2열 5행 = 10칸 주차장. 각 칸에 센서가 있다고 **가정**한다(실물 미설치).

```
브라우저(index.html)          서버(server.cpp)              아두이노(client.ino)
      │                              │                            │
      │  WebSocket  ws://:9900/ws    │   TCP :9991 압축 ASCII 라인  │
      ├─────────────────────────────>│<───────────────────────────┤
      │   예약 요청 {slot,user_id,rid}│    상태 프레임(변화시 즉시)  │
      │                              ├───────────────────────────>│
      │                              │    예약 하달 R|rid|slot|uid │
      │                              │<───────────────────────────┤
      │<─────────────────────────────┤    예약 ACK (rid 로 상관)   │
      │   확정 브로드캐스트           │                            │
      │                              └─> data_log.json (최신 2건, 원자적 교체)
      │  HTTP :9900 (같은 프로세스가 index.html / data_log.json 도 서빙)
```

## 왜 이 구조인가

| 결정 | 근거 |
|---|---|
| 브라우저만 WebSocket, 아두이노는 raw TCP | 브라우저는 raw TCP 소켓을 못 연다. 아두이노는 반대로 WS 프레이밍을 감당할 여유가 없다. 좁은 쪽(9600bps)만 압축한다 |
| 서버가 HTTP 도 직접 서빙 | `python -m http.server` 를 따로 띄울 필요가 사라지고, 같은 오리진이라 CORS 가 없다 |
| `occupied` 와 `reserved` 를 분리 | 하나로 합치면 "예약해 둔 자리에 차가 들어옴"이라는 정상 시나리오를 표현할 수 없다 |
| data_log.json 을 임시파일+rename 으로 교체 | 사용자가 "파일 복사 분할"을 고려하라 했으나, 동시 읽기 문제의 정석은 원자적 교체다. 독자는 옛 파일 전체나 새 파일 전체만 보고 반쯤 쓰인 파일을 볼 수 없다. 잠금도 복사본도 불필요. **윈도우는 `rename()` 이 기존 파일에 실패하므로 `MoveFileEx(..., MOVEFILE_REPLACE_EXISTING)`** |
| 압축 ASCII 라인 (JSON 아님) | 아래 대역폭 참조 |
| 변화시 즉시 + 주기 갱신 | 3초 고정 주기는 실시간이 아니다. 변화 없는 구간에서 채널을 비워 두는 것이 요점 |

## 현행 코드의 결함 (개선 대상)

**client.ino**
- SoftwareSerial 9600bps 에 150바이트 JSON — 초당 약 960바이트가 상한이라 여유가 없다
- `AT+CIPSEND=<n>` 뒤 `delayMicroseconds(1200)` — 모듈의 `>` 프롬프트를 기다리지 않는 경합
- 수신측이 `+IPD,<len>:` 프레이밍을 파싱하지 않고 원시 스트림에서 `"pin":` 을 훑는다 — 우연히 동작하는 코드
- `String` 연결 — AVR 힙 단편화. 장시간 구동 데모에서 실제로 죽는 경로
- setup 의 `delay(2000)` 연쇄 — 블로킹

**server.cpp**
- Winsock 전용이라 macOS 에서 빌드·검증 불가
- 단일 클라이언트 블로킹 accept — 브라우저와 아두이노를 동시에 못 받는다
- data_log.json 에 무한 append — 파일이 계속 커지고, 최신 2건 유지 요구와 어긋난다
- 예약 하달 경로 없음 (수신 전용)

**index.html**
- 10초 폴링 — 실시간이 아니다
- 센서 카드/표만 있고 주차 격자와 예약 UI 가 없다
- 서버로 보내는 경로가 아예 없다

### 루트 통합 검증 — 아무도 못 하던 구간

web-engineer 는 서버가 없어 WS 코드를 **검토만** 했고, socket-engineer 는 브라우저 없이
자기 도구로만 확인했다. **그 사이가 비어 있었다.** 루트가 실제 Chrome 을 CDP 로 몰아 메웠다
(하네스는 스크래치패드의 `integration.py`, 스크린샷 5장 포함):

```
PASS  자리 타일 10개가 §1 순서로 렌더  — ['A1'..'A5','B1'..'B5']
PASS  센서 온라인
PASS  클릭 가능한 빈 자리 존재 — A1
PASS  예약 확인 대화가 뜬다 — "예약하시겠습니까? / A1 자리를 예약합니다…"
PASS  예약이 확정 상태로 반영됨 — A1 = '사용 중 (입차 완료) / 내 예약'
PASS  occupied=1,reserved=1 조합이 화면에 나타남
PASS  출차 후 예약이 은퇴되어 다시 빈 자리가 됨      ← REQ-0022 의 요점
JS 오류 0건
```

그 밖에 루트가 독립 재현한 것: 빌드(`-Wall -Wextra` 경고 0), WS accept 벡터 독립 계산,
16비트 확장 길이 실사용(831B / 길이필드 `0x033F`), ack 타겟팅(클라 2개), `data_log.json` 2건 유지,
ACK 유실 시 **동일 wire_rid** 재전송, 재부팅 후 예약 재하달.

### 전선 포맷 교차 검증

arduino-engineer 가 손으로 편 바이트 트레이스와 socket-engineer 의 `net/fake_arduino.py` —
**서로 다른 두 구현이 4줄 전부 일치.** 자기 보고끼리가 아니라 독립 구현끼리 맞은 것이다.

### 아직 검증되지 않은 것 (추정을 통과로 적지 않는다)

- **Windows 빌드·실행.** 이 팀의 어떤 머신에서도 컴파일할 수 없다. cpp-engineer 의 정적 검토
  (REQ-0021)와 그 반영(REQ-0023)까지가 한계다. `MoveFileEx` 원자적 교체 경로도 미검증.
- **실제 아두이노 보드.** `>` 프롬프트 타이밍, ESP-01 의 실제 AT 응답 문구,
  SoftwareSerial 송신 중 수신 유실의 실제 정도는 실기에서만 확인된다.
  `fake_arduino.py` 는 루프백 TCP 라 9600bps 지연도 유실도 재현하지 않는다 —
  `--drop-rate` 는 그 **결과만** 흉내낸다.
- 부하·동시 접속 한계 (데모 규모 가정).

명세를 먼저 얼린 이유: 세 도메인이 같은 전선 포맷에 합의해야 한다. 병렬로 먼저 풀면
서로 안 맞는 포맷 세 개가 나온다. 명세가 확정된 뒤에야 셋을 동시에 풀었다.

### 루트가 명세를 검산한 결과 (REQ-0016 수용 전)

세 담당이 이 문서 하나로 병렬 구현하므로 예제가 1바이트만 틀려도 셋 다 깨진다. 그래서 수용 전에 재계산했다:

| 항목 | 결과 |
|---|---|
| 체크섬 예제 8건 (§2.5) | 전부 일치 |
| `Sec-WebSocket-Accept` 자가검증 벡터 (§5.1) | RFC 6455 예제와 일치 |
| 스냅샷 직렬화 크기 (§5.3) | 845 B — 125 B 초과 확인. **WS 16비트 확장 길이 필수**가 맞다 |
| 9600bps 대역폭 (§3.2) | 1Hz 최대프레임 6.15 %, 최악 14.90 % — 재계산 일치 |

### socket-engineer 가 올린 판단 3건 — 전부 승인

1. **ACK `result=2`(이미 예약됨) 추가.** 루트가 준 3종(성공/이미점유/잘못된자리)이 불완전했다.
   `occupied`/`reserved` 를 직교로 정한 이상 "비었지만 남이 예약한 자리"가 실제로 발생한다.
2. **`rid` 를 두 이름공간으로 분리** (브라우저=문자열 / 전선=서버 발급 uint16, 서버가 번역).
   브라우저 둘이 같은 rid 를 고르는 건 가정이 아니라 시간문제다.
3. **예약의 durable owner = 서버.** 아두이노는 전원이 끊기면 `reserved` 를 잃지만 서버는 안 잃는다.
   센서 진실값(`occupied`)의 주인은 아두이노, 사람의 약속(`reserved`)의 주인은 서버.

### 명세가 잡아낸, 루트가 놓쳤던 함정 둘

- **SoftwareSerial 은 송신 중 수신을 잃는다** (§6.3). AVR 의 `write()` 가 인터럽트를 끈 채 블로킹하므로
  57~61 ms 동안 들어온 바이트가 지연이 아니라 **유실**된다. → 서버 재전송(§7.3)과
  아두이노 rid 멱등성(§4.2)이 선택이 아니라 필수가 된다.
- **WS 스냅샷이 845 B** 라 7비트 길이 필드로는 못 보낸다 (§5.2). ack(82 B)만 시험하면 통과하고
  첫 스냅샷에서 깨진다.

## 소유권 메모 (루트가 처리함)

`조별과제샘플/server.cpp` 는 확장자 규칙상 `cpp-engineer` 로 떨어지지만 내용은 소켓 서버다.
`.claude/ownership.json` 에 파일 단위 경로 규칙을 추가해 `socket-engineer` 로 돌렸다.
폴더 전체(`조별과제샘플/**`)를 주지 않은 이유는 `.ino`/`.html` 까지 뺏기기 때문이다.

**같은 규칙을 NFC 와 NFD 두 형태로 적어 두었다 — 중복이 아니다.** macOS 는 같은 한글 경로를
두 정규화 형태로 넘기는데 `ownership_guard.py` 는 정규화를 하지 않는다. 한쪽만 적으면
다른 형태로 들어온 경로가 **조용히** 확장자 규칙으로 새어나가 `cpp-engineer` 소유가 된다.
실측으로 확인했다:

```
NFC 조별과제샘플/server.cpp -> socket-engineer (경로 규칙)
NFD 조별과제샘플/server.cpp -> cpp-engineer    (확장자 규칙)   ← 규칙 추가 전
```

한글 경로를 다루는 규칙을 추가할 때마다 이 함정을 다시 밟게 된다. 근본 해결은 훅에서
경로와 글롭을 NFC 로 정규화하는 것이지만, 훅 편집이 이 세션에서 차단되어 데이터 쪽으로 우회했다.
