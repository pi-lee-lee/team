# 주차 관제 데모 — 진행 상황 (인수인계)

> 대상: `조별과제샘플/client.ino`, `조별과제샘플/server.cpp`, `조별과제샘플/index.html`
> 원본은 그대로 개선한다 — 새 트리로 옮기지 않는다(README 의 실행 절차가 깨진다).
> 프로토콜 원본: `docs/net/parking-protocol.md` (socket-engineer 소유, 작성 중)

## 무엇을 만드는가

2열 5행 = 10칸 주차장. 각 칸에 센서가 있다고 **가정**한다(실물 미설치).

```
브라우저(index.html)          서버(server.cpp)              아두이노(client.ino)
      │                              │                            │
      │  WebSocket  ws://:9900/ws    │   TCP :9991 압축 ASCII 라인  │
      ├─────────────────────────────>│<───────────────────────────┤
      │   예약 요청 {slot,user_id,rid}│    상태 프레임(변화시 즉시)  │
      │                              ├───────────────────────────>│
      │                              │    예약 하달 R|rid|slot|uid │
      │                              │<───────────────────────────┤
      │<─────────────────────────────┤    예약 ACK (rid 로 상관)   │
      │   확정 브로드캐스트           │                            │
      │                              └─> data_log.json (최신 2건, 원자적 교체)
      │  HTTP :9900 (같은 프로세스가 index.html / data_log.json 도 서빙)
```

## 왜 이 구조인가

| 결정 | 근거 |
|---|---|
| 브라우저만 WebSocket, 아두이노는 raw TCP | 브라우저는 raw TCP 소켓을 못 연다. 아두이노는 반대로 WS 프레이밍을 감당할 여유가 없다. 좁은 쪽(9600bps)만 압축한다 |
| 서버가 HTTP 도 직접 서빙 | `python -m http.server` 를 따로 띄울 필요가 사라지고, 같은 오리진이라 CORS 가 없다 |
| `occupied` 와 `reserved` 를 분리 | 하나로 합치면 "예약해 둔 자리에 차가 들어옴"이라는 정상 시나리오를 표현할 수 없다 |
| data_log.json 을 임시파일+rename 으로 교체 | 사용자가 "파일 복사 분할"을 고려하라 했으나, 동시 읽기 문제의 정석은 원자적 교체다. 독자는 옛 파일 전체나 새 파일 전체만 보고 반쯤 쓰인 파일을 볼 수 없다. 잠금도 복사본도 불필요. **윈도우는 `rename()` 이 기존 파일에 실패하므로 `MoveFileEx(..., MOVEFILE_REPLACE_EXISTING)`** |
| 압축 ASCII 라인 (JSON 아님) | 아래 대역폭 참조 |
| 변화시 즉시 + 주기 갱신 | 3초 고정 주기는 실시간이 아니다. 변화 없는 구간에서 채널을 비워 두는 것이 요점 |

## 현행 코드의 결함 (개선 대상)

**client.ino**
- SoftwareSerial 9600bps 에 150바이트 JSON — 초당 약 960바이트가 상한이라 여유가 없다
- `AT+CIPSEND=<n>` 뒤 `delayMicroseconds(1200)` — 모듈의 `>` 프롬프트를 기다리지 않는 경합
- 수신측이 `+IPD,<len>:` 프레이밍을 파싱하지 않고 원시 스트림에서 `"pin":` 을 훑는다 — 우연히 동작하는 코드
- `String` 연결 — AVR 힙 단편화. 장시간 구동 데모에서 실제로 죽는 경로
- setup 의 `delay(2000)` 연쇄 — 블로킹

**server.cpp**
- Winsock 전용이라 macOS 에서 빌드·검증 불가
- 단일 클라이언트 블로킹 accept — 브라우저와 아두이노를 동시에 못 받는다
- data_log.json 에 무한 append — 파일이 계속 커지고, 최신 2건 유지 요구와 어긋난다
- 예약 하달 경로 없음 (수신 전용)

**index.html**
- 10초 폴링 — 실시간이 아니다
- 센서 카드/표만 있고 주차 격자와 예약 UI 가 없다
- 서버로 보내는 경로가 아예 없다

### 루트 통합 검증 — 아무도 못 하던 구간

web-engineer 는 서버가 없어 WS 코드를 **검토만** 했고, socket-engineer 는 브라우저 없이
자기 도구로만 확인했다. **그 사이가 비어 있었다.** 루트가 실제 Chrome 을 CDP 로 몰아 메웠다
(하네스는 스크래치패드의 `integration.py`, 스크린샷 5장 포함):

```
PASS  자리 타일 10개가 §1 순서로 렌더  — ['A1'..'A5','B1'..'B5']
PASS  센서 온라인
PASS  클릭 가능한 빈 자리 존재 — A1
PASS  예약 확인 대화가 뜬다 — "예약하시겠습니까? / A1 자리를 예약합니다…"
PASS  예약이 확정 상태로 반영됨 — A1 = '사용 중 (입차 완료) / 내 예약'
PASS  occupied=1,reserved=1 조합이 화면에 나타남
PASS  출차 후 예약이 은퇴되어 다시 빈 자리가 됨      ← REQ-0022 의 요점
JS 오류 0건
```

그 밖에 루트가 독립 재현한 것: 빌드(`-Wall -Wextra` 경고 0), WS accept 벡터 독립 계산,
16비트 확장 길이 실사용(831B / 길이필드 `0x033F`), ack 타겟팅(클라 2개), `data_log.json` 2건 유지,
ACK 유실 시 **동일 wire_rid** 재전송, 재부팅 후 예약 재하달.

## 테스트 모드 (명세 v1.3 · REQ-0027~0035)

센서가 아직 없으므로 **브라우저에서 센서값을 주입**할 수 있다. 구조적으로는 반전(제어가 하행)이다.

```
브라우저 토글/주입 ──WS──> 서버 ──T 프레임──> 아두이노(값을 보관) ──S 프레임의 tmask──> 되돌아옴
```

핵심 설계 결정:

| 결정 | 근거 |
|---|---|
| 값을 **아두이노가** 들고 있는다 (서버가 지어내지 않는다) | 서버가 위조하면 아두이노 경로가 시험되지 않은 채 남는다 — 이 기능이 존재하는 이유가 그 경로다 |
| 무장 여부의 진실은 `S` 의 `tmask` (ACK 아님) | 해제 ACK 가 유실되면 화면이 가짜 값을 경고 없이 진짜로 표시한다. 장치가 매 프레임 알리면 다음 프레임에 저절로 복구된다 |
| 주입 대상은 `occupied` 만 | `reserved` 는 서버·사용자의 것이다(§7.4). 예약은 정상 경로로 만들 수 있다 |
| 재부팅하면 오버라이드 소멸, 서버가 재하달 **안 한다** | 예약과 반대다. 사람의 약속이 아니라 임시 상태다 |
| 무장 중 표시가 **필수** | 반전 구조의 전형적 사고는 켠 채 시연하고 가짜 값을 실측으로 보고하는 것이다 |

## 번호판 수신·매칭 (REQ-0037)

폰(digitcam)이 인식한 번호판을 주차 서버가 받아 예약과 잇는다. **명세는 한 글자도 안 고쳤다** —
양쪽 전선이 이미 명세돼 있었고 없던 것은 그 둘을 잇는 서버 내부 정책이었다.

```
폰 ──TCP 5500 JSON──> 서버 ──매칭──> 예약 있으면 그 자리 / 없으면 빈자리 배정
                        └─ 아두이노에는 번호판을 보내지 않는다
```

### 두 이름공간 — `rid` 를 나눈 것과 같은 구조

| 구간 | 값 | 제약 |
|---|---|---|
| 브라우저 ↔ 서버 · 서버 내부 | **번호판 전체** | UTF-8 (JSON) |
| 서버 → 아두이노 (전선 `userid`) | 빈 값 | ASCII 0*8 (§2.3) |

`'980가4568'` 은 8글자지만 UTF-8 로 10바이트에 비ASCII라 `valid_userid()` 를 통과하지 못한다.
**답은 규칙 완화가 아니다** — 그러면 REQ-0023 이 막은 버그(잘린 값이 체크섬과 함께 형식상 유효한
라인으로 나가는 것)가 되살아난다. 아두이노는 `userid` 를 쓰지 않으므로 비우면 잃는 것이 없다.

**스냅샷은 무변경.** `slots[].user_id` 가 v1 부터 자리만 잡아 두고 `null` 이던 필드다 —
번호판이 그 자리에 들어간다.

### 인식 실패 정책 — 새 임계값을 만들지 않았다

"열지 않고 재시도"가 **이미 구조에서 나온다**: 폰이 `conf < min_confidence`(기본 0.70)를 폰에서
버리고, 전송 조건이 `fresh && !value.isEmpty()` 이며 `fresh` 는 상승 엣지다
(`send.min_interval_ms` 하한 1000ms). 즉 **인식 실패 = 서버에 아무것도 안 옴 = 안 열림 = 재시도.**

서버에 절대 임계값을 두면 오히려 해롭다 — `conf` 는 문자별 최소값이라 문자 수가 늘수록 낮아져서
**긴 번호판만 유독 거절된다.** 명세가 그 비교를 경고해 뒀다.

### 루트 검증

```
한글 번호판 2대 → 빈자리 배정 A1·A2
전선 라인: 'R,1,A1,,13' · 'R,2,A2,,13'   ← userid 비어 있음, ASCII, 번호판 누출 없음
중복 수신 → "이미 A1 에 배정돼 있다. 새로 배정하지 않는다"
빈자리 없음 → "배정 실패. 차단기를 열 자리가 없다"
```

> socket-engineer 가 **설계를 맞게 해 놓고 조립부 한 줄에서 샌 것**을 스스로 잡아 보고했다 —
> `R,1,B2,980가4568,F7` 이 나가 가짜 아두이노가 UnicodeEncodeError 로 죽었다. 그때
> **가짜 아두이노가 죽은 것도 결함**이라고 보고 같이 고쳤다(진짜 장치라면 깨진 줄로 보고 버려야 한다).

## 다음 구조 결정 (미착수 — 잊은 것이 아니다)

### 1. 아두이노 다중 장치 (5대 확보, 현재 1대 가동) — **방향 확정, 미착수**

> 이 절은 사용자와의 검토 결과다. 구현 지시가 아니라 **착수할 때 참조할 기록**이다.

#### 결론: 장치를 **역할**로 나눈다. 칸으로 나누지 않는다.

```
센서 보드   : 10칸 점유 감지 → S 프레임을 보내는 유일한 장치
차단기 보드 : 차단기 개폐. S 를 보내지 않는다
LED 보드    : 바닥 경로 안내(WS2812 스트립이면 핀 하나). S 를 보내지 않는다
```

#### 이 분리가 없애는 복잡도 — 원래 가장 비쌌던 부분이다

처음에 루트가 "명세를 다시 여는 규모"라고 본 근거는 셋이었는데, **셋 다 여러 장치가 같은
10칸 상태를 보고할 때만 생긴다.** `S` 를 보내는 장치가 하나면 전부 성립하지 않는다:

| 문제 | 역할 분리 시 |
|---|---|
| 어느 장치가 어느 칸을 소유하는가 | 분할 자체가 없다 |
| 두 장치가 같은 칸을 주장하면 | 주장자가 하나뿐 |
| 여러 `S` 를 어떻게 병합하는가 | 병합 대상이 없다 |

#### ⚠ 이 판단이 깨지는 조건 — 명세에 못 박을 것

**"`S` 를 보내는 장치는 하나"가 전제다.** 나중에 칸이 늘어 "보드 2개에 10칸씩" 같은 분할을 하면
위 셋이 전부 돌아온다. 역할 분리는 유지하되 **칸 분할은 별도의 큰 결정**으로 다뤄야 한다.

#### 덤 — 대역폭도 같이 나뉜다

9600bps 병목은 보드마다 따로다. 지금 1Hz 하트비트가 7.29% 를 쓰는데(§3.2), 차단기·LED 명령이
같은 링크에 실리면 거기서 경쟁한다. 역할을 나누면 **센서 링크는 현재 예산 그대로**이고
액추에이터는 자기 링크를 통째로 쓴다. LED 경로 안내처럼 데이터가 많은 쪽에 특히 유리하다.

#### 그래도 남는 것 — 다섯 중 넷은 평범한 확장이다

1. **⚠ 받기만 하는 장치는 자기를 알릴 방법이 없다 — 이것만 진짜 새 설계다.**
   `devid` 는 **`S` 프레임에만** 있고 `S` 는 장치→서버 방향이다. LED 보드는 보고할 칸이 없어
   `S` 를 보낼 이유가 없는데, 그러면 **접속만 하고 침묵하는 연결**이 되어 서버가 정체를 모른다.
   → hello 프레임을 두거나, 모든 장치가 최소 프레임을 주기적으로 보내게 해야 한다.
2. **하달 주소는 전선에 안 넣어도 된다.** 어떤 프레임에도 수신 장치 지정 필드가 없지만,
   서버가 **소켓을 골라 쓰므로** 라우팅이 성립한다. 전선 포맷 무변경.
3. **`device.online` 이 단수다**(§5.3). "센서는 살아있고 LED 만 끊김"을 표현 못 한다. 스키마 변경.
4. **재부팅 재하달(§7.4)이 역할별로 갈린다.** 예약이 필요한 것은 센서 보드(reserved 비트)와
   LED 보드(어디로 안내할지) **둘 다**라, 어느 장치가 재부팅했느냐에 따라 보낼 내용이 다르다.
5. **서버의 `sock_t ard` 하나를 맵으로.** 평범한 작업이다.

#### 착수 순서 (정해질 때)

명세 개정(역할 개념 + 자기소개 프레임 + 장치별 online) → 서버 다중 연결 → 역할별 펌웨어.
물리 보드가 1대라 검증은 가짜 아두이노 여러 개로 한다.

#### 참고: "차량 주차완료"는 별도 장치가 아니다

배정된 칸의 `occupied` 가 0→1 이 되는 것이 곧 주차 완료다. 센서 보드가 이미 보내는 정보이고,
"그때 안내 LED 를 끈다" 같은 것은 **서버 규칙**으로 처리된다.

### 2. 차단기·LED 액추에이터

하드웨어가 생길 때. 바닥 LED 가이드는 **WS2812 주소지정 스트립이면 핀 하나**로 되고,
경로 표시(입구→자리)도 스트립이라야 가능하다. 5대 구성이면 핀 문제 자체가 없다.

### 3. 브라우저 이벤트 스트림 — "빈자리 없음"을 화면에 못 알린다

지금은 로그에만 찍힌다. 알리려면 WS 메시지가 필요한데 **하지 않기로 했다.**

이유가 "나중에"가 아니라 구조적이다: 기존 `error` 는 전부 **브라우저 요청에 대한 응답**이고
그 브라우저의 `rid` 를 달고 간다. 그런데 "번호판이 왔는데 빈자리가 없다"는 **요청한 브라우저가
없는 사건**이라 성격이 다르다 — 누구에게 보낼지부터 다르다(스냅샷처럼 전원 broadcast).

그리고 차단기 작업이 오면 같은 성격의 사건이 여럿 생긴다(차량 도착 · 번호판 매칭됨 ·
자리 안내 시작 · 차단기 열림). **일회성 `error` 코드를 지금 하나 만들면 그때 모양이 어긋난다.**
비요청 이벤트를 한 벌로 설계할 때 같이 넣는다.

### 4. `data_log.json` 에 `user_id` 가 없다 (정보 부족 — 안전 문제 아님)

§5.3 스냅샷은 `user_id` 를 담지만 §9.1 파일 항목은 `id/occupied/reserved/overridden` 뿐이다.
폴백 중에는 "누가 주차했는지"가 안 보인다. 다만 **웹이 이미 "소유자 정보 없음"으로 정직하게
표시하므로** REQ-0033(주입값이 실측처럼 보이던 것)과 달리 위험하지 않다. 필요해지면 추가한다.

### 조건부 대기 항목 (잊은 것이 아니다)

- **실물 센서 채터링 대책** — 착수 조건: **실물 센서를 한 칸이라도 배선하는 시점.**
  접점이 100ms 보다 빠르게 떨면 최악 초당 10프레임 → 채널 약 60%(1Hz 예산은 6.15%).
  디바운스 상수는 실물 접점에서 재야 정할 수 있어 지금 정하면 근거 없는 숫자가 된다.
- **ESP-01 이 새 TCP 연결에서 `CONNECT` 를 단독 줄로 올린다는 전제** — 멱등 캐시 비우기가
  이 전제에 기댄다. 하네스는 그 문자열을 직접 밀어 넣으므로 전제 자체를 검증하지 않는다.
  **틀리면 캐시가 안 비워지고 증상은 다시 "조용한 성공"이다.** 실기에서 서버를 재시작한 뒤
  한 칸에 주입했는데 다른 칸 ACK 가 오면 이 전제를 의심해라.

### 아직 검증되지 않은 것 (추정을 통과로 적지 않는다)

- **Windows 빌드·실행.** 이 팀의 어떤 머신에서도 컴파일할 수 없다. cpp-engineer 의 정적 검토
  (REQ-0021)와 그 반영(REQ-0023)까지가 한계다. `MoveFileEx` 원자적 교체 경로도 미검증.
- **실제 아두이노 보드.** `>` 프롬프트 타이밍, ESP-01 의 실제 AT 응답 문구,
  SoftwareSerial 송신 중 수신 유실의 실제 정도는 실기에서만 확인된다.
  `fake_arduino.py` 는 루프백 TCP 라 9600bps 지연도 유실도 재현하지 않는다 —
  `--drop-rate` 는 그 **결과만** 흉내낸다.
- 부하·동시 접속 한계 (데모 규모 가정).

명세를 먼저 얼린 이유: 세 도메인이 같은 전선 포맷에 합의해야 한다. 병렬로 먼저 풀면
서로 안 맞는 포맷 세 개가 나온다. 명세가 확정된 뒤에야 셋을 동시에 풀었다.

### 루트가 명세를 검산한 결과 (REQ-0016 수용 전)

세 담당이 이 문서 하나로 병렬 구현하므로 예제가 1바이트만 틀려도 셋 다 깨진다. 그래서 수용 전에 재계산했다:

| 항목 | 결과 |
|---|---|
| 체크섬 예제 8건 (§2.5) | 전부 일치 |
| `Sec-WebSocket-Accept` 자가검증 벡터 (§5.1) | RFC 6455 예제와 일치 |
| 스냅샷 직렬화 크기 (§5.3) | 845 B — 125 B 초과 확인. **WS 16비트 확장 길이 필수**가 맞다 |
| 9600bps 대역폭 (§3.2) | 1Hz 최대프레임 6.15 %, 최악 14.90 % — 재계산 일치 |

### socket-engineer 가 올린 판단 3건 — 전부 승인

1. **ACK `result=2`(이미 예약됨) 추가.** 루트가 준 3종(성공/이미점유/잘못된자리)이 불완전했다.
   `occupied`/`reserved` 를 직교로 정한 이상 "비었지만 남이 예약한 자리"가 실제로 발생한다.
2. **`rid` 를 두 이름공간으로 분리** (브라우저=문자열 / 전선=서버 발급 uint16, 서버가 번역).
   브라우저 둘이 같은 rid 를 고르는 건 가정이 아니라 시간문제다.
3. **예약의 durable owner = 서버.** 아두이노는 전원이 끊기면 `reserved` 를 잃지만 서버는 안 잃는다.
   센서 진실값(`occupied`)의 주인은 아두이노, 사람의 약속(`reserved`)의 주인은 서버.

### 명세가 잡아낸, 루트가 놓쳤던 함정 둘

- **SoftwareSerial 은 송신 중 수신을 잃는다** (§6.3). AVR 의 `write()` 가 인터럽트를 끈 채 블로킹하므로
  57~61 ms 동안 들어온 바이트가 지연이 아니라 **유실**된다. → 서버 재전송(§7.3)과
  아두이노 rid 멱등성(§4.2)이 선택이 아니라 필수가 된다.
- **WS 스냅샷이 845 B** 라 7비트 길이 필드로는 못 보낸다 (§5.2). ack(82 B)만 시험하면 통과하고
  첫 스냅샷에서 깨진다.

## 소유권 메모 (루트가 처리함)

`조별과제샘플/server.cpp` 는 확장자 규칙상 `cpp-engineer` 로 떨어지지만 내용은 소켓 서버다.
`.claude/ownership.json` 에 파일 단위 경로 규칙을 추가해 `socket-engineer` 로 돌렸다.
폴더 전체(`조별과제샘플/**`)를 주지 않은 이유는 `.ino`/`.html` 까지 뺏기기 때문이다.

**같은 규칙을 NFC 와 NFD 두 형태로 적어 두었다 — 중복이 아니다.** macOS 는 같은 한글 경로를
두 정규화 형태로 넘기는데 `ownership_guard.py` 는 정규화를 하지 않는다. 한쪽만 적으면
다른 형태로 들어온 경로가 **조용히** 확장자 규칙으로 새어나가 `cpp-engineer` 소유가 된다.
실측으로 확인했다:

```
NFC 조별과제샘플/server.cpp -> socket-engineer (경로 규칙)
NFD 조별과제샘플/server.cpp -> cpp-engineer    (확장자 규칙)   ← 규칙 추가 전
```

한글 경로를 다루는 규칙을 추가할 때마다 이 함정을 다시 밟게 된다. 근본 해결은 훅에서
경로와 글롭을 NFC 로 정규화하는 것이지만, 훅 편집이 이 세션에서 차단되어 데이터 쪽으로 우회했다.
