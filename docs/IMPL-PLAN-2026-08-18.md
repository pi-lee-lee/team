## 단계별 — 무엇을 · 왜 그 순서인가 · 무엇이 끝의 조건인가

### 1. `ACK_TIMEOUT` 유도식 — **socket + web 한 배포** `[먼저인 이유: 측정 도구 복구]`

**지금 문제**: `ACK_TIMEOUT=1500` 이 정상 왕복 **1230ms** 에 **271ms 여유**뿐이다.
그래서 **재전송에 늦은 ACK 이 섞이고**, 그것을 가르는 판별자가 **파괴가 드물수록 오탐이 커진다.**

```
수정 후 : 늦은 ACK 이 빠지고 재전송이 파괴만 센다  →  🔑 판별자가 필요 없어진다
```

**입력은 실측으로 있다**: 왕복 마지막 `1229 · 1225 · 1230`(세 창·두 망·두 펌웨어에서 고정).
⚠ **`rtt_max` 를 쓰지 마라** — 창 D 최대가 `1599` 이고 **최대에 맞추면 실패 감지가 느려진다.**
**중앙값 + 한 슬롯 여유**가 맞고 **둘 다 실측으로 갖고 있다.**

🔴 **web 과 같은 배포여야 한다** — `ack_budget_ms` 가 그 값에서 계산된다.
**서버만 올리면 화면이 옛 예산으로 돈다.**

**끝의 조건**: 서버·화면이 같은 해시로 배포되고 `queued` 왕복이 새 예산으로 도는 것을 확인.
⚠ **`재전송` 의 뜻이 바뀌므로 창 간 대조 불가 칸으로 표시한다**(socket 이 미리 적어 뒀다).


### 1.5 🔴 `cmdPending` 구멍 — **사용자가 실물로 재현했다. 최우선**

**사용자 보고**: *"웹이 살아있어서 한걸음 진행을 20개 이상 보내면 응답이 없습니다 (자체 타임아웃)."*

⚠ **처음에 "esp01 리셋"으로 보고됐고 우리도 그렇게 조사했다** — 그런데 **시리얼 로그에
리셋 표지가 0건**이었다. 사용자가 화면 문구를 알려 주자 **1초에 갈렸다.**

```js
index.html:1948
if (p.kind === 'sim_step') state.simOutcome = { level:'err', text:'응답이 없습니다 (자체 타임아웃)' };
```

**`sim_step` 이 "한걸음 진행"이고, 이건 화면이 자기 타이머로 포기한 것이다. 장치는 정상이다.**

#### 기전 — web 이 오늘 찾아 놓고 미룬 그 구멍이다

```
20개 이상 누른다 → 큐에 쌓인다 → 서버가 queued 를 보낸다
→ 🔴 queued 분기가 state.pending 만 보고 state.cmdPending 은 안 본다
→ sim_step 경로에서 그 프레임을 조용히 버린다
→ 6초 고정 타이머가 그냥 만료 → "응답이 없습니다"
```

**서버도 장치도 정상인데 화면만 실패라고 말한다.** 그래서 로그에 흔적이 없다.

⚠ **web 이 "피해가 예약보다 작다"고 판단해 별건으로 미뤘고, 사용자가 실물로 뒤집었다.**
**20개 규모에서는 거의 확실히 재현된다.**

#### 고칠 것

```
· queued 분기가 state.cmdPending 도 본다
· 🔴 6초 고정 대신 ack_budget_ms(12600)를 쓴다 — 지금은 큐 대기(최대 4800ms)를 못 견딘다
· 예약 경로(REQ-0166)에서 이미 한 것과 같은 처리다 — 그 경로엔 닫혀 있고 이 경로엔 안 닫혔다
```

**끝의 조건**: 20개 이상 연타에서 `자체 타임아웃` 이 안 나고 `queued` 가 화면에 보이는 것.
🔴 **사용자 조작으로 검증한다** — 그것이 이 결함을 드러낸 유일한 자극이다.

#### ★ 이 사건에서 배운 것 (규칙 후보)

> **증상 보고를 받으면 그 문구를 코드에서 먼저 찾아라.**

**루트가 `grep 'System Ready'` 0건을 보고 "로그와 안 맞는다"고만 했다.** 문구를 소스에서 찾는 것이
**첫 수순이어야 했다** — 사용자가 문구를 알려 주자 1초에 갈렸다.
⚠ **그리고 "리셋"이라는 사용자 낱말을 그대로 조사 대상으로 삼은 것**도 같은 실수다.
**사용자는 증상을 보고하지 원인을 보고하지 않는다.**

### 2. 서버 노드별 리팩터링 `[2번인 이유: 나머지 셋이 이 계약 위에 선다]`

**전역 상태를 `Node` 로 내린다** — `ard_last_ms`·`downq`·`downq_bytes`·`rtt_max_ms`·
`win_skips`·`dmax_flushes` 전부. **이미 "그 소켓의" 값이라 개념 변경이 아니라 그릇 변경이다.**

🔴 **약화 금지**(사용자 강조: *"작동은 해야 한다!! 없애는 것이 아니다"*):
`DOWN_BATCH_CAP_B` · `q_deferred` · `D_max` 창 포기 박자 · `queued` · 배포 순서.
**규칙은 한 글자도 안 바뀐다. 한 벌을 N 벌로 만들 뿐이다.**

**같이 들어가는 것**: `Zone`/`Module` 자료 구조 · 하행 라우팅(`zone → (devid,name) → 그 노드 큐`) ·
`actionable`/`blocked_reason` 계산 · 맵 정의를 상태와 **별도 키**로 · 완료 판정(전부 일치해야 `done`).

⚠ **`first-S-wins`·`aux_conflicts` 는 없어진다** — 모듈 등록이 장치를 명시하므로 추측이 불필요하다.

**끝의 조건**: 노드 1대(P1)로 **지금 동작이 그대로 유지**되는 것. **회귀가 먼저다.**
