## 아직 검증 못 한 것 (정직하게)

1. **실기기 전부** — 프리뷰, 흔들림 게이트, 실제 번호판. 폰이 없다.
2. **TCP 실제 전송** — 루프백만 했다. 한글 UTF-8 수신, 재접속, android-engineer 가 고쳤지만
   실측 못 한 "재접속 시 잔여 1건 폐기" 가 여기 걸려 있다.
3. **소프트 키보드가 설정 입력칸을 가리는지** — `adb shell input text` 는 하드웨어 키보드 경로라
   에뮬레이터에서 소프트 키보드가 안 뜬다. `ime()` 인셋 + `adjustResize` 는 걸어 뒀으나 미실측.
4. **구형 단축 번호판(2+한글+4)** — 실제 이미지가 없다.
5. **장면이 통째로 바뀔 때의 움직임 오판** — 계약 §9.1 의 알려진 한계.

## 폰이 생기면 — 이 순서로

계약 §11 의 4·5번이다. **샘플 → 전송 → 카메라 → 실차** 순으로 변수를 하나씩 늘린다.

1. **샘플 이미지 모드** (카메라 없이) — 이 기기에서 APK·네이티브·OpenCV·인식기가 도는지.
   에뮬레이터와 같은 26/26 이 나와야 한다.
2. **샘플 + TCP 전송** ← 차도 종이도 없이 **전송 경로 전체**를 검증할 수 있다.
   `socket-engineer` 에게 `net/test_server.py` 기동을 요청하고, 앱 설정 화면에서 노트북 IP·포트 5500
   입력. 한글이 안 깨지는지, 서버를 껐다 켜면 재접속하는지 확인.
3. **카메라로 촬영** — 모니터에 `samples/plates/` 를 띄우고 비추면 인쇄물 없이 된다.
   ⚠ 화면 촬영은 모아레·반사로 실제보다 불리하다. 여기서 안 읽혀도 실패로 단정하지 마라.
4. **실제 차량**.

**폰 연결 전 확인**: 이전에 앱을 실행한 적 있는 기기라면 옛 설정 파일이 남아 있다.
`adb shell rm /sdcard/Android/data/com.example.digitcam/files/server.properties`

## 현장에서 틀어질 만한 곳 — 미리 짚어 둔다

| 증상 | 먼저 의심할 것 |
|---|---|
| 계속 "움직임" 으로만 뜬다 | 버그가 아니라 `vision.motion_threshold` 다. 화면의 `motion` 실측값보다 조금 위로 올려라(2.5~3.0). 설정 화면에서 리빌드 없이 바뀐다 |
| 번호판이 `blurry` 로 계속 거절된다 | `vision.min_sharpness`. 화면의 `sharp` 값을 보고 조정 |
| 전송은 되는데 서버 로그가 빈다 | 포트. macOS 는 5000 을 AirPlay 가 점유한다 — 5500 을 쓴다 |
| 값이 안 나온다 | 화면의 `reason` 을 봐라. `moving`/`no_plate`/`blurry`/`segment_fail`/`low_conf` 중 어디서 막혔는지 나온다 |

## 이 프로젝트에서 실제로 배운 것 (반복하지 마라)

- **루트가 감으로 적은 임계값 두 개가 전부 틀렸다.** `min_sharpness=60`, `motion_threshold=0.60`
  둘 다 실측에서 "그 지표로는 쓸 수 있는 임계가 존재하지 않는다"로 판명됐다.
  **숫자를 계약에 적을 때는 근거를 같이 적거나, 근거가 없다고 명시하라.**
- **같은 체크아웃을 공유하므로 편집 중 스냅샷으로 빌드될 수 있다.** 채점 수치를 보고할 때
  네이티브 소스 mtime 을 같이 적는다(계약 §10.1). 실제로 이 규칙이 사고를 한 번 잡았다.
- **빌드 통과와 파일 저장 성공은 기능이 있다는 증거가 아니다.** 설정 화면은 두 조건을 만족하고도
  입력칸이 시스템 바에 가려 쓸 수 없었다. **화면은 눈으로 봐라.**
- **막혔을 때 우회하지 말고 요청을 발행하는 것**이 이 구조가 의도한 동작이다. 소유권 훅 오탐도
  그렇게 드러났다.
