# 사전 등록 · 창 AD — **묶음 하행. 자극이 있는 창이다**

> # 🔴 성격이 창 AC 와 또 다르다
> ### 창 AC = *"샘플이 성립하는가"*(자극 12건) · **창 AD = *"묶음이 한 창에 나가는가"***
> ### **비율이 아니라 각본별 ✅/❌ 다.** 사용자 지시: *"실제코드로 테스트해봐라"*

**발행 22:3x — 굽기·배포 *전* 에 쓴다.** ⚠ **결과를 보고 해석을 고치면 사전 등록이 무의미해진다.**

## 0. 🔴 t0 와 순서 — **굽기 리셋이 t0 가 아니다**
```
굽기 → (대기) → 🔴 **배포** → 그때 연다
t0 = **배포 완료 시각**
```
> ### **이번엔 서버가 자극원이다. 배포 전에 열면 옛 판이라 묶음 자체가 없다 — 잴 것이 없다.**
⚠ 내 탭 개방도 DTR 리셋이다. **개입 중 가장 나중 것 뒤** 가 실질 t0 다 — 둘 다 값으로 적는다.
⚠ 첫 `[CNT]` 줄은 부팅 60초 기여분(§7.174).
✅ **arduino 가 굽고 포트를 놓고 다시 안 잡는다** — 배포 직후 내가 바로 열 수 있다.
⚠ **굽기~배포 사이 구간은 새 펌웨어 + 옛 서버**다. 서버가 에코 비트를 무시할 뿐 안 깨진다.
   🔑 **그 구간을 판정에 안 쓴다** — 짝이 안 맞는 조합이다.
✅ 칩이 26,566 → **27,232 (+666B)**. **늘어나므로 꼬리 잔재 문제가 없다**(줄 때만 생긴다).

## 1. 무엇이 바뀌나 — **축이 여섯 + 서버 하나**
```
장치(arduino 예고 · 🔑 정본은 굽기 보고다) :
  모듈 **5 → 6** (`A1 B1 LD LC DR` + **`L2`**) · hex 폭 2 · 등록 **76B**
  flash 27,232(84% · +666B) · RAM 1,243(+13B)
  축 여섯 : 입력훅 · 에코A · 배너 · 거절로그 · 개명(hex 0) · L2
서버 : **`bb9db82` + 각본 루프**(측정 전용) · 묶음 하행 · 이름 길이 · 콜백 계약
  🔴 하행이 **한 창에 4줄 묶여** 나간다 — 지금까지는 낱개였다
     프레임 : LCD 줄 ~19B × 4 ≈ **76B 한 거래**  → 🔴 **`>=64B` 대역이다. 내 대역 축이 바뀐다**
  · 요약 신설 : `명령결과 성공/거절/무응답` · `묶음미룸` · `묶음 상한 N건`(기동 줄)
  · `미결속모듈 **0/6**` 이 정상 (모듈 6)
  🔴 측정 뒤 **주석 판(`bb9db82`)으로 되돌린다 — 그 시각부터가 무자극이다**
```
🔴 **이상이 나오면 후보가 일곱이다.** 귀속이 어렵다는 것을 미리 적는다.
🔴 **분모가 또 바뀐다** — 모듈 5→**6**. **자리 10→7→1 · 모듈 12→5→6.**
**창 AC 이전과 대역 진입률·`N` 분포를 합치지 않는다.**

## 2. 표지 — **무조건 떠야 하는 것**
```
✅ `[PARKING NODE] proto v1 / **1 spots** / **2 sensors** / **6 modules** / dev=P1`
   🔑 **창 AC 에서 내가 찾은 라벨 결함이 고쳐진 형태다** — `slots` 하나가 `spots`+`sensors` 로 갈렸다
✅ `[REG] 등록 전송 **76B**` · `D,*,7,**6**,`
✅ `D,A1,IP` `D,B1,IP` `D,LD,OG` `D,LC,OL` `D,DR,OB` **`D,L2,OL`**
❌ **0건이어야 한다** : `2 slots` · `5 modules` · `12 modules` · `D,E1,` · `D,X1,`
```
🔑 **`❌목록` 을 미리 선언한다** — 부재는 선언 안 하면 아무도 안 센다.
🔑 **배너에 `spots`/`sensors` 가 갈려 나오면 §2(창 AC)의 라벨 결함이 고쳐진 것이다.**

### 🔴 조건부 표지 — **부재를 실패로 읽지 않는다. 단 ㉢ 은 예외다**
```
`[G] 거절 idx=n — 등록 없음 / 콜백이 거절 / 인자 해독 실패`
`[LC] 거절 — 7자리 초과: <값>`  ·  `[DR] 거절 — 명령표에 없는 값: <값>`
```
```
㉠㉡㉣ 에서 부재 → **정상**(그 갈래를 안 밟았다)
🔴 ㉢ 에서 부재  → **신호다.** 일부러 밟는 각본이므로 안 뜨면 ❌
```
> ### **같은 표지의 부재가 각본에 따라 정상이기도 실패이기도 하다. 그래서 각본별로 미리 갈라 적는다.**

### ⚠ 🔴 내 계측기의 한계를 **미리 선언한다** (§7.198)
```
내 탭은 **성공한 콜백만** 본다 — 창 AC 에서 `[LC]` print 가 early return 뒤에 있어
**거절한 콜백이 "안 불린 것"과 같은 모양**이었다
```
### ✅ **확인받았다 (arduino · 22:3x) — 넷 다 `return` 앞이다**
```
[LC] 거절 / [L2] 거절 / [DR] 거절  → `return false` **앞** ✅
[G]  거절 idx=n — <사유>          → `commitAck` 앞 · 사이에 return 없음 ✅
```
> ### **그러므로 ㉢ 의 `[LC] 거절` 부재는 진짜 신호다. "미측정" 갈래를 닫는다.**
🔑 **창 AC 에서 내가 물린 함정이 이번엔 *굽기 전에* 닫혔다** — 물어봤기 때문이다.

### 🔴 그리고 **거절 사유가 셋으로 갈린다 — 섞여 나오면 그게 결함이다**
```
`[G] 거절 idx=n — **인자 해독 실패**`     → 프레임·서버 쪽
`[G] 거절 idx=n — **등록 없음**`          → `setup()` 의 `router.on`
`[G] 거절 idx=n — **콜백이 거절** arg=v`  → 기여자 핸들러
```
**셋은 고치는 곳이 다 다르다.** 사유를 뭉뚱그려 "거절 N건"으로 안 적는다.

## 3. 🔴 시험 각본 — **여섯 단계. 예측·관측·판정을 지금 고정한다**

### ⚠⚠ 🔴 **자극 전체가 약 72초다** (socket · 12초 × 6단계)
```
㉠ 4건묶음 → ㉡ 5건거절 → ㉢ 8자리섞임 → ㉣ 단건 → ⑤ DR열기 → ⑤ DR닫기 → **멈춘다**
```
> ### **여섯 단계가 끝나면 더 안 쏜다. 그 뒤는 조용한 구간이다.**
🔴 **놓치면 그 자료가 창에 없다.** 탭을 열고 **각본이 시작되기 전** 에 준비를 끝낸다.
⚠ **그리고 이 짧음이 판정에 미치는 영향을 미리 적는다** — **각 각본의 표본이 1회다.**
**`n=1` 로 비율을 쓰지 않는다. ✅/❌ 만 낸다.**

### ㉠ 4건 묶음 — 🔑 **이건 내 탭만 답한다**
```
🔮 예측 : 서버가 넷을 한 번에 내보낸다
관측   : `+IPD` 건수 · 그 안의 `G,` 개수 · `[G]` 넷의 시각
판정   :
  ✅ **`+IPD` 1건에 `G,` 넷**            → 진짜 묶음. **구조로 성립**
  ⚠ `+IPD` 4건인데 `[G]` 넷이 한 슬롯 안 → **묶음이 아니라 연발.** 결과는 같아도 기전이 다르다
  🔴 `[G]` 가 넷보다 적다                → 실패 → **아래 판별 순서로 간다**
```
🔑 **1차 판정자를 *구조*(한 `+IPD`)로 잡았다** — 시각 기반은 슬롯 폭·지터에 딸려 흔들린다.

### 🔴 ㉠ 이 실패하면 — **갈래가 둘이 아니라 셋이다** (arduino 가 셋째를 알려 줬다 · 22:3x)

**내 첫 판별식은 둘이었다. arduino 가 `[G]` 침묵의 세 번째 원인을 밝혔다:**
```c
같은 `rid` 재수신(멱등) → sendAck 만 하고 **return** → 🔴 **`[G]` 줄이 안 나온다**
```
> ### **서버가 재전송하면 장치는 조용하고 ACK 만 간다. 그 침묵은 결함이 아니다.**

**✅ 그래서 셋으로 가른다 — 🔑 세 갈래가 전부 내 탭 안에서 갈린다:**
```
① `[G]` 부족 + `penddrop` **+3**              → **알려진 묶음 손실.** 크기만 적는다
② `[G]` 부족 + `penddrop` **0** + 🔑 **ACK 는 나갔다**  → **멱등 재수신.** 결함 아니다
🔴 ③ `[G]` 부족 + `penddrop` **0** + **ACK 도 없다**    → **이때만 새 결함이다**
```
🔑 **②를 가르는 것이 ACK 다** — 창 AC 에서 `A,678,G2,0` 이 **내 시리얼에도 찍히는 것**을 확인해 뒀다.
**그 확인이 없었으면 ②와 ③을 못 갈랐다.**

#### 🔴 ACK 을 쓸 때 주의 둘 (arduino 가 소스로 확인 · 22:4x)
```
① **멱등 ACK 도 즉시 안 나간다** — `sendAck` 은 "보냈다"가 아니라 `ackQ.push` 다.
   정상 ACK 과 **같은 슬롯 배치**에 실린다
   🔑 설계 결정이다 — 즉시 보내면 ACK 이 **수신 창 한복판**에서 나가 하행을 깬다
     (창 B 에서 `cksumng=5` 로 실측된 그 기전)
   🔴 **그러므로 타이밍으로 "멱등이다"를 가를 수 없다. ②·③ 은 ACK 의 *유무* 로만 갈린다**
🔴 ② **중복 ACK 은 안 나간다** — `push` 가 같은 `rid` 가 큐에 있으면 넣지 않는다
   → **재전송 두 번에 ACK 하나**일 수 있다. **개수로 짝을 맞추지 마라**
```
⚠ **분모를 같이 본다** : `penddrop / pendfill` (창 AC 값 **0 / 1638**).
**`0/0` 은 "안 버렸다"가 아니라 "셀 일이 없었다"다.**
> ### **`penddrop 0` 만 적지 마라. `0/0` 은 최소한 `0/0` 이라고 말해 주는데 분모 없는 `0` 은 건강처럼 보인다.**

### ㉡ 5건 — **서버가 거절한다**
```
🔮 예측 : 서버 단에서 막혀 **장치에 아무것도 안 온다**
판정   : ✅ `+IPD` **0건** (그 시각대) · 🔴 뭐라도 오면 서버가 안 막은 것
⚠ 이 `0` 은 **직전 각본에서 `+IPD` 를 봤을 때만** 근거가 된다 — 그래야 "못 본다"가 배제된다
```

### ㉢ 하나만 8자리 — **셋 수행 + 거절 하나**
```
🔮 예측 : `[G]` **셋** + 🔴 **거절 줄이 *둘* 같이 나온다** (arduino 확정 · 22:35)
```
`[LC] 거절 — 7자리 초과: <값>`          ← 콜백이 찍는다 (`return false` 앞)
`[G] 거절 idx=3 — 콜백이 거절 arg=…`    ← 🔑 **라우터**가 dispatch 결과를 받고 찍는다
```
```
✅ `[G]` 셋 + **두 줄 다**        → 정상
🔴 **한 줄만 나온다**             → **그게 신호다**
   · `[LC]` 만 → 라우터가 결과를 안 받는다(계약 문제)
   · `[G] 거절` 만 → 콜백 로그가 안 나온다(창 AC 함정 재발)
🔴 넷 다 수행                     → **거절이 아예 안 걸렸다.** 가장 나쁘다
```
🔑 **`[G] 거절` 은 콜백 *밖* 에서(라우터가) 찍는다 — 그래서 창 AC 의 함정이 구조적으로 없다.**
**콜백이 아무 로그도 안 남겨도 `[G] 거절` 은 나온다.** ✅ **"미측정" 갈래를 완전히 닫는다.**
🔑 **이 각본에서만 조건부 표지의 부재가 신호다.**
```

### 🔴 ㉠ 의 **실패가 예측돼 있다 — 이것을 "발견"으로 읽지 않는다** (socket 이 값으로 줬다 · 22:4x)
```
arduino 실측 : **송신 중에 묶음이 오면 4건 중 3건이 사라진다**
🔑 확률은 그대로고 **손실 크기만 N배** 다 — 낱개일 땐 1건 잃던 것이 묶으면 3건이다
```
> ### **그러므로 `[G]` 가 넷보다 적은 것은 *알려진 기전* 일 수 있다. 새 결함이 아니다.**
```
✅ `[G]` 1~3 + `penddrop` **+3**   → **알려진 기전.** 결함 보고 안 한다. **크기만 적는다**
🔴 `[G]` 부족 + `penddrop` **+0**  → **이때만 새 결함이다**
```
⚠ **이걸 미리 안 적으면 `[G] 1/4` 를 보고 "묶음이 깨진다"로 보고하게 된다.**
**예측된 실패를 발견으로 내는 것이 오늘 가장 비싼 실수 유형이었다.**

### 🔴 ⑤ 에코 확인 — **창 AC 에서 "미측정"이던 칸이 이번엔 열린다**
```
각본 : `DR 열기(1)` → `DR 닫기(2)`
🔮 예측 : 상행 `S` 의 에코 자리가 **1 → 2** 로 따라 움직인다
관측   : 두 명령 전후의 `S,...` 필드
판정   : ✅ 따라 움직인다  ·  🔴 안 움직인다 = 에코 미구현
        ⚠ **값이 이미 2 였으면 "안 밟았다"** — 전이를 못 봤으므로 **미측정**이다
```
🔑 **③번 갈래를 여는 이유**: 창 AC 판정에서 *"조건이 이미 만족돼 있어서 통과"* 를 규율로 적어 뒀다.
**`열기 → 닫기` 순서라 전이가 강제되지만, 시작값이 이미 1 이면 첫 명령이 전이를 안 만든다.**
**시작값을 먼저 적고 판정한다.**

⚠ arduino: *"부팅 직후 에코 마스크는 `0` 이다(`.bss` · 생성자 없음) → 굽기 뒤 첫 창이면 `0→1` 전이가 반드시 생긴다."*
🔑 **그 말을 근거로 쓰지 않는다.** 본인이 그렇게 말했다 — *"내 말을 근거로 쓰지 말고 그 창의 첫 `S` 에서 읽어라."*
**시작값은 관측으로 적는다.** (그 사이 누가 `DR` 에 명령을 보냈으면 `0` 이 아니다)

#### 🔴 그리고 **`DR 닫기(2)` 가 이 굽기의 핵심 시험이다**
```
`arg=2` 는 **0 이 아닌데** 에코가 **내려가야** 한다  (`router.echoIs(arg == 1)`)
🔴 안 내려가면 : **문은 닫혔는데 서버는 열린 줄 안다 — 조용히 틀린 자료**
```
> ### **`0 이 아니면 켜짐` 이라는 자연스러운 오독이 정확히 이 자리에서 터진다.**
**arduino 가 호스트 시험에서 이 갈래를 단언으로 들고 있다 — 실기에서 어긋나면 그건 진짜다.**
🔑 **⑤ 두 단계 중 *닫기* 가 더 중요하다.** 열기는 `0→1` 이라 상식과 같고, **닫기만 계약을 시험한다.**

### ㉣ 단건 회귀
```
🔮 예측 : 창 AC 와 같이 `[G]` 1 + ACK `result=0`
판정   : ✅ 성립 · 🔴 실패면 **묶음 도입이 단건을 깼다** — 회귀다
```
