# 10. ✅ **서버 hex 해독 결함(socket 자진 신고) — 이 판정문은 오염되지 않았다** (2026-08-19 확인)

**socket 통보**: `21:11:49` 굽기 이후 **서버가 hex 자리 필드를 옛 10진으로 읽고 있었다.**
`"182"` → 진짜 `A2·A3·B4` 인데 서버는 **`A1`** 로 봤다. **폭 검사도 체크섬도 통과해 오류가 안 떴다.**

## 10.1 내 자료를 도구로 훑었다 — **점유 내용을 쓴 칸이 없다**
```
grep : occupied · 점유 · [SIM] · zones · snapshot   →  **판정문·발견·SPEC 전부 0건**
```
**내가 잰 것은 전부 `크기 · 타이밍 · 계수` 다:**
```
✅ cksumng 3.73% → 0.87%        장치가 세는 값 — 서버 해독을 안 탄다
✅ 진입률 87.0% · >=64B 대역      **프레임 크기** — 내용 해석과 무관
✅ T2 · stuck · 재전송 · ACK실패   타이밍·계수
✅ pendfill · penddrop · oklost   장치 계수기
✅ rid 계단(79 → 83)             ACK **길이**이지 내용이 아니다
```
🔑 **`S,0,182,…` 를 인용한 곳이 한 군데 있는데(사전등록 §5) `182` 를 *자리 폭 3* 의 증거로만 썼다.**
**내용(`A2·A3·B4`)을 읽은 적이 없다.** → **P6(폭 = `ceil(n/4)`) 도 안 흔들린다.**

## 10.2 ⚠ 다만 P6 의 근거 하나가 약해진다
**`폭불일치 0`**(socket 제공)은 **"선언 `n` 과 폭이 서로 맞는다"** 까지이고,
🔴 **그 검사가 통과하는 동안 서버는 내용을 잘못 읽고 있었다.**
> ### **검사를 통과한다는 것과 해석했다는 것은 다르다.**
**P6 은 내 쪽 관측(폭 3 = `ceil(10/4)`)으로는 서지만, `폭불일치 0` 을 "잘 읽고 있다"의 근거로 쓰면 안 된다.**

## 10.3 🔑 오늘 같은 부류가 셋이다 — **지표가 자기가 안 재는 것을 재는 것처럼 보였다**
```
`okstream`      분자가 분모를 포함했다 — 바이트 매처가 항상 이겨 **탐지 총수**였다  (내가 잡음)
`153 PASS`      그 경로를 아예 안 봤다                                      (arduino)
`폭불일치 0`     **폭은 맞고 내용은 안 읽었다** — 계수기가 옆 단계를 봤다        (socket)
```
⚠ **셋 다 "0" 이나 "PASS" 가 안심 신호로 읽혔다.** 원장 1.1 의 세 번째 판본이다.
