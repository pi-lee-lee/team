> # 🔴🔴 **이 창의 가장 큰 함정 — 먼저 읽어라**
> ### **창 Z 는 앞 `21분` 이 *완전 무사고* 였다가 `19:11` 부터 터졌다.**
> ### **그러므로 `25분` 전에 "발작이 사라졌다"고 쓰면, 창 Z 를 *재현한 것* 을 "나았다"로 읽는 것이다.**
> ```

> # 🔴 머리 배너

> ### **③ 반례: 창 S 는 깨진 AT `0/997` 인데 `busy p` 868 · 23분 미복구였다**(FINDING-1650)

> ### **⑤ "정상" = 끊김 0 이 아니라 **끊겨도 자력 회복**(사용자 확정 · §7.188)

## 2. 🔴 유일한 물음 — **창 Z 의 발작이 재현되는가**
```
창 Z(이동 전 · 옛 망) 실적 :
   18:50~19:11  무사고 21분
   🔴 19:11~19:38  **발작 셋** (esprst 1 → 24) · 시작 간격 **12분 · 11분**
   19:38~20:00  거의 조용(19:45 한 건) → **esprst 25 로 고정**
   UART : 깨진 나가는 AT **0 / 3,296** · `busy p` **0**
```
```
✅ 발작이 **사라지거나 모양이 바뀌면** → 🔑 **환경 축의 증거**다
🔴 발작이 **그대로 재현되면**         → 환경 후보가 크게 약해지고 **장치·펌웨어 쪽이 남는다**

```
**측정 방법(창 Z 와 같게)**: `[CNT]` 의 `esprst` **증가 시각**을 뽑아 발작 시작 간격을 잰다.
🔴 **목표 `n≥5`** — 창 Z 는 n=3 에서 4차가 안 와 **주기 주장이 깨졌다.**

### 🔴 새 축이 하나 생겼다 — **AP 가 바뀌었다**
```
`3F_302` → **`SK_WiFiGIGA50DC_2.4G`** (2.4G) · 서브넷도 `192.168.0.x` → `192.168.35.x`
→ 창 Z 와 **AP 자체가 다르다.** "환경이 바뀌었다"의 내용이 바로 이것이다
🔮 **GTK rekey 후보는 새 AP 에서 다시 봐야 한다** — 값이 다를 수 있다
```
🔴 **사용자에게 물을 것**: **새 공유기의 `group key rekey interval`(그룹키 갱신 주기).**
**옛 AP 것을 물어도 이 창에는 안 맞는다.** 창이 바뀌었으니 물음도 새 AP 로 바꾼다.

```
🔴 깨진 나가는 AT **8 / 1,115 = 0.72%**   (①비출력 **5** + ②**출력가능 3**)
   실물 : `AT+CIPS\x89ND=23` · `AT+CIP\xA7END=24` · `AT+CIPSEND=24\x1A`
          🔴 `AT+CIPSEND{24` ×3  ← **`=`(0x3D) → `{`(0x7B). 둘 다 출력 가능 문자**

⚠ **루트는 `3 / 1,068 = 0.28%` 로 봤다 — 한 부류만 센 값이다.**
🔑 **②출력가능 손상 3건이 그 차이다.** 내 맹점을 고친 도구가 아니면 안 잡힌다.
**0.28% 는 I(0.15)·P(0.19) 쪽으로 읽히지만 `0.72%` 는 R(1.45)·V(1.44) 쪽에 더 가깝다 — 읽기가 달라진다.**
