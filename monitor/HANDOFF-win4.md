### 🔴 이 창의 목적은 기전 C 검증이었다 — **그런데 검증에 실패했다(헛시험)**

전문: `monitor/FINDING-2026-08-17-0754-downlink-collision.md`

```
07:54:35  주입 1건  →  07:54:40  끊김 1건  →  07:55:31  socket 정지
```
- **끊김의 기전은 C 가 아니라 `B.리셋계열`** — `★ 정지 감지` **0건**, 배너 + `0.0.0.0`, `esprst=1`.

  UART 에서 깨진다. **하행 흐름 제어(B 경로)를 먼저 풀어야 C 를 시험할 수 있다.**

## 4. 🔴 기전 C 감시 — **자동. 내가 죽어도 잡힌다**

`monitor/ALERT-win4-stall.md` 를 요약기가 5분마다 판정한다.

```
정지 감지 <= 하행(+IPD) + CONNECT 수   →  ✅ 알려진 경로
정지 감지 >  그 합                      →  🔴🔴 전제가 깨졌다
```

⚠ **경보 파일의 현재 식은 `<= +IPD` 까지만 본다.** arduino 가 `lastTxOkAt` 대입을
**`:2148 ALREADY CONNECTED` · `:2160 CONNECT`** 에서도 찾았으므로 **재접속만으로도 발동 가능**하다
(**C-2**). 창3 에서는 C-2 **0건**이었다. **판정할 때는 `+IPD + CONNECT 수` 로 계산하라.**

⚠ 🔴 **`★ 정지 감지 0` 을 수정 확인으로 읽지 마라** — §3 을 보라. **하행이 장치에 도달해
`[TX] A,` 가 나가는 조건**에서만 그 0 이 뜻을 갖는다. 창4 는 그 조건을 못 만들었다.
→ **경보의 용도는 "C 가 새로 뜨는가" 를 놓치지 않는 것**이지 수정 검증이 아니다.

**연쇄 접기**: `CONNECT` 직후의 C-2 는 **새 사건이 아니라 앞 사건의 꼬리**다.
**첫 끊김만 세고 접은 건수를 따로 찍어라.**
