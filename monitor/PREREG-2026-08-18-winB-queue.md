## 2. 예측 (사건 뒤 수정 금지)

### ① 서버측 — socket 이 등록한 것: **오프라인 0 · 세션 종료 0 · ACK실패 0 · 300 완주**
3차①(큐 없음)은 **i=51 에서 중단 · 세션 종료 `errno=54` · 최대공백 10.0초**였다.
- **판정선**: `시도 = 300`(완주) 이고 위 셋이 0 이면 **큐가 이 기전을 막았다.**
  하나라도 0 이 아니면 **큐만으로는 부족**하고 그것이 발견이다.
- ⚠ `inj5` 는 이 예측을 **서버측만** 채점한다.

### ② 🔴🔴 **철회하고 고친다 (00:41 · `inj6` 시작 전 · socket 반박)**

~~**`[SLOT-OOW]` 가 0 이어야 한다** · 판정선 `oow/거래 = 0`~~ → **성립할 수 없다.**

**이유(좌표계가 다르다)**: `S+0ms` 는 **socket 좌표**(=`S` 도착 기준)이고 `[SLOT-OOW]` 는
**장치 좌표**(`sinceSlot` = `slotStart` 기준)다. arduino 숫자로 계산하면
```
slotStart + due(≈0) + txTime(≈48ms) + d1(≈33ms) + d2(≈33ms) ≈ slotStart + **115ms**
→ sinceSlot < 600 이므로 **모든 하행이 OOW 로 계상된다** → `oow ≈ 100%` 가 **정상 결과**다
→ 그리고 그것은 위반이 아니다: 장치는 ≈48ms 에 송신을 끝냈으므로 115ms 는 **안전 지대**다
```
🔴 **내가 이미 아는 사실을 내 예측에 적용하지 못했다** — `oow` 의 과대계상은
`PREREG-2026-08-17-winA2-slot3.md §2.6.2` 와 창 A 판정문 §4 에 **내가 직접 적어 뒀다.**
**원장 7.84(규칙을 만든 순간이 가장 위험하다)·7.101 의 재현이다.**
⚠ 이 판정선을 그대로 뒀으면 **`oow ≈ 100%` 를 보고 "큐가 창을 못 지켰다"로 정반대 판정**을 냈다.

### ②′ 고친 판정선 — **건별로 `도착 오프셋` vs `due + txTime`**

```
✅ 기대 : 오프셋이 **100~130ms 대에 몰리고**, `due + txTime`(≈48ms) **보다 이른 건이 0**
🔴 위반 : 오프셋이 `due .. due+txTime` **안에** 떨어진 건 — **그것만이 진짜 위반**이다
🔑 결과 지표: 그 위반의 결과가 `[CKSUM NG]` 다(위험 구간에 들어가면 깨진다)
```
- **분모**: 하행 거래 `N ≥ 200` · 그리고 **`[SLOT-OOW]` 건수 자체는 분자가 아니라 좌표 기록**이다.
- **자료(00:43 정정 · socket 지적)**: 🔴 **이 회차는 내 `[SLOT-OOW]` 도착 오프셋(장치 ms) 하나로만 본다.**
  socket 의 ms 는 **WS 로 보낸 시각**이고 **전선 송신 시각이 아니다** — 그 사이에 **큐 대기(0~1200ms)** 가 있다.
  전선 송신은 서버의 `→ARD … (S+0ms)` 줄인데 **그 줄은 1초 해상도**다.
  → **기준점이 될 줄이 ms 가 아니므로 두 로그를 ms 로 맞출 수 없다.**
  ✅ 다만 **`도착 오프셋 > due + txTime` 인가**는 **장치 오프셋만으로 갈린다** — 그것이 ②′ 의 판정선이다.
  📋 **다음 요구사항**: `→ARD` 줄을 ms 로 올린다(창 B 판정 뒤 · socket 목록에 넣었다).
  ⚠ 그래야 *"기대는 있는데 `+IPD` 가 없는 건"*(창 A2 `130ms 아래 공백` · `wire_rid=1086`)을 셀 수 있다.
- ⚠ **`oow` 의 절대 수를 창 A2 와 비교하지 마라**(정의가 다르고, 이제 큐 때문에 착지 위상 자체가 바뀐다).

### ~~② 🔑 장치측 — `[SLOT-OOW]` 가 0 이어야 한다~~</details>
큐는 하행을 **장치가 말한 직후(`S+0ms`)에만** 보낸다(socket 실측: 착지 위상 전부 `(S+0ms)`).
그러면 도착이 **항상 수신 창 안**이므로 **송신 창 도착(=`oow`)이 원리적으로 안 생긴다.**
- **판정선**: `oow / 하행 거래 = 0` (분모 `N ≥ 200`). **`oow > 0` 이면 큐가 창을 못 지킨 것**이고
  그 오프셋 분포가 **어디서 새는지**를 가리킨다.
- 🔴 **`oow=0` 을 분모 없이 인용하지 마라** — 창 A 에서 내가 들어갔던 함정이다(자극 0 의 0).
- 🔴🔴 **범위 축소(00:4x · arduino)**: `oow` 는 **하행 도착**만 본다. **우리 ACK 은 `sendAck →
  sendLine` 으로 슬롯을 우회**하므로(게이트만 열려 있으면 수신 창 한복판에도 나간다)
  **`oow=0` 은 "슬롯 규율이 지켜졌다"를 뜻하지 않는다.** `[SLOT]`·`smiss`·`skip` 도 `statusTick`
  경로만 본다 → **ACK 경로 위반을 세는 칸이 지금 없다.**
  → ✅ **예측 ②의 판정 문장은 "하행 도착이 수신 창 안이었다" 로 좁힌다.** 그 이상은 못 말한다.
- ⚠ `[SLOT] ack=` 는 **ACK 총수가 아니다**(큐 경유분만). **ACK 총수는 `[TX] A,` 로 센다.**
  다음 굽기에서 `sendAck` 이 슬롯에 묶이면 `ack=` 정의가 바뀐다 → **`oow` 와 함께 대조 불가 칸.**

### ③ `[CNT] cksumng = 0` · `ssovf` 증가 0
파괴는 **하행이 송신 구간에 착지할 때** 났다(창 A 4건). ②가 참이면 착지 자체가 없어 **0 이어야 한다.**
- ⚠ **`CKSUM NG` 은 "깨진 것"만 센다. "사라진 것"은 못 센다**(창 A2 `wire_rid=1086` 이 그 사각).
  → **socket 의 `재전송` 과 같이 봐야 손실 상·하한이 잡힌다.**

### ④ 유휴 리셋은 **남을 수 있다**
창 A2 유휴 69분에 `esprst=2` 였다. **큐는 하행 경로만 고친다** → 유휴 리셋이 그대로여도
**큐 실패가 아니다.** 반대로 **줄어들면 그것은 설명이 필요한 결과**다(큐와 무관한 축이 바뀐 셈).

## 3. 판정 절차

1. 분모 먼저: `시도 − 미주입` · 슬롯 수 · 노출. `N < 200` 이면 **판정하지 않는다.**
2. `inj5`(서버만)와 `inj6`(양쪽)을 **한 표에 합치지 말고 두 칸으로** 낸다.
3. 손실은 **`CKSUM NG`(하한) ↔ `재전송`(상한)** 두 수로 적는다. 한쪽만 쓰지 않는다.
4. 내 로그의 문자 손상(에코 줄 4.2% · 수신 줄 0.28%)을 `0` 옆에 적는다(원장 7.106).
5. 서버 로그는 **같은 파일**이다 — `INSTANCE-END`(22f788d) → 새 `INSTANCE`(aeb5283) **경계로 갈라 읽는다.**

## 4. 기록해 둘 실측 둘 (창 B 배포 직후 · socket 제공)


🔴 **망 왕복(`d1+d2`)으로 쓸 수 없다** — 정의가 `하행 송신 → ACK 도착`이고 그 사이에
**장치의 다음 송신 창 대기(0~1200ms)** 가 들어 있다. 🔑 **ACK 도 슬롯 규율을 지킨다**는 것이
그 수의 정체다 — 설계가 도는 증거이면서 동시에 **이 방법으로 `d1+d2` 를 못 재는 이유**다.
→ **arduino 의 `cap` 재계산 입력으로 넘기지 못한다**(socket·루트 정정).

```
W_srv 가 음수 → **하한 150ms 로 클램프**됐다
```
🔴 **클램프가 없었으면 창이 0 이 되어 하행이 전부 막혔을 것이다.** 사고가 안 난 것은
**설계 여유가 우연히 살린 것**이고, **우연히 살아난 것은 다음에 안 살아난다.**
→ **클램프를 상수가 아니라 규칙으로 만들어야 하는지**는 socket 의 판단 항목(루트 배정).

> ### 🔴 **②′ 의 문턱(48ms)도 좁다.** 실측 위반이 **175ms** 에서 났다.
> `due` 는 `sendSlotBatch` **호출 시각**이고, 실제 UART 작업(`AT+CIPSEND` 명령 → 프롬프트 대기 →
> 페이로드)은 **그보다 훨씬 뒤까지 이어진다.** 창 A 의 116ms 건과 같은 방향이고 **이번엔 도착 시각이다.**

🔑 **그리고 이것이 arduino 가 자진 신고한 그 경로와 맞물린다** — 슬롯을 우회하는 송신(`sendAck →
sendLine`)과 프롬프트 대기 구간이 **계측기 어디에도 안 잡힌다.** `oow` 는 이 위반을 세지 못하고
(`175 > 48` 이라 "안전"으로 분류된다) **`[CKSUM NG]` 만이 그것을 드러낸다.**

⚠ **더 나쁜 가능성**: 큐가 **착지 위상을 135~207ms 에 고정**했고 **그 대역이 장치의 CIPSEND 구간과
겹친다.** 그러면 **큐가 이 특정 충돌을 오히려 집중시킨** 셈이다. 창 A(무큐)는 위상이 훑고 지나갔다.
🔴 **표본이 2건이다. 확대하지 마라** — 완주 후 `cksumng` 최종값과 `재전송` 을 짝지어 판정한다.
