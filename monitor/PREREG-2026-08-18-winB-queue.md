## 0. 🔴 이 창은 **두 조각**이다 — 판정은 `inj6` 로 낸다

```
inj5  00:32:28~   서버 aeb5283 pid 4029 · 300건 목표   🔴 **장치측 관측 없음**(내 탭이 내려가 있었다)

```
**`inj5` 를 버리지 않는 이유**(루트 확정):
```
inj5 = "큐가 있을 때 **서버가** 무엇을 보는가"
inj6 = "그때 **장치가** 무엇을 겪는가"
```
🔑 창 A 에서 배운 것이 정확히 그것이다 — **한쪽 계수만으로는 `재전송 0` 이 "파괴 0" 인지
"못 셈" 인지 안 갈린다**(창 A 에서 socket 의 `유실 0` 이 파괴 3 을 덮고 있었다).
**두 조각이 그 갈래를 채운다.**

⚠ **왜 `inj5` 에 관측이 없었나**: 루트가 배포 **완료** 통보를 socket 에게만 보냈다(자진 신고).
내가 기다린 신호가 존재하지 않았다. 🔴 **그리고 지금 탭을 열지 않은 것이 판정이다** —
탭 개방은 DTR 리셋이라 **진행 중인 `inj5` 를 끊는다.** 75건 통과·재전송 0 으로
**3차①의 중단점(51)을 이미 넘긴 것 자체가 대조값**이므로 그것을 깨지 않는다.

## 2. 예측 (사건 뒤 수정 금지)

### ① 서버측 — socket 이 등록한 것: **오프라인 0 · 세션 종료 0 · ACK실패 0 · 300 완주**
3차①(큐 없음)은 **i=51 에서 중단 · 세션 종료 `errno=54` · 최대공백 10.0초**였다.
- **판정선**: `시도 = 300`(완주) 이고 위 셋이 0 이면 **큐가 이 기전을 막았다.**
  하나라도 0 이 아니면 **큐만으로는 부족**하고 그것이 발견이다.
- ⚠ `inj5` 는 이 예측을 **서버측만** 채점한다.

### ② 🔑 장치측 — **`[SLOT-OOW]` 가 0 이어야 한다**
큐는 하행을 **장치가 말한 직후(`S+0ms`)에만** 보낸다(socket 실측: 착지 위상 전부 `(S+0ms)`).
그러면 도착이 **항상 수신 창 안**이므로 **송신 창 도착(=`oow`)이 원리적으로 안 생긴다.**
- **판정선**: `oow / 하행 거래 = 0` (분모 `N ≥ 200`). **`oow > 0` 이면 큐가 창을 못 지킨 것**이고
  그 오프셋 분포가 **어디서 새는지**를 가리킨다.
- 🔴 **`oow=0` 을 분모 없이 인용하지 마라** — 창 A 에서 내가 들어갔던 함정이다(자극 0 의 0).
- 🔴🔴 **범위 축소(00:4x · arduino)**: `oow` 는 **하행 도착**만 본다. **우리 ACK 은 `sendAck →
  sendLine` 으로 슬롯을 우회**하므로(게이트만 열려 있으면 수신 창 한복판에도 나간다)
  **`oow=0` 은 "슬롯 규율이 지켜졌다"를 뜻하지 않는다.** `[SLOT]`·`smiss`·`skip` 도 `statusTick`
  경로만 본다 → **ACK 경로 위반을 세는 칸이 지금 없다.**
  → ✅ **예측 ②의 판정 문장은 "하행 도착이 수신 창 안이었다" 로 좁힌다.** 그 이상은 못 말한다.
- ⚠ `[SLOT] ack=` 는 **ACK 총수가 아니다**(큐 경유분만). **ACK 총수는 `[TX] A,` 로 센다.**
  다음 굽기에서 `sendAck` 이 슬롯에 묶이면 `ack=` 정의가 바뀐다 → **`oow` 와 함께 대조 불가 칸.**

### ③ `[CNT] cksumng = 0` · `ssovf` 증가 0
파괴는 **하행이 송신 구간에 착지할 때** 났다(창 A 4건). ②가 참이면 착지 자체가 없어 **0 이어야 한다.**
- ⚠ **`CKSUM NG` 은 "깨진 것"만 센다. "사라진 것"은 못 센다**(창 A2 `wire_rid=1086` 이 그 사각).
  → **socket 의 `재전송` 과 같이 봐야 손실 상·하한이 잡힌다.**

### ④ 유휴 리셋은 **남을 수 있다**
창 A2 유휴 69분에 `esprst=2` 였다. **큐는 하행 경로만 고친다** → 유휴 리셋이 그대로여도
**큐 실패가 아니다.** 반대로 **줄어들면 그것은 설명이 필요한 결과**다(큐와 무관한 축이 바뀐 셈).

## 3. 판정 절차

1. 분모 먼저: `시도 − 미주입` · 슬롯 수 · 노출. `N < 200` 이면 **판정하지 않는다.**
2. `inj5`(서버만)와 `inj6`(양쪽)을 **한 표에 합치지 말고 두 칸으로** 낸다.
3. 손실은 **`CKSUM NG`(하한) ↔ `재전송`(상한)** 두 수로 적는다. 한쪽만 쓰지 않는다.
4. 내 로그의 문자 손상(에코 줄 4.2% · 수신 줄 0.28%)을 `0` 옆에 적는다(원장 7.106).
5. 서버 로그는 **같은 파일**이다 — `INSTANCE-END`(22f788d) → 새 `INSTANCE`(aeb5283) **경계로 갈라 읽는다.**

## 4. 기록해 둘 실측 둘 (창 B 배포 직후 · socket 제공)

```
왕복 최대 751ms · 마지막 140ms · n=18
```
🔴 **망 왕복(`d1+d2`)으로 쓸 수 없다** — 정의가 `하행 송신 → ACK 도착`이고 그 사이에
**장치의 다음 송신 창 대기(0~1200ms)** 가 들어 있다. 🔑 **ACK 도 슬롯 규율을 지킨다**는 것이
그 수의 정체다 — 설계가 도는 증거이면서 동시에 **이 방법으로 `d1+d2` 를 못 재는 이유**다.
→ **arduino 의 `cap` 재계산 입력으로 넘기지 못한다**(socket·루트 정정).

```
W_srv 가 음수 → **하한 150ms 로 클램프**됐다
```
🔴 **클램프가 없었으면 창이 0 이 되어 하행이 전부 막혔을 것이다.** 사고가 안 난 것은
**설계 여유가 우연히 살린 것**이고, **우연히 살아난 것은 다음에 안 살아난다.**
→ **클램프를 상수가 아니라 규칙으로 만들어야 하는지**는 socket 의 판단 항목(루트 배정).
