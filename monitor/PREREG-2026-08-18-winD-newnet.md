# 창 D — 창 정의와 사전 등록 (`slot5` = 코드는 `slot4` 와 동일 · **망만 다르다**) · 2026-08-18

> 🔴 `inj8-pre` 시작 **전**에 쓴다. 결과는 §4 에만.

## 1. 🔴 `t0` — 이번엔 순서가 반대였다 (탭이 먼저, 장치가 나중)

```
09:10:29  탭 개방(DTR 리셋) — 그때 **ESP 는 죽어 있었다**(rx=0 · [AT] 0줄 · 5.6분)
09:16:08  **[System Ready] · rx 0→82**        ← 🔴 **t0_D**
09:16:24  IP 확보 192.168.0.214 · 09:16:27 +ARD 세션#1 · 09:16:44 첫 SEND OK
t_start = **09:18:08** (t0+120s)
```
🔑 **`t0` 의 정의는 "재는 대상이 지금 상태로 존재하기 시작한 시각"** 이다. 탭 개방 리셋은 **Uno 만**
되살렸고 **ESP 는 그때 없었다** → 탭 개방을 `t0` 로 쓰면 **5.6분의 사망 구간이 창 안에 들어간다.**
🔴 **`09:10:29~09:16:08` 은 유휴 기준선으로 쓰지 않는다** — **정상 유휴와 죽어 있는 것은 다르다.**
⚠ 지금까지 모든 창은 `t0 = 탭 개방 DTR` 이었다. **이 창만 다르고, 그 이유가 위 한 줄이다.**

## 2. 🔴 창 A~C 와 합산 금지 — 바뀐 것이 넷이다
```
AP(SSID/PASS) · 서브넷(192.168.35.x → 192.168.0.x) · USB 재연결(포트명 21201→1101) · ESP 전원 리셋
```
**넷 다 우리가 재던 지표(지연·재전송·링크 안정성·착지 위상)와 같은 축이다.**
✅ **코드 축은 창 C 와 동일**(`slot5` 는 접속 대상 3줄만 다르고 거동 변경 0 · arduino hex 대조).
→ **그래서 `inj8-pre` 가 "같은 코드 · 새 망"의 기준선이 된다.** ②(`cntTick`) 판정은 **이것과 대비**한다.

## 3. 이 망의 **유휴 실측** (t0+46분 · 하행 0건)
```
[CNT] 10:02:40  up=3120 slot=2600 · oow=**0** · cksumng=**0**   ← 자극 없는 0
                · **esprst=3 · drop=4 · resync=6 · stuck=2** · ssovf=2 · skip=13 · online=1
```
🔴 **하행이 하나도 없는데 모듈 리셋 3건.** 대조: 창 A2 유휴 69분 `esprst=2` · 창 C 유휴 5.5h `13`.
→ **`inj8-pre` 구간에 리셋이 나와도 "주입 탓"으로 세지 마라.** 이 46분이 그 분모다.
⚠ 그리고 이것이 **`inj8-pre` 를 돌리는 근거를 강화한다** — 망 변경으로 **유휴 안정성 자체가 달라졌을 수
있고**, 창 C 를 전(前)으로 썼으면 **그 축이 통째로 숨었다.**

## 4. 예측 (자료 전)
- **`cksumng` 의 60초 주기가 새 망에서도 유지된다** — `[CNT]` 는 장치 내부 타이머라 망과 무관하다.
  🔴 **이것이 먼저 확인돼야 ②의 효과를 "주기 소멸"로 읽을 수 있다.** 안 유지되면 **②를 굽기 전에
  왜 사라졌는지부터 밝힌다**(망이 착지 위상을 옮겼을 가능성).
- **착지 오프셋 분포**가 창 C(최소 83ms)와 다르면 **망이 위상을 옮긴 것**이다 — 창 C 에서 "미확인"으로
  남긴 `135→83ms` 가 여기서 갈린다.
- **`ssovf`** 는 셋으로 갈린 상태다(주입분 · 재접속 폭풍분 · 미상). **`esprst` 가 오른 표본은 빼고 읽는다.**
