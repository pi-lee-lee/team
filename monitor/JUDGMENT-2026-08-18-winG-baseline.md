> ### **48~53B 프레임이 40건 있었는데도 T2 가 0 이다. 없어서 안 난 게 아니다.**

## 9.1 대역표 — **문턱이 63 과 64 사이**
```
창 G 전체 · CIPSEND 크기대역 대 T2
  <48     748 거래 → T2 1  (0.1%)
  48~63    43 거래 → T2 0  (0.0%)
  >=64     34 거래 → T2 9  (26.5%)
```
**`_SS_MAX_RX_BUFF = 64`(SoftwareSerial 링버퍼)와 자리가 맞는다.**
🔑 **arduino 가 "내 64B 는 기전 경계, 네 48B 는 표본 추출 기준"이라고 갈라 주지 않았으면
내 48B 축으로 계속 세어 이 문턱을 못 봤다.** — §"이름이 아니라 정의를 맞춰라"의 성공 사례.

## 9.2 🔑 하행 동시성 교락을 **창 안에서** 뗀다
```
2차 주입 창(하행 4건 동시 · 같은 부하) :  <48 → 35거래 T2 0   ·   >=64 → 19거래 T2 9
```
**같은 창·같은 하행 조건에서 크기만으로 갈린다.** → **"하행 존재"·"슬롯당 하행 건수" 축이 떨어진다.**

## 9.3 🔴 그리고 **뒤집힘은 원인이 아니었다 — 크기와 교락된 지표였다**
```
socket 판별 시험(52B) : 뒤집힘 14건 → T2 **0건**
2차 주입     (90~94B) : 뒤집힘  5건 → T2 **5건**
```
> ### **뒤집혀도 `SEND OK` 가 오면 T2 가 안 난다.** 갈리는 것은 **`SEND OK` 가 살아 오느냐**이고
> ### 그것이 **64B 에서 갈린다.** **오전에 내가 "뒤집힘이 T2 를 가른다"고 한 것을 이로써 좁힌다.**

## 9.4 ⚠ 내 판정기 두 번째 결함 — 결과를 `SEND OK 유무` 에서 `T2` 로 바꿨다
처음 낸 대역표는 `48~63` 이 **32.6% 실패**로 나왔다. 원문을 열었더니 **뒤집힌 거래에서

🔑 **순서가 뒤집히는 자료에서 "그 줄 이후"로 구간을 잡으면 안 된다.** 결과 지표를 **`T2`** 로 바꿔 해결했다.
