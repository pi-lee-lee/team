> ### 🔑 **서버는 "실패 0" 인데 장치는 파괴 5 를 셌다.**

### 3.1 기전 — **ACK 우회 송신과의 충돌** (arduino 원문 분석)

```
00:42:38  [AT] "AT+CIPSEND=38"                   ← 앞 하행의 **ACK** 을 쓰기 시작(sendAck→sendLine)
00:42:40  [TX] S,142 · [SLOT] n=151 due=0 r=1
00:42:40  [AT] "+IPD,16:T,34AT+CIPSEND=38" (25)  🔴 하행이 잘리고 우리 명령이 끼었다
00:42:40  [SLOT-OOW] +175ms · [CKSUM NG]
```
`sendAck` 은 **슬롯 창을 보지 않는다**(`client.ino:1853`) → **175ms 에도 송신을 시작한다.**
`due=0` 은 그 슬롯의 **배치** 송신 시작이라 **ACK 송신이 그 줄에 안 나온다** → 계측기가 못 봤다.

### 3.2 ✅ 출처가 갈렸다 — **장치의 60초 주기 디버그 출력**이다 (내 추론 하나를 철회한다)

```

```
**내가 처음 쓴 것**: ~~"장치 출력이 원인이면 도착 오프셋은 안 변해야 하므로, 늦어진 것은
서버 flush 지연(60초 요약)을 가리킨다"~~ → 🔴 **전제가 틀렸다(socket 반박 · 두 근거 모두 실측):**

**(1) 위상 논증 — 서버는 원인이 될 수 없다**
```
socket 요약 위상 : 두 회차 내내 **:50~:51 고정**(서버 인스턴스 하나 · pid 4029)
손실 위상        : inj5 **:24** → inj6 **:40**   ← **움직였다**

```
→ **서버 위상이 안 움직였는데 손실 위상이 움직였다 → 서버는 원인이 아니다.**

**(2) 내 "오프셋이 늦었다"는 관측도 (나)로 설명된다**

**첫 바이트 도착 시각 자체가 늦게 찍힌다.** `+35ms` 는 *"내가 늦게 보냈다"* 가 아니라
**"장치가 늦게 봤다"** 다. 🔑 **arduino 의 `pendLine` 과 같은 종류 — 측정 지점이 사건에 밀린다**
(원장 7.104). **오늘 이 형태가 세 번째다.**

⚠ **엄밀한 범위**(socket 이 스스로 달았다): 위 논증은 **(가)를 반박**하지만 **`[CNT]` 자체를

**`[CNT]` 라는 특정은 내 정합 자료가 받친다**: 다섯 시각 중 **4/4 에서 `[CNT]`+`[RAM]` 동반**,
그리고 **`00:44:40` 은 `[CNT]` 도 없고 파괴도 없다**(결손이 같이 빠졌다). **둘을 합쳐야 결론이다.**

⚠ 그리고 **`SOAK_REPORT_MS`(서버 요약 주기)를 건드리지 않는다**(socket 결정) —
**원인이 아닌 것을 고치면 다음 사람이 그 변경을 근거로 잘못 추론한다.**

## 4. 단정 범위 — 반드시 같이 읽어라

1. 🔴 **`oow=304`·`smiss=1` 로 "설계가 지켜졌다"를 말할 수 없다.** `sendAck` 이 슬롯을 우회하고

   → **`cksumng=5` 의 원인이 ACK 충돌이므로 `oow=304` 안에 그 사건은 없다. 두 수를 인과로 잇지 마라.**
2. **`oow=304` 는 `slot3` 첫 기준선**이다(도착 시각 정의). **창 A 의 `693`(처리 시각)과 대조 금지.**
   그리고 큐 때문에 착지 위상 자체가 바뀌었다 — **이 창 안에서만 읽는다.**
3. ⚠ **`ssovf 3 → 5`**: 증가 시각(`[CNT]` 표본 기준) `00:43:39·00:44:39·00:46:39·00:47:39·00:48:40`.
   🔴 **`00:44:39` 에 올랐는데 그 분에는 파괴가 없다**(`00:44:40` 정상) → **창 A 와 같은 패턴이다:
   수는 비슷하고 시각이 어긋난다. `ssovf` 와 `cksumng` 를 기전으로 잇지 마라.**
   ⚠ 그리고 **창 B 는 배치가 묶여 하행이 커진 창**이라 arduino 가 *"`ssovf` 는 창 B 부터 값을 갖는다"*
   고 한 자리다 — **증가가 예상된 것과 새 사건을 이 자료로는 못 가른다.**

### 🔴 4.3 `ssovf` A/B 판별 — **이 자료로는 못 가른다. 해상도가 이긴다** (원문 확인)

후보: **A** 배치가 커져 64B 링버퍼를 넘긴다 / **B** `[CNT]` 블로킹 동안 `pumpSerialRaw()` 가 안 돌아 쌓인다.

**루트 논거**: *"5번째 증가 구간(`00:48:10~40`)에 하행이 없으니 A 가 아니다."*
→ 🔴 **원문을 열었더니 성립하지 않는다.** 증가가 보인 `[CNT]` 는 `00:48:40` 이고 **직전 표본은
`00:47:39`** 이므로 **판별 구간은 61초 전체**다. 그 구간 실측:
```
00:47:39~00:48:40 (61초 · 339줄) : **+IPD 14건** · [TX] 64 · SEND OK 64 · CIPSEND 52 · 이상 0
                                   (주입은 00:47:56 종료 — 앞 17초에 하행이 몰려 있다)
```
**하행이 14건 있었다. A 는 배제되지 않는다.**
🔑 **`ssovf` 는 `[CNT]` 표본에서만 읽히므로 판별 해상도가 60초다.** 그 안에 주입 구간과 유휴 구간이
같이 들어가면 **어떤 대비도 성립하지 않는다.** 이 판별은 **자료가 아니라 계측 방식 때문에 막혔다.**

⚠ **정황도 양쪽으로 갈린다**: `창 A 52분/[CNT] 52회 → ssovf 3` 대 `창 B 9분/9회 → ssovf 5`.
arduino 는 A 쪽 정황으로, 루트는 *"B 라면 `[CNT]` 횟수에 비례해야 하니 회당 10배는 B 단독으로 안 된다"* 로
읽었다. **둘 다 일리가 있고 그래서 정황으로는 못 정한다.**

📋 **가르는 데 필요한 것(arduino 요청 항목)**: **넘침을 발견한 순간 줄을 찍어라**
```
[SSOVF] +<슬롯오프셋>      ← 지금은 [CNT] 에만 누계로 실린다
```
**그 한 줄이면 `[CNT]` 출력 구간과 겹치는지, 하행 도착과 겹치는지 건별로 갈린다.**

### ✅ 4.4 `ssovf` 계수 정의는 `slot2`↔`slot3` 에서 **안 바뀌었다** (확인 요청 답)

**`ssovf` 는 손대지 않았다.** → **창 A ↔ 창 B 를 이을 수 있는 몇 안 되는 칸 중 하나다.**
⚠ 다만 **잇는다고 원인이 같다는 뜻은 아니다**(§4.3). 그리고 **`3` 도 `5` 도 하한**이다(읽으면 지워진다).

### 📌 4.5 arduino 의 논거 이력 — 그대로 남긴다 (그 자체가 자료다)
```

```
🔑 **"내가 '창 B 부터 값을 갖는다'고 한 그 자리에 실제로 값이 생겼고, 그 값이 아직 안 읽혔다"** —
이것이 지금 상태의 정확한 서술이다.
4. ⚠ **창 A 의 `CKSUM NG 4` 는 내가 손으로 센 것**이고 여기 `cksumng=5` 는 **펌웨어 계수기**다.

### 7.2 창 C 에서 정의가 또 바뀌는 칸 — **미리 박는다**
```
창 B 까지 : ack = ackq 를 거친 것만(게이트가 닫혔을 때만 · 소수 경로)
