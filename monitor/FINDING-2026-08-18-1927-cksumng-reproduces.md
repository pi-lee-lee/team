# 발견 · **`cksumng` 손상은 창 H 특유가 아니다 — 새 망에서 재현된다** (2026-08-18 19:27)

**창 I** t0 `19:23:03` · 주입 `19:23:51~`(진행 중) · 새 망 · 새 서버 인스턴스 · 새 IP

## 1. 창 H 의 미결이 닫혔다 — **다만 기대한 방향이 아니다**
창 H 판정문 §7.2 에 *"낮게 나오면 **창 H 특유**의 것"* 이라고 적었다. **낮지 않다. 더 높다.**
```
창 H  cksumng 85 / 하행 약 3,923줄 = **2.17%**
창 I  cksumng 22 / 하행 약   501줄 = **4.39%**
```
> ### ✅ **확정: "창 H 특유"라는 설명은 죽었다.** 망·서버·IP 가 전부 바뀌었는데 재현된다.

## 2. ⚠ 그러나 **"수정이 만들었다"는 아직 아니다 — 하행 밀도가 다르다**
```
창 H  3,923줄 / 34.7분 ≈ **113줄/분**
창 I    501줄 /  2.9분 ≈ **173줄/분**    ← 1.5배 빽빽하다
```
**손상이 밀도에 비례하는 성질이면 4.39% 대 2.17% 는 그 차이로 설명된다.**
🔴 **아직 못 가른다.** 갈리려면 **같은 밀도에서 두 판본**을 비교해야 하는데 **수정 전 펌웨어를 덮어썼다**(7.136).

## 3. 지문은 창 H 와 같다 — **바이트 손상이 아니라 줄 조립 실패**
```
19:24:01  [CKSUM NG] T,31,S,B1,1,6B,32,S,B2,1,6B      ← 하행 두 줄이 붙었다
19:24:07  [CKSUM NG] T,43,S,A3,1,AT+CIPSEND=62        ← 🔴 **우리 CIPSEND 에코와 붙었다**
19:24:21  [CKSUM NG] T,87,S,B1,1,66T,88,S,A4,1,6F     ← 하행 두 줄이 붙었다
19:24:28  [CKSUM NG] T,107,S,A2,1                     ← 잘렸다
```
🔑 **`T,43,…AT+CIPSEND=62` 가 기전을 가리킨다** — **하행 줄이 조립되는 중에 우리가 쓰기를 시작한다.**
**고친 것(`SEND OK` 실종)과 같은 경계의 반대 방향이다**: 전에는 **우리가 받을 줄**을 잃었고,
지금은 **하행 줄**이 붙거나 잘린다. **둘 다 반이중 UART 의 줄 조립 문제다.**

## 4. 같은 창의 다른 계수 (2.9분 · CIPSEND 150)
```

stuck 0 · resync 0 · **penddrop 0** · okstream 142 · ssovf 18 · oow 109
```

창 H 는 `penddrop=9` 였다. **이 창에서는 (나) 기전이 발동 자체를 안 했다.**
🔑 **새 물음**: `>=64B` 134거래에서 왜 발동을 안 했나. **창 G 에서는 같은 대역 34거래 중 9건이 T2 였다.**
