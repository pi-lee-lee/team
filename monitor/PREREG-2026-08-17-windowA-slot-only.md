# 사전 등록 — **창 A**(슬롯 펌웨어 + 큐 없는 서버)에 대한 예측 · 2026-08-17 **20:1x**

> 🔴 **자료를 보기 전에 쓴다.** `§1`·`§2` 는 **사건 뒤에 고치지 마라** — 고치면 사전 등록이 아니다.
> 결과는 **`§5` 에만** 적는다. (같은 규칙을 `PREREG-2026-08-17-reset-onset.md` 에서 쓰고 있다.)
> 작성 `monitor-engineer`. 창 개방 전 · 포트 미개방 · 실물 미접촉.

## 0. 왜 이 사전 등록이 필요한가

루트가 배포 순서를 **(나) 슬롯 펌웨어 먼저 → (가) 서버 큐 나중**으로 정했다(굽기 비용 때문 ·
내가 요청한 반대 순서보다 낫다 — 굽기 1회로 두 창이 나온다).

```
창 A = 슬롯 펌웨어(REQ-0164) + 운영 서버 build=22f788d   ← 큐 없음(내가 서버 로그로 확인: pid 46224)
창 B = 창 A + 하행 큐(가)
```

🔴 **창 A 에서 사건이 창4 보다 줄지 않거나 오히려 늘 수 있다.** 그것이 **설계 실패로 오독될 위험**이
있어서 미리 적는다 — **서버가 아직 수신 창을 안 지키므로 충돌 기전은 창 A 에서 그대로 살아 있다.**
장치 쪽 규율만으로는 하행 착지 시각을 통제할 수 없다.

## 1. 🔴 예측 (사건 뒤 수정 금지)

### 예측 ① `[SLOT-OOW]`(수신 창 밖 하행 도착)가 **크게 찍힌다 — 대략 절반**

근거: 큐가 없는 서버는 이벤트 시점에 즉시 보낸다. 하행 착지가 슬롯 위상에 대해 균일하다면
**수신 창(600~1200ms)은 슬롯의 절반**이므로 위반은 **약 50%**.
- **판정 규칙**: `OOW / 하행 거래 ≥ 0.25` 이면 예측 적중. `0.05` 미만이면 **빗나감**
  (그때는 "서버가 이미 창을 지킨다" 또는 **"표지가 안 붙었다"** 를 갈라야 한다 — §2.3).
- 🔑 **이 예측이 맞으면 그 자체로 표지 교정이 된다** — 분모가 실재함이 증명되고,
  창 B 의 `OOW ≈ 0` 이 "설계가 먹었다"로 읽을 수 있게 된다(루트 지적).

### 예측 ② 거래당 사건 확률이 **창4 보다 낮아지지 않는다** (같거나 1.3~1.6배)

계산 근거 — **충돌 기전이 "하행이 장치 송신 구간에 착지"라면 거래당 확률 ≈ 송신 듀티**다.

| | 한 거래의 송신 구간 | 주기 | 듀티 |
|---|---|---|---|
| 창4 (42B 프레임) | 프롬프트 3ms + 페이로드 3.6ms + `SEND OK` 대기 16~40ms ≈ **23~47ms** | 1.11s | **2.1~4.2%** |
| 창 A (묶음 ~200B) | 3ms + 17.4ms + 20~45ms ≈ **40~65ms** | 1.2s | **3.3~5.4%** |

- 상수 출처: `promptms=3ms` · `okms=16~40ms` 는 **arduino 의 `cipsize` 프로브 실측**(설계 문서).
  페이로드 시간은 `바이트×10 ÷ 115200` 계산값. ⚠ **내 로그 해상도는 1초라 내가 잰 값이 아니다**
  (원장 7.51 — 해상도보다 짧은 구간은 내 계측으로 검증 불가).
- 창4 실측 대조: 거래당 사건 **클러스터 4/84 = 4.8%** · 낱개 7/84 = 8.3%
  → **듀티 2.1~4.2% 와 같은 자릿수다.** 이 일치가 기전 가설의 정량적 근거 하나다.
- **판정 규칙**: 창 A 의 거래당 클러스터 확률이 `0.03~0.10` 안이면 예측 적중.
  `0.01` 미만이면 **빗나감** → 슬롯 펌웨어가 **하행 착지와 무관한 다른 경로**로 기전을 줄였다는 뜻이고,
  그때는 무엇이 줄였는지를 따로 찾아야 한다(재동기 소멸? 거래 수 감소?).

### 예측 ③ `[TX-RESYNC]`·`실패 1/3` 이 **줄어든다** (사건 수와 별개로)

근거: 프레임 수가 줄고(밀린 ACK 를 한 번에 실음) 프롬프트 왕복 횟수가 줄면 재동기 기회도 준다.
- **판정 규칙**: 시간당 `[TX-RESYNC]` 가 창4 의 **절반 이하**면 적중.

## 2. 🔴 판정 절차와 함정 (사건 뒤 수정 금지)

1. **분모를 먼저 찍는다** — 하행 거래 수 `N`. `N < 315` 면 **판정하지 않는다**
   (§7.2 계산: `N ≥ 630` 이 10배 주장선, `315` 가 5배선). **못 채우면 "못 가른다"를 적는다.**
2. **`t0` 는 arduino 굽기 리셋**으로 잡고 `RECIPE-newbaseline-t0.md` 절차를 따른다.
   굽기 직후 안정화가 창 앞부분에 겹친다 — `t_start = t0 + 120s` 규칙 그대로.
3. 🔴 **`OOW = 0` 을 "서버가 창을 지켰다"로 읽지 마라.** 셋을 갈라야 한다:
   ① 표지가 코드에 안 들어갔다 ② 하행이 아예 없었다(`N=0`) ③ 정말 안 지켰다.
   **①·②를 배제하는 것이 분모 출력의 역할이다**(`zeroguard` 규약).
4. **창4 와 같은 표에 넣지 마라.** 구조가 다르다(`METRICS-slot-boundary` §5).
   거래당 확률 비교는 **참고값**으로만 쓰고, 판정문 본문은 `관측 N거래 · 사건 n건 · 위반 m건` 형태.
5. **커밋 차이 목록을 받기 전에 판정하지 마라** — 슬롯 외 변경이 섞여 있으면 그것도 축이다.

## 2.5 창 개방 **전** 추가 — 대조군 조건 (2026-08-17 **20:2x** · 아직 `tap` 미개방 · 자료 0건)

⚠ 아래는 §1 예측을 고치는 것이 **아니다.** 창이 열리기 전에 들어온 **구성 정보**이고,
자료가 한 줄도 없는 상태에서 적는다. **개방 후에는 이 절도 고치지 않는다.**

### 2.5.1 🔴 창4 를 대조군으로 쓸 때 **변수가 여섯이다** (arduino 통보 20:1x)

창4(`0fba51f`) → 창 A(`slot1`) 사이에 커밋 `443a352` 하나가 들어갔고, 그 안에
**슬롯과 무관한 변경이 다섯** 있다:
```
① ACK 큐   ② 3단 게이트(busy 폭풍 경로 제거)   ③ sendOkT1Passed(okto 단위: 증상→사건)
④ cifsrRefused(esprst 정의 변경 — 오탐 제거)   ⑤ [CNT] 칸 3개 추가
```
🔴 **`esprst`·`okto` 는 창4 와 이름이 같고 세는 것이 다르다.** `drop` 도 ②가 경로를 바꾼다.
→ **시계열로 이을 수 있는 것은 `전송 3회 연속 실패`·리셋 표지(배너/`0.0.0.0`/부트ROM)·노출 시간뿐**
  (`METRICS-slot-boundary` §5 목록 그대로). **`[CNT]` 계열 이름으로 창4 와 잇지 마라.**

### 2.5.2 프레임 주기 기준선이 이동했다 — **내가 직접 확인했다**(포트 미접촉, 서버 로그만)

```
창4  1.113s  → 2초 간격이 8.9프레임마다 (11%)
창 A 1.198s  → 2초 간격이 4.4프레임마다 (22.9%)   ← 실측: 20:12:36~20:16:26 · S 193프레임 / 230초
```
🔴 **"2초 공백이 늘었다"는 고장이 아니라 설계다.** 굽기 전후 간격 분포를 같은 표에 넣지 않는다.
⚠ 추가 관측: **같은 초에 두 프레임이 온 자리 7건 / 간격 220개 = 3.2%**(seq 는 연속 — 중복 아님).
  `1.2s` 주기에 1초 해상도면 원리적으로 안 나오는 값이므로 **1초 미만 간격이 실재한다.**
  arduino 는 "접속 직후 첫 두 프레임"만 예상했지만 **구간 중간에도 나온다**(20:15:04·:09·:33 …).
  → 판정 때 **`>=3s` 후보 판정에는 영향 없음**을 확인하고 쓸 것.

### 2.5.3 창 B 는 **축이 하나가 아니다** (루트 통보 20:2x)

`queued` 의 `ack_budget_ms` 필드가 큐와 **같은 배포에 들어가야 한다**(먼저 올리면 증폭 고리가
열린다 — 원장 `e58fd8b`). 즉 **창 B = 큐 + `ack_budget_ms` 이고 분리 불가**다.
→ **창 B 판정에서 "큐의 효과"라고 쓰지 마라.** `큐+ack_budget_ms 묶음의 효과`가 정확하다.
🔑 다만 `--down-immediate` 스위치가 있어 **같은 바이너리에서 (가)만 끄고 켤 수 있다** →
   굽기 없이 축 하나만 흔드는 A/B 가 가능하다. **그때가 큐 단독 효과를 볼 유일한 기회다.**
⚠ **그 창에 큐가 켜져 있었는지는 기본값으로 판단하지 마라 — 서버 기동 로그의 경고 유무로 본다.**
  (기본값은 소스의 성질이고, 그 창에 무엇이 돌았는지는 로그의 성질이다 — 루트 지적.)

### 2.5.4 새 계측기 `wifi.overflow()` — **이 수는 하한이다** (REQ-0167)

`SoftwareSerial` 넘침 계수기가 이번 굽기에 들어갔다. 지금까지 호출 0건이라 **아무도 모르던 칸**이다.
🔴 **읽으면 플래그가 지워진다 → 여러 번 넘친 것이 1건으로 뭉친다.**
```
0 이 아니다  →  강한 신호(확실히 넘쳤다)
0 이다      →  "측정 지점들 사이에 안 넘쳤다"까지만. 넘침 없음이 아니다
```
→ **측정 위치를 결과와 같이 인용한다.** 위치 없이 `overflow=0` 을 건강으로 쓰지 않는다.
⚠ **버퍼 증설은 이번 굽기에 안 들어갔다** — 들어가면 "안 넘쳤다"가 *원래 안 넘쳤다*인지
  *키워서 안 넘쳤다*인지 안 갈린다. **창 A 의 축을 하나로 유지하는 것과 같은 이유다.**

## 2.6 계측기 성질 추가 (2026-08-17 **20:3x** · 탭은 열렸으나 **하행 0건 = 예측 ①·②의 분모 0**)

⚠ **왜 이 시점에 적는 것이 정당한가**: 예측 ①·②는 **하행 도착**에 대한 것이고,
이 글을 쓰는 시점의 서버 로그 `→ARD` 는 **20:00 이후 0건**이다(검증 가능). 즉 **해당 자료가
한 줄도 없다.** 그래서 이 절은 **예측을 고치지 않고**(§1 의 숫자 그대로) **해석 제약만 더한다.**

### 2.6.1 ✅ `smiss` = **(B) 송신 창 침범 가드의 발동 계수** (arduino 답 20:3x)

내가 §2.5 에서 "(B)를 세는 칸이 없다"고 적은 것이 **틀렸다 — 이미 있다.**

| 칸 | 정확한 뜻 |
|---|---|
| `slot=` | 지난 슬롯 총수 = **분모** |
| **`smiss=`** | **온라인인데 그 슬롯에 시도조차 못 한 수** = **가드 발동 계수**(오프라인 슬롯은 제외) |
| `skip=` | 게이트(`SEND OK` 미도착)로 양보한 슬롯. 슬롯당 최대 1 |

- 관계식: `slot = 실제 송신 슬롯 + smiss + 오프라인 슬롯`
- **교차 검증**: `[SLOT] n=` 의 **번호 건너뜀 수 = 안 보낸 슬롯 수** → `smiss` 와 맞아야 한다.
  ⚠ **판정 때 이 대조를 반드시 한다.** 안 맞으면 둘 중 하나가 거짓말이다.
- 🔑 **가드가 발동한 슬롯은 상행이 통째로 밀려 `2.4초` 공백이 된다** →
  **`smiss` 가 오른 구간의 공백은 링크 이상이 아니라 가드다.** 공백을 사건으로 세기 전에 이 칸을 본다.

### 2.6.2 🔴 `oow` 는 **충돌이 아니라 "송신 창 구간 도착"을 센다** — 오탐과 누락이 **동시에** 있다

arduino 가 좌표계를 맞추다 스스로 잡아 정정했다. 판정식은 `sinceSlot < 600` 인데
**장치가 실제로 UART 를 쓰는 것은 `due ~ due+txTime`**(≈45ms · 최악 185ms) 뿐이다.

```
과대: due=0 에 45ms 만 쓰고 끝냈는데 slotStart+145ms 도착 → 안전한데 oow++   ← 오탐
누락: 진짜 충돌한 바이트는 사라져 handleLine 에 **도달조차 못 한다**        ← 안 세짐
```

> 🔴 **판정 규칙 추가**: `oow > 0` 을 곧바로 충돌로 읽지 않는다.
> **`[SLOT] due=` 와 대조해 `도착 오프셋 > due + txTime` 인 것은 안전으로 분류한다.**
> 그리고 **`oow` 는 살아남은 것만 센다**는 것을 수치와 같이 적는다(양방향 편향).

⚠ **예측 ①의 숫자(≈0.5)는 그대로 둔다** — 그것은 **계수기가 무엇을 찍을지**에 대한 예측이고
`sinceSlot<600` 기준으로 균일 도착이면 절반이 걸리는 것이 맞다. **다만 그 절반을
"설계 위반 절반"으로 읽지 않는다.** 위반 판정은 위 대조를 통과한 것만.

### 2.6.3 세션 경계 — 칩이 다르므로 섞지 않는다

```
세션#2  20:12:36 ~ 20:22:04   slot1  (가드 없음 · ssovf 없음)   ← 시리얼 기록 없음
세션#3  20:22:33 ~ 20:25:3x   slot2                             ← 시리얼 기록 없음
세션#4  20:25:37(내 DTR) ~     slot2  = **창 A 본체**            ← t0
```
🔴 **`slot1` 구간의 `due`·짧은간격 비율을 창 A 와 같은 표에 넣지 마라**(가드 상한이 없었다).
그리고 **`t0` 리셋은 우리 것**이므로 재부팅 사건으로 세지 않는다.

## 3. 이 예측이 **틀리면 무엇을 알게 되나** (미리 정한다)
