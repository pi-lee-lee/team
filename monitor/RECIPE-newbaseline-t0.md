## 1. 🔴 t0 의 정의 — **애매하게 두면 새벽에 갈린다**

### t0 = **시리얼 탭이 포트를 열면서 DTR 이 토글되어 보드가 리셋된 순간**

**표지(로그에서 t0 를 찾는 법)**: 시리얼 로그의 **첫 부트 배너 줄**.
탭이 열리기 전에는 로그 자체가 없으므로 **파일의 첫 배너가 곧 t0** 다.
(A 창의 대응물: `16:59:54` — 그때도 우리 DTR 리셋이었다.)

### 🔴 t0 는 **우리가 만든 리셋**이다 — 사건으로 세지 마라

`16:59:54` 와 같은 성격이다. **선언된 개입**으로 표시하고, 그 리셋에 뒤따르는
첫 재접속은 **링크 끊김 사건이 아니다.**

### 창 시작 `t_start` ≠ t0

| 기호 | 값 | 왜 |
|---|---|---|
| `t0` | 첫 부트 배너 시각 | 개입 시각. 여기서부터 세면 우리 리셋이 사건 1건으로 들어간다 |
| `t_start` | **t0 + 120초** | 기동 창 12초(원장 6.5) + 여유. 이 구간의 접속은 부팅 결과이지 끊김이 아니다 |
| `t_end` | 창을 닫는 시각(루트가 정한다) | ⚠ **미래를 넣지 마라**(원장 1.2 — 78배 희석 사고) |

**판정문에는 t0 · t_start · t_end 를 셋 다 적는다.** 하나만 적으면 다음 사람이 나머지를 추측한다.

## 2. 🔴🔴 A 와 순서가 뒤집혔다 — **자동 제외가 안 걸린다**

**A 창**: 서버가 창 안에서 떴다(17:53:07). → `link_drop_probe.py` 의
`SERVER_START_GRACE_S=90` 제외가 **자동으로 걸렸다**(제외 1건: `17:53:08 uptime 3180`).

**새 기준선**: **서버가 먼저 뜨고**(순서 2) **탭이 나중에 열린다**(순서 3).
→ 창 안에 `=== INSTANCE` 줄이 **없다.**

### 실측으로 확인된 도구 거동 (`frozen-A/link_drop_probe.py` L142·L146)

```python
starts = [... if "소크 관측 시작" in s or s.lstrip().startswith("=== INSTANCE")]
return any(0 <= (t - st).total_seconds() <= SERVER_START_GRACE_S for st in starts)
```

**제외는 스캔 구간 안의 서버 기동 줄에만 걸린다.**

🔴 **따라서 새 기준선에서는 우리 DTR 리셋의 재접속이 "재부팅 없는 재연결" 1건으로
그냥 세어진다.** 노출이 짧으면 λ 가 눈에 띄게 부풀 수 있다
(예: 2시간 창에서 1건 = +0.5/h — A 의 3.13/h 대비 16%).

**대처 — 셋 중 하나를 반드시 한다:**

1. `t_start = t0 + 120s` 로 창을 시작한다 ← **기본. 가장 단순하고 도구 수정이 없다**
2. 그래도 첫 ACCEPT 이 들어오면 **판정문에 손으로 제외하고 그 사실을 적는다**
3. ❌ 동결 도구를 고치지 않는다 — 고치면 A 와 다른 자로 재게 된다

⚠ **첫 ACCEPT 의 `uptime` 이 작다(≲120s)면** 도구는 그것을 "재부팅"으로 분류한다.
   그건 맞다 — **우리가 리셋했으니까.** "재부팅 1건"을 보고 놀라지 마라. 우리 것이다.

## 8. 🔴 **하행 "도달" 의 정의** — 루트가 나에게 정하라고 한 것 (23:5x)

> **정의 없이 명령만 들어가면 또 못 센다.** A 에서 실제로 그렇게 됐다.

### 8.1 관측점은 **셋**이다 — 서버 둘 + 시리얼 하나

A 창의 유일한 하행 1건(`17:53:08`)에서 실측으로 확인한 사슬이다:

```
① 서버 송신   2026-08-16 17:53:08  →ARD C,1,A4,2B                 (parking-server.log)
② 장치 수신   17:53:08  [AT] "+IPD,10:C,1,A4,2B" (17)              (serial-newbase.log)
③ 서버 수신   2026-08-16 17:53:08  ←ARD A,1,A4,0,35               (parking-server.log)
```

⚠ `+IPD,<n>:` 에 **연결 id 가 없다** — `CIPMUX=0` 이라서다(원장 3.4).
⚠ 서버 로그만 보면 ①③ 둘뿐이라 **②가 빠진 이유를 못 가른다.** 시리얼이 있어야 세 갈래가 갈린다.

### 8.2 이 창에서 셀 칸 — **4칸. 3칸으로 접지 마라**

| 칸 | 정의 | 뜻 |
|---|---|---|
| **D0. 도달** | ①→②→③ 이 seq 일치로 모두 있음 | 하행이 끝까지 돌았다 |
| **D1. 장치는 받았는데 응답이 안 옴** | ①②는 있고 **③ 없음** | 상행 응답 경로 문제 |
| **D2. 장치가 못 받음** | ①은 있고 **②③ 없음** | 하행 전달 자체가 끊겼다 |
| **D3. 미실행** | ①이 **0건** | 🔴 **측정 안 됨.** 건강이 아니다(원장 1.1) |

🔴 **D3 를 D0 100% 로 적지 마라.** A 에서 하마터면 `1/1 = 100% 도달` 로 쓸 뻔했다.
   분모가 1 이고 그 1 도 제외 구간 안이었다.

### 8.3 짝짓기 규칙 — 미리 못박는다

- **seq 로 짝짓는다.** `→ARD C,<seq>,…` ↔ `+IPD,…:C,<seq>,…` ↔ `←ARD A,<seq>,…`
  ⚠ seq 는 **인스턴스마다 1 부터 다시 시작한다**(A 에서 `→ARD C,1` 이 두 번째 인스턴스의 1 이었다).
  **인스턴스 경계를 넘어 짝짓지 마라.**
- **마감 시한**: ① 이후 **30초**. 그 안에 ③이 없으면 D1/D2 로 떨어뜨리고,
  **늦게 온 것은 별도로 세서 판정문에 적는다**(버리지 않는다).
- **시각차는 재되 값으로 쓰지 마라** — 서버는 서브초, 시리얼은 **1초 해상도**이고
  **서로 다른 시계**다. 도달률은 건수로 내고, 지연은 "같은 초 / 1초 / 2초 이상"으로만 적는다.

### 8.4 표본이 없으면 **없다고 적는다**

주입 계획이 오지 않으면 D3(미실행)로 판정한다. **"하행 문제 0건" 이라고 쓰면 거짓이다.**

→ **오늘 밤 OS 업데이트로 재부팅될 근거는 없다. 노출 계획에 크게 반영하지 않는다.**

남는 사실은 이것뿐이다: **21:04:49 에 정상 종료 절차가 스톨했고 패닉은 없었다.
누가/무엇이 재시작을 요청했는지는 이 흔적으로 안 정해진다.**

### 9.3 그러니 **무관측 재발을 전제로 설계한다**

원인이 안 밝혀졌으므로 **또 일어날 수 있다고 보고 창을 연다:**

- 🔴 **탭과 감시기가 같이 죽으면 경보가 없다**(21:04:50 에 실제로 그랬다).
- → 창 도중 **로그 파일 크기가 자라는지 직접, 주기적으로** 확인한다.
  루트도 따로 본다(23:5x). **감시기 생존을 이행으로 읽지 않는다.**
- → 판정은 **"계획 노출"이 아니라 "실측 노출"** 로 낸다. 잘리면 잘린 대로 §0 에 선언한다.

### 9.4 `INSTANCE-END reason=` 은 **`normal` 과 `signal` 둘 다 받아야 한다**

`signal` 이 `a091f17`(17:06)에서 `normal` 로 개명됐고 **한 파일 안에 두 이름이 공존한다.**
**둘은 같은 뜻이다.** `signal` 을 모르는 파서는 그 종료를 비정상/미상으로 오분류한다(원장 7.17).

## 10. 창을 닫을 때 — **서버 `INSTANCE-END` 줄과 반드시 대조한다**

A 에서 이 대조가 값졌다(판정문 §12). 그대로 한다:

```
=== INSTANCE-END logfmt=3 pid=<서버> stop=<시각> reason=normal frames=<N> sessions=<M> ===
```

| 대조 항목 | 내 재구성 |
|---|---|
| `stop=` | 로그 마지막 줄 시각 |
| `sessions=` | `link_drop_probe` 의 ACCEPT 총수(제외분 포함) |
| `frames=` | ⚠ **S 프레임 수가 아니다.** `←ARD S` + `←ARD A` 합계다(원장 7.15) |
| (추가) | 시리얼 `[TX]` 총수 — 서버 수신 총수와 맞아야 상행 무손실이다 |

**맞으면 재구성이 검증되고, 어긋나면 그 자체가 발견이다.**

### 11.1 🔴 새 창 판정문 §0 에 **그대로** 넣을 문장들

> **"새 창은 펌웨어와 서버가 동시에 바뀐 구성이다. A 와 견줄 때 어느 쪽 효과인지 못 가른다."**

> **"2단계가 자해를 줄일 것이라고 쓰지 마라."** 구운 뒤 자해가 줄어도 **다른 이유일 수 있다.**

## 12. 🔴 새 펌웨어(`539ac53`)가 **새 로그 줄**을 낸다 — 파서에 없으면 조용히 0 이 된다

arduino 통보(23:59). **창을 열기 전에 이 목록을 파서와 대조한다**(원장 1.1 의 '못 셈').

| 새 줄 | 세는 것 |
|---|---|
| `[TX-WAIT] 앞 전송의 SEND OK 를 아직 못 봤다 — 이번 주기는 건너뛴다` | `skip` |
| `[TX-WAIT] ★ SEND OK 상한 초과 → 대기를 푼다` | `okto` |
| `[CNT] up= drop= esprst= resync= sendfail= okto= skip= online=` (60초 주기, DEBUG 밖) | 누계 |

### 12.1 ⚠ `resync_gap.py` 의 N/P 이분법이 **이 펌웨어에서 깨진다** — 고치기 전에는 A 전용이다

`resync_gap.py` 는 앵커의 **다음 송신 주기**가 `[TX]` 냐 `[TX-RESYNC]` 냐로 N/P 를 가른다.
새 칩에는 **셋째 결말 `skip`(주기를 통째로 건너뜀)** 이 생겼다.
지금 코드는 skip 을 주기 시작으로 인식하지 못해 **그 앵커를 조용히 N 으로 떨어뜨린다.**

→ **새 창 자료에 이 도구를 그대로 돌리지 마라.** `[TX-WAIT] … 건너뛴다` 를 세 번째 주기
  종류로 넣고, 모집단을 **N / P / S(skip)** 3칸으로 늘린 뒤에 쓴다.
  ⚠ 그리고 그것은 **A 와 다른 계측기**다 — A 값과 같은 표에 넣지 마라.

### 12.2 ⚠ `okto` 를 옛 "미도달 0.33%" 와 견주지 마라 (arduino 경고 · 원장 6.5-1)

그 값은 **2단계 없는 칩**에서 나왔고 2단계는 **송신 타이밍 자체를 바꾼다.**
**새 칩에서 기대치를 새로 잡는 것이 첫 일이다.**

### 12.3 🔑 arduino 가 REQ-0139 §4 의 물음에 답했다

내 물음: *"프롬프트 대기와 `SEND OK` 대기가 같은 타이머인가?"*
→ **다른 타이머고, `SEND OK` 게이트가 `CIPSEND` 보다 앞에 있다.** 그래서 2단계가
그 경로를 **지나긴 지난다** — 다만 상한 2000ms 가 내가 잰 병리 분포(2~3s) **한가운데**라
**일부만 걸린다.** (판정문 §4 의 "나는 모른다"는 이것으로 닫혔다.)

## 13. 하행 주입 계획(socket) 과 §8 정의의 대조

`docs/net/PLAN-downlink-injection.md` — socket 이 §8 에 맞춰 썼다. **어긋나지 않는다.**
다만 **판정할 때 반드시 같이 적을 것 넷**:

1. 🔴 **`result=4` 는 실패가 아니라 기대값이다.** 무장하지 않은 `T,S` 는 장치가 거절하고
   **아무 상태도 안 바꾼다** — 그것이 기준선을 안 흔드는 이유다. `result=4` 를 D1/D2 로 세지 마라.
   **D0(도달)의 정의는 "①②③ 이 seq 로 이어졌다"이지 "result 가 0 이다"가 아니다.**
2. 🔴 **socket 의 "ACK 없음 N건" 은 D1+D2 의 합이다.** 그쪽은 ①③만 본다.
   **②(`+IPD`)는 내 시리얼에만 있다.** 그걸 "장치가 못 받았다"로 읽으면 안 된다 — 내가 가른다.
3. **짝짓기는 `seq` + 인스턴스**로 한다. socket 의 `rid`(inj-N)는 주입기 수명 단조 증가라
   **서버가 재기동하면 seq 와 대응이 어긋난다.** rid 는 socket 로그와 대조할 때만 쓴다.
4. 🔴 **주입은 측정 대상을 늘린다** — ACK 하나가 장치 TX 하나이고, 링크 끊김의 유력 기전이
   바로 장치 TX 순간이다. socket 계산으로 5분 주기면 자연 송신 대비 **약 0.4%** 증가다.
   **작지만 0 이 아니다. λ 를 판정하면 이 변수가 창 안에 있었다고 적어라.**

✔ ACK 마감 **30초**는 §8.3 과 같은 값으로 맞췄다(확인).
✔ 첫 주입 **t0+150초** 는 `SERVER_START_GRACE_S=90` 을 넘긴다 — A 의 유일한 1건이
   그 안에서 버려진 것을 피하려는 것이고, 내 `t_start = t0+120s` 와도 어긋나지 않는다.
✔ 독립 기록 `~/parking-logs/downlink-inject.log` 가 있다 — **서버 로그가 잘려도
   "무엇을 언제 넣었는지"가 남는다.** A 에서 잃은 것이 정확히 그 종류였다.
