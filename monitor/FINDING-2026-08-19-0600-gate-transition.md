# 발견 · **차단봉 상태 전이를 잡았다 — "아무도 못 봤다"는 틀렸다** (2026-08-19)

**socket 보고**: *"`05:57:45~05:57:52` occ = `60A` 로 명령 전후 안 변한다. 이미 열려 있었다.
→ **명령이 실제로 상태를 바꾼다는 것은 실물에서 아직 미검증이다.** `close_gate` 를 걸어야 보인다."*

## 1. 🔴 내 창 L 에 **전이가 있다** (`05:44:26`)
```
05:44:24  [TX] S,183,**608**,800,229,P1,37          ← occ = 608
05:44:26  [AT] "+IPD,12:G,3,10,1,44"                ← G 명령 (E1 열기)
05:44:27  [TX] S,185,**60A**,000,231,P1,49          ← 🔑 occ = **60A** — **바뀌었다**
05:44:27  [AT] " S,185,60A,…**A,3,G0,0,35**"        ← ACK `G0` (result=0)
```
```
0x608 = 0110 0000 1000        0x60A = 0110 0000 1010
차이 = 비트 1 (값 2) = **idx 10 = E1**   ← socket 이 말한 그 비트다
```
> ### **명령 → 에코 변화 → ACK 이 한 슬롯 안에서 다 보인다. 실물에서 검증됐다.**
⚠ **`close_gate` 를 걸 필요가 없다** — 이미 자료가 있다. **web 에 그렇게 전해야 한다.**

## 2. 세 건의 갈래가 전부 나온다 (창 L)
```
05:44:26  G,3  → occ 608 → **60A**   **전이 있음** · ACK G0
05:46:46  G,6  → occ 60A → 60A       이미 열림   · ACK G0
05:55:54  G,9  → occ 60A → 60A       이미 열림   · ACK G0
```
🔑 **socket 이 본 `05:57:47` 은 네 번째이고, 셋 다 이미 열린 뒤였다.**
**첫 건에서만 전이가 보이는 것이 당연하다** — **가상 차단봉이 첫 명령에서 자율 토글을 멈추고
열린 상태로 굳기 때문**(arduino 설계). **그 굳는 순간이 `05:44:26` 이다.**

## 3. 🔴 그래서 socket 의 `장치거절 0/1` 을 **"첫 시도"로 읽으면 안 된다**
```
`M = 1` 은 **그 서버 인스턴스가 띄운 수**다 (05:57:12 기동)
실제 `G` 는 그 전에 **최소 3건** 더 있었다 (05:44 · 05:46 · 05:55)
```
> ### **계수기는 프로세스와 함께 0 으로 돌아간다. "처음"이 아니라 "이 인스턴스에서 처음"이다.**
⚠ **오늘 `세션 번호` 에서 같은 것을 겪었다**(socket 서버가 재기동 안 하면 번호가 누적). **분모는 프로세스 수명에 묶인다.**

## 4. ⚠ 부수 관측 — **두 번째 필드도 움직인다**
```
05:44:24  S,183,608,**800**,…        05:44:27  S,185,60A,**000**,…
```
**`occ` 옆 칸이 `800` → `000` 으로 같이 바뀌었다.** ⚠ **내가 그 필드의 정의를 모른다 — 추정하지 않는다.**
**arduino·socket 에 무엇인지 물어야 한다.**

# 5. 🔴 **자진 정정 — "05:44:26 에 굳었다"는 틀렸다. 리셋이 자율을 되살린다**

## 5.1 창 M 실측 — **자율 토글이 계속 돌았다**
```
05:58:30 ~ 06:01:41   occ 가 608 ↔ 609 ↔ 60A ↔ 60B 로 **37회** 바뀐다 (자율 토글)
06:01:44   첫 `G` 명령 (G,6,10,1)
06:01:46   occ 609 → 60B  (그 명령의 결과)
그 뒤 :    **`G` 직후에만 바뀐다** — 자율 토글 정지 ✅
```
> ### **§2 에 쓴 "첫 명령에서 멈추고 그 굳는 순간이 05:44:26" 은 **틀렸다**.**

## 5.2 🔴 왜 되살아났나 — **내 탭이 리셋했다**
```
05:56:56  창 L 탭 종료        05:58:16  **창 M 탭 개방 = DTR 리셋**
05:58:30~ 자율 토글 재개
```
**리셋이 자율을 다시 켠다.** ✅ **arduino 설계("첫 명령에서 영구 정지")는 *전원 주기 안에서* 참이다.**
🔑 **정확한 진술: "첫 `G` 이후 정지. 단 리셋하면 다시 시작한다."**
⚠ **그리고 그 리셋을 만든 것이 나다** — **원장 7.161 의 재판**이다:
**내 탭 개방은 내 로그에 «tap» 줄로 남지만, 남이 보면 "자율이 갑자기 되살아났다"로 보인다.**

## 5.3 ✅ 그 대신 **명령 ↔ 전이 짝이 4쌍 깨끗하게 나온다** (자율 정지 뒤)
```
06:03:35  G,7,10,**0**(닫기)  →  06:03:36  occ 60B → **609**   ✅ 닫는 전이
06:05:19  G,8,10,**1**(열기)  →  06:05:20  occ 609 → **60B**   ✅ 여는 전이
06:05:38  G,11,10,**0**(닫기) →  06:05:40  occ 60B → **609**   ✅
06:07:51  G,12,10,**0**(닫기) →  변화 없음 — **이미 닫힘**      ✅ 멱등
```
> ### **socket 의 닫는 전이 관측(`60B → 609`)을 내 계측기가 독립으로 확인했다.**
🔑 **자율이 도는 동안에는 이 짝짓기가 불가능하다** — 값이 저절로 바뀌므로 **명령 때문인지 알 수 없다.
자율이 멈춘 뒤에야 인과가 보인다.** ⚠ **창 L 의 `608 → 60A`(§1)는 자율 구간이었다 —
**명령과 같은 시각이지만 자율 토글일 수도 있다. §1 의 확신을 낮춘다.**

## 5.4 ✅ `res` 필드 정체 확인 (socket 답변 + 내 실측)
```
S,<seq>,<occ>,<**res**>,<uptime>,<devid>,<ck>     res = **예약 마스크** · occ 와 같은 부호 규칙
06:01:41  res 000 → **800**   (0x800 = 비트 11 = 자리 0 = A1 예약)
06:01:44  res 800 → **000**   (예약 해제)
06:05:35  res 000 → 800  ·  06:05:37  res 800 → 000
```
⚠ **`occ` 와 `res` 가 둘 다 3자리 hex 라 헷갈리기 쉽다.** 🔑 **그리고 이 칸이 자가 치유의 입력이다** —
**hex 전환 뒤 7시간 동안 서버가 못 읽던 그 칸이고, `치유 <재하달>/<검사>` 의 분모가 이것을 읽은 횟수다.**
