## 2. 🔑 가비지 안에 `+I` 가 있다 — **하행이 송신과 UART 에서 충돌한 모양**

```
"AT+CIP\x86+I\x88…"
   ↑ 장치가 쓰던 AT+CIPSEND
          ↑ 들어오던 +IPD 의 머리
```

**시리얼에 깨끗한 `+IPD,` 는 0건이다.** 하행 바이트는 왔지만 **온전한 줄로 안 잡혔다.**

### 서버 쪽이 이 그림을 완성한다

```
07:54:35  →ARD T,3,S,A1,1,59      ← 1차 송신
07:54:37  →ARD T,3,S,A1,1,59      ← 🔑 재전송 (ACK 가 안 오니까)
07:54:39  →ARD T,3,S,A1,1,59      ← 🔑 재전송
07:54:43  세션#6 종료 → 세션#7
07:54:43  = 재연결 판정: **링크 재접속**(장치는 안 죽었다) — uptime 163 → 171
```

**`←ARD A` 는 한 건도 없다.**

⚠ **증폭 고리로 보인다 (추정 · n=1)**: 하행 도착 → UART 충돌 → 프롬프트 놓침 →
ACK 없음 → **서버가 재전송** → 또 충돌 → 3연속 실패.
장치의 실패 시각(:36 · :39 · :40)과 서버 재전송(:35 · :37 · :39)이 맞물린다.
🔴 **단정하지 마라. n=1 이고, 재전송이 원인인지 결과인지 이 자료로 못 가른다.**

## 3. 🔴 socket 주입기의 분류 하나가 **틀렸다** — 내 D 판정을 오염시킨다

주입기 로그:
```
07:54:40  ! 미주입 inj-1 — 서버 거절 code=ack_timeout. 전선에 안 나갔다
```

**"전선에 안 나갔다"가 사실과 다르다.** 서버 로그에 `→ARD T,3` 이 **세 번** 찍혀 있다.

- socket 의 정의: `미주입` = **서버가 전선에 안 내보냄** → **D3(미실행)** 쪽
- 실제: **전선에 나갔고 ACK 만 안 왔다** → **D1/D2** 쪽

🔴 **`ack_timeout` 을 `미주입` 으로 이름 붙이면, 도달 실패가 "시도 안 함"으로 분류된다.**
**도달률 분모(`시도 − 미주입`)에서 실패가 빠져 나가 도달률이 부풀려진다.**
→ socket 에게 알렸다. **`미주입` 은 서버가 전선에 안 내보낸 경우로만 좁혀야 한다.**

### 이 사건의 D 판정

| 칸 | 값 |
|---|---|
| ① 서버 송신 | ✅ 3회(`→ARD T,3`) |
| ② 장치 수신 | ❌ 깨끗한 `+IPD` **0건**(가비지에 `+I` 파편만) |
| ③ 서버 수신 | ❌ `←ARD A` 0건 |

→ **D2 (장치가 못 받음). D3(미실행) 아니다.**
