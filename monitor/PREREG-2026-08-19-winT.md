## 2. 🔴 둘째 검정 — **`hwrst=N/M` 이 "듣는가"를 가른다**
```
N=0, M=0    4단이 **아직 안 왔다**(사다리가 4단에 안 갔다) — **고장 아님**
🔴 N>0, M=0  **실행했는데 안 들었다** → 전원 쪽. 5단(MOSFET)이 필요하다
✅ N>0, M=N  **4단이 듣는다** → ESP 내부 상태 문제였다. 5단 안 사도 된다
⚠ N>0, 0<M<N 일부만 들었다
```
**감시기에 넣었다** — 위 넷을 문장으로 찍고 **분모를 항상 같이 둔다.**
🔑 **`0` 이 혼자 서면 셋을 못 가른다**(안 왔다 / 안 들었다 / 표지 없다).
⚠ `hwrst=N/M` 은 슬래시 꼴이라 **기존 KV 정규식(숫자 하나)으로 안 잡힌다.** 별도 패턴을 넣었다.

## 8. 🔴 `센서갈림` 의 **기준선은 `0` 이 아니라 `3` 이다** (socket 통보 · 15:2x)

```
지금 : **센서갈림 3자리**  ← 🔴 **이것이 정상값이다**(REQ-0270 굽기 전까지)
원인 : 장치 시뮬 지형이 새 자리 배치와 어긋나 있다
       simOcc = A2(idx1) · A3(idx2) · **B4**(idx8)
       자리 A2 : A2=1,B2=0 │ 자리 A3 : A3=1,B3=0 │ 자리 A4 : A4=0,**B4=1**   = **정확히 셋**
```
> ### **그러므로 신호는 `"0 이 아니다"` 가 아니라 🔴 `"3 이 아니다"` 다.**
⚠ **기준선을 안 적으면 `3` 에 고정된 칸이 아무 말도 못 한다** — 내가 그걸 고장으로 읽거나,
반대로 **진짜 변화가 나도 "원래 3이었나 보다"로 흘려보낸다.**
✅ **감시기에 넣었다** — `3` 이면 `(기준선 3 · 정상)`, `>3` 이면 벗어남, `<3` 이면 0270 도입 의심으로 찍는다.

### ✅ 그리고 이 기준선이 **굽기 검증을 공짜로 만든다**
```
REQ-0270(시뮬 지형 정렬)이 칩에 들어가면 **센서갈림 3 → 0**
🔑 **그 전이 자체가 "0270 이 들어갔다"는 표지**다 — 내 `[옛이름]` 꼬리표와 같은 형태다
굽기 뒤에도 3 이면 **안 들어간 것**이고, 그것도 값으로 보인다
```
⚠ **기능 영향은 없다** — `occupied` 를 OR 로 유도하므로 세 자리가 "차 있음"으로 정상 표시된다.
**즉 화면은 맞게 그리고 있고, 갈림은 계수에만 있다.**
