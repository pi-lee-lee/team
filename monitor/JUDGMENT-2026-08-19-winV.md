## 1. ✅ 굽기 도입 — **산출물 표지 셋 전부 통과**
```
[REG] 등록 전송 **143B**(전 145B) · `OBV` **0건** · `D,E1,OB,11`·`D,X1,OB,0C`
[BOOT] 사다리 4단 **미배선** ← `배선됨(A2)` 소멸 = `ESP_RST_WIRED=0`
```
🔴 **`센서갈림` 은 표지로 안 썼다** — **내 감시기가 16:10:53 에 굽기 없이 `3→0` 거짓 표지를 냈다.**
원인은 **점유 비트가 런타임에 움직이는 것**(`60A→609`). 감시기에서 그 표지를 뺐다.
> ### **좋은 표지의 조건: 그 사건 말고 다른 것으로는 만들어질 수 없어야 한다.**

✅ **배경 집계(16:32:51)가 위 값과 정확히 일치했다 — 늦게 나온 축이 없다.**
🔑 **얼릴 때 같은 것을 다 셌기 때문이다.** 창 R·S·U 에서 세 번 겪은 "늦게 오는 축"이 이번엔 없었다.

## 3. 🔴 판정 — **말할 수 있는 것은 하나뿐이다**
```
✅ **파서가 안 죽었다**(`busy p` 0) — **이분값이라 10분 표본으로도 말할 수 있다**
❌ 그 밖 전부 "흔적" — 10분 42초로는 창 T 기준선(41분) 유지 여부를 못 답한다
```
⚠ **끊김은 났다**(`CIFSR 0.0.0.0` 2 · `esprst` 2). **새 기준으로는 정상이다** —
사용자 확정: *"정상 = 끊김 0 이 아니라 **끊겨도 자력 회복**"*(원장 §7.188).

### 🔴 그리고 이 창에서 **자력 복구의 천장이 3단이다**
```
사용자: **"리셋선은 없다"** → `ESP_RST_WIRED=0` → **4·5단 실행 불가**
→ `busy p` 가 0 이 아니게 되면 **3단이 안 먹고, 그 위가 없다. 사람이 개입해야 한다**
```
**이건 결함 보고가 아니라 *현재 하드웨어의 사실* 이다.** 안 적으면 다음 사람이 없는 기능을 고장으로 쫓는다.

# 🔴 정정 (16:4x) — **§2 의 `깨진 나가는 AT 0` 은 틀렸다. 실제 `6 / 417` 이다**

```
❌ 내가 적은 것 : 깨진 나가는 AT **0**
✅ 직접 재계수  : **6 / 417**
   실물 : `AT+CIPMUX=0\x08` · `AT+CIPSEN\x8C=21` · `AT+CIPSEND=22\x18`
```
## 왜 틀렸나 — **내 집계 스크립트의 이스케이프가 뭉개졌다**
얼림 파일을 만들 때 `grep` 을 **heredoc 안**에서 불렀고, `\x` 패턴의 백슬래시가 셸을 거치며 사라져
**아무것도 안 잡고 `0` 을 냈다.** 창 밖에서 직접 치면 6 이 나온다.
> ### 🔴 **`0` 이 그럴듯해서 판정문에 그대로 실렸다. 오늘 이 자리에서만 네 번째다.**
⚠ **처방**: 손상 계수는 **heredoc·subprocess 안에서 세지 않는다. 셸에서 직접 친 값만 쓴다.**

## 🔴 그리고 **내 탐지기에 맹점이 하나 더 있다** (창 W 에서 드러났다)
```
`AT+CIPSEND!24`  ← `=`(0x3D) → `!`(0x21). **둘 다 출력 가능 문자라 `\x` 가 안 붙는다**
→ **내 `\x` 패턴이 이 부류를 통째로 못 본다**
```
**전 창 재검사(출력가능 손상 기준):** 창 T **0/3,470** · 창 V **0/417** · 창 W **1/222**
✅ **창 T 는 두 기준 모두 0 이라 그 판정은 그대로 선다.**
🔴 **창 V 는 `\x` 기준 6 이 있었다** — **이 창을 "UART 깨끗"으로 읽으면 안 된다.**

## ⚠ 그러므로 창 V 판정 §3 을 좁힌다
```
❌ "깨진 나가는 AT 0" 을 근거로 한 어떤 문장도 못 쓴다
✅ 여전히 참 : **`busy p` = 0**(파서 안 죽음) — 그 축은 손상 계수와 무관하다
```
