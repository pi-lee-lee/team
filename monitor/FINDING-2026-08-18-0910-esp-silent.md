## 1. 관측 (부팅 후 105초)
```
[AT] 줄 수            **0**      ← ESP 가 보낸 것을 찍는 줄. 창 C 에서는 초당 여러 줄이었다
System Ready(ESP 배너) **0**
[DIAG] 전 구간         **rx=0 lines=0**
[LADDER] 실패(CWJAP **무응답**) 29s · 연속 2회 → 2단
```
> ### 🔑 **비밀번호가 틀렸다면 ESP 가 `FAIL`/`ERROR` 라도 보낸다. 그것조차 없다.**
> **응답 자체가 없으므로 "에코가 바이너리와 같은가"를 따지는 단계 이전이다.**

**그래서 자격증명 재굽기는 낭비다.** arduino 가 `strings`·`od` 로 확인한
`AT+CWJAP="3F_302","0424719222!!"` 는 **의심 대상이 아니다.**
🔑 **`rx=0` 한 칸이 가설 하나를 통째로 배제했고 굽기 하나를 아꼈다.**

## 2. 소프트웨어로 할 수 있는 것이 없다 (arduino 소스 확인)
```c
client.ino:781  #define ESP_RST_WIRED 0    // 2026-08-15 A2↔ESP RST 를 **물리적으로 분리**
```
→ **사다리 4단(ESP 하드리셋)은 구조적으로 못 간다.** `AT+RST` 도 응답이 없어 무의미하다.
**즉 자동 복구 경로가 없다** — 이것도 확정된 정보다.

## 3. 실물 판별 순서 (arduino → 루트 → 사용자)
```
빨간 꺼짐              → 전원 단
빨간 켜짐·파란 안 깜빡  → 🔴 CH_PD(EN) 또는 UART   ← 가장 유력
둘 다 정상             → 배선 방향/GND
```
🔑 **`CH_PD` 가 HIGH 가 아니면 전원이 있어도 한 바이트도 안 나온다** — 지금 증상과 같다.
**GND 공통이 빠져도 전원 LED 는 켜지고 UART 만 죽는다** — 역시 같은 증상이다.
⚠ `Uno ↔ 기판` 은 **듀폰 점퍼(납땜 아님)** 이고 **포트 이름 변경(`21201`→`1101`)이 USB 재연결의 증거**다.

## 4. 🔑 내 탭이 이 복구의 유일한 기록이다
**사용자 조작이라 사전 통보가 없다.** → **`rx` 가 0 에서 벗어나는 시각이 곧 복구 시각**이고
**어느 조치가 살렸는지를 그 시각이 가른다.**
→ **"한 번에 하나씩 만지고 그때마다 알려 달라"** 를 arduino 가 루트를 통해 사용자에게 요청했다.
🔴 **여러 개를 동시에 고치면 어느 것이 살렸는지 영영 모른다** — 우리가 축 하나로 판정해 온 이유와 같다.
