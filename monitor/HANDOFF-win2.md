## 5. 새 펌웨어가 내는 **새 로그 줄** — 파서에 없으면 조용히 0 이 된다

| 새 줄 | 세는 것 |
|---|---|
| `[TX-WAIT] 앞 전송의 SEND OK 를 아직 못 봤다 — 이번 주기는 건너뛴다` | `skip` |
| `[TX-WAIT] ★ SEND OK 상한 초과 → 대기를 푼다` | `okto` |
| `[CNT] up= drop= esprst= resync= sendfail= okto= skip= online=` (60초 주기) | 누계 |

⚠ **`[CNT]` 는 누적값이다. 구간값으로 읽지 마라**(원장 6.8).
⚠ **`okto` 를 옛 "미도달 0.33%" 와 견주지 마라** — 그 값은 2단계 **없는** 칩에서 나왔고
2단계는 송신 타이밍 자체를 바꾼다. **새 칩에서 기대치를 새로 잡는 것이 첫 일이다.**

### 🔴 `resync_gap.py` 는 이 칩에 **그대로 쓰면 안 된다**

N/P 를 "다음 송신 주기가 `[TX]` 냐 `[TX-RESYNC]` 냐"로 가르는데, 새 칩에는
**셋째 결말 `skip`** 이 있다. 지금 코드는 skip 을 주기 시작으로 인식하지 못해
**그 앵커를 조용히 N 으로 떨어뜨린다.**
→ `[TX-WAIT] … 건너뛴다` 를 세 번째 종류로 넣고 **N / P / S 3칸**으로 늘린 뒤 써라.
→ 그렇게 고치면 **A 와 다른 계측기**다. 같은 표에 넣지 마라.

## 6. 하행 도달 — **4칸으로 센다. 정의는 미리 박아 뒀다**

전체 정의는 `monitor/RECIPE-newbaseline-t0.md` **§8**. 요약:

```
① 서버 송신   →ARD T,<seq>,S,…        (parking-server.log)
② 장치 수신   [AT] "+IPD,<n>:T,<seq>,…" (serial-win2.log)   🔑 여기가 핵심
③ 서버 수신   ←ARD A,<seq>,…          (parking-server.log)
```

| 칸 | 조건 |
|---|---|
| **D0 도달** | ①②③ 이 seq 일치로 모두 있음 |
| **D1 받았는데 응답 없음** | ①② 있고 ③ 없음 |
| **D2 못 받음** | ① 있고 ②③ 없음 |
| **D3 미실행** | ①이 없음 — **측정 안 됨. 건강이 아니다** |

- 🔴 **`result=4` 는 실패가 아니라 기대값이다.** 무장 안 한 `T,S` 는 장치가 거절하고
  **아무 상태도 안 바꾼다** — 그래서 기준선을 안 흔든다. **D1/D2 로 세지 마라.**
- 🔴 **socket 의 `미주입`(서버가 장치 오프라인이라 전선에 안 내보냄)은 D3 쪽이다.**
  **도달률 분모 = 시도 − 미주입.** (socket 이 배포 직전에 이 결함을 잡았다 — 안 잡았으면
  보드가 안 붙은 오늘 밤에 **없는 하행 고장 96건**이 판정문에 박혔다.)
- 🔴 **socket 의 "응답 없음 N건" 은 D1+D2 의 합이다.** 그쪽은 ①③만 본다.
  **②는 내 시리얼에만 있다.** "장치가 못 받았다"로 읽지 마라.
- 짝짓기는 **`seq` + 인스턴스**. socket 의 `rid`(inj-N)는 주입기 수명 단조 증가라
  **서버가 재기동하면 seq 와 대응이 어긋난다.** rid 는 socket 로그 대조용으로만.
- 독립 기록: `~/parking-logs/downlink-inject.log` — **서버 로그가 잘려도 무엇을 언제
  넣었는지 남는다.** A 에서 잃은 것이 정확히 그 종류다.

4. **창을 닫으면 서버 `INSTANCE-END` 줄과 대조하라** (A 에서 값졌다 · 판정문 §12):
   `stop=` · `sessions=` · `frames=`.
   🔴 **`frames=` 는 S 프레임 수가 아니라 상행 전체(S+A)다**(원장 7.15).
