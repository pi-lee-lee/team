## 3. ①에 대한 답 — **"온다/안 온다" 이분법이 안 맞는다**

요청서의 틀:
> **온다** → ESP 는 살아서 전송 중 → **기다리는 것이 옳고 상한을 올려야 한다**
> **끝내 안 온다** → ESP 가 죽었거나 명령이 삼켜짐 → **올리면 손해만 본다**

**측정 결과는 셋이다.**

| 경우 | 건수 | ESP 는 살아 있었나 |
|---|---|---|
| ① 온다 (Δ 2~3s) | 20 | **살아 있었다** |
| ② 안 온다 · `busy` 없음 | 6 | 모듈 리셋 계열 — 죽었다고 볼 근거 있음 |
| ③ **안 온다 · 그런데 `busy` 로 답했다** | **4** | 🔴 **살아 있었는데 `SEND OK` 는 끝내 안 왔다** |

### ③이 요청서의 이분법을 깬다 — 원문을 열어 확인했다

```
20:54:02  [TX] S,12384,…              ← 앵커. 페이로드를 실제로 썼다
20:54:02  [AT] "AT+CIPSEND=42"
20:54:03  [TX-RESYNC] 프롬프트 놓침    ← 1초 뒤. 실패 1/3
20:54:03  [NET] 전송 실패 1/3
20:54:03  [AT] "busy s..."             ← 🔑 ESP 가 살아서 "지금 전송 중" 이라고 답한다
20:54:03  [AT] "\xA6,12384,…,39AT+CIPSEND=42" (54)   ← 앵커의 페이로드가 늦게 메아리쳤다
20:54:05  [TX-RESYNC] · 실패 2/3 · busy
20:54:06  [TX-RESYNC] · 실패 3/3 → 오프라인 전환
                                       ← `SEND OK` 는 끝내 없었다
```

**ESP 는 살아 있었고(`busy` 로 답했고), 앵커의 페이로드를 받았음을 메아리로 보였는데,
그 전송의 `SEND OK` 는 오지 않았다.** ①의 "온다 → 기다리면 된다"도,
"안 온다 → 죽었다"도 이 4건을 설명하지 못한다.

**판단은 네 영역이다.** 나는 여기까지만 말할 수 있다.

## 4. 🔴 그리고 이것을 봐라 — **P 의 방아쇠가 `SEND OK` 대기가 아니다**

원문 둘을 열어 확인한 것이다(`18:03:21` · `20:54:02` · `18:24:50` 동일 모양):

```
T+0s   [TX] …              앵커 (페이로드 씀)
T+0s   [AT] "AT+CIPSEND=…"
T+1~2s [TX-RESYNC] 프롬프트 놓침   ← 🔴 실패 카운터를 올린 것은 **이 줄**이다
T+1~2s [NET] 전송 실패 1/3
```

**실패 1/3 을 만든 것은 `SEND OK` 를 못 받은 것이 아니라 다음 주기에서 `>` 프롬프트를
못 받은 것이다.** 3진아웃까지 4~5초인데, 그 4~5초는 **프롬프트 놓침 3회**로 채워진다.

→ **`SEND_OK_TIMEOUT_MS` 를 올리는 것이 이 경로를 바꾸는지 나는 모른다.**
   펌웨어에서 프롬프트 대기와 `SEND OK` 대기가 같은 타이머인지 다른 타이머인지는
   **네 소스의 문제**다. 내가 관측한 것은 **로그에 찍힌 방아쇠가 프롬프트 놓침**이라는 것뿐이다.

⚠ 이 관측은 루트가 `RESUME §7.1` 에 적은
   *"2단계는 관측된 자해 두 건을 못 막는다"* 와 **같은 방향**이다.

## 7. ⚠ 내 도구의 결함 하나를 스스로 잡았다 — 공개한다

첫 판에서 **pre-A 의 N 최대값이 `Δ=9s`(앵커 `17:06:42`)** 로 나왔다. 이상해서 원문을 열었다:

```
17:06:42  [TX] S,350,…
17:06:43  [AT] "ERROR"           ← 링크가 죽었다
17:06:43  [AT] "Unlink"
17:06:43  [DIAG] offline step=3  ← 회복 사다리가 돈다
…  (9초 뒤 새 연결에서 SEND OK)
```

**"정상 송신이 9초 걸린 것"이 아니라 "링크가 죽고 사다리가 돈 9초"였다.**
3진아웃을 거치지 않아 링크붕괴 표지에 안 걸렸고, 다음 주기가 `[TX]` 라서 N 으로 떨어졌다.

→ 표지에 `[DIAG] offline step=` 을 더했다. 다시 돌리니 그 건은 `링크붕괴먼저` 로 가고
   **pre-A 의 N 최대는 2s** 가 됐다 — A(2s)와 일치한다.
→ **A 구간의 결론은 이 정정으로 바뀌지 않았다**(A 의 N 최대 2s 는 원문 확인 결과 깨끗하다).
