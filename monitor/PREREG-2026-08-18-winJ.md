🔴 **자료 전에 쓴다.** 캡처는 아직 시작하지 않았다. **실행 기록칸은 측정 후에만 채운다.**

## 0. 🔴 이 창은 **장치만 바뀐 창이 아니다** — 축 넷
```
21:06:38  socket 서버 교체 — `D`/`Q` 등록 파서 · 요약줄 칸 추가        ← 서버 축
21:11:49  arduino 굽기 (커밋 def8093) — ① hex 인코딩 ② D 등록+Q ③ 모듈 표   ← 장치 축 셋
```
**판정문에 반드시 넷을 갈라 적고, 내 계측기로 못 가르는 것은 "귀속 불가"로 쓴다.**

## 1. 축 분담 (굽기 **전에** 정했다 — 창 I 에서는 사후에 알았다)
| 축 | 누가 가르나 |
|---|---|
| **hex 인코딩** | ✅ **내 시리얼** — `S` 프레임 크기 · `≥64B` 진입률 |
| **D 등록 + Q** | ✅ **socket 서버 로그** — `등록 완료/형식오류/질의/포기/폭불일치` |
| | ⚠ **간접 실기 표지 하나**: `D` 줄 수 = `moduleCount()` (arduino 제공) |
| **모듈 표** | 🔴 **표지 없음 → 내 관측 밖.** arduino 의 바이트 대조는 **호스트 시험이지 실기 관측이 아니다** |

## 2. 🔴 분모 규칙 — **`0` 을 읽기 전에 분모부터**
```
pendfill = 0  →  `penddrop=0` 은 **아무 뜻도 없다**(그 경로가 안 돌았다)
pendfill > 0  →  넘침률 = penddrop / (pendfill + penddrop)
bigfill = 0   →  `bigdrop`·`bigokst` 도 같은 뜻이다
```
🔑 **창 I 에서 `penddrop=0` 을 "발동 안 함"인지 "분모 0"인지 못 갈라 판정 불가로 남겼다. 이번에 열린다.**
🔑 **불변식 검사(arduino 요청)**: `pendfill ≥ bigfill` · `penddrop ≥ bigdrop`. **깨지면 펌웨어 이상.**
❌ **`okstream` 은 판정에 쓰지 않는다** — 바이트 매처가 줄 완성 **전**에 발화해 **항상 이기므로**
탐지 총수이지 구조된 수가 아니다. **`oklost`/`bigoklost` 가 그 자리다.**

```
   🔴 `등록 완료 ≥ 1` 을 **먼저** 확인한다. 안 찍히면 "파서가 안 돎"과 "등록 안 됨"이 구분 안 된다
```

## 6. 🔴 **자극 전 공동 등록 — socket 의 ACK 모델을 내 창 I 실측으로 검증했다**

**socket 등록**(자료 전): *"ACK 줄은 hex 와 무관하다(비트열이 아니다). 13B + LF.
창 J 는 `S 22B` + 4ACK = **74B** → 여전히 `≥64B`. **문턱을 넘는 데 필요한 ACK 수가 2 → 4 로 오른다**"*

### 6.1 내 창 I 실측 — **ACK 비용은 고정 13B 가 아니다. 자란다**
```
ack=0  n=283  tx= 39          (기준 S)
ack=1  n= 33  tx= 52   → 13.0B/건
ack=2  n=147  tx= 67   → 14.0B/건
ack=3  n=124  tx= 82   → 14.3B/건
ack=4  n=785  tx= 97   → **14.5B/건**
ack=5  n=  7  tx=113   → 14.8B/건
```
🔑 **원인은 `rid` 자릿수다** — `A,57,B1,4,04`(12자) 대 `A,1017,B1,4,04`(14자). **창이 길어질수록 커진다.**
⚠ **그래서 창 초반과 후반의 같은 `ack=4` 가 다른 바이트 수다.** 내가 앞서 `90·94B` 를 인용한 것도
**창 초반 값**이고 **창 전체 중앙값은 97** 이다 — **같은 창 안에서도 시간 의존이 있다.**

### 6.2 🔮 그래서 예측을 **socket 보다 한 칸 낮춘다**
```
창 J 기준 S = **21B**(실측) · CIPSEND = tx+1
  ack=1 → 35        ack=2 → 48
  ack=3 → **61~66**  ← 🔴 **경계 위다. rid 가 자라면 넘는다**
  ack=4 → **74~80**  ← ≥64 확실
```
> ### 🔮 **내 예측: 문턱을 넘는 ACK 수는 `4` 가 아니라 `3~4` 이고, *창 후반으로 갈수록 3 으로 내려간다*.**
> **socket 의 `4` 는 `rid` 가 작을 때만 참이다.**

**반증 조건**
```
❌ 창 J 에서 `ack=3` 이 끝까지 `CIPSEND < 64` 면  → 내 예측이 틀렸고 socket 의 13B 고정이 맞다
❌ 진입률이 **0** 이면 → 둘 다 틀렸다(ACK 가 hex 와 무관하다는 전제가 깨진 것)
```
🔑 **이건 "hex 의 이득이 얼마인가"가 아니라 "그 이득이 시간에 따라 줄어드는가"를 묻는다.**
**`rid` 가 계속 자라면 이득은 창이 길어질수록 잠식된다** — **그게 참이면 다음 손잡이는 `rid` 폭이다.**
