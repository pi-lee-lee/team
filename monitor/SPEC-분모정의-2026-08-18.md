# 분모 정의 — **창 G / 창 H 를 같은 규칙으로 세기 위한 확정본** (2026-08-18 · monitor)

🔴 **판정 분모는 이 문서의 정의 하나만 쓴다.** 루트 확인 요청 · arduino 합의
(*"판정 분모는 monitor 가 창 H 에서 창 G 와 같은 규칙으로 다시 낸 값 하나만 쓴다"*).

## 1. 🔴 세 배 차이가 났던 이유 — **둘 다 내 숫자이고 둘 다 맞다. 세는 것이 다르다**
```
[SLOT] tx>=48B   75건   ← **줄** 을 센다. T2 대기 중 `r=0` 슬롯도 같은 tx= 를 계속 찍는다
CIPSEND >=48B    19건   ← **실제 나간 전송 시도** 를 센다
```
> ### **약 4배 차이이고, 고장이 심할수록 격차가 커진다**(건너뛴 슬롯이 늘기 때문).
> ### 🔴 **고장이 분모를 키우는 방향의 편향이라 특히 위험하다.**

## 2. ✅ 확정 — **분모는 `CIPSEND 거래` 다**
```
분모 1건 = 로그에 `[AT] "AT+CIPSEND=<n>"` 이 한 번 찍힌 것
크기     = 그 줄의 <n>  (CIPSEND 가 선언한 바이트 수. `[SLOT] tx=` 가 아니다)
```
⚠ **`[SLOT] tx=` 는 분모로 쓰지 않는다.** 참고 지표로만 낸다.
⚠ **`<n>` 과 `[SLOT] tx=` 는 보통 1 차이다**(`tx=37` ↔ `CIPSEND=38`). **대역 경계에서 어긋난다** —
**대역은 항상 `CIPSEND` 의 `<n>` 으로 자른다.**

## 3. ✅ 크기 대역 — **문턱은 64B 다. `48B` 는 쓰지 않는다**
```
<48   ·   48~63   ·   >=64        ← 세 대역으로 낸다
```
🔴 **`>=48B` 를 판정 기준으로 쓰지 마라.** 그것은 **표본이 모였나**를 보는 추출 기준이었고,
**기전 경계는 `>=64`** 다(`_SS_MAX_RX_BUFF`, arduino). 창 G 실측:
```
<48  748거래 → T2 1 (0.1%)   ·   48~63  43거래 → T2 0 (0.0%)   ·   >=64  34거래 → T2 9 (26.5%)
```

## 4. ✅ 결과 지표 — **`T2` 다. `SEND OK 유무` 가 아니다**
```
성공/실패 = 그 거래 뒤 12초 안에 `[TX-WAIT] ★★ T2 초과` 가 났는가
```
🔴 **`SEND OK` 유무로 세면 틀린다** — 뒤집힌 거래에서는 `SEND OK` 가 `AT+CIPSEND` 줄보다
**먼저** 찍혀 "그 줄 이후" 검사에 안 잡힌다(실제로 `48~63` 이 32.6% 로 잘못 나왔다).
⚠ **관측 대상이 순서를 어기는 것이 우리가 쫓는 현상이므로, 순서를 전제한 파서는 반드시 틀린다.**

## 5. ✅ 구간 경계
```
창 t0        탭 개방 DTR 리셋 시각 (로그 첫 줄) — **서버 t0 와 다른 시계다**
주입 구간    socket 이 통보한 시작·종료 시각 (초 단위) 으로 자른다
자극 전/후   주입 구간 밖. **자극 부재 구간과 주입 구간을 같은 분모로 묶지 않는다**
```
⚠ **판정은 주입 구간에서만 한다.** 자극 없는 구간의 `T2 0` 은 **자극 부재**이지 건강이 아니다.

## 6. 창 G 확정값 (창 H 는 이 표와 같은 칸으로 낸다)
```
구간        CIPSEND거래   <48        48~63      >=64        T2
자극전       321         318         3          0          1
1차 주입      16           2         0         14          1
2차 주입      54          35         0         19          8
자극후       118         118         0          0          0
판별시험      81          41        40          0          0
```
🔑 **창 H 비교는 `>=64` 칸의 `거래수`와 `T2 비율`로 한다.** 창 G 의 `>=64` 는 **34거래 · T2 9 (26.5%)** 다.
⚠ **총 주입 건수는 비교하지 마라** — 감독기가 정지 뒤 라운드를 다시 열어
**장치가 나쁠수록 총 주입이 는다. 인과가 거꾸로 읽힌다**(socket).
