# 사전 등록 · 창 I — **새 망에서 수정이 유지되는가** (2026-08-18)

🔴 **이 문서는 자료를 보기 전에 쓴다.** 창 I 의 캡처는 아직 시작하지 않았다.
⚠ **실행 기록칸은 비워 둔다** — 창 G 에서 **재지 않은 t0 를 미리 적는 실수**를 했다(7.x 취소선 참조).
**측정한 뒤에만 채운다.**

## 0. 답할 질문 하나
> **창 H 의 `>=64B` 1,025거래 → T2 0건이 *새 망* 에서도 성립하는가.**

## 1. 규칙 — 창 G/H 와 같게
```
분모   monitor/SPEC-분모정의-2026-08-18.md 확정본 (CIPSEND 거래 · [SLOT] 줄이 아니다)
대역   <48 · 48~63 · >=64        판정선  T2 계수
같이   okstream · penddrop · resync · ssovf · cksumng · stuck
```
🔴 **"그 밖" 칸을 둔다** — `정상 / 뒤집힘 / 에코실종·지연` **세 갈래 합계가 원시 `★★ T2` 계수와 맞는지**
대조한다. **창 G 에서 이 검산이 분모 누락 57건을 잡았다**(원장 7.125).

## 2. 예측 (반증 조건을 같이 적는다)
| # | 예측 | 반증 |
|---|---|---|
| **P1** | `>=64B` 대역 T2 **0건** | **1건이라도 나면** 수정이 새 망에서 완전하지 않다 |
| **P2** | `penddrop > 0` (부하가 걸리면) | `penddrop=0` 이면 **버릴 줄이 안 생긴 것** = 자극 부족을 의심 |
| **P3** | `resync` 비율이 창 H 수준(3/2340) 이하 | 크게 오르면 `PROMPT_TIMEOUT` 갈래가 새 망에서 산다 |
| **P4** | `cksumng` / 하행도착 ≈ **2.17%** (창 H 값) | 크게 낮으면 **창 H 특유**였다는 뜻 ← 🔑 **창 H 미결을 닫는 항목** |
| **P5** | 세 갈래 T2 합계 = 원시 T2 계수 | 어긋나면 **내 도구가 또 분류를 흘리고 있다** |

⚠ **P1 이 참이어도 "고쳐졌다"의 재확인일 뿐이다.** 🔴 **`T2=0` 은 `>=64B` 표본이 찼을 때만 뜻이 있다.**

## 3. 🔴 정지·판정 조건 — 도구가 본다
```
① >=64B 거래 >= 30건    → P1 판정 가능 (창 G 가 34건이었다. 그 자릿수를 맞춘다)
② 하행 도착 >= 500줄    → P4 판정 가능 (창 H 는 약 3,923줄이었다)
③ 위가 안 차면          → **"판정 불가"** 라고 쓴다. 억지로 결론 내지 않는다
```
`monitor/sendok_order.py` 가 ①의 분모를 찍는다. ②는 `+IPD`·후속 하행줄로 센다.
