## 0. 5분 구간표 — **창 R 과 같은 형식** (그래야 모양을 견준다)
```
구간        S프레임   T2   손상AT          │  (참고) 옛 기판 창 R
 +0~ 5분     227      0     **0**          │   172   1   0
 +5~10분     247      0     **0**          │   204   1   0
+10~15분     246      0     **0**          │   198   1   0
+15~20분     167      0     **0**   ←🔴    │    97   4   **7**  ← 옛 기판은 여기서 무너졌다
+20~25분      14      1     **0**   ←🔴    │   150   4   7
그 뒤          0      -      -             │   119   5   1
```
⚠ **옛 기판 열은 참고다. 크기 비교가 아니다**(다른 기판 · 다른 조건). **보는 것은 "손상 AT 가 켜지는가"뿐이다.**

## 1. ✅ 축 ① — **기전 A(UART 손상)가 이 창에서 `0` 이다**
```
🔴 깨진 **나가는** AT 명령 : **0**    (옛 기판 창 R: **14**)
   상행에 AT 혼재         : **0**    (옛 기판: **14**)
   이스케이프 포함 줄      : **4**    (옛 기판: **41**)
   T2                     : **1**    (옛 기판: **17**)
```
> ### **옛 기판이 `+15분` 에 7건을 냈던 자리에서 창 S 는 `0` 이다. 판별자가 갈렸다.**
🔴 **그러나 "기판 불량이 원인이었다"는 안 쓴다.** 교체와 동시에 **USB 재삽입·전원 재투입**이 일어났다 —
**교락이다.** 참인 것은 **"이 창에서 기전 A 가 0"** 까지다.
🔑 §*"내 것이 아니다를 증명해도 저것이다는 안 따라온다"*.

## 2. 🔴 축 ② — **그런데 무너졌다. 이번엔 결합/IP 상실이다**
```
`CIFSR → "0.0.0.0"` **24회**(최종 · 개입 구간 포함) · 유효 구간 기준 **22회**   ← 내 원장의 **1차 판별자**(정상 부팅에는 안 뜬다)
CWJAP OK 6 · T2 1 · +20분부터 S프레임 14 → 그 뒤 **0**
14:05:56  [DIAG] offline **사다리=5/254** · up=2683s   ← 약 20분째 미복구
```
> ### **기전 A 는 사라지고 기전 B 가 남았다. 두 창이 서로 다른 층에서 무너졌다.**
```
창 R(옛 기판) : 결합은 분 단위로 섰다(단0 46~447초) · **UART 가 깨졌다** → 기전 A
창 S(새 기판) : **UART 는 깨끗하다(0)** · **결합이 상실됐다**              → 기전 B
```
⚠ **이 대조는 값의 크기 비교가 아니라 *어느 계수가 켜지고 꺼지는가* 다.** 이분값이라 표본이 작아도 말할 수 있다.

## 2.1 🔴 **결합유지가 `1084초`였다 — 고장의 *모양* 이 창 R 과 다르다** (배경 집계 · 늦게 나왔다)
```
✅ 단0(깨끗) : **1084s = 18분 4초**  ← 비영 표본이 **이것 하나**다
⚠ 단1~5     : 5·6·9·10·10·12·13·25·28s · "없음" ×290   ← 붕괴 뒤의 값들
```
```
창 R(옛 기판) : 단0 **46~447초 · n=10**   → **끊기고 붙기를 반복**했다
창 S(새 기판) : 단0 **1084초 · n=1**      → **오래 붙어 있다가 한 번 무너지고 끝났다**
```
> ### **같은 "무너짐"이 아니다. 창 R 은 반복 단절, 창 S 는 *한 번의 종국적 붕괴* 다.**
🔑 **5분 구간표와 맞는다** — `+15~20분`까지 프레임이 정상(167~247)이다가 `+20분`에 14로 떨어지고 그 뒤 0.
**18분 유지 → 붕괴 → 289회 사다리 천장 → 미복구.**
⚠ **크기 비교가 아니다**(다른 기판·다른 조건). **모양의 대조**이고, 비영 표본이 각각 10개와 1개다.

## 3. 🔴 축 ③ — **자력 복구 경로가 없다** (구조 · 값으로 확인)
```
사다리 단 분포 : 0단 1 · 1단 2 · 2단 2 · 3단 2 · 4단 2 · **5단 289**
DIAG          : `사다리=5/254`  → **5단(천장)에 254회 누적**
```
**4단(하드웨어 리셋) 미실행**(`ESP_RST_WIRED=0`) · **5단(전원 재투입) 미구현**(부품 미보유)
→ **실질 조치의 마지막은 3단 `AT+RST` 이고, 그 위는 60초 백오프로 같은 것을 반복할 뿐이다.**
> ### **장치는 스스로 이 상태에서 못 빠져나온다.**

### ⚠ 루트의 숫자 하나를 정정한다
루트가 *"3단이 천장이다"* 라고 했는데 **DIAG 의 `step=3` 은 사다리 단이 아니라 `netStep`(다른 상태 기계)이다.**
**사다리는 `사다리=5/254` 로 5단**이다. **결론(자력 복구 없음)은 그대로 서고 숫자만 다르다.**

## 4. ✅ 루트가 물은 것 ① — **`화면` 정의**
```
`화면 N(최대 M)` = **`:9900` 의 WS 클라이언트 수**다. **모듈 수도, 끊김 표시 수도 아니다.**
```
**근거(내 창 O 판정 §5 · 검정 통과)**: 주입기 8개를 붙이자 `1 → 9`, 주입을 끝내자 `9 → 1`.
**8 = 주입기 수**로 정확히 맞았다.
> ### **그러므로 `화면 3~4` 는 "브라우저 탭이 3~4개 붙어 있다"는 뜻이고 링크 상태와 무관하다.**
✅ **루트의 우려(*"링크 멀쩡한 구간에도 3이면 별개 결함"*)는 성립하지 않는다.** 그 값은 원래 링크를 안 본다.
⚠ **이름이 `화면` 이라 "화면에 뭐가 표시됐다"로 읽힌다** — §*"배너는 선언이고 값은 결과다"* 와 같은 자리다.

## 5. ✅ 루트가 물은 것 ② — **축②가 축③ 없이 나았을지는 못 답한다**
**사다리가 5단(실질 3단)에 막혀 있어서 "더 강한 조치로 복구됐을 것"을 관측할 방법이 없다.**
> ### **미상으로 둔다. 대체 주장을 세우지 않는다.**

### 🔴 그리고 **미상이 확정됐다** — 손 RST-만 시험은 **안 왔다** (14:0x)
```
14:06:0x  사용자가 **ESP01 전원만** 재투입 (아두이노 up 은 안 끊겼다: 2700→2769s)
14:07:19  SEND OK 재개 — **복구됨**
14:07:43  사용자가 **아두이노도 리셋** (up=3s · 사다리=0/0)
```
**손 RST 만 떨어뜨리는 판별 시험은 하지 않았고 전원을 뺐다.**
> ### **그러므로 "HW 리셋만으로 풀렸을까"는 이 창에서 *영영* 못 답한다. 미상 확정이다.**
🔑 **`ESP_RST_WIRED` 를 1 로 켜는 굽기가 다음 발생 때 그 답을 자동으로 준다** — 그때 4단이 실제로 밟힌다.
🔑 **이건 §"감시할 수 없는 것은 조건으로 적지 마라"의 복구 판본이다** — **밟히지 않는 경로의 결과는 못 센다.**
