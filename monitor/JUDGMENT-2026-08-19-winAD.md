> # 🔴 항목별 ✅/❌ 다. 비율 창이 아니다
> ### **각본별 표본 `n=1`.** 자극이 12초 × 6단계 ≈ 72초뿐이다


## 🔴 ㉠ 4건 묶음 — ✅ **진짜 묶음. 연발이 아니다**

### 판정자는 시각이 아니라 **구조** 였다 — `+IPD` 헤더 수
```
22:42:32  [AT] "+IPD,**64**:G,468,2,1,7E" (20)   ← 🔴 헤더는 여기 **한 번만**
22:42:32  [G] idx=2 arg=1
22:42:32  [AT] "G,469,3,1234567,7F" (18)          ← 🔑 **+IPD 헤더 없이** 이어진다
22:42:32  [LC] 1234567
22:42:32  [G] idx=3 arg=1234567
22:42:32  [AT] "G,470,4,1,71" (12)                ← 없다
22:42:32  [DR] arg=1
22:42:32  [G] idx=4 arg=1
22:42:32  [AT] "G,471,5,7654321,70" (18)          ← 없다
```
> ### **ESP 가 64B 를 *한 `+IPD`* 로 넘겼고, 장치 줄 조립기가 네 줄로 쪼갠 것이다.**
> ### **연발이면 헤더가 네 번 나온다. 한 번이다.**
```
`G,` 담은 `+IPD` **1건** · 그 안의 `G,` **넷** · `[G]` **4/4** · rid **468~471**
전체 `+IPD` 도 **1건** — 등록 국면이 안 섞였다(socket 의 4초 지연이 들었다)
```

### ✅ 🔴 바이트가 **세 계측기에서 맞았다**
```
서버 : socket 의 `send_raw` **64B 한 호출**            (소켓 계층)
ESP  : `+IPD,**64**:` 헤더 선언값                       (AT 파서 계층)
나   : 12+18+12+18 = 60B + 개행 4 = **64B**             (문자를 셈)
```
> ### **셋이 독립으로 같은 수를 말한다. 맹점을 공유하지 않는 세 각도다.**
🔑 **socket 이 답할 수 있었던 것은 *"한 `write` 였다"* 까지였고,
*"한 조각으로 도착했다"* 는 `+IPD` 헤더 하나가 답했다.**
**두 명제를 갈라 놓은 것이 이 판정을 만들었다** — 한쪽만으로는 못 말한다.

## ✅ 곁들여 — **ACK 도 한 거래로 나갔다** (예상 밖 소득)
```
22:42:34  [AT] "AT+CIPSEND=76"
` S,68,0F,00,94,P1,47**A,468,G2,0,3E A,469,G3,0,3E A,470,G4,0,31 A,471,G5,0,31**`
→ 하행 묶음 4건에 **상행 ACK 넷이 `S` 프레임과 한 CIPSEND 로** 묶여 나갔다
```
**왕복이 각각 1회다.** `ackQ` 배치가 하행 묶음과 **대칭으로** 맞아떨어졌다.
🔑 arduino 가 *"`sendAck` 은 보낸 게 아니라 담은 것"* 이라고 한 설계가 여기서 값을 냈다 —
**즉시 보냈으면 ACK 넷이 수신 창을 네 번 깼을 것이다.**

## 🔴 판별식 셋 — **어느 갈래도 안 갔다. 그런데 그것이 "안전하다"는 뜻은 아니다**
```
`[G]` **4/4** · `penddrop` **0 / pendfill 41**
→ ① 묶음 손실 아님 · ② 멱등 재수신 아님 · ③ 새 결함 아님
```
> ### ⚠ **`n=1` 이다. "묶음 손실이 없다"로 쓰지 않는다.**
> ### **송신 창과 안 겹쳤을 뿐일 수 있고, 그 위험은 그대로 남아 있다.**
🔑 **arduino·socket 실측**: 겹치면 **4건 중 3건이 사라진다**(penddrop=3, 1건 생존).
**확률은 그대로고 손실 크기만 N배다.** **이번에 안 났다고 그 기전이 사라진 것이 아니다.**
