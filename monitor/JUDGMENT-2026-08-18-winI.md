# 9. 🔴 **자진 정정 — "바이트 손상이 아니라 줄 조립 실패"는 틀렸다. 둘 다 있다**

socket 이 *"네 4,017 과 내 4,074 가 같은 규칙으로 세어졌는가"* 를 물어 **정의를 맞추다가 나왔다.**

## 9.1 내 "도착 줄" 의 정의 (확인함)
```
+IPD 줄 1,097  +  [AT] "T/M,…" 줄 2,920  =  4,017
```
✅ **`[CKSUM NG]` 건도 이 안에 들어 있다** — 원문에서 **먼저 `[AT] "T,43,…"` 으로 찍히고
그 다음 줄에 `[CKSUM NG]` 이 따로 찍힌다**(같은 도착의 진단 줄이지 별개 도착이 아니다).
**빠뜨리지도, 중복 세지도 않았다.**

## 9.2 `CKSUM NG` 150건 분해 — **`S,<슬롯>` 출현 수로 센다**
```
C 잘림(레코드 1개)        57   예: T,107,S,A2,1
D 레코드 0 — 조각         52   예: **T,1017,S,A,1,69**      ← 🔴 슬롯명이 `A1` 이 아니라 `A`
A 하행 2줄이 붙음         29   예: T,31,S,B1,1,6B,32,S,B2,1,6B
B 우리 CIPSEND 에코와 붙음 12   예: T,43,S,A3,1,AT+CIPSEND=62
```

## 9.3 🔴 정정: **D 52건은 바이트가 빠진 것이다**
`T,1017,S,**A**,1,69` — 슬롯명 `A1` 에서 **문자 하나가 사라졌다.** 줄 경계 문제가 아니다.
> ### **내가 창 H·창 I 에서 "바이트 손상이 아니라 줄 조립 실패"라고 두 번 적었다. 좁힌다:**
> ### **줄 조립 실패(A·B·C)와 바이트 탈락(D)이 *둘 다* 있고, 대략 2:1 이다.**

## 9.4 ⚠ 57 이 두 번 나오지만 **연결하지 않는다**
```
socket 전선 4,074 − 내 도착 4,017 = **57**       C 잘림 = **57**
```
**같은 수가 나왔지만 기전을 잇지 못했다.** 병합(A)이 29건이니 **줄 손실 예측은 29** 이지 57 이 아니다.
🔴 **수가 맞는 것은 근거가 아니다**(오늘 8.4초·8.3초에서 이미 겪었다). **일치는 기록하되 인과로 쓰지 않는다.**

## 9.5 socket 의 "통째로 사라진 배치가 없다" 는 성립한다
**배치 1,097 = 1,097 로 정확히 맞는다** → **링크 수준 유실이 아니라 배치 *안의* 손상**이다.
✅ **그 진술은 내 분해와 어긋나지 않는다** — A·B·C·D 전부 배치 안에서 일어난다.
