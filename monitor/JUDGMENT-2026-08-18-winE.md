## 0. 🔑 **파괴가 사라졌다 — 그리고 분모가 있다**

```
                    창 D(전 · cntTick 옛것)      **창 E(후 · 슬롯에 묶음)**
[CKSUM NG]          **3건**(전부 [CNT] 정합)      **0건**
하행 도착(내 OOW)   294                          **256**(10.5분 시점 · 계속 증가 중)
[CNT] cksumng       3                            **0**
```
> ### 🔴 **`0` 이지만 "자극 없어서 0" 이 아니다.** 하행이 **256건 도착**했고 `[CNT] oow=240` 이다.
> **사전 등록한 그 조건**(*"파괴 0 이면 분모를 같이 찍어 가른다"*)을 **충족한 0** 이다.

**판정선 재확인**: 등록한 것은 *"`[CKSUM NG]` 시각이 `[CNT]` 와 더 이상 정합하지 않는가"* 였다.
**정합을 논할 사건 자체가 없다** → **더 강한 결과다.**

## 1. 다른 칸도 전부 0 이 됐다 — 이것이 더 놀랍다
```
창 D 주입 구간 : skip=21 · ssovf 2→8 · okto 4~5 · smiss=2 · esprst=3 · drop=4 · stuck=2
창 E 10.5분    : **skip=0 · ssovf=0 · okto=0 · smiss=0 · esprst=0 · drop=0 · stuck=0** · online=1
```
🔑 **`skip`(게이트 양보)과 `ssovf`(링버퍼 넘침)가 0 이다.** `[CNT]` 출력이 송신 창으로 옮겨지면서
**수신 구간을 막지 않게 된 결과**로 보인다 — ⚠ **가설이다.** `ssovf` 는 원인이 셋으로 갈려 있었고
(주입 계열 · 재접속 폭풍 · 미상) **이번 0 은 그중 어느 것이 사라졌는지까지는 말하지 않는다.**

⚠ **`esprst`/`drop` 이 0 인 것은 이 창의 유휴가 짧아서일 수 있다**(창 D 는 유휴 46분에 이미 3·4 였다).
**같은 길이로 재기 전에는 "링크가 더 안정해졌다"고 쓰지 마라.**

## 2. 착지 오프셋 — 망이 같으므로 ②의 효과만 남는다
```
창 D : 최소 141 · 중앙 152 · 최대 478
창 E : 최소 **134** · 중앙 **144** · 최대 591
```
**거의 같다**(중앙 −8ms). 🔑 **② 는 착지 위상을 바꾸지 않았다** — 바뀐 것은 **장치가 그 위상에서
무엇을 하고 있었나**다. **`[CNT]` 가 그 구간에서 빠진 것**이 유일한 차이다.

## 3. 남은 확인 (완주 후)
- **완주분 최종 `cksumng`** — 지금은 10.5분 시점이다. 0 이 유지되는지.
- **socket 판별자와의 대조** — 그쪽이 재전송을 갈라 **파괴 0** 을 독립으로 확인하면 **2/2** 다.
  🔑 **그쪽 판별자는 `[CNT]` 시각과 무관**하므로 **내 0 과 독립**이다.
- ⚠ **`[CNT]` 출력 시각이 최대 1.2초 늦어진다**(arduino 예고) — 실측 `[CNT]` 간격이
  `10:29:53 … 10:36:54` 로 **60~61초 유지**다. **주기는 안 밀렸다** ✅(`cntLastAt` 재장전 설계대로).
