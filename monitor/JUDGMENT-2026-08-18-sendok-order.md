## 1. 🔴 판정선 — 이보다 깨끗한 분리는 오늘 없었다

```
짝지어진 거래            3,783건
  정상 순서              3,772   →  그 뒤 T2  **0건**
  순서 뒤집힘               11   →  그 뒤 T2  **10건**
```
> ### **정상 순서에서는 3,772번 중 한 번도 T2 가 안 났고, 뒤집힌 11번 중 10번 났다.**

**"뒤집힘"의 정의**: `[AT] " S,…"`(페이로드 에코)가 `[AT] "AT+CIPSEND=n"` 보다 **먼저** 찍힌 거래.

**크기 편향도 같이 나온다** — 루트가 본 "48B 이상 2~4배"와 방향이 같다:
```
뒤집힌 거래 크기 : 54×3 · 96×2 · 136 · 81 · 92 · 82 · 40 · 38
정상  거래 크기 : 40×2761 · 38×688 · 39×196 · 36×59 …   ← 큰 값이 거의 없다
```

## 2. arduino 의 확정 조건 ①②③ — 답

| **③** | T2 시각에 `stuck` 이 올랐는가 | ✅ **올랐다**(15:42:04 `[CNT] stuck=5`, 그 창에서 +4). **T2 경로 확정** |
| **①** | 같은 `inSend` 구간에 `[AT]` 줄이 둘 이상 왔는가 | ✅ **그 증거가 곧 뒤집힘이다** — 한 줄이 미뤄지고 다른 줄이 먼저 나왔다 |
| **②** | `SEND OK` 가 다른 문자열에 붙어 온 줄 | ✅ **3건 · 전부 T2 시각** `"SEND OKAT+CIPCLOSE"` (15:42:04 · 15:45:13 · 15:49:21) |

### 2.1 ⚠ 그러나 ②는 **원인이 아니라 사후다**
원문 순서가 그렇게 말한다:
```
15:42:04  [TX-WAIT] ★★ T2 초과 → 링크를 다시 세운다     ← 먼저
15:42:04  [NET] 6 CIPCLOSE (낡은 소켓 닫기)
15:42:04  [AT] "SEND OKAT+CIPCLOSE" (18)                ← 그 다음
```
**`SEND OK` 는 8초 뒤에 *도착은 했다*.** 우리가 이미 포기한 뒤였고, 회수 경로의 `CIPCLOSE` 에코와
한 줄로 붙어서 왔다. **`strncmp` 접두 비교로 못 잡는 형태가 아니다**(앞이 아니라 뒤에 붙었다).

## 3. 🔴 내 자료로 **못 가르는 것** — 여기서 멈춘다

**뒤집힘의 원인은 두 가지가 남고, 시리얼 로그로는 갈 수 없다:**
```
(가) 우리가 실제로 페이로드를 먼저 보냈다 (프롬프트 `>` 를 안 기다림)
     → ESP 는 그 바이트를 명령으로 읽고, 뒤이은 CIPSEND 의 54B 를 영영 기다린다 → SEND OK 없음
(나) 보낸 순서는 맞았고 **출력 순서만** 뒤집혔다 (`pendLine` 이 첫 줄을 미룸)
     → 그렇다면 실종된 `SEND OK` 는 **버려진 둘째 줄**이다
```
🔴 **버려진 줄은 출력되지 않으므로 내 로그에 없다.** 그래서 *"안 왔다"* 와 *"우리가 버렸다"* 를
**계측기가 구분할 수 없다**(원장 7.109 · 1.1). **한쪽을 고르지 않는다 — 못 갈랐다가 답이다.**

**갈리는 방법**(arduino 영역): `inSend` 중 버린 줄에 **계수기 하나**를 붙이면 즉시 갈린다.
`(가)`면 그 계수가 0 이고, `(나)`면 T2 마다 오른다.

## 4. REQ-0218 ① — **루트의 짝짓기 방법에 함정이 셋 있다**

winF 실측:

| 함정 | 결과 |

| 🔴 **늦게 온 `SEND OK` 도 '도착'으로 잡힌다** — 실제로 3건이 T2 **뒤에** 왔다 | **손실과 지연이 안 갈린다** |

> ### 🔑 **그래서 판정선은 `SEND OK` 계수가 아니라 `T2` 계수다.**
> `T2` 는 **장치가 실제로 게이트를 못 푼 횟수**다. winF 에서
> **짝짓기 손실 8~11건 < T2 14건** — **루트의 방법은 손실을 *과소* 평가한다.**
> (늦게 온 것이 도착으로 잡히기 때문이다.)

⚠ **그리고 `T1 초과 19 / T2 14`** 는 **5건이 T1~T2 사이에 늦게 도착해 회복됐다**는 뜻이다.
**"지연"과 "실종"이 실제로 둘 다 있다.** 어느 한쪽으로 부르지 마라.

## 5. REQ-0218 ② — **정의를 맞춘 뒤의 대조**

```
내 T2            14건   = 장치가 8,000ms 기다리다 포기한 **사건**
내 CONNECT       22건   = `CIPSTART` 뒤 ESP 가 준 `CONNECT` (같은 창)
서버 세션종료     22건   = 세션 전이 **사건**            ← 🔑 **22 = 22**
서버 최대공백 8.x  9건   = **세션당 최대치 1값** (사건 수가 아니다)
```
- ✅ **재접속은 22 = 22 로 자릿수가 아니라 값이 맞는다.** 두 계측기가 같은 것을 셌다.
- ✅ **T2 14 ≤ 재접속 22** — **14건이 T2 가 만든 재접속**이고 나머지 8건은 다른 이유다.
- ⚠ **8.x초 9건 < T2 14건 은 모순이 아니다** — `최대공백` 은 **세션당 한 값**이라
  한 세션에 T2 가 둘이면 하나만 찍힌다. **구조상 `9 ≤ 14` 여야 한다.**
- 🔴 **`최대공백` 을 사건 수로 쓰지 마라.** 게다가 그 문자열은 **소크 상태줄에도 있다**
  (창 전체 2,386 대 108) — 갈라 세지 않으면 한 사건이 수십 건이 된다(원장 7.119).

✅ 확정 : 크기 편향 — 뒤집힘은 큰 프레임(54~136B)에 몰린다

# 7. 🔴 **자진 정정 — 내 도구가 분모에서 57건을 조용히 뺐다** (2026-08-18 · 창 G 원문에서 발각)

## 7.1 어떻게 들켰나
창 G 에서 **`뒤집힘 0` 인데 `T2` 가 1건** 났다. 예측(P1)과 어긋나서 **원문을 열었다:**
```
16:40:15  [AT] "AT+CIPSEND=36"              ← 순서는 정상이다
          … 페이로드 에코가 안 온다 · 8초 …
16:40:23  ★★ T2 초과 → CIPCLOSE
16:40:23  [AT] " S,17,…,3FAT+CIPCLOSE" (47) ← 에코가 **여기서** 나온다(8초 지연 · 붙어서)
16:40:26  [AT] "SEND OK"
```
**내 짝짓기는 `cmd → echo` 가 *붙어 있을 때만* 셌다.** 에코가 안 붙은 거래는
**정상도 뒤집힘도 아니어서 `else: i += 1` 로 빠졌다** — **분모에서 사라졌다.**

## 7.2 다시 센 결과 — **세 갈래이고, 합이 맞는다**
```
CIPSEND 거래 3,840건
  정상 순서       3,772  →  T2  0건
  순서 뒤집힘        11  →  T2 10건
  에코 실종/지연     57  →  T2  4건     ← 🔴 종전 판에 없던 갈래
                             합계 14 = **원시 `★★ T2` 계수 14건과 정확히 일치**
```
✅ **핵심 결론은 살아남았고 오히려 강해졌다** — **정상 순서 3,772건 중 T2 0건**은 그대로이고,
이제 **T2 14건이 전부 두 이상 갈래로 설명된다**(종전엔 10건만 설명하고 4건이 안 보였다).

## 7.3 🔴 그러나 **"뒤집힘이 원인"은 좁혀야 한다**
```
뒤집힘 갈래  크기 54·81·82·92·96·136B   ← 큰 프레임 편향 (내가 보고한 그것)
에코실종 갈래 크기 40×39 · 38×10 · 54×3 ← **작은 프레임이 지배. 편향이 없다**
```
> ### **두 갈래는 크기 분포가 다르다 → 같은 기전이 아닐 가능성이 높다.**
> **`뒤집힘` 은 T2 14건 중 10건만 설명한다.** 나머지 4건에 "큰 프레임" 이야기를 붙이지 마라.

⚠ 그리고 **에코실종 57건 중 53건은 T2 없이 회복**됐다 — **지연이 대부분이고 실종은 소수**다.
(7.123 의 "지연과 실종이 둘 다 있다"가 여기서도 같은 모양으로 나온다.)

## 7.4 교훈 — **분류에 "그 밖" 칸이 없으면 그 칸이 조용히 사라진다**
