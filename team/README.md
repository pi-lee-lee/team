# team/ — 상시 기동 에이전트 팀 운영 도구

운영 규약은 프로젝트 루트의 `CLAUDE.md` 에 있다. 이 문서는 **왜 이렇게 만들었는지**와
실측으로 확인한 런타임 사실을 남긴다. 나중에 구조를 바꾸려는 사람이 같은 함정을 다시 밟지 않도록.

## 구성

```
team/bin/
├─ team-up.sh      전원 상시 기동(멱등). 에이전트 명단 = .claude/agents/*.md
├─ team-status.sh  에이전트 상태 + 미결 요청 + 최근 이벤트
├─ req.sh          md 요청 프로토콜 (new/list/show/claim/done/reject)
├─ agent-new.sh    새 상시 에이전트 생성 — 정의·소유권·표·기동을 한 번에
├─ teamctl.py      JSON/마크다운 상태 파일 조작(레지스트리, 소유권, 표 생성)
├─ selftest.py     소유권 훅 회귀 테스트 — 규칙을 고치면 반드시 돌린다
└─ _common.sh      공용 경로·헬퍼(ID 원자 할당, front-matter 읽기/쓰기, 원장 기록)
```

## 실측으로 확인한 런타임 사실 (2026-08-13, Claude Code 2.1.231)

구조 전체가 이 네 가지 위에 서 있다. 추정이 아니라 프로브를 띄워 확인했다.

1. **`claude --bg -n <이름>` 은 이름이 붙은 상시 백그라운드 세션을 만든다.**
   `ListAgents` 로 발견되고 `SendMessage` 로 주소 지정된다. 스스로 종료하지 않는다.
   → "각 에이전트를 팀모드로 개별 기동, 상시 유지"가 네이티브로 성립한다.

2. **`--bg` 는 `--session-id` 를 무시한다.** ("--bg manages the session id")
   → 세션 id 를 미리 정할 수 없다. 그래서 기동 후 `claude agents --json` 으로
   실제 id 를 읽어 레지스트리에 기록한다(`team-up.sh`).

3. **기동 셸의 환경변수는 에이전트 세션에 상속되지 않는다.**
   `AGENT_ROLE=x claude --bg` 로 띄워도 훅에서 `os.environ["AGENT_ROLE"]` 은 비어 있다.
   백그라운드 세션을 데몬이 띄우기 때문이다.
   → **환경변수로 역할을 식별하려던 설계는 여기서 죽는다.** 대신 훅 입력에 항상 들어오는
   `session_id` 를 `.claude/team/registry.json` 으로 역할에 매핑한다.

4. **PreToolUse 훅의 `exit 2` 는 도구 호출을 실제로 실패시킨다.**
   `acceptEdits` 모드에서 확인했다(허용 파일은 써지고 차단 파일은 만들어지지 않았다).
   훅은 권한 시스템과 별개 계층이라 권한 모드를 올려도 소유권 집행은 살아 있다.

## 설계 결정과 근거

**소유권을 `.claude/ownership.json` 한 곳에만 둔다.**
에이전트 정의 6곳에 소유 규칙을 복사해 적으면 반드시 어긋난다. 에이전트 md 는 자기
영역만 요약하고 "원천은 ownership.json" 이라고 가리킨다. `CLAUDE.md` 의 표는
`teamctl.py render-table` 이 자동 생성한다. 훅은 매 호출마다 파일을 새로 읽으므로
규칙을 고치면 재기동 없이 즉시 반영된다.

**경로가 확장자를 이긴다.**
`.cpp` 만 보고 소유자를 정하면 안드로이드 JNI(`android/app/src/main/cpp/*.cpp`)와
아두이노 스케치(`arduino/**/*.cpp`)를 구분할 수 없다. 둘은 툴체인도 수명주기도 다르다.
그래서 경로 규칙을 먼저 보고, 안 걸릴 때만 확장자로 판정한다.

**모르는 경로는 막는다(기본 거부).**
규칙에 없는 파일은 `root` 소유로 떨어져 전문 에이전트가 손대지 못한다. 새 위치가
필요하면 규칙을 먼저 추가한다 — "일단 쓰고 나중에 정리"를 구조적으로 막는다.

**루트도 예외가 아니다.**
루트가 도메인 파일을 고칠 수 있으면, 가장 바쁜 세션이 규칙을 우회해버려 나머지 구조가
전부 장식이 된다. 루트의 권한은 "직접 고치는 힘"이 아니라 "누구에게 시킬지 정하는 힘"이다.

**루트는 중계자가 아니라 감시자다.**
A→B 요청이 반드시 루트를 거치게 하면 루트가 병목이 된다. 모든 요청이 `requests/` 에
파일로 남기 때문에 루트는 중계하지 않아도 전부 본다(`team-status.sh`).

**요청 ID 는 날짜와 무관한 전역 단조 증가다.**
날짜 폴더로만 나누면 8/13 에 열어 8/15 에 닫는 요청을 잃는다. 그래서 날짜 폴더(보관)와
`open/` 링크(미결 목록)와 `INDEX.md`(원장)를 분리했다. ID 할당은 `mkdir` 락이라
두 에이전트가 동시에 발행해도 번호가 겹치지 않는다("읽고 +1 하고 쓰기"는 겹친다).

**`INDEX.md` 는 고쳐 쓰지 않고 쌓기만 한다.**
상태를 되쓰면 동시 갱신에 줄이 깨진다. 현재 상태의 원천은 각 요청 md 의 front-matter 고,
원장은 "언제 무슨 일이 있었나"의 감사 기록이다.

## 삭제 스크립트를 만들지 않은 이유

사용자 규약: **"생성된 에이전트는 삭제되지 않는다."**
그래서 `agent-del.sh` 는 존재하지 않으며, 앞으로도 만들지 않는다.

이유는 규약 때문만이 아니다. 에이전트를 지우면 (1) 그가 소유하던 파일이 주인 없는 상태가
되어 아무도 못 고치게 되고, (2) 과거 요청 원장에 남은 이름이 아무 데도 닿지 않게 된다.
필요 없어진 에이전트는 지우는 게 아니라 **유휴 상태로 둔다** — 비용은 대기 세션 하나뿐이다.

일회성 하위 에이전트도 같은 이유로 금지다(`no_subagent_guard.py`). 생겼다 사라지는
에이전트는 레지스트리에 없고, 레지스트리에 없으면 소유권 판정에서 루트로 취급되며,
무엇보다 "모든 에이전트는 상시 기동"이라는 불변식을 깬다.

## 알려진 한계

- **Bash 검사는 휴리스틱이다.** 리다이렉션·`sed -i`·`rm` 같은 명시적 파일 변조는 잡지만,
  빌드 도구가 내부적으로 쓰는 파일까지는 못 막는다. 주 방어선은 `Edit`/`Write` 차단이고
  Bash 검사는 실수를 잡는 그물이지 샌드박스가 아니다.
- **권한 프롬프트에 걸리면 에이전트가 멈춘다.** 백그라운드 세션은 TTY 가 없다.
  `team-status.sh` 에 `⏸ waiting(permission prompt)` 로 보이므로, 그 명령을
  `.claude/settings.json` 의 `permissions.allow` 에 추가하면 다음부터 통과한다.
- **`--restart` 는 세션 컨텍스트를 버린다.** 에이전트가 쌓아온 대화 맥락이 사라지므로
  필요할 때만 쓴다. 평소에는 인자 없는 `team-up.sh` (멱등)를 쓴다.

## 규칙을 고친 뒤에는

