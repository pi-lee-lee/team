# team/ — 도메인 소유권 기반 에이전트 팀 운영 도구

운영 규약은 프로젝트 루트의 `CLAUDE.md` 에 있다. 이 문서는 **왜 이렇게 만들었는지**와
실측으로 확인한 런타임 사실을 남긴다. 나중에 구조를 바꾸려는 사람이 같은 함정을 다시 밟지 않도록.

## 구성

```
team/
├─ team.sh         ⭐ 진입점 — 루트 + 에이전트 전원을 tmux 한 세션에 띄운다
team/bin/
├─ stop.sh         팀 종료(루트 + 에이전트 전원). 작업이 끝나면 이걸로 내린다
├─ _agent_pane.sh  tmux 창 하나에서 대화형 에이전트를 띄우는 실행부
├─ team-up.sh      대안 — headless 백그라운드 기동(멱등). 명단 = .claude/agents/*.md
├─ team-status.sh  에이전트 상태 + 미결 요청 + 최근 이벤트
├─ req.sh          md 요청 프로토콜 (new/list/show/claim/done/reject)
├─ agent-new.sh    새 상시 에이전트 생성 — 정의·소유권·표·기동을 한 번에
├─ teamctl.py      JSON/마크다운 상태 파일 조작(레지스트리, 소유권, 표 생성)
├─ selftest.py     소유권 훅 회귀 테스트 — 규칙을 고치면 반드시 돌린다
└─ _common.sh      공용 경로·헬퍼(ID 원자 할당, front-matter 읽기/쓰기, 원장 기록)
```

## 실측으로 확인한 런타임 사실 (2026-08-13, Claude Code 2.1.231)

구조 전체가 이 네 가지 위에 서 있다. 추정이 아니라 프로브를 띄워 확인했다.

1. **`claude --bg -n <이름>` 은 이름이 붙은 상시 백그라운드 세션을 만든다.**
   `ListAgents` 로 발견되고 `SendMessage` 로 주소 지정된다. 스스로 종료하지 않는다.
   → "각 에이전트를 팀모드로 개별 기동, 상시 유지"가 네이티브로 성립한다.

2. **`--bg` 는 `--session-id` 를 무시한다.** ("--bg manages the session id")
   → 세션 id 를 미리 정할 수 없다. 그래서 기동 후 `claude agents --json` 으로
   실제 id 를 읽어 레지스트리에 기록한다(`team-up.sh`).

3. **기동 셸의 환경변수는 에이전트 세션에 상속되지 않는다.**
   `AGENT_ROLE=x claude --bg` 로 띄워도 훅에서 `os.environ["AGENT_ROLE"]` 은 비어 있다.
   백그라운드 세션을 데몬이 띄우기 때문이다.
   → **환경변수로 역할을 식별하려던 설계는 여기서 죽는다.** 대신 훅 입력에 항상 들어오는
   `session_id` 를 `.claude/team/registry.json` 으로 역할에 매핑한다.

4. **git 저장소에서는 백그라운드 세션의 Edit/Write 가 기본적으로 차단된다.**
   `worktree.bgIsolation` 기본값이 `"worktree"` 라서, bg 세션은 `EnterWorktree` 를 부르기 전까지
   공유 체크아웃을 못 고친다. `git init` 을 한 순간 팀 전체가 파일을 못 쓰게 됐다(실제로 겪음).
   → 이 팀은 **의도적으로 공유 체크아웃을 함께 편집한다.** 조율 수단이 worktree 가 아니라
   파일 소유권이기 때문이다. 각자 격리된 사본에서 일하면 cpp 가 고친 JNI 를 android 가 볼 수 없다.
   그래서 `.claude/settings.json` 에 `"worktree": {"bgIsolation": "none"}` 을 명시했다.
   **이 줄을 지우면 팀이 조용히 마비된다.**

5. **루트가 보낸 SendMessage 는 기본 설정에서 에이전트에게 도착하지 않는다.**
   `crossSessionInbound` 의 기본값은 "보내는 쪽과 받는 쪽의 **권한 모드 계급이 같을 때만**
   자동 전달"이다. 에이전트는 `bypassPermissions`, 루트(대화형)는 프롬프트 모드라 계급이
   어긋나 메시지가 수신 승인 대기로 보류됐다가 만료된다.
   실제로 REQ-0001 마감 지시 3건이 **전부 미도달**했고, 담당이 지시를 무시한 것처럼 보였다.
   에이전트끼리는 둘 다 bypass 라 계급이 같아 정상 전달된다(그래서 REQ-0002 는 성립했다).
   → 이 값은 동의에 영향을 주는 설정이라 **프로젝트 `settings.json` 에서는 읽히지 않는다.**
   그래서 `team-up.sh` 가 기동 시 `--settings '{"crossSessionInbound":"accept"}'` 로 넘긴다.
   사용자 전역 설정을 건드리지 않고 팀 에이전트에만 적용된다. 전달 성공을 실측 확인했다.

6. **PreToolUse 훅의 `exit 2` 는 도구 호출을 실제로 실패시킨다.**
   `acceptEdits` 모드에서 확인했다(허용 파일은 써지고 차단 파일은 만들어지지 않았다).
   훅은 권한 시스템과 별개 계층이라 권한 모드를 올려도 소유권 집행은 살아 있다.

## 왜 백그라운드에서 tmux 포그라운드로 옮겼나

처음에는 `claude --bg` 로 띄웠다. "상시 기동, 자원이 허용하는 한 종료하지 않는다"를
네이티브로 만족하고 터미널이 없어도 살아있기 때문이다. 그런데 실사용에서 함정 셋을 밟았고
**그중 둘이 백그라운드 세션 전용 기본값**이었다:

| 문제 | 백그라운드 | tmux 포그라운드 |
|---|---|---|
| `worktree` 격리로 파일 못 씀 | bg 세션 전용 기본값 | 해당 없음 |
| 루트 메시지 미도달 | 권한 계급 불일치로 보류·만료 | 같은 계급이라 정상 전달 |
| 승인 프롬프트 | TTY 가 없어 **조용히 멈춤** | 창에 떠서 사람이 답할 수 있음 |

세 번째가 결정적이다. 백그라운드의 유일한 장점은 "사람이 없어도 도는 것"인데,
**그 자율성은 애초에 얻을 수 없었다** — auto 모드 분류기가 `--permission-mode` 와 무관하게
명령을 판정하기 때문이다(bypassPermissions 로 올린 뒤에도 `find -o`, `adb logcat`,
`gradlew` 에서 멈췄다). 장점을 못 얻으면서 단점만 떠안은 구성이었다.

대가는 명확하다: **tmux 세션이 죽으면 팀이 죽는다.** 헤드리스가 필요하면 `team-up.sh` 가
그대로 남아 있고, 소유권·레지스트리·요청 프로토콜은 전부 `session_id` 기준이라 양쪽이 공유한다.

## 설계 결정과 근거

**소유권을 `.claude/ownership.json` 한 곳에만 둔다.**
에이전트 정의 6곳에 소유 규칙을 복사해 적으면 반드시 어긋난다. 에이전트 md 는 자기
영역만 요약하고 "원천은 ownership.json" 이라고 가리킨다. `CLAUDE.md` 의 표는
`teamctl.py render-table` 이 자동 생성한다. 훅은 매 호출마다 파일을 새로 읽으므로
규칙을 고치면 재기동 없이 즉시 반영된다.

**경로가 확장자를 이긴다.**
`.cpp` 만 보고 소유자를 정하면 안드로이드 JNI(`android/app/src/main/cpp/*.cpp`)와
아두이노 스케치(`arduino/**/*.cpp`)를 구분할 수 없다. 둘은 툴체인도 수명주기도 다르다.
그래서 경로 규칙을 먼저 보고, 안 걸릴 때만 확장자로 판정한다.

**모르는 경로는 막는다(기본 거부).**
규칙에 없는 파일은 `root` 소유로 떨어져 전문 에이전트가 손대지 못한다. 새 위치가
필요하면 규칙을 먼저 추가한다 — "일단 쓰고 나중에 정리"를 구조적으로 막는다.

**루트도 예외가 아니다.**
루트가 도메인 파일을 고칠 수 있으면, 가장 바쁜 세션이 규칙을 우회해버려 나머지 구조가
전부 장식이 된다. 루트의 권한은 "직접 고치는 힘"이 아니라 "누구에게 시킬지 정하는 힘"이다.

**루트는 중계자가 아니라 감시자다.**
A→B 요청이 반드시 루트를 거치게 하면 루트가 병목이 된다. 모든 요청이 `requests/` 에
파일로 남기 때문에 루트는 중계하지 않아도 전부 본다(`team-status.sh`).

**요청 ID 는 날짜와 무관한 전역 단조 증가다.**
날짜 폴더로만 나누면 8/13 에 열어 8/15 에 닫는 요청을 잃는다. 그래서 날짜 폴더(보관)와
`open/` 링크(미결 목록)와 `INDEX.md`(원장)를 분리했다. ID 할당은 `mkdir` 락이라
두 에이전트가 동시에 발행해도 번호가 겹치지 않는다("읽고 +1 하고 쓰기"는 겹친다).

**`INDEX.md` 는 고쳐 쓰지 않고 쌓기만 한다.**
상태를 되쓰면 동시 갱신에 줄이 깨진다. 현재 상태의 원천은 각 요청 md 의 front-matter 고,
원장은 "언제 무슨 일이 있었나"의 감사 기록이다.

## 삭제 스크립트를 만들지 않은 이유

사용자 규약: **"생성된 에이전트는 삭제되지 않는다."**
그래서 `agent-del.sh` 는 존재하지 않으며, 앞으로도 만들지 않는다.

이유는 규약 때문만이 아니다. 에이전트를 지우면 (1) 그가 소유하던 파일이 주인 없는 상태가
되어 아무도 못 고치게 되고, (2) 과거 요청 원장에 남은 이름이 아무 데도 닿지 않게 된다.
필요 없어진 에이전트는 지우는 게 아니라 **유휴 상태로 둔다** — 비용은 대기 세션 하나뿐이다.

일회성 하위 에이전트도 같은 이유로 금지다(`no_subagent_guard.py`). 생겼다 사라지는
에이전트는 레지스트리에 없고, 레지스트리에 없으면 소유권 판정에서 루트로 취급되며,
무엇보다 "모든 에이전트는 상시 기동"이라는 불변식을 깬다.

## 실사용에서 잡은 오탐 세 가지 (모두 selftest 회귀 케이스로 남김)

Bash 변조 검사는 처음에 "명령줄 어딘가에 변조 패턴이 있고 어딘가에 남의 경로가 있으면 차단"
이었다. 이 규칙은 실제로 돌리자마자 정상 작업을 막았다.

1. **`platform` 안에 `rm ` 이 들어 있다.** 부분문자열 매칭이라 `arduino-cli compile --fqbn
   esp32:esp32:platform …` 이 차단됐다. → 낱말형 패턴은 명령 위치(줄머리·`;`·`|`·`&` 뒤)에서만 찾는다.
2. **`2>&1` 을 파일 쓰기로 봤다.** stderr 리다이렉션이 걸려 정상 명령이 전부 막혔다.
   → 리다이렉션은 대상만 검사하고, `>&`(fd 복제)는 대상이 아니므로 매치되지 않게 했다.
3. **루트 소유 스크립트를 '실행'하는 걸 '수정'으로 봤다.** 에이전트가 `team/bin/req.sh` 를
   호출하는 것만으로 차단됐다(요청 프로토콜 자체가 마비). → 각 명령 구획의 첫 토큰(실행 파일)은
   경로 후보에서 제외한다. 실행과 수정은 다르다.

교훈: 이런 규칙은 책상에서 다 못 잡는다. **규칙을 고치면 `selftest.py` 를 돌린다.**

## 권한 허용 목록을 넉넉히 둔 이유

`permissions.allow` 에 읽기 전용 유틸리티(`echo`, `cat`, `sort`, `awk` …)를 넓게 넣어 뒀다.
복합 명령(`a && b`)은 **하위 명령이 전부 허용돼야** 통과하는데, `echo` 하나가 빠져 있어서
에이전트가 `ls -a && echo … && find …` 에서 승인 대기로 멈춘 적이 있다. 백그라운드 세션은
TTY 가 없어 스스로 승인할 수 없으므로 그대로 정지한다.

반대로 **파일을 바꾸는 명령(`cp`/`mv`/`rm` 등)은 일부러 넣지 않았다.** 소유권 훅이
휴리스틱인 이상, 권한 프롬프트를 2차 관문으로 남겨두는 편이 안전하다.

## 알려진 한계

- **Bash 검사는 휴리스틱이다.** 리다이렉션·`sed -i`·`rm` 같은 명시적 파일 변조는 잡지만,
  빌드 도구가 내부적으로 쓰는 파일까지는 못 막는다. 주 방어선은 `Edit`/`Write` 차단이고
  Bash 검사는 실수를 잡는 그물이지 샌드박스가 아니다.
- **`python3` 은 허용 목록에 있고, 가장 쉬운 우회로다.**
  `python3 -c "open('cpp/x.cpp','w').write(...)"` 는 어떤 변조 패턴에도 걸리지 않는다.
  각 도메인이 파이썬 도구를 쓰므로 막지 않았다. 이 구조는 **실수를 막는 장치이지
  적대적 우회를 막는 장치가 아니다** — 이 전제를 바꾸려면 샌드박스가 필요하다.
- **권한 프롬프트에 걸리면 에이전트가 멈춘다.** 백그라운드 세션은 TTY 가 없다.
  `team-status.sh` 에 `⏸ 대기(permission prompt)` 로 보이므로, 그 명령을
  tmux 모드에서는 그 창으로 가서 직접 답하면 된다(그래서 포그라운드로 옮겼다).
  반복되면 `.claude/settings.json` 의 `permissions.allow` 에 그 명령을 추가한다.
- **재기동은 세션 컨텍스트를 버린다.** 다만 요청이 md 파일로 남아 있으므로 작업 자체는
  잃지 않는다 — 재기동한 에이전트가 `req.sh list` 로 자기 미결을 다시 집어 든다.
  (md 통신을 고집하는 실질적 이유가 이것이다: 세션이 죽어도 일이 안 죽는다.)
- **tmux 세션이 끝나면 전원 종료된다 — 이건 버그가 아니라 설계다.** 에이전트는 작업
  세션이 사는 동안만 상주한다. "상시 기동"은 *작업마다 워커를 만들고 죽이지 않는다*는
  뜻이지 머신이 켜져 있는 내내 떠 있으라는 뜻이 아니다. OS 로그인 자동 기동은 두지 않는다.

## 규칙을 고친 뒤에는

```bash
python3 team/bin/selftest.py     # 33개 케이스 — 차단이 실제로 일어나는지 확인
python3 team/bin/teamctl.py render-table   # CLAUDE.md 표 재생성
```
