# 폴더 자족성 검사 — `five` 요구사항을 **기계로** 지킨다

> 사용자 요구: *"해당 폴더 내에는 필요한 모든 파일을 복사하여 **그 폴더의 파일들만으로**
> 아두이노 플래싱과 테스트 서버 기동까지 가능해야 한다"*

## 왜 도구가 필요한가

**사람 눈으로는 못 지킨다.** `#include` 하나가 상위를 가리켜도 **개발 머신에서는 그 파일이
있어서 빌드가 된다.** 깨지는 곳은 파일을 옮긴 뒤 — 즉 **2차 실기 날 아침의 다른 PC** 다.

그래서 이 도구가 하는 일은 `cpp/winparse/` 와 같은 계열이다: **없는 조건을 만들어서 본다.**
폴더를 **저장소 밖 임시 위치로 복사해** 거기서 빌드한다.

## 돌리는 법

```bash
# 서버 폴더 (윈도우 대상이라 맥에서는 툴체인 shim 이 필요하다)
python3 cpp/selfcontained/check_folder.py 조별과제샘플/VS_server_multi/five \
        --build cpp --toolchain-shim cpp/winparse/shim

# 장치 폴더 (arduino-cli 가 있으면 실제 컴파일까지)
python3 cpp/selfcontained/check_folder.py 조별과제샘플/ardu_multi/five/p1 \
        --build arduino --fqbn arduino:avr:uno

# 정적 검사만 (도구가 없어도 항상 된다)
python3 cpp/selfcontained/check_folder.py <폴더>
```
```
나가는 값 : 0 자족적 · 1 아님 · 2 검사 자체를 못 함
⚠ **0 을 "빌드된다"로 읽지 마라.** --build none 이면 정적 검사만 한 것이다
```

## 무엇을 보나

```
A. `#include "..."` **추이 폐포**가 폴더를 벗어나나        ← 자족성의 본체
B. include 문자열에 `../` · 절대경로가 있나                 ← 해석 전에 잡는다
C. `<...>` 요구 목록 — 폴더 밖이지만 **정상**이다
   🔴 아두이노 폴더는 **코어/라이브러리로 가른다** — 라이브러리는 설치가 필요하고,
      그만큼 "폴더만 복사하면 플래싱된다" 가 안 참이다
D. **격리 빌드** — 저장소 밖으로 복사해 거기서 컴파일
E. **음성 대조** — 헤더 하나를 빼고 다시 돌려 **정말 실패하는지** 확인
```

### 🔴 이 도구가 스스로 지키는 규율 둘

**① 음성 대조 없이 통과를 보고하지 않는다.**
> *"검사가 아무것도 안 봐도 `exit=0` 은 나온다."*

`D` 가 통과하면 곧바로 **가장 큰 헤더를 지우고 다시 빌드**해서 실패하는지 본다.
실패하지 않으면 그 자체를 결함으로 판정한다 — 그 경우 앞의 ✅ 는 아무 뜻이 없다.

**② "자족성 실패"와 "이 기기에 툴체인이 없음"을 가른다.**
윈도우 대상 폴더를 맥에서 돌리면 `<windows.h>` 를 못 찾는다. 그건 **폴더 잘못이 아니다.**
그것을 🔴 로 찍으면 아무도 이 도구를 안 믿게 된다. 그래서 못 찾은 것이 **선언된 시스템
헤더뿐**이면 `⚠ 툴체인 부재` 로 갈라 내고 판정에서 뺀다.

### 🔑 그리고 **안 쓰는 라이브러리 include** 를 따로 짚는다

안 쓰는 `#include <Lib.h>` 는 공짜가 아니다. arduino-cli 가 그 헤더를 보고 **라이브러리를
빌드에 넣고**, 라이브러리의 **ISR·전역은 참조 여부와 무관하게 링크된다**(`--gc-sections` 도
ISR 은 못 뺀다 — 벡터 테이블이 잡고 있다).

```
실측 2026-08-25(arduino) : `<Servo.h>` 한 줄을 지우자 **보드마다 flash 200 B** 가 줄었다
  p1 28,722 → 28,522 · p2 28,774 → 28,574 · p5 28,526 → 28,326
```
★ 그리고 그 한 줄이 *"이 폴더는 라이브러리 설치가 선행 조건"* 을 만든다 —
**안 쓰는데 자족성을 깬다.** 지우면 둘이 같이 닫힌다.

⚠ 휴리스틱이라 **판정에는 안 넣는다**(헤더 이름과 식별자가 다른 라이브러리가 있다).
양방향 대조를 확인했다:
```
쓰는 경우  ardu_multi/parking_p1 의 Servo(`Servo enterServo;`)  → **안 짚는다** ✅
안 쓰는 경우 합성 폴더의 `<Servo.h>`                             → **짚는다** ✅
```


## ⚠ 이 도구가 **못 보는 것**

> 규율(2026-08-25): **"못 본다"를 적을 때는 *무엇을 시도했는지* 를 같이 적는다.**

```
· 대상 PC 의 실물 툴체인 — 시도: `<...>` 요구 목록을 뽑아 준다.
  못 함: 그 PC 에 MSVC·arduino-cli·라이브러리가 실제로 있는지는 **사람이 본다**
· 데이터 파일 의존 — 시도: 없음. `#include` 만 따라간다.
  🔴 소스에 적힌 **런타임 경로**(모델·설정·assets)가 폴더 밖이면 이 도구는 못 잡는다
· 빌드 시스템 파일 — 시도: 없음. `.vcxproj`·`CMakeLists` 가 폴더 밖을 가리켜도 안 본다
  → `five` 폴더가 생기면 **그 파일들을 눈으로 한 번 봐야 한다**
· 링크 — `-fsyntax-only` 다. 미정의 심볼은 `cpp/winparse/` 쪽 절차가 본다
```
